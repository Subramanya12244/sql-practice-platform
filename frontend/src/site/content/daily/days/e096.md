## Understand

### What an Excel file actually is

An `.xlsx` file is a **workbook**: a zip archive of XML files that holds one or more **worksheets** (the tabs at the bottom of the window). Each worksheet is a grid of **cells** addressed by column letter and row number, such as `B3`. A cell holds a value (a number, text, a boolean, a date, an error such as `#DIV/0!`) or a **formula** such as `=B3*C3`. People use Excel as a database, a calculator, a report and a form all at once, so a workbook that arrives at a data pipeline is rarely shaped like a table. Today you read the well-behaved case; Day 97 handles the messy one.

Three facts shape everything you do when you read Excel from Python. First, **a worksheet has no schema**. A column does not have a type; every cell has its own. A column that looks like numbers can contain the text `"n/a"` in row 40, and Excel does not complain. Second, **the file stores formatting, not meaning**. A date is stored as a number (days since a starting date) and a cell format makes it look like `05/01/2026`. Third, **a formula cell stores two things**: the formula text and the last value Excel calculated for it, called the **cached value**. Python libraries can read either, and which one you get depends on how you open the file.

### Reading with pandas

`pandas.read_excel(path, sheet_name=...)` returns a DataFrame. By default it reads the first sheet, treats the first row as the header and guesses each column's type from the values it finds. It needs an **engine**, a library that knows the file format; for `.xlsx` files pandas uses `openpyxl`, which you install with `pip install openpyxl`. The most useful parameters are `sheet_name` (a name, a position, a list of them, or `None` for all sheets as a dictionary of DataFrames), `header` (which row holds the column names, counting from 0), `skiprows` (rows to ignore before the header), `usecols` (columns to keep, by letter range such as `"A:C"` or by name), `nrows` (how many data rows to read), `dtype` (a type for each column) and `na_values` (extra strings to treat as missing). To discover what a workbook contains before you read it, open it with `pd.ExcelFile(path)` and look at its `sheet_names`.

`read_excel` is the same idea as `read_csv` with extra parameters for sheets, which is why the browser examples today use `read_csv` on text: every option you learn for `header`, `skiprows`, `usecols`, `nrows` and `dtype` carries over, and the data engineering problem (what shape and types do I get?) is identical.

### Reading with openpyxl

`openpyxl` is the library under pandas. `load_workbook(path)` returns a workbook object; `wb.sheetnames` lists the tabs; `wb["Orders"]` gets one worksheet; `ws["B3"].value` reads one cell; `ws.iter_rows(min_row=2, max_col=4, values_only=True)` yields each row as a tuple of values, and it is the right tool when you need to look at cells yourself, for example to find where a table starts. `ws.max_row` and `ws.max_column` report the extent of the used area, which can be larger than the visible data because a cell that was once formatted counts.

**Formulas and cached values.** `load_workbook(path)` returns formulas as text (`"=B2*C2"`). `load_workbook(path, data_only=True)` returns the cached values instead. pandas reads cached values. A workbook written by Excel carries cached values; a workbook written by a program such as `openpyxl` stores the formula but **no cached value**, so reading it with `data_only=True` gives `None` until Excel opens and saves the file. This is a frequent surprise in pipelines that generate a workbook and read it straight back.

### Types, dates and identifiers

pandas guesses types from the cells. A numeric column becomes `int64` or `float64`; a column that mixes numbers and text becomes `object`. Excel stores every number as a floating-point value, so an integer column that has one empty cell becomes `float64` with `NaN`. A **date** cell is a number with a date format; openpyxl converts it to a `datetime` when the format is a date format, but a date in a column that is formatted as General arrives as a bare number such as `46027`. The conversion is `pd.to_datetime(serial, unit="D", origin="1899-12-30")`, because Excel counts days from 30 December 1899 (a historical quirk chosen so that dates after February 1900 agree with older spreadsheet programs).

**Identifiers are text, not numbers.** A zip code `02134`, a product code `00417` or a 16-digit card reference loses its leading zeros or its last digits when treated as a number. Read identifier columns with `dtype={"product_code": str}`. The mirror problem is a number stored as text (`"1,250"`, `" 99 "`), which arrives as `object` and breaks sums until you clean it with `pd.to_numeric`.

### A first schema test

After every read, assert what you expect: the column names, the number of rows, the types and the absence of fully empty rows. A short function that raises on a mismatch is cheap and stops a changed workbook from loading bad data. You will build the same kind of check, in SQL, into the loading days later in this block.

### Common misconception

Learners assume that a workbook is "just a CSV with tabs" and that reading it once proves the pipeline works. The file the business sends next month will have a new sheet name, an extra column or a note typed above the table. The symptom is a `KeyError` on a column name, a header read as data, or, worse, no error and a column that quietly became `object`. Read by explicit sheet name, state the header row, and test the schema.

### Why it matters

Finance, sales operations, HR and external partners still exchange data as Excel. A data engineer who can read a workbook reliably, with named sheets and explicit types, turns a manual copy and paste into a repeatable ingestion step that feeds the same validated database tables as the CSV pipeline from Days 93 to 95.

## Syntax and key functions

Reading with pandas (needs `openpyxl`):

```python
import pandas as pd

xl = pd.ExcelFile("orders.xlsx")                    # open once, list sheets
print(xl.sheet_names)
df = pd.read_excel(
    "orders.xlsx",
    sheet_name="Orders",        # name, position, list, or None for all sheets
    header=0,                   # row number of the column names
    usecols="A:D",              # letters or a list of names
    nrows=100,                  # data rows to read
    dtype={"order_id": str},    # force a type
)
```

Reading with openpyxl:

```python
from openpyxl import load_workbook

wb = load_workbook("orders.xlsx", data_only=True)    # cached values, not formulas
ws = wb["Orders"]
for row in ws.iter_rows(min_row=2, max_col=4, values_only=True):
    print(row)
```

| Item | What it does or returns |
|---|---|
| `pd.ExcelFile(path).sheet_names` | List of sheet names without reading the data. |
| `pd.read_excel(path, sheet_name=...)` | A DataFrame, or a dict of DataFrames when several sheets are requested. |
| `header`, `skiprows`, `usecols`, `nrows` | Which rows and columns become the table. |
| `dtype`, `na_values` | Force column types; extra strings that mean missing. |
| `load_workbook(path, data_only=...)` | Workbook object; formulas as text or cached values. |
| `wb.sheetnames`, `ws.max_row`, `ws.max_column` | Tabs and used extent. |
| `ws.iter_rows(min_row, max_row, min_col, max_col, values_only)` | Row tuples (or cell objects). |
| `pd.to_datetime(n, unit="D", origin="1899-12-30")` | Converts Excel serial numbers to timestamps. |
| `pd.to_numeric(s, errors="coerce")` | Converts text to numbers, invalid values become `NaN`. |

## Learn by example

### Example 1: Build a workbook and read it with pandas

The code writes a two-sheet workbook into a temporary folder with `openpyxl`, then reads it back in several ways. `pd.ExcelFile` lists the sheets; `read_excel` with `usecols` and `nrows` reads a range; `dtype` keeps `sku` as text. The third read shows the date column arriving as a real timestamp. This example needs `openpyxl`, which the browser does not have, so it is a local example (the next ones are browser-safe).

```python local
import os
import tempfile
from datetime import datetime

import pandas as pd
from openpyxl import Workbook

with tempfile.TemporaryDirectory() as folder:
    path = os.path.join(folder, "orders.xlsx")
    wb = Workbook()
    ws = wb.active
    ws.title = "Orders"
    ws.append(["order_id", "sku", "qty", "unit_price", "ordered_on"])
    ws.append([1001, "00417", 2, 9.5, datetime(2026, 1, 5)])
    ws.append([1002, "00418", 1, 20.0, datetime(2026, 1, 6)])
    ws.append([1003, "00417", 5, 9.5, datetime(2026, 1, 9)])
    ref = wb.create_sheet("Lookup")
    ref.append(["sku", "name"])
    ref.append(["00417", "Notebook"])
    ref.append(["00418", "Pen"])
    wb.save(path)

    with pd.ExcelFile(path) as xl:
        print(xl.sheet_names)
    orders = pd.read_excel(path, sheet_name="Orders", dtype={"sku": str})
    print(orders.dtypes.astype(str).to_dict())
    print(orders.loc[0, "sku"], orders.loc[0, "ordered_on"].date())
    part = pd.read_excel(path, sheet_name="Orders", usecols="A:C", nrows=2)
    print(part.shape, list(part.columns))
    both = pd.read_excel(path, sheet_name=None)
    print({name: frame.shape for name, frame in both.items()})
    guessed = pd.read_excel(path, sheet_name="Lookup")
    print(guessed["sku"].tolist())
```

```output
['Orders', 'Lookup']
{'order_id': 'int64', 'sku': 'object', 'qty': 'int64', 'unit_price': 'float64', 'ordered_on': 'datetime64[ns]'}
00417 2026-01-05
(2, 3) ['order_id', 'sku', 'qty']
{'Orders': (3, 5), 'Lookup': (2, 2)}
[417, 418]
```

The last line is the identifier trap. The `Lookup` cells were written as the text `"00417"`, yet without `dtype` pandas returns the integers `417` and `418`, because its parser converts columns of digit-only strings to numbers, just as `read_csv` does. The leading zeros are gone and a join to the warehouse would find nothing. State the type yourself with `dtype={"sku": str}`.

### Example 2: Cells, formulas and cached values with openpyxl

The workbook has a total column that is a formula. Reading it normally gives the formula text. Reading with `data_only=True` gives `None`, because the file was written by a program and has never been calculated by Excel. `iter_rows` with `values_only=True` yields plain tuples (the unit price `20.0` comes back as `20`, because Excel stores one kind of number), and `ws.max_row` reports the used extent.

```python local
import os
import tempfile

from openpyxl import Workbook, load_workbook

with tempfile.TemporaryDirectory() as folder:
    path = os.path.join(folder, "calc.xlsx")
    wb = Workbook()
    ws = wb.active
    ws.append(["qty", "unit_price", "total"])
    for i, (q, p) in enumerate([(2, 9.5), (1, 20.0), (5, 9.5)], start=2):
        ws.append([q, p, f"=A{i}*B{i}"])
    wb.save(path)

    formulas = load_workbook(path)
    print(formulas.active["C2"].value, formulas.sheetnames)
    cached = load_workbook(path, data_only=True)
    print(cached.active["C2"].value)
    print(formulas.active.max_row, formulas.active.max_column)
    for row in formulas.active.iter_rows(min_row=2, max_col=2, values_only=True):
        print(row)
```

```output
=A2*B2 ['Sheet']
None
4 3
(2, 9.5)
(1, 20)
(5, 9.5)
```

### Example 3: The same reading options on CSV text (browser-safe)

`read_excel` and `read_csv` share these options, so the browser can practise them on text. The text has a title line above the table, an unused column and a trailing note. `skiprows` removes the title, `usecols` keeps three columns, `nrows` stops before the note, and `dtype` protects the product code. The final lines show how a missing value turns an integer column into floats.

```python run
import io
import pandas as pd

text = """Orders export
order_id,sku,qty,unit_price,comment
1001,00417,2,9.5,ok
1002,00418,,20.0,
1003,00417,5,9.5,rush
Total rows: 3
"""

df = pd.read_csv(io.StringIO(text), skiprows=1, nrows=3, usecols=["order_id", "sku", "qty", "unit_price"], dtype={"sku": str})
print(df)
print(df.dtypes.astype(str).to_dict())
print(df["sku"].tolist())
print(df["qty"].isna().sum(), df["qty"].sum())
```

```output
   order_id    sku  qty  unit_price
0      1001  00417  2.0         9.5
1      1002  00418  NaN        20.0
2      1003  00417  5.0         9.5
{'order_id': 'int64', 'sku': 'object', 'qty': 'float64', 'unit_price': 'float64'}
['00417', '00418', '00417']
1 7.0
```

### Example 4: Serial dates, text numbers and a schema test

A sheet exported with General formatting gives dates as serial numbers, amounts with thousands separators as text and a count that includes a note. The function repairs the types, then `check_schema` raises when a column is missing or a type is wrong. The last call shows the error message a changed workbook would produce.

```python run
import pandas as pd

raw = pd.DataFrame({
    "order_id": [1001, 1002, 1003],
    "ordered_on": [46027, 46028, 46031],
    "amount": ["1,250.50", " 99 ", "n/a"],
})

def repair(df):
    out = df.copy()
    out["ordered_on"] = pd.to_datetime(out["ordered_on"], unit="D", origin="1899-12-30")
    out["amount"] = pd.to_numeric(out["amount"].str.replace(",", "").str.strip(), errors="coerce")
    return out

def check_schema(df, expected):
    missing = [c for c in expected if c not in df.columns]
    if missing:
        raise ValueError("missing columns: " + ", ".join(missing))
    wrong = [c for c, kind in expected.items() if df[c].dtype.kind != kind]
    if wrong:
        raise ValueError("wrong types: " + ", ".join(wrong))

clean = repair(raw)
print(clean["ordered_on"].dt.strftime("%Y-%m-%d").tolist())
print(clean["amount"].tolist())
check_schema(clean, {"order_id": "i", "ordered_on": "M", "amount": "f"})
print("schema ok")
try:
    check_schema(raw, {"order_id": "i", "ordered_on": "M", "amount": "f", "region": "O"})
except ValueError as err:
    print(err)
```

```output
['2026-01-05', '2026-01-06', '2026-01-09']
[1250.5, 99.0, nan]
schema ok
missing columns: region
```

Serial 46027 is 5 January 2026 because Excel's day 1 is 31 December 1899 under the `origin` chosen above. The text `"n/a"` becomes `NaN` through `errors="coerce"`, and the check passes only because the repaired types are right.

## Real-world applications

- **Monthly finance upload.** A finance team sends a workbook with a sheet per region. The pipeline lists the sheets with `ExcelFile`, reads each by name with explicit `dtype`, and checks the schema before loading, so a renamed sheet fails loudly instead of loading nothing.
- **Partner product catalogue.** Product codes such as `00417` must keep their leading zeros to join to the warehouse. Reading them as text with `dtype` prevents matches from silently disappearing.
- **Generated reports read back.** A job writes a workbook with formulas and a second job reads it. Knowing that cached values are `None` until Excel saves the file tells you to write values, not formulas, in files meant for machines.
- **Date-serial exports.** Systems that dump Excel with General formatting deliver dates as numbers; the origin conversion from example 4 turns them into a usable time axis.

## Daily review

### Key takeaways

- A workbook holds sheets of cells; a sheet has no schema, so you state sheet, header and types yourself.
- `read_excel` and `read_csv` share `header`, `skiprows`, `usecols`, `nrows`, `dtype`, so the browser can practise them on text.
- pandas reads cached formula values; a program-written file has none until Excel saves it.
- Excel dates are serial numbers from 30 December 1899 unless the cell has a date format.
- Identifiers are text. Read them with `dtype=str`.

### Common mistakes

- **Reading the first sheet by default.** A new sheet inserted first loads the wrong data without an error. Pass `sheet_name="Orders"`.
- **Leading zeros lost.** `00417` becomes `417` when the cell is numeric. Pass `dtype={"sku": str}` and compare with the warehouse key.
- **Integer column turned into floats.** One empty cell makes `qty` a `float64` column. Use the nullable `Int64` type after cleaning if integers are required.
- **`data_only=True` returns `None`.** The file was written by a program and never calculated. Write values, or open and save in Excel first.
- **Header read as data.** A title row above the table makes the header row wrong. Use `skiprows` or `header=n`.

### Revision notes

- `ExcelFile(path).sheet_names` first, then `read_excel(sheet_name=...)`.
- Options: `header`, `skiprows`, `usecols`, `nrows`, `dtype`, `na_values`.
- openpyxl: `load_workbook`, `iter_rows(values_only=True)`, `data_only`.
- Serial dates: `pd.to_datetime(n, unit="D", origin="1899-12-30")`.
- Always follow a read with a schema check.
