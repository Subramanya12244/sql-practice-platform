## Objectives

- Turn three business questions into three charts, each with a data table, a chart type chosen with the Day 114 rules and a finding-style title.
- Build the chart data in tested functions, and reconcile every table with the source total before drawing.
- Draw the charts with matplotlib using a colour-blind-safe palette, a focus colour and annotations, and check each figure by reading its properties.
- Assemble a short sales insight report: findings first, charts after, and a caveats paragraph, saved to files.

## Understand

### What the project is

This project day combines the whole visualisation phase into one small deliverable: a sales insight report for a manager. The data is the 240-order table used all week. The report answers three questions, shows one chart for each, states each finding in a sentence with a number, and ends with what the data cannot tell. Everything is produced by a script that can be rerun, so next month's data produces next month's report with no manual editing.

### The sequence

Work in five steps. First, write the questions and for each decide the family (Day 114): which category earns the most is a comparison, how revenue moves through the year is a trend, how large orders are in each category is a distribution. Second, write a function `chart_tables` that returns the table behind each chart and a function `findings` that turns those tables into sentences, because the sentence and the chart must come from the same numbers. Third, reconcile: the monthly table and the category table must each add up to the total revenue of the source, and the group sizes of the distribution chart must add up to the row count. A chart whose numbers do not reconcile is not shown. Fourth, draw the three figures with a shared palette, a focus colour on the element that carries the finding, an annotation on that element, labelled axes with units and an insight title (Day 122). Fifth, assemble the report: write the findings in order of importance, add the charts, and add a caveats paragraph.

### Working rules

Keep data preparation, drawing and writing in separate functions, so each can be tested alone. Generate titles and findings from the data (Example 4 of Day 122) so a changed dataset cannot leave a stale claim. Test each figure by reading it back (`ax.get_title()`, `len(ax.patches)`, heights) and comparing with the table. Choose chart types by the question, not by habit; if a chart does not answer one of the three questions, remove it. Save each chart as a PNG at 150 dpi with trimmed margins and close the figure. Never write a causal claim the data cannot support: the table has no information about marketing, price changes or stock, so any explanation of why revenue peaked is a hypothesis for the manager to check, and the caveats paragraph should say so.

### What good looks like

A strong report has three findings, each with a number, a base and a comparison; three charts that work in greyscale; an insight title on each chart that is true to the table; a caveats paragraph that names the limits (one year, 240 orders, no cost data, no cause); and a script that rebuilds everything from the table in seconds. Treat the project as practice for the habit that matters most in analyst work: every number in the document traces back to a line of code.

## Learn by example

### Example 1: Questions, chart choices and reconciliation

The plan states each question with its family and chart, then the data tables are built and reconciled with the source total. The reconciliation is the gate: if it fails the script stops before drawing anything. It runs in the browser.

```python run
import numpy as np
import pandas as pd


def make_orders():
    rng = np.random.default_rng(7)
    n = 240
    category = rng.choice(["Home", "Electronics", "Beauty", "Sports"], size=n, p=[0.35, 0.2, 0.25, 0.2])
    base = pd.Series({"Home": 45, "Electronics": 160, "Beauty": 28, "Sports": 60})
    df = pd.DataFrame({
        "order_date": pd.Timestamp("2025-01-01") + pd.to_timedelta(rng.integers(0, 365, n), unit="D"),
        "category": category,
        "quantity": rng.integers(1, 6, n),
        "unit_price": (base[category].to_numpy() * (0.8 + 0.4 * rng.random(n))).round(2),
        "shipping_days": rng.integers(1, 9, n),
    })
    df["revenue"] = (df["quantity"] * df["unit_price"]).round(2)
    return df.sort_values("order_date").reset_index(drop=True)

def chart_tables(orders):
    monthly = orders.groupby(orders["order_date"].dt.month)["revenue"].sum().round(0)
    by_category = orders.groupby("category")["revenue"].sum().round(0).sort_values(ascending=False)
    medians = orders.groupby("category")["revenue"].median().sort_values(ascending=False)
    groups = {name: orders.loc[orders["category"] == name, "revenue"] for name in medians.index}
    return {"monthly": monthly, "by_category": by_category, "medians": medians, "groups": groups}


def findings(orders):
    t = chart_tables(orders)
    top = t["by_category"].index[0]
    share = t["by_category"].iloc[0] / t["by_category"].sum() * 100
    best, worst = int(t["monthly"].idxmax()), int(t["monthly"].idxmin())
    ratio = t["medians"].iloc[0] / t["medians"].iloc[-1]
    return [
        f"{top} earns {share:.0f}% of revenue, more than any other category.",
        f"Revenue peaked in month {best} ({t['monthly'].max():,.0f}) and was lowest in month {worst} ({t['monthly'].min():,.0f}).",
        f"The median {t['medians'].index[0]} order is {ratio:.1f} times the median {t['medians'].index[-1]} order.",
    ]

plan = {
    "Which category earns the most?": ("comparison", "sorted bar"),
    "How does revenue move through the year?": ("trend", "line"),
    "How large are orders in each category?": ("distribution", "box plots"),
}
for question, (family, chart) in plan.items():
    print(f"{question} -> {family}: {chart}")

orders = make_orders()
t = chart_tables(orders)
total = round(float(orders["revenue"].sum()))
print("source total:", total)
print("by category adds up:", abs(float(t["by_category"].sum()) - total) <= 2)
print("monthly adds up:", abs(float(t["monthly"].sum()) - total) <= 6)
print("group rows:", sum(len(g) for g in t["groups"].values()), "of", len(orders))
```

```output
Which category earns the most? -> comparison: sorted bar
How does revenue move through the year? -> trend: line
How large are orders in each category? -> distribution: box plots
source total: 48966
by category adds up: True
monthly adds up: True
group rows: 240 of 240
```

### Example 2: Findings generated from the tables

The three findings are sentences built from the same tables as the charts, so they cannot disagree with them. Each has a number and a comparison. Read them as a manager would: could you act on each?

### Example 3: Draw the three figures and check them

One function per chart returns a figure. The category bar uses the focus colour on the top category, the monthly line marks the peak with an annotation, and the box plot is ordered by median. The titles come from the findings. The checks read each figure back: number of bars, number of points, number of boxes and the titles.

```python local
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt
import numpy as np
import pandas as pd


def make_orders():

    top = t["by_category"].index[0]
    share = t["by_category"].iloc[0] / t["by_category"].sum() * 100
    best, worst = int(t["monthly"].idxmax()), int(t["monthly"].idxmin())
    ratio = t["medians"].iloc[0] / t["medians"].iloc[-1]
    return [
        f"{top} earns {share:.0f}% of revenue, more than any other category.",
        f"Revenue peaked in month {best} ({t['monthly'].max():,.0f}) and was lowest in month {worst} ({t['monthly'].min():,.0f}).",
        f"The median {t['medians'].index[0]} order is {ratio:.1f} times the median {t['medians'].index[-1]} order.",
    ]

FOCUS, GREY = "#D55E00", "#999999"


def figure_category(t, title):
    fig, ax = plt.subplots(figsize=(7, 4))
    names = list(t["by_category"].index)
    ax.bar(names, t["by_category"].values, color=[FOCUS if i == 0 else GREY for i in range(len(names))])
    ax.set_title(title)
    ax.set_ylabel("Revenue (GBP)")
    ax.set_ylim(bottom=0)
    return fig


def figure_monthly(t, title):
    fig, ax = plt.subplots(figsize=(7, 4))
    ax.plot(t["monthly"].index, t["monthly"].values, marker="o", color=FOCUS)
    peak = int(t["monthly"].idxmax())
    ax.annotate(f"Peak: month {peak}", xy=(peak, t["monthly"].max()), xytext=(peak - 3, t["monthly"].max() * 1.05),
                arrowprops={"arrowstyle": "->"})
    ax.set_title(title)
    ax.set_xlabel("Month")
    ax.set_ylabel("Revenue (GBP)")
    ax.set_ylim(bottom=0)
    return fig


def figure_sizes(t, title):
    fig, ax = plt.subplots(figsize=(7, 4))
    names = list(t["groups"])
    ax.boxplot([t["groups"][n] for n in names], tick_labels=names)
    ax.set_title(title)
    ax.set_ylabel("Order revenue (GBP)")
    return fig


orders = make_orders()
t = chart_tables(orders)
lines = findings(orders)
figs = {"category": figure_category(t, lines[0]), "monthly": figure_monthly(t, lines[1]), "sizes": figure_sizes(t, lines[2])}

a = figs["category"].axes[0]
print("category: bars", len(a.patches), "| top bar", int(a.patches[0].get_height()))
b = figs["monthly"].axes[0]
print("monthly: points", len(b.lines[0].get_ydata()), "| annotation:", [x.get_text() for x in b.texts])
c = figs["sizes"].axes[0]
print("sizes: groups", len(c.get_xticklabels()), "| order:", [x.get_text() for x in c.get_xticklabels()])
print("titles match findings:", [f.axes[0].get_title() for f in figs.values()] == lines)
```

### Example 4: Assemble and save the report

The report is a Markdown file with the findings first, the charts after and a caveats paragraph. The three PNGs and the file are written into a temporary folder; the script prints the file names (sorted, so the output is stable) and the first lines of the report. Sizes of files are not printed because they vary between machines.

## Real-world applications

- **Monthly management pack.** The same structure (questions, tables, findings, charts, caveats) is rerun every month from the new data, so the pack is produced in minutes and stays consistent.
- **Self-checking reports.** The reconciliation gate (Example 1) is what stops a wrong chart reaching a client when a source file changes shape.
- **Handover to non-technical readers.** Findings-first reports with one chart per question are what stakeholders read; the code is kept for audit.
- **Portfolio work.** A reproducible report with tests and caveats shows employers more than a notebook of unlabelled charts.

## Daily review

### Key takeaways

- Start from questions, choose the chart family for each, and drop charts that answer none.
- Build tables and findings in functions from the same numbers so charts and text agree.
- Reconcile every table with the source before drawing.
- Test each figure by reading its properties back.
- A report is findings first, caveats stated, and fully reproducible.

### Common mistakes

- Writing the findings by hand after looking at the charts. Symptom: a title that disagrees with the table after the data refresh. Fix: generate them from the tables.
- Skipping reconciliation. Symptom: monthly and category totals that differ without anyone noticing. Fix: assert that each table sums to the source total.
- Claiming a reason in a finding. Symptom: "revenue peaked because of the summer sale". Fix: state what the data shows and list the cause as a question.
- Leaving figures open. Symptom: a `RuntimeWarning` about too many figures. Fix: `plt.close(fig)` after saving.

### Revision notes

- Question, family, chart; table; finding; figure; caveat.
- `chart_tables`, `findings`, one figure function per chart.
- Reconcile with the source total; check titles against findings.
- `savefig(dpi=150, bbox_inches="tight")`, `plt.close`.
