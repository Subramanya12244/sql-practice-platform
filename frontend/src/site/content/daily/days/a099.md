## Understand

### Merge: a join between queries

On Day 98 you cleaned one table. Real reports combine tables, and Power Query offers two ways: merge and append. **Merge Queries** joins two tables side by side on a key, the way `VLOOKUP` and `XLOOKUP` do for one column (Day 94), the way `merge` does in pandas and `JOIN` does in SQL. Use Home, Merge Queries (or Merge Queries as New, which leaves both originals alone and creates a third query). In the dialog you pick the first table and click the key column, then pick the second table and click its key column. Excel shows how many rows match. You then choose a **join kind**:

- **Left Outer**: all rows of the first table, with the matching row from the second where there is one, and nulls where there is none. This is the lookup.
- **Right Outer**: the mirror image.
- **Full Outer**: all rows from both.
- **Inner**: only rows that match in both tables.
- **Left Anti**: rows of the first table with no match in the second. Use it to find orders whose product is not in the price list.
- **Right Anti**: the mirror image.

Merging adds one new column that holds a whole nested table for each row. Click the double-arrow icon in the column header to **expand** it and tick the columns you want, which adds them as ordinary columns. Untick "Use original column name as prefix" when the prefix is not useful. A merge matches keys exactly, including case, so clean the keys (trim, same case, same type) in both queries before merging, as on Day 98. A key that is text in one table and a number in the other does not match. When the second table has the same key twice, each matching row is repeated, so the output has more rows than the first table: remove duplicates in the lookup table first. This is the same row multiplication you saw with pandas `merge` on Day 94.

### Append: stacking tables

**Append Queries** stacks one table under another. It is used when the same kind of data arrives in several pieces, such as one table per month or per region. Home, Append Queries (or as New) opens a dialog for two tables or for three or more. Columns are matched by **name**, not by position. A column that exists in only one table is kept, and its cells are null for the rows that came from the other table. The column order follows the first table. This is `pd.concat` with `ignore_index=True`. The most common mistake is columns that mean the same thing but are named differently (`Qty` and `Quantity`): append treats them as two columns, and half of each is null. Rename to a single name before the append.

### Custom columns

Add Column, Custom Column opens a box for a formula. The formula uses the **M language**, and column names are written in square brackets: `[Qty] * [Price]`. The result is a new column, for which you should set a data type afterwards. Add Column, Conditional Column builds an `if ... then ... else` through a dialog, and Column From Examples lets you type expected results so that Excel infers the formula. Be aware that M is not the worksheet formula language: functions have different names (`Text.Upper`, not `UPPER`), the text join operator is still `&`, and keywords are lower case.

### M language basics

Behind every query is a script that you can read in the **Advanced Editor** (Home, Advanced Editor) or in the formula bar. It has the shape `let` steps `in` result. Each step is a name, an equals sign and an expression, and the steps are separated by commas. The last line after `in` names the step that is the query's output. Because each step refers to the previous one by name, the script is exactly the Applied Steps list written in text.

```text
let
    Source = Excel.CurrentWorkbook(){[Name="Orders"]}[Content],
    Typed = Table.TransformColumnTypes(Source, {{"Qty", Int64.Type}}),
    Big = Table.SelectRows(Typed, each [Qty] >= 3)
in
    Big
```

The points that matter are these. M is **case-sensitive**: `Table.SelectRows` works and `table.selectrows` fails. Step names that contain spaces are written `#"Changed Type"`. `each` introduces a small function that is applied to every row, and `[Qty]` inside it means the Qty field of the current row. `if [Qty] >= 3 then "Big" else "Small"` is the conditional. Text is joined with `&`, comments start with `//`, and a missing value is `null`. A step name can be anything, so rename steps in the Applied Steps pane (right-click, Rename) to describe their purpose: "Remove test rows" is better than "Filtered Rows1".

### Chains of queries and refresh

A merge refers to another query by its name. If `Orders` merges with `Prices`, then `Prices` must be refreshed before `Orders`. Power Query works out this order itself, and View, Query Dependencies draws the chain. For lookup tables that you do not need on a sheet, use Close & Load To and choose "Only Create Connection". Data, Refresh All refreshes every query, and each query runs all its steps from the source. If a source column is renamed, a step that names it fails with an error at the step where the column is first used, and the Applied Steps pane marks that step. Fix the name in the step, not in the loaded sheet. Formulas that depend on a loaded Table (a pivot, a chart) see the new data after the refresh.

### Why it matters, and the misconception

Merge and append are what turn files from several places into one analysable table, with the logic recorded. A common misconception is that merge works like `VLOOKUP` and returns only the first match; it is a join, and returns every match. Another is that you must write M by hand. Most work is done through the ribbon, and M is read to understand or adjust what it produced.

## Syntax and key functions

Ribbon commands:

```text
Home > Merge Queries > Merge Queries as New
Home > Append Queries > Append Queries as New
Add Column > Custom Column
Add Column > Conditional Column
Home > Advanced Editor
View > Query Dependencies
Data > Refresh All
```

The M functions behind them:

```text
Table.NestedJoin(left, {"Key"}, right, {"Key"}, "NewColumn", JoinKind.LeftOuter)
Table.ExpandTableColumn(merged, "NewColumn", {"Price"}, {"Price"})
Table.Combine({table1, table2})
Table.AddColumn(table, "Amount", each [Qty] * [Price], type number)
Table.SelectRows(table, each [Qty] >= 3)
```

| Item | Meaning |
|---|---|
| `JoinKind.LeftOuter`, `Inner`, `FullOuter`, `LeftAnti` | Join kind for a merge. |
| `Table.Combine` | Append a list of tables, matching columns by name. |
| `each [Field]` | A function applied to every row; `[Field]` is the current row's value. |
| `let ... in` | The script: named steps, then the output step. |
| `#"Step Name"` | Reference to a step whose name contains spaces. |
| `null` | A missing value. |

pandas counterparts: `left.merge(right, on="Key", how="left")`, `pd.concat([a, b], ignore_index=True)`, `df["Amount"] = df["Qty"] * df["Price"]`, `np.where(...)`.

## Learn by example

### Example 1: Merge with different join kinds

Orders and a price list. Order 4 has a code that is not priced, and the price list has an item that no order uses.

| Order | Code | Qty |
|---|---|---|
| 1 | P1 | 3 |
| 2 | P2 | 5 |
| 3 | P1 | 2 |
| 4 | P9 | 1 |

| Code | Price |
|---|---|
| P1 | 10 |
| P2 | 25 |
| P3 | 7 |

```python run
import pandas as pd

orders = pd.DataFrame({"Order": [1, 2, 3, 4], "Code": ["P1", "P2", "P1", "P9"], "Qty": [3, 5, 2, 1]})
prices = pd.DataFrame({"Code": ["P1", "P2", "P3"], "Price": [10, 25, 7]})
for how in ["left", "inner", "outer"]:
    print(how, len(orders.merge(prices, on="Code", how=how)))
m = orders.merge(prices, on="Code", how="left", indicator=True)
print(m[m["_merge"] == "left_only"]["Order"].tolist())
print(m.drop(columns="_merge").to_string(index=False))
```

```output
left 4
inner 3
outer 5
[4]
 Order Code  Qty  Price
     1   P1    3   10.0
     2   P2    5   25.0
     3   P1    2   10.0
     4   P9    1    NaN
```

Left Outer keeps all 4 orders, Inner keeps the 3 that match, and Full Outer gives 5 rows because it adds the unused P3. The orders with no match, found here with `indicator=True`, are what Left Anti returns: order 4. The last table is the Left Outer result after expanding `Price`; order 4 has a null price (shown as `NaN`).

### Example 2: Duplicate keys multiply rows

If the price list holds P1 twice (an old and a new price), a merge returns both.

```python run
import pandas as pd

orders = pd.DataFrame({"Order": [1, 2], "Code": ["P1", "P2"]})
prices = pd.DataFrame({"Code": ["P1", "P1", "P2"], "Price": [10, 11, 25]})
print(len(orders.merge(prices, on="Code", how="left")))
clean = prices.drop_duplicates("Code", keep="last")
print(orders.merge(clean, on="Code", how="left").to_string(index=False))
```

```output
3
 Order Code  Price
     1   P1     11
     2   P2     25
```

Two orders become three rows because P1 matches twice. In Power Query the fix is Remove Duplicates (or Group By) on the lookup table before the merge. The pandas call `drop_duplicates("Code", keep="last")` keeps the later price. In Power Query, Remove Duplicates keeps one row of each key but you should not rely on which one after a sort; when the choice matters (the latest price), make it explicit, for example with Group By and a Max of the date.

### Example 3: Append with different columns

January and February files. February has an extra column and one column named differently.

```python run
import pandas as pd

jan = pd.DataFrame({"Region": ["North", "South"], "Qty": [3, 5]})
feb = pd.DataFrame({"Region": ["East"], "Quantity": [4], "Note": ["new"]})
stacked = pd.concat([jan, feb], ignore_index=True)
print(stacked.to_string())
feb2 = feb.rename(columns={"Quantity": "Qty"})
print(pd.concat([jan, feb2], ignore_index=True)["Qty"].tolist())
```

```output
  Region  Qty  Quantity Note
0  North  3.0       NaN  NaN
1  South  5.0       NaN  NaN
2   East  NaN       4.0  new
[3, 5, 4]
```

Because the names differ, `Qty` and `Quantity` become two columns, each partly null, and `Note` is null for the January rows. After the rename the append has a single `Qty` column holding 3, 5 and 4. The M function is `Table.Combine({Jan, Feb})` and it behaves in the same way: columns from the first table come first, then new ones.

### Example 4: Custom and conditional columns

```text
Amount   = [Qty] * [Price]
Size     = if [Qty] >= 3 then "Big" else "Small"
Label    = [Code] & "-" & Text.From([Qty])
```

The first formula is the Custom Column dialog, the second is a Conditional Column, and the third joins text, using `Text.From` to convert the number, because M does not convert silently (a number cannot be joined to text with `&`).

```python run
import numpy as np
import pandas as pd

d = pd.DataFrame({"Code": ["P1", "P2", "P1"], "Qty": [3, 5, 2], "Price": [10, 25, 10]})
d["Amount"] = d["Qty"] * d["Price"]
d["Size"] = np.where(d["Qty"] >= 3, "Big", "Small")
d["Label"] = d["Code"] + "-" + d["Qty"].astype(str)
print(d.to_string(index=False))
```

```output
Code  Qty  Price  Amount  Size Label
  P1    3     10      30   Big  P1-3
  P2    5     25     125   Big  P2-5
  P1    2     10      20 Small  P1-2
```

Amounts are 30, 125 and 20, sizes Big, Big and Small, and labels `P1-3`, `P2-5` and `P1-2`. The difference to pandas is only in the syntax: `each`-style row formulas in M are columns operations in pandas. In both, joining text and a number needs an explicit conversion (`Text.From` in M, `astype(str)` in pandas).

### Example 5: A chain of queries, as pandas functions

Query `Prices` (the lookup), query `Orders` (appends January and February, merges `Prices`, adds `Amount`).

```python run
import pandas as pd

def prices_query():
    p = pd.DataFrame({"Code": ["P1", "P2", "P2"], "Price": [10, 25, 26]})
    return p.drop_duplicates("Code", keep="first")

def orders_query(jan, feb):
    appended = pd.concat([jan, feb], ignore_index=True)                  # Append Queries
    merged = appended.merge(prices_query(), on="Code", how="left")       # Merge Queries, expand Price
    merged["Amount"] = merged["Qty"] * merged["Price"]                   # Custom Column
    return merged

jan = pd.DataFrame({"Code": ["P1", "P2"], "Qty": [3, 5]})
feb = pd.DataFrame({"Code": ["P1", "P9"], "Qty": [2, 1]})
out = orders_query(jan, feb)
print(out.to_string(index=False))
print(out["Amount"].sum(), out["Price"].isna().sum())
feb_new = pd.DataFrame({"Code": ["P1", "P9", "P2"], "Qty": [2, 1, 4]})
print(orders_query(jan, feb_new)["Amount"].sum())
```

```output
Code  Qty  Price  Amount
  P1    3   10.0    30.0
  P2    5   25.0   125.0
  P1    2   10.0    20.0
  P9    1    NaN     NaN
175.0 1
275.0
```

The result has 4 rows, total amount 175 (30 + 125 + 20, the P9 row has no price so its amount is missing and is skipped by the sum), and one unmatched price. When the February data gains a row (P2, quantity 4) the same chain gives 275: the new amount is 100. This is what Refresh All does: `Prices` is evaluated, then `Orders`, with no manual steps. In Excel the unmatched row would show `null` in `Price` and `Amount`, and a Left Anti merge would list it for follow-up.

## Real-world applications

- **Enriching transactions.** A Left Outer merge adds category, region or cost from a master list, and a Left Anti merge lists the transactions with missing master data (Example 1).
- **Combining periodic files.** Append stacks monthly exports into one table; a refresh picks up next month's file after it is added to the chain (Examples 3 and 5).
- **Derived measures.** Custom and conditional columns build amount, size band and label columns before the data reaches a PivotTable (Example 4).
- **Auditing a merge.** Comparing row counts before and after a merge shows duplicate keys, the usual cause of inflated totals (Example 2).

## Daily review

### Key takeaways

- Merge is a join: choose the join kind, expand the nested column, clean and de-duplicate keys first.
- Append stacks tables and matches columns by name; unmatched columns become null.
- Custom columns use M: `[Field]` for the current row, `each` for row functions, `if ... then ... else`, `&`.
- A query is a `let ... in` script, case-sensitive, with one named step per applied step.
- Refresh All runs the chain of queries in dependency order.

### Common mistakes

- Merging on keys with different case, spaces or types and getting no matches.
- Not removing duplicate keys from the lookup table, which inflates the row count and the totals.
- Appending tables whose column names differ, ending with two half-empty columns.
- Writing worksheet functions (`UPPER`) or the wrong case (`table.selectrows`) in M.
- Joining text and a number with `&` without `Text.From`.
- Editing the loaded sheet by hand instead of the query, so the change disappears at the next refresh.
