## Understand

### Why NumPy exists

A Python list can hold anything: numbers, text, other lists, all mixed together. That freedom has a price. Each item in a list is a full Python object stored somewhere in memory, and the list only keeps a pointer to it. Adding up a million numbers in a list means a million pointer lookups, a million type checks and a million additions carried out by the Python interpreter, one at a time. That is slow, and it uses a lot of memory.

**NumPy** (the package `numpy`, imported by convention as `np`) solves this with one new type, the **ndarray** (n-dimensional array). An ndarray stores its values side by side in one block of memory, and every value has the same type. Because the type is known and fixed, the work of adding, comparing or multiplying values can be done by compiled code that loops over the block directly. The learner-visible result is that one line of NumPy often replaces a Python loop and runs tens or hundreds of times faster. Pandas, which you meet from Day 68, is built on top of NumPy arrays, so everything in this block of days is also the foundation of pandas.

A useful picture: a list is a shelf of boxes, each box holding a pointer to something stored elsewhere. An array is an egg tray: identical slots, packed together, each holding the value itself.

### Creating an array

The most direct way is `np.array([...])`, which converts a list (or a list of lists) into an array. `np.array([3, 1, 4])` is a one-dimensional array of three integers. A list of equal-length lists becomes a two-dimensional array, which you can picture as a table with rows and columns.

Often you do not have the values yet, only a rule. `np.zeros(5)` makes five zeros, `np.ones((2, 3))` makes a 2 by 3 grid of ones, and `np.full((2, 2), 7)` makes a 2 by 2 grid filled with 7. Notice that the size of a 2D array is given as a tuple, `(rows, columns)`.

Two functions make evenly spaced numbers. `np.arange(start, stop, step)` works like `range`: it includes `start`, excludes `stop` and moves by `step`, so `np.arange(0, 10, 3)` is `[0, 3, 6, 9]`. `np.linspace(start, stop, num)` includes **both** ends and splits the gap into `num` points, so `np.linspace(0, 1, 5)` is `[0, 0.25, 0.5, 0.75, 1]`. Use `arange` when you know the step and `linspace` when you know how many points you want. With floating-point steps, `arange` can be surprising about whether the end is included because of rounding, which is another reason to prefer `linspace` for decimals.

### Shape, ndim and size

Every array knows its **shape**, a tuple giving the length along each dimension. A table with 3 rows and 4 columns has shape `(3, 4)`. A flat array of 5 values has shape `(5,)`, with a trailing comma because it is a tuple of one number. The attribute **ndim** is the number of dimensions, which is `len(shape)`, and **size** is the total number of values, which is the product of the shape. These are attributes, not methods, so you write `a.shape` without parentheses. Calling `a.shape()` raises `TypeError: 'tuple' object is not callable`, a very common first error.

An **axis** is one dimension of the array. For a 2D array, axis 0 runs down the rows and axis 1 runs across the columns. You will rely on axes heavily on Day 66.

`reshape` gives the same values a new shape without changing them: `np.arange(6).reshape(2, 3)` fills a 2 by 3 grid row by row. The new shape must hold exactly the same number of values, so `reshape(4, 2)` on six values raises a `ValueError`. You may pass `-1` for one dimension and let NumPy work it out: `reshape(-1, 2)` on six values means three rows of two.

### dtype: one type for the whole array

The **dtype** (data type) says what kind of value every slot holds. Common ones are `int64` (whole numbers), `float64` (decimals), `bool` (`True` or `False`) and `<U5`-style text types. NumPy picks a dtype when it creates the array: all whole numbers give an integer dtype, a single decimal point anywhere turns the whole array into floats, and a mix of numbers and text turns everything into text. This choice is called **upcasting**: the array takes the most general type that can hold every value, so `np.array([1, 2.5, 3])` is `[1.0, 2.5, 3.0]`.

You can ask for a type with `dtype=`, as in `np.array([1, 2, 3], dtype=float)`, and convert later with `astype`. `astype` returns a new array and leaves the old one alone, just like string methods on Day 4. Converting floats to integers drops the decimal part towards zero without rounding: `np.array([2.9, -2.9]).astype(int)` is `[2, -2]`. If you want rounding, call `np.round` first.

### Default integer width depends on the platform

When NumPy picks an integer dtype for you, the width of that integer depends on the computer. On most desktop and laptop computers the default is `int64` (8 bytes per value). In the browser Python that these lessons run in, which is a 32-bit environment, the default is `int32` (4 bytes per value). The values you see in lists are the same, but `a.dtype`, `a.itemsize` and `a.nbytes` of an array whose dtype you did not set can differ between machines. For that reason this lesson sets `dtype=np.int64` or `np.int32` explicitly wherever it shows a width. Floats are `float64` everywhere. When you write code that must behave the same everywhere, set the dtype yourself rather than relying on the default.

### The common misconception

Learners treat an array as a fancier list and try to put mixed things in it, or expect `a + b` to join two arrays end to end. A list stores anything and `+` concatenates. An array stores one type and `+` adds element by element (Day 65 covers this fully). If you actually want to join arrays, use `np.concatenate`. The symptom is a result whose length did not change when you expected it to double, or a whole array of text strings because one value was a word.

### Why it matters in data work

Sensor readings, prices, test scores and pixel values are all long runs of numbers of the same kind. Holding them in one typed block makes arithmetic fast and memory small, and the dtype is also a quality check: if a column of numbers has become text, the dtype shows it immediately. Shape errors are the other most common source of confusion in numerical code, so reading `shape` before and after every step is a habit worth building from the first day.

### Reading the shape of data you did not build

When you load data, your first questions are always the same: how many values, how many dimensions, what type? Those are exactly `size`, `ndim` and `dtype`. A table of 1,000 measurements for 12 sensors should have shape `(1000, 12)`; if you see `(12, 1000)` the data was probably loaded the wrong way round, and every later calculation would silently use the wrong axis. Checking `shape` takes one second and prevents hours of confusion, which is why experienced analysts print it so often.

## Syntax and key functions

Build arrays:

```python
import numpy as np

np.array(list_or_nested_list, dtype=None)
np.zeros(shape)
np.ones(shape)
np.full(shape, value)
np.arange(start, stop, step)
np.linspace(start, stop, num)
```

`shape` is an integer or a tuple such as `(2, 3)`. `arange` excludes `stop`; `linspace` includes it.

Inspect and convert:

```python
a.shape
a.ndim
a.size
a.dtype
a.astype(float)
a.reshape(rows, cols)
a.tolist()
```

| Expression | Returns |
|---|---|
| `np.array([1, 2, 3])` | A 1D integer array. |
| `np.zeros((2, 3))` | A 2 by 3 array of `0.0` floats. |
| `np.full((2, 2), 7)` | A 2 by 2 array of 7. |
| `np.arange(0, 10, 3)` | `[0, 3, 6, 9]`. |
| `np.linspace(0, 1, 5)` | Five floats from 0 to 1 inclusive. |
| `a.shape` | Tuple of lengths, e.g. `(3, 4)`. |
| `a.ndim` | Number of dimensions. |
| `a.size` | Total number of values. |
| `a.dtype` | The element type, e.g. `int64`. |
| `a.astype(float)` | A new array converted to the type. |
| `a.reshape(2, 3)` | Same values, new shape; use `-1` to infer one length. |
| `a.tolist()` | A plain Python list (nested for 2D). |

## Learn by example

### Example 1: Creating arrays and reading their attributes

A list becomes an array, and the attributes describe it. Nested lists give a 2D array. The first array is created with `dtype=np.int64` so that the printed type name is the same on every computer (see the note on default integer width in the lesson). We print `tolist()` so that the output does not depend on how NumPy formats arrays.

```python run
import numpy as np

a = np.array([3, 1, 4, 1, 5], dtype=np.int64)
t = np.array([[1, 2, 3], [4, 5, 6]])
print(a.tolist(), a.shape, a.ndim, a.size, a.dtype)
print(t.tolist(), t.shape, t.ndim, t.size)
print(type(a).__name__, len(a), len(t))
```

```output
[3, 1, 4, 1, 5] (5,) 1 5 int64
[[1, 2, 3], [4, 5, 6]] (2, 3) 2 6
ndarray 5 2
```

### Example 2: Arrays built from a rule

`zeros`, `ones` and `full` take a shape. `arange` stops before its stop value, while `linspace` includes both ends. `arange` with an integer step gives integers, and `linspace` always gives floats.

```python run
import numpy as np

print(np.zeros(3).tolist())
print(np.ones((2, 2)).tolist())
print(np.full((2, 3), 7).tolist())
print(np.arange(0, 10, 3).tolist())
print(np.arange(5).tolist())
print(np.linspace(0, 1, 5).tolist())
print(np.linspace(10, 20, 3).tolist())
```

```output
[0.0, 0.0, 0.0]
[[1.0, 1.0], [1.0, 1.0]]
[[7, 7, 7], [7, 7, 7]]
[0, 3, 6, 9]
[0, 1, 2, 3, 4]
[0.0, 0.25, 0.5, 0.75, 1.0]
[10.0, 15.0, 20.0]
```

### Example 3: dtype and upcasting

NumPy chooses the most general type that fits every value. The `kind` letter `i` means integer, `f` float and `U` text; we print the kind of the integer array because its exact width depends on the platform. One decimal makes the whole array float, and one string makes everything text. `astype` converts to a new array and truncates towards zero when going from float to int.

```python run
import numpy as np

ints = np.array([1, 2, 3])
mixed = np.array([1, 2.5, 3])
text = np.array([1, "two", 3])
print(ints.dtype.kind, mixed.dtype, text.dtype.kind)
print(mixed.tolist())
print(text.tolist())

f = np.array([2.9, -2.9, 0.5])
print(f.astype(int).tolist())
print(np.round(f).astype(int).tolist())
print(np.array([0, 1, 2], dtype=float).tolist())
print(np.array([0, 1, 2]).astype(bool).tolist())
```

```output
i float64 U
[1.0, 2.5, 3.0]
['1', 'two', '3']
[2, -2, 0]
[3, -3, 0]
[0.0, 1.0, 2.0]
[False, True, True]
```

### Example 4: reshape and why the sizes must match

`reshape` fills the new grid row by row. The original array is not changed. A shape with the wrong number of values raises an error, which we catch so that the message can be shown. Using `-1` lets NumPy compute one length.

```python run
import numpy as np

a = np.arange(6)
g = a.reshape(2, 3)
print(g.tolist(), g.shape)
print(a.shape)
print(a.reshape(-1, 2).tolist())
print(a.reshape(3, -1).shape)
try:
    a.reshape(4, 2)
except ValueError as e:
    print("ValueError:", e)
```

```output
[[0, 1, 2], [3, 4, 5]] (2, 3)
(6,)
[[0, 1], [2, 3], [4, 5]]
(3, 2)
ValueError: cannot reshape array of size 6 into shape (4,2)
```

### Example 5: A realistic set-up, hourly temperatures

Hourly readings for two days are stored as one flat list of 48 values. We build them with `linspace`, reshape them into a table of days by hours, and use the attributes to check the table before doing anything else. Rounding keeps the printed numbers stable.

```python run
import numpy as np

hours = np.linspace(10, 22, 48)
table = np.round(hours, 1).reshape(2, 24)
print(table.shape, table.ndim, table.size)
rows = table.tolist()
print(rows[0][:4])
print(rows[1][-3:])
print(table.dtype)
print(table.astype(int).tolist()[0][:4])
```

```output
(2, 24) 2 48
[10.0, 10.3, 10.5, 10.8]
[21.5, 21.7, 22.0]
float64
[10, 10, 10, 10]
```

## Real-world applications

- **Loading numeric columns.** A column of prices or sensor values becomes a float array. Checking `dtype` and `shape` straight after loading catches columns that arrived as text or tables loaded the wrong way round, as in the temperature table of Example 5.
- **Generating test and simulation data.** `arange` builds ID or time sequences and `linspace` builds even grids, such as 100 points between a minimum and a maximum for a chart axis or a what-if analysis.
- **Preparing data for models.** Statistical and machine-learning libraries expect numeric 2D arrays with one row per record. `reshape` and `astype` are the tools that put raw lists into that form.
- **Saving memory.** Choosing a smaller dtype (for example `float32` instead of `float64`) halves the memory of a large measurement table when the extra precision is not needed.

## Daily review

### Key takeaways

- An ndarray stores values of one dtype in one block of memory, which is why it is fast and compact.
- `shape`, `ndim`, `size` and `dtype` are attributes (no parentheses) and describe any array.
- `arange` excludes its stop value; `linspace` includes both ends and takes a count.
- Mixed values are upcast to the most general dtype; `astype` returns a converted copy.
- `reshape` needs the same number of values and fills row by row; `-1` means "work it out".

### Common mistakes

- Writing `a.shape()` with parentheses, which raises `TypeError: 'tuple' object is not callable`. Drop the parentheses.
- Expecting `np.arange(1, 5)` to include 5. It gives `[1, 2, 3, 4]`.
- Putting one text value in a numeric array and getting every value as text. The dtype shows a text kind instead of a number kind.
- Reshaping to a size that does not match, which raises `ValueError: cannot reshape array of size 6 into shape (4,2)`. Multiply the new lengths and compare with `size`.
- Expecting `astype(int)` to round. It truncates towards zero, so 2.9 becomes 2. Call `np.round` first.
- Using `np.zeros(2, 3)` instead of `np.zeros((2, 3))`. The shape is one tuple argument.

### Revision notes

- `np.array`, `zeros`, `ones`, `full`, `arange`, `linspace`.
- `a.shape` is a tuple, `a.ndim` is its length, `a.size` is the product.
- One dtype per array; upcast order is bool, int, float, text.
- `astype` returns a new array; `reshape(-1, n)` infers rows.
