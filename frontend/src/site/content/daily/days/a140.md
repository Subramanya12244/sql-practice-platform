## Objectives

- Define a KPI with a name, formula, owner, period, target and direction, and reject vague KPIs.
- Compute variance to target, in absolute and percentage terms, with the direction of good taken into account.
- Write a RAG (red, amber, green) status rule as a function and apply it consistently.
- Add context to a number: previous period, rolling average and year to date against target.
- Build a scorecard table in pandas and read it.

## Understand

### What a KPI is

A **KPI** (key performance indicator) is a measure chosen because it tells you whether you are achieving a specific goal. Not every number is a KPI. Revenue is a measure; "monthly revenue against the 5,500 target, owned by the commercial director, reviewed every month" is a KPI. The difference is the goal, the owner and the review. A page of fifty numbers is a report; a page of five KPIs is a scorecard. A good KPI has a clear **definition** that two analysts would compute identically (which orders count, which dates, which currency), a **target** that someone agreed, an **owner** who can act on it, a **period** (month, quarter, year to date), and a **direction**: whether higher is better (revenue) or lower is better (days to ship, cost per order). Without a direction the same variance means opposite things, and without a target the number cannot be judged.

Choose few KPIs. A useful discipline is to start from the decisions: if no one would do anything differently whether the number is up or down, it is not a KPI. Keep each KPI tied to one goal and avoid metrics that can be driven up without helping the business (Day 143 returns to this). Define a KPI once, in one place, and reuse the definition on every page, in the same way that measures are explicit in Power BI (Day 129).

### Targets and variance

A **target** is the value the KPI should reach in the period. Targets should be set from something real: last year's value with an agreed growth, a budget, a capacity, a service-level promise. **Variance** is the gap between the actual value and the target, and it is usually shown in two forms: the **absolute variance**, actual minus target (+567.50), and the **percentage variance**, that gap divided by the target (+10.3%). Show both when the reader needs the size and the proportion. Another common view is **attainment**: actual divided by target, so 110.3% means the target was exceeded by a tenth.

The direction matters. For a KPI where higher is better, a positive variance is favourable. For one where lower is better, such as average days to ship, the same positive variance is unfavourable. A scorecard function should take the direction as a parameter and return a **favourable** or **unfavourable** reading and not leave it to the reader. Also decide how to treat a zero target, where percentage variance is undefined, rather than letting the division fail.

### RAG status

**RAG** stands for red, amber, green, a traffic-light summary of a KPI against its target. It is a rule, so write it down and apply it identically to every KPI. A common rule for higher-is-better KPIs: green when attainment is 100% or more, amber from 90% up to but not including 100%, red below 90%. For lower-is-better KPIs the thresholds mirror: green when actual is at most the target, amber up to 10% above, red above that. The thresholds are a business choice and should be agreed with the KPI owner, and the boundary cases (exactly 100%, exactly 90%) must be defined, because the logic of the function is the only place where they are settled. Two cautions: colour should not be the only signal (add the variance or a symbol), and RAG hides magnitude, so a KPI at 99.9% and one at 90.1% are both amber although they are very different.

### Context for numbers

A number without context is hard to judge: 6,067.50 in December could be good or bad. Context comes from comparisons chosen to answer a question. **Target** says whether we are where we planned. **Previous period** (last month, or the same month last year) says which way we are moving. A **rolling average** (for example the last three months) smooths noise, so one odd month does not trigger a reaction. **Year to date against year-to-date target** shows whether a good December hides a poor start. A scorecard shows each KPI with several of these side by side: actual, target, variance, status and a small trend. Be careful that the comparisons are like for like: the same definition, the same period length and a complete period. Comparing the first half of a month with a full previous month makes any KPI look bad.

### Why it matters

KPIs steer behaviour. People optimise what is measured, so a badly defined KPI produces badly aimed effort. A scorecard with clear definitions, targets and statuses turns a meeting from "is this number right?" into "what do we do about it?". The misconception is that a KPI is simply an important number. Without a target, an owner and a direction, it is only a number.

## Syntax and key functions

The scorecard is built with ordinary pandas and Python. The pieces and the formulas:

| Quantity | Formula |
|---|---|
| Absolute variance | `actual - target` |
| Percentage variance | `(actual - target) / target` |
| Attainment | `actual / target` |
| RAG, higher is better | green at or above 1.00, amber from 0.90, otherwise red |
| RAG, lower is better | green at or below 1.00, amber up to 1.10, otherwise red |
| Previous period change | `current / previous - 1` |
| Rolling average | `series.rolling(3).mean()` |
| Year to date | `series.cumsum()` within the year |

```python
def attainment(actual, target, higher_is_better=True):
    return actual / target if higher_is_better else target / actual
```

## Learn by example

### Example 1: A KPI is a complete definition

A KPI record has fields; a function reports what is missing.

```python run
REQUIRED = ["name", "formula", "owner", "period", "target", "direction"]

kpis = [
    {"name": "Monthly revenue", "formula": "sum(quantity * unit_price)", "owner": "Commercial director", "period": "month", "target": 5500, "direction": "higher"},
    {"name": "Customer happiness", "formula": "", "owner": None, "period": "month", "target": None, "direction": "higher"},
    {"name": "Days to ship", "formula": "mean(ship_days)", "owner": "Operations lead", "period": "month", "target": 4.0, "direction": "lower"},
]

def missing(kpi):
    return [f for f in REQUIRED if kpi.get(f) in (None, "")]

for k in kpis:
    gaps = missing(k)
    print(k["name"], "complete" if not gaps else "missing " + ", ".join(gaps))
```

```output
Monthly revenue complete
Customer happiness missing formula, owner, target
Days to ship complete
```

The first and third KPIs are complete. "Customer happiness" has no formula, owner or target, so nobody can compute it the same way twice or be accountable for it. It is a wish, not a KPI. Writing the record is the cheapest quality check.

### Example 2: Variance with a direction

Compute absolute and percentage variance and a favourable or unfavourable reading.

```python run
import numpy as np
import pandas as pd

rng = np.random.default_rng(7)
countries = ["UK", "Germany", "France", "Spain"]
cats = ["Hardware", "Software", "Services"]
customers = pd.DataFrame({
    "customer_id": range(1, 41),
    "customer_name": [f"Customer {i:02d}" for i in range(1, 41)],
    "country": [countries[i % 4] for i in range(40)],
    "segment": [["Retail", "Corporate"][(i // 4) % 2] for i in range(40)],
})
products = pd.DataFrame({
    "product_id": range(1, 13),
    "product_name": [f"Product {i:02d}" for i in range(1, 13)],
    "category": [cats[i % 3] for i in range(12)],
    "unit_cost": [float(10 + 5 * i) for i in range(12)],
})
n = 400
sales = pd.DataFrame({
    "order_id": range(1, n + 1),
    "order_date": pd.to_datetime("2025-01-01") + pd.to_timedelta(rng.integers(0, 365, n), unit="D"),
    "customer_id": rng.integers(1, 41, n),
    "product_id": rng.integers(1, 13, n),
    "quantity": rng.integers(1, 6, n),
})
sales["unit_price"] = (sales["product_id"].map(products.set_index("product_id")["unit_cost"]) * 1.5).round(2)
calendar = pd.DataFrame({"date": pd.date_range("2025-01-01", "2025-12-31")})
calendar["year"] = calendar["date"].dt.year
calendar["quarter"] = calendar["date"].dt.quarter
calendar["month_number"] = calendar["date"].dt.month
calendar["month_name"] = calendar["date"].dt.strftime("%B")
sales["revenue"] = sales["quantity"] * sales["unit_price"]
fact = (sales.merge(customers, on="customer_id").merge(products, on="product_id")
        .merge(calendar, left_on="order_date", right_on="date"))
monthly = fact.groupby(fact["order_date"].dt.to_period("M"))["revenue"].sum()

def variance(actual, target, higher_is_better=True):
    absolute = actual - target
    pct = absolute / target * 100 if target else None
    good = absolute >= 0 if higher_is_better else absolute <= 0
    return round(absolute, 2), (round(pct, 1) if pct is not None else None), "favourable" if good else "unfavourable"

print(variance(float(monthly["2025-12"]), 5500))
print(variance(float(monthly["2025-03"]), 5500))
print(variance(4.6, 4.0, higher_is_better=False))
print(variance(3.8, 4.0, higher_is_better=False))
print(variance(10, 0))
```

```output
(567.5, 10.3, 'favourable')
(-872.5, -15.9, 'unfavourable')
(0.6, 15.0, 'unfavourable')
(-0.2, -5.0, 'favourable')
(10, None, 'favourable')
```

December revenue of 6,067.50 is 567.50 above the 5,500 target, +10.3%, favourable. March at 4,627.50 is 872.50 below, -15.9%, unfavourable. For days to ship (lower is better), 4.6 against 4.0 is +0.6 and unfavourable, and 3.8 is -0.2 and favourable: the same sign of variance means opposite things. A zero target returns `None` for the percentage instead of failing.

### Example 3: A RAG function applied to a year

Apply a documented rule to every month of 2025.

```python run
import numpy as np
import pandas as pd

rng = np.random.default_rng(7)
countries = ["UK", "Germany", "France", "Spain"]
cats = ["Hardware", "Software", "Services"]
customers = pd.DataFrame({

    "customer_name": [f"Customer {i:02d}" for i in range(1, 41)],
    "country": [countries[i % 4] for i in range(40)],
    "segment": [["Retail", "Corporate"][(i // 4) % 2] for i in range(40)],
})
products = pd.DataFrame({
    "product_id": range(1, 13),
    "product_name": [f"Product {i:02d}" for i in range(1, 13)],
    "category": [cats[i % 3] for i in range(12)],
    "unit_cost": [float(10 + 5 * i) for i in range(12)],
})
n = 400
sales = pd.DataFrame({
    "order_id": range(1, n + 1),
    "order_date": pd.to_datetime("2025-01-01") + pd.to_timedelta(rng.integers(0, 365, n), unit="D"),
    "customer_id": rng.integers(1, 41, n),
    "product_id": rng.integers(1, 13, n),
    "quantity": rng.integers(1, 6, n),
})
sales["unit_price"] = (sales["product_id"].map(products.set_index("product_id")["unit_cost"]) * 1.5).round(2)
calendar = pd.DataFrame({"date": pd.date_range("2025-01-01", "2025-12-31")})
calendar["year"] = calendar["date"].dt.year
calendar["quarter"] = calendar["date"].dt.quarter
calendar["month_number"] = calendar["date"].dt.month
calendar["month_name"] = calendar["date"].dt.strftime("%B")
sales["revenue"] = sales["quantity"] * sales["unit_price"]
fact = (sales.merge(customers, on="customer_id").merge(products, on="product_id")
        .merge(calendar, left_on="order_date", right_on="date"))
monthly = fact.groupby(fact["order_date"].dt.to_period("M"))["revenue"].sum()

def rag(actual, target, higher_is_better=True):
    ratio = actual / target if higher_is_better else target / actual
    if ratio >= 1.0:
        return "green"
    if ratio >= 0.9:
        return "amber"
    return "red"

status = monthly.map(lambda v: rag(float(v), 5500))
print(pd.DataFrame({"revenue": monthly, "attainment_pct": (monthly / 5500 * 100).round(1), "status": status}).to_string())
print(status.value_counts().sort_index().to_dict())
print(rag(5500, 5500), rag(4950, 5500), rag(4949.99, 5500))
```

```output
            revenue  attainment_pct status
order_date                                
2025-01      5160.0            93.8  amber
2025-02      5475.0            99.5  amber
2025-03      4627.5            84.1    red
2025-04      5280.0            96.0  amber
2025-05      5512.5           100.2  green
2025-06      6045.0           109.9  green
2025-07      6225.0           113.2  green
2025-08      5235.0            95.2  amber
2025-09      5730.0           104.2  green
2025-10      5122.5            93.1  amber
2025-11      6652.5           121.0  green
2025-12      6067.5           110.3  green
{'amber': 5, 'green': 6, 'red': 1}
green amber red
```

Six months are green, five amber and one red. The last line tests the boundaries: exactly 100% is green, exactly 90% (4,950) is amber and just under is red. Without a test like this, the same rule can be implemented differently in two reports, and the same month would show two colours.

dec = monthly["2025-12"]

ytd_target = target * 12

    "actual": round(float(dec), 2),
    "target": target,
    "vs_target_pct": round(float((dec / target - 1) * 100), 1),
    "vs_prev_month_pct": round(float((dec / prev - 1) * 100), 1),
    "rolling_3m_avg": round(float(roll3), 2),
    "ytd": round(float(ytd), 2),

The four comparisons tell different stories (above target, down on November, above trend, above plan for the year), which is why a scorecard shows several and the reader does not rely on one.

### Example 5: A lower-is-better KPI

Average days to ship per month against a target of 4.0 days or less. The shipping days are generated in code for the exercise.

```python run
import numpy as np
import pandas as pd

rng = np.random.default_rng(7)
countries = ["UK", "Germany", "France", "Spain"]
cats = ["Hardware", "Software", "Services"]
customers = pd.DataFrame({
    "customer_id": range(1, 41),
    "customer_name": [f"Customer {i:02d}" for i in range(1, 41)],
    "country": [countries[i % 4] for i in range(40)],
    "segment": [["Retail", "Corporate"][(i // 4) % 2] for i in range(40)],
})
products = pd.DataFrame({
    "product_id": range(1, 13),
    "product_name": [f"Product {i:02d}" for i in range(1, 13)],
    "category": [cats[i % 3] for i in range(12)],
    "unit_cost": [float(10 + 5 * i) for i in range(12)],
})
n = 400
sales = pd.DataFrame({
    "order_id": range(1, n + 1),
    "order_date": pd.to_datetime("2025-01-01") + pd.to_timedelta(rng.integers(0, 365, n), unit="D"),
    "customer_id": rng.integers(1, 41, n),
    "product_id": rng.integers(1, 13, n),
    "quantity": rng.integers(1, 6, n),
})
sales["unit_price"] = (sales["product_id"].map(products.set_index("product_id")["unit_cost"]) * 1.5).round(2)
calendar = pd.DataFrame({"date": pd.date_range("2025-01-01", "2025-12-31")})
calendar["year"] = calendar["date"].dt.year
calendar["quarter"] = calendar["date"].dt.quarter
calendar["month_number"] = calendar["date"].dt.month
calendar["month_name"] = calendar["date"].dt.strftime("%B")
sales["revenue"] = sales["quantity"] * sales["unit_price"]
fact = (sales.merge(customers, on="customer_id").merge(products, on="product_id")
        .merge(calendar, left_on="order_date", right_on="date"))
ship = pd.Series(rng.integers(1, 8, len(sales)), index=sales.index, name="ship_days")
by_month = ship.groupby(sales["order_date"].dt.to_period("M")).mean().round(2)

def rag_low(actual, target):
    ratio = target / actual
    return "green" if ratio >= 1.0 else ("amber" if ratio >= 0.9 else "red")

table = pd.DataFrame({"avg_days": by_month, "status": by_month.map(lambda v: rag_low(float(v), 4.0))})
print(table.head(6).to_string())
print(table["status"].value_counts().sort_index().to_dict())
```

```output
            avg_days status
order_date                 
2025-01         4.13  amber
2025-02         3.85  green
2025-03         4.06  amber
2025-04         3.68  green
2025-05         4.13  amber
2025-06         4.67    red
{'amber': 5, 'green': 5, 'red': 2}
```

Months at or below 4.0 days are green, up to 4.44 are amber and anything above is red. The code uses the target divided by the actual, so the same ratio thresholds work as for higher-is-better KPIs. In the table, January at 4.13 days is amber, although a naive reading ("above 4, so red") would call it red: the rule is explicit, so the status is not a matter of opinion.

## Real-world applications

- **Monthly business review scorecard.** Five KPIs with target, variance, status and trend on one page, built from a definition table (Examples 1 and 4).
- **Operational monitoring.** Service-level KPIs where lower is better (waiting time, delivery days) with direction-aware status (Examples 2 and 5).
- **Budget tracking.** Year-to-date against year-to-date target shows whether a strong month hides a weak year (Example 4).
- **Governance.** A KPI register with owner, formula and target prevents two teams reporting different numbers under the same name.

## Daily review

### Key takeaways

- A KPI has a definition, target, owner, period and direction; otherwise it is only a measure.
- Variance is actual minus target, in absolute and percentage form; direction decides favourable or not.
- RAG is a documented rule with tested boundaries, not an impression.
- Context (target, previous period, rolling average, YTD) turns a number into a judgement.
- Fewer KPIs, each tied to a decision.

### Common mistakes

- Showing a number with no target or comparison, so the reader cannot tell if it is good.
- Treating a positive variance as good for a lower-is-better KPI.
- Letting different reports use different RAG thresholds or boundary rules.
- Comparing a partial period with a complete one.
- Dividing by a zero target and showing an error or infinity instead of handling it.

### Revision notes

- KPI = name, formula, owner, period, target, direction.
- Variance, percentage variance, attainment.
- RAG function with boundary tests; mirror it for lower-is-better.
- Context: target, previous period, rolling average, YTD against target.
