## Objectives

- Recognise the four common kinds of mess in business workbooks: merged cells, multi-row headers, subtotal and footer rows, and values stored with the wrong type.
- Read a sheet without a header, find the header row and the first and last data rows by rule instead of by fixed position.
- Flatten a two-row header with a merged group label into one clean column name per column.
- Repair numbers, dates and missing-value markers, including text amounts such as `(1,250.00)` and `-`.
- Check a repaired table against the total the sheet itself reports, and explain why a footer is evidence, not data.

## Understand

### Why spreadsheets become messy

A spreadsheet is designed to be read by people, so its author optimises for the eye. A title across the top, a coloured band that says "Q1" above three month columns, a blank row to separate blocks, a subtotal after each group and a line at the bottom saying "Source: Finance, prepared 3 Feb" all make the sheet easier to read and harder to load. None of that is data, and none of it is marked as decoration. A pipeline has to tell the real rows from the dressing using rules that survive next month's edition of the file.

The general method is the same on every messy sheet. **Read the raw cells with no interpretation** (no header, no type guessing). **Describe the layout** with a few facts you can compute: which row holds the column names, where the data starts, where it ends. **Reshape** to one header row and one record per row. **Repair types** column by column. **Check** the result against something the sheet itself offers, such as its total.

### Merged cells

A **merged cell** is a rectangle of cells that Excel treats as one. Merging is mostly cosmetic, for example a "Q1" label centred over the columns Jan, Feb and Mar. In the file, only the **top-left cell** of the merged range holds the value; the other cells in the range are empty. A program reading row by row therefore sees `"Q1", None, None` where a person sees "Q1 over all three". With `openpyxl` you can list the ranges with `ws.merged_cells.ranges` and unmerge them with `ws.unmerge_cells("B3:D3")`, after which you copy the value into the rest of the range yourself. With pandas the usual repair is a **forward fill** (`ffill`), which copies the last non-empty value to the empty cells after it. Forward fill is only correct when the gaps are merged cells. If a gap means "not available" it would invent data, so decide per column.

### Multi-row headers

A header that spans two or more rows (group label above, member label below) cannot be a DataFrame header as it is, because a DataFrame wants one name per column. Two repairs exist. You can read with `header=[2, 3]` and get a column **MultiIndex**, a two-level label, which is useful for analysis but awkward to load into a database. The pipeline repair is to **flatten**: forward-fill the top row, then join the two labels with an underscore, giving `q1_jan`, `q1_feb`, `q1_mar`. Lowercase names with no spaces become column names in a database table without quoting. A column whose group label has no member label (such as `Region`) keeps its single name.

### Finding the table by rule

A fixed rule such as "the header is on row 5" breaks the day someone inserts a line. Look for a **landmark** instead: the header row is the first row in which the cell in column A equals `Region`; the data begins on the next row that has a non-empty first cell after the header block; the data ends before the first row whose first cell starts with `Total`, `Subtotal` or `Source`, or that is completely empty. Landmarks are text the business is unlikely to change because the readers depend on them. If a landmark is missing the pipeline should stop with a message, not guess.

### Footers, subtotals and notes

Rows such as `Subtotal North` and `Total` are **derived**: they repeat information already in the rows above. Loading them next to the detail rows doubles every sum, the most expensive silent error in reporting. Drop them from the data, but keep the total: after repair, the sum of your detail rows should equal the footer's reported total. When it does not, something was dropped, duplicated or misread, and the difference tells you how much. This is a small **reconciliation**, the habit Day 100 turns into a full report.

### Type repair

Business workbooks store numbers as text for good reasons: `$1,250.50` shows a currency symbol, `(300.00)` means negative 300 in accounting notation, `12%` is a percentage, `-` or `n/a` means not applicable, and a trailing space or a non-breaking space (the character ` `, which looks like a space but is not equal to one) sneaks in from copied web pages. Repair in a fixed order: strip whitespace, replace marker strings with missing values, handle the parentheses as a sign, remove currency symbols and thousands separators, then convert with `pd.to_numeric(..., errors="coerce")`. **Count what became missing**: a coerced value that was not on your list of known markers is a bug in the data or in the rule, and should be listed, not hidden. Dates have the same trouble: `05/01/2026` is 5 January in some countries and 1 May in others. State the format explicitly with `pd.to_datetime(s, format="%d/%m/%Y")`.

### Common misconception

Learners try to make one generic cleaner for all sheets. The better design is a small function per layout, with the landmarks and repairs written down, and a check that fails when the layout changes. A generic cleaner passes bad data without a sound.

### Why it matters

Messy workbooks are the normal case for finance, operations and partner data. The difference between a pipeline that runs for two years and one that is rewritten every quarter is whether its assumptions about the layout are explicit and checked.

## Syntax and key functions

Inspecting merged cells and unmerging with openpyxl:

```python
from openpyxl import load_workbook

wb = load_workbook("report.xlsx")
ws = wb.active
print(ws.merged_cells.ranges)          # e.g. [<MergedCellRange B3:D3>]
ws.unmerge_cells("B3:D3")              # value stays in B3; C3 and D3 become empty
```

Reading raw and reshaping with pandas:

```python
raw = pd.read_excel("report.xlsx", header=None)      # no header, no interpretation
top = raw.iloc[2].ffill()                            # fill merged group labels
sub = raw.iloc[3]
names = [f"{t}_{s}" if pd.notna(s) and pd.notna(t) else (s if pd.notna(s) else t)
         for t, s in zip(top, sub)]
```

| Item | What it does or returns |
|---|---|
| `pd.read_excel(path, header=None)` | Raw cell grid; columns numbered from 0. |
| `df.iloc[r]`, `df.iloc[a:b]` | A row, or a block of rows, by position. |
| `Series.ffill()` | Copies the last non-missing value forward over gaps. |
| `Series.str.strip()`, `.str.replace(pat, repl, regex=...)` | Whitespace and symbol clean-up. |
| `Series.str.startswith(prefix, na=False)` | Boolean test used to find footer rows. |
| `pd.to_numeric(s, errors="coerce")` | Numbers; invalid text becomes `NaN`. |
| `pd.to_datetime(s, format=...)` | Dates with an explicit format. |
| `df.melt(id_vars, var_name, value_name)` | Wide columns to long rows. |
| `ws.merged_cells.ranges`, `ws.unmerge_cells(range)` | List and remove merges (openpyxl). |

## Learn by example

### Example 1: What a merged header looks like in the file

The code builds a small messy workbook: a title, a group header "Q1" merged over three columns, month names, two data rows and a footer. It then shows what a program sees: the merge range, the value only in the top-left cell, and the raw rows pandas reads with `header=None`. This needs `openpyxl`, so it is a local example.

```python local
import os
import tempfile

import pandas as pd
from openpyxl import Workbook, load_workbook

with tempfile.TemporaryDirectory() as folder:
    path = os.path.join(folder, "messy.xlsx")
    wb = Workbook()
    ws = wb.active
    ws["A1"] = "Regional sales 2026"
    ws["A3"], ws["B3"] = "Region", "Q1"
    ws.merge_cells("B3:D3")
    for col, month in zip("BCD", ["Jan", "Feb", "Mar"]):
        ws[f"{col}4"] = month
    ws.append(["North", 10, 12, 9])
    ws.append(["South", 7, 8, 11])
    ws.append(["Total", 17, 20, 20])
    wb.save(path)

    ws2 = load_workbook(path).active
    print([str(r) for r in ws2.merged_cells.ranges])
    print(ws2["B3"].value, ws2["C3"].value, ws2["D3"].value)
    raw = pd.read_excel(path, header=None)
    print(raw.shape)
    print(raw.iloc[2].tolist())
    print(raw.iloc[3].tolist())
```

```output
['B3:D3']
Q1 None None
(7, 4)
['Region', 'Q1', nan, nan]
[nan, 'Jan', 'Feb', 'Mar']
```

The two lines of cell values show the problem: `Q1` followed by `None` twice, and a raw grid whose first rows are decoration (`NaN` is pandas' marker for an empty cell).

### Example 2: Flatten a two-row header (browser-safe)

The DataFrame `raw` is what `read_excel(header=None)` would return for a sheet with a title, a blank row, a merged group header and a member header. The code locates the header row by its landmark (`Region` in column 0), forward-fills the group labels, joins group and member into one lowercase name and keeps the data rows below.

```python run
import pandas as pd

nan = float("nan")
raw = pd.DataFrame([
    ["Regional sales 2026", nan, nan, nan, nan, nan],
    [nan, nan, nan, nan, nan, nan],
    ["Region", "Q1", nan, nan, "Q2", nan],
    [nan, "Jan", "Feb", "Mar", "Apr", "May"],
    ["North", 10, 12, 9, 14, 15],
    ["South", 7, 8, 11, 6, 9],
])

top_row = raw.index[raw[0] == "Region"][0]
group = raw.iloc[top_row].ffill()
member = raw.iloc[top_row + 1]
names = []
for g, m in zip(group, member):
    names.append(f"{g}_{m}".lower() if pd.notna(m) else str(g).lower())
data = raw.iloc[top_row + 2:].copy()
data.columns = names
print(names)
print(data.reset_index(drop=True))
```

```output
['region', 'q1_jan', 'q1_feb', 'q1_mar', 'q2_apr', 'q2_may']
  region q1_jan q1_feb q1_mar q2_apr q2_may
0  North     10     12      9     14     15
1  South      7      8     11      6      9
```

`Region` has no member label, so it keeps its own name. The group label `Q2` was copied into column 5 by `ffill`, so `May` becomes `q2_may`.

### Example 3: Find the data block and drop footers

The table has a subtotal row after each region and a footer. The code detects the data end with a rule (first cell starts with `Subtotal`, `Total` or `Source`), keeps the detail rows and remembers the footer total for the check. A missing landmark raises an error instead of guessing.

```python run
import pandas as pd

nan = float("nan")
raw = pd.DataFrame([
    ["Sales by product", nan, nan],
    ["Product", "Region", "Amount"],
    ["Pen", "North", 120],
    ["Pen", "South", 80],
    ["Subtotal Pen", nan, 200],
    ["Book", "North", 300],
    ["Book", "South", 50],
    ["Subtotal Book", nan, 350],
    ["Total", nan, 550],
    ["Source: finance", nan, nan],
])

def extract(raw):
    hits = raw.index[raw[0] == "Product"]
    if len(hits) != 1:
        raise ValueError("header landmark 'Product' not found exactly once")
    header_row = hits[0]
    body = raw.iloc[header_row + 1:]
    first = body[0].astype(str)
    is_note = first.str.startswith(("Subtotal", "Total", "Source"))
    detail = body[~is_note].copy()
    detail.columns = [c.lower() for c in raw.iloc[header_row]]
    reported = float(body.loc[first == "Total", 2].iloc[0])
    return detail.reset_index(drop=True), reported

detail, reported = extract(raw)
print(detail)
print(detail["amount"].sum(), reported, detail["amount"].sum() == reported)
try:
    extract(raw.iloc[2:])
except ValueError as err:
    print(err)
```

```output
  product region amount
0     Pen  North    120
1     Pen  South     80
2    Book  North    300
3    Book  South     50
550 550.0 True
header landmark 'Product' not found exactly once
```

The rows are not misread; they are classified by a rule. The sum of the detail rows equals the reported total, which is the evidence that nothing was lost.

### Example 4: Repair types and count what you could not read

The amount column mixes accounting negatives, currency symbols, thousands separators, marker strings and a non-breaking space. The function repairs them in a fixed order and returns the numbers plus the list of original values that became missing without being a known marker, so a surprise is visible. Dates use an explicit day-first format.

```python run
import pandas as pd

amounts = pd.Series(["$1,250.50", "(300.00)", " 99 ", "-", "n/a", "12 ", "twelve"])
MARKERS = {"-", "n/a", ""}

def repair_amount(s):
    text = s.astype(str).str.replace(" ", " ", regex=False).str.strip()
    is_marker = text.str.lower().isin(MARKERS)
    negative = text.str.startswith("(") & text.str.endswith(")")
    cleaned = text.str.replace(r"[()$,\s]", "", regex=True)
    values = pd.to_numeric(cleaned.where(~is_marker), errors="coerce")
    values = values.where(~negative, -values)
    unexpected = text[values.isna() & ~is_marker].tolist()
    return values, unexpected

values, unexpected = repair_amount(amounts)
print(values.tolist())
print(unexpected)

dates = pd.Series(["05/01/2026", "31/01/2026"])
parsed = pd.to_datetime(dates, format="%d/%m/%Y")
print(parsed.dt.strftime("%Y-%m-%d").tolist())
```

```output
[1250.5, -300.0, 99.0, nan, nan, 12.0, nan]
['twelve']
['2026-01-05', '2026-01-31']
```

`twelve` is the only unexpected value: it is missing after conversion but it is not a known marker, so the pipeline would report it rather than treat it like `n/a`.

## Real-world applications

- **Budget workbooks with group headers.** A department sends quarterly figures with merged quarter labels. Flattening to `q1_jan` style names and melting to long rows gives one row per department and month, ready for a table.
- **Finance reports with subtotals.** Dropping `Subtotal` and `Total` rows by rule, then checking the detail sum against the reported total, prevents the doubled revenue a naive load would produce.
- **Partner price lists.** Prices arrive as `$1,250.50` and `(300.00)` credits. A fixed repair order and a list of unexpected values catches `twelve` before it reaches the warehouse.
- **Monthly re-delivery.** Landmark rules (find `Region`, stop at `Total`) survive an inserted title line; a fixed row number would not.

## Daily review

### Key takeaways

- Read raw first, describe the layout with computed facts, then reshape.
- A merged range stores its value only in the top-left cell; forward fill restores the rest when gaps are merges.
- Flatten multi-row headers to one lowercase name per column.
- Subtotal and footer rows are derived data; remove them and use the footer total as a check.
- Repair types in a fixed order and report values that became missing unexpectedly.

### Common mistakes

- **Forward fill on a data column.** `ffill` on `amount` invents values for blanks that meant "none". Use it only on label columns that came from merges.
- **Fixed row numbers.** `skiprows=4` fails when a title line is added. Find the header with a landmark.
- **Loading the total row.** The sum doubles. Filter rows whose first cell starts with `Total`, and compare instead.
- **Converting with `errors="coerce"` and moving on.** Typos become `NaN` silently. Count and list the unexpected ones.
- **Day-first dates parsed month-first.** `05/01/2026` becomes 1 May. Pass `format=`.

### Revision notes

- Read with `header=None`, locate landmarks, slice, flatten headers.
- `ffill` for merged labels only.
- Drop rows by prefix (`Subtotal`, `Total`, `Source`), keep the reported total for a check.
- Repair order: strip, markers, parentheses sign, symbols, `to_numeric`.
- Always report unexpected values.
