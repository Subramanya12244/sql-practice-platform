## Objectives

- Apply arithmetic and comparison operators to whole arrays instead of writing loops.
- Apply the broadcasting rules to decide whether two shapes can be combined, and what shape results.
- Use universal functions such as `np.sqrt`, `np.exp`, `np.abs`, `np.round`, `np.maximum` and `np.where`.
- Rewrite a Python loop over numbers as one vectorised expression and check that both give the same answer.
- Explain broadcasting errors such as `operands could not be broadcast together` and fix them with `reshape` or `[:, None]`.

## Understand

### Vectorisation: the loop moves inside NumPy

To double a list of numbers in plain Python you write a loop or a comprehension: `[x * 2 for x in values]`. With an array you write `a * 2`. This is **vectorisation**: an operation is applied to every element of an array in one expression, and the looping happens inside NumPy's compiled code rather than in the Python interpreter. The behaviour is **element-wise**, meaning that position 0 is combined with position 0, position 1 with position 1, and so on. So `a + b` adds two arrays of the same shape position by position, `a * b` multiplies them position by position (this is not matrix multiplication), and `a > 3` compares every element with 3 and returns a boolean array, the mask you used on Day 64.

Vectorisation matters for two reasons. The code is shorter and closer to the way you would describe the calculation in words, "price times quantity", and it is much faster on large arrays, often by a factor of 50 to 100, because the per-element cost of the interpreter disappears. Fast, readable code is the reason analysts reach for NumPy and, later, pandas.

A mental model: imagine a row of calculators, one per element, all given the same instruction at once. The instruction `a * 2` is sent to every calculator and each one works on its own value.

### Operators and universal functions

The ordinary operators `+`, `-`, `*`, `/`, `//`, `%` and `**` all work element-wise, and so do the comparisons `==`, `!=`, `<`, `<=`, `>` and `>=`. Beyond the operators there are **universal functions**, usually called ufuncs: functions that take an array and apply a calculation to each element, returning an array of the same shape. Examples are `np.sqrt`, `np.exp`, `np.log`, `np.abs`, `np.round`, `np.floor`, `np.ceil`, `np.minimum` and `np.maximum`. The last two take two arrays (or an array and a number) and pick the smaller or larger value at each position: `np.maximum(a, 0)` replaces every negative value with 0. Note that these ufuncs are different from the aggregations of Day 66, which reduce an array to fewer numbers.

`np.where(condition, x, y)` is the vectorised "if". It looks at a boolean mask and takes the value from `x` where the mask is true and from `y` where it is false: `np.where(a >= 50, "pass", "fail")` labels every score. It replaces a loop with an `if` statement inside.

### Broadcasting: combining different shapes

What if the two arrays do not have the same shape? `a + 100` already does this: the single number 100 is stretched to match `a`. **Broadcasting** is the general rule that lets NumPy combine arrays of different shapes without copying data. NumPy compares the two shapes starting from the **last** dimension and moving left. Two dimensions are compatible when they are equal, or when one of them is 1. A dimension of length 1 is stretched to match the other. If one array has fewer dimensions, 1s are added on its left. If any pair of dimensions is neither equal nor 1, the operation fails.

Some worked cases. Shape `(3, 4)` with shape `(4,)`: compare 4 with 4, fine, then the missing leading dimension is treated as 1 and stretched to 3. The row of four numbers is added to every row. Shape `(3, 4)` with shape `(3,)`: compare 4 with 3, which is neither equal nor 1, so this raises `ValueError: operands could not be broadcast together with shapes (3,4) (3,)`. Shape `(3, 4)` with shape `(3, 1)`: compare 4 with 1 (stretch), then 3 with 3, fine. The column of three numbers is combined with every column. This gives you a way to apply one value per row: add an axis with `[:, None]` or `reshape(-1, 1)` to turn a flat array of shape `(3,)` into a column of shape `(3, 1)`.

Two flat arrays of shape `(3,)` and `(4,)` fail, but `(3, 1)` with `(4,)` works and produces a `(3, 4)` table, in which every pair of values is combined. That is the standard way to build a multiplication table or a grid of all combinations.

### Common misconception

There are two. The first is thinking `a * b` is a matrix product or a dot product. It is a position-by-position product. The second is expecting a broadcast to "just work" when the lengths happen to be compatible by size, for example subtracting a per-row value of shape `(3,)` from a `(3, 4)` table. The rule is about aligning from the right, not about which length looks plausible, so the per-row array must be reshaped into a column first. The symptom is the `ValueError` above or, worse, a table of the right shape in which the numbers were applied along the wrong axis. When both axes happen to have the same length (for example a 3 by 3 table), broadcasting does not fail, and a wrong alignment is silent. Always print a small case and check one result by hand.

### Avoiding loops, and when a loop is still fine

The aim of vectorising is not to ban loops. A loop over a few dozen items, or one in which every step depends on the previous result, is fine. The rule of thumb is: if a loop goes over every element of a large array and does the same arithmetic on each, replace it with an array expression. You can verify the replacement by running both on a small array and comparing, which `np.array_equal` or `np.allclose` do. `allclose` is the right check for decimals, because floating-point results can differ in the last digits.

### Why it matters in data work

Unit conversions, percentage changes, normalisation (Day 67) and z-scores are all arithmetic applied to a whole column. Broadcasting is what lets you subtract a per-column mean from every row in one line. Understanding it also prevents silent errors: a shape bug that does not raise an error produces a plausible but wrong table. Printing the `shape` of each operand before combining them is the cheapest safeguard.

### Operations that change the type

Dividing integers with `/` always produces floats, even when the division is exact: `np.array([4, 6]) / 2` is `[2.0, 3.0]`. Floor division `//` keeps integers when both inputs are integers. Mixing an integer array with a float uses the upcasting rule from Day 63. Dividing by zero in an array does not raise an exception; it gives `inf` or `nan` and a warning, so check denominators with a mask before dividing when zeros are possible.

## Syntax and key functions

Element-wise operations:

```python
a + b
a * 2
a ** 2
a > 3
np.sqrt(a)
np.maximum(a, 0)
np.where(condition, if_true, if_false)
```

Broadcasting helpers:

```python
col = row_values[:, None]
col = row_values.reshape(-1, 1)
table = col + other_row
```

`[:, None]` adds a new axis of length 1 and turns shape `(n,)` into `(n, 1)`.

| Expression | Returns |
|---|---|
| `a + b`, `a * b` | Element-wise sum and product (same or broadcastable shapes). |
| `a / 2`, `a // 2`, `a % 2` | Element-wise true division, floor division, remainder. |
| `np.sqrt(a)`, `np.exp(a)`, `np.abs(a)` | Element-wise function, same shape. |
| `np.round(a, 1)` | Rounded values. |
| `np.maximum(a, b)` | Larger value at each position. |
| `np.where(mask, x, y)` | `x` where the mask is true, otherwise `y`. |
| `np.allclose(a, b)` | `True` if all values are close. |
| `a[:, None]` | `a` with an extra axis, `(n,)` becomes `(n, 1)`. |

## Learn by example

### Example 1: Element-wise arithmetic instead of a loop

The loop and the array expression give the same numbers. The array version has no loop and is the form used from now on.

```python run
import numpy as np

prices = [10.0, 24.5, 8.0, 15.0]
loop = []
for p in prices:
    loop.append(round(p * 1.2, 2))
print(loop)

a = np.array(prices)
print(np.round(a * 1.2, 2).tolist())
print((a * 2).tolist(), (a - 5).tolist(), (a / 4).tolist())
qty = np.array([3, 1, 4, 2])
print((a * qty).tolist())
print((a > 12).tolist())
print(np.allclose(np.round(a * 1.2, 2), loop))
```

```output
[12.0, 29.4, 9.6, 18.0]
[12.0, 29.4, 9.6, 18.0]
[20.0, 49.0, 16.0, 30.0] [5.0, 19.5, 3.0, 10.0] [2.5, 6.125, 2.0, 3.75]
[30.0, 24.5, 32.0, 30.0]
[False, True, False, True]
True
```

### Example 2: Universal functions and np.where

`np.sqrt`, `np.abs` and `np.maximum` work on each element. `np.where` is a vectorised if/else that builds a new array. Dividing integers gives floats.

```python run
import numpy as np

a = np.array([4, 9, 16, 25])
print(np.sqrt(a).tolist())
d = np.array([-3.5, 2.0, -0.5, 7.25])
print(np.abs(d).tolist(), np.maximum(d, 0).tolist())
print(np.round(d).tolist(), np.floor(d).tolist())

scores = np.array([45, 78, 62, 91, 50])
print(np.where(scores >= 60, "pass", "fail").tolist())
print(np.where(scores >= 60, scores, 60).tolist())
print((np.array([4, 6]) / 2).tolist(), (np.array([7, 9]) // 2).tolist())
```

```output
[2.0, 3.0, 4.0, 5.0]
[3.5, 2.0, 0.5, 7.25] [0.0, 2.0, 0.0, 7.25]
[-4.0, 2.0, -0.0, 7.0] [-4.0, 2.0, -1.0, 7.0]
['fail', 'pass', 'pass', 'pass', 'fail']
[60, 78, 62, 91, 60]
[2.0, 3.0] [3, 4]
```

### Example 3: Broadcasting a row and a column

A shape `(4,)` row is broadcast across the rows of a `(3, 4)` table. A shape `(3, 1)` column is broadcast across the columns. The shapes show why each combination works.

```python run
import numpy as np

t = np.arange(12).reshape(3, 4)
row = np.array([100, 200, 300, 400])
col = np.array([10, 20, 30]).reshape(3, 1)
print((t + row).tolist())
print((t + col).tolist())
print(t.shape, row.shape, col.shape)
print((t + row).shape, (t + col).shape)

grid = np.array([1, 2, 3])[:, None] * np.array([1, 2, 3, 4])
print(grid.tolist(), grid.shape)
```

```output
[[100, 201, 302, 403], [104, 205, 306, 407], [108, 209, 310, 411]]
[[10, 11, 12, 13], [24, 25, 26, 27], [38, 39, 40, 41]]
(3, 4) (4,) (3, 1)
(3, 4) (3, 4)
[[1, 2, 3, 4], [2, 4, 6, 8], [3, 6, 9, 12]] (3, 4)
```

### Example 4: Broadcasting errors and fixes

A per-row array of shape `(3,)` cannot be combined with a `(3, 4)` table, because the last dimensions (4 and 3) differ. Turning it into a column fixes it. The error text is shortened so that the output is stable.

```python run
import numpy as np

t = np.arange(12).reshape(3, 4)
per_row = np.array([1, 10, 100])
try:
    t + per_row
except ValueError as e:
    print("ValueError:", str(e)[:36])
print((t + per_row[:, None]).tolist())
print((t * per_row.reshape(-1, 1)).tolist())
```

```output
ValueError: operands could not be broadcast toge
[[1, 2, 3, 4], [14, 15, 16, 17], [108, 109, 110, 111]]
[[0, 1, 2, 3], [40, 50, 60, 70], [800, 900, 1000, 1100]]
```

### Example 5: A realistic case, converting and normalising

Temperatures in Celsius for three sensors over four hours are converted to Fahrenheit with one expression, then each sensor (row) has its own average subtracted, which needs a column of shape `(3, 1)`. The row averages come from plain Python (`sum` and `len` on each row, Day 8), because aggregation methods are the topic of Day 66. Rounding keeps the printed values clean.

```python run
import numpy as np

c = np.array([[20.0, 22.0, 24.0, 26.0],
              [10.0, 12.0, 11.0, 15.0],
              [30.0, 31.0, 29.0, 34.0]])
f = c * 9 / 5 + 32
print(np.round(f, 1).tolist())

row_means = np.array([sum(r) / len(r) for r in c.tolist()])
print(row_means.tolist(), row_means.shape)
centred = c - row_means[:, None]
print(np.round(centred, 2).tolist())
print([round(sum(r), 6) for r in centred.tolist()])
```

```output
[[68.0, 71.6, 75.2, 78.8], [50.0, 53.6, 51.8, 59.0], [86.0, 87.8, 84.2, 93.2]]
[23.0, 12.0, 31.0] (3,)
[[-3.0, -1.0, 1.0, 3.0], [-2.0, 0.0, -1.0, 3.0], [-1.0, 0.0, -2.0, 3.0]]
[0.0, 0.0, 0.0]
```

## Real-world applications

- **Unit and currency conversion.** One expression such as `c * 9 / 5 + 32` converts a whole column of readings, as in Example 5, instead of a loop over every value.
- **Business rules on whole columns.** `np.where(scores >= 60, "pass", "fail")` and `np.maximum(d, 0)` apply threshold rules and floors to millions of values in one line, the array form of a `CASE` expression in SQL.
- **Centring and scaling data.** Subtracting a per-column or per-row average uses broadcasting, and it is the first step of normalising data for comparison or modelling.
- **Building grids.** A column times a row creates every combination, for example price tiers by quantities, without nested loops.

## Daily review

### Key takeaways

- Operators work element-wise; `a * b` is position-by-position, not a matrix product.
- Universal functions (`np.sqrt`, `np.abs`, `np.maximum`) apply to each element; `np.where` is a vectorised if/else.
- Broadcasting aligns shapes from the last dimension: dimensions must be equal or 1, and missing leading dimensions count as 1.
- `[:, None]` or `reshape(-1, 1)` turns a flat array into a column for per-row operations.
- Replace loops that repeat the same arithmetic on every element; check with `np.allclose`.

### Common mistakes

- Subtracting a per-row array of shape `(3,)` from a `(3, 4)` table and getting `operands could not be broadcast together`. Reshape it to a column.
- Assuming a broadcast is correct because it did not fail, when the table is square and the values were applied along the wrong axis. Check one number by hand.
- Using the Python `math.sqrt` on an array, which raises `TypeError: only length-1 arrays can be converted`. Use `np.sqrt`.
- Using `and`/`or` with arrays. Use `&`/`|` with parentheses, or `np.where`.
- Comparing decimal results with `==`. Use `np.allclose`.
- Forgetting that dividing by zero gives `inf` or `nan` with a warning rather than an exception.

### Revision notes

- Element-wise: `+ - * / ** > ==`; ufuncs `sqrt exp log abs round maximum`.
- `np.where(mask, a, b)` replaces loops with ifs.
- Broadcasting: align right, dimensions equal or 1, `(3,4) + (4,)` ok, `(3,4) + (3,)` not, `(3,4) + (3,1)` ok.
- `x[:, None]` makes a column.
