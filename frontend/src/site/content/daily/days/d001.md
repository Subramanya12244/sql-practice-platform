## Understand

### What Python is and what a program is

A **program** is a list of instructions that a computer follows from top to bottom. Python is a programming language: a fixed vocabulary and set of grammar rules for writing those instructions so that a computer can carry them out. You write the instructions as plain text. A piece of software called the **interpreter** reads that text one instruction at a time and does what each one says. When people say "install Python", they mean installing the interpreter, because without it your text file is only text.

Python is popular in data work because the instructions read close to English, the language ships with many ready-made tools, and the same skills carry from small cleaning jobs to large pipelines. This programme builds from that first instruction up to pipelines, so today is only about getting a working setup and seeing your first output.

### Installing Python and checking it works

Download the installer for your operating system from python.org, or install through your system's package manager. On Windows, tick the option that adds Python to the PATH during setup. The **PATH** is the list of folders your terminal searches when you type a command name. If Python is not on the PATH, the terminal answers that it cannot find the command.

You check the installation in a **terminal**: a window where you type text commands and the computer prints text answers. It is called Terminal on macOS, a terminal app on Linux, and PowerShell or Command Prompt on Windows. The command name differs by system. macOS and Linux normally use `python3`. Windows normally uses `python` or the launcher `py`. Every example below uses `python3`; substitute the name that works on your machine.

```text
$ python3 --version
Python 3.12.4
```

The `$` is only a symbol that stands for "the terminal is waiting for you"; you never type it. Your version number will differ, and any 3.x version recent enough to be supported is fine for this programme. The in-browser exercises on DataForge use their own Python, so you can do every exercise today even before your own installation works.

### Two ways to run Python

There are two ways to give instructions to the interpreter, and a beginner mixes them up often, so keep them apart from the start.

The **REPL** (Read, Evaluate, Print, Loop) is a conversation. You type `python3` with nothing after it and the interpreter starts and shows a `>>>` prompt. You type one instruction, press Enter, and Python reads it, evaluates it, prints the result and waits for the next. The REPL is a scratchpad: ideal for checking what `7 * 6` gives or what a command does. Nothing you type there is saved. You leave it with `exit()` or by pressing Ctrl+D (Ctrl+Z then Enter on Windows).

A **script** is a text file, conventionally ending in `.py`, that holds many instructions. You run the whole file with `python3 filename.py`. Python starts at the first line, carries out each line in order, and stops after the last. Scripts are what you keep, share and rerun, so almost all real work is done in scripts. Any plain text editor can create one, though a code editor such as VS Code makes the work easier.

### Why a line can show a result in the REPL but not in a script

In the REPL, if you type an expression such as `2 + 3`, Python prints its value, `5`, automatically. That convenience exists only in the interactive session. In a script, a line containing just `2 + 3` is calculated and the answer is thrown away. To see something when you run a file, you must ask for it with `print()`.

### print(): showing a result

`print()` is a **function**: a named, ready-made action. You call it by writing its name followed by parentheses, and you put what you want to show inside the parentheses. The things inside are called **arguments**. Text must be wrapped in quotes so that Python knows it is text and not an instruction; text in quotes is called a **string**. Numbers and calculations are written without quotes. If you give `print()` several arguments separated by commas, it shows them on one line with a single space between them. Every call to `print()` ends the current line, so two calls make two lines. Calling `print()` with nothing inside prints an empty line.

### Comments

A **comment** starts with `#` and runs to the end of the line. Python ignores everything from the `#` onward. Comments are for people: they explain why a line exists, label sections, or temporarily disable a line without deleting it. A good comment explains the reason for something that is not obvious; a bad comment repeats what the code already says.

### Reading an error

Python is strict about spelling and punctuation. If you write `pritn("hi")`, the interpreter stops and reports an error that names the line and the kind of problem. In a script, the error appears in the terminal and the program stops at that line, so nothing after it runs. Read the last line of the message first: it names the error type, such as `NameError` (a name Python does not know) or `SyntaxError` (grammar that Python cannot read). Errors are normal information, not a verdict on you.

### Common misconception

Learners often think that `print("2 + 3")` and `print(2 + 3)` do the same thing. They do not. Inside quotes Python treats `2 + 3` as plain characters and prints them unchanged. Without quotes it is a calculation, so Python works out 5 and prints that. The quotes decide whether Python does the sum.

### Why it matters

Every data task, from cleaning a spreadsheet export to loading a database, is a script run by an interpreter, and `print()` is your first way of checking what the code did. Learning to run a file, read the output and read an error message is the foundation for everything that follows.

## Syntax and key functions

Run a script from the terminal, in the folder where the file is saved:

```text
python3 script.py
```

`python3` starts the interpreter, and `script.py` is the file to run. If the terminal is in a different folder, give the full or relative path to the file.

Start the interactive REPL:

```text
python3
>>> 2 + 3
5
>>> exit()
```

Lines starting with `>>>` are what you type; the line without it is Python's answer.

Call `print()`:

```python
print(value)
print(value1, value2, value3)
print()
```

`print(value)` shows one value and ends the line. With several comma-separated values it separates them with one space. With empty parentheses it prints a blank line.

Write a comment:

```python
# a full-line comment
print("hello")  # a comment after code
```

Everything after `#` on the line is ignored.

| Item | What it does | Example |
|---|---|---|
| `python3 --version` | Shows the installed Python version. | `Python 3.12.4` |
| `python3 file.py` | Runs every line of the file, top to bottom. | `python3 hello.py` |
| `print(x)` | Shows `x` and moves to the next line. | `print("Hi")` shows `Hi` |
| `print()` | Shows an empty line. | `print()` |
| `"text"` or `'text'` | A string: characters treated as text. | `"Hello"` |
| `#` | Starts a comment that Python ignores. | `# note to self` |
| `exit()` | Leaves the REPL. | `exit()` |

## Learn by example

### Example 1: Your first output

`print()` receives one string and shows it. The quotes tell Python this is text; they are not part of the output.

```python run
print("Hello, data world!")
```

```output
Hello, data world!
```

### Example 2: Text versus a calculation

The first call prints the characters `2 + 3` unchanged because they are inside quotes. The second has no quotes, so Python calculates 5 first. The third mixes both: a text label and a calculation separated by a comma, which `print()` joins with a space.

```python run
print("2 + 3")
print(2 + 3)
print("2 + 3 =", 2 + 3)
```

```output
2 + 3
5
2 + 3 = 5
```

### Example 3: Comments

The first line is a full-line comment. The inline comment after the second `print` is ignored too. The third `print` is disabled by turning it into a comment, so it produces no output. This is a common way to test a program without deleting code.

```python run
# Greet the reader
print("Welcome")  # this comment is ignored
# print("This line is switched off")
print("Goodbye")
```

```output
Welcome
Goodbye
```

### Example 4: Several lines and a blank line

Each call to `print()` ends its line, so separate calls make separate lines. An empty `print()` creates a blank line, which helps to separate sections of output. Quotes can be single or double; using double quotes here lets the text contain an apostrophe.

```python run
print("Daily sales report")
print()
print("Orders:", 12)
print("Items sold:", 7 * 5)
print("That's all")
```

```output
Daily sales report

Orders: 12
Items sold: 35
That's all
```

### Example 5: A tiny script

This is the shape of a real script: a comment header, a title, a blank line, then results that Python calculates. The seconds in a day come from 24 hours times 60 minutes times 60 seconds. No variables are needed yet; those arrive tomorrow.

```python run
# time_facts.py - how long is a day?
print("Time facts")
print()
print("Minutes in a day:", 24 * 60)
print("Seconds in a day:", 24 * 60 * 60)
print("Hours in a week:", 7 * 24)
```

```output
Time facts

Minutes in a day: 1440
Seconds in a day: 86400
Hours in a week: 168
```

## Real-world applications

- **Checking a pipeline step.** Data engineers put `print()` calls in a script to see how many rows were read or which file is being processed. A line such as `print("Rows loaded:", 1250)` shows whether a step worked before anything is saved.
- **Quick calculations beside your data.** An analyst keeps a REPL open to test arithmetic, such as a 7-day total or a unit conversion, before putting it in a report. It is faster than opening a spreadsheet.
- **Documenting scripts with comments.** A header comment that says what a script does and why makes a nightly job understandable to a colleague months later. Switching a line off with `#` is also how you test a change safely, because you can switch the original line back on.
- **Running the same file on a schedule.** Automation tools run `python3 script.py` for you at a fixed time. Knowing that a script is just a file run from the terminal is what lets you move a job from your laptop to a server.

## Daily review

### Key takeaways

- The interpreter reads your text file and carries out its instructions from top to bottom.
- The REPL (`python3`) is a scratchpad that prints expression values automatically; a script (`python3 file.py`) prints only what `print()` asks for.
- `print()` shows its arguments, separated by one space, and ends the line.
- Text goes in quotes; calculations do not. `print("2 + 3")` and `print(2 + 3)` differ.
- `#` starts a comment that Python ignores.

### Common mistakes

- Typing the `$` or `>>>` symbols as part of a command. They are prompts, not part of the instruction.
- Forgetting the quotes around text, which makes Python look for a name that does not exist (`NameError`).
- Forgetting a closing quote or a closing parenthesis, which produces a `SyntaxError`.
- Writing a bare expression such as `2 + 3` in a script and expecting to see 5.
- Naming your own file `python.py` or `print.py`; keep descriptive names such as `time_facts.py` instead.

### Revision notes

- Check the install: `python3 --version`. Start the REPL: `python3`. Leave it: `exit()`.
- Run a file: `python3 file.py`.
- `print("text", 1 + 2)` shows `text 3`; `print()` shows a blank line.
- `# comment` is for people; Python skips it.
- Error messages end with the error type: read the last line first.
