## Understand

### Start from the question, not the chart

A **visual** is one chart, card or table on a report page. Power BI offers dozens, but a small set covers almost every question, and the choice follows from what the reader wants to know. Ask which of five things is being shown: a single value (how much in total), a comparison between categories (which is biggest), a trend over time (is it rising), a part-to-whole split (what share), or a relationship between two measures (do they move together). A sixth need, detail, is served by a table. Picking by "what looks nice" produces the classic problems: a pie chart with twelve slices, a line chart across unordered categories, a map where a bar chart would be exact.

The standard matches are these. A **card** shows one number such as total revenue. A **bar chart** (horizontal) compares categories and copes with long names and many items; a **column chart** (vertical) compares a few categories or shows a short time series. A **line chart** shows a trend over a continuous time axis, since the eye follows the slope. A **donut or pie chart** shows part-to-whole only when there are very few parts, and a bar chart is usually the better answer even then. A **scatter plot** shows a relationship between two measures, one point per item. A **table** lists exact values and a **matrix** is a table with a row and a column hierarchy, a PivotTable in a report. In this lesson the course rules, which you will encode in code, are: line for time trends, bar for comparisons with more than seven categories, column for comparisons with seven or fewer, donut for at most five parts and bar otherwise, scatter for a relationship, card for one value.

### Slicers and filters

A **slicer** is a visual that lets the report reader choose values of a field, for example a country or a year. By default a slicer filters every visual on its page, and slicers can be synchronised across pages in the View, Sync slicers pane. A slicer is a filter in the filter context from Day 130: selecting UK adds a filter on `Customers[country]`, and all measures re-evaluate. The Filters pane holds the filters set by the author and has three scopes: **visual** (one chart), **page** (every visual on the page) and **report** (every page). The reader can see and change these in the pane unless the author hides or locks them, so a filter is not a security feature (Day 135 covers real security). Slicers are for the reader, filters for the author.

### Cross-filtering and highlighting

When the reader clicks a bar, the other visuals on the page respond. Depending on the setting, Power BI either **highlights** the matching portion in the other visuals, keeping the totals visible as a shaded part, or **filters** them so that they show only the selection. The behaviour is set per pair of visuals with the Edit interactions command, which is how an author stops a card of overall revenue from reacting to a click. In terms of filter context, a click adds a filter on the clicked field to every visual that is set to listen.

### Drill-down and drill-through

**Drill-down** moves inside one visual along a hierarchy, for example from year to quarter to month on the same chart (hierarchies were part of Day 128). **Drill-through** moves to another page: the author builds a detail page, marks the field to receive (for example customer), and the reader right-clicks a customer in any visual and chooses Drill through to land on a page that is filtered to that customer. Drill-through suits "show me everything about this one item" without making the summary page crowded.

### Tooltips and bookmarks

A **tooltip** is the box that appears on hover. By default it shows the values of the mark; a **report-page tooltip** shows a whole small visual, such as a trend line for the hovered category, which adds detail without taking page space. A **bookmark** captures the state of a page, meaning its filters, slicer selections and which visuals are visible, under a name. Buttons linked to bookmarks let the reader switch views, for example between a revenue view and a margin view, and a navigation of bookmarks can imitate tabs. Treat a bookmark as a saved dictionary of selections: restoring it simply sets those selections again.

### Why it matters

Interactivity multiplies the questions one page can answer, but each extra control also adds a way for the reader to misread the page, such as a forgotten slicer making a total look low. The misconception to avoid is that more visuals and more controls mean a better report. Every visual needs a question that it answers, and every control must be visible in its state.

## Syntax and key functions

Power BI visuals are configured in the Build pane (fields) and the Format pane, not with syntax. The reference below lists the controls of this lesson.

| Control | Scope and effect |
|---|---|
| Slicer | Filters all visuals on its page (or synced pages) for the reader. |
| Visual, page, report filter | Filter set by the author at one visual, one page or all pages. |
| Edit interactions | Chooses per visual whether a click filters, highlights or does nothing. |
| Drill-down | Moves down a hierarchy in the same visual. |
| Drill-through | Opens a detail page filtered to the clicked item. |
| Report-page tooltip | A small page shown on hover. |
| Bookmark | A saved state of filters, slicers and visual visibility. |

The course rule for choosing a visual, as Python:

```python
def choose_visual(question):
    kind = question["kind"]
    if kind == "single": return "card"
    if kind == "trend": return "line"
    if kind == "relationship": return "scatter"
    if kind == "detail": return "table"
    n = question["categories"]
    if kind == "part": return "donut" if n <= 5 else "bar"
    return "column" if n <= 7 else "bar"
```

## Learn by example

### Example 1: A visual-selection rule

Encode the rule and apply it to five questions about the sample model.

```python run
def choose_visual(question):
    kind = question["kind"]
    if kind == "single":
        return "card"
    if kind == "trend":
        return "line"
    if kind == "relationship":
        return "scatter"
    if kind == "detail":
        return "table"
    n = question["categories"]
    if kind == "part":
        return "donut" if n <= 5 else "bar"
    return "column" if n <= 7 else "bar"

questions = [
    ("Total revenue", {"kind": "single"}),
    ("Revenue by month", {"kind": "trend"}),
    ("Revenue by category", {"kind": "compare", "categories": 3}),
    ("Revenue by customer", {"kind": "compare", "categories": 40}),
    ("Share of revenue by category", {"kind": "part", "categories": 3}),
    ("Share of revenue by product", {"kind": "part", "categories": 12}),
]
for text, q in questions:
    print(f"{text}: {choose_visual(q)}")
```

```output
Total revenue: card
Revenue by month: line
Revenue by category: column
Revenue by customer: bar
Share of revenue by category: donut
Share of revenue by product: bar
```

A single value goes on a card, a time series on a line, three categories on a column chart, 40 customers on a bar chart (long names read horizontally and a top-N filter keeps it short), and twelve product shares become a bar chart because a donut would show twelve unreadable slices. The rule is deliberately simple: it is a checklist you can defend, not a law.

### Example 2: A slicer is a filter on the data behind every visual

Selecting UK and Germany in a country slicer filters the fact table before every visual draws.

```python run
import numpy as np
import pandas as pd

rng = np.random.default_rng(7)
countries = ["UK", "Germany", "France", "Spain"]
cats = ["Hardware", "Software", "Services"]
customers = pd.DataFrame({
    "customer_id": range(1, 41),
    "customer_name": [f"Customer {i:02d}" for i in range(1, 41)],
    "country": [countries[i % 4] for i in range(40)],
    "segment": [["Retail", "Corporate"][(i // 4) % 2] for i in range(40)],
})
products = pd.DataFrame({
    "product_id": range(1, 13),
    "product_name": [f"Product {i:02d}" for i in range(1, 13)],
    "category": [cats[i % 3] for i in range(12)],
    "unit_cost": [float(10 + 5 * i) for i in range(12)],
})
n = 400
sales = pd.DataFrame({
    "order_id": range(1, n + 1),
    "order_date": pd.to_datetime("2025-01-01") + pd.to_timedelta(rng.integers(0, 365, n), unit="D"),
    "customer_id": rng.integers(1, 41, n),
    "product_id": rng.integers(1, 13, n),
    "quantity": rng.integers(1, 6, n),
})
sales["unit_price"] = (sales["product_id"].map(products.set_index("product_id")["unit_cost"]) * 1.5).round(2)
calendar = pd.DataFrame({"date": pd.date_range("2025-01-01", "2025-12-31")})
calendar["year"] = calendar["date"].dt.year
calendar["quarter"] = calendar["date"].dt.quarter
calendar["month_number"] = calendar["date"].dt.month
calendar["month_name"] = calendar["date"].dt.strftime("%B")
sales["revenue"] = sales["quantity"] * sales["unit_price"]
fact = (sales.merge(customers, on="customer_id").merge(products, on="product_id")
        .merge(calendar, left_on="order_date", right_on="date"))
selected = ["UK", "Germany"]
view = fact[fact["country"].isin(selected)]
print(len(view), round(float(view["revenue"].sum()), 2))
print(view.groupby("category")["revenue"].sum().round(2).to_string())
```

```output
196 33495.0
category
Hardware    10125.0
Services    11805.0
Software    11565.0
```

With the slicer on, the card shows 33,495.00 from 196 order rows, down from 67,132.50 from 400, and the category bars show the filtered values. This is the same filter context as Day 130: the slicer adds `country` to the dictionary of selections.

### Example 4: Drill-through to a customer

A drill-through page receives one customer and lists that customer's orders.

```python run
import numpy as np
import pandas as pd

rng = np.random.default_rng(7)
countries = ["UK", "Germany", "France", "Spain"]
cats = ["Hardware", "Software", "Services"]
customers = pd.DataFrame({

    "customer_name": [f"Customer {i:02d}" for i in range(1, 41)],
    "country": [countries[i % 4] for i in range(40)],
    "segment": [["Retail", "Corporate"][(i // 4) % 2] for i in range(40)],
})
products = pd.DataFrame({
    "product_id": range(1, 13),
    "product_name": [f"Product {i:02d}" for i in range(1, 13)],
    "category": [cats[i % 3] for i in range(12)],
    "unit_cost": [float(10 + 5 * i) for i in range(12)],
})
n = 400
sales = pd.DataFrame({
    "order_id": range(1, n + 1),
    "order_date": pd.to_datetime("2025-01-01") + pd.to_timedelta(rng.integers(0, 365, n), unit="D"),
    "customer_id": rng.integers(1, 41, n),
    "product_id": rng.integers(1, 13, n),
    "quantity": rng.integers(1, 6, n),
})
sales["unit_price"] = (sales["product_id"].map(products.set_index("product_id")["unit_cost"]) * 1.5).round(2)
calendar = pd.DataFrame({"date": pd.date_range("2025-01-01", "2025-12-31")})
calendar["year"] = calendar["date"].dt.year
calendar["quarter"] = calendar["date"].dt.quarter
calendar["month_number"] = calendar["date"].dt.month
calendar["month_name"] = calendar["date"].dt.strftime("%B")
sales["revenue"] = sales["quantity"] * sales["unit_price"]
fact = (sales.merge(customers, on="customer_id").merge(products, on="product_id")
        .merge(calendar, left_on="order_date", right_on="date"))
def drill_through(customer):
    d = fact[fact["customer_name"] == customer]
    top = d.sort_values(["revenue", "order_id"], ascending=[False, True]).head(3)
    return len(d), round(float(d["revenue"].sum()), 2), top[["order_id", "product_name", "quantity", "revenue"]]

rows, total, top = drill_through("Customer 13")
print(rows, total)
print(top.to_string(index=False))
```

```output
15 3195.0
 order_id product_name  quantity  revenue
      151   Product 10         5    412.5
      209   Product 10         5    412.5
      201   Product 12         4    390.0
```

Customer 13 has 15 orders worth 3,195.00 and the detail page lists the biggest ones. The summary page stays at category and month level; the one-customer view appears only on request, which keeps the summary uncluttered.

### Example 5: A bookmark is a saved state

A bookmark saves slicer selections and a visible-visual choice; restoring it sets them again.

```python run
import numpy as np
import pandas as pd

rng = np.random.default_rng(7)
countries = ["UK", "Germany", "France", "Spain"]
cats = ["Hardware", "Software", "Services"]
customers = pd.DataFrame({
    "customer_id": range(1, 41),
    "customer_name": [f"Customer {i:02d}" for i in range(1, 41)],
    "country": [countries[i % 4] for i in range(40)],
    "segment": [["Retail", "Corporate"][(i // 4) % 2] for i in range(40)],
})
products = pd.DataFrame({
    "product_id": range(1, 13),
    "product_name": [f"Product {i:02d}" for i in range(1, 13)],
    "category": [cats[i % 3] for i in range(12)],
    "unit_cost": [float(10 + 5 * i) for i in range(12)],
})
n = 400
sales = pd.DataFrame({
    "order_id": range(1, n + 1),
    "order_date": pd.to_datetime("2025-01-01") + pd.to_timedelta(rng.integers(0, 365, n), unit="D"),
    "customer_id": rng.integers(1, 41, n),
    "product_id": rng.integers(1, 13, n),
    "quantity": rng.integers(1, 6, n),
})
sales["unit_price"] = (sales["product_id"].map(products.set_index("product_id")["unit_cost"]) * 1.5).round(2)
calendar = pd.DataFrame({"date": pd.date_range("2025-01-01", "2025-12-31")})
calendar["year"] = calendar["date"].dt.year
calendar["quarter"] = calendar["date"].dt.quarter
calendar["month_number"] = calendar["date"].dt.month
calendar["month_name"] = calendar["date"].dt.strftime("%B")
sales["revenue"] = sales["quantity"] * sales["unit_price"]
fact = (sales.merge(customers, on="customer_id").merge(products, on="product_id")
        .merge(calendar, left_on="order_date", right_on="date"))
bookmarks = {
    "Overview": {"countries": ["UK", "Germany", "France", "Spain"], "metric": "revenue"},
    "UK focus": {"countries": ["UK"], "metric": "units"},
}

def show(name):
    state = bookmarks[name]
    d = fact[fact["country"].isin(state["countries"])]
    value = d["revenue"].sum() if state["metric"] == "revenue" else d["quantity"].sum()
    return f"{name}: {state['metric']} = {float(value):,.1f}"

for name in bookmarks:
    print(show(name))
```

```output
Overview: revenue = 67,132.5
UK focus: units = 247.0
```

The two bookmarks produce two views of the same data from a saved dictionary: all countries by revenue (67,132.5), and the UK by units. A button linked to each bookmark switches views with one click. A bookmark that stores slicer selections will also restore a stale selection, which is why bookmark names should say what they show.

## Real-world applications

- **Executive overview page.** Cards for the key numbers, a line for the trend and a bar for the biggest categories follow the rule in Example 1.
- **Self-service exploration.** A country and year slicer lets a regional manager see only their market, as in Example 2, without a separate report.
- **Customer review.** Drill-through from a customer in any visual to a detail page supports account reviews without a crowded overview (Example 4).
- **Alternative views.** Bookmarks switch one page between a revenue and a units view, which avoids two near-identical pages (Example 5).

## Daily review

### Key takeaways

- Choose the visual from the question: single value, comparison, trend, part-to-whole, relationship, detail.
- A slicer is a reader-facing filter on the filter context; filter panes set the scope by visual, page or report.
- A click either cross-filters or highlights; Edit interactions sets it per pair of visuals.
- Drill-down goes inside a hierarchy; drill-through opens a filtered detail page.
- Tooltip pages add detail on hover; a bookmark saves filters, slicers and visibility.

### Common mistakes

- Using a donut or pie for more than five parts, which makes the slices unreadable; use a bar chart.
- Using a line chart for unordered categories, which suggests a trend that does not exist.
- Leaving a slicer selection on and forgetting that every number on the page is filtered; show the selection or add a reset bookmark.
- Treating a hidden filter as security: a reader can change a filter in the pane, and only row-level security restricts data.
- Letting every visual cross-filter every other, so that a card of the overall total changes when the reader clicks a bar.
