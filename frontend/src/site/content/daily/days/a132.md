## Objectives

- Use `VAR` and `RETURN` to name intermediate results and say when a variable is evaluated.
- Write iterator measures with `SUMX` and explain the row-by-row calculation they perform.
- Rank items with `RANKX`, choose how ties are handled, and select the best N with `TOPN`.
- Rewrite a nested DAX expression into a readable form with variables and layout.
- Reproduce each result with pandas row-wise arithmetic, `rank` and `nlargest`.

## Understand

### Variables: VAR and RETURN

A **variable** gives a name to the result of an expression inside a measure. It is declared with `VAR`, and the measure ends with `RETURN` followed by the final expression.

```dax
Gross Margin % =
VAR Revenue = [Total Revenue]
VAR Cost = [Total Cost]
RETURN
    DIVIDE(Revenue - Cost, Revenue)
```

Variables do three things. They make a measure readable, because each step has a name. They avoid repetition, since the value is calculated once and used as often as you like. And they make debugging easier: you can temporarily `RETURN Revenue` to see one step. A variable is evaluated once, **where it is declared**, in the filter context that exists at that point; it is not re-evaluated later. This is the subtle part. If a variable is declared before a `CALCULATE` that changes the context, the variable keeps the original value inside that `CALCULATE`, while a measure called inside it is re-evaluated in the new context. Many "my share is always 100%" bugs come from a variable declared at the wrong place. A variable holds a value (a number or a text) or a whole table, and its name cannot be reused inside the same measure.

### Iterators: the X functions

`SUM(Sales[Revenue])` needs a stored column. An **iterator** has the same name with an X and works row by row. `SUMX(<table>, <expression>)` goes through each row of the table, evaluates the expression with that row as the **row context** (Day 130), and adds up the results. `AVERAGEX`, `MINX`, `MAXX` and `COUNTX` follow the same pattern.

```dax
Total Cost = SUMX(Sales, Sales[quantity] * RELATED(Products[unit_cost]))
```

Here `RELATED` is allowed because `SUMX` creates a row context on each `Sales` row. The expression is computed per row first and the results are then aggregated, which is not the same as multiplying two totals. `SUM(Sales[quantity]) * AVERAGE(Products[unit_cost])` is a different, wrong number. The same rule explains why the revenue measure can be written without a stored column: `SUMX(Sales, Sales[quantity] * Sales[unit_price])`. In pandas this is `(df.quantity * df.unit_price).sum()`: a row-wise computation followed by a sum. Iterators are also the way to apply a rule to each row before totalling, such as capping each order at 300.

The table argument can be a filtered table. `SUMX(FILTER(Sales, Sales[quantity] > 3), ...)` iterates only the rows that pass. The iterator respects the filter context of the cell: it iterates the rows that are still visible.

### Ranking with RANKX

`RANKX(<table>, <expression>, [value], [order], [ties])` evaluates the expression for each row of the table, orders the results and returns the position of the current item. The table is normally written with `ALL`, so that the ranking compares all items and not only the items visible in the current cell.

```dax
Customer Rank = RANKX(ALL(Customers[customer_name]), [Total Revenue])
```

By default the order is descending: the highest revenue gets rank 1. The default tie rule is **skip**: if two items share rank 2, the next one is rank 4. The option `DENSE` closes the gap, so the next one is rank 3. In pandas the two rules are `rank(method="min")` and `rank(method="dense")`. Because the measure is evaluated per cell, in a table of customers each row gets that customer's rank. In a visual where only one customer is visible and `ALL` is missing, every rank would be 1, a frequent mistake.

### TOPN

`TOPN(<n>, <table>, <expression>, [order])` returns the `n` rows of the table with the highest values of the expression. It returns a table, so it is used as a filter inside `CALCULATE`:

```dax
Top 5 Customers Revenue = CALCULATE([Total Revenue], TOPN(5, ALL(Customers), [Total Revenue]))
```

`ALL(Customers)` makes the candidates independent of the current customer filter. When rows tie at the Nth place, `TOPN` can return more than `n` rows, so a top-5 can include six customers; decide whether that is acceptable or add a tie-breaker. The pandas equivalent is `nlargest(5)`, and `nlargest(5, keep="all")` shows the tie behaviour.

### Readable DAX

Readable DAX is a professional habit. Put each argument of a long function on its own line, indent consistently, name variables with the business meaning (`Revenue`, `PriorRevenue`), prefer variables to repeating an expression, and finish with a single `RETURN`. Compare `DIVIDE(CALCULATE([Total Revenue]) - CALCULATE([Total Revenue], SAMEPERIODLASTYEAR(Calendar[date])), CALCULATE([Total Revenue], SAMEPERIODLASTYEAR(Calendar[date])))` with the same measure written with two variables: the second can be read aloud. Measures are read far more often than written, by colleagues and by you in three months.

### Why it matters

Variables, iterators and ranking cover the measures that stakeholders ask for second: margin per row, capped or rule-based totals, "top customers" and "rank of this product". They are also where performance and correctness problems appear (Day 136), so the habits in this lesson pay off later. The misconception to drop is that `SUMX` is "just a slow SUM": it is the only way to compute from several columns or related tables per row before totalling.

## Syntax and key functions

```dax
Measure =
VAR name = <expression>
RETURN <expression using name>

SUMX(<table>, <row expression>)
RANKX(<table>, <expression>, [value], [order], [ties])
TOPN(<n>, <table>, <expression>, [order])
```

| Function | Returns |
|---|---|
| `VAR ... RETURN` | The final expression, using named intermediate values computed once. |
| `SUMX(table, expr)` | The sum of `expr` evaluated for each row of `table`. |
| `AVERAGEX`, `MINX`, `MAXX`, `COUNTX` | The same pattern with other aggregations. |
| `RANKX(table, expr)` | The rank of the current item (descending by default, ties skip). |
| `TOPN(n, table, expr)` | A table of the top `n` rows by `expr`. |

pandas counterparts:

```python
(df["quantity"] * df["unit_cost"]).sum()      # SUMX
series.rank(method="min", ascending=False)    # RANKX, ties skip
series.nlargest(5)                            # TOPN
```

## Learn by example

### Example 1: Variables name the steps

The gross margin measure uses two variables. In pandas they are ordinary Python variables.

```python run
import numpy as np
import pandas as pd

rng = np.random.default_rng(7)
countries = ["UK", "Germany", "France", "Spain"]
cats = ["Hardware", "Software", "Services"]
customers = pd.DataFrame({
    "customer_id": range(1, 41),
    "customer_name": [f"Customer {i:02d}" for i in range(1, 41)],
    "country": [countries[i % 4] for i in range(40)],
    "segment": [["Retail", "Corporate"][(i // 4) % 2] for i in range(40)],
})
products = pd.DataFrame({
    "product_id": range(1, 13),
    "product_name": [f"Product {i:02d}" for i in range(1, 13)],
    "category": [cats[i % 3] for i in range(12)],
    "unit_cost": [float(10 + 5 * i) for i in range(12)],
})
n = 400
sales = pd.DataFrame({
    "order_id": range(1, n + 1),
    "order_date": pd.to_datetime("2025-01-01") + pd.to_timedelta(rng.integers(0, 365, n), unit="D"),
    "customer_id": rng.integers(1, 41, n),
    "product_id": rng.integers(1, 13, n),
    "quantity": rng.integers(1, 6, n),
})
sales["unit_price"] = (sales["product_id"].map(products.set_index("product_id")["unit_cost"]) * 1.5).round(2)
calendar = pd.DataFrame({"date": pd.date_range("2025-01-01", "2025-12-31")})
calendar["year"] = calendar["date"].dt.year
calendar["quarter"] = calendar["date"].dt.quarter
calendar["month_number"] = calendar["date"].dt.month
calendar["month_name"] = calendar["date"].dt.strftime("%B")
sales["revenue"] = sales["quantity"] * sales["unit_price"]
fact = (sales.merge(customers, on="customer_id").merge(products, on="product_id")
        .merge(calendar, left_on="order_date", right_on="date"))
revenue = float(fact["revenue"].sum())
cost = float((fact["quantity"] * fact["unit_cost"]).sum())
margin = (revenue - cost) / revenue
print(revenue, cost, round(margin, 4))

by_cat = fact.assign(cost=fact["quantity"] * fact["unit_cost"]).groupby("category")[["revenue", "cost"]].sum()
print(((by_cat["revenue"] - by_cat["cost"]) / by_cat["revenue"]).round(4).to_string())
```

```output
67132.5 44755.0 0.3333
category
Hardware    0.3333
Services    0.3333
Software    0.3333
```

Revenue is 67,132.50, cost 44,755.00 and the margin 0.3333. Every row of the sample sells at 1.5 times its cost, so every category also shows 0.3333. The measure is the same formula evaluated in each category's filter context.

### Example 5: A readable top-N share measure

Combine the pieces: variables for the numerator and denominator, `TOPN` for the numerator.

```dax
Top 5 Share =
VAR TopRevenue =
    CALCULATE([Total Revenue], TOPN(5, ALL(Customers[customer_name]), [Total Revenue]))
VAR AllRevenue =
    CALCULATE([Total Revenue], ALL(Customers[customer_name]))
RETURN
    DIVIDE(TopRevenue, AllRevenue)
```

```python run
import numpy as np
import pandas as pd

rng = np.random.default_rng(7)
countries = ["UK", "Germany", "France", "Spain"]
cats = ["Hardware", "Software", "Services"]
customers = pd.DataFrame({
    "customer_id": range(1, 41),
    "customer_name": [f"Customer {i:02d}" for i in range(1, 41)],
    "country": [countries[i % 4] for i in range(40)],
    "segment": [["Retail", "Corporate"][(i // 4) % 2] for i in range(40)],
})
products = pd.DataFrame({
    "product_id": range(1, 13),
    "product_name": [f"Product {i:02d}" for i in range(1, 13)],
    "category": [cats[i % 3] for i in range(12)],
    "unit_cost": [float(10 + 5 * i) for i in range(12)],
})
n = 400
sales = pd.DataFrame({
    "order_id": range(1, n + 1),
    "order_date": pd.to_datetime("2025-01-01") + pd.to_timedelta(rng.integers(0, 365, n), unit="D"),
    "customer_id": rng.integers(1, 41, n),
    "product_id": rng.integers(1, 13, n),
    "quantity": rng.integers(1, 6, n),
})
sales["unit_price"] = (sales["product_id"].map(products.set_index("product_id")["unit_cost"]) * 1.5).round(2)
calendar = pd.DataFrame({"date": pd.date_range("2025-01-01", "2025-12-31")})
calendar["year"] = calendar["date"].dt.year
calendar["quarter"] = calendar["date"].dt.quarter
calendar["month_number"] = calendar["date"].dt.month
calendar["month_name"] = calendar["date"].dt.strftime("%B")
sales["revenue"] = sales["quantity"] * sales["unit_price"]
fact = (sales.merge(customers, on="customer_id").merge(products, on="product_id")
        .merge(calendar, left_on="order_date", right_on="date"))
def top_share(df, n):
    by_customer = df.groupby("customer_id")["revenue"].sum()
    top_revenue = by_customer.nlargest(n).sum()
    all_revenue = by_customer.sum()
    return top_revenue / all_revenue

print(round(float(top_share(fact, 5)), 4))
for country, d in fact.groupby("country"):
    print(country, round(float(top_share(d, 5)), 4))
```

```output
0.2148
France 0.6465
Germany 0.6228
Spain 0.6724
UK 0.8003
```

For the whole model, the top five customers hold 21.5% of revenue. The measure uses `ALL(Customers[customer_name])`, which removes only the customer-name filter and keeps a country filter from a matrix row. In the France row the candidates are the ten French customers, so the top five hold 64.7% of France's revenue, and the UK shows 80.0%. Writing `ALL(Customers)` instead would also clear the country filter, and every row would show the same 21.5%. The variables make the formula readable: numerator, denominator, ratio.

## Real-world applications

- **Rule-based totals.** `SUMX` applies per-row rules such as capped orders, discounts or currency conversion before totalling (Example 2).
- **Leaderboards.** `RANKX` powers "rank of this salesperson" tables, with ties handled deliberately (Example 3).
- **Concentration analysis.** A top-N share shows how dependent revenue is on a few customers, a risk metric for finance and sales (Examples 4 and 5).
- **Maintainable models.** Variables make reviewed measures understandable by the next analyst (Example 1).

## Daily review

### Key takeaways

- `VAR` names a value that is computed once, where it is declared, in the filter context at that point.
- `SUMX` and other X functions evaluate an expression per row and then aggregate.
- `RANKX` needs `ALL` on the items to rank; the default is descending with ties skipping ranks.
- `TOPN` returns a table, used as a filter in `CALCULATE`, and can return more than N rows when there are ties.
- Readable DAX uses variables, one argument per line and a single `RETURN`.

### Common mistakes

- Declaring a variable before `CALCULATE` and expecting it to change inside it. It keeps the value from where it was declared.
- Multiplying totals (`SUM(a) * AVERAGE(b)`) instead of iterating, which gives a plausible but wrong number.
- Leaving out `ALL` in `RANKX`, so every visible item ranks 1.
- Assuming `TOPN(5, ...)` always returns exactly five rows.
- Reusing a variable name in the same measure, or using a variable in another measure, where it does not exist.

### Revision notes

- `VAR x = ... RETURN ...`; evaluated once at the declaration.
- `SUMX(table, row expression)`: row context, then sum.
- `RANKX(ALL(items), measure)`: descending, skip ties unless `DENSE`.
- `TOPN(n, ALL(items), measure)` inside `CALCULATE`; ties can add rows.
- pandas: row-wise arithmetic, `rank(method="min")`, `nlargest`.
