## Objectives

- Profile a messy table before changing it, counting missing values, duplicates and inconsistent spellings.
- Standardise text columns and convert amounts and dates to proper types, recording the values that cannot be converted.
- Remove exact duplicates and resolve repeated keys with an explicit rule, and separate unusable rows into a rejects table.
- Validate the cleaned table with assertions and produce a small summary that proves the cleaning worked.

## Understand

### What a cleaning project is

Real data arrives messy: extra spaces, inconsistent capitals, numbers stored as text with currency symbols, dates in impossible formats, rows repeated by an export that ran twice. A cleaning project turns one such file into a table that can be trusted, and it does so in a repeatable way. The result is only useful if you can say what you changed, what you removed and why. Today you combine tools from Days 70 to 84 into one small pipeline: inspect, fix text, fix types, deduplicate, deal with missing values, validate.

### The order of the steps

The order matters because each step makes the next one possible. **Profile first**: read everything as text (`dtype=str`) so pandas does not guess, then count missing values, duplicates and distinct spellings. You cannot fix what you have not seen. **Standardise text second**: strip spaces and unify case, because a duplicate such as `"UK "` and `"uk"` is invisible to `drop_duplicates` until the text is the same. **Convert types third**: remove currency symbols and commas, then use `pd.to_numeric` and `pd.to_datetime` with `errors="coerce"`, so unusable values become `NaN` or `NaT` instead of stopping the program. Count how many became missing; each one is a decision you must make explicitly. **Deduplicate fourth**: drop exact copies, then handle repeated keys with a stated rule such as "keep the last row for each order id", which assumes the later row is the correction. **Handle missing values fifth**: decide per column whether to fill, flag or reject. A missing amount cannot be guessed in a revenue table, so such rows go to a rejects table that someone can review. **Validate last**: assert the rules the clean table must satisfy.

### Keep what you reject

Dropping bad rows silently makes revenue look lower with no explanation. Instead, move them into a separate `rejects` table with a reason, and report the counts: rows read, rows kept, rows rejected, duplicates removed. These four numbers must add up, and checking that they do is the cheapest validation there is.

### Validated output

Validation turns your assumptions into checks that fail loudly. Typical checks are: the key is unique, amounts are positive, dates fall in the expected range, categories belong to an allowed list, and no required column has missing values. Python's `assert` statement stops the program with an error if a check fails. In a pipeline that runs every night, a failed assertion is better than a wrong report.

### Common misconception

Learners often think cleaning means "make errors disappear". Cleaning means making every decision visible: a value coerced to `NaN` is not repaired, only flagged. If you fill it, the fill rule must be stated; if you drop it, the drop must be counted. A table that looks tidy but cannot be explained is not clean.

## Syntax and key functions

```python nocheck
raw = pd.read_csv(io.StringIO(text), dtype=str)        # no type guessing
s.str.strip().str.title()                              # text fixes
pd.to_numeric(s.str.replace("[$,]", "", regex=True), errors="coerce")
pd.to_datetime(s, format="%Y-%m-%d", errors="coerce")
df.drop_duplicates()                                   # exact copies
df.drop_duplicates(subset="order_id", keep="last")     # repeated key rule
assert df["order_id"].is_unique
```

| Step | Tool |
|---|---|
| Profile | `isna().sum()`, `duplicated().sum()`, `value_counts()` |
| Standardise | `.str.strip()`, `.str.lower()`, `map` with a dictionary |
| Convert | `to_numeric`, `to_datetime` with `errors="coerce"` |
| Deduplicate | `drop_duplicates(subset=..., keep=...)` |
| Reject | boolean mask on `isna()`; keep the rejected rows |
| Validate | `assert` on uniqueness, ranges and allowed values |

### Example 2: Standardise the text

Strip spaces, fix capitals and map long country names to codes with a function.

```python run
import io
import pandas as pd
RAW = """order_id,customer,order_date,amount,country,status
1001, ada lovelace ,2024-01-05,"$1,200.50",uk,Shipped
1002,BO CHEN,2024-01-07,85,UK ,shipped
1003,Cy Diaz,2024-01-09,,United Kingdom,SHIPPED
1004,di evans,2024-13-45,40,US,returned
1005,ada lovelace,2024-01-12,abc,us,shipped
1002,BO CHEN,2024-01-07,85,UK ,shipped
1006,Ed Fox,2024-02-01,"$99.99",US,Pending
1007,Fay Gray,n/a,60,DE,pending
1006,Ed Fox,2024-02-01,"$109.99",US,shipped
1008,Gus Hall,2024-02-14,150,Germany,Shipped
"""
raw = pd.read_csv(io.StringIO(RAW), dtype=str)
CODES = {"UNITED KINGDOM": "UK", "GERMANY": "DE"}
df = raw.copy()
df["customer"] = df["customer"].str.strip().str.title()
df["status"] = df["status"].str.strip().str.lower()
df["country"] = df["country"].str.strip().str.upper().map(lambda v: CODES.get(v, v))
print(df["customer"].unique().tolist())
print(sorted(df["country"].unique().tolist()), sorted(df["status"].unique().tolist()))
```

```output

['DE', 'UK', 'US'] ['pending', 'returned', 'shipped']
```

The seven country spellings are now three codes, and the two spellings of `ada lovelace` are one customer.

### Example 4: Deduplicate and reject

Exact copies are dropped, repeated ids keep the last row (a later correction), and rows with a missing amount or date go to a rejects table.

```python run
import io
import pandas as pd
RAW = """order_id,customer,order_date,amount,country,status
1001, ada lovelace ,2024-01-05,"$1,200.50",uk,Shipped
1002,BO CHEN,2024-01-07,85,UK ,shipped
1003,Cy Diaz,2024-01-09,,United Kingdom,SHIPPED
1004,di evans,2024-13-45,40,US,returned
1005,ada lovelace,2024-01-12,abc,us,shipped
1002,BO CHEN,2024-01-07,85,UK ,shipped
1006,Ed Fox,2024-02-01,"$99.99",US,Pending
1007,Fay Gray,n/a,60,DE,pending
1006,Ed Fox,2024-02-01,"$109.99",US,shipped
1008,Gus Hall,2024-02-14,150,Germany,Shipped
"""
raw = pd.read_csv(io.StringIO(RAW), dtype=str)
df = raw.copy()
df["amount"] = pd.to_numeric(df["amount"].str.replace("[$,]", "", regex=True), errors="coerce")
df["order_date"] = pd.to_datetime(df["order_date"], format="%Y-%m-%d", errors="coerce")
step1 = df.drop_duplicates()
step2 = step1.drop_duplicates(subset="order_id", keep="last")
bad = step2["amount"].isna() | step2["order_date"].isna()
clean, rejects = step2[~bad], step2[bad]
print(len(raw), len(step1), len(step2), len(clean), len(rejects))
print(rejects["order_id"].tolist())
print(clean[["order_id", "amount"]].to_string(index=False))

['1003', '1004', '1005', '1007']
order_id  amount
    1001 1200.50
    1002   85.00
    1006  109.99
    1008  150.00
```

Ten rows read, one exact copy removed, one repeated id resolved, four rows rejected, four kept. Order 1006 keeps the corrected amount.

### Example 5: Validate and report

The cleaning is wrapped in a function. Assertions state what must be true, and a summary groups revenue by country.

```python run
import io
import pandas as pd
RAW = """order_id,customer,order_date,amount,country,status
1001, ada lovelace ,2024-01-05,"$1,200.50",uk,Shipped
1002,BO CHEN,2024-01-07,85,UK ,shipped
1003,Cy Diaz,2024-01-09,,United Kingdom,SHIPPED
1004,di evans,2024-13-45,40,US,returned
1005,ada lovelace,2024-01-12,abc,us,shipped
1002,BO CHEN,2024-01-07,85,UK ,shipped
1006,Ed Fox,2024-02-01,"$99.99",US,Pending
1007,Fay Gray,n/a,60,DE,pending
1006,Ed Fox,2024-02-01,"$109.99",US,shipped
1008,Gus Hall,2024-02-14,150,Germany,Shipped
"""
raw = pd.read_csv(io.StringIO(RAW), dtype=str)
CODES = {"UNITED KINGDOM": "UK", "GERMANY": "DE"}

def clean_orders(raw):
    df = raw.copy()
    df["customer"] = df["customer"].str.strip().str.title()
    df["country"] = df["country"].str.strip().str.upper().map(lambda v: CODES.get(v, v))
    df["status"] = df["status"].str.strip().str.lower()
    df["amount"] = pd.to_numeric(df["amount"].str.replace("[$,]", "", regex=True), errors="coerce")
    df["order_date"] = pd.to_datetime(df["order_date"], format="%Y-%m-%d", errors="coerce")
    df = df.drop_duplicates().drop_duplicates(subset="order_id", keep="last")
    bad = df["amount"].isna() | df["order_date"].isna()
    return df[~bad].reset_index(drop=True), df[bad]

clean, rejects = clean_orders(raw)
assert clean["order_id"].is_unique
assert (clean["amount"] > 0).all()
assert clean["country"].isin(["UK", "US", "DE"]).all()
assert clean["order_date"].between("2024-01-01", "2024-12-31").all()
summary = clean.groupby("country").agg(orders=("order_id", "size"), revenue=("amount", "sum")).round(2)
print(summary.to_string())
print("read", len(raw), "kept", len(clean), "rejected", len(rejects), "duplicates", len(raw) - len(clean) - len(rejects))
```

```output
         orders  revenue
country                 
DE            1   150.00
UK            2  1285.50
US            1   109.99
read 10 kept 4 rejected 4 duplicates 2
```

All assertions pass. The four counts add up: 10 rows read, 4 kept, 4 rejected and 2 duplicates removed.

## Real-world applications

- **Loading a vendor file.** A data engineer writes a `clean_orders` function once and runs it on every new file, with the assertions as the acceptance test.
- **Reporting with an audit trail.** An analyst delivers revenue figures together with the counts of rejected and duplicate rows, so reviewers see what was excluded.
- **Quarantine tables.** Rejected rows go to a separate table that a data owner reviews, which is how data quality processes work in pipelines.

## Daily review

### Key takeaways

- Profile first, read as text, and count problems before fixing any.
- Standardise text before deduplicating; convert types with `errors="coerce"` and count the failures.
- Use an explicit rule for repeated keys, and keep rejected rows with counts.
- Validate with assertions and reconcile counts: read equals kept plus rejected plus duplicates.

### Common mistakes

- Deduplicating before standardising text: `"UK "` and `"uk"` look different, so copies survive. Clean the text first.
- Using `errors="coerce"` and never looking at the `NaN` values it creates. Always count them.
- Calling `drop_duplicates()` without a subset on a table where repeated ids differ in one column: both rows survive and the key is not unique. Decide a rule with `subset` and `keep`.
- Overwriting the raw table. Work on a copy so the original can be re-checked.

### Revision notes

- Order: profile, text, types, duplicates, missing, validate.
- Keep `rejects` and report counts.
- `assert` turns a rule into a check.
