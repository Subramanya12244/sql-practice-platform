## Understand

### What a lookup is

A **lookup** fetches a value from a reference table by finding a **key**. You have an orders list that holds a product code, and a separate price list that holds each product code with its price. A lookup takes the product code from the order row, finds it in the price list and brings the price back. It is the Excel counterpart of a left join in SQL and of `merge` in pandas. The pieces are always the same: the **lookup value** (the key you have), the **lookup range** (where to search, with the key in one column) and the **return range** (where the answer lives).

A lookup table must have unique keys for the result to mean anything. A price list with the same product code twice has no single right answer.

### Exact and approximate match

In an **exact match**, Excel looks for a key equal to the lookup value, and returns an error (`#N/A`, "not available") if there is none. In an **approximate match**, Excel looks for the largest key that is less than or equal to the lookup value. Approximate match is right when the keys are ranges, such as a tax band that starts at 0, 10,000 and 40,000, or a grade that begins at 0, 50, 70 and 90. A score of 73 falls in the band starting at 70. For an approximate match to work, the keys must be sorted from smallest to largest. If they are not, the result can be wrong without any error message.

This is the most important thing to remember about the oldest lookup function: `VLOOKUP` uses an approximate match unless you tell it not to. The fourth argument is `TRUE` or omitted for approximate and `FALSE` (or 0) for exact. A beginner who types `=VLOOKUP(A2, Prices, 2)` for an exact job gets answers that look right on a small sorted sample and are wrong on real data.

### VLOOKUP

`VLOOKUP(lookup_value, table_array, col_index_num, [range_lookup])` searches the first column of `table_array` for `lookup_value`, then returns the value from column number `col_index_num` of the same row. For a price list in `F2:G10`, `=VLOOKUP(B2, $F$2:$G$10, 2, FALSE)` finds B2 in column F and returns the price from column G. The table address is absolute (Day 92) so that it does not move when filled down. Three weaknesses explain why newer functions exist. The key must be in the first column, so `VLOOKUP` cannot look to the left. The column number is a hard-coded count, so inserting a column in the table silently makes the formula return the wrong column. And it returns only the first match when keys repeat.

### XLOOKUP

`XLOOKUP(lookup_value, lookup_array, return_array, [if_not_found], [match_mode], [search_mode])` takes the search column and the answer column as two separate ranges. It needs Excel 2021 or Microsoft 365 (it is not in Excel 2019 or earlier). Its exact match is the default, so the common job is shorter: `=XLOOKUP(B2, Prices[Code], Prices[Price], "not listed")`. Because search and return are separate, it can look left, and inserting columns does not break it. `if_not_found` replaces the `#N/A` with something readable. `match_mode` 0 is exact, -1 is exact or the next smaller item, 1 is exact or the next larger item and 2 allows wildcards. `search_mode` 1 searches from the first item (the default) and -1 from the last, which is how you find the most recent match in a list sorted by date.

### INDEX and MATCH

`MATCH(lookup_value, lookup_array, 0)` returns the position of the key within a range, counted from 1. `INDEX(return_array, position)` returns the item at that position. Joined, `=INDEX(G2:G10, MATCH(B2, F2:F10, 0))` does what `VLOOKUP` does, but the search and return columns are separate, so it works in any direction and survives inserted columns. The last argument of `MATCH` is `0` for exact, `1` for the largest value that is smaller or equal (sorted ascending, like approximate `VLOOKUP`), and `-1` for the smallest value that is larger or equal (sorted descending). INDEX with MATCH works in every version of Excel, so it is the right choice when a file must open in older versions.

### How Excel behaves compared with pandas

A merge in pandas joins on exact, case-sensitive equality and keeps every matching row. Excel differs in four ways. Text comparison in lookups is **case-insensitive**: `"north"` finds `"North"`. A lookup returns the **first** match and ignores the rest, while `merge` returns one output row for every match and so can **multiply rows** if the lookup table has duplicates. A missing key gives `#N/A` in Excel and `NaN` in pandas. A key stored as text in one table and as a number in the other (`"101"` against `101`) fails in Excel with `#N/A` because the two are different types, even though they look identical; pandas raises a `ValueError` in `merge` when the column types are incompatible. A key with a trailing space also fails in both.

### Why it matters

Lookups are how analysts combine tables: attach a category to a product, a region to a customer, or a rate to a date. Most "the numbers do not match" problems in a workbook are lookup problems: a duplicate key, a text number, a hidden space or an approximate match used where an exact one was intended.

## Syntax and key functions

```excel
=VLOOKUP(lookup_value, table_array, col_index_num, FALSE)
=XLOOKUP(lookup_value, lookup_array, return_array, "not found", 0, 1)
=INDEX(return_array, MATCH(lookup_value, lookup_array, 0))
```

In `VLOOKUP`, `FALSE` requests an exact match; leave it out and you get an approximate match. In `XLOOKUP`, only the first three arguments are required. In `MATCH`, `0` means exact.

| Function | Returns |
|---|---|
| `VLOOKUP(v, table, n, FALSE)` | Value in column `n` of the row whose first column equals `v`; `#N/A` if none. |
| `VLOOKUP(v, table, n, TRUE)` | Same, using the largest key not greater than `v` (table sorted ascending). |
| `XLOOKUP(v, keys, values, nf)` | The matching item of `values`, or `nf` when no match. |
| `MATCH(v, keys, 0)` | Position (from 1) of the exact match; `#N/A` if none. |
| `INDEX(values, k)` | The `k`th item of `values`. |
| `IFNA(f, v)` | `f` unless it is `#N/A`, then `v`. |

pandas equivalents: `left.merge(right, on="Code", how="left")`, `s.map(series)`, `pd.merge_asof(left, right, on="Key")` for approximate matches.

## Learn by example

### Example 1: An exact VLOOKUP and its merge

The price list is in `F2:G5` and the orders have codes in column B.

| Code | Price |
|---|---|
| P1 | 10.00 |
| P2 | 25.00 |
| P3 | 7.50 |
| P4 | 40.00 |

```excel
=VLOOKUP(B2, $F$2:$G$5, 2, FALSE)
=XLOOKUP(B2, $F$2:$F$5, $G$2:$G$5)
=INDEX($G$2:$G$5, MATCH(B2, $F$2:$F$5, 0))
```

All three return the same price. For orders with codes `P2`, `P1`, `P4`, `P9`, the code `P9` is not in the list: `VLOOKUP` and `INDEX/MATCH` return `#N/A`, and `XLOOKUP` also returns `#N/A` unless you give it an `if_not_found`.

```python run
import pandas as pd

prices = pd.DataFrame({"Code": ["P1", "P2", "P3", "P4"], "Price": [10.0, 25.0, 7.5, 40.0]})
orders = pd.DataFrame({"Order": [1, 2, 3, 4], "Code": ["P2", "P1", "P4", "P9"]})
out = orders.merge(prices, on="Code", how="left")
print(out.to_string(index=False))
print(orders["Code"].map(prices.set_index("Code")["Price"]).tolist())
```

```output
 Order Code  Price
     1   P2   25.0
     2   P1   10.0
     3   P4   40.0
     4   P9    NaN
[25.0, 10.0, 40.0, nan]
```

A left merge keeps all orders and gives `NaN` where the key is missing, just as the lookup gives `#N/A`. `how="left"` is essential: the default `inner` would drop order 4. `map` with a Series does the same lookup for one column.

### Example 2: Duplicates, case and spaces

Suppose the price list has `P2` twice, and one order key is typed as `"p2 "` in lower case with a trailing space.

| Code | Price |
|---|---|
| P1 | 10 |
| P2 | 25 |
| P2 | 26 |

Excel's `VLOOKUP("P2", table, 2, FALSE)` returns 25, the first match. `VLOOKUP("p2", ...)` also returns 25, because it ignores case. `VLOOKUP("p2 ", ...)` returns `#N/A` because of the trailing space.

```python run
import pandas as pd

prices = pd.DataFrame({"Code": ["P1", "P2", "P2"], "Price": [10, 25, 26]})
orders = pd.DataFrame({"Code": ["P2", "p2", "p2 "]})
print(orders.merge(prices, on="Code", how="left").to_string(index=False))

first = prices.drop_duplicates("Code", keep="first").assign(key=lambda d: d["Code"].str.lower())
orders["key"] = orders["Code"].str.strip().str.lower()
print(orders.merge(first[["key", "Price"]], on="key", how="left")["Price"].tolist())
```

```output
Code  Price
  P2   25.0
  P2   26.0
  p2    NaN
 p2     NaN
[25, 25, 25]
```

The first merge shows the differences: the duplicate `P2` doubles the first order into two rows, and `p2` and `p2 ` find nothing because pandas matches exactly. The second block copies Excel: keep the first duplicate, compare in lower case. It also goes one step beyond Excel by stripping the space, which Excel's lookup would not do on its own. Use `TRIM` in the formula (`=VLOOKUP(TRIM(B2), ...)`) or clean the data.

### Example 3: XLOOKUP, left lookups and the last match

An employee table has the name first and the ID second, and a log table is sorted by date, with several rows for the same ID.

| ID | Name |
|---|---|
| 7 | Ada |
| 9 | Grace |

```excel
=XLOOKUP(9, B2:B3, A2:A3, "no such ID")
=XLOOKUP(5, B2:B3, A2:A3, "no such ID")
=XLOOKUP(7, LogID, LogStatus, "none", 0, -1)
```

The first formula looks up an ID in the second column and returns the name from the first column, which `VLOOKUP` cannot do. The second shows the message. The third uses search mode -1 to return the last (most recent) status for ID 7.

```python run
import pandas as pd

emp = pd.DataFrame({"Name": ["Ada", "Grace"], "ID": [7, 9]})
print(emp.set_index("ID")["Name"].get(9, "no such ID"))
print(emp.set_index("ID")["Name"].get(5, "no such ID"))

log = pd.DataFrame({"ID": [7, 9, 7], "Status": ["new", "open", "closed"]})
print(log.loc[log["ID"] == 7, "Status"].iloc[0])
print(log.loc[log["ID"] == 7, "Status"].iloc[-1])
print(log.drop_duplicates("ID", keep="last").set_index("ID")["Status"].to_dict())
```

```output
Grace
no such ID
new
closed
{9: 'open', 7: 'closed'}
```

`get(key, default)` is the replica of `if_not_found`. The third and fourth lines show the first and last match for ID 7, and the final line keeps the last status for each ID, which is the table version of search mode -1. `merge` has no search mode: you decide which duplicates to keep before the join.

### Example 4: INDEX and MATCH step by step

```excel
=MATCH("Grace", B2:B4, 0)         gives 2
=INDEX(C2:C4, 2)                  gives the second item of C2:C4
=INDEX(C2:C4, MATCH("Grace", B2:B4, 0))
```

Let `B2:B4` hold `Ada`, `Grace`, `Alan` and `C2:C4` hold the salaries 50, 62, 58.

```python run
names = ["Ada", "Grace", "Alan"]
salary = [50, 62, 58]

pos = names.index("Grace") + 1
print(pos)
print(salary[pos - 1])
print(salary[names.index("Grace")])
try:
    names.index("Zed")
except ValueError:
    print("not found")
```

```output
2
62
62
not found
```

`MATCH` returns 2 (position counted from 1), so the Python position is `index + 1`. `INDEX` with 2 returns 62. The `ValueError` plays the role of the `#N/A` that `MATCH` returns for a missing name. Wrap with `IFNA(..., "not found")` to display your own message.

### Example 5: Approximate match on bands

Commission bands start at the sales amounts 0, 1000 and 5000 with rates 0%, 2% and 5%. The band table must be sorted ascending.

| From | Rate |
|---|---|
| 0 | 0% |
| 1000 | 2% |
| 5000 | 5% |

```excel
=VLOOKUP(B2, $F$2:$G$4, 2, TRUE)
=XLOOKUP(B2, $F$2:$F$4, $G$2:$G$4, , -1)
=INDEX($G$2:$G$4, MATCH(B2, $F$2:$F$4, 1))
```

Amounts 999, 1000, 4999 and 5000 give 0%, 2%, 2% and 5%: an amount exactly on a threshold falls in that band.

```python run
import pandas as pd

bands = pd.DataFrame({"From": [0, 1000, 5000], "Rate": [0.0, 0.02, 0.05]})
sales = pd.DataFrame({"Amount": [999, 1000, 4999, 5000, -5]}).sort_values("Amount")
out = pd.merge_asof(sales, bands, left_on="Amount", right_on="From", direction="backward")
print(out[["Amount", "Rate"]].to_string(index=False))
```

```output
 Amount  Rate
     -5   NaN
    999  0.00
   1000  0.02
   4999  0.02
   5000  0.05
```

`merge_asof` with `direction="backward"` picks the last band whose start is less than or equal to the amount, and both inputs must be sorted. The amount -5 is below the first band, so pandas gives `NaN`; `VLOOKUP` returns `#N/A` for the same reason. Make the first band start low enough to cover every possible value.

### Example 6: A text number defeats a lookup

A key stored as text, `"101"`, does not match the number `101`.

```python run
import pandas as pd

a = pd.DataFrame({"ID": ["101", "102"], "Name": ["Ada", "Grace"]})
b = pd.DataFrame({"ID": [101, 102], "City": ["Oslo", "Rome"]})
try:
    a.merge(b, on="ID")
except ValueError as e:
    print(type(e).__name__)
b["ID"] = b["ID"].astype(str)
print(a.merge(b, on="ID").to_string(index=False))
```

```output
ValueError
 ID  Name City
101   Ada Oslo
102 Grace Rome
```

In Excel the same mismatch shows no message at all, only `#N/A`. Both cases are fixed by converting both keys to the same type: with `VALUE` or `--` in the formula, or with `Text to Columns` for a whole column. Left-aligned keys with a green triangle are the warning sign.

## Real-world applications

- **Enriching transactions.** Look up category, region or unit cost for each transaction from a reference sheet. The exact match with `XLOOKUP` and a clear not-found message makes missing master data visible (Examples 1 and 3).
- **Banded calculations.** Commission, tax or discount tiers sit in a small sorted table and an approximate match applies them (Example 5).
- **Reconciling two lists.** `MATCH` with `IFNA` flags items in one list that are missing from the other, a first check before a merge in pandas (Example 4).
- **Auditing a join.** Count rows before and after a merge to find duplicate keys that multiply rows, which Excel's first-match lookup would hide (Example 2).

## Daily review

### Key takeaways

- A lookup finds a key in one column and returns a value from another; it is the spreadsheet join.
- `VLOOKUP` defaults to an approximate match; write `FALSE` for exact.
- `XLOOKUP` (Excel 2021 or 365) has an exact default, separate columns, a not-found argument and a search direction; `INDEX`/`MATCH` works in all versions and in any direction.
- Approximate matches need the keys sorted ascending and a first key low enough to cover every value.
- Excel's lookup ignores case and returns the first match; `merge` is case-sensitive and returns every match.

### Common mistakes

- Omitting `FALSE` in `VLOOKUP`: the exact-looking answers are wrong when the table is not sorted or the key is not present.
- Hard-coding the column number and then inserting a column in the table, so `VLOOKUP` returns the wrong field.
- Letting the table range drift when filling down because it lacks `$` signs, so lookups fail in lower rows.
- Looking up a text number in a numeric key column, or a key with a trailing space, and reading the `#N/A` as "missing data".
- Merging in pandas with duplicate keys and finding more rows than before.
- Using an inner `merge` where a left lookup was intended, which silently drops unmatched rows.

### Revision notes

- `=VLOOKUP(v, table, n, FALSE)`, `=XLOOKUP(v, keys, values, "none")`, `=INDEX(values, MATCH(v, keys, 0))`.
- Approximate: sorted keys, `TRUE`, `MATCH(v, keys, 1)`, or `merge_asof(direction="backward")`.
- `#N/A` means not found; `IFNA` or `if_not_found` handle it.
- Check type, spaces and duplicates before looking up.
