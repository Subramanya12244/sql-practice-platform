## Understand

### Filter context

Day 129 ended with a promise: a measure returns a different number in each cell of a visual. The reason is the **filter context**, the set of filters in force on the model at the moment a measure is evaluated. Every one of the following adds filters: the row and column headings of a matrix or the axis of a chart, a slicer, a filter in the Filters pane (visual, page or report level) and a selection made by clicking another visual. Filters travel along relationships. A filter on `Products[category]` restricts the product table, and because the relationship runs from `Products` to `Sales` (Day 127), only the sales of those products remain visible. The measure `SUM(Sales[Revenue])` then adds up the surviving rows.

A good mental model is a spreadsheet of the whole model with some rows hidden. The filter context decides which rows are hidden; the measure only adds up what is left. A measure has no idea which cell it is drawing; it only sees what remains visible.

### CALCULATE: changing the filter context

`CALCULATE(<expression>, <filter>, <filter>, ...)` evaluates the expression in a **modified** filter context. It starts from the current context, applies the filter arguments, and then evaluates. It is the most important function in DAX, because it is how a measure asks "what would this number be if the filters were different?".

```dax
Hardware Revenue = CALCULATE([Total Revenue], Products[category] = "Hardware")
```

A filter argument that names a column and a value replaces any existing filter on that same column. In a matrix row for Software, `Hardware Revenue` still shows the revenue of Hardware, because the Software filter on `category` was replaced, not combined with the new one. Filters on other columns stay: in the cell Software by UK the measure returns Hardware sold to UK customers. This replace-on-same-column rule is the thing beginners expect to work the other way round (they expect "Software and Hardware", which is empty).

### ALL: removing filters

`ALL` is a filter modifier that removes filters. `ALL(Products)` removes every filter on the `Products` table, `ALL(Products[category])` removes only the filter on that column, and `ALL(Sales)` clears the fact table. Removing the filter on the grouping column gives a denominator for a share of total:

```dax
Revenue Share = DIVIDE([Total Revenue], CALCULATE([Total Revenue], ALL(Products)))
```

In the Hardware row the numerator carries the Hardware filter and the denominator evaluates with the category filter removed. Filters that are not removed still apply, so with a slicer on country the share is a share of that country's revenue, which is usually what the reader wants.

### FILTER: conditions on rows

A simple condition on one column, such as `Products[category] = "Hardware"`, is shorthand for a filter that returns the allowed values of that column. When the condition involves several columns or a measure, write it with `FILTER(<table>, <condition>)`. `FILTER` is an **iterator**: it goes through the table row by row, evaluates the condition for each row, and returns the rows where it is true. That row-by-row behaviour is where its power and its cost both come from.

```dax
Large Order Revenue = CALCULATE([Total Revenue], FILTER(Sales, Sales[Revenue] > 300))
```

The inner `FILTER` returns the `Sales` rows with revenue above 300, and `CALCULATE` uses them as a filter. Note that `FILTER(Sales, ...)` iterates the rows that are visible in the current context; to ignore the current filters, wrap the table in `ALL`, as in `FILTER(ALL(Sales[Revenue]), Sales[Revenue] > 300)`, which is what a one-column boolean condition does for you.

### Row context and context transition

Day 129 introduced the **row context**: inside a calculated column or an iterator the formula knows its current row. A row context is not a filter. Inside a calculated column on `Customers`, the expression `SUM(Sales[Revenue])` ignores which customer the row is, because no filter has been placed on `Sales`. It returns the total of all sales, repeated on every customer row, which is the most common first surprise in DAX.

`CALCULATE` fixes this through **context transition**: when `CALCULATE` is evaluated inside a row context, it converts the current row into filters on the columns of that row and then evaluates. In a `Customers` column, `CALCULATE(SUM(Sales[Revenue]))` turns the row into a filter on that customer, and the relationship carries it to `Sales`. A measure reference behaves the same way, because every measure reference is wrapped in an implicit `CALCULATE`. So `Customers[Customer Revenue] = [Total Revenue]` returns each customer's own revenue. The pandas version is a `groupby` on the customer.

### Why it matters

Share of total, year-to-date, top N and "versus all" comparisons all rely on `CALCULATE`. Without it a report can only show what the visual's filters give; with it, one measure can compare a selection to its own baseline. The misconception to avoid is thinking `CALCULATE` adds to the filters. It overrides filters on the same column, removes them with `ALL`, and only otherwise adds.

## Syntax and key functions

```dax
CALCULATE(<expression>, <filter1>, <filter2>, ...)
FILTER(<table>, <condition>)
ALL(<table or column>, ...)
```

The first argument of `CALCULATE` is the expression to evaluate (usually a measure). Each later argument is a filter: a boolean test on one column, a table from `FILTER` or `ALL`, or another filter modifier.

| Function | What it does |
|---|---|
| `CALCULATE(expr, filters)` | Evaluates `expr` in the current filter context changed by the filters. |
| `FILTER(table, condition)` | Returns the rows of `table` for which the condition is true. |
| `ALL(table or column)` | Returns all rows or values and so removes filters on them. |
| Boolean filter such as `Products[category] = "Hardware"` | Replaces the filter on that column with the given values. |

The pandas model used in this lesson treats the context as a dictionary:

```python
def revenue(ctx):            # ctx maps a column to the allowed values
    d = fact
    for col, vals in ctx.items():
        d = d[d[col].isin(vals)]
    return d["revenue"].sum()
```

## Learn by example

### Example 1: A filter context is a set of selections

Each cell of a matrix is a dictionary of selected values; the measure is one function of it.

```python run
import numpy as np
import pandas as pd

rng = np.random.default_rng(7)
countries = ["UK", "Germany", "France", "Spain"]
cats = ["Hardware", "Software", "Services"]
customers = pd.DataFrame({
    "customer_id": range(1, 41),
    "customer_name": [f"Customer {i:02d}" for i in range(1, 41)],
    "country": [countries[i % 4] for i in range(40)],
    "segment": [["Retail", "Corporate"][(i // 4) % 2] for i in range(40)],
})
products = pd.DataFrame({
    "product_id": range(1, 13),
    "product_name": [f"Product {i:02d}" for i in range(1, 13)],
    "category": [cats[i % 3] for i in range(12)],
    "unit_cost": [float(10 + 5 * i) for i in range(12)],
})
n = 400
sales = pd.DataFrame({
    "order_id": range(1, n + 1),
    "order_date": pd.to_datetime("2025-01-01") + pd.to_timedelta(rng.integers(0, 365, n), unit="D"),
    "customer_id": rng.integers(1, 41, n),
    "product_id": rng.integers(1, 13, n),
    "quantity": rng.integers(1, 6, n),
})
sales["unit_price"] = (sales["product_id"].map(products.set_index("product_id")["unit_cost"]) * 1.5).round(2)
calendar = pd.DataFrame({"date": pd.date_range("2025-01-01", "2025-12-31")})
calendar["year"] = calendar["date"].dt.year
calendar["quarter"] = calendar["date"].dt.quarter
calendar["month_number"] = calendar["date"].dt.month
calendar["month_name"] = calendar["date"].dt.strftime("%B")
sales["revenue"] = sales["quantity"] * sales["unit_price"]
fact = (sales.merge(customers, on="customer_id").merge(products, on="product_id")
        .merge(calendar, left_on="order_date", right_on="date"))
def revenue(ctx):
    d = fact
    for col, vals in ctx.items():
        d = d[d[col].isin(vals)]
    return round(float(d["revenue"].sum()), 2)

print(revenue({}))
print(revenue({"category": ["Software"]}))
print(revenue({"category": ["Software"], "country": ["UK"]}))
```

```output
67132.5
20835.0
4725.0
```

With no filters the measure returns the model total, 67,132.50. A row for Software gives 20,835.00, and adding a UK slicer gives 4,725.00. The measure itself never changed; only the dictionary did.

### Example 2: CALCULATE replaces a filter on the same column

`calculate(ctx, category=["Hardware"])` copies the context and sets the `category` selection, which is what a boolean filter argument does.

```dax

```

        .merge(calendar, left_on="order_date", right_on="date"))
def revenue(ctx):
    d = fact
    for col, vals in ctx.items():
        d = d[d[col].isin(vals)]
    return round(float(d["revenue"].sum()), 2)

def calculate(ctx, **changes):
    new = dict(ctx)
    for col, vals in changes.items():
        if vals is None:
            new.pop(col, None)      # ALL on that column
        else:
            new[col] = vals         # replace the selection
    return revenue(new)

cell = {"category": ["Software"], "country": ["UK"]}
print(revenue(cell))
print(calculate(cell, category=["Hardware"]))

```output
4725.0
4005.0
```

In the Software by UK cell, the plain measure is 4,725.00. `Hardware Revenue` returns 4,005.00: the Software selection was replaced by Hardware, and the UK filter on a different column was kept. That is the Hardware by UK figure from Day 129.

## Real-world applications

- **Share of total and ranking context.** A sales page shows each category's share with `ALL`, and the share still responds to a country slicer (Example 3).
- **Segment definitions.** "Large order revenue" or "Corporate revenue" measures built with `FILTER` and boolean filters let one visual compare a segment to the total without a new table (Example 4).
- **Customer attributes.** A calculated column such as lifetime revenue, using context transition, can then be used to band customers into tiers in a slicer (Example 5).
- **Benchmarks in one visual.** A "versus Hardware" or "versus all" line is a `CALCULATE` that replaces or removes the grouping filter (Example 2).

## Daily review

### Key takeaways

- Filter context is the set of filters from headings, slicers and filter panes, carried through relationships.
- `CALCULATE` evaluates an expression in a changed context: a filter on a column replaces the existing filter on that column.
- `ALL` removes filters from a table or column; it is the usual denominator of a share.
- `FILTER` iterates rows and returns those that pass a condition.
- Context transition turns the current row into filters; measure references do it automatically.

### Common mistakes

- Expecting `CALCULATE([m], Products[category] = "Hardware")` to give blank in the Software row. It replaces the filter and returns Hardware.
- Using `ALL(Sales)` when the filters sit on `Products`, so the denominator is still filtered. Name the table or column that holds the filter.
- Writing `SUM(Sales[Revenue])` in a calculated column and getting the same total on every row. Wrap it in `CALCULATE` or use a measure.
- Wrapping a large table in `FILTER` when a boolean column condition would do, which is slower and harder to read.
- Forgetting that `ALL` removes the selected filters from slicers on that table too, which can make a share ignore a slicer unintentionally.

### Revision notes

- Filter context: headings, slicers, filter panes, through relationships.
- `CALCULATE(expr, filters)`; same-column filters are replaced.
- `ALL(table)` or `ALL(column)` removes filters; share = measure / `CALCULATE(measure, ALL(...))`.
- `FILTER(table, condition)` iterates; context transition: row becomes filter.
- pandas model: a dictionary of selected values per column.
