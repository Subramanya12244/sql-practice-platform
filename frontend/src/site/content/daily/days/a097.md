## Objectives

- Choose a chart type (column, bar, line, pie, scatter) from the question the chart answers and the shape of the data.
- Build a chart from a Table or a PivotTable, and a combo chart that puts a second measure on a secondary axis.
- Format a chart so that it is honest and readable: title, axis titles, a zero baseline for bars, few colours, direct labels.
- Assemble an interactive dashboard from KPI cells, charts, PivotCharts and slicers on one sheet.
- Prepare the data behind each chart with pandas, so that every number in a chart can be checked.

## Understand

### A chart answers a question

A **chart** is a drawing of numbers in which position, length or angle stands for a value. Before choosing a chart, state the question in one sentence: "How did revenue change month by month?", "Which regions sell most?", "What share does each product have?", "Do larger orders have bigger discounts?". The question decides the chart, and the shape of the data confirms it. Decoration is never the reason to choose.

- **Comparing categories** (regions, products): a **column** chart (vertical bars) or a **bar** chart (horizontal bars). Use bars when the labels are long, and sort the categories by value unless they have a natural order.
- **Change over time**: a **line** chart, with the time axis in order and equal spacing. Use columns for a few periods when you want the individual values to stand out.
- **Parts of a whole**: a **pie** chart is acceptable only for a few slices (about five or fewer) that add to 100%. Otherwise a sorted bar chart is easier to read, because lengths are compared more accurately than angles.
- **Relationship between two numbers**: a **scatter** chart, one point per row.
- **Two measures with different units**: a **combo** chart.

### Building a chart in Excel

Select a cell inside the data and choose Insert, then Recommended Charts, or pick a type from the Charts group. Excel guesses which cells are labels and which are values. When the source is an Excel Table, the chart uses the whole Table columns and grows when rows are added. Check three things at once: the labels are on the axis, each series is the right column, and the chart title is meaningful. Right-click the chart and choose Select Data to change the series by hand, and Switch Row/Column if the categories and the series are swapped. A chart built from a **PivotTable** is a **PivotChart** (PivotTable Analyze, PivotChart). It follows the pivot: filtering the pivot or a slicer filters the chart, and it is rebuilt on refresh.

### Combo charts and secondary axes

A **combo chart** combines two chart types in one plot, such as columns for revenue and a line for margin percentage. Choose Insert, Recommended Charts, All Charts, then Combo, and for each series choose a type, with a tick for Secondary Axis. The reason for a **secondary axis** is that revenue (thousands) and margin (a percentage between 0 and 1) have different scales: on one axis the margin line would sit flat against the bottom. The secondary axis is a second vertical scale drawn on the right. Use it sparingly, because readers cannot tell which scale a point belongs to, and a different axis range can make two lines appear to cross or follow each other when they do not. Label both axes and colour each axis title like its series.

### Formatting for honesty and readability

Use the Chart Design and Format tabs, or the plus button at the chart's corner, to set the elements. Give the chart a title that states the message, not only the topic ("Revenue grew 18% from January to March" is better than "Revenue"). Add axis titles with units. For column and bar charts, the value axis must start at **zero**: a bar's length is the value, and a truncated axis makes small differences look huge. A line chart may start above zero because the position of the line matters, not its length from the baseline. Remove what carries no information: heavy gridlines, 3-D effects, background pictures and a legend when there is one series. Use one colour for all bars and a different one only to highlight the point you are making. Use data labels when there are few points, and number formats such as `#,##0` for thousands.

### Dashboards

A **dashboard** is one sheet that shows the few numbers and charts that answer a recurring question and lets the viewer change the view. The usual building blocks are:

- **KPI cells**: large formula cells with totals and rates, such as `=SUM(Sales[Amount])` (Day 95 gave `SUMIFS` for conditional ones). Place them at the top.
- **Charts and PivotCharts** below or beside them, each with one message.
- **Slicers and timelines** that filter the PivotTables (Day 96) behind the charts. A slicer is connected to each pivot through Report Connections, so one click updates every chart.
- **Sparklines** (Insert, Sparklines): tiny line or column charts inside a single cell, one per row.
- **Conditional formatting** such as data bars or colour rules to flag values.

Keep the raw data and the pivots on other sheets. The dashboard sheet holds only what the viewer reads. KPI formulas written on a Table do not respond to a pivot slicer. If KPI cells must follow a filter, base them on the pivot (with `GETPIVOTDATA`), or use a slicer on the Table and write the KPIs with `SUBTOTAL(109, ...)`, which ignores filtered rows. Order the sheet in the way people read: top left first, most important first.

### Misconceptions and why it matters

One misconception is that a more elaborate chart is more professional. The opposite is usually true: the audience should see the answer in a few seconds. A second misconception is that a chart is a picture. In Excel it is a live object linked to cells: change a number and the bars move, which also means a wrong number in the source becomes a wrong bar. Verifying the data behind each chart, as the examples below do with pandas, is part of the work.

## Syntax and key functions

Charts have no formula syntax, but a chart series is defined by a `SERIES` formula visible when you click a series:

```excel
=SERIES(Sheet1!$B$1, Sheet1!$A$2:$A$13, Sheet1!$B$2:$B$13, 1)
```

The arguments are the series name cell, the category labels, the values and the plot order. A dashboard KPI and a text label can be built with ordinary formulas:

```excel
=SUM(Sales[Amount])
=SUBTOTAL(109, Sales[Amount])
=TEXT(B2/B1-1, "+0.0%;-0.0%")
```

Sparklines are inserted from the Insert tab, not typed as formulas.

| Item | Use |
|---|---|
| Column / Bar | Compare categories; value axis starts at 0. |
| Line | Change over time. |
| Pie | Few slices that add to a whole. |
| Scatter | Relationship between two numbers. |
| Combo, Secondary Axis | Two measures with different scales. |
| PivotChart | A chart tied to a PivotTable. |
| Slicer, Timeline | Buttons that filter pivots and their charts. |
| Sparkline | A mini chart in one cell. |

## Learn by example

### Example 1: Prepare the data for a column and a line chart

Every chart begins as a small table. Monthly revenue for a line chart, and revenue by region sorted for a bar chart.

| Month | Region | Amount |
|---|---|---|
| 2025-01 | North | 100 |
| 2025-01 | South | 60 |
| 2025-02 | North | 120 |
| 2025-02 | South | 50 |
| 2025-03 | North | 150 |
| 2025-03 | South | 90 |

```python run
import pandas as pd

d = pd.DataFrame({
    "Month": ["2025-01", "2025-01", "2025-02", "2025-02", "2025-03", "2025-03"],
    "Region": ["North", "South", "North", "South", "North", "South"],
    "Amount": [100, 60, 120, 50, 150, 90],
})
monthly = d.groupby("Month")["Amount"].sum()
print(monthly.to_dict())
print(monthly.pct_change().round(3).tolist())
by_region = d.groupby("Region")["Amount"].sum().sort_values(ascending=False)
print(by_region.to_dict())
```

```output
{'2025-01': 160, '2025-02': 170, '2025-03': 240}
[nan, 0.062, 0.412]
{'North': 370, 'South': 200}
```

The line chart has three points, 160, 170 and 240. The month-on-month changes are `nan` (no previous month), +6.2% (0.062) and +41.2%. The bar chart is sorted North (370) then South (200). In Excel, a PivotChart on this Table with Month in Axis and Amount in Values produces the same three points.

### Example 2: A pie chart or a sorted bar chart?

Five categories are fine for a pie; twelve are not. The table compares shares for each case.

```python run
import pandas as pd

s = pd.Series({"A": 40, "B": 25, "C": 15, "D": 10, "E": 6, "F": 4})
share = (s / s.sum() * 100).round(1)
print(share.to_dict())
top = s.sort_values(ascending=False)
grouped = pd.concat([top.iloc[:3], pd.Series({"Other": top.iloc[3:].sum()})])
print((grouped / grouped.sum() * 100).round(1).to_dict())
```

```output
{'A': 40.0, 'B': 25.0, 'C': 15.0, 'D': 10.0, 'E': 6.0, 'F': 4.0}
{'A': 40.0, 'B': 25.0, 'C': 15.0, 'Other': 20.0}
```

Six slices (40, 25, 15, 10, 6 and 4 percent) are hard to compare by angle, and the last two are barely visible. Keeping the top three and adding the rest as `Other` (40.0, 25.0, 15.0 and 20.0 percent) leaves four slices that are easy to compare. A sorted bar chart of all six categories is still the clearest. Excel's way to get `Other` is a helper column in the Table or a manual group in the pivot (Day 96).

### Example 3: A combo chart and why it needs a second axis

Revenue is in the hundreds and margin is a fraction.

| Month | Revenue | Margin |
|---|---|---|
| Jan | 160 | 0.25 |
| Feb | 170 | 0.30 |
| Mar | 240 | 0.28 |

Select the three columns, choose Insert, Recommended Charts, All Charts, Combo. Set Revenue to Clustered Column and Margin to Line, and tick Secondary Axis for Margin. The matplotlib code below draws the same picture and prints its properties instead of an image. It needs `matplotlib` on your computer.

```python local
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt

months = ["Jan", "Feb", "Mar"]
revenue = [160, 170, 240]
margin = [0.25, 0.30, 0.28]
fig, ax = plt.subplots()
ax.bar(months, revenue)
ax.set_ylabel("Revenue")
ax2 = ax.twinx()
ax2.plot(months, margin, marker="o", color="tab:orange")
ax2.set_ylabel("Margin")
ax.set_title("Revenue and margin by month")
print(ax.get_title())
print(len(ax.patches), len(ax2.lines))
print(ax.get_ylabel(), ax2.get_ylabel())
print(ax.get_ylim()[0], ax2.get_ylim()[0] <= 0.25)
```

```output
Revenue and margin by month
3 1
Revenue Margin
0.0 True
```

The chart has 3 bars and one line, the left axis is Revenue and the right axis is Margin. A bar axis starts at 0. The line has its own range around 0.25 to 0.30, which would be invisible on the revenue scale (a line at 0.3 next to bars of 160 to 240).

### Example 4: Truncated axes exaggerate differences

Two columns show 95 and 100. With the axis starting at 0, the second bar is 5.3% longer. With the axis starting at 90, it is twice as long.

```python run
a, b = 95, 100
print(round(b / a - 1, 3))
for base in [0, 90]:
    ha, hb = a - base, b - base
    print(base, round(hb / ha, 2))
```

```output
0.053
0 1.05
90 2.0
```

The true difference is 5.3%. With a zero baseline, the visual ratio is 1.05, which matches. With the baseline at 90, the visual ratio is 2.0, so the picture claims a 100% difference. In Excel, check Format Axis, Bounds, Minimum: it must be 0 for bars and columns.

### Example 5: KPI cells and a slicer on a Table

A dashboard shows total revenue, order count and average order value for the selected region. If a slicer on the Table selects `North`, `SUBTOTAL` formulas ignore the hidden rows.

```excel
Revenue:     =SUBTOTAL(109, Sales[Amount])
Orders:      =SUBTOTAL(103, Sales[Amount])
Average:     =IFERROR(B2/B3, 0)
```

Code 103 is `COUNTA` that ignores filtered rows. For the table below, the values with no filter are 6 orders and 570 revenue, and for North 3 orders and 370.

```python run
import pandas as pd

d = pd.DataFrame({
    "Region": ["North", "South", "North", "South", "North", "South"],
    "Amount": [100, 60, 120, 50, 150, 90],
})
def kpis(df):
    revenue = int(df["Amount"].sum())
    orders = len(df)
    return revenue, orders, float(round(revenue / orders, 2)) if orders else 0

print(kpis(d))
print(kpis(d[d["Region"] == "North"]))
print(kpis(d[d["Region"] == "West"]))
```

```output
(570, 6, 95.0)
(370, 3, 123.33)
(0, 0, 0)
```

With no filter the dashboard shows 570 from 6 orders (average 95.0); with the North slicer it shows 370 from 3 orders (average 123.33). If the slicer selected nothing, the `IFERROR` (Day 92) turns the division by zero into 0, as the third line shows. A plain `SUM` would ignore the filter and show 570 under every slicer position, a classic dashboard bug.

## Real-world applications

- **Monthly management pack.** A sheet with KPI cells, a line chart of the last twelve months and a sorted bar chart by region, all fed from pivots, replaces a slide deck that was rebuilt by hand each month (Examples 1 and 5).
- **Explaining a trade-off.** A combo chart of revenue and margin shows whether growth came with falling margin, provided both axes are labelled (Example 3).
- **Reviewing a chart before it is sent.** A checklist of zero baselines, titles with the message and a limited number of pie slices catches misleading charts (Examples 2 and 4).
- **Self-service reports.** Slicers let managers explore by region or product without changing formulas (Example 5).

## Daily review

### Key takeaways

- Choose the chart by the question: bars for categories, lines for time, pies for a few parts, scatter for two numbers, combo for two scales.
- A chart from a Table or PivotTable is a live object; check the data behind it.
- Bars and columns start at zero. Secondary axes are used sparingly and always labelled.
- Dashboards put KPI cells, charts and slicers on one sheet, with data and pivots elsewhere.
- Use `SUBTOTAL(109, ...)` when a KPI must follow a Table filter; a pivot slicer needs `GETPIVOTDATA` or a PivotChart.

### Common mistakes

- Using a pie for ten categories, or for numbers that do not form a whole.
- Starting a column axis at 90 so that a 5% difference looks like 100%.
- Putting two measures on one axis, so that the small one looks flat; or using a secondary axis without labelling it.
- Sorting categories alphabetically when the message is a ranking.
- KPI formulas with `SUM` that do not follow the slicer, so charts and totals disagree.
- Leaving the default title ("Chart Title") or a legend for a single series.

### Revision notes

- Question, then chart type; sort bars; line for time order.
- Combo: Insert, Recommended Charts, All Charts, Combo, Secondary Axis.
- Axis minimum 0 for bars (Format Axis, Bounds).
- Slicer, Report Connections, Refresh All; `SUBTOTAL(109, ...)` follows filters.
