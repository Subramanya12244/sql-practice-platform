## Objectives

- Translate values with `Series.map` and a dictionary, and find the values the dictionary missed.
- Apply your own function to each value with `Series.apply`, and to each row with `DataFrame.apply(axis=1)`.
- Rewrite a row-by-row function as a whole-column (vectorised) expression with arithmetic, comparisons and `np.where`.
- Decide between `map`, `apply` and a vectorised operation, and explain why one is faster.

## Understand

### Three ways to change every value

Cleaning data often means changing every value in a column by some rule: turning the code `"M"` into `"Male"`, turning a price string into a number, or labelling an order "large" or "small". Pandas gives three families of tools for this. `map` translates values using a lookup. `apply` calls a function that you write on each value, or on each row. A **vectorised** operation works on the whole column at once, such as `df["qty"] * df["price"]`. Day 73 used vectorised arithmetic to create derived columns; today you compare it with the other two and learn when each is the right choice.

A good mental model is a post office sorting letters. `map` is a sorter with a printed table: look up the address, drop the letter in the matching bin. `apply` is a sorter who reads each letter and makes a judgement call, one letter at a time. A vectorised operation is a conveyor machine that processes the whole tray in one pass. The sorter with judgement can handle any rule, the machine is far quicker but only for rules it was built for.

### map: lookup by value

`Series.map(arg)` takes a dictionary, a function or another series and replaces each value. With a dictionary, each value is looked up as a key. The result has the same length and index as the original. Values that are not keys in the dictionary become `NaN`, not unchanged: this is the most common surprise. `s.map({"M": "Male", "F": "Female"})` turns a stray `"X"` into `NaN`. Afterwards `fillna("Other")` supplies a default, or you can compare `s.isin(mapping)` to find the missed values before mapping. `map` is the right tool for recoding categories and for attaching a value from a small lookup table, and it is much cheaper than `apply` for this, because a dictionary lookup is all it does.

### apply: your function on each value or row

`Series.apply(func)` calls `func` once for each value and collects the returns into a new series. This is the tool for a rule that is too awkward for a lookup or an expression, such as parsing `"$1,200 (est.)"` into the number 1200. The function should return one value per input and should not print or change anything outside itself. `DataFrame.apply(func, axis=1)` calls the function once per row, passing the row as a series so that you can read several columns, for example `row["qty"] * row["price"]`. With the default `axis=0` the function receives each column instead, which is a different job and rarely what a beginner wants. Reading a row-wise result is simple, but there is a cost: pandas must build a series object for each row and run Python code on it.

### Vectorised operations

Pandas and NumPy implement arithmetic, comparisons and many functions in compiled code that loops over the entire array without running Python for each item. `df["qty"] * df["price"]` multiplies both columns in one step. A comparison such as `df["amount"] > 100` returns a boolean series. For an if-else rule, `np.where(condition, value_if_true, value_if_false)` evaluates the condition on the whole column and picks the result for each row. Rules with three outcomes nest one `np.where` inside another. The `.str` accessor from Day 76 and the `.dt` accessor from Day 77 are vectorised in the same sense: they accept the whole column. The loop still exists, but it runs in compiled code instead of in your function.

### Performance and the order of preference

On a few thousand rows nothing you choose will feel slow. On millions of rows, calling a Python function once per row can be many times slower than the vectorised equivalent, and it grows in proportion to the data. A reliable approach is to try the tools in this order. First look for a vectorised expression or a built-in method. If the rule is a lookup, use `map` with a dictionary. If neither works, use `apply` with a small, clear function. Do not guess about speed when it matters: time the alternatives on a realistic sample. What you can always do is reason about the number of Python-level calls, which Example 4 counts directly.

### Common misconception

Learners often think `apply` is "the pandas way" of doing anything and reach for it first, writing `df.apply(lambda r: r["a"] + r["b"], axis=1)` where `df["a"] + df["b"]` does the same job faster and shorter. The reverse mistake is forcing a complicated rule into nested vectorised expressions that nobody can read. The goal is correct, readable code first, and speed where the data is large.

A second misconception is that `map` leaves unknown values alone, as Python's `str.replace` would. It does not. When you map a column, any value missing from the dictionary silently turns into `NaN`, and a later `sum` or `groupby` then drops those rows. Count missing values straight after a mapping, as Day 74 taught.

### Why it matters

Recoding, parsing and labelling are daily tasks in cleaning data, and they run on tables of any size. Choosing a vectorised form by default keeps pipelines fast as the data grows, and recognising a silent `NaN` from `map` prevents lost rows. These choices also affect readers: a short vectorised line is easier to review than a function and an `axis=1` call.

## Syntax and key functions

```python nocheck
s.map({"M": "Male", "F": "Female"})      # dictionary lookup, misses become NaN
s.map(func)                              # function on each value
s.apply(func)                            # function on each value
df.apply(func, axis=1)                   # function on each row (a Series)
np.where(condition, if_true, if_false)   # vectorised if-else
```

For `map` the argument is a dictionary, a function or a series. For `apply` the function takes one value (or one row with `axis=1`) and returns one value. `np.where` takes a boolean array and two values or arrays of the same length.

| Tool | Does | Returns |
|---|---|---|
| `s.map(dict)` | looks up each value; unknown keys give `NaN` | series, same length |
| `s.apply(f)` | calls `f(value)` per value | series, same length |
| `df.apply(f, axis=1)` | calls `f(row)` per row | series, one value per row |
| `np.where(c, a, b)` | picks `a` or `b` per position | NumPy array |
| `s.isin(keys)` | tests membership | boolean series |

## Learn by example

### Example 1: map with a dictionary

Status codes become labels. The unknown code `"Z"` becomes `NaN` and is replaced afterwards.

```python run
import pandas as pd
codes = pd.Series(["P", "S", "S", "Z", "D"])
labels = {"P": "pending", "S": "shipped", "D": "delivered"}
mapped = codes.map(labels)
print(mapped.to_string())
print("missed:", mapped.isna().sum())
print(mapped.fillna("unknown").tolist())
```

```output
0      pending
1      shipped
2      shipped
3          NaN
4    delivered
missed: 1
['pending', 'shipped', 'shipped', 'unknown', 'delivered']
```

`Z` was not a key, so row 3 is `NaN` until `fillna` replaces it.

### Example 2: apply with your own function

A function turns messy price text into a number, returning `None` when it cannot. `apply` runs it on every value.

```python run
import pandas as pd
raw = pd.Series(["$1,200", "850", "n/a", "$99.5"])

def to_price(text):
    cleaned = text.replace("$", "").replace(",", "")
    try:
        return float(cleaned)
    except ValueError:
        return None

prices = raw.apply(to_price)
print(prices.to_string())
print(prices.sum())
```

```output
0    1200.0
1     850.0
2       NaN
3      99.5
2149.5
```

The function handles one value, and pandas supplies the loop. `sum()` skips the missing price.

### Example 3: row-wise apply and its vectorised twin

The same line total is computed twice. Both give identical results, and `equals` proves it.

```python run
import pandas as pd
df = pd.DataFrame({"qty": [2, 5, 1, 4], "price": [9.5, 2.0, 30.0, 7.25]})
slow = df.apply(lambda row: row["qty"] * row["price"], axis=1)
fast = df["qty"] * df["price"]
print(fast.tolist())
print(slow.equals(fast))
```

```output
[19.0, 10.0, 30.0, 29.0]
True
```

The second form needs no function and no per-row series, which is why it is the better choice here.

### Example 4: if-else rules and counting calls

A three-way label is built with nested `np.where`. A counter then shows how many Python calls `apply` makes compared with the vectorised form, which makes none.

```python run
import numpy as np
import pandas as pd
amount = pd.Series([40, 250, 120, 900, 15, 300])
size = np.where(amount >= 300, "large", np.where(amount >= 100, "medium", "small"))
print(size.tolist())

calls = []
def label(x):
    calls.append(x)
    return "large" if x >= 300 else "medium" if x >= 100 else "small"

by_apply = amount.apply(label)
print(by_apply.tolist() == size.tolist())
print("python calls made by apply:", len(calls))
```

```output
['small', 'medium', 'medium', 'large', 'small', 'large']
True
python calls made by apply: 6
```

`apply` called the function six times, once per row. With a million rows it would be a million calls, while `np.where` stays inside compiled code.

### Example 5: when apply is the right tool

Some rules cannot be written as an expression. Here each text is cut into a number and a unit, and the quantity is converted to grams.

```python run
import pandas as pd
sizes = pd.Series(["500 g", "2 kg", "1.5 kg", "250 g"])

def grams(text):
    number, unit = text.split()
    return float(number) * (1000 if unit == "kg" else 1)

print(sizes.apply(grams).tolist())
```

```output
[500.0, 2000.0, 1500.0, 250.0]
```

A vectorised version would need several `.str` steps and a mask. A small function is clearer, and the data is small.

## Real-world applications

- **Recoding survey answers.** An analyst maps numeric codes (`1`, `2`, `3`) to labels with a dictionary, then counts `NaN` to find answers outside the codebook.
- **Parsing legacy exports.** A data engineer writes one function that turns `"$1,200 (est.)"` into a number and uses `apply`, because the format has too many exceptions for a simple expression.
- **Feature flags on large tables.** A line total, a discount flag or a size band over millions of rows is written with arithmetic and `np.where`, so the job finishes in seconds.
- **Auditing a transformation.** After replacing a row-wise `apply` with a vectorised expression, `equals` or a comparison of totals proves that the new code gives the same result.

## Daily review

### Key takeaways

- `map` with a dictionary is a lookup; values missing from the dictionary become `NaN`.
- `apply` runs your function once per value (or per row with `axis=1`); it handles any rule at a cost in speed.
- Vectorised arithmetic, comparisons and `np.where` process the whole column and are the default choice.
- Prefer vectorised, then `map`, then `apply`; confirm a rewrite with `equals`.

### Common mistakes

- Mapping a column and finding `NaN` in the result: the dictionary lacked some values. Check `mapped.isna().sum()` and add the missing keys or use `fillna`.
- Writing `df.apply(func)` without `axis=1` and getting a `KeyError` or a result per column: the function receives whole columns. Add `axis=1` for rows.
- Using `axis=1` for arithmetic that a column expression does in one line. The result is right but slow; write `df["a"] + df["b"]`.
- Using `if x > 100:` on a whole series raises `ValueError: The truth value of a Series is ambiguous`. Use `np.where` or a boolean mask.

### Revision notes

- `map(dict)`: misses give `NaN`. `apply(f)`: one call per value.
- `axis=1` means one call per row.
- `np.where(cond, a, b)` is the vectorised if-else.
- Check equal results with `.equals`.
