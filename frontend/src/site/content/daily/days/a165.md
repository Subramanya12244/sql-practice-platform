## Objectives

- Turn a report into a function with parameters (month, status, minimum amount), validate the parameters, and run it for different periods without editing code.
- Export a result to CSV text with stable formatting and write the file safely (temporary name, then rename) with a name that identifies the period.
- Wrap the report in a small command-line entry point with `argparse` and return a run log (parameters, row count, total, file).
- Read a cron schedule (five fields) and check an expression against dates, and list what a scheduled job needs: absolute paths, environment variables, logs and failure alerts.
- Export a result to an Excel workbook with `openpyxl` (header style, number format, frozen header, formula total) and say what the file does and does not contain.

## Understand

### A report is a function

Until now a report was a notebook you edited each month: change the date, run all cells, copy the result. That works once and fails the third time, when the date is edited in one cell and forgotten in another, or when a colleague has to run it. **Reporting automation** starts by turning the report into a **function with parameters**: `build_report(conn, month, status, min_amount)`. Everything that changes between runs is an argument, everything that does not is inside. The function has the three-step shape of Day 159 (query, transform, summarise), it uses parameterised SQL (Day 157) for the values, and it **validates its arguments** before touching the database: a month must look like `2025-03`, a status must be in an allowed list, and a column that comes from outside is checked against a whitelist. A function that rejects bad input with a clear message is safer than one that returns an empty table that someone mistakes for "no sales".

### Making the run repeatable: entry point, log and idempotent output

A function is not yet a job. The job needs an **entry point**, a way to start it from outside with the parameters: a command line such as `python run_report.py --month 2025-03`. The standard library module `argparse` defines the options, converts types (`type=float`) and gives defaults. Keep the logic in `main(argv)` and pass the argument list explicitly, so the same code can be tested without a terminal.

Every run returns a **run log**: the parameters, the number of rows, the total of the key measure and the name of the file written, as on Day 159. Appended to a log file, it answers "did the March report run, and with what?" without opening the report. The output name contains the period (`revenue_2025-03.csv`), and running the same month twice **overwrites the same file** instead of creating `revenue_2025-03 (2).csv`. This is idempotence (Day 161) for files. To avoid a half-written file being picked up by a reader, write to a temporary name in the same folder and then rename it with `os.replace`, which replaces the target in one step on the same file system.

### Exports: CSV and Excel

**CSV** is plain text with one record per line and commas between fields. It is the format of choice for loading into other tools, since every system reads it. For a reproducible export, fix the details: the column order, the number of decimals (`float_format="%.2f"`), the line ending, the encoding (UTF-8) and `index=False` so that the DataFrame index does not appear as an extra unnamed column. Values containing a comma or a quote are quoted by the writer automatically; do not build CSV lines by joining strings yourself.

**Excel** is the format business readers expect, because they can filter it, chart it and add to it. `DataFrame.to_excel` writes a sheet, and `openpyxl` (the library pandas uses for `.xlsx`) lets you add formatting: a bold header, number formats such as `#,##0.00`, column widths and a frozen header row. Two facts prevent confusion. First, **openpyxl does not calculate formulas**: if you write `=SUM(C2:C4)` into a cell, the file stores the formula text and no result, and the value appears only when Excel (or another spreadsheet program) opens and recalculates it; a program reading the file back with `data_only=True` sees an empty value, and pandas reads it as missing. So a number that other code needs should be written as a value, and a formula is for the human reader. Second, the browser Python has no `openpyxl`, so the Excel example runs locally; the graded exercises of this day use CSV text, which carries the same lessons.

### Scheduling

**Scheduling** means starting the job automatically. On Linux and macOS the classic tool is **cron**. A schedule is five fields: minute, hour, day of month, month and day of week. A star means "every"; `*/15` means "every 15"; `1-5` is a range; `1,15` a list. So `0 6 * * 1` means 06:00 on Mondays (the day-of-week field runs from 0 to 6 starting on Sunday, and 7 is also accepted as Sunday on most systems), and `30 7 1 * *` means 07:30 on the first day of each month. Four practical rules save an afternoon of confusion. Cron runs with a **minimal environment**, so use absolute paths for the Python interpreter and the script, and have the job read its secrets (the database URL) from variables that the schedule sets, never from a file in your home directory that only you can see. Cron uses the **time zone of the machine** unless the system is configured otherwise, so decide what "06:00" means. Send output to a **log file** (`>> report.log 2>&1`), because nobody is looking at a terminal. And make the job **fail loudly**: a non-zero exit code on any failed check, which a scheduler or a wrapper can turn into an alert. Orchestration tools (for example Apache Airflow) add retries, dependencies between tasks and monitoring on top of the same idea; the job you write here is exactly what such a tool would run.

### Why it matters, and the misconception

Reports that depend on a person remembering to run them stop the month that person is on leave, and reports that are run by hand drift: this month's file is made differently from last month's. The misconception is that automation means "set the schedule". The schedule is the last and smallest step; the work is the parameters, the validation, the safe output and the run log. A schedule without these simply produces wrong files on time.

```python

def parse_args(argv):
    p = argparse.ArgumentParser(prog="run_report")
    p.add_argument("--month", required=True)
    p.add_argument("--min-amount", type=float, default=0.0)

```

The PostgreSQL side of a parameterised report can be a function that takes the parameter and returns a table:

```sql-syntax
CREATE FUNCTION <name>(<param> <type>) RETURNS TABLE (<columns>)
LANGUAGE sql AS $$ SELECT ... WHERE col >= <param> $$;
SELECT * FROM <name>('<value>');
```

| Function | Returns or does |
|---|---|
| `argparse.ArgumentParser`, `add_argument`, `parse_args(argv)` | Command-line options, typed and with defaults. |
| `df.to_csv(index=False, float_format="%.2f", lineterminator="\n")` | CSV text (or file) with fixed formatting. |
| `os.replace(tmp, final)` | Renames a file, replacing the target in one step. |

## Learn by example

The SQLite examples use the same generated database as Day 159 (nine customers in three countries and 54 orders between January and June 2025). `sqlite3` stands in for PostgreSQL: placeholders are `?` (PostgreSQL drivers use `%s`), dates are text, and `substr(order_date, 1, 7)` replaces `to_char` or `date_trunc`.

### Example 1: A report function with validated parameters

The function checks the month format and the status, runs a parameterised query and returns the revenue per country. The same function serves any month.

```python run
import sqlite3
import pandas as pd

def make_db():
    conn = sqlite3.connect(":memory:")
    conn.execute("CREATE TABLE customers (customer_id INTEGER PRIMARY KEY, name TEXT, country TEXT)")
    conn.execute("CREATE TABLE orders (order_id INTEGER PRIMARY KEY, customer_id INTEGER, order_date TEXT, amount REAL, status TEXT)")
    countries = ["DE", "FR", "UK"]
    conn.executemany("INSERT INTO customers VALUES (?, ?, ?)", [(i, f"cust{i:02d}", countries[i % 3]) for i in range(1, 10)])
    rows, x = [], 7
    for k in range(1, 55):
        x = (x * 75 + 74) % 65537
        status = "refunded" if k % 11 == 0 else ("failed" if k % 13 == 0 else "paid")
        rows.append((k, x % 9 + 1, f"2025-{(x // 9) % 6 + 1:02d}-{(x // 54) % 28 + 1:02d}", float(20 + (x // 1512) % 180), status))
    conn.executemany("INSERT INTO orders VALUES (?, ?, ?, ?, ?)", rows)
    conn.commit()
    return conn
import re

ALLOWED_STATUS = {"paid", "refunded", "failed"}

def build_report(conn, month, status="paid", min_amount=0.0):
    if not re.fullmatch(r"\d{4}-\d{2}", month):
        raise ValueError("month must look like 2025-03")
    if status not in ALLOWED_STATUS:
        raise ValueError("status must be one of " + ", ".join(sorted(ALLOWED_STATUS)))
    sql = """SELECT c.country, COUNT(*) AS orders, ROUND(SUM(o.amount), 2) AS revenue
             FROM orders o JOIN customers c ON c.customer_id = o.customer_id
             WHERE substr(o.order_date, 1, 7) = ? AND o.status = ? AND o.amount >= ?
             GROUP BY c.country ORDER BY revenue DESC, c.country"""
    return pd.read_sql_query(sql, conn, params=(month, status, min_amount))

conn = make_db()
print(build_report(conn, "2025-03").to_string(index=False))
print(build_report(conn, "2025-03", min_amount=100).to_string(index=False))
for bad in [("2025-3", "paid"), ("2025-03", "shipped")]:
    try:
        build_report(conn, *bad)
    except ValueError as e:
        print("rejected:", e)
conn.close()
```

```output
country  orders  revenue
     UK       5    239.0
     FR       3    145.0
     DE       1     39.0
Empty DataFrame
Columns: [country, orders, revenue]
Index: []
rejected: month must look like 2025-03
rejected: status must be one of failed, paid, refunded
```

The two calls differ only in an argument. The invalid inputs are rejected with a message instead of returning an empty table, which a reader could mistake for a month without sales.

### Example 2: CSV text with stable formatting, written safely

The CSV text is built with fixed decimals and no index, a value with a comma is quoted by the writer, and a round trip through `read_csv` gives the same table back. The file is written to a temporary name and then renamed, and writing the same period twice leaves one file.

```python run
import io
import os
import tempfile
import pandas as pd

df = pd.DataFrame({"customer": ["Ana Silva", "Ortega, Luis", 'Dee "DJ" Park'], "revenue": [1200.5, 310.0, 89.9]})
text = df.to_csv(index=False, float_format="%.2f", lineterminator="\n")
print(text, end="")
back = pd.read_csv(io.StringIO(text))
print("round trip equal:", back.equals(df))

def write_csv_atomic(frame, folder, name):
    final = os.path.join(folder, name)
    tmp = final + ".tmp"
    frame.to_csv(tmp, index=False, float_format="%.2f", lineterminator="\n")
    os.replace(tmp, final)
    return name

with tempfile.TemporaryDirectory() as folder:
    write_csv_atomic(df, folder, "revenue_2025-03.csv")
    write_csv_atomic(df, folder, "revenue_2025-03.csv")
    print(sorted(os.listdir(folder)))
```

```output
customer,revenue
Ana Silva,1200.50
"Ortega, Luis",310.00
"Dee ""DJ"" Park",89.90
round trip equal: True
['revenue_2025-03.csv']
```

The writer quoted the comma and the quotes (`"Ortega, Luis"` and `"Dee ""DJ"" Park"`), so the file reads back correctly. Only one file remains after two runs, and no `.tmp` file is left behind.

### Example 3: An entry point with a run log

`main(argv, conn)` parses the options, builds the report, writes `revenue_<month>.csv` and returns a run log. Running a month twice leaves one file; running another month adds one.

```python run
import sqlite3
import pandas as pd

def make_db():
    conn = sqlite3.connect(":memory:")
    conn.execute("CREATE TABLE customers (customer_id INTEGER PRIMARY KEY, name TEXT, country TEXT)")
    conn.execute("CREATE TABLE orders (order_id INTEGER PRIMARY KEY, customer_id INTEGER, order_date TEXT, amount REAL, status TEXT)")
    countries = ["DE", "FR", "UK"]
    conn.executemany("INSERT INTO customers VALUES (?, ?, ?)", [(i, f"cust{i:02d}", countries[i % 3]) for i in range(1, 10)])
    rows, x = [], 7
    for k in range(1, 55):
        x = (x * 75 + 74) % 65537
        status = "refunded" if k % 11 == 0 else ("failed" if k % 13 == 0 else "paid")
        rows.append((k, x % 9 + 1, f"2025-{(x // 9) % 6 + 1:02d}-{(x // 54) % 28 + 1:02d}", float(20 + (x // 1512) % 180), status))
    conn.executemany("INSERT INTO orders VALUES (?, ?, ?, ?, ?)", rows)
    conn.commit()
    return conn
import argparse
import os
import re
import tempfile

def build_report(conn, month, status="paid", min_amount=0.0):
    if not re.fullmatch(r"\d{4}-\d{2}", month):
        raise ValueError("month must look like 2025-03")
    sql = """SELECT c.country, COUNT(*) AS orders, ROUND(SUM(o.amount), 2) AS revenue
             FROM orders o JOIN customers c ON c.customer_id = o.customer_id
             WHERE substr(o.order_date, 1, 7) = ? AND o.status = ? AND o.amount >= ?
             GROUP BY c.country ORDER BY c.country"""
    return pd.read_sql_query(sql, conn, params=(month, status, min_amount))

def parse_args(argv):
    p = argparse.ArgumentParser(prog="run_report")
    p.add_argument("--month", required=True)
    p.add_argument("--status", default="paid")
    p.add_argument("--min-amount", type=float, default=0.0)
    p.add_argument("--out-dir", required=True)
    return p.parse_args(argv)

def main(argv, conn):
    args = parse_args(argv)
    df = build_report(conn, args.month, args.status, args.min_amount)
    name = f"revenue_{args.month}.csv"
    final = os.path.join(args.out_dir, name)
    df.to_csv(final + ".tmp", index=False, float_format="%.2f", lineterminator="\n")
    os.replace(final + ".tmp", final)
    return {"month": args.month, "status": args.status, "rows": len(df), "total": round(float(df["revenue"].sum()), 2), "file": name}

conn = make_db()
with tempfile.TemporaryDirectory() as folder:
    for month in ["2025-03", "2025-03", "2025-04"]:
        print(main(["--month", month, "--out-dir", folder], conn))
    print(sorted(os.listdir(folder)))
conn.close()
```

```output
{'month': '2025-03', 'status': 'paid', 'rows': 3, 'total': 423.0, 'file': 'revenue_2025-03.csv'}
{'month': '2025-03', 'status': 'paid', 'rows': 3, 'total': 423.0, 'file': 'revenue_2025-03.csv'}
{'month': '2025-04', 'status': 'paid', 'rows': 3, 'total': 326.0, 'file': 'revenue_2025-04.csv'}
['revenue_2025-03.csv', 'revenue_2025-04.csv']
```

Because the logic lives in `main(argv, conn)` and the arguments are a plain list, the job is tested here without a terminal. From a terminal, `main(sys.argv[1:], conn)` would be called at the bottom of `run_report.py`. The first two runs produced identical logs and the same file.

### Example 4: Reading a cron schedule

A small matcher for the five cron fields (numbers, `*`, lists, ranges and `*/n`) is checked against dates. It is a teaching tool that lets you verify what an expression means; it follows the field order minute, hour, day of month, month, day of week with Sunday as 0.

```python run
from datetime import datetime

def field_matches(spec, value, low):
    for part in spec.split(","):
        step = 1
        if "/" in part:
            part, s = part.split("/")
            step = int(s)
        if part == "*":
            start, end = low, None
        elif "-" in part:
            a, b = part.split("-")
            start, end = int(a), int(b)
        else:
            start, end = int(part), (int(part) if step == 1 else None)
        if value >= start and (end is None or value <= end) and (value - start) % step == 0:
            return True
    return False

def cron_matches(expr, when):
    minute, hour, dom, month, dow = expr.split()
    weekday = (when.weekday() + 1) % 7            # Python: Monday is 0; cron: Sunday is 0
    return (field_matches(minute, when.minute, 0) and field_matches(hour, when.hour, 0)
            and field_matches(dom, when.day, 1) and field_matches(month, when.month, 1)
            and field_matches(dow, weekday, 0))

monday_morning = datetime(2025, 3, 3, 6, 0)       # a Monday
for expr in ["0 6 * * 1", "*/15 * * * *", "30 7 1 * *", "0 6 * * 1-5"]:
    hits = [t for t in [monday_morning, datetime(2025, 3, 3, 6, 15), datetime(2025, 3, 1, 7, 30), datetime(2025, 3, 8, 6, 0)] if cron_matches(expr, t)]
    print(f"{expr:14}", [t.strftime("%a %d %H:%M") for t in hits])
```

```output
0 6 * * 1      ['Mon 03 06:00']
*/15 * * * *   ['Mon 03 06:00', 'Mon 03 06:15', 'Sat 01 07:30', 'Sat 08 06:00']
30 7 1 * *     ['Sat 01 07:30']
0 6 * * 1-5    ['Mon 03 06:00']
```

`0 6 * * 1` fires only on the Monday at 06:00, `*/15` matches 06:00 and 06:15, `30 7 1 * *` matches the first of the month at 07:30, and `1-5` for the weekday adds nothing on the Saturday 8 March. The real `cron` supports more forms (names, `@daily`), and the machine's time zone decides what 06:00 means.

### Example 5: An Excel workbook with formatting and a formula (local)

The summary is written to an `.xlsx` file with a bold header, a number format, a frozen header row and a total formula, then read back to show what was stored. It needs `pip install openpyxl pandas` and runs on your own computer; the browser shows it read-only with the verified output.

```python local
import os
import tempfile
import pandas as pd
from openpyxl import Workbook, load_workbook
from openpyxl.styles import Font

df = pd.DataFrame({"country": ["DE", "FR", "UK"], "orders": [9, 9, 8], "revenue": [342.0, 356.0, 364.0]})

wb = Workbook()
ws = wb.active
ws.title = "Summary"
ws.append(list(df.columns))
for row in df.itertuples(index=False, name=None):
    ws.append(row)
ws.append(["Total", "=SUM(B2:B4)", "=SUM(C2:C4)"])
for cell in ws[1]:
    cell.font = Font(bold=True)
for r in range(2, 6):
    ws.cell(r, 3).number_format = "#,##0.00"
ws.column_dimensions["A"].width = 14
ws.freeze_panes = "A2"

with tempfile.TemporaryDirectory() as folder:
    path = os.path.join(folder, "revenue_2025-03.xlsx")
    wb.save(path)
    sheet = load_workbook(path)["Summary"]
    print(sheet.title, sheet.freeze_panes, sheet["C2"].number_format, sheet["A1"].font.b)
    print("formula cell:", sheet["B5"].value)
    print("cached value:", load_workbook(path, data_only=True)["Summary"]["B5"].value)
    print("pandas sees:", pd.read_excel(path, sheet_name="Summary")["revenue"].tolist())
```

```output
Summary A2 #,##0.00 True
formula cell: =SUM(B2:B4)
cached value: None
pandas sees: [342.0, 356.0, 364.0, nan]
```

The formula is stored as text and has no cached result, because `openpyxl` does not calculate: reading with `data_only=True` gives `None`, and pandas reads the total cell as missing (`nan`). Anyone opening the file in Excel sees the totals, but a program that needs them must get them from the values. `df.to_excel(path, sheet_name="Summary", index=False)` writes just the values when no formatting is needed.

### Example 6: A parameterised report inside PostgreSQL

A SQL function takes the month as a parameter and returns the report table. This runs on the PostgreSQL-compatible browser database, with its own small table. A scheduled job would call `SELECT * FROM report_revenue('2025-03-01')` with a `%s` placeholder and load the result with `read_sql_query`.

```sql run
DROP TABLE IF EXISTS ra_orders;
CREATE TABLE ra_orders (order_id integer PRIMARY KEY, country text, order_date date, amount numeric(10,2), status text);
INSERT INTO ra_orders VALUES
  (1, 'DE', DATE '2025-03-02', 120.00, 'paid'), (2, 'FR', DATE '2025-03-09', 80.50, 'paid'),
  (3, 'DE', DATE '2025-03-15', 45.00, 'refunded'), (4, 'DE', DATE '2025-03-28', 60.00, 'paid'),
  (5, 'FR', DATE '2025-04-01', 99.00, 'paid');
CREATE OR REPLACE FUNCTION report_revenue(p_month date)
RETURNS TABLE (country text, orders bigint, revenue numeric)
LANGUAGE sql AS $$
  SELECT o.country, COUNT(*), SUM(o.amount)
  FROM ra_orders o
  WHERE o.status = 'paid'
    AND o.order_date >= p_month
    AND o.order_date < p_month + INTERVAL '1 month'
  GROUP BY o.country
  ORDER BY o.country
$$;
SELECT * FROM report_revenue(DATE '2025-03-01');
```

```output
country | orders | revenue
DE | 2 | 180.00
FR | 1 | 80.50
```

The half-open range from Day 159 again: the start of the month up to, but not including, the start of the next. The April order is excluded without any special case.

## Real-world applications

- **Monthly management pack**: `main(["--month", "2025-03", ...])` writes the CSV and workbook for finance, and the run log shows rows and totals (Examples 1 to 3 and 5).
- **Weekly KPI file for a BI tool**: a Monday 06:00 schedule (Example 4) writes `kpi_<week>.csv` in a fixed format that a dashboard picks up.
- **Self-service reporting**: the SQL function (Example 6) or the Python function takes a month, so a colleague asks for another period without code changes, and bad input is rejected with a clear message (Example 1).
- **Month-end re-runs**: a corrected source file is reloaded (Day 161) and the same command is run again; the period-named output is overwritten, not duplicated (Example 2).

## Daily review

### Key takeaways

- Put everything that changes into parameters, validate them, and keep the query parameterised.
- An entry point with `argparse` and a returned run log makes the report a job; test `main(argv)` with an explicit list.
- Name outputs by period and write them atomically (temporary name, then `os.replace`) so reruns are idempotent.
- CSV: fix decimals, order, line ending and `index=False`; let the writer quote.
- `openpyxl` stores formulas, not their results; write values for programs, formulas for people.
- Cron: five fields, minimal environment, machine time zone, log file, non-zero exit on failure.

### Common mistakes

- Editing the date in the notebook each month. One forgotten cell gives a mixed-period report; pass the period as a parameter.
- Building CSV lines by string joining. A comma in a name shifts every column after it; use `to_csv`.
- Forgetting `index=False`. The file gets an unnamed first column that confuses the next reader.
- Reading back a formula cell with `data_only=True` and getting `None`. The file was written by a program and never calculated; write values for downstream code.
- Using relative paths and the wrong interpreter in a cron job. It works in your terminal and fails in cron with "command not found"; use absolute paths.
- Not logging or alerting. The job fails on Tuesday and nobody knows until the next report is requested; log to a file and exit non-zero on failure.

### Revision notes

- `build_report(conn, month, ...)`: validate, parameterised SQL, return a DataFrame.
- `main(argv)` with `argparse`; run log: parameters, rows, total, file.

- Cron: `minute hour dom month dow`; `0 6 * * 1` is 06:00 on Mondays.
- `openpyxl`: `Font(bold=True)`, `number_format`, `freeze_panes`; formulas are not calculated.
