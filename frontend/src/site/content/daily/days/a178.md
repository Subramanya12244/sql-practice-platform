## Objectives

- Write findings that each state a claim, a number, a base and a caveat, using numbers computed from the analysis.
- Check every number in the narrative against the verified results with code, including a tolerance for rounding.
- Test whether a conclusion survives a change of treatment, such as analysing the raw instead of the cleaned data.
- Write a recommendation that follows from the findings and names what would change it.

## Understand

### What this stage produces

The analysis has numbers and charts. A reader still has to be told what they mean. This stage produces the narrative: a short document with a summary of three to five findings, a recommendation, the caveats and the next steps. The narrative is the part of the capstone that a manager reads, so it is judged on whether the claims are right and the limits are honest. Everything in it comes from the verified results of Days 174 to 177, never from memory or from a rounded figure typed by hand.

### Anatomy of a finding

A finding has four parts. The claim is the statement in plain words ("Email returns the most net revenue per unit of spend"). The number gives the size (13.68 against 5.58 for social and 5.37 for paid search). The base says what the number is out of: 95 email orders, 489 valid orders in total. The caveat says what limits it: ratios use campaign attribution on the order and ignore customers who would have bought anyway. A finding without a base cannot be judged, because 59 returns could be a lot or a little. A finding without a caveat overclaims. The narrative style is short sentences, the claim first, then the number.

### Numbers must trace to code

Every figure in the narrative should be produced by code and inserted by code. A figure typed from memory drifts: someone regenerates the data or fixes a cleaning rule, and the text is silently wrong. A consistency check extracts all the numbers from the narrative text and tests each against a dictionary of verified results, within a tolerance for rounding (for example 0.005 for a figure rounded to two decimals). Any number that matches nothing is reported, and either the text or the analysis is wrong. This check is cheap and catches the embarrassing mistakes before a reader does.

### Does the conclusion survive?

A sensitivity check changes one treatment and asks whether the conclusion moves. Here: rank the channels by return on spend using the raw data (with duplicates and bad rows) and using the cleaned data. If the ranking is the same, say so, because it makes the finding sturdier and shows that cleaning did not manufacture the result. If the ranking changes, the finding must say that it depends on the cleaning decision. This is more honest than reporting one number as if no other treatment were possible.

### Recommendation and caveats

A recommendation is an action that follows from the findings, for example "move a test share of budget from paid search to email for one month and measure net revenue per unit of spend again". It names what would change it: if the email advantage disappears when new data arrives, revisit. Caveats are collected in one place: the data is synthetic and covers six months, attribution is simple, return reasons were not used and customers who never ordered are outside the base. Learners often hide caveats at the end in small print. Place the main caveat next to each claim it limits, and keep a short section for the rest.

### Common misconception

A narrative is not a description of the work. "I cleaned the data and ran SQL queries" tells a manager nothing. State what was found and what to do. The method belongs in the README.

## Syntax and key functions

```python
numbers = re.findall(r"\d+(?:\.\d+)?", text)          # extract numbers from a text
ok = any(abs(float(n) - v) <= tol for v in verified)  # match within a tolerance
sentence = f"{claim}: {number} (base: {base}). Caveat: {caveat}."
```

| Function | Returns |
|---|---|
| `re.findall(pattern, text)` | List of all non-overlapping matches |
| `abs(a - b) <= tol` | True when two numbers agree within the tolerance |
| `s.rank(ascending=False)` | Rank of each value, 1 for the largest |
| `series.idxmax()` | Index label of the largest value |
| `a.equals(b)` or `list(a) == list(b)` | Exact comparison of two results |

## Learn by example

### Example 1: Findings from the numbers

Each finding is built from computed numbers with its claim, number, base and caveat, so the text can never disagree with the analysis.

```python run
import numpy as np
import pandas as pd


def generate(seed=7):
    """Seeded online-store data with planted defects: 500 orders, 120 customers, 20 products."""
    rng = np.random.default_rng(seed)
    customers = pd.DataFrame({
        "customer_id": np.arange(1, 121),
        "country": rng.choice(["DE", "FR", "UK", "US"], 120, p=[0.3, 0.2, 0.2, 0.3]),
        "signup_date": pd.Timestamp("2024-07-01") + pd.to_timedelta(rng.integers(0, 180, 120), unit="D"),
    })
    customers.loc[rng.choice(120, 8, replace=False), "country"] = "us "
    products = pd.DataFrame({
        "product_id": np.arange(1, 21),
        "category": np.repeat(["home", "beauty", "sports", "electronics"], 5),
        "unit_price": (10 + rng.random(20) * 90).round(2),
    })
    campaigns = pd.DataFrame({
        "campaign_id": [0, 1, 2, 3],
        "channel": ["organic", "email", "paid_search", "social"],
        "spend": [0.0, 800.0, 2500.0, 1200.0],
    })
    n = 500
    orders = pd.DataFrame({
        "order_id": np.arange(1001, 1001 + n),
        "customer_id": rng.integers(1, 121, n),
        "product_id": rng.integers(1, 21, n),
        "order_date": pd.Timestamp("2025-01-01") + pd.to_timedelta(rng.integers(0, 180, n), unit="D"),
        "quantity": rng.integers(1, 5, n),
        "discount_pct": rng.choice([0, 10, 20], n, p=[0.6, 0.25, 0.15]),
        "campaign_id": rng.choice([0, 1, 2, 3], n, p=[0.4, 0.2, 0.25, 0.15]),
    })
    orders.loc[rng.choice(n, 5, replace=False), "quantity"] = -1
    orders.loc[rng.choice(n, 6, replace=False), "customer_id"] = 999
    orders = pd.concat([orders, orders.sample(10, random_state=1)], ignore_index=True)
    returned = rng.choice(np.arange(1001, 1001 + n), 60, replace=False)
    returns = pd.DataFrame({
        "order_id": np.concatenate([returned, [9001, 9002, 9003]]),
        "reason": rng.choice(["damaged", "wrong_item", "changed_mind"], 63, p=[0.3, 0.2, 0.5]),
    })
    return {"orders": orders, "customers": customers, "products": products, "campaigns": campaigns, "returns": returns}



def clean(t):
    """Apply the quality rules; return cleaned tables and a row-accounting log."""
    log = {}
    o = t["orders"]
    log["raw_orders"] = len(o)
    o = o.drop_duplicates()
    log["after_duplicates"] = len(o)
    o = o[o["quantity"] > 0]
    log["after_quantity"] = len(o)
    c = t["customers"].copy()
    c["country"] = c["country"].str.strip().str.upper()
    o = o[o["customer_id"].isin(c["customer_id"])]
    log["after_customers"] = len(o)
    r = t["returns"]
    log["raw_returns"] = len(r)
    r = r[r["order_id"].isin(o["order_id"])].drop_duplicates("order_id")
    log["clean_returns"] = len(r)
    p = t["products"]
    o = o.merge(p[["product_id", "unit_price"]], on="product_id", how="left")
    o["revenue"] = (o["quantity"] * o["unit_price"] * (1 - o["discount_pct"] / 100)).round(2)
    o["returned"] = o["order_id"].isin(r["order_id"])
    return {"orders": o.reset_index(drop=True), "customers": c, "products": p, "campaigns": t["campaigns"], "returns": r.reset_index(drop=True)}, log



def prepare(ct):
    """Analysis tables from the clean data: orders with category, channel and month, plus the three chart series."""
    o = ct["orders"].merge(ct["products"][["product_id", "category"]], on="product_id")
    o = o.merge(ct["campaigns"][["campaign_id", "channel"]], on="campaign_id")
    o["month"] = o["order_date"].dt.month
    net = o[~o["returned"]]
    net_month = net.groupby("month")["revenue"].sum().round(2)
    spend = ct["campaigns"].set_index("channel")["spend"]
    roas = (net.groupby("channel")["revenue"].sum() / spend[spend > 0]).dropna().round(2)
    rate = (o.groupby("category")["returned"].mean() * 100).round(1)
    return o, net_month, roas, rate


ct, log = clean(generate())
o, net_month, roas, rate = prepare(ct)
total = float(net_month.sum())
orders = len(o)
peak = net_month.idxmax()
growth = (net_month[peak] / net_month[peak - 1] - 1) * 100
best, worst = roas.idxmax(), roas.idxmin()
top, low = rate.idxmax(), rate.idxmin()
n_top = int((o["category"] == top).sum())
r_top = int(o.loc[o["category"] == top, "returned"].sum())
findings = [
    ("May is the strongest month for net revenue", f"month {peak} net revenue {net_month[peak]:.2f}, {growth:.1f}% above the month before", f"{orders} valid orders, net total {total:.2f}", "six months of synthetic data show no seasonality"),
    (f"{best.capitalize()} returns the most net revenue per unit of spend", f"{roas[best]:.2f} against {roas[worst]:.2f} for {worst}", "channels with spend", "attribution uses the order's campaign only"),
    (f"{top.capitalize()} has the highest return rate", f"{rate[top]:.1f}% ({r_top} of {n_top} orders) against {rate[low]:.1f}% for {low}", "valid orders per category", "category counts are small"),
]
for i, (claim, number, base, caveat) in enumerate(findings, 1):
    print(f"F{i}. {claim}: {number}. Base: {base}. Caveat: {caveat}.")
```

```output
F1. May is the strongest month for net revenue: month 5 net revenue 10677.92, 47.2% above the month before. Base: 489 valid orders, net total 52630.99. Caveat: six months of synthetic data show no seasonality.
F2. Email returns the most net revenue per unit of spend: 13.68 against 5.37 for paid_search. Base: channels with spend. Caveat: attribution uses the order's campaign only.
F3. Home has the highest return rate: 14.5% (17 of 117 orders) against 8.7% for sports. Base: valid orders per category. Caveat: category counts are small.
```

## Real-world applications

- An analyst writes the executive summary of a monthly report so that each finding carries its base and caveat, as in Example 1, and the numbers come from the query results.
- A reviewer runs a number consistency check on a report draft before it is sent, which catches a mistyped figure (Example 2).
- A data scientist reports whether a model comparison result holds under a different treatment of missing values, the same idea as the raw versus clean ranking in Example 3.
- A product manager reads a recommendation that names what would change it and plans the follow-up measurement.

## Daily review

### Key takeaways

- A finding is a claim, a number, a base and a caveat.
- Insert numbers into the text with code, and check the text against the verified results.
- Test whether the conclusion survives a different treatment of the data.
- A recommendation is an action with a condition that would change it.

### Common mistakes

- Reporting a count without its base: 17 returns means nothing without the 117 orders. Always give the denominator.
- Typing rounded figures by hand and letting them drift after the data is regenerated. Generate the sentences from variables.
- Burying the caveat on the last page. Put the key caveat next to the claim it limits.
- Describing the method instead of the result. Keep the narrative to findings and actions, and put the method in the README.

### Revision notes

- Finding template: claim, number, base, caveat.
- Verified headline numbers: net revenue 52630.99, 489 orders, email 13.68 return on spend, home 14.5% return rate.
- Sensitivity: the channel ranking is the same on raw and clean data.
