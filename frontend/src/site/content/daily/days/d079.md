## Understand

### The question groupby answers

Most business questions are about groups: revenue per customer, orders per month, average delay per carrier. A table of order lines holds the facts, but the answer is one number per group. In SQL you wrote `GROUP BY` and aggregate functions on Days 36 and 37; pandas offers the same idea with `df.groupby(...)`. The method does not compute anything by itself. It prepares the groups, and you then say what to do with each one.

### Split, apply, combine

The operation always has three steps, and naming them helps you reason about any result. In the **split** step, pandas puts each row into a group according to the value in the key column. In the **apply** step, a calculation runs on each group on its own, such as a sum of one column. In the **combine** step, the one-value results are gathered into a new table with one row per group. A concrete picture: you deal a pile of order slips into stacks, one stack per customer. You total each stack separately. Then you write the totals in a list with one line per stack. The original slips are not changed.

For `orders.groupby("customer")["amount"].sum()`, the key is the `customer` column, the column being summarised is `amount`, and the function is `sum`. The result is a series whose index holds the group keys, sorted by key by default. Writing the pieces in this order, key, then column, then function, avoids most beginner errors.

### Aggregations and their differences

The usual summaries are `sum`, `mean`, `min`, `max`, `count`, `size` and `nunique`. Two are easily confused. `size()` counts the rows in each group, including rows with missing values. `count()` counts the non-missing values in each column, so it can give different numbers for different columns, exactly like `COUNT(*)` and `COUNT(column)` in SQL on Day 36. If a group has three rows and one `amount` is `NaN`, then `size` is 3 and `count` of `amount` is 2. `nunique()` counts distinct values, such as the number of different orders per customer. Choose `size` when you mean "how many rows", and `count` only when you want to ignore missing values. The functions `sum`, `mean` and the others skip `NaN` by default, as Day 74 explained.

### More than one key, and what the index becomes

Passing a list of keys, `groupby(["region", "product"])`, makes one group for each distinct combination. The result then has a two-level **MultiIndex**: the keys become the index and are no longer ordinary columns. This is a common stumbling block, because you cannot select `result["region"]` afterwards. Call `reset_index()` on the result, or pass `as_index=False` to `groupby`, to move the keys back into columns. For the usual reporting table, `as_index=False` or `reset_index()` is the right habit.

### Named aggregation

Often you want several summaries with readable names at once. **Named aggregation** is written inside `agg`, using one keyword per output column: `agg(orders=("order_id", "nunique"), revenue=("amount", "sum"))`. Each keyword is the new column name, and each value is a pair of the source column and the function name. The result has one row per group and exactly the columns you named, with no confusing multi-level column labels. This is the pandas counterpart of `SELECT COUNT(DISTINCT order_id) AS orders, SUM(amount) AS revenue ... GROUP BY`.

### Groups you do not see

By default, rows whose key is missing (`NaN`) are dropped from the result. A customer column with some blanks will give totals that do not add up to the grand total, and no warning appears. You can check with `df["customer"].isna().sum()`, and `groupby(..., dropna=False)` keeps a group for the missing key. The same silence applies to a key that you mistyped: `"North"` and `"north "` are two different groups. Clean the keys first with the string methods of Day 76.

### Common misconception

Learners often think `groupby` returns a table straight away, and print `df.groupby("customer")` expecting to see numbers. It shows an object description, because the apply step has not run. Another misconception is that groupby changes `df`. It never does; it builds a new result, so you assign it to a name.

### Why it matters

Grouped summaries are the core of reporting and of exploration. They also catch wrong data: a group with an unexpected size or a missing group points straight to a data problem. A reliable habit is to compare the sum of the group results with the total of the original column. If they differ, rows were dropped or double counted.

## Syntax and key functions

```python nocheck
df.groupby("key")["col"].sum()                       # series, index = keys
df.groupby(["k1", "k2"], as_index=False)["col"].sum()  # keys stay columns
df.groupby("key").size()                             # rows per group
df.groupby("key").agg(name=("col", "func"), ...)     # named aggregation
result.reset_index()                                 # keys back into columns
```

`groupby` takes one key column or a list of them. Selecting a column in square brackets chooses what to summarise; leaving it out summarises every numeric column. The function can be called as a method or given as a string inside `agg`.

| Call | Returns |
|---|---|
| `g["col"].sum()`, `.mean()`, `.min()`, `.max()` | one value per group, skipping `NaN` |
| `g.size()` | rows per group, including missing values |
| `g["col"].count()` | non-missing values per group |
| `g["col"].nunique()` | distinct values per group |
| `g.agg(name=("col", "func"))` | one named column per aggregation |
| `groupby(..., dropna=False)` | keeps a group for missing keys |
| `reset_index()` | turns the group keys into columns |

## Learn by example

### Example 1: Look at the split, then sum

Iterating over a groupby shows the stacks before they are summarised. Then one line produces the totals.

```python run
import pandas as pd
orders = pd.DataFrame({
    "customer": ["Ada", "Bo", "Ada", "Cy", "Bo", "Ada"],
    "amount": [30.0, 20.0, 50.0, 15.0, 10.0, 5.0],
})
for name, part in orders.groupby("customer"):
    print(name, part["amount"].tolist())
print(orders.groupby("customer")["amount"].sum().to_string())
```

```output
Ada [30.0, 50.0, 5.0]
Bo [20.0, 10.0]
Cy [15.0]
customer
Ada    85.0
Bo     30.0
Cy     15.0
```

Ada has three rows, so three amounts are summed: 30, 50 and 5. The result is sorted by customer name.

### Example 2: size and count are not the same

One amount is missing. `size` counts the row, while `count` does not.

```python run
import numpy as np
import pandas as pd
orders = pd.DataFrame({
    "customer": ["Ada", "Ada", "Ada", "Bo", "Bo"],
    "amount": [30.0, np.nan, 50.0, 20.0, 10.0],
})
g = orders.groupby("customer")
print(pd.DataFrame({"size": g.size(), "count": g["amount"].count(), "sum": g["amount"].sum()}).to_string())
```

```output
          size  count   sum
customer                   
Ada          3      2  80.0
Bo           2      2  30.0
```

Ada has 3 rows but only 2 known amounts, and the sum skips the missing one.

### Example 3: Two keys and the index

Grouping by region and product gives a two-level index. `as_index=False` keeps both keys as columns.

```python run
import pandas as pd
sales = pd.DataFrame({
    "region": ["N", "N", "S", "S", "N", "S"],
    "product": ["pen", "ink", "pen", "pen", "pen", "ink"],
    "amount": [10, 20, 5, 15, 30, 40],
})
as_series = sales.groupby(["region", "product"])["amount"].sum()
print(as_series.index.names)
flat = sales.groupby(["region", "product"], as_index=False)["amount"].sum()
print(flat.to_string())
```

```output
['region', 'product']
  region product  amount
0      N     ink      20
1      N     pen      40
2      S     ink      40
3      S     pen      20
```

Every combination that exists in the data gets a row; there is no row for a combination that never occurs.

### Example 4: Named aggregation and a check

One call produces orders, revenue and average line, then a sort puts the biggest first. The last line checks that nothing was lost.

```python run
import pandas as pd
lines = pd.DataFrame({
    "customer": ["Ada", "Bo", "Ada", "Cy", "Bo", "Ada"],
    "order_id": [1, 2, 1, 3, 4, 5],
    "amount": [30.0, 20.0, 50.0, 15.0, 10.0, 5.0],
})
summary = lines.groupby("customer").agg(
    orders=("order_id", "nunique"),
    lines=("order_id", "size"),
    revenue=("amount", "sum"),
    avg_line=("amount", "mean"),
).round(2).sort_values("revenue", ascending=False)
print(summary.to_string())
print(summary["revenue"].sum() == lines["amount"].sum())
```

```output
          orders  lines  revenue  avg_line
customer                                  
Ada            2      3     85.0     28.33
Bo             2      2     30.0     15.00
Cy             1      1     15.0     15.00
True
```

Ada has 3 lines but only 2 distinct orders, because order 1 has two lines.

### Example 5: A derived key and a missing key

Grouping by `dt.month` uses a Day 77 skill. A row with a missing customer disappears unless `dropna=False` is given.

```python run
import numpy as np
import pandas as pd
d = pd.DataFrame({
    "when": pd.to_datetime(["2024-01-05", "2024-01-20", "2024-02-02", "2024-02-10"]),
    "customer": ["Ada", None, "Ada", "Bo"],
    "amount": [10, 20, 30, 40],
})
print(d.groupby(d["when"].dt.month)["amount"].sum().to_string())
print(d.groupby("customer")["amount"].sum().to_string())
print(d.groupby("customer", dropna=False)["amount"].sum().to_string())
```

```output
when
1    30
2    70
customer
Ada    40
Bo     40
customer
Ada    40
Bo     40
NaN    20
```

The second total misses 20, the amount of the row with no customer. The third keeps it in a `NaN` group.

## Real-world applications

- **Revenue per customer and per month.** A sales analyst uses named aggregation to produce orders, revenue and average order value in one table for a report.
- **Data quality counts.** A data engineer groups a loaded table by source file and compares `size` with the number of lines in each file to spot dropped rows.
- **Reconciliation.** After a pipeline step, the sum of grouped amounts is compared with the original total, as in Example 4, to prove that nothing was lost or doubled.
- **Finding duplicates by key.** Grouping by an id and keeping `size() > 1` lists ids that appear more than once.

## Daily review

### Key takeaways

- groupby splits rows into groups, applies a summary to each, and combines the results into one row per group.
- `size` counts rows; `count` counts non-missing values; `nunique` counts distinct values.
- Several keys give one group per existing combination and a MultiIndex unless you use `as_index=False` or `reset_index()`.
- Named aggregation gives readable column names.
- Missing keys are dropped by default.

### Common mistakes

- Selecting `result["region"]` after grouping by two keys raises `KeyError: 'region'` because the keys are in the index. Use `reset_index()` or `as_index=False`.
- Printing `df.groupby("k")` and seeing `<pandas...DataFrameGroupBy object at 0x...>`: no function was applied yet. Add `.sum()` or `.agg(...)`.
- Using `count` when you meant `size` gives smaller numbers whenever the column has `NaN`. Decide which one answers the question.
- Group totals that do not add up to the grand total: some keys are missing or misspelled. Check `isna()` and clean the key text.

### Revision notes

- Split, apply, combine.
- `size` rows, `count` non-missing, `nunique` distinct.
- `as_index=False` keeps keys as columns.
- `agg(name=("col", "func"))`.
- `dropna=False` keeps missing keys.
