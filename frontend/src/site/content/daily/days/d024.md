## Objectives

- Write an `__init__` method that sets attributes, and use `self` correctly in methods.

- Apply encapsulation: protect data with naming conventions, properties and validation.

## Understand

### Why classes

So far, data and the functions that work on it have been separate: a dictionary holds an order and a function totals it. As programs grow, it becomes hard to keep track of which function belongs to which data. **Object-oriented programming** (OOP) bundles data and the operations on it together. A **class** is a template that describes what a kind of thing has and does. An **object** (also called an **instance**) is one concrete thing made from that template. You have used objects all along: each `str`, `list` and `date` is an object of a class, with attributes (data) and methods (functions that belong to the object). The class `Customer` might describe "a customer has a name and a balance, and can pay or receive money", and `Customer("Ana")` and `Customer("Bo")` are two separate customers.

An analogy: a class is the architect's plan for a house, and objects are the houses built from it. All have the same layout, but each has its own paint colour and its own people living in it.

### Defining a class and creating objects

```python
class Customer:
    def __init__(self, name, balance=0):
        self.name = name
        self.balance = balance
```

Calling the class like a function, `ana = Customer("Ana", 100)`, creates a new object. Python then runs `__init__` on the new object. `__init__` is the **initializer**, a special method (names with double underscores on both sides are called dunder methods) that sets up the object's starting state. Inside the class, the first parameter of every method is conventionally called `self`: it is the object the method is working on. When you write `ana.pay(30)`, Python passes `ana` as `self` automatically, so you supply only `30`. That is why a method defined with three parameters is called with two arguments. `self.name = name` creates an **instance attribute**: a variable stored on that one object, which you read as `ana.name`. Forgetting `self.` makes a plain local variable that vanishes when `__init__` ends.

### Methods

A **method** is a function defined inside a class that works on an object. Write `def pay(self, amount):` and use `self.balance` to read or change the object's data. A method can return a value or modify `self`. Calling `ana.pay(30)` changes `ana` only and never touches another customer. The state of an object is the set of values in its attributes at a moment, and methods are the controlled way to change that state.

### Instance versus class attributes

An attribute set on `self` belongs to one object. An attribute defined directly in the class body, outside any method, is a **class attribute**, shared by every object of the class. It suits constants and counters, such as `currency = "EUR"`. Reading `ana.currency` finds the class attribute when the object has no attribute of its own. Assigning `ana.currency = "USD"` creates a new instance attribute on `ana` only, and leaves the class value and every other object unchanged.

### Readable output with `__repr__`

Printing an object gives something like `<__main__.Customer object at 0x7f...>`, which tells you nothing. Defining `__repr__` (and returning a string) controls how the object is shown: `return f"Customer({self.name!r}, {self.balance})"`. Aim for text that looks like the code that would create the object. `print` and the REPL both use it when no `__str__` exists. A related method, `__str__`, is for friendlier text.

### Encapsulation

**Encapsulation** means keeping an object's data behind its methods, so that other code cannot put the object into an invalid state, for example a negative balance. Python does not enforce privacy, but follows conventions: a name beginning with one underscore, such as `_balance`, means "internal, do not touch from outside", and the double-underscore form `__balance` goes further by mangling the name. A **property** is a method used like an attribute. With the `@property` decorator, `ana.balance` calls a method, and a matching `@balance.setter` can validate before storing. You can then expose a read-only value, or reject bad input with a `ValueError` (Day 21), while callers keep writing `ana.balance = 50`. The decorator syntax `@name` is explained on Day 27; here treat it as a label that turns a method into a property.

### Common misconception

Learners think each object gets its own copy of the code. All objects of a class share the same methods, and only the data (instance attributes) is separate. Another common one: a list defined in the class body, such as `items = []`, is shared by every object, so appending to it in one object appears in all of them. Create mutable per-object data in `__init__`.

### Why it matters

Data pipelines grow into many steps that share state: a connection, a batch of rows, a run summary. Classes keep that state and its operations together, and the libraries you use next, such as pandas and SQLAlchemy, are full of classes whose objects you create and call methods on.

## Syntax and key functions

```python
class ClassName:
    shared = "value"            # class attribute

    def __init__(self, arg):
        self.arg = arg          # instance attribute

    def method(self, x):
        return self.arg + x

    def __repr__(self):
        return f"ClassName({self.arg!r})"

obj = ClassName(5)
obj.method(2)
```

The class body holds a class attribute, `__init__`, a method and `__repr__`. `obj` is an object created by calling the class; `obj.method(2)` passes `obj` as `self`.

```python
class Account:
    def __init__(self, balance):
        self._balance = balance

    @property
    def balance(self):
        return self._balance
```

A property gives read access through a method; a setter would add validation.

| Name | Meaning |
|---|---|
| `class Name:` | Defines a class. |
| `Name(args)` | Creates an object and runs `__init__`. |
| `self` | The object a method is working on. |
| `obj.attr` / `obj.attr = v` | Read / set an attribute. |
| `__init__(self, ...)` | Sets up a new object. |
| `__repr__(self)` | Text shown by `print` and the REPL. |
| `_name` | Convention: internal, not for outside use. |
| `@property` | Makes a method readable like an attribute. |
| `isinstance(obj, Name)` | `True` when `obj` was made from the class. |
| `vars(obj)` | Dictionary of an object's instance attributes. |

## Learn by example

### Example 1: The first class

The class stores a name and a balance. Two objects are created from it and kept separate. `type` and `isinstance` show how an object relates to its class, and `vars` shows that the data lives on each object.

```python run
class Customer:
    def __init__(self, name, balance=0):
        self.name = name
        self.balance = balance

ana = Customer("Ana", 100)
bo = Customer("Bo")
print(ana.name, ana.balance)
print(bo.name, bo.balance)
bo.balance = 25
print(ana.balance, bo.balance)
print(type(ana).__name__, isinstance(ana, Customer))
print(vars(bo))
```

```output
Ana 100
Bo 0
100 25
Customer True
{'name': 'Bo', 'balance': 25}
```

### Example 2: Methods and self

Each method receives the object as `self`. `pay` and `receive` change the state, and `summary` returns text. `ana.pay(30)` supplies one argument although the definition has two parameters, because `self` is passed automatically. The method and its equivalent function-style call show the same thing.

```python run
class Customer:
    def __init__(self, name, balance=0):
        self.name = name
        self.balance = balance

    def receive(self, amount):
        self.balance += amount

    def pay(self, amount):
        self.balance -= amount

    def summary(self):
        return f"{self.name}: {self.balance}"

ana = Customer("Ana", 100)
ana.pay(30)
ana.receive(5)
print(ana.summary())
Customer.pay(ana, 10)
print(ana.summary())
```

```output
Ana: 75
Ana: 65
```

### Example 3: Class attributes versus instance attributes

`currency` lives on the class and is shared. Assigning to it through one object creates an object-level copy that hides the shared value for that object only. Changing the class value affects every object that has not overridden it. A counter on the class tracks how many objects exist.

```python run
class Product:
    currency = "EUR"
    count = 0

    def __init__(self, name, price):
        self.name = name
        self.price = price
        Product.count += 1

a = Product("pen", 2)
b = Product("book", 12)
print(a.currency, b.currency, Product.count)
a.currency = "USD"
print(a.currency, b.currency, Product.currency)
Product.currency = "GBP"
print(a.currency, b.currency)
print("currency" in vars(a), "currency" in vars(b))
```

```output
EUR EUR 2
USD EUR EUR
USD GBP
True False
```

### Example 4: Readable objects with __repr__

Without `__repr__` the printed object is an address. Defining it makes lists of objects readable, which matters when debugging. The `!r` in the format inserts the quoted representation of the name.

```python run
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __repr__(self):
        return f"Point({self.x!r}, {self.y!r})"

    def distance_to(self, other):
        return ((self.x - other.x) ** 2 + (self.y - other.y) ** 2) ** 0.5

p = Point(0, 0)
q = Point(3, 4)
print(p)
print([p, q])
print(p.distance_to(q))
```

```output
Point(0, 0)
[Point(0, 0), Point(3, 4)]
5.0
```

### Example 5: Encapsulation with a property

The balance is stored in `_balance`, and the property setter rejects a negative value. Outside code still writes `acct.balance = 50`, but the check runs. A read-only property, `is_overdrawn`, is computed from the state. The `try` catches the `ValueError` raised for the invalid value.

```python run
class Account:
    def __init__(self, balance=0):
        self.balance = balance

    @property
    def balance(self):
        return self._balance

    @balance.setter
    def balance(self, value):
        if value < 0:
            raise ValueError("balance cannot be negative")
        self._balance = value

    @property
    def is_empty(self):
        return self._balance == 0

acct = Account(20)
acct.balance = 50
print(acct.balance, acct.is_empty)
try:
    acct.balance = -5
except ValueError as error:
    print("rejected:", error)
print(acct.balance)
```

```output
50 False
rejected: balance cannot be negative
50
```

### Example 6: A small realistic class

A `BatchStats` object collects the results of processing a batch of rows: it counts good and bad rows, keeps the bad row numbers and reports a summary. State and behaviour live together, so the main loop stays short. This is the shape of a typical pipeline helper.

```python run
class BatchStats:
    def __init__(self, name):
        self.name = name
        self.ok = 0
        self.bad_rows = []

    def record(self, row_number, is_valid):
        if is_valid:
            self.ok += 1
        else:
            self.bad_rows.append(row_number)

    @property
    def total(self):
        return self.ok + len(self.bad_rows)

    def report(self):
        rate = 100 * self.ok / self.total if self.total else 0
        return f"{self.name}: {self.ok}/{self.total} ok ({rate:.1f}%), bad rows {self.bad_rows}"

stats = BatchStats("orders")
for number, value in enumerate(["12", "x", "7", "", "40"], start=1):
    stats.record(number, value.isdigit())
print(stats.report())
other = BatchStats("empty")
print(other.report())
```

```output
orders: 3/5 ok (60.0%), bad rows [2, 4]
empty: 0/0 ok (0.0%), bad rows []
```

## Real-world applications

- **Pipeline state.** A class such as `BatchStats` (Example 6) keeps counts, errors and timings in one object that every step updates, instead of passing many loose variables.
- **Wrapping a resource.** A `Database` or `ApiClient` class stores a connection or base URL in `__init__` and offers methods such as `fetch()`, which is how most libraries are used.
- **Validated records.** A class with property setters (Example 5) refuses invalid values at the moment of assignment, so bad data is caught at the source.
- **Understanding libraries.** A pandas `DataFrame` or a `datetime` is an object: `df.shape` is an attribute and `df.head()` is a method, so reading classes is how you read documentation.

## Daily review

### Key takeaways

- A class is a template; an object is one instance created by calling the class.
- `__init__` sets up the object's attributes, and `self` refers to the object inside every method.
- Instance attributes belong to one object; class attributes are shared by all objects.
- Define `__repr__` so objects print readably.
- Encapsulation keeps state behind methods and properties, using `_name` for internal data.

### Common mistakes

- Forgetting `self` in a method definition, which gives `TypeError: method() takes 1 positional argument but 2 were given`. Add `self` as the first parameter.
- Forgetting `self.` before an attribute, such as `name = name` in `__init__`. The value is lost when the method ends, and later access raises `AttributeError`.
- Defining a mutable class attribute such as `items = []` and finding the list shared by every object. Create it in `__init__`.
- Calling a method without brackets, `acct.is_empty` for a normal method, which returns the method object instead of calling it.
- Printing an object and seeing `<__main__.Customer object at 0x...>`. Define `__repr__`.
- Assigning to `obj.currency` and expecting every object to change. This sets an instance attribute on that one object.
- Writing `__init__` with a `return` value. `__init__` must return `None`.

### Revision notes

- `class Name:` then `def __init__(self, ...):` and `self.attr = value`.
- `obj = Name(args)`; `obj.method(args)` passes `obj` as `self`.
- Class attribute: in the class body, shared. Instance attribute: on `self`, per object.
- `__repr__` returns a string; `_name` marks internal; `@property` reads like an attribute.
- `isinstance(obj, Name)`, `vars(obj)`.
