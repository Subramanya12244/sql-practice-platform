## Understand

### Why data engineers meet APIs

Until now the data arrived as files: CSV text and Excel workbooks that someone placed in a folder. Many sources never produce a file. A payment provider, a shop platform, a weather service or a company's own application exposes its data through an **API** (application programming interface): a set of addresses that a program can ask over the network for data, and sometimes for changes. The next twelve days follow one pipeline: ask an API for orders, handle everything that can go wrong, clean the answer, load it into PostgreSQL, validate the load and analyse it.

### Client, server, request, response

Every API call has two parties. The **server** holds the data and the rules. The **client** is your program. The client sends a **request**; the server sends back one **response**. The conversation uses **HTTP**, the protocol the web runs on. A request has a **method** (what to do: `GET` reads, and Day 102 covers the others), a **URL** (what to act on), **headers** (small labelled pieces of extra information, such as who you are) and sometimes a **body** (data you send). A response has a **status code** (a number that says how it went: `200` means success, `404` means not found), headers and usually a body.

**Stateless** means that the server remembers nothing between requests. Each request must carry everything the server needs: which resource, which page, which credentials. This is why the examples later in this block pass the same header on every call, and why a page number belongs in the request and not in the server's memory.

### Resources and endpoints

REST is a style of API design built around **resources**: the things the API is about, named with nouns, such as `orders` or `customers`. An **endpoint** is a URL path that addresses a resource. A path for a **collection** (`/orders`) stands for all of them; a path for one **item** (`/orders/17`) stands for a single one. The Orders API of this block has:

| Request | Meaning |
|---|---|
| `GET /orders?page=2&page_size=50` | One page of the order collection. |
| `GET /orders/17` | The order whose `order_id` is 17. |
| header `X-Api-Key: <key>` | Identifies the caller on every request. |

A page response looks like `{"data": [...], "page": 2, "total_pages": 3}`. Each order record has `order_id`, `customer_id`, `amount_cents`, `currency`, `status` (`paid`, `refunded` or `failed`) and `created_at`. There are 120 orders. This is a made-up service, replaced in the browser by a function that returns canned data, and in local examples by a small server running on your own computer. No example calls a real service.

### Anatomy of a URL

`https://api.shop.example/orders?page=2&page_size=50` has four parts. The **scheme** (`https`) says how to talk; `https` is HTTP over an encrypted connection. The **host** (`api.shop.example`) says which server. The **path** (`/orders`) says which resource. The **query string** (after `?`) holds `name=value` pairs joined by `&` that refine the request: which page, how many records, which filter. Special characters in values must be **percent-encoded** (a space becomes `%20`); libraries such as `requests` do that for you when you pass parameters as a dictionary, which is one reason to avoid building URLs by hand.

### JSON

The body of most API responses is **JSON** (JavaScript Object Notation), a text format for nested data. It has six kinds of value: objects `{"a": 1}`, arrays `[1, 2]`, strings `"x"` (always double-quoted), numbers, booleans `true` and `false`, and `null`. Python's `json` module maps them to dictionaries, lists, `str`, `int` or `float`, `True` and `False`, and `None`. `json.loads(text)` turns JSON text into Python values ("load string"); `json.dumps(value)` does the reverse. Three things surprise newcomers: JSON has no date type (dates travel as strings such as `"2026-03-01T10:00:00Z"`, which you must parse), JSON keys are always strings, and a number such as `19.90` is a float, so money should travel as integer cents (`amount_cents: 1990`), as this API does.

### Common misconception

Learners think an API call returns "the data" in one piece, and treat the first response as complete. Real APIs return pieces (pages), can refuse (a status other than 200) and can change. The response must be checked before it is used: status first, then structure, then values. The following days build each of those checks.

### Why it matters

Pipelines that read APIs fail in ways that file pipelines do not: the network is slow, the server is busy, the key expires, a field disappears. Knowing what a request and a response consist of lets you read the failure instead of guessing at it.

## Syntax and key functions

Parsing and building JSON:

```python
import json

order = json.loads('{"order_id": 17, "status": "paid", "note": null}')
text = json.dumps(order, sort_keys=True)
```

A request with the `requests` library (needs `pip install requests`; the browser cannot import it):

```python
import requests

response = requests.get(
    "https://api.shop.example/orders",
    params={"page": 2, "page_size": 50},      # becomes ?page=2&page_size=50
    headers={"X-Api-Key": key},
    timeout=10,
)
print(response.status_code, response.headers["Content-Type"])
data = response.json()
```

| Item | What it does or returns |
|---|---|
| `json.loads(text)` | Python value (dict, list, ...) from JSON text. |
| `json.dumps(value, indent=, sort_keys=)` | JSON text from a Python value. |
| `requests.get(url, params, headers, timeout)` | A `Response` object. |
| `response.status_code` | Integer status such as 200 or 404. |
| `response.headers` | Case-insensitive mapping of response headers. |
| `response.json()` | Parsed body (raises an error if the body is not JSON). |
| `response.text` | Body as text. |
| `response.url` | The final URL, with the encoded query string. |

## Learn by example

### Example 1: The parts of a URL (browser-safe)

The browser Python cannot import `urllib`, so the code splits the URL with string methods to show the four parts and builds the query dictionary. Later, `requests` does this for you.

```python run
url = "https://api.shop.example/orders?page=2&page_size=50"
scheme, rest = url.split("://", 1)
host_and_path, query_text = rest.split("?", 1)
host, path = host_and_path.split("/", 1)
query = dict(pair.split("=", 1) for pair in query_text.split("&"))
print(scheme)
print(host)
print("/" + path)
print(query)
print({k: int(v) for k, v in query.items()})
```

```output
https
api.shop.example
/orders
{'page': '2', 'page_size': '50'}
{'page': 2, 'page_size': 50}
```

The query values are text until you convert them: the server also receives `"2"` and `"50"` as text and converts them itself.

### Example 2: JSON text to Python and back

One order as JSON text. The code parses it, shows the Python types that result (including `None` for `null`), parses the timestamp string into a date, and writes the value back as sorted compact JSON. The round trip shows that JSON keeps the structure and not the Python types.

```python run
import json
from datetime import datetime

text = '{"order_id": 17, "customer_id": 8, "amount_cents": 1990, "currency": "EUR", "status": "paid", "created_at": "2026-03-05T10:30:00Z", "note": null, "tags": ["gift", "web"]}'
order = json.loads(text)
print({k: type(v).__name__ for k, v in order.items()})
created = datetime.strptime(order["created_at"], "%Y-%m-%dT%H:%M:%SZ")
print(created.date(), created.hour)
print(order["amount_cents"] / 100)
print(json.dumps(order, sort_keys=True, separators=(",", ":")))
print(json.loads(json.dumps({"a": (1, 2)})))
```

```output
{'order_id': 'int', 'customer_id': 'int', 'amount_cents': 'int', 'currency': 'str', 'status': 'str', 'created_at': 'str', 'note': 'NoneType', 'tags': 'list'}
2026-03-05 10
19.9
{"amount_cents":1990,"created_at":"2026-03-05T10:30:00Z","currency":"EUR","customer_id":8,"note":null,"order_id":17,"status":"paid","tags":["gift","web"]}
{'a': [1, 2]}
```

The last line shows the tuple coming back as a list: JSON has arrays, not tuples.

### Example 3: Calling a stand-in Orders API

The function `get` replaces the network in the browser. It has the same call shape as `requests.get` and returns an object with `status_code`, `headers` and `json()`. It checks the key, serves one page of the collection and one item, and answers `404` for an unknown order. The same client code works against a real server in Example 4.

```python run
import json

STATUSES = ["paid", "paid", "refunded", "failed"]
ORDERS = [
    {"order_id": i, "customer_id": i * 7 % 25 + 1, "amount_cents": 1000 + i * 137 % 9000,
     "currency": "EUR" if i % 4 else "USD", "status": STATUSES[i % 4],
     "created_at": f"2026-03-{(i - 1) // 4 + 1:02d}T{i * 7 % 24:02d}:{i * 13 % 60:02d}:00Z"}
    for i in range(1, 121)
]

class Response:
    """Looks like a `requests` response: status_code, headers, json(), raise_for_status()."""
    def __init__(self, status_code, body=None, headers=None):
        self.status_code = status_code
        self._body = body
        self.headers = headers or {}

    def json(self):
        return json.loads(json.dumps(self._body))

    def raise_for_status(self):
        if self.status_code >= 400:
            raise RuntimeError(f"HTTP {self.status_code}")

def get(path, params=None, headers=None, timeout=None):
    params = params or {}
    if (headers or {}).get("X-Api-Key") != "demo-key-123":
        return Response(401, {"error": "invalid api key"})
    json_type = {"Content-Type": "application/json"}
    if path == "/orders":
        page, size = int(params.get("page", 1)), int(params.get("page_size", 20))
        pages = -(-len(ORDERS) // size)
        return Response(200, {"data": ORDERS[(page - 1) * size:page * size], "page": page, "total_pages": pages}, json_type)
    if path.startswith("/orders/"):
        found = [o for o in ORDERS if o["order_id"] == int(path.rsplit("/", 1)[1])]
        return Response(200, found[0], json_type) if found else Response(404, {"error": "order not found"}, json_type)
    return Response(404, {"error": "no such route"})

KEY = {"X-Api-Key": "demo-key-123"}
page = get("/orders", {"page": 2, "page_size": 50}, KEY)
body = page.json()
print(page.status_code, page.headers["Content-Type"])
print(body["page"], body["total_pages"], len(body["data"]))
print(body["data"][0])
item = get("/orders/17", headers=KEY)
print(item.status_code, item.json()["status"])
print(get("/orders/999", headers=KEY).status_code, get("/orders").status_code)
```

```output
200 application/json
2 3 50
{'order_id': 51, 'customer_id': 8, 'amount_cents': 7987, 'currency': 'EUR', 'status': 'failed', 'created_at': '2026-03-13T21:03:00Z'}
200 paid
404 401
```

Three status codes already appear: `200` for success, `404` for a missing order and `401` for a missing key. Day 102 organises them into classes.

### Example 4: The same calls over real HTTP

This local example starts a small HTTP server on `127.0.0.1` (your own computer, a random free port) in a background thread and calls it with `requests`. The server code is scaffolding that imitates the Orders API; read the client part at the bottom. `response.url` shows the encoded URL that `requests` built from the parameter dictionary.

```python local
import json
import threading
from http.server import BaseHTTPRequestHandler, HTTPServer
from urllib.parse import parse_qs, urlparse

import requests

STATUSES = ["paid", "paid", "refunded", "failed"]
ORDERS = [
    {"order_id": i, "customer_id": i * 7 % 25 + 1, "amount_cents": 1000 + i * 137 % 9000,
     "currency": "EUR" if i % 4 else "USD", "status": STATUSES[i % 4],
     "created_at": f"2026-03-{(i - 1) // 4 + 1:02d}T{i * 7 % 24:02d}:{i * 13 % 60:02d}:00Z"}
    for i in range(1, 121)
]

API_KEY = "demo-key-123"

def start_server(orders, rate_limit_every=0):
    state = {"requests": 0, "orders": {o["order_id"]: dict(o) for o in orders}}

    def route(method, parts, query, body):
        table = state["orders"]
        if parts == ["orders"] and method == "GET":
            rows = [table[k] for k in sorted(table)]
            if "cursor" in query:
                start = int(query["cursor"] or 0)
                size = int(query.get("limit", 25))
                nxt = start + size
                return 200, {"data": rows[start:nxt], "next_cursor": str(nxt) if nxt < len(rows) else None}
            if "offset" in query:
                start, size = int(query["offset"]), int(query.get("limit", 25))
                return 200, {"data": rows[start:start + size], "offset": start, "total": len(rows)}
            page, size = int(query.get("page", 1)), int(query.get("page_size", 20))
            if page < 1 or not 1 <= size <= 100:
                return 400, {"error": "bad paging parameters"}
            pages = -(-len(rows) // size)
            return 200, {"data": rows[(page - 1) * size:page * size], "page": page, "total_pages": pages}
        if parts == ["orders"] and method == "POST":
            if not body or "customer_id" not in body:
                return 422, {"error": "customer_id is required"}
            new_id = max(table) + 1
            table[new_id] = {"order_id": new_id, **body}
            return 201, table[new_id]
        if len(parts) == 2 and parts[0] == "orders" and parts[1].isdigit():
            key = int(parts[1])
            if key not in table:
                return 404, {"error": "order not found"}
            if method == "GET":
                return 200, table[key]
            if method == "PUT":
                table[key] = {"order_id": key, **body}
                return 200, table[key]
            if method == "DELETE":
                del table[key]
                return 204, None
        return 404, {"error": "no such route"}

    class Handler(BaseHTTPRequestHandler):
        def log_message(self, *args):
            pass

        def handle_request(self, method):
            state["requests"] += 1
            length = int(self.headers.get("Content-Length") or 0)
            body = json.loads(self.rfile.read(length)) if length else None
            if self.headers.get("X-Api-Key") != API_KEY:
                status, payload, extra = 401, {"error": "invalid api key"}, {}
            elif rate_limit_every and state["requests"] % rate_limit_every == 0:
                status, payload, extra = 429, {"error": "slow down"}, {"Retry-After": "2"}
            else:
                url = urlparse(self.path)
                query = {k: v[0] for k, v in parse_qs(url.query, keep_blank_values=True).items()}
                status, payload = route(method, url.path.strip("/").split("/"), query, body)
                extra = {}
            data = b"" if payload is None else json.dumps(payload).encode()
            self.send_response(status)
            self.send_header("Content-Type", "application/json")
            self.send_header("Content-Length", str(len(data)))
            for name, value in extra.items():
                self.send_header(name, value)
            self.end_headers()
            self.wfile.write(data)

        do_GET = lambda self: self.handle_request("GET")
        do_POST = lambda self: self.handle_request("POST")
        do_PUT = lambda self: self.handle_request("PUT")
        do_DELETE = lambda self: self.handle_request("DELETE")

    server = HTTPServer(("127.0.0.1", 0), Handler)
    threading.Thread(target=server.serve_forever, daemon=True).start()
    return server, f"http://127.0.0.1:{server.server_port}", state

server, base, state = start_server(ORDERS)
try:
    headers = {"X-Api-Key": API_KEY}
    response = requests.get(base + "/orders", params={"page": 3, "page_size": 50}, headers=headers, timeout=5)
    print(response.status_code, response.headers["Content-Type"])
    print(response.url.split("/orders", 1)[1])
    body = response.json()
    print(body["page"], body["total_pages"], len(body["data"]), body["data"][0]["order_id"])
    print(requests.get(base + "/orders/17", headers=headers, timeout=5).json()["amount_cents"])
    print(requests.get(base + "/orders/999", headers=headers, timeout=5).status_code)
    print(requests.get(base + "/orders", timeout=5).json())
    print("requests served:", state["requests"])
finally:
    server.shutdown()
    server.server_close()
```

```output
200 application/json
?page=3&page_size=50
3 3 20 101
3329
404
{'error': 'invalid api key'}
requests served: 4
```

The server never remembers that you asked for page 3 earlier. Every request repeats the key and the page, which is what stateless means in practice.

## Real-world applications

- **Payments and orders.** A pipeline asks a payment provider's orders endpoint for yesterday's transactions every morning instead of waiting for a file.
- **SaaS reporting.** CRM, ticketing and marketing tools expose REST APIs; reading their JSON is how their data reaches the warehouse.
- **Reference data.** Exchange rates and country lists come from small APIs. The client needs the same four things each time: URL, parameters, key, parsed JSON.
- **Debugging in production.** When a job fails with `401` or `429`, knowing the request parts tells you whether the key, the rate or the URL is at fault.

## Daily review

### Key takeaways

- An API is addressed by URLs; a REST API names resources with nouns and addresses collections and single items.
- A request has a method, URL, headers and optional body; a response has a status, headers and usually a body.
- The server is stateless: every request carries what it needs.
- JSON has six value kinds that map to Python types; dates and money need your own handling.
- The Orders API: `GET /orders?page=N&page_size=P`, header `X-Api-Key`, 120 orders.

### Common mistakes

- **Using `response.json()` without checking the status.** An error response has a JSON body too, and the code then fails on a missing field. Check `status_code` first.
- **Building query strings by hand.** Spaces and `&` in values break the URL. Pass a `params` dictionary.
- **Expecting JSON dates to be dates.** They are strings. Parse them and decide the time zone.
- **Treating the first page as all the data.** `total_pages` says otherwise.
- **Forgetting the key.** A `401` comes back, not data.

### Revision notes

- URL: scheme, host, path, `?query`.
- Request: method, URL, headers, body. Response: status, headers, body.
- `json.loads` / `json.dumps`; `null` is `None`; tuples become lists.
- Orders API fields: order_id, customer_id, amount_cents, currency, status, created_at.
