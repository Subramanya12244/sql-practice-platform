## Objectives

- Plan a small analytics project as five steps (load, validate, clean, analyse, report) and write the questions and checks before the code.
- Load a raw extract into a sqlite3 database, validate it with row counts, key and orphan checks, and clean it in SQL with a log of the rows each step changed.
- Combine SQL (filter, join, aggregate) and pandas (growth, shares, formatting) in one reproducible script.
- Produce a short written report whose every number comes from the code, with caveats.

## Understand

### What the project is

This project day joins the analyst data-preparation skills of the last ten days into one small deliverable. The scenario is an online shop that sends you a raw extract of 60 customers and 505 order rows for March to August 2025, and asks three questions: how much paid revenue came in each month and region, which channel earns the most, and which regions are growing. A real database is replaced by an in-memory `sqlite3` database. SQLite differs from PostgreSQL in some details (type names, `||` and `SUBSTR` instead of `date_trunc`, no `::` casts), but the workflow of loading, checking, querying and reporting is the same, and the SQL used here is standard enough to port.

### The five steps

First write the questions and the checks you expect to need. Second load the raw data unchanged into `customers` and `orders_raw`, and never edit that table, so you can always return to the source. Third validate: count rows, test that the order key is unique, look for orders whose customer does not exist (orphans) and for inconsistent labels. The raw extract has planted problems: five exact duplicate rows, three orders for a customer number that does not exist, and four channel labels with stray spaces or capitals. Fourth clean into a new table with SQL and log how many rows each step changed; decide what to do with orphans and write the decision down (here they are kept, counted, and shown as `Unknown` region instead of being silently dropped). Fifth analyse and report: a SQL query does the filtering, joining and grouping, pandas does the growth and share calculations, and a small function turns the results into text.

### Working rules

Do the heavy filtering and aggregation in SQL and the flexible reshaping in pandas (Day 158). Every step is a function, so the whole project reruns from raw data with one call. Keep a validation dictionary that you print before and after cleaning, and compare the two. Never report a number you cannot reproduce from the script. Separate the facts from the explanations: the report states what the data shows, and any reason for it is a question for the business.

### What good looks like

A strong submission loads without editing the raw table, prints a validation block that shows the problems and then shows them fixed, keeps a row-accounting line (505 raw rows, 500 after removing duplicates), reports each of the three answers with a number and a base, and ends with caveats: the data cover six months and one shop, three orders have no customer record, refunded orders are excluded from revenue, and growth over six months says little about the year.

## Learn by example

### Example 1: Load the raw data and see its problems

The raw extract is created with a seeded generator and loaded unchanged. Four quick queries show the planted problems before any cleaning, which is what the validation step is for.

```python run
import sqlite3
import numpy as np
import pandas as pd


def make_raw():
    rng = np.random.default_rng(7)
    n_c, n = 60, 500
    customers = pd.DataFrame({
        "customer_id": np.arange(1, n_c + 1),
        "region": rng.choice(["North", "South", "East", "West"], size=n_c),
        "signup_date": (pd.Timestamp("2025-01-01") + pd.to_timedelta(rng.integers(0, 150, n_c), unit="D")).strftime("%Y-%m-%d"),
    })
    orders = pd.DataFrame({
        "order_id": np.arange(5001, 5001 + n),
        "customer_id": rng.integers(1, n_c + 1, n),
        "order_date": (pd.Timestamp("2025-03-01") + pd.to_timedelta(rng.integers(0, 180, n), unit="D")).strftime("%Y-%m-%d"),
        "channel": rng.choice(["web", "app", "store"], size=n, p=[0.5, 0.3, 0.2]),
        "amount": (20 + rng.random(n) * 180).round(2),
        "status": rng.choice(["paid", "refunded"], size=n, p=[0.93, 0.07]),
    })
    orders.loc[[5, 25, 45], "customer_id"] = 999
    orders.loc[[10, 20, 30, 40], "channel"] = ["Web ", "APP", "web ", "Store"]
    orders = pd.concat([orders, orders.iloc[[100, 200, 300, 400, 450]]], ignore_index=True)
    return customers, orders


def load_raw(conn):
    customers, orders = make_raw()
    customers.to_sql("customers", conn, index=False)
    orders.to_sql("orders_raw", conn, index=False)

conn = sqlite3.connect(":memory:")
load_raw(conn)
one = lambda sql: conn.execute(sql).fetchone()[0]
print("customers:", one("SELECT COUNT(*) FROM customers"), "| raw order rows:", one("SELECT COUNT(*) FROM orders_raw"))
print("distinct order ids:", one("SELECT COUNT(DISTINCT order_id) FROM orders_raw"))
print("orphan orders:", one("SELECT COUNT(*) FROM orders_raw WHERE customer_id NOT IN (SELECT customer_id FROM customers)"))
print("channel labels:", sorted(r[0] for r in conn.execute("SELECT DISTINCT channel FROM orders_raw")))
conn.close()
```

```output

distinct order ids: 500
orphan orders: 3
channel labels: ['APP', 'Store', 'Web ', 'app', 'store', 'web', 'web ']
```

### Example 2: Clean in SQL and validate before and after

The cleaning is one `CREATE TABLE ... AS SELECT DISTINCT` that removes exact duplicates and normalises the channel text. The validation function reports the same checks after cleaning, so the change is visible: duplicates and messy labels are gone, but the three orphan orders remain and are counted, not hidden.

### Example 4: Growth, channel mix and the answers

Pandas calculates what is awkward in SQL: month-over-month growth for each region and the share of revenue by channel. The first month has no previous month, so growth starts in the second. The extract ends on 28 August, so August is a partial month and the last full month, July, is used. Each result answers one of the three questions.

## Real-world applications

- **Recurring management report.** A script with this load, validate, clean, query, report structure is rerun each month on a fresh extract, with the validation block as the first thing a reviewer reads.
- **Handover to engineering.** The same steps become an ETL job: the raw table is the staging layer, the cleaned table the reporting layer, and the validation dictionary the data quality gate.
- **Audit trail.** The row-accounting line (505 raw, 500 clean, 3 orphans reported) answers the question "where did the other five rows go?" without anyone rerunning the work.
- **Portfolio piece.** A small end-to-end project with checks and caveats shows an employer how you work, not only that you can write a query.

## Daily review

### Key takeaways

- Load raw data unchanged, validate, then clean into a new table with a log.
- Validate before and after cleaning with the same function, and compare.
- Do filtering, joins and grouping in SQL, and growth and shares in pandas.
- Decide what happens to rows that fail checks and write it down; do not silently drop them.
- A report states results, bases and caveats, and every number comes from code.

### Common mistakes

- Editing the raw table. Symptom: you cannot tell what the source said. Fix: keep `orders_raw` and write a cleaned table.
- An inner join that drops orphans. Symptom: the regional totals are lower than the order total. Fix: a left join with `COALESCE`, and a count of orphans in the report.
- Cleaning labels after grouping. Symptom: `web` and `Web ` appear as two channels. Fix: normalise text before any aggregation.
- Comparing growth on a partial month. Symptom: a sharp fall in the last month. Fix: check the date range and exclude or flag the incomplete month.

### Revision notes

- Steps: questions, load, validate, clean, analyse, report.
- Validation: counts, unique key, orphans, labels, totals.
- `CREATE TABLE ... AS SELECT DISTINCT ... LOWER(TRIM(...))`.
- Left join plus `COALESCE` keeps orphan rows visible.
