## Objectives

- Write analytical SQL for the capstone questions: monthly net revenue, return on spend, return rate and repeat customers.
- Use window functions for month-over-month change, running totals and ranks.
- Aggregate to the right grain before joining, so that spend and revenue are never multiplied.
- Check every query result against the pandas figures from the clean tables.

## Understand

### What this stage produces

Day 175 left a loaded star schema. This stage turns the five questions from Day 172 into SQL, runs them and records the results that the charts (Day 177) and the narrative (Day 178) will use. Each query is a small, named, reviewed piece of code stored in the `sql/` folder, and each result is cross-checked against an independent computation in pandas. A query that gives a number nobody has verified is a liability: the check is what lets you state the number in a report.

### Aggregate first, then join

The most common wrong answer in this kind of analysis comes from joining at the wrong grain. Return on spend is net revenue divided by spend. Net revenue lives on orders (many rows per campaign) and spend lives on campaigns (one row per campaign). If you join orders to campaigns and then sum spend, the spend is added once per order. The fix is to aggregate the orders to one row per campaign in a common table expression (CTE, a named subquery introduced with `WITH`) and join that to the campaign table afterwards, so each campaign contributes one revenue figure and one spend figure. The same rule explains why `COUNT(*)` after a join to a many-sided table inflates counts.

### Net revenue in SQL

Net revenue is revenue of orders that were not returned. In SQL this is conditional aggregation: `SUM(CASE WHEN returned = 0 THEN revenue ELSE 0 END)`. Computing it inside the aggregate keeps all orders in the row count (so you can still report orders and return rate) while the revenue sum excludes returned ones. Return rate is the average of the `returned` flag: `AVG(returned)` is the share of returned orders, because the flag is 0 or 1.

### Windows for change and cumulative figures

A window function computes a value for each row using a set of related rows, without collapsing rows as `GROUP BY` does. `LAG(net) OVER (ORDER BY ym)` gives the previous month's value on the current row, which makes month-over-month change a one-line expression. `SUM(net) OVER (ORDER BY ym)` is a running total. `RANK() OVER (ORDER BY net DESC)` numbers rows by size. `SUM(x) OVER ()` with an empty window gives the grand total on every row, useful for shares. The first month has no previous month, so `LAG` returns NULL and the growth is NULL: report it as not available and never as zero.

### Metrics that need care

The repeat customer share is customers with two or more orders divided by customers with at least one order. State the base: customers who ordered, not all 120 customers, because some customers never ordered in the window. Concentration is how much of revenue the largest customers provide: rank customers by revenue and take a cumulative share. A misconception is to treat a high return on spend as proof that a channel works: organic orders have no spend, so their ratio is undefined, and a channel's customers may have bought anyway. The numbers in the narrative need those caveats.

### Checking against pandas

For each query, compute the same figure from the clean DataFrame: net revenue by month with `groupby`, return rate with `mean`. When SQL and pandas agree, you have two independent implementations agreeing, which is strong evidence. When they differ, the difference usually points to a join at the wrong grain or a NULL handled differently.

## Syntax and key functions

```sql-syntax
WITH per_group AS (
    SELECT key, SUM(CASE WHEN flag = 0 THEN amount ELSE 0 END) AS net FROM t GROUP BY key
)
SELECT key, net,
       LAG(net) OVER (ORDER BY key) AS previous,
       SUM(net) OVER (ORDER BY key) AS running,
       RANK() OVER (ORDER BY net DESC) AS rnk
FROM per_group ORDER BY key;
```

| Function | Returns |
|---|---|
| `LAG(x) OVER (ORDER BY k)` | Value of `x` from the previous row, NULL for the first |
| `SUM(x) OVER (ORDER BY k)` | Running total in the order of `k` |
| `SUM(x) OVER ()` | Total over all rows, repeated on every row |
| `RANK() OVER (ORDER BY x DESC)` | Rank with ties sharing a rank |
| `AVG(flag)` | Share of rows with flag 1 when the flag is 0 or 1 |
| `CASE WHEN ... END` | Conditional value inside an aggregate |

## Learn by example

### Example 1: Monthly net revenue, growth and running total

A CTE aggregates net revenue per month. The outer query adds the previous month's value with `LAG` for the growth percentage and a running total. The first month has no growth.

```python run
import numpy as np
import pandas as pd


def generate(seed=7):
    """Seeded online-store data with planted defects: 500 orders, 120 customers, 20 products."""
    rng = np.random.default_rng(seed)
    customers = pd.DataFrame({
        "customer_id": np.arange(1, 121),
        "country": rng.choice(["DE", "FR", "UK", "US"], 120, p=[0.3, 0.2, 0.2, 0.3]),
        "signup_date": pd.Timestamp("2024-07-01") + pd.to_timedelta(rng.integers(0, 180, 120), unit="D"),
    })
    customers.loc[rng.choice(120, 8, replace=False), "country"] = "us "
    products = pd.DataFrame({
        "product_id": np.arange(1, 21),
        "category": np.repeat(["home", "beauty", "sports", "electronics"], 5),
        "unit_price": (10 + rng.random(20) * 90).round(2),
    })
    campaigns = pd.DataFrame({
        "campaign_id": [0, 1, 2, 3],
        "channel": ["organic", "email", "paid_search", "social"],
        "spend": [0.0, 800.0, 2500.0, 1200.0],
    })
    n = 500
    orders = pd.DataFrame({
        "order_id": np.arange(1001, 1001 + n),
        "customer_id": rng.integers(1, 121, n),
        "product_id": rng.integers(1, 21, n),
        "order_date": pd.Timestamp("2025-01-01") + pd.to_timedelta(rng.integers(0, 180, n), unit="D"),
        "quantity": rng.integers(1, 5, n),
        "discount_pct": rng.choice([0, 10, 20], n, p=[0.6, 0.25, 0.15]),
        "campaign_id": rng.choice([0, 1, 2, 3], n, p=[0.4, 0.2, 0.25, 0.15]),
    })
    orders.loc[rng.choice(n, 5, replace=False), "quantity"] = -1
    orders.loc[rng.choice(n, 6, replace=False), "customer_id"] = 999
    orders = pd.concat([orders, orders.sample(10, random_state=1)], ignore_index=True)
    returned = rng.choice(np.arange(1001, 1001 + n), 60, replace=False)
    returns = pd.DataFrame({
        "order_id": np.concatenate([returned, [9001, 9002, 9003]]),
        "reason": rng.choice(["damaged", "wrong_item", "changed_mind"], 63, p=[0.3, 0.2, 0.5]),
    })
    return {"orders": orders, "customers": customers, "products": products, "campaigns": campaigns, "returns": returns}



def clean(t):
    """Apply the quality rules; return cleaned tables and a row-accounting log."""
    log = {}
    o = t["orders"]
    log["raw_orders"] = len(o)
    o = o.drop_duplicates()
    log["after_duplicates"] = len(o)
    o = o[o["quantity"] > 0]
    log["after_quantity"] = len(o)
    c = t["customers"].copy()
    c["country"] = c["country"].str.strip().str.upper()
    o = o[o["customer_id"].isin(c["customer_id"])]
    log["after_customers"] = len(o)
    r = t["returns"]
    log["raw_returns"] = len(r)
    r = r[r["order_id"].isin(o["order_id"])].drop_duplicates("order_id")
    log["clean_returns"] = len(r)
    p = t["products"]
    o = o.merge(p[["product_id", "unit_price"]], on="product_id", how="left")
    o["revenue"] = (o["quantity"] * o["unit_price"] * (1 - o["discount_pct"] / 100)).round(2)
    o["returned"] = o["order_id"].isin(r["order_id"])
    return {"orders": o.reset_index(drop=True), "customers": c, "products": p, "campaigns": t["campaigns"], "returns": r.reset_index(drop=True)}, log

import sqlite3

SCHEMA = """
CREATE TABLE dim_customer (customer_id INTEGER PRIMARY KEY, country TEXT NOT NULL, signup_date TEXT NOT NULL);
CREATE TABLE dim_product (product_id INTEGER PRIMARY KEY, category TEXT NOT NULL, unit_price REAL NOT NULL CHECK (unit_price > 0));
CREATE TABLE dim_campaign (campaign_id INTEGER PRIMARY KEY, channel TEXT NOT NULL, spend REAL NOT NULL);
CREATE TABLE dim_date (date_id INTEGER PRIMARY KEY, full_date TEXT NOT NULL, year INTEGER NOT NULL, month INTEGER NOT NULL);
CREATE TABLE fact_orders (
    order_id INTEGER PRIMARY KEY,
    customer_id INTEGER NOT NULL REFERENCES dim_customer(customer_id),
    product_id INTEGER NOT NULL REFERENCES dim_product(product_id),
    campaign_id INTEGER NOT NULL REFERENCES dim_campaign(campaign_id),
    date_id INTEGER NOT NULL REFERENCES dim_date(date_id),
    quantity INTEGER NOT NULL CHECK (quantity > 0),
    discount_pct INTEGER NOT NULL,
    revenue REAL NOT NULL,
    returned INTEGER NOT NULL CHECK (returned IN (0, 1))
);
CREATE TABLE fact_returns (order_id INTEGER PRIMARY KEY REFERENCES fact_orders(order_id), reason TEXT NOT NULL);
"""


def load(ct):
    """Create the star schema in an in-memory SQLite database and load the cleaned tables."""
    db = sqlite3.connect(":memory:")
    db.execute("PRAGMA foreign_keys = ON")
    db.executescript(SCHEMA)
    c = ct["customers"].assign(signup_date=ct["customers"]["signup_date"].dt.strftime("%Y-%m-%d"))
    db.executemany("INSERT INTO dim_customer VALUES (?, ?, ?)", c.astype(object).values.tolist())
    db.executemany("INSERT INTO dim_product VALUES (?, ?, ?)", ct["products"].astype(object).values.tolist())
    db.executemany("INSERT INTO dim_campaign VALUES (?, ?, ?)", ct["campaigns"].astype(object).values.tolist())
    days = pd.date_range("2025-01-01", "2025-06-30")
    dd = pd.DataFrame({"date_id": days.strftime("%Y%m%d").astype(int), "full_date": days.strftime("%Y-%m-%d"), "year": days.year, "month": days.month})
    db.executemany("INSERT INTO dim_date VALUES (?, ?, ?, ?)", dd.astype(object).values.tolist())
    o = ct["orders"]
    f = pd.DataFrame({"order_id": o["order_id"], "customer_id": o["customer_id"], "product_id": o["product_id"], "campaign_id": o["campaign_id"],
                      "date_id": o["order_date"].dt.strftime("%Y%m%d").astype(int), "quantity": o["quantity"], "discount_pct": o["discount_pct"],
                      "revenue": o["revenue"], "returned": o["returned"].astype(int)})
    db.executemany("INSERT INTO fact_orders VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?)", f.astype(object).values.tolist())
    db.executemany("INSERT INTO fact_returns VALUES (?, ?)", ct["returns"].astype(object).values.tolist())
    db.commit()
    return db


t = generate()
ct, log = clean(t)
db = load(ct)
q = """
WITH m AS (
    SELECT d.year * 100 + d.month AS ym, COUNT(*) AS orders,
           SUM(CASE WHEN o.returned = 0 THEN o.revenue ELSE 0 END) AS net
    FROM fact_orders o JOIN dim_date d ON d.date_id = o.date_id
    GROUP BY d.year, d.month
)
SELECT ym, orders, ROUND(net, 2),
       ROUND(100.0 * (net - LAG(net) OVER (ORDER BY ym)) / LAG(net) OVER (ORDER BY ym), 1) AS growth,
       ROUND(SUM(net) OVER (ORDER BY ym), 2) AS running
FROM m ORDER BY ym
"""
for ym, orders, net, growth, running in db.execute(q):
    print(ym, orders, net, "n/a" if growth is None else growth, running)
pdnet = ct["orders"].loc[~ct["orders"]["returned"], "revenue"].sum()
print("pandas net total:", round(float(pdnet), 2))
db.close()
```

### Example 3: Repeat customers and concentration

A CTE counts orders and revenue per customer. The outer query reports the repeat share on the right base, and a window ranks customers to find the share of revenue from the top ten.

### Example 4: The same window query in PostgreSQL

The window query is portable. This block builds a small month table with `generate_series` in the browser's PostgreSQL and computes growth with `LAG`, so you can compare the PostgreSQL form with the SQLite form above.

```sql run
DROP TABLE IF EXISTS monthly_net;
CREATE TABLE monthly_net AS
SELECT m AS month_no, (100 + m * 10 + (m % 3) * 15)::numeric(10, 2) AS net
FROM generate_series(1, 6) AS m;
SELECT month_no, net,
       ROUND(100.0 * (net - LAG(net) OVER (ORDER BY month_no)) / LAG(net) OVER (ORDER BY month_no), 1) AS growth,
       SUM(net) OVER (ORDER BY month_no) AS running
FROM monthly_net
ORDER BY month_no
LIMIT 10;
```

```output
2 | 150.00 | 20.0 | 275.00

4 | 155.00 | 19.2 | 560.00
5 | 180.00 | 16.1 | 740.00
6 | 160.00 | -11.1 | 900.00
```

## Real-world applications

- A marketing analyst reports return on spend per channel by aggregating revenue per campaign first, as in Example 2, so budget decisions are not distorted by a join that multiplies spend.
- A finance team tracks month-over-month growth and a running total with `LAG` and a windowed `SUM`, the form in Example 1, for the monthly business review.
- A product team monitors return rate by category with `AVG` of a 0/1 flag and flags categories above an agreed threshold.
- A customer team measures repeat share and revenue concentration (Example 3) to decide whether to invest in retention or in acquisition.

## Daily review

### Key takeaways

- Aggregate to one row per entity before joining, so measures keep their grain.
- Conditional aggregation gives net revenue without dropping orders from the count.
- `LAG`, windowed `SUM` and `RANK` give growth, running totals and ranks without collapsing rows.
- Check each query against an independent pandas computation and state the base of every share.

### Common mistakes

- Summing campaign spend after joining to orders: the spend is multiplied by the number of orders. Aggregate orders per campaign first.
- Treating the first month's NULL growth as 0: it is not available. Display `n/a` or leave it blank.
- Using `AVG(returned)` on a column that holds NULLs or other codes: the share is wrong. Make sure the flag is only 0 or 1.
- Ranking by revenue alone when two customers can tie: the running total order is then unstable. Add a tie breaker such as `customer_id`.

### Revision notes

- Net revenue is `SUM(CASE WHEN returned = 0 THEN revenue ELSE 0 END)`; return rate is `AVG(returned)`.
- Return on spend is net revenue per campaign divided by that campaign's spend, undefined for organic.
- Window forms: `LAG(x) OVER (ORDER BY k)`, `SUM(x) OVER (ORDER BY k)`, `SUM(x) OVER ()`, `RANK() OVER (...)`.
