## Objectives

- Explain which names a function can see, using the terms local scope and global scope, and predict what a program prints when a name is reused.
- Give parameters default values and explain when the default is evaluated.
- Call a function with keyword arguments and mix them correctly with positional ones.
- Accept any number of positional arguments with `*args` and any number of keyword arguments with `**kwargs`.
- Unpack a list or dictionary into a call with `*` and `**`, and avoid the mutable default argument trap.

## Understand

### Scope: where a name can be seen

On Day 14 you learned that names created inside a function are local. The **scope** of a name is the part of the program where it can be used. There are two scopes you need today.

- The **global scope** holds names created at the top level of the file, outside any function.
- A **local scope** is created each time a function is called. It holds the function's parameters and any names assigned inside it, and it disappears when the function returns.

The lookup rule is: when Python meets a name inside a function, it looks first in the local scope, and then in the global scope. So a function can **read** a global name. But when a function **assigns** to a name, Python creates a new local name, even if a global name with the same spelling exists. The global one is not changed. This is called **shadowing**: the local name hides the global one while the function runs.

```text
rate = 0.2             # global
def fee(amount):
    rate = 0.5         # a new local name; the global rate stays 0.2
    return amount * rate
```

A picture: each function call is a private room with its own whiteboard. Writing on the whiteboard does not change the notice board in the hall (the globals), although you can look at the notice board from inside the room.

The keyword `global name` inside a function tells Python that assignments to `name` should change the global one. It works, but it makes code hard to follow, because any call can silently change a value used elsewhere. Better design: pass values in as parameters and return results. Reading a global constant, such as `TAX_RATE = 0.2`, is fine.

A related error: using a local name before it has a value. If a function assigns to `count` anywhere in its block, then `count` is local in the **whole** function, so reading it before the assignment raises `UnboundLocalError`.

### Default values

A parameter can have a **default** value, written with `=` in the definition: `def total(price, tax=0.2):`. If the caller leaves that argument out, the default is used. Parameters with defaults must come **after** the ones without, because positional matching fills parameters from the left. The defaults are evaluated **once, when the function is defined**, not on every call.

That timing causes the most famous Python trap. If the default is a **mutable** object such as a list, the same list is shared by every call that uses the default, so changes pile up between calls:

```python nocheck
def add_item(item, items=[]):    # the one list is created at definition time
    items.append(item)
    return items
```

The safe pattern is to use `None` as the default and create a new list inside the function: `if items is None: items = []`.

### Keyword arguments

In a call you can name the parameter: `total(price=50, tax=0.1)`. A **keyword argument** is matched by name, not by position, so the order does not matter and the call documents itself. Positional arguments must come first in a call, then keyword arguments. Giving the same parameter twice (by position and by name) is a `TypeError`, as is using a name that does not exist. Keyword arguments are especially useful when a function has several optional settings: you override only the ones you need.

### *args: any number of positional arguments

If you do not know how many values a caller will pass, put `*args` as the last positional parameter: `def total(*numbers):`. Inside the function, `numbers` is a **tuple** of all the extra positional arguments. The name `args` is a convention; the star is what matters. `total()` gives an empty tuple, so the function should handle that.

### **kwargs: any number of keyword arguments

`**kwargs` collects extra **keyword** arguments into a **dictionary**: `def describe(**fields):` called as `describe(name="Ada", age=36)` gives `fields == {"name": "Ada", "age": 36}`. It must come last in the definition. It is used for options that vary and for passing settings through.

### Unpacking into a call

The same stars work in a call. `f(*values)` spreads a list or tuple into separate positional arguments, and `f(**options)` spreads a dictionary into keyword arguments. So `max(*[3, 9, 4])` is `max(3, 9, 4)`.

### The order of parameters

When a definition uses several kinds, the order is fixed: normal parameters, then parameters with defaults, then `*args`, then `**kwargs`. Mixing them in another order is a `SyntaxError`.

### A worked trace of a call with defaults and keywords

Take `def total(price, tax=0.2, shipping=5)` and the call `total(100, shipping=0)`. Python first matches the positional argument 100 to the first parameter, `price`. It then matches the keyword `shipping` by name to the third parameter and sets it to 0. The parameter `tax` received nothing, so it takes its default 0.2. The function therefore runs with `price=100`, `tax=0.2`, `shipping=0`. Every parameter must end up with exactly one value, and that is the rule behind the errors: a missing required parameter, or a value supplied twice, is a `TypeError`.

Why do defaults and keywords matter in data work? Real functions have many settings: a delimiter, a number of decimals, whether to drop empty rows. A good default makes the common call short, and keyword arguments make the unusual call readable: `clean(text, lower=False)` says what it does, while `clean(text, False, True, 2)` makes the reader count positions. When you design a function, put the essential inputs first without defaults and the optional settings after them with defaults.

## Syntax and key functions

```text
def f(a, b, c=10):            # c has a default
def f(a, *args):              # extra positionals in a tuple
def f(a, **kwargs):           # extra keywords in a dict
def f(a, b=1, *args, **kwargs):

f(1, 2)                       # positional
f(1, c=5)                     # keyword
f(*[1, 2, 3])                 # unpack a sequence
f(**{"a": 1, "c": 5})         # unpack a dictionary
global name                   # inside a function: assign to the global name
```

| Item | Meaning |
|---|---|
| local scope | names created in the current call; gone afterwards |
| global scope | names created at the top level of the file |
| `param=default` | optional parameter, default evaluated once at definition |
| keyword argument | `name=value` in a call |
| `*args` | tuple of extra positional arguments |
| `**kwargs` | dictionary of extra keyword arguments |
| `x is None` | the safe test for a missing optional argument |

## Learn by example

### Example 1: Local, global and shadowing

```python run
rate = 0.2

def fee_local(amount):
    rate = 0.5
    return amount * rate

def fee_global(amount):
    return amount * rate

print(fee_local(100), fee_global(100), rate)

count = 0
def bump():
    global count
    count += 1

bump()
bump()
print(count)
```

```output
50.0 20.0 0.2
2
```

`fee_local` used its own `rate` and left the global one alone. `bump` changed the global because of `global count`.

### Example 2: Default parameters

```python run
def total(price, tax=0.2, shipping=5):
    return round(price * (1 + tax) + shipping, 2)

print(total(100))
print(total(100, 0.1))
print(total(100, 0.1, 0))
```

```output
125.0
115.0
110.0
```

Each call supplies as many arguments as it needs; the rest take the defaults.

### Example 3: Keyword arguments

```python run
def total(price, tax=0.2, shipping=5):
    return round(price * (1 + tax) + shipping, 2)

print(total(100, shipping=0))
print(total(shipping=0, price=100, tax=0.1))
print(total(50, tax=0.0))
```

```output
120.0
110.0
55.0
```

The first call skips `tax` and overrides only `shipping`, which is awkward with positional arguments alone. The second call shows that keyword order does not matter.

### Example 4: The mutable default trap and its fix

```python run
def bad_add(item, items=[]):
    items.append(item)
    return items

def good_add(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items

print(bad_add("a"))
print(bad_add("b"))
print(good_add("a"))
print(good_add("b"))
```

```output
['a']
['a', 'b']
['a']
['b']
```

`bad_add` reused one list across calls. `good_add` creates a new list each time because the default is `None`.

### Example 5: *args and **kwargs

```python run
def average(*numbers):
    if not numbers:
        return None
    return sum(numbers) / len(numbers)

def describe(**fields):
    parts = []
    for key in sorted(fields):
        parts.append(f"{key}={fields[key]}")
    return ", ".join(parts)

print(average(4, 8, 6))
print(average())
print(describe(name="Ada", age=36, city="London"))
print(describe())
values = [10, 20, 60]
print(average(*values))
options = {"city": "Paris", "name": "Bo"}
print(describe(**options))
```

```output
6.0
None
age=36, city=London, name=Ada

30.0
city=Paris, name=Bo
```

Inside `average`, `numbers` is the tuple `(4, 8, 6)`. The last two calls unpack a list and a dictionary into the calls.

### Example 6: A flexible report function

A realistic function mixes every kind of parameter. It requires a title, accepts any number of values, and takes optional named settings with defaults.

```python run
def report(title, *values, decimals=1, unit="", **notes):
    """Return a one-line report of the values with optional notes."""
    total = sum(values)
    line = f"{title}: n={len(values)}, total={total:.{decimals}f}{unit}"
    for key in sorted(notes):
        line += f" [{key}: {notes[key]}]"
    return line

print(report("Sales", 120.5, 99.25, 80))
print(report("Sales", 120.5, 99.25, 80, decimals=2, unit=" EUR"))
print(report("Visits", 10, 20, source="web", region="EU"))
print(report("Empty"))
```

```output
Sales: n=3, total=299.8
Sales: n=3, total=299.75 EUR
Visits: n=2, total=30.0 [region: EU] [source: web]
Empty: n=0, total=0.0
```

Parameters after `*values` can only be given by keyword, so `decimals` and `unit` cannot be filled by accident with a value meant for `values`. The nested `{decimals}` inside the format spec takes the precision from the variable.

## Real-world applications

- **Configurable cleaning functions.** `clean(text, lower=True, strip=True)` has sensible defaults and lets callers override one option by name.
- **Flexible aggregation.** A function with `*values` works for two numbers or two hundred without building a list first.
- **Passing options through.** `**kwargs` lets a wrapper function forward settings to another function, a pattern used heavily in data libraries.
- **Avoiding hidden state.** Understanding scope prevents bugs where a function silently changes a value used somewhere else in a pipeline.

## Daily review

### Key takeaways

- A function reads from local scope first, then global; assigning to a name makes it local unless `global` is used.
- Prefer parameters and `return` over `global`.
- Defaults are evaluated once at definition; never use a list or dictionary as a default, use `None`.
- Keyword arguments are matched by name and come after positional ones in a call.
- `*args` is a tuple, `**kwargs` is a dictionary; `*` and `**` also unpack in a call.

### Common mistakes

- **Expecting an assignment inside a function to change a global.** The global stays the same. Return the value and assign it outside.
- **`UnboundLocalError`.** `count += 1` inside a function where `count` is global gives `UnboundLocalError: cannot access local variable 'count' where it is not associated with a value`. Pass `count` in and return it.
- **Mutable default argument.** The list persists between calls, so results grow. Use `None` and create the list inside.
- **Default parameter before a non-default one.** `def f(a=1, b):` is `SyntaxError: non-default argument follows default argument`.
- **Giving a parameter twice.** `total(100, price=50)` raises `TypeError: total() got multiple values for argument 'price'`.
- **Forgetting that `*args` is a tuple.** `args.append(x)` fails with `AttributeError`. Convert with `list(args)`.

### Revision notes

- Local first, then global; `global` is a last resort.
- `def f(a, b=1, *args, **kwargs)` order.
- Defaults evaluated once; `None` for mutable defaults.
- `f(*seq)` and `f(**mapping)` unpack in the call.
