## Objectives

- Explain what a date table must provide for time intelligence functions to work.
- Write measures for year-to-date, previous month, same period last year and rolling three months.
- Compute year-on-year and month-on-month growth as a measure with `DIVIDE`.
- Describe each time intelligence function as a change to the date filter inside `CALCULATE`.
- Reproduce YTD, shifts and rolling sums with `cumsum`, `shift` and `rolling` in pandas.

## Understand

### Time intelligence is CALCULATE with dates

Day 130 showed that `CALCULATE` can replace a filter. **Time intelligence** is the same idea applied to the date filter. A matrix of months puts a filter on `Calendar[date]` in each cell: the cell for March 2025 sees the dates 1 to 31 March. "Same period last year" means the same set of dates moved back one year; "year to date" means all dates from 1 January up to the end of that selection. The time intelligence functions compute those altered sets of dates, and `CALCULATE` applies them to a measure such as `[Total Revenue]`. Nothing new happens to the sales: only the dates that are allowed to be visible change.

### What the date table must satisfy

These functions look at the `Calendar` table, not at `Sales[order_date]`, which is why Day 128 made the calendar. It needs a column of type date with one row per day, no gaps and no duplicates, and the calendar must cover whole years. It is related to `Sales[order_date]` and marked as the date table in the model, so that Power BI knows which column holds the dates. If the calendar misses days, "previous month" and "same period last year" return wrong or empty ranges. For same-period-last-year to show anything, the calendar and the sales must also contain the earlier year. The sample sales cover only 2025, so this lesson adds 2024: it takes the same 400 orders one year earlier with the quantity halved (rounded up), and the calendar runs from 1 January 2024 to 31 December 2025.

### Year to date

`TOTALYTD(<measure>, Calendar[date])` evaluates a measure over all dates from the start of the year to the last date visible in the cell. In the cell for March 2025 the revenue covers January to March 2025. It resets at the start of each year. The long form, `CALCULATE([Total Revenue], DATESYTD(Calendar[date]))`, does the same and makes the mechanism visible: `DATESYTD` returns the set of dates, `CALCULATE` replaces the date filter with it. The pandas picture is a cumulative sum inside each year.

### Previous period and same period last year

`PREVIOUSMONTH(Calendar[date])` returns the dates of the month before the first visible date; `PREVIOUSQUARTER` and `PREVIOUSYEAR` work in the same way. `SAMEPERIODLASTYEAR(Calendar[date])` shifts the visible dates back by exactly one year. In a monthly matrix, March 2025 gives March 2024. Both go inside `CALCULATE`:

```dax
Revenue PM = CALCULATE([Total Revenue], PREVIOUSMONTH(Calendar[date]))
Revenue SPLY = CALCULATE([Total Revenue], SAMEPERIODLASTYEAR(Calendar[date]))
```

The pandas equivalents are `shift(1)` and `shift(12)` on a monthly series, which assume the months are consecutive and complete, the same condition the date table guarantees. Growth is then built from two measures: `YoY % = DIVIDE([Total Revenue] - [Revenue SPLY], [Revenue SPLY])`. The `DIVIDE` returns blank for the first year in the data, where there is no prior value, instead of an error.

### Rolling periods

A **rolling** (moving) period always covers the same length, such as the last three months, and moves with the cell. `DATESINPERIOD(Calendar[date], <end date>, <number>, <interval>)` returns the dates counted back from an end date; a negative number means backwards.

```dax
Revenue Rolling 3M =
CALCULATE(
    [Total Revenue],
    DATESINPERIOD(Calendar[date], MAX(Calendar[date]), -3, MONTH)
)
```

`MAX(Calendar[date])` is the last date visible in the cell, here the last day of the month, so the window is that month and the two before it. A rolling window smooths seasonality and noise and is a typical trend line. In pandas it is `rolling(3).sum()`. Notice that for January 2025 the window reaches into November and December 2024, so the earlier year must exist in the model.

### Reading the results carefully

Three habits keep time measures honest. First, check the grain: `PREVIOUSMONTH` is meaningful in a month matrix, but on a card with no date filter the "last visible date" is the end of the whole calendar, so the card compares the final month of the data with the month before it, which is rarely what the reader assumes. Put a date slicer on such pages or state the period in the title. Second, check the first period: the first month in the data has no previous month, so a growth measure is blank there, and a chart showing blank is correct; do not replace it with zero, which would read as a collapse. Third, check completeness: if the current month is only half over, its YTD and its growth against a full previous month are not comparable, so many reports compare to the same day range or show "month to date" labels. A fiscal year that does not end in December changes the year-to-date reset point; `TOTALYTD` takes an optional year-end argument for that, and the fiscal calendar column from Day 128 is the safer way to model it.

### Why it matters

Almost every business question is relative: against last month, last year, the year so far. If the measure is built on `CALCULATE` with the date table, the same measure works in a month matrix, a quarter chart and a card with a date slicer. The misconceptions are to filter `Sales[order_date]` instead of `Calendar[date]` (the time intelligence functions then do nothing useful), and to forget that a YTD or SPLY value in a cell with a partial period compares a partial period with a full one.

## Syntax and key functions

```dax
TOTALYTD(<expression>, <dates>)
CALCULATE(<expression>, DATESYTD(<dates>))
CALCULATE(<expression>, PREVIOUSMONTH(<dates>))
CALCULATE(<expression>, SAMEPERIODLASTYEAR(<dates>))
CALCULATE(<expression>, DATESINPERIOD(<dates>, <end date>, <n>, <interval>))
```

`<dates>` is the date column of the marked date table.

| Function | Returns |
|---|---|
| `TOTALYTD(expr, dates)` | The expression evaluated from 1 January to the last visible date. |
| `DATESYTD(dates)` | The set of dates from the start of the year to the last visible date. |
| `PREVIOUSMONTH(dates)` | The dates of the month before the first visible date. |
| `SAMEPERIODLASTYEAR(dates)` | The visible dates shifted back one year. |
| `DATESINPERIOD(dates, end, n, interval)` | A window of `n` intervals ending at `end` (negative `n` goes back). |
| `DIVIDE(a, b)` | The ratio, blank when `b` is zero or blank. |

The pandas equivalents on a monthly Series `monthly`:

```python
monthly.groupby(monthly.index.year).cumsum()   # YTD
monthly.shift(1)                               # previous month
monthly.shift(12)                              # same month last year
monthly.rolling(3).sum()                       # rolling 3 months
```

### Example 1: The monthly series and the extended model

Build monthly revenue for 2024 and 2025 from the extended data and print the first six months of 2025.

```python run
import numpy as np
import pandas as pd

rng = np.random.default_rng(7)
countries = ["UK", "Germany", "France", "Spain"]
cats = ["Hardware", "Software", "Services"]
customers = pd.DataFrame({
    "customer_id": range(1, 41),
    "customer_name": [f"Customer {i:02d}" for i in range(1, 41)],
    "country": [countries[i % 4] for i in range(40)],
    "segment": [["Retail", "Corporate"][(i // 4) % 2] for i in range(40)],
})
products = pd.DataFrame({
    "product_id": range(1, 13),
    "product_name": [f"Product {i:02d}" for i in range(1, 13)],
    "category": [cats[i % 3] for i in range(12)],
    "unit_cost": [float(10 + 5 * i) for i in range(12)],
})
n = 400
sales = pd.DataFrame({
    "order_id": range(1, n + 1),
    "order_date": pd.to_datetime("2025-01-01") + pd.to_timedelta(rng.integers(0, 365, n), unit="D"),
    "customer_id": rng.integers(1, 41, n),
    "product_id": rng.integers(1, 13, n),
    "quantity": rng.integers(1, 6, n),
})
sales["unit_price"] = (sales["product_id"].map(products.set_index("product_id")["unit_cost"]) * 1.5).round(2)
calendar = pd.DataFrame({"date": pd.date_range("2025-01-01", "2025-12-31")})
calendar["year"] = calendar["date"].dt.year
calendar["quarter"] = calendar["date"].dt.quarter
calendar["month_number"] = calendar["date"].dt.month
calendar["month_name"] = calendar["date"].dt.strftime("%B")
sales["revenue"] = sales["quantity"] * sales["unit_price"]
fact = (sales.merge(customers, on="customer_id").merge(products, on="product_id")
        .merge(calendar, left_on="order_date", right_on="date"))
s24 = sales.copy()
s24["order_date"] = s24["order_date"] - pd.DateOffset(years=1)
s24["quantity"] = (s24["quantity"] + 1) // 2
s24["revenue"] = s24["quantity"] * s24["unit_price"]
both = pd.concat([s24, sales], ignore_index=True)
monthly = both.groupby(both["order_date"].dt.to_period("M"))["revenue"].sum()
print(len(both), round(float(both["revenue"].sum()), 2))
print(monthly["2025-01":"2025-06"].round(2).to_string())
```

```output
800 107647.5
order_date
2025-01    5160.0
2025-02    5475.0
2025-03    4627.5
2025-04    5280.0
2025-05    5512.5
2025-06    6045.0
Freq: M
```

The extended data holds 800 order rows. March 2025 revenue is 4,627.50 and the matrix cell for March 2025 shows exactly this number. Every other measure in the lesson is computed from this series.

## Real-world applications

- **Executive trend cards.** A card shows `Revenue YTD` and its growth against last year's YTD, the standard board-pack number (Examples 2 and 4).
- **Trend charts.** A line of `Revenue Rolling 3M` over monthly revenue removes seasonal noise so a decline or a recovery is visible (Example 5).
- **Monthly review.** An operations page shows revenue, previous month and the percentage change next to each other (Example 3).
- **Seasonal retail.** A year-on-year view compares the same month in two years, which avoids reading a December peak as growth (Example 4).

## Daily review

### Key takeaways

- Time intelligence changes the filter on the `Calendar` date column inside `CALCULATE`.
- The calendar must be a complete, continuous date table that is marked as the date table, and it must contain the earlier periods.
- `TOTALYTD`, `PREVIOUSMONTH`, `SAMEPERIODLASTYEAR` and `DATESINPERIOD` each return a set of dates.
- Growth is `DIVIDE` of the difference by the earlier value, so a missing earlier value gives blank.
- pandas: `cumsum` within a year, `shift`, `rolling`.

### Common mistakes

- Using `Sales[order_date]` instead of `Calendar[date]` in the function, which gives wrong or unchanged results.
- A calendar with gaps or missing years, so the previous period is empty or short.
- Reading a YTD, SPLY or growth number for the current, incomplete month as if it were a full period.
- Dividing by the previous value with `/` and getting an error at the first period; use `DIVIDE`.
- Using `shift(12)` on a monthly series with a missing month in pandas, which silently compares the wrong months. Reindex to complete months first.

### Revision notes

- Date table: continuous, whole years, marked, related to the fact.
- `TOTALYTD` / `DATESYTD`; `PREVIOUSMONTH`; `SAMEPERIODLASTYEAR`; `DATESINPERIOD(dates, end, -n, MONTH)`.
- Growth = `DIVIDE(current - prior, prior)`.
- pandas: `groupby(year).cumsum()`, `shift(1)`, `shift(12)`, `rolling(3).sum()`.
