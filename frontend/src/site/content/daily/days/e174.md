## Objectives

- Read every page of a paginated JSON API with a loop that stops on `total_pages`, and explain why page-number loops need a stop condition.
- Read the API key from the environment, mask it in logs and fail clearly when it is missing or wrong.
- Retry a rate-limited request using the server's wait time and an exponential back-off, and give up with a clear error after a limit.
- Ingest the customers CSV and land both sources as raw rows, so that running the same batch twice leaves the same row counts.
- Check the stage with numbers: pages, calls, rate-limited calls, records and landed rows.

## Understand

### The ingestion stage and its contract

Day 173 scoped the capstone. This day builds its first stage, **ingestion**: getting the data out of the sources and into your own storage, with as little change as possible. The stage has one contract: after it runs, the **raw layer** holds every record the sources returned, exactly as returned, tagged with the batch it came from. Cleaning happens on Day 175, never here. Keeping the raw copy untouched means that when a cleaning rule turns out to be wrong you can fix it and replay from the raw layer without calling the API again, which matters when the API is slow, rate-limited or paid per call.

### Pagination

An API that returns 120 orders does not send them in one response. It sends **pages**: `GET /orders?page=N&page_size=P` returns `{"data": [...], "page": N, "total_pages": T}`. The client loops from page 1 and stops after page T. Two mistakes are common. Stopping when a page comes back shorter than `page_size` fails when the last page is exactly full or when a page is short for another reason; trusting `total_pages` is more reliable. Looping a fixed number of times silently drops data when the source grows. With 120 records and a page size of 25 the loop makes 5 calls, and the last page holds 20 records.

### Credentials

The API wants an `X-Api-Key` header. A key is a secret, so it is read from the **environment** (`os.environ`), never written in the source code and never printed. If it is missing the program should stop at start with a message naming the variable, not fail later with an unclear 401. When you must log it, print a masked form such as the first two characters followed by stars. Committing a key to Git, which Day 179 revisits, is a leak that stays in the history.

### Rate limits and retries

A server protects itself by answering **429 Too Many Requests**, usually with a `Retry-After` header that says how many seconds to wait. A pipeline that treats 429 as a fatal error fails nightly; one that retries without waiting makes the problem worse. The standard answer is **retry with exponential back-off**: wait the time the server asked for, and double the wait after each further failure of the same request, up to a limited number of tries. After the limit the code raises an error that names the page, because an endless retry loop hides an outage. Retry only errors that can recover: 429 and temporary server errors. Retrying a 401 never helps.

In this capstone the stand-in API answers 429 on every third call, with a wait of 2 seconds. The code calls a `sleep` function that is passed in, so the examples can record the waits instead of waiting.

### Landing raw data and idempotency

The raw layer is a table with one row per record: the batch id, the position and the payload as JSON text. An **idempotent** load gives the same result when run twice. Appending on every run would double the table; instead the load deletes the rows of that batch and inserts them again inside one transaction, so a crash in the middle leaves either the old batch or the new one.

### Common misconception

Learners test with a small page and a happy path. The failures that matter appear only in production: the third call is limited, the key has expired, the last page is short. The stand-in here fails on purpose so that the code is tested against them.

### Why it matters

Most pipeline outages are ingestion outages. A reliable, replayable raw layer is what lets every later stage be rebuilt.

## Syntax and key functions

The stand-in API and the pagination loop:

```python
body = api(page, page_size, {"X-Api-Key": key})   # {"data": [...], "page": 1, "total_pages": 5}
while page <= body["total_pages"]: ...
```

Retry with back-off:

```python
for attempt in range(max_tries):
    try:
        return call()
    except RateLimited as e:
        sleep(e.retry_after * 2 ** attempt)
raise RuntimeError("giving up")
```

Real HTTP with `requests` (shown in Example 4 against a local server):

```python
r = requests.get(url, params={"page": 1, "page_size": 25}, headers={"X-Api-Key": key}, timeout=5)
r.status_code, r.headers.get("Retry-After"), r.json()
```

| Item | What it does or returns |
|---|---|
| `os.environ.get("NAME")` | The variable's value, or `None` when it is not set. |
| `total_pages` | The stop condition of the page loop. |
| `Retry-After` | Seconds the server asks the client to wait after a 429. |
| `retry_after * 2 ** attempt` | Wait for the first, second, third retry: x, 2x, 4x. |
| `csv.DictReader(io.StringIO(text))` | Yields one dict per CSV row, keyed by the header. |
| `INSERT ... ` after `DELETE` in one `with conn:` | Replaces a batch atomically. |

## Learn by example

### Example 1: Paginate the stand-in API

The stand-in function replaces the network: it takes the page, the page size and the headers and returns the same JSON the real endpoint would. This version has no rate limit yet. The loop stops on `total_pages`, so it makes exactly five calls. A wrong key raises an error before any data is returned.

```python run
import random
from datetime import date, timedelta

COUNTRIES = ["DE", "FR", "IN", "US", "BR"]
CATEGORIES = ["tools", "books", "games"]

def generate(seed=7):
    """Seeded stand-in data: customers, products and 120 raw order records with planted defects."""
    rng = random.Random(seed)
    customers = [(f"C{n:03d}", f"Customer {n:02d}", COUNTRIES[n % 5]) for n in range(1, 21)]
    products = [(f"P{n:02d}", f"Product {n:02d}", CATEGORIES[n % 3]) for n in range(1, 9)]
    price = {pid: 500 * (i + 1) for i, (pid, _, _) in enumerate(products)}
    orders = []
    for n in range(1, 121):
        pid = products[rng.randrange(8)][0]
        qty = rng.randint(1, 4)
        day = date(2026, 1, 1) + timedelta(days=(n - 1) * 89 // 119)
        orders.append({
            "order_id": f"O{n:04d}", "customer_id": customers[rng.randrange(20)][0], "product_id": pid,
            "quantity": qty, "amount_cents": price[pid] * qty, "currency": "EUR",
            "status": rng.choices(["paid", "refunded", "failed"], weights=[8, 1, 1])[0],
            "created_at": f"{day}T{(n * 7) % 24:02d}:{(n * 13) % 60:02d}:00Z",
        })
    orders[29]["amount_cents"] = -1000
    orders[44]["customer_id"] = "C999"
    orders[59]["created_at"] = ""
    orders[74]["currency"] = "???"
    orders[104]["status"] = "pending"
    orders[119] = dict(orders[9])
    return customers, products, orders

def get_orders(page, page_size, headers):
    if headers.get("X-Api-Key") != "secret-key":
        raise PermissionError("401 invalid API key")
    start = (page - 1) * page_size
    return {"data": ORDERS[start:start + page_size], "page": page, "total_pages": -(-len(ORDERS) // page_size)}

customers, products, ORDERS = generate()
records, page, total, calls = [], 1, 1, 0
while page <= total:
    body = get_orders(page, 25, {"X-Api-Key": "secret-key"})
    calls += 1
    records.extend(body["data"])
    total = body["total_pages"]
    page += 1
print("calls:", calls, "records:", len(records), "last page size:", len(body["data"]))
try:
    get_orders(1, 25, {"X-Api-Key": "wrong"})
except PermissionError as e:
    print("error:", e)
```

```output
calls: 5 records: 120 last page size: 20
error: 401 invalid API key
```

### Example 2: Retry on 429 with back-off

Now the stand-in answers 429 on every third call. `fetch_page` catches the rate-limit error, waits `retry_after * 2 ** attempt` seconds through the `sleep` function it was given (here a list append, so nothing really waits) and calls again. Pages 3 and 5 each hit the limit once, so there are 7 calls for 5 pages, two waits of 2 seconds, and all 120 records arrive. The last lines show the give-up path: an API that always answers 429 raises an error that names the page.

```python run
import random
from datetime import date, timedelta

COUNTRIES = ["DE", "FR", "IN", "US", "BR"]
CATEGORIES = ["tools", "books", "games"]

def generate(seed=7):

    rng = random.Random(seed)
    customers = [(f"C{n:03d}", f"Customer {n:02d}", COUNTRIES[n % 5]) for n in range(1, 21)]
    products = [(f"P{n:02d}", f"Product {n:02d}", CATEGORIES[n % 3]) for n in range(1, 9)]
    price = {pid: 500 * (i + 1) for i, (pid, _, _) in enumerate(products)}
    orders = []
    for n in range(1, 121):
        pid = products[rng.randrange(8)][0]
        qty = rng.randint(1, 4)
        day = date(2026, 1, 1) + timedelta(days=(n - 1) * 89 // 119)
        orders.append({
            "order_id": f"O{n:04d}", "customer_id": customers[rng.randrange(20)][0], "product_id": pid,
            "quantity": qty, "amount_cents": price[pid] * qty, "currency": "EUR",
            "status": rng.choices(["paid", "refunded", "failed"], weights=[8, 1, 1])[0],
            "created_at": f"{day}T{(n * 7) % 24:02d}:{(n * 13) % 60:02d}:00Z",
        })
    orders[29]["amount_cents"] = -1000
    orders[44]["customer_id"] = "C999"
    orders[59]["created_at"] = ""
    orders[74]["currency"] = "???"
    orders[104]["status"] = "pending"
    orders[119] = dict(orders[9])
    return customers, products, orders

class RateLimited(Exception):
    def __init__(self, retry_after):
        super().__init__("429 too many requests")
        self.retry_after = retry_after

class Unauthorized(Exception):
    pass

def make_api(orders, api_key="secret-key", every=3):
    """Stand-in for GET /orders?page=N&page_size=P: no network, same answers (200, 401, 429)."""
    state = {"calls": 0, "limited": 0}
    def get_orders(page, page_size, headers):
        state["calls"] += 1
        if headers.get("X-Api-Key") != api_key:
            raise Unauthorized("401 invalid API key")
        if every and state["calls"] % every == 0:
            state["limited"] += 1
            raise RateLimited(2)
        total = -(-len(orders) // page_size)
        start = (page - 1) * page_size
        return {"data": orders[start:start + page_size], "page": page, "total_pages": total}
    return get_orders, state

def fetch_page(api, page, size, headers, sleep, max_tries=5):
    for attempt in range(max_tries):
        try:
            return api(page, size, headers)
        except RateLimited as e:
            sleep(e.retry_after * 2 ** attempt)
    raise RuntimeError(f"page {page} still rate limited after {max_tries} tries")

def fetch_all(api, headers, sleep, size=25):
    records, page, total = [], 1, 1
    while page <= total:
        body = fetch_page(api, page, size, headers, sleep)
        records.extend(body["data"])
        total = body["total_pages"]
        page += 1
    return records

customers, products, orders = generate()
api, state = make_api(orders, every=3)
waits = []
records = fetch_all(api, {"X-Api-Key": "secret-key"}, waits.append)
print("records:", len(records), "calls:", state["calls"], "rate limited:", state["limited"], "waits:", waits)

always, _ = make_api(orders, every=1)
try:
    fetch_page(always, 1, 25, {"X-Api-Key": "secret-key"}, waits.append, max_tries=3)
except RuntimeError as e:
    print("error:", e)
print("waits so far:", waits)
```

```output
records: 120 calls: 7 rate limited: 2 waits: [2, 2]
error: page 1 still rate limited after 3 tries
waits so far: [2, 2, 2, 4, 8]
```

### Example 3: Credentials from the environment

The key comes from `os.environ`. The helper stops at start when the variable is missing, with a message that names the variable but never contains a key, and the log line shows only a masked key. The example sets the variable inside the code to simulate your shell; on your computer you would run `export DATAFORGE_API_KEY=...` before the program.

```python run
import os

def load_key(name="DATAFORGE_API_KEY"):
    key = os.environ.get(name)
    if not key:
        raise SystemExit(f"missing environment variable {name}")
    return key

def mask(key):
    return key[:2] + "*" * (len(key) - 2)

try:
    load_key()
except SystemExit as e:
    print("startup error:", e)
os.environ["DATAFORGE_API_KEY"] = "secret-key"
key = load_key()
print("using key:", mask(key))
print("header names only:", sorted({"X-Api-Key": key}))
```

```output
startup error: missing environment variable DATAFORGE_API_KEY
using key: se********
header names only: ['X-Api-Key']
```

### Example 4: The same loop over real HTTP

This example starts a throwaway `http.server` on `127.0.0.1` in a thread and calls it with `requests`, so the page loop, the key header, the 429 with `Retry-After` and the retry are real HTTP. The server answers 429 on every third request. It runs only on your own computer (the browser has no sockets), so it is shown with its verified output.

```python local
import json
import threading
from http.server import BaseHTTPRequestHandler, HTTPServer
from urllib.parse import parse_qs, urlparse
import requests

import random
from datetime import date, timedelta

COUNTRIES = ["DE", "FR", "IN", "US", "BR"]

        day = date(2026, 1, 1) + timedelta(days=(n - 1) * 89 // 119)
        orders.append({

            "quantity": qty, "amount_cents": price[pid] * qty, "currency": "EUR",
            "status": rng.choices(["paid", "refunded", "failed"], weights=[8, 1, 1])[0],
            "created_at": f"{day}T{(n * 7) % 24:02d}:{(n * 13) % 60:02d}:00Z",
        })
    orders[29]["amount_cents"] = -1000
    orders[44]["customer_id"] = "C999"
    orders[59]["created_at"] = ""
    orders[74]["currency"] = "???"
    orders[104]["status"] = "pending"
    orders[119] = dict(orders[9])
    return customers, products, orders

customers, products, orders = generate()
hits = {"n": 0}

class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        hits["n"] += 1
        if self.headers.get("X-Api-Key") != "secret-key":
            self.send_response(401); self.end_headers(); return
        if hits["n"] % 3 == 0:
            self.send_response(429); self.send_header("Retry-After", "2"); self.end_headers(); return
        q = parse_qs(urlparse(self.path).query)
        page, size = int(q["page"][0]), int(q["page_size"][0])
        body = json.dumps({"data": orders[(page - 1) * size:page * size], "page": page, "total_pages": -(-len(orders) // size)}).encode()
        self.send_response(200); self.send_header("Content-Type", "application/json"); self.end_headers(); self.wfile.write(body)
    def log_message(self, *args):
        pass

server = HTTPServer(("127.0.0.1", 0), Handler)
threading.Thread(target=server.serve_forever, daemon=True).start()
url = f"http://127.0.0.1:{server.server_port}/orders"
waits, records, page, total = [], [], 1, 1
while page <= total:
    r = requests.get(url, params={"page": page, "page_size": 25}, headers={"X-Api-Key": "secret-key"}, timeout=5)
    if r.status_code == 429:
        waits.append(int(r.headers["Retry-After"]))
        continue
    r.raise_for_status()
    body = r.json()
    records.extend(body["data"])
    total, page = body["total_pages"], page + 1
bad = requests.get(url, params={"page": 1, "page_size": 25}, headers={"X-Api-Key": "nope"}, timeout=5)
server.shutdown()
server.server_close()
print("records:", len(records), "requests:", hits["n"], "waits:", waits, "wrong key status:", bad.status_code)
```

```output
records: 120 requests: 8 waits: [2, 2] wrong key status: 401
```

### Example 5: Ingest both sources and land them twice

The customers CSV is read with `csv.DictReader` after a header check. Orders are fetched through the retrying loop and both sources are landed in raw tables. `land` replaces a batch inside one transaction, so landing batch `b1` twice leaves 120 rows, and landing a second batch `b2` adds 120 more. The raw payload is the JSON text of the record, unchanged, including the defective records.

## Real-world applications

- **Nightly API extracts.** The retry loop of Example 2 is what keeps a nightly job from failing on a rate limit; the number of waits is a metric worth logging.
- **Secrets handling.** Example 3's pattern (environment variable, fail at start, masked log) is how connection strings and API keys are handled in schedulers and CI.
- **Replayable pipelines.** The raw layer of Example 5 lets you rerun cleaning after a bug fix without calling the source again.
- **Contract tests against fake services.** The local server of Example 4 lets you test 401 and 429 paths that a real vendor would never produce on demand.

## Daily review

### Key takeaways

- Loop over pages until `total_pages`; do not guess from short pages or fixed counts.
- Read secrets from the environment, fail at start if absent, never print them whole.
- Retry only recoverable errors, honour `Retry-After`, back off exponentially, and stop after a limit with a clear error.
- Land raw data unchanged with a batch id and replace batches atomically so re-runs are idempotent.
- Check ingestion with numbers: 5 pages, 7 calls with two 429s, 120 records, 120 rows per batch.

### Common mistakes

- Appending on every run, so the raw table doubles. Delete the batch and insert in one transaction.
- Retrying in a tight loop without waiting, which keeps the 429 coming. Sleep first.
- Retrying forever. Add a maximum number of tries and raise an error naming the page.
- Retrying a 401, which never recovers. Retry only 429 and temporary 5xx.
- Cleaning while ingesting, so the original values are lost and bugs cannot be replayed.
- Printing the whole header dictionary, which leaks the key into the logs.

### Revision notes

- Page loop: start at 1, stop after `total_pages`; 120 records at 25 per page is 5 calls.
- Back-off: `retry_after * 2 ** attempt`, with a `max_tries`.
- Key: `os.environ.get`, stop at start if missing, mask when logging.
- Batch landing: `DELETE` the batch then `INSERT`, in one `with conn:`.
