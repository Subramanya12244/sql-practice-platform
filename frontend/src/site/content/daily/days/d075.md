## Objectives

- Find repeated rows and repeated keys with `duplicated()`, and choose which copy counts as the duplicate with `subset` and `keep`.
- Remove duplicates with `drop_duplicates()` and explain why you must decide what "the same record" means first.
- Convert column types with `astype`, and convert text to numbers safely with `pd.to_numeric(..., errors="coerce")`.
- Use the categorical dtype for columns with a few repeated labels, and read its `categories` and `codes`.
- Check types with `pd.api.types` predicates instead of printing type names.

## Understand

### Why duplicates happen

A **duplicate** is a record that appears more than once in a table. Duplicates come from systems that send the same event twice, from files appended together twice, from joins that multiply rows, and from people who enter the same customer under slightly different spellings. They are harmful because they inflate counts and totals: if an order appears twice, revenue is overstated. They are also not always errors. Two rows with the same customer and the same product may be two real purchases. So the first question is always: **what makes two rows "the same record"?** In some tables it is the whole row, in others a key such as an order id or the pair (customer, date).

### Finding duplicates: duplicated

`df.duplicated()` returns a boolean Series with one value per row: `True` when the row is a repeat of an **earlier** row (all columns equal). The first occurrence is `False`, and the later copies are `True`. This default is `keep="first"`. `keep="last"` marks all but the last occurrence instead, and `keep=False` marks **every** member of a duplicated group, including the first, which is the way to display all the rows involved. `subset=["id"]` limits the comparison to chosen columns: two rows with the same id count as duplicates even if their other columns differ.

Since `True` counts as 1, `df.duplicated().sum()` is the number of surplus rows, and `df[df.duplicated(subset=["id"], keep=False)]` shows all rows that share an id, which you should read before deciding what to do. Exact duplicates are the easy case. Near-duplicates, such as `Ana` and `ana ` or `C` and `c`, are not found because the values differ, so clean the text first (the next lesson covers the text tools) or compare on a cleaned key.

### Removing duplicates: drop_duplicates

`df.drop_duplicates()` returns a new table without the repeated rows, keeping the first occurrence by default. It has the same `subset` and `keep` arguments. `df.drop_duplicates(subset=["id"], keep="last")` keeps the last row for each id, which is the right choice when later rows are updates of earlier ones. The row labels of the kept rows are unchanged, so you may want `reset_index(drop=True)` afterwards. As with every pandas method it returns a new table, so store the result.

Think before removing. If duplicates differ in a column such as the date or amount, dropping by key keeps one version and silently discards the other, so decide which one is correct (the newest? the largest?) and sort accordingly before you drop. If you do not know why the duplicates exist, report the count rather than removing them.

### Converting types: astype

`df["qty"].astype(float)` returns a new column converted to decimals, `astype(str)` converts to text, `astype(bool)` to booleans. Converting a decimal to an integer with `astype(int)` truncates towards zero (1.9 becomes 1), just like NumPy on Day 63, and it fails with an error if the column contains missing values, because an ordinary integer column cannot hold `NaN`. Converting text that is not a number with `astype(int)` raises a `ValueError`. To convert and keep the result, assign it back: `df["qty"] = df["qty"].astype(float)`.

### Text to numbers: to_numeric

Data read from files often has numbers stored as text, as in Day 70's column with the word `ten`. `pd.to_numeric(series)` converts text to numbers and raises a `ValueError` at the first value it cannot read. The argument `errors="coerce"` instead turns unreadable values into `NaN`, so the conversion succeeds and the problems become visible as missing values: count them with `isna().sum()` and look at the original text to decide what to do. The result of a conversion with gaps is a float column. `to_numeric` accepts surrounding spaces (`" 7 "` becomes 7), but not thousands separators or currency symbols such as `1,200` or `$5`; remove those characters from the text first (the next lesson shows how).

### Checking types

Printing a dtype shows names such as `int64`, `float64` and `object`, and the names depend on the platform and the pandas version. In code, ask yes/no questions with `pd.api.types`: `is_numeric_dtype(s)`, `is_integer_dtype(s)`, `is_float_dtype(s)`, `is_string_dtype(s)`, `is_datetime64_any_dtype(s)` and `isinstance(s.dtype, pd.CategoricalDtype)`. These predicates give the same answer everywhere.

### The categorical dtype

A column such as `city` or `status` has a few distinct labels repeated thousands of times. The **categorical** dtype stores each distinct label once, the **categories**, and stores each row as a small integer code that points to the category. Convert with `astype("category")`. Benefits: much less memory for long columns with few labels, a fixed list of allowed values, and the ability to define an order: `pd.Categorical(values, categories=["low", "mid", "high"], ordered=True)` makes `low < mid < high`, so sorting and `max` follow that order instead of alphabetical order. `s.cat.categories` lists the categories and `s.cat.codes` the codes. A value not in the categories becomes missing, which makes categorical columns a good guard against typos. The cost is that some operations need care, for example you cannot assign a new label that is not in the categories.

### The common misconception

Learners believe that `drop_duplicates()` finds duplicates in the real-world sense. It only finds identical values in the compared columns. Another is that `astype(int)` rounds, and that a column of numbers read from a file is numeric. If the file has one stray word, the whole column is text, and `astype(int)` stops with an error while `to_numeric(errors="coerce")` shows exactly which entries are bad.

### Why it matters in data work

Duplicates and wrong types cause the most common quiet errors: inflated totals, text that sorts as `"10" < "9"`, joins that fail because ids are text on one side and numbers on the other. Cleaning them is a routine step after inspection and missing-value handling. A reliable routine: find with `duplicated`, look at examples, decide on the key and the rule, drop, convert types with `to_numeric`, and check again with the predicates. Always compare the row count before and after and report it.

### Order of cleaning steps

The order matters. Convert types before comparing values (the text `"5"` and the number 5 are different), clean text before looking for duplicates (case and spaces), and handle missing values before changing a column to an integer type. Doing it in a different order tends to produce errors or hides duplicates, so write the order down when you document a cleaning script.

## Syntax and key functions

```python
df.duplicated(subset=None, keep="first")
df.drop_duplicates(subset=None, keep="first")
s.astype(float)
pd.to_numeric(s, errors="coerce")
s.astype("category")
s.cat.categories
s.cat.codes
pd.api.types.is_numeric_dtype(s)
```

| Expression | Returns |
|---|---|
| `df.duplicated()` | Boolean Series: True for repeats of an earlier row. |
| `keep="last"` / `keep=False` | Mark all but the last / mark every member of a duplicated group. |
| `subset=["id"]` | Compare only the listed columns. |
| `df.drop_duplicates()` | New table without repeated rows. |
| `s.astype(type)` | New column converted; `int` truncates; errors on gaps or bad text. |
| `pd.to_numeric(s, errors="coerce")` | Numbers, with `NaN` where text cannot be read. |
| `s.astype("category")` | Categorical column. |
| `s.cat.categories`, `s.cat.codes` | The labels; the integer code of each row. |
| `pd.api.types.is_numeric_dtype(s)` | `True` for numeric columns (also `is_integer_dtype`, `is_string_dtype`). |

## Learn by example

### Example 1: Finding duplicates

The default marks repeats of earlier rows. `subset` compares only chosen columns and `keep=False` marks every member of a group, which shows all the rows to inspect. The sum counts the surplus rows.

```python run
import pandas as pd

pd.set_option("display.width", 200)
pd.set_option("display.max_columns", 20)

df = pd.DataFrame({"id": [1, 2, 2, 3, 3], "name": ["a", "b", "b", "c", "C"], "v": [1.5, 2.0, 2.0, 3.0, 3.5]})
print(df.duplicated().tolist(), df.duplicated().sum())
print(df.duplicated(subset=["id"]).tolist())
print(df.duplicated(subset=["id"], keep="last").tolist())
print(df[df.duplicated(subset=["id"], keep=False)])
```

```output
[False, False, True, False, False] 1
[False, False, True, False, True]
[False, True, False, True, False]
   id name    v
1   2    b  2.0
2   2    b  2.0
3   3    c  3.0
4   3    C  3.5
```

### Example 2: Removing duplicates and choosing the survivor

By default the first row of each group is kept. `keep="last"` keeps the latest. To keep the largest value instead, sort before dropping. Row labels are unchanged until `reset_index`.

```python run
import pandas as pd

pd.set_option("display.width", 200)
pd.set_option("display.max_columns", 20)

df = pd.DataFrame({"id": [1, 2, 2, 3, 3], "name": ["a", "b", "b", "c", "C"], "v": [1.5, 2.0, 2.0, 3.0, 3.5]})
print(df.drop_duplicates())
print(df.drop_duplicates(subset=["id"], keep="last"))
best = df.sort_values("v", ascending=False, kind="stable").drop_duplicates(subset=["id"]).sort_index()
print(best["v"].tolist(), len(df), len(best))
print(df.drop_duplicates(subset=["id"]).reset_index(drop=True).index.tolist())
```

```output
   id name    v
0   1    a  1.5
1   2    b  2.0
3   3    c  3.0
4   3    C  3.5
   id name    v
0   1    a  1.5
2   2    b  2.0
4   3    C  3.5
[1.5, 2.0, 3.5] 5 3
[0, 1, 2]
```

### Example 3: astype and to_numeric

`astype` converts clean data, and truncates decimals when going to integers. Text with an invalid entry stops `to_numeric`, but with `errors="coerce"` the bad entry becomes `NaN` and can be counted. Predicates check the types.

```python run
import pandas as pd

f = pd.Series([1.9, 2.1, -0.5])
print(f.astype(int).tolist(), pd.api.types.is_integer_dtype(f.astype(int)))
print(pd.Series([1, 2]).astype(str).tolist(), pd.Series([1, 0]).astype(bool).tolist())

s = pd.Series(["3", "4.5", "x", " 7 "])
print(pd.api.types.is_numeric_dtype(s))
try:
    pd.to_numeric(s)
except ValueError:
    print("to_numeric stopped at the bad value")
n = pd.to_numeric(s, errors="coerce")
print(n.tolist(), pd.api.types.is_float_dtype(n), n.isna().sum())
print(s[n.isna()].tolist())
```

```output
[1, 2, 0] True
['1', '2'] [True, False]
False
to_numeric stopped at the bad value
[3.0, 4.5, nan, 7.0] True 1
['x']
```

### Example 4: Categorical columns

`astype("category")` stores each label once and each row as a code. An ordered categorical sorts by the defined order rather than alphabetically. A value outside the categories becomes missing.

```python run
import pandas as pd

c = pd.Series(["lo", "hi", "lo", "mid"]).astype("category")
print(c.cat.categories.tolist(), c.cat.codes.tolist())
print(isinstance(c.dtype, pd.CategoricalDtype), pd.api.types.is_string_dtype(pd.Series(["a"])))
print(c.value_counts().sort_index().to_dict())

size = pd.Series(pd.Categorical(["lo", "hi", "lo", "mid"], categories=["lo", "mid", "hi"], ordered=True))
print(size.sort_values(kind="stable").tolist(), size.max())
print(sorted(["lo", "hi", "lo", "mid"]))

typo = pd.Series(pd.Categorical(["lo", "hgh", "mid"], categories=["lo", "mid", "hi"]))
print(typo.isna().tolist())

long = pd.Series(["north", "south"] * 500)
print(long.memory_usage(deep=True) > long.astype("category").memory_usage(deep=True))
```

```output
['hi', 'lo', 'mid'] [1, 0, 1, 2]
True True
{'hi': 1, 'lo': 2, 'mid': 1}
['lo', 'lo', 'mid', 'hi'] hi
['hi', 'lo', 'lo', 'mid']
[False, True, False]
True
```

### Example 5: A cleaning routine in the right order

A small orders table has text amounts with a bad entry and two orders that are repeated exactly. The steps run in the order that works: convert the types first (so that text amounts compare as numbers), then drop duplicates, then report before and after.

```python run
import pandas as pd

pd.set_option("display.width", 200)
pd.set_option("display.max_columns", 20)

raw = pd.DataFrame({"order": [101, 102, 102, 103, 104, 104],
                    "customer": ["Ana", "Ben", "Ben", "Cy", "Di", "Di"],
                    "amount": ["10.5", "20", "20", "n/a", "7.25", "7.25"]})
step = raw.assign(amount=pd.to_numeric(raw["amount"], errors="coerce"))
print(step.duplicated().sum(), step.duplicated(subset=["order"]).sum())
clean = step.drop_duplicates().reset_index(drop=True)
print(clean)
print(len(raw), len(clean), int(clean["amount"].isna().sum()))
print(pd.api.types.is_float_dtype(clean["amount"]), round(clean["amount"].sum(), 2))
```

```output
2 2
   order customer  amount
0    101      Ana   10.50
1    102      Ben   20.00
2    103       Cy     NaN
3    104       Di    7.25
6 4 1
True 37.75
```

## Real-world applications

- **Protecting totals.** Finding and removing repeated events, as in Examples 1, 2 and 5, keeps counts and revenue from being inflated by double deliveries.
- **Keeping the latest version.** `drop_duplicates(subset=key, keep="last")` keeps the newest update of each record in an append-only log.
- **Fixing columns that arrive as text.** `to_numeric(errors="coerce")`, as in Examples 3 and 5, converts the readable values and points to the bad ones.
- **Efficient labels.** Categorical columns, as in Example 4, save memory in large tables and define sort orders such as low, mid and high.

## Daily review

### Key takeaways

- Decide what makes a record the same record, then use `duplicated(subset=..., keep=...)` to look and `drop_duplicates` to remove.
- `keep=False` shows all members of a group; sort first to choose which copy survives.
- `astype` converts clean data; `to_numeric(errors="coerce")` converts messy text and exposes bad values as `NaN`.
- `astype(int)` truncates and fails with gaps; a column with gaps is float.
- Categorical columns store labels once, can be ordered, and turn typos into missing values; check types with `pd.api.types`.

### Common mistakes

- Dropping duplicates by key without deciding which version is right, and losing the correct one.
- Expecting `Ana` and `ana ` to be found as duplicates. Clean the text first.
- Using `astype(int)` on a column with `NaN`, which raises an error.
- Using `astype(int)` and expecting rounding. It truncates; use `round` first.
- Using `to_numeric` without `errors="coerce"` on messy data, so one bad value stops the whole conversion.
- Comparing printed dtype names between machines instead of using `pd.api.types`.

### Revision notes

- `df.duplicated(subset=[...], keep="first" | "last" | False)`, `df.drop_duplicates(...)`.
- `pd.to_numeric(s, errors="coerce")`, `s.astype(float)`, `s.astype("category")`.
- `pd.Categorical(values, categories=[...], ordered=True)`.
- Order: convert types, clean text, drop duplicates, report counts.
