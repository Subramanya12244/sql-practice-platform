## Understand

### Booleans: the answer to a yes/no question

A **boolean** (type `bool`) is a value that is either `True` or `False`. You met it on Day 2 as one of the basic types. Booleans matter because programs make decisions, and a decision is the answer to a yes/no question: is this order over 100? Is this customer active? Is this field empty? Tomorrow's `if` statements will use these answers to choose which code runs. Today you learn to ask the questions and combine the answers.

Be careful with the spelling. `True` and `False` start with a capital letter. `true` is not a Python word, so Python treats it as a variable name and raises `NameError: name 'true' is not defined`.

### Comparison operators

A **comparison operator** takes two values and produces a boolean. Python has six.

| Operator | Question it asks |
|---|---|
| `==` | Are the two values equal? |
| `!=` | Are they different? |
| `<` and `<=` | Is the left value smaller (or smaller or equal)? |
| `>` and `>=` | Is the left value larger (or larger or equal)? |

The most common beginner error is mixing up `=` and `==`. A single `=` is **assignment**: it stores a value in a name (`price = 40`). A double `==` is **comparison**: it asks a question and gives back a boolean (`price == 40`). Writing `if price = 40:` is a syntax error, which at least protects you; the worse mistake is writing a comparison where you meant to store a value, because Python accepts it and nothing is stored.

Numbers compare by value, so `3 == 3.0` is `True`: an `int` and a `float` with the same value are equal. A string and a number are never equal, so `"3" == 3` is `False`. Strings compare character by character using the numeric code of each character, which means `"apple" < "banana"` is `True`, but every capital letter sorts before every lowercase letter, so `"Zebra" < "apple"` is also `True`. Strings that hold digits compare as text, not as numbers: `"10" < "9"` is `True` because the first character `"1"` comes before `"9"`. Convert with `int()` first if you want numeric order.

Floating-point numbers can surprise you. Computers store them in binary, so `0.1 + 0.2` is slightly more than `0.3`, and `0.1 + 0.2 == 0.3` is `False`. Round both sides (you used `round()` on Day 3) before comparing computed decimals for equality.

### Combining conditions: and, or, not

Real questions have several parts: is the customer an adult **and** a member? The **logical operators** combine booleans.

- `a and b` is `True` only when both are true.
- `a or b` is `True` when at least one is true.
- `not a` flips the value: `not True` is `False`.

When a program has several operators, Python applies `not` first, then `and`, then `or`, the same way multiplication comes before addition. So `True or False and False` means `True or (False and False)`, which is `True`. Brackets override the order, and they also make your intent obvious to the next reader, so use them whenever a condition mixes `and` with `or`.

Python also evaluates **lazily**, which is called **short-circuiting**. For `a and b`, if `a` is false, the answer must be false, so Python never looks at `b`. For `a or b`, if `a` is true, `b` is skipped. This is more than speed: it lets you write a safe check first and a risky one second, such as `len(text) > 0 and text[0] == "A"`.

### Truthiness: every value is true or false

Anywhere Python needs a yes/no answer, it accepts any value, not only booleans. A value's **truthiness** is whether it counts as true. The rule is short: zero, empty and nothing are false; everything else is true. The false values you know so far are `0`, `0.0`, the empty string `""` and `None`. Later days add empty collections such as `[]` and `{}`, which are also false. You can check any value with `bool(value)`.

The misconception to avoid: `"0"` and `"False"` are **true**, because they are non-empty strings. Only the empty string `""` is false, and a string containing only a space is true. This matters when reading data, because a field read as text never becomes false just because it looks like zero.

There is one more twist. `and` and `or` do not always return `True` or `False`: they return one of the two values they were given. `x or y` gives `x` if `x` is truthy and `y` otherwise, so `name or "anonymous"` is a compact way to supply a fallback for an empty string. `x and y` gives `x` if `x` is falsy, and `y` otherwise.

### Chained comparisons

Mathematics writes `50 <= score < 80`, and Python allows exactly that. A **chained comparison** means every link is true: it equals `50 <= score and score < 80`, except that `score` is only evaluated once. Chains read naturally for range checks. They work with any operators, so `1 < 2 < 3` is `True` and `1 < 3 < 2` is `False`.

### == versus is, and None

`==` asks whether two values are **equal**. `is` asks whether they are the **same object** in memory. Two separate objects can be equal without being the same object; you will see this with lists on Day 8. Use `==` for comparing data. Use `is` for one special case: `None`. Write `x is None` and `x is not None`, because `None` exists only once in a program, and this form is the accepted style.

## Syntax and key functions

```text
left OPERATOR right            # one comparison, gives True or False
a and b    a or b    not a     # logical operators
low <= value < high            # chained comparison
value is None                  # identity test, for None
value is not None
bool(value)                    # truthiness of any value
```

- `OPERATOR` is one of `==`, `!=`, `<`, `<=`, `>`, `>=`. Both sides are evaluated first, then compared.
- `and`, `or` and `not` are words, not symbols. Precedence from highest to lowest is comparisons, then `not`, then `and`, then `or`.
- A chain such as `low <= value < high` is true only if every link is true.

| Tool | What it returns |
|---|---|
| `a == b`, `a != b` | `True` or `False` for equal or different |
| `a < b`, `a <= b`, `a > b`, `a >= b` | `True` or `False` for ordering |
| `a and b` | `a` if `a` is falsy, otherwise `b` |
| `a or b` | `a` if `a` is truthy, otherwise `b` |
| `not a` | the opposite boolean, always `True` or `False` |
| `a is b`, `a is not b` | `True` or `False` for same object or not |
| `bool(x)` | `False` for `0`, `0.0`, `""`, `None` (and empty collections), `True` otherwise |

## Learn by example

### Example 1: Comparing numbers and strings

Each `print()` receives several comparisons separated by commas, and each prints as a boolean. The last two lines show the float surprise and the type difference.

```python run
price = 40
print(price == 40, price != 40, price > 50, price <= 40)
print("apple" < "banana", "Zebra" < "apple", "10" < "9", 10 < 9)
print(0.1 + 0.2 == 0.3, round(0.1 + 0.2, 2) == 0.3)
print(3 == 3.0, "3" == 3)
```

```output
True False False True
True True True False
False True
True False
```

Notice that `"10" < "9"` is `True` while `10 < 9` is `False`: the same digits compare differently as text and as numbers.

### Example 2: and, or, not and short-circuiting

The first five lines combine booleans. The last three show short-circuiting: the right-hand side of `and` is risky (an `IndexError` or a division by zero), but Python never evaluates it when the left-hand side already decided the answer.

```python run
age = 34
member = True
print(age >= 18 and member)
print(age < 18 or member)
print(not member)
print(True or False and False)
print((True or False) and False)

text = ""
print(len(text) > 0 and text[0] == "A")
text = "Apple"
print(len(text) > 0 and text[0] == "A")
x = 0
print(x != 0 and 10 / x > 2)
```

```output
True
True
False
True
False
False
True
False
```

Lines 4 and 5 differ only by brackets. For the empty text, `text[0]` would raise `IndexError`, and for `x = 0` the division would raise `ZeroDivisionError`, but neither is reached because the first condition was already false.

### Example 3: Truthiness

Each `bool()` call shows whether a value counts as true. After that, `or` supplies a fallback and `and` shows which value it returns.

```python run
print(bool(0), bool(1), bool(-3), bool(0.0))
print(bool(""), bool(" "), bool("0"), bool("False"))
print(bool(None))
name = ""
print(name or "anonymous")
print(5 and "yes", 0 and "yes")
```

```output
False True True False
False True True True
False
anonymous
yes 0
```

The first line shows that only zero is false among numbers. The second shows that only the empty string is false among strings: a space, `"0"` and `"False"` are all true. `name or "anonymous"` gives the fallback because `""` is false, and `5 and "yes"` gives `"yes"`, while `0 and "yes"` stops at `0`.

### Example 4: Chained comparisons and None

```python run
score = 72
print(50 <= score < 80)
print(50 <= score and score < 80)
print(1 < 2 < 3, 1 < 3 < 2)
print(5 == 5 == 5.0)
x = None
print(x is None, x is not None)
```

```output
True
True
True False
True
True False
```

The first two lines are the same test written two ways. `5 == 5 == 5.0` is a chain in which every link holds, and `x is None` is the correct way to test for a missing value.

### Example 5: A realistic order review rule

An analyst flags an order for manual review when it is big and not cancelled, or when it has a coupon and is still pending. Each order is described by three variables (`total`, `status`, `coupon`), and the same four condition lines are repeated for each of three orders. Naming each condition keeps the final rule readable. On Day 11 a loop will remove the repetition.

```python run
total = 120.0
status = "shipped"
coupon = ""
big = total >= 100
active = status != "cancelled"
discounted = bool(coupon)
review = (big and active) or (discounted and status == "pending")
print(1, big, active, discounted, review)

total = 15.5
status = "pending"
coupon = "SAVE5"
big = total >= 100
active = status != "cancelled"
discounted = bool(coupon)
review = (big and active) or (discounted and status == "pending")
print(2, big, active, discounted, review)

total = 300.0
status = "cancelled"
coupon = ""
big = total >= 100
active = status != "cancelled"
discounted = bool(coupon)
review = (big and active) or (discounted and status == "pending")
print(3, big, active, discounted, review)
```

```output
1 True True False True
2 False True True True
3 True False False False
```

Order 1 is big and active, so the first bracket is true. Order 2 is small, but it has a coupon and is pending, so the second bracket is true. Order 3 is big but cancelled, so neither bracket is true.

## Real-world applications

- **Filtering rows.** Every data filter is a boolean: `total >= 100 and status != "cancelled"` selects the rows a report needs. The same logic later appears in SQL `WHERE` clauses and pandas filters.
- **Data quality checks.** `bool(field)` and `value is None` find missing or empty fields before they cause errors further along a pipeline. Knowing that `"0"` is truthy stops you from treating a text zero as missing.
- **Range validation.** Chained comparisons such as `0 <= discount <= 1` check that percentages, ages and scores are in a valid range.
- **Business rules.** Rules such as the review rule in Example 5 are combinations of named conditions. Brackets and short-circuiting keep them correct and safe.

## Daily review

### Key takeaways

- Comparisons produce `True` or `False`; `==` compares, `=` assigns.
- Precedence is `not`, then `and`, then `or`. Use brackets when mixing `and` with `or`.
- `and` and `or` short-circuit and return one of their operands, not always a boolean.
- Falsy values: `0`, `0.0`, `""`, `None`, and empty collections. Everything else is truthy, including `"0"` and `"False"`.
- Chain range checks as `low <= value < high`. Test `None` with `is None`.

### Common mistakes

- **Using `=` in a condition.** `if price = 40:` raises `SyntaxError: invalid syntax`. Write `==`.
- **Comparing numeric text.** `"10" < "9"` is `True`, so sorting or filtering numbers stored as strings gives wrong results. Convert with `int()` or `float()` first.
- **Comparing floats for equality.** `0.1 + 0.2 == 0.3` is `False`. Round both sides first.
- **Writing `x == 1 or 2`.** This means `(x == 1) or 2`, which is always truthy. Write `x == 1 or x == 2`.
- **Expecting `"False"` to be false.** Any non-empty string is true. Compare the text instead: `value == "False"`.

### Revision notes

- Six comparisons; `==` is not `=`.
- `not` > `and` > `or`; brackets for clarity.
- Falsy: zero, empty, `None`. Check with `bool()`.
- `a < b < c` means both links hold; `is None` for `None`.
