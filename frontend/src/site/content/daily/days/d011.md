## Objectives

- Write a `for` loop that runs a block of code once for every item of a list, string, tuple, set or dictionary.
- Use `range()` with one, two and three arguments to repeat code a set number of times or to produce number sequences.
- Pair each item with its position using `enumerate()`, and walk through two sequences together with `zip()`.
- Build totals, counts and new lists with the accumulator pattern.
- Explain why the loop variable keeps its last value, and why changing a list while looping over it is risky.

## Understand

### Repeating work

On Day 10 you counted fruit by writing the same line again and again. A **loop** repeats a block of code so you write it once. A **`for` loop** repeats it **once for each item** of a collection. The collection can be a list, a string (item by item), a tuple, a set, a dictionary or anything else you can go through, which Python calls an **iterable**.

```text
for item in collection:
    block that uses item
```

The line ends with a colon and the block is indented, just like `if` on Day 7. The name after `for` is the **loop variable**. On each pass, called an **iteration**, Python assigns the next item to it and runs the block. When the items run out, the loop ends and the program continues with the first line that is not indented.

A mental model: a conveyor belt delivers items one at a time to a worker. The worker does the same job on each item and never decides how many items there are; the belt does.

### Looping over different things

Looping over a list gives the items. Looping over a string gives its characters. Looping over a dictionary gives its **keys**; use `d.items()` to get the pairs and unpack them into two loop variables, `for key, value in d.items():`. A set gives its items in no reliable order, so sort first when the order matters: `for x in sorted(s):`.

### range(): numbers on demand

`range()` produces a sequence of integers without building the whole list.

- `range(5)` gives 0, 1, 2, 3, 4: five numbers, starting at 0 and **stopping before** 5.
- `range(2, 6)` gives 2, 3, 4, 5.
- `range(0, 10, 3)` gives 0, 3, 6, 9: the third number is the **step**.
- A negative step counts down: `range(5, 0, -1)` gives 5, 4, 3, 2, 1.

The stop value is excluded, exactly like a slice. Wrap a range in `list()` to see it. Use `for i in range(n):` when you need to repeat something `n` times, or when you need the positions to use as indexes, as in `for i in range(len(items)):`. The second case is often better written with `enumerate`.

### enumerate() and zip()

`enumerate(items)` yields `(position, item)` pairs, so `for i, item in enumerate(items):` gives you both without manual counting. A second argument sets where counting starts: `enumerate(items, 1)` is handy for numbered lists that begin at 1.

`zip(a, b)` walks through two (or more) sequences together, producing a tuple with one item from each: `for name, score in zip(names, scores):`. It stops when the **shorter** sequence ends, silently ignoring the extra items of the longer one.

### Accumulators

An **accumulator** is a variable you create before the loop and update inside it. This is the single most important loop pattern. A total starts at 0 and adds each item; a count starts at 0 and adds 1 when a condition holds; a result list starts as `[]` and receives items with `append()`; a dictionary of counts starts as `{}` and uses `get(key, 0) + 1`. Always put the starting line **before** the `for`. If you put `total = 0` inside the loop, it resets on every pass and you only keep the last item's value.

### Two traps

First, the loop variable is an ordinary variable. After the loop it still holds the last item, and if the collection was empty it was never created. Second, do not add or remove items of a list while looping over it. The loop follows positions, and removing an item shifts the later ones, so some items are skipped. Loop over a copy (`for x in items.copy():`) or build a new list instead.

### Why it matters

Almost every data task is "do this for each row". Totals per customer, validation of every record and reports of every item are all loops with accumulators.

### A worked trace

Trace `total = 0` followed by `for price in [4, 6, 10]: total += price`. Before the loop, `total` is 0. On the first iteration `price` is 4 and `total` becomes 4. On the second `price` is 6 and `total` becomes 10. On the third `price` is 10 and `total` becomes 20. The items are exhausted, so the loop ends and `total` stays 20. Writing the values in a small table, one row per iteration, is the most reliable way to understand any loop.

One more misconception: assigning to the loop variable does not change the list. In `for x in nums: x = x * 2` the name `x` is rebound to a new number on each pass, but `nums` is unchanged, because `x` is only a name pointing at the current item. To produce doubled values, append them to a new list, or assign by position with `nums[i] = nums[i] * 2` inside `for i in range(len(nums))`. The second form is one of the few good reasons to loop over positions instead of items.

## Syntax and key functions

```text
for item in collection:
    ...
for i in range(stop):  /  range(start, stop)  /  range(start, stop, step):
    ...
for i, item in enumerate(items, start):
    ...
for a, b in zip(list_a, list_b):
    ...
for key, value in d.items():
    ...
```

- The loop variable can have any name; choose one that says what each item is.
- The block runs zero times for an empty collection.
- `range` never includes its stop value.

| Function | What it gives |
|---|---|
| `range(n)` | integers 0 to n-1 |
| `range(a, b, step)` | integers from `a` up to but not including `b` |
| `enumerate(items, start=0)` | `(position, item)` pairs |
| `zip(a, b, ...)` | tuples of matching items, ending with the shortest input |
| `d.items()` | `(key, value)` pairs |
| `sum(items)`, `len(items)` | total and count (often replace a hand-written accumulator) |

## Learn by example

### Example 1: Looping over a list and a string

```python run
fruits = ["apple", "pear", "fig"]
for fruit in fruits:
    print("I like", fruit)
for letter in "data":
    print(letter, end=" ")
print()
print("last fruit variable:", fruit)
```

```output
I like apple
I like pear
I like fig
d a t a 
last fruit variable: fig
```

`end=" "` (Day 5) keeps the letters on one line. After the loop, `fruit` still holds the last item.

### Example 2: range

```python run
print(list(range(5)))
print(list(range(2, 6)))
print(list(range(0, 10, 3)))
print(list(range(5, 0, -1)))
for i in range(3):
    print("pass", i)
```

```output
[0, 1, 2, 3, 4]
[2, 3, 4, 5]
[0, 3, 6, 9]
[5, 4, 3, 2, 1]
pass 0
pass 1
pass 2
```

### Example 3: Accumulators

```python run
prices = [12.5, 8.0, 30.0, 4.5]
total = 0
count_big = 0
big_prices = []
for price in prices:
    total = total + price
    if price >= 10:
        count_big += 1
        big_prices.append(price)
print(total)
print(count_big, big_prices)
print(total / len(prices))
```

```output
55.0
2 [12.5, 30.0]
13.75
```

Three accumulators start before the loop and are updated inside it. The last line divides by `len(prices)` after the loop has finished.

### Example 4: enumerate and zip

```python run
names = ["Ada", "Bo", "Cy"]
scores = [91, 78, 85]
for position, name in enumerate(names, 1):
    print(position, name)
for name, score in zip(names, scores):
    print(name, score)
extra = [1, 2, 3, 4, 5]
print(len(list(zip(names, extra))))
```

```output
1 Ada
2 Bo
3 Cy
Ada 91
Bo 78
Cy 85
3
```

`zip` stopped after three pairs even though `extra` has five items.

### Example 5: Counting with a dictionary

This is the loop that replaces Day 10's repeated lines.

```python run
colors = ["red", "blue", "red", "red", "green", "blue"]
counts = {}
for color in colors:
    counts[color] = counts.get(color, 0) + 1
print(counts)
for color, n in counts.items():
    print(color, n)
```

```output
{'red': 3, 'blue': 2, 'green': 1}
red 3
blue 2
green 1
```

### Example 6: A realistic report

The loop walks through a list of order dictionaries, totals the amount per customer and tracks the largest order.

```python run
orders = [
    {"customer": "Ada", "total": 120.0},
    {"customer": "Bo", "total": 80.5},
    {"customer": "Ada", "total": 45.0},
    {"customer": "Cy", "total": 200.0},
]
per_customer = {}
largest = 0
for order in orders:
    name = order["customer"]
    per_customer[name] = per_customer.get(name, 0) + order["total"]
    if order["total"] > largest:
        largest = order["total"]
for name, amount in per_customer.items():
    print(f"{name}: {amount:.2f}")
print("Largest order:", largest)
```

```output
Ada: 165.00
Bo: 80.50
Cy: 200.00
Largest order: 200.0
```

## Real-world applications

- **Per-row processing.** Checking, cleaning or converting every record in a list of rows is a `for` loop.
- **Totals and summaries.** A total, count or maximum is an accumulator updated once per row.
- **Group counts.** The dictionary counting loop is the plain-Python equivalent of `GROUP BY` with `COUNT`.
- **Combining columns.** `zip()` joins parallel lists, such as a list of names and a list of scores, into records.

## Daily review

### Key takeaways

- `for item in collection:` runs the block once per item; the block is indented.
- `range(stop)` starts at 0 and excludes `stop`; the optional third value is the step.
- `enumerate` gives positions and `zip` pairs sequences; `zip` stops at the shortest.
- Create accumulators before the loop and update them inside it.
- Do not change a list while looping over it.

### Common mistakes

- **Resetting an accumulator inside the loop.** `total = 0` in the block means the result is only the last item. Move it above the `for`.
- **Off-by-one with `range`.** `range(1, 5)` stops at 4. To include 5, write `range(1, 6)`.
- **Forgetting the colon or indent.** `SyntaxError: expected ':'` or `IndentationError: expected an indented block`.
- **Removing items while looping.** `for x in items: items.remove(x)` skips every other item. Loop over `items.copy()` or build a new list.
- **Expecting `zip` to keep extras.** Items of the longer list are dropped without any error. Check the lengths if that matters.
- **Printing inside the loop when you wanted one result.** A `print` in the block prints once per item. Print after the loop.

### Revision notes

- `for x in items:`; strings give characters; dictionaries give keys.
- `range(a, b, step)`, stop excluded.
- `enumerate(items, 1)`, `zip(a, b)`, `d.items()`.
- Accumulator: initialise, update, use after the loop.
