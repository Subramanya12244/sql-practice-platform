## Objectives

- Write `if`, `elif` and `else` blocks that run different code depending on a condition.
- Explain how Python picks exactly one branch of an `if`/`elif`/`else` chain, and order the branches correctly.
- Nest conditions, and flatten them with `and` or with a chain of `elif` branches when that reads better.
- Write a conditional expression (`a if condition else b`) for a simple either-or value.
- Use guard clauses to reject bad input first, so the main case stays simple.

## Understand

### Making a program choose

So far every program you wrote ran its lines from top to bottom, every time. A **conditional statement** lets the program choose: some lines run only when a condition is true. The condition is any expression that gives a boolean, such as the comparisons and `and`/`or` combinations from Day 6. This is how a program treats a cancelled order differently from a shipped one.

### if and else

```text
if condition:
    lines that run when the condition is true
else:
    lines that run when it is false
```

The first line ends with a colon. The lines that belong to the branch are **indented**, which means they start with the same number of spaces (four is the standard). The indented lines form a **block**. Indentation is not decoration in Python: it is the only thing that says which lines belong to the `if`. A line that goes back to the left margin is outside the statement and always runs.

The `else` part is optional. Without it, nothing happens when the condition is false. Python checks the condition once, picks one block, runs it, and carries on after the whole statement.

### elif: more than two outcomes

When there are several cases, add `elif` (short for "else if") branches between `if` and `else`. Python checks the conditions **from top to bottom** and runs the block of the **first** condition that is true. It then skips all the rest. If none is true, the `else` block runs, if there is one.

This top-to-bottom rule is the heart of the topic and the source of the classic mistake: the order of the branches changes the result. If you grade scores with `score >= 70` before `score >= 90`, a score of 95 stops at the first test and gets the wrong grade, because the later, stricter test is never reached. Put the most specific or strictest condition first.

A useful picture is a row of doors. You walk down the corridor and go through the first door that opens for you. You never come back to try the others.

### Truthiness in conditions

An `if` accepts any value, not just booleans, using the truthiness rules from Day 6. `if name:` means "if name is not empty". This is compact and common in real code, but write the explicit comparison (`if total > 0:`) when it makes the intent clearer.

### Nested conditions

You can put an `if` inside another `if`'s block. This is a **nested condition**, and the inner test runs only when the outer one was true. Nesting is natural when the second question only makes sense after the first, but each level adds indentation, and deep nesting is hard to read. Two flat alternatives often work: combine tests with `and`, or use an `elif` chain. If the outer and inner conditions lead to the same actions, both versions behave the same; choose the one that is easier to read.

### Conditional expressions

An `if` statement does things. Often you only need to choose a **value**. A **conditional expression** does this in one line:

```text
value_if_true if condition else value_if_false
```

It is an expression, so it can sit inside an assignment or a `print()`. The condition is evaluated first, then only the chosen value. You can chain them, but more than one level quickly becomes hard to read; switch to `if`/`elif`/`else` instead. Use a conditional expression when there are two outcomes and both are short.

### Guard clauses

A **guard clause** is a check at the top that deals with a bad or special case straight away, leaving the normal case for the rest of the code. For example, check that an amount is present, then that it is a number, then that it is above zero, and only then use it. Written this way, the code stays flat instead of growing a staircase of nested `if` blocks. In this lesson a guard is an early `if`/`elif` that reports a problem; once you learn functions on Day 14, the same idea becomes an early `return`, which is where guard clauses are most common.

The misconception to avoid is thinking that an `else` after a series of separate `if` statements belongs to all of them. An `else` attaches only to the one `if`/`elif` chain directly above it. Two separate `if` statements are two separate decisions, and both can run.

### A worked trace

Tracing means following the program by hand, one line at a time, writing down the value of each variable. Take `score = 72` and the grading chain from above. Python tests `score >= 90`: 72 is not at least 90, so the result is false and the block is skipped. It then tests `score >= 80`: false again. Next, `score >= 70`: true, so `grade = "C"` runs and the whole chain ends; the `else` is never looked at. The same trace with `score = 95` stops at the first test. Whenever a conditional gives a surprising result, trace it this way with the actual values rather than guessing.

## Syntax and key functions

```text
if condition:
    block

if condition:
    block
else:
    block

if condition_1:
    block
elif condition_2:
    block
else:
    block

result = value_if_true if condition else value_if_false
```

- The colon ends each `if`, `elif` and `else` line. Missing it gives `SyntaxError: expected ':'`.
- The block is every following line indented further than the `if`. Use four spaces, consistently.
- There can be any number of `elif` branches and at most one `else`, which must be last.
- Only the first true branch runs.

| Form | What it does |
|---|---|
| `if` | Runs its block when the condition is truthy |
| `elif` | Is tested only if all earlier branches were false |
| `else` | Runs when no earlier branch ran |
| `a if c else b` | Evaluates to `a` when `c` is truthy, otherwise `b` |
| `str.isdigit()` | Returns `True` when a non-empty string has only digits (used in Example 5) |

## Learn by example

### Example 1: if and else

The two indented `print()` lines are the block. The last line is not indented, so it runs whatever the temperature is.

```python run
temperature = 31
if temperature > 30:
    print("hot")
    print("drink water")
else:
    print("fine")
print("done")
```

```output
hot
drink water
done
```

Change `temperature` to 20 and only `fine` and `done` print.

### Example 2: elif chains and the order of branches

The first chain grades a score. The second shows the ordering mistake: 95 is at least 90, but the test for 70 comes first. The last statement uses truthiness: `0` is falsy.

```python run
score = 72
if score >= 90:
    grade = "A"
elif score >= 80:
    grade = "B"
elif score >= 70:
    grade = "C"
else:
    grade = "F"
print(score, grade)

wrong_order = 95
if wrong_order >= 70:
    label = "C"
elif wrong_order >= 90:
    label = "A"
else:
    label = "F"
print(wrong_order, label)

count = 0
if count:
    print("non-zero")
else:
    print("zero")
```

```output
72 C
95 C
zero
```

The 95 gets `C` because Python stops at the first true branch.

### Example 3: Nested and flat versions

Both programs apply the same rule to the same data. The first nests an `if` inside an `if`; the second flattens it with `and` and `elif`.

```python run
age = 20
has_id = True
if age >= 18:
    if has_id:
        print("entry allowed")
    else:
        print("show your ID")
else:
    print("too young")

if age >= 18 and has_id:
    print("entry allowed")
elif age >= 18:
    print("show your ID")
else:
    print("too young")
```

```output
entry allowed
entry allowed
```

The flat version repeats `age >= 18` but has no extra indentation. Neither is always better; prefer the one a reader understands at a glance.

### Example 4: Conditional expressions

Each line chooses a value rather than running a block. The third shows a chained expression, which already looks dense. The last uses truthiness inside the expression.

```python run
stock = 0
status = "in stock" if stock > 0 else "sold out"
print(status)
n = 7
print("even" if n % 2 == 0 else "odd")
price = 80
tier = "low" if price < 50 else "mid" if price < 100 else "high"
print(tier)
print("Items:", stock if stock else "none")
```

```output
sold out
odd
mid
Items: none
```

### Example 5: Guard clauses for input

The program reads an amount as text, checks the bad cases first, and handles the good case last in the `else`. The fee is 20 percent of the amount below 100, and a flat 20 otherwise, chosen with a conditional expression. The input `42` is supplied through `stdin`.

```python run
text = input()
rate = 0.2
if text.strip() == "":
    print("Error: empty amount")
elif not text.strip().isdigit():
    print("Error: not a whole number")
elif int(text) == 0:
    print("Error: amount must be above zero")
else:
    amount = int(text)
    fee = amount * rate if amount < 100 else 20
    print("Amount:", amount)
    print("Fee:", fee)
```

```stdin
42
```

```output
Amount: 42
Fee: 8.4
```

Running it with other inputs gives `Amount: 250` and `Fee: 20` for `250`, `Error: empty amount` for an empty line, `Error: not a whole number` for `abc`, and `Error: amount must be above zero` for `0`. Order matters here too: `int(text)` is only reached after the earlier guards proved the text is safe to convert.

## Real-world applications

- **Labelling and bucketing.** An `if`/`elif`/`else` chain turns a number into a category such as a size tier, a grade or a risk band, which is how raw columns become report-friendly labels.
- **Input validation.** Guard clauses reject empty, malformed or out-of-range values before they reach a calculation, as in Example 5.
- **Data cleaning rules.** A conditional expression such as `value if value else "unknown"` fills gaps in a field in one line.
- **Business logic.** Rules like discounts, shipping fees and approval limits are conditions on several fields, written as branches in a pipeline step.

## Daily review

### Key takeaways

- `if`, `elif` and `else` choose one block; the first true condition wins and the rest are skipped.
- Indentation defines the block, and the colon ends the condition line.
- Order `elif` branches from the strictest to the loosest.
- `a if condition else b` picks a value; keep it to two short outcomes.
- Guard clauses handle bad input first and keep the main case flat.

### Common mistakes

- **Forgetting the colon.** `if x > 3` gives `SyntaxError: expected ':'`. Add the colon.
- **Wrong or missing indentation.** A missing indent gives `IndentationError: expected an indented block`, and a line that is indented too little silently runs every time. Indent every line of the block by the same four spaces.
- **Branches in the wrong order.** Checking `>= 70` before `>= 90` gives 95 the lowest matching label. Put the strictest test first.
- **Using `=` instead of `==`.** `if status = "open":` is a `SyntaxError`. Use `==`.
- **Treating separate `if`s as one chain.** Two `if` statements in a row can both run. Use `elif` when the cases exclude each other.

### Revision notes

- `if cond:` plus an indented block; `elif` for more cases; `else` last.
- Top to bottom, first true branch only.
- Conditional expression: `a if cond else b`.
- Guards first, normal case last; flatten before nesting deeply.
