## Understand

### Files are text, tables are objects

A CSV file (comma-separated values) is plain text: one line per row, with values separated by commas, and usually a first line of column names. Reading it into pandas means turning that text into a DataFrame with typed columns, so that numbers can be added and dates compared. The function is `pd.read_csv`. It accepts a file path, a web address, or any file-like object. In these lessons the data must be created inside the code, so we wrap CSV text in `io.StringIO`, which makes a string behave like an open file. A real file would simply be `pd.read_csv("sales.csv")` and works the same way.

pandas guesses types while reading. Columns of whole numbers become `int64`, columns of decimals become `float64`, and everything else stays text. The guess is usually right, but it is the source of many data bugs, so the options below let you take control.

### The main read_csv options

- `sep` is the separator character. The default is a comma. For semicolon files, common in countries that write decimals with a comma, use `sep=";"`. For tab files use `sep="\t"`.
- `header` says which line holds the column names. The default is the first line. `header=None` says there is no header line, and pandas numbers the columns 0, 1, 2. Combine it with `names=[...]` to supply your own names.
- `usecols` keeps only some columns, which saves memory on wide files: `usecols=["id", "price"]`.
- `index_col` makes one column the row index instead of an ordinary column.
- `na_values` lists extra strings that mean "missing", for example `na_values=["-", "n/a", "?"]`. By default pandas already treats empty cells and strings such as `NA` and `NaN` as missing, and stores them as `NaN`.
- `skiprows` skips lines at the top (a title or comments), and `nrows` reads only the first n data rows, which is handy for a quick look at a huge file.
- `dtype` sets column types by name: `dtype={"zip": str}` keeps leading zeros, which would be lost if the column were read as a number (`01234` would become `1234`).
- `parse_dates` converts the named columns from text to real date-time values: `parse_dates=["date"]`.

### Dates: why parse_dates matters

Without `parse_dates`, a date column is plain text. Text sorts alphabetically and cannot do date arithmetic. With it, the column is stored as a date-time type, in which a later date really is larger and subtraction gives a time difference. If a date is written in an unusual way, such as `13/01/2024`, ambiguity between day-first and month-first is a real risk, and parsing options exist for it; for now remember to check that the dates you read are the dates you meant. The parsed column has a dedicated date-time dtype, and you can test for it with `pd.api.types.is_datetime64_any_dtype(df["date"])`.

### Writing CSV

`df.to_csv(path)` writes the table as text. If you call it without a path, it returns the CSV text as a string, which is useful in tests and examples. By default it also writes the index as a first column with no name. When the index is just 0, 1, 2, that column is noise, and reading the file back would produce an extra column called `Unnamed: 0`. Pass `index=False` to leave it out. Other options are `sep=`, `columns=[...]` to write only some columns in a chosen order, and `header=False`. Missing values are written as empty cells.

### JSON

JSON (JavaScript Object Notation) is the text format of web services. Tabular JSON usually appears as a list of objects, one per row, such as `[{"id": 1, "price": 9.5}, {"id": 2, "price": 4}]`. `pd.read_json` turns that into a DataFrame, and `df.to_json(orient="records")` turns a table back into the same layout. The `orient` argument chooses the layout: `"records"` is a list of row objects, `"columns"` (the default for a DataFrame) is an object of columns keyed by index label, `"index"` is an object keyed by row label, and `"split"` separates `columns`, `index` and `data`. Records is the most common for exchanging data with other programs. Nested JSON, where values are themselves objects or lists, needs flattening first and is beyond today. For files and strings of JSON that you want to handle without pandas, the standard-library `json` module from the earlier Python days still applies.

### Excel

Excel workbooks (`.xlsx`) are read with `pd.read_excel("file.xlsx", sheet_name="Q1")` and written with `df.to_excel("out.xlsx", sheet_name="Q1", index=False)`. A workbook has several sheets; `sheet_name` chooses one by name or number, and `sheet_name=None` reads all of them into a dictionary of DataFrames. pandas does not read the file format itself. It needs a separate package for `.xlsx` files, `openpyxl`, which is not available in the browser Python that runs the other examples. So in this lesson the Excel code is shown in a plain code block and one example that runs only on your own computer (marked `python local`) writes a workbook to a temporary folder and reads it back. The CSV and JSON examples run in the browser.

### The common misconception

Learners think that reading a file gives exactly what is in it. In practice the reader makes decisions: it guesses types, converts empty cells to `NaN`, drops leading zeros from codes that look like numbers, and may merge a header into the data if `header` is wrong. The symptom is a table with strange column names such as `0` and `1`, a column of numbers that turned into text because one cell holds `n/a`, or ZIP codes without their zeros. The cure is to look at `shape`, a few rows and `dtypes` straight after every read, and to state your options.

### Why it matters in data work

Almost every analysis begins with a file: an export from a system, a spreadsheet from a colleague, a JSON download from a service. Reading it correctly, with the right separator, types and dates, avoids hours of confusion later. Writing results back to CSV or JSON is how you hand them to other people and tools. Write with `index=False` unless the index carries information, and always read back a small sample of what you wrote to verify it.

### Round trips

A useful test of your options is the round trip: write a table to CSV text, read it back, and compare with `equals`. If the result differs, one of your reading or writing options is losing information, such as the index, the date type or leading zeros. We use this idea in the examples.

## Syntax and key functions

Read and write:

```python
import io
import pandas as pd

df = pd.read_csv(io.StringIO(text), sep=",", header=0, usecols=None, index_col=None,
                 na_values=None, skiprows=None, nrows=None, dtype=None, parse_dates=None)
text = df.to_csv(index=False)
df = pd.read_json(io.StringIO(json_text))
json_text = df.to_json(orient="records")
```

Excel (needs `openpyxl`, shown only):

```python
df = pd.read_excel("sales.xlsx", sheet_name="Q1")
df.to_excel("out.xlsx", sheet_name="Q1", index=False)
```

| Function or option | Purpose |
|---|---|
| `pd.read_csv(src, ...)` | Read CSV from a path, URL or file-like object into a DataFrame. |
| `sep`, `header`, `names` | Separator, header line, own column names. |
| `usecols`, `nrows`, `skiprows` | Choose columns, limit or skip lines. |
| `index_col` | Use a column as the row index. |
| `na_values` | Extra strings to treat as missing. |
| `dtype`, `parse_dates` | Force column types, parse date columns. |
| `df.to_csv(path_or_None, index=False)` | Write CSV; with no path returns the text. |
| `pd.read_json(src)` | Read JSON records into a DataFrame. |
| `df.to_json(orient="records")` | JSON text: a list of row objects. |
| `pd.read_excel`, `df.to_excel` | Excel sheets; require `openpyxl`. |

## Learn by example

### Example 1: Reading CSV text and checking it

CSV text is wrapped in `io.StringIO` so that it behaves like a file. After reading we look at the shape, the column names, the types and the table. The empty cell becomes `NaN`, which makes its column `float64`.

```python run
import io
import pandas as pd

pd.set_option("display.width", 200)
pd.set_option("display.max_columns", 20)

text = """id,city,price,qty
1,Oslo,9.5,3
2,Rome,4.0,
3,Lima,12.25,5
"""
df = pd.read_csv(io.StringIO(text))
print(df)
print(df.shape, df.columns.tolist())
print(df[["id", "price", "qty"]].dtypes.to_string())
print(df["qty"].isna().sum())
```

```output
   id  city  price  qty
0   1  Oslo   9.50  3.0
1   2  Rome   4.00  NaN
2   3  Lima  12.25  5.0
(3, 4) ['id', 'city', 'price', 'qty']
id         int64
price    float64
qty      float64
1
```

### Example 2: Separators, headers, missing markers and column choice

A semicolon file without a header line gets its names from `names=`. The text `-` is declared missing with `na_values`, `usecols` keeps two columns and `skiprows` skips a title line. `nrows` reads only the first row.

```python run
import io
import pandas as pd

pd.set_option("display.width", 200)
pd.set_option("display.max_columns", 20)

raw = "1;Oslo;9.5\n2;Rome;-\n3;Lima;12.25\n"
df = pd.read_csv(io.StringIO(raw), sep=";", header=None, names=["id", "city", "price"], na_values=["-"])
print(df)
print(df["price"].tolist())

two = pd.read_csv(io.StringIO(raw), sep=";", header=None, names=["id", "city", "price"], usecols=["city", "price"], nrows=1)
print(two)

titled = "Report 2024\nid,score\n1,50\n2,60\n"
print(pd.read_csv(io.StringIO(titled), skiprows=1, index_col="id"))
```

```output
   id  city  price
0   1  Oslo   9.50
1   2  Rome    NaN
2   3  Lima  12.25
[9.5, nan, 12.25]
   city  price
0  Oslo    9.5
    score
id       
1      50
2      60
```

### Example 3: dtype and parse_dates

ZIP codes keep their leading zeros when `dtype` makes them text. Without it they become numbers. `parse_dates` turns the date column into real dates, so we can take the earliest date and the difference between dates.

```python run
import io
import pandas as pd

text = """zip,date,amount
01234,2024-03-05,10
00501,2024-01-20,25
98101,2024-02-11,7
"""
plain = pd.read_csv(io.StringIO(text))
typed = pd.read_csv(io.StringIO(text), dtype={"zip": str}, parse_dates=["date"])
print(plain["zip"].tolist())
print(typed["zip"].tolist())
print(pd.api.types.is_datetime64_any_dtype(plain["date"]), pd.api.types.is_datetime64_any_dtype(typed["date"]))
print(typed["date"].min())
print((typed["date"].max() - typed["date"].min()).days)
```

```output
[1234, 501, 98101]
['01234', '00501', '98101']
False True
2024-01-20 00:00:00
45
```

### Example 4: Writing CSV and round trips

Without a path, `to_csv` returns text. By default the index is written as an unnamed first column, and reading it back creates `Unnamed: 0`. With `index=False` the round trip returns the original table.

```python run
import io
import pandas as pd

df = pd.DataFrame({"item": ["pen", "ink"], "price": [1.5, 4.0]})
print(df.to_csv(), end="")
print("--")
text = df.to_csv(index=False)
print(text, end="")
print("--")
back = pd.read_csv(io.StringIO(df.to_csv()))
print(back.columns.tolist())
print(df.equals(pd.read_csv(io.StringIO(text))))
print(df.to_csv(index=False, columns=["price"]), end="")
```

```output
,item,price
0,pen,1.5
1,ink,4.0
--
item,price
pen,1.5
ink,4.0
--
['Unnamed: 0', 'item', 'price']
True
price
1.5
4.0
```

### Example 5: JSON records

`read_json` turns a list of objects into a DataFrame, and `to_json(orient="records")` writes one back. A different `orient` gives a different layout. `json.loads` from the standard library shows that the result is ordinary JSON.

```python run
import io
import json
import pandas as pd

text = '[{"id": 1, "name": "Ana", "score": 9.5}, {"id": 2, "name": "Ben", "score": 7.0}]'
df = pd.read_json(io.StringIO(text))
print(df.shape, df.columns.tolist())
print(df["score"].tolist())
print(df.to_json(orient="records"))
print(df.to_json(orient="columns"))
print(json.loads(df.to_json(orient="split"))["columns"])
```

```output
(2, 3) ['id', 'name', 'score']
[9.5, 7.0]
[{"id":1,"name":"Ana","score":9.5},{"id":2,"name":"Ben","score":7.0}]
{"id":{"0":1,"1":2},"name":{"0":"Ana","1":"Ben"},"score":{"0":9.5,"1":7.0}}
['id', 'name', 'score']
```

### Example 6: Excel with a temporary workbook (local only)

This example needs `openpyxl`, which the browser lacks, so it runs only on your computer and the output shown was checked there. It writes a two-sheet workbook into a temporary folder, reads one sheet back, then reads all sheets as a dictionary.

```python local
import os
import tempfile
import pandas as pd

q1 = pd.DataFrame({"item": ["pen", "ink"], "sales": [10, 4]})
q2 = pd.DataFrame({"item": ["pen", "ink"], "sales": [12, 6]})
with tempfile.TemporaryDirectory() as folder:
    path = os.path.join(folder, "sales.xlsx")
    with pd.ExcelWriter(path) as writer:
        q1.to_excel(writer, sheet_name="Q1", index=False)
        q2.to_excel(writer, sheet_name="Q2", index=False)
    back = pd.read_excel(path, sheet_name="Q2")
    print(back["sales"].tolist())
    everything = pd.read_excel(path, sheet_name=None)
    print(sorted(everything), everything["Q1"].shape)
    print(back.equals(q2))
```

```output
[12, 6]
['Q1', 'Q2'] (2, 2)
True
```

## Real-world applications

- **Loading system exports.** Exports from a CRM or accounting system arrive as CSV, often with semicolons, title lines and odd missing markers. `sep`, `skiprows` and `na_values`, as in Example 2, make them readable.
- **Keeping codes intact.** ZIP codes, phone numbers and product codes must be read as text with `dtype`, as in Example 3, or leading zeros are lost for ever.
- **Exchanging data with web services.** JSON records, as in Example 5, are how APIs send tables, and `to_json(orient="records")` is how you send one back.
- **Working with spreadsheets from colleagues.** Excel files with several sheets are read with `read_excel`, as in Examples 6 and 7, and converted to CSV for a pipeline.

## Daily review

### Key takeaways

- `read_csv` guesses types; control it with `sep`, `header`, `names`, `usecols`, `na_values`, `dtype` and `parse_dates`, and check `shape` and `dtypes` after reading.
- `to_csv(index=False)` avoids an extra index column; without a path it returns text.
- Leading zeros survive only with `dtype=str`.
- `parse_dates` converts date text to real dates that sort and subtract correctly.
- JSON tables are lists of records: `read_json` and `to_json(orient="records")`.
- Excel needs `openpyxl`, which is not in the browser.

### Common mistakes

- Forgetting `index=False` and later seeing an `Unnamed: 0` column.
- Reading a semicolon file with the default separator and getting one wide column.
- Letting ZIP codes become numbers, so `01234` turns into `1234`.
- Leaving dates as text, so sorting is alphabetical and subtraction raises a `TypeError`.
- Missing markers such as `-` or `n/a` keep a numeric column as text. Declare them with `na_values`.
- Using `header=0` on a file with no header, so the first data row becomes the column names.

### Revision notes

- `pd.read_csv(io.StringIO(text), sep, header, names, usecols, na_values, skiprows, nrows, dtype, parse_dates, index_col)`.
- `df.to_csv(index=False)`; `pd.read_json(...)`, `df.to_json(orient="records")`.
- `pd.read_excel(path, sheet_name=...)` needs `openpyxl`.
- Round trip: write, read back, `equals`.
