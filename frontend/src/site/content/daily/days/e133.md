## Objectives

- Write validation rules as code: a name, a severity and a function that returns pass or fail for every row.
- Separate row-level rules (one verdict per row) from dataset-level rules (one verdict for the table).
- Run a rule list into a report DataFrame and a table of failing rows, with sample ids and rates.
- Enforce the report: warn on low-severity failures, stop the pipeline on critical ones, and quarantine the failing rows.

## Understand

### From dimensions to executable rules

Day 132 gave you words for the ways data can be wrong and one-off checks for each. A pipeline needs those checks written down once, run on every load and reported in the same shape. A **validation rule** is a small, named, testable piece of code that states one expectation about the data: "every order has a customer id", "status is one of paid, refunded, failed", "the table has at least 50 rows". Writing rules as code, and not as notes in a document, means the expectation runs every night and cannot drift away from what people believe. Writing them as **data** (a list of records with a name, a severity and a function) means a new rule is one more entry, and the runner never changes.

### Row-level rules

A **row-level rule** gives each row its own verdict. In pandas it is a function that takes the DataFrame and returns a boolean Series of the same length, `True` where the row passes: `lambda d: d["status"].isin(ALLOWED)`. Because the verdicts are per row, you know exactly which rows failed, you can quarantine them (Day 129) and the failure rate is the share of `False`. The common traps are in missing values. `NaN >= 0` is `False`, so a missing amount would fail the range rule as well as the completeness rule; if the dimensions are to be reported separately, the range rule must pass missing values and let a presence rule report them (`d["amount"].isna() | (d["amount"] >= 0)`). Comparisons with `NaN` never raise an error, they just give `False`, which is why a rule that "works" can quietly report the wrong rows.

### Dataset-level rules

Some expectations are about the table as a whole and cannot be decided row by row: "at least 50 rows", "the key is unique", "the total amount is within 1 percent of the control total from the source", "the newest row is less than 26 hours old". A **dataset-level rule** returns one verdict and a detail (the measured value). It is usually a function from the DataFrame to a pair `(passed, detail)`. Dataset rules catch problems that no single row shows: an empty file in which every row rule passes trivially, a truncated load, a duplicate that makes each row look valid on its own.

### Severity and thresholds

Not every failure deserves the same response. A **severity** tags each rule: **critical** failures stop the pipeline or block publication (a missing customer id breaks joins), **warning** failures are reported and tracked (a currency that does not match the country). Rules can also carry a **maximum failure rate**: a row rule with `max_fail_rate = 0.02` passes if no more than 2 percent of the rows fail. Thresholds must be honest (Day 132): 0 percent for keys, a small tolerance for noisy optional fields, set from a month of data. A rule set that always fails is ignored, and one that never fails is not testing anything.

### Reporting failures

The runner returns two things. The **report** is one row per rule: its name, kind, severity, rows checked, rows failing, the failure rate, a few sample ids and the verdict. This is what goes into a log, an `etl_runs`-style table (Day 130) or a message. The **failing rows** table lists each failed row once per rule it broke, with the key and the rule name; from it you can see which rows to quarantine and which rule hits most. Reporting only a pass or fail flag hides everything the engineer needs: how many, which, and how bad.

### Enforcing

The report is then acted on. A function `enforce(report)` raises an error that names the failed critical rules when any critical rule failed, so the scheduler marks the run failed and the dashboard is not refreshed. Warnings are logged and do not stop the run. The failing rows are removed from the data to be loaded and written to the quarantine, so the load contains only rows that passed every critical rule. The order matters: validate, then quarantine, then load, then reconcile that `read = loaded + quarantined`.

### Testing the rules themselves

A rule that cannot fail is useless. Test each rule on a tiny DataFrame that contains one passing row and one failing row and assert the verdicts. When a bug is found in production data, add its row to the test first. A misconception is that validation code is simple enough not to need tests; a wrong comparison or a `NaN` mistake silently hides defects, which is worse than having no rule because everyone trusts it.

### Why it matters in data work

Rules as code turn quality from a meeting topic into a gate in the pipeline. Everyone can read the rule list, the report shows the trend, and a bad load stops before it reaches a dashboard.

## Syntax and key functions

```python
RULE = {"name": "status allowed", "severity": "critical", "ok": lambda d: d["status"].isin(ALLOWED)}
passed = RULE["ok"](df)                      # boolean Series, True where the row passes
failing_ids = df.loc[~passed, "order_id"].tolist()
```

| Item | What it does or returns |
|---|---|
| row rule | `df -> boolean Series`, True where the row passes. |
| dataset rule | `df -> (passed, detail)`: one verdict and the measured value. |
| `~mask` | Inverts a boolean Series: the failing rows. |
| `s.isna() \| (s >= 0)` | Lets missing values pass a range rule so presence is reported once, elsewhere. |
| `pd.DataFrame(records)` | Builds the report from a list of dicts. |
| `df.loc[mask, col]` | The values of a column for rows where the mask is True. |
| severity | `critical` stops the run, `warning` is reported. |
| `max_fail_rate` | The share of failing rows that a rule tolerates. |

### Example 2: A runner that builds the report

The runner applies every row rule and builds one report row per rule, with the number of rows checked and failing, the rate, up to three sample ids and the verdict under the rule's failure-rate limit. The report is a DataFrame, so it can be printed, stored or filtered.

```python run
import pandas as pd

orders = pd.DataFrame({
    "order_id": ["A1", "A2", "A3", "A3", "A5", "A6", "A7", "A8", "A9", "A10"],
    "customer_id": [10, 11, None, 12, 13, 14, None, 15, 16, 17],
    "amount": [19.9, 25.0, 12.5, 12.5, -5.0, 40.0, None, 7.5, 3.0, 8.0],
    "status": ["paid", "paid", "refunded", "refunded", "shipped", "paid", "failed", "paid", "PAID", "paid"],
    "currency": ["EUR", "EUR", "USD", "USD", "EUR", "EUR", "EUR", "USD", "EUR", "EUR"],
    "country": ["DE", "FR", "US", "US", "DE", "DE", "FR", "US", "DE", "US"],
    "updated_at": ["2025-03-06 08:00", "2025-03-06 07:30", "2025-03-05 22:00", "2025-03-05 22:00", "2025-03-04 09:00",
                   "2025-03-06 10:15", "2025-03-01 12:00", "2025-03-06 06:45", "2025-03-06 09:30", "2025-03-02 08:00"],
})

ALLOWED = {"paid", "refunded", "failed"}
NOW = pd.Timestamp("2025-03-06 12:00")

ROW_RULES = [
    {"name": "customer_id present", "severity": "critical", "ok": lambda d: d["customer_id"].notna()},
    {"name": "amount present", "severity": "warning", "ok": lambda d: d["amount"].notna()},
    {"name": "status allowed", "severity": "critical", "ok": lambda d: d["status"].isin(ALLOWED)},
    {"name": "amount >= 0", "severity": "critical", "ok": lambda d: d["amount"].isna() | (d["amount"] >= 0)},
    {"name": "currency matches country", "severity": "warning",
     "ok": lambda d: d["country"].map({"DE": "EUR", "FR": "EUR", "US": "USD"}) == d["currency"]},
]

def run_row_rules(df, rules, max_fail_rate=0.0):
    records = []
    for rule in rules:
        ok = rule["ok"](df)
        failing = df.loc[~ok, "order_id"].tolist()
        rate = len(failing) / len(df)
        records.append({"rule": rule["name"], "severity": rule["severity"], "checked": len(df), "failing": len(failing),
                        "rate": round(rate, 2), "sample": ",".join(failing[:3]), "result": "PASS" if rate <= max_fail_rate else "FAIL"})
    return pd.DataFrame(records)

print(run_row_rules(orders, ROW_RULES).to_string(index=False))
```

```output
                    rule severity  checked  failing  rate sample result
     customer_id present critical       10        2   0.2  A3,A7   FAIL
          amount present  warning       10        1   0.1     A7   FAIL
          status allowed critical       10        2   0.2  A5,A9   FAIL
             amount >= 0 critical       10        1   0.1     A5   FAIL
currency matches country  warning       10        1   0.1    A10   FAIL
```
### Example 3: Dataset-level rules

Four rules about the table as a whole return a pair of verdict and measured value: a minimum row count, a unique key, a total within 1 percent of a control total from the source, and a freshness limit measured against a fixed `now`. The report shows the measurements, not only pass or fail.

```python run
import pandas as pd

orders = pd.DataFrame({
    "order_id": ["A1", "A2", "A3", "A3", "A5", "A6", "A7", "A8", "A9", "A10"],
    "customer_id": [10, 11, None, 12, 13, 14, None, 15, 16, 17],
    "amount": [19.9, 25.0, 12.5, 12.5, -5.0, 40.0, None, 7.5, 3.0, 8.0],
    "status": ["paid", "paid", "refunded", "refunded", "shipped", "paid", "failed", "paid", "PAID", "paid"],
    "currency": ["EUR", "EUR", "USD", "USD", "EUR", "EUR", "EUR", "USD", "EUR", "EUR"],
    "country": ["DE", "FR", "US", "US", "DE", "DE", "FR", "US", "DE", "US"],
    "updated_at": ["2025-03-06 08:00", "2025-03-06 07:30", "2025-03-05 22:00", "2025-03-05 22:00", "2025-03-04 09:00",
                   "2025-03-06 10:15", "2025-03-01 12:00", "2025-03-06 06:45", "2025-03-06 09:30", "2025-03-02 08:00"],
})

ALLOWED = {"paid", "refunded", "failed"}
NOW = pd.Timestamp("2025-03-06 12:00")

ROW_RULES = [
    {"name": "customer_id present", "severity": "critical", "ok": lambda d: d["customer_id"].notna()},
    {"name": "amount present", "severity": "warning", "ok": lambda d: d["amount"].notna()},
    {"name": "status allowed", "severity": "critical", "ok": lambda d: d["status"].isin(ALLOWED)},
    {"name": "amount >= 0", "severity": "critical", "ok": lambda d: d["amount"].isna() | (d["amount"] >= 0)},
    {"name": "currency matches country", "severity": "warning",
     "ok": lambda d: d["country"].map({"DE": "EUR", "FR": "EUR", "US": "USD"}) == d["currency"]},
]

def dataset_rules(df, control_total):
    total = float(df["amount"].sum())
    newest_age = (NOW - pd.to_datetime(df["updated_at"]).max()).total_seconds() / 3600
    return [
        ("row count >= 8", len(df) >= 8, len(df)),
        ("order_id unique", not df["order_id"].duplicated().any(), int(df["order_id"].duplicated().sum())),
        ("total within 1% of control", abs(total - control_total) <= 0.01 * control_total, round(total, 1)),
        ("newest row < 26 h old", newest_age < 26, round(newest_age, 1)),
    ]

for name, passed, detail in dataset_rules(orders, control_total=125.0):
    print(f"{name:30} {'PASS' if passed else 'FAIL'}  measured {detail}")
```

```output
row count >= 8                 PASS  measured 10
order_id unique                FAIL  measured 1
total within 1% of control     FAIL  measured 123.4
newest row < 26 h old          PASS  measured 1.8
```
### Example 4: The failing rows

The failing rows table has one record per row and rule, and it identifies the row by its position in the frame as well as by `order_id`, because `A3` appears twice and only one of its two rows is bad. It shows which rule fails most and which rows break more than one. The clean table keeps only rows that pass every critical rule, and the counts reconcile.

```python run
import pandas as pd

orders = pd.DataFrame({
    "order_id": ["A1", "A2", "A3", "A3", "A5", "A6", "A7", "A8", "A9", "A10"],

    "amount": [19.9, 25.0, 12.5, 12.5, -5.0, 40.0, None, 7.5, 3.0, 8.0],
    "status": ["paid", "paid", "refunded", "refunded", "shipped", "paid", "failed", "paid", "PAID", "paid"],
    "currency": ["EUR", "EUR", "USD", "USD", "EUR", "EUR", "EUR", "USD", "EUR", "EUR"],
    "country": ["DE", "FR", "US", "US", "DE", "DE", "FR", "US", "DE", "US"],
    "updated_at": ["2025-03-06 08:00", "2025-03-06 07:30", "2025-03-05 22:00", "2025-03-05 22:00", "2025-03-04 09:00",
                   "2025-03-06 10:15", "2025-03-01 12:00", "2025-03-06 06:45", "2025-03-06 09:30", "2025-03-02 08:00"],
})

ALLOWED = {"paid", "refunded", "failed"}
NOW = pd.Timestamp("2025-03-06 12:00")

ROW_RULES = [
    {"name": "customer_id present", "severity": "critical", "ok": lambda d: d["customer_id"].notna()},
    {"name": "amount present", "severity": "warning", "ok": lambda d: d["amount"].notna()},
    {"name": "status allowed", "severity": "critical", "ok": lambda d: d["status"].isin(ALLOWED)},
    {"name": "amount >= 0", "severity": "critical", "ok": lambda d: d["amount"].isna() | (d["amount"] >= 0)},

     "ok": lambda d: d["country"].map({"DE": "EUR", "FR": "EUR", "US": "USD"}) == d["currency"]},
]

    ok = rule["ok"](orders)
    for row_no in orders.index[~ok]:
        failures.append({"row": row_no, "order_id": orders.loc[row_no, "order_id"], "rule": rule["name"], "severity": rule["severity"]})

critical_rows = sorted(set(fail_df.loc[fail_df["severity"] == "critical", "row"]))
clean = orders.drop(index=critical_rows)
```

### Example 5: Enforce the report

`enforce` raises `ValidationError` naming the failed critical rules, and only logs warnings. The first call runs on the raw data and stops; the second runs on the cleaned data after the critical failures are quarantined and passes with warnings.

```python run
import pandas as pd

orders = pd.DataFrame({
    "order_id": ["A1", "A2", "A3", "A3", "A5", "A6", "A7", "A8", "A9", "A10"],
    "customer_id": [10, 11, None, 12, 13, 14, None, 15, 16, 17],
    "amount": [19.9, 25.0, 12.5, 12.5, -5.0, 40.0, None, 7.5, 3.0, 8.0],
    "status": ["paid", "paid", "refunded", "refunded", "shipped", "paid", "failed", "paid", "PAID", "paid"],
    "currency": ["EUR", "EUR", "USD", "USD", "EUR", "EUR", "EUR", "USD", "EUR", "EUR"],
    "country": ["DE", "FR", "US", "US", "DE", "DE", "FR", "US", "DE", "US"],
    "updated_at": ["2025-03-06 08:00", "2025-03-06 07:30", "2025-03-05 22:00", "2025-03-05 22:00", "2025-03-04 09:00",
                   "2025-03-06 10:15", "2025-03-01 12:00", "2025-03-06 06:45", "2025-03-06 09:30", "2025-03-02 08:00"],
})

ALLOWED = {"paid", "refunded", "failed"}
NOW = pd.Timestamp("2025-03-06 12:00")

ROW_RULES = [
    {"name": "customer_id present", "severity": "critical", "ok": lambda d: d["customer_id"].notna()},
    {"name": "amount present", "severity": "warning", "ok": lambda d: d["amount"].notna()},
    {"name": "status allowed", "severity": "critical", "ok": lambda d: d["status"].isin(ALLOWED)},
    {"name": "amount >= 0", "severity": "critical", "ok": lambda d: d["amount"].isna() | (d["amount"] >= 0)},
    {"name": "currency matches country", "severity": "warning",
     "ok": lambda d: d["country"].map({"DE": "EUR", "FR": "EUR", "US": "USD"}) == d["currency"]},
]

class ValidationError(Exception):
    pass

def failed_rules(df, rules):
    return [(r["name"], r["severity"], int((~r["ok"](df)).sum())) for r in rules if (~r["ok"](df)).any()]

def enforce(df, rules):
    failed = failed_rules(df, rules)
    critical = [name for name, severity, n in failed if severity == "critical"]
    for name, severity, n in failed:
        if severity == "warning":
            print(f"warning: {name} failed on {n} rows")
    if critical:
        raise ValidationError("critical rules failed: " + ", ".join(critical))
    return len(df)

try:
    enforce(orders, ROW_RULES)
except ValidationError as exc:
    print("stopped:", exc)

keep = pd.Series(True, index=orders.index)
for rule in ROW_RULES:
    if rule["severity"] == "critical":
        keep &= rule["ok"](orders)
cleaned = orders[keep]
print("loadable rows:", enforce(cleaned, ROW_RULES))
```

```output
warning: amount present failed on 1 rows
warning: currency matches country failed on 1 rows
stopped: critical rules failed: customer_id present, status allowed, amount >= 0
warning: currency matches country failed on 1 rows
loadable rows: 6
```
## Real-world applications

- **A gate before the load.** The runner and `enforce` (Examples 2 and 5) sit between transform and load; a critical failure stops the run and the report is attached to the alert.
- **Quarantine feeds.** The failing rows table of Example 4 is the quarantine input: each row has the rule that rejected it, which tells the data owner what to fix.
- **Dataset checks against controls.** The total and row-count rules (Example 3) catch a truncated file in which every individual row looks fine.
- **A shared rule list.** Analysts and engineers review the same list of named rules, so "what do we mean by valid" has one answer.

## Daily review

### Key takeaways

- A rule is a name, a severity and a function; rules as data keep the runner fixed.
- Row-level rules return one verdict per row; dataset-level rules return one verdict and a measured value.
- Let missing values pass range and set rules, and report them once with a presence rule.
- Report per rule: checked, failing, rate, samples, verdict; keep a failing-rows table.
- Enforce by severity: critical stops the run, warnings are logged; quarantine the failing rows, then reconcile.

### Common mistakes

- Writing `d["amount"] >= 0` and failing missing amounts too, so one defect is reported by two rules. Add `d["amount"].isna() |`.
- Reporting only `PASS` or `FAIL`, which hides how many rows failed and which. Report counts, rates and samples.
- Writing row rules for everything, so an empty table passes every rule. Add dataset rules for counts and totals.
- A threshold of 0 percent on a noisy optional field, so the pipeline fails every night. Set thresholds from history.
- Never testing the rules, so a wrong comparison trusts bad data. Test each rule with a passing and a failing row.
- Concatenating empty DataFrames when nothing failed, which pandas warns about. Build the report from a list of records.

### Revision notes

- Row rule: `df -> mask`; dataset rule: `df -> (passed, detail)`.
- `df.loc[~mask, "id"]` are the failing keys; `rate = failing / checked`.
- Report: rule, severity, checked, failing, rate, sample, result.
- Enforce: raise on critical, log warnings, quarantine, reconcile.
