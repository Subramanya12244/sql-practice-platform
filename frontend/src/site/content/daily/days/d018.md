## Objectives

- Write list comprehensions that transform items, filter items, or do both, and translate between a comprehension and the equivalent `for` loop.
- Write dictionary and set comprehensions.
- Use a conditional expression inside a comprehension to choose between two values, and a trailing `if` to drop items; tell the two apart.
- Write a comprehension with two `for` clauses, and read it as nested loops.
- Decide when a plain loop is clearer than a comprehension.

## Understand

### A loop on one line

On Day 13 you built new lists with the pattern: start with an empty list, loop, maybe test, append. It takes four lines every time. A **list comprehension** expresses the same pattern in one expression inside square brackets:

```text
[expression for item in collection]
[expression for item in collection if condition]
```

Read it from the middle: "for each `item` in `collection`, (if `condition`), compute `expression` and collect the results in a new list". The comprehension is a **new list**; the source is not changed. Compare:

```text
squares = []
for n in numbers:
    squares.append(n * n)

squares = [n * n for n in numbers]
```

The two are the same loop. The first part, the **expression**, says what goes into the new list. The `for` clause says where the items come from. The optional `if` clause at the end is a **filter**: only the items for which the condition is true are processed.

### Transform, filter, or both

- **Transform** (map): `[len(w) for w in words]` gives the length of every word.
- **Filter**: `[w for w in words if len(w) > 3]` keeps only the long words, unchanged.
- **Both**: `[w.upper() for w in words if len(w) > 3]` filters first, then transforms what remains.

A very common mistake is to mix up the two places where a condition can appear. A trailing `if` **removes items**. A conditional expression (`a if c else b`, Day 7) **chooses between two values and keeps every item**, and it goes at the **front**, in the expression part: `["big" if n > 10 else "small" for n in numbers]` gives one result per number. If you write `[n for n in numbers if n > 10 else 0]`, Python reports a `SyntaxError`, because `else` belongs to the front part.

### Why comprehensions instead of map and filter

On Day 17 you used `map` and `filter` with lambdas. A comprehension says the same thing in a form most Python programmers find easier to read, because it has no `lambda`, no `list()` wrapper, and the condition and the expression are written naturally. `list(map(lambda n: n * n, filter(lambda n: n % 2 == 0, numbers)))` becomes `[n * n for n in numbers if n % 2 == 0]`.

### Dictionary and set comprehensions

Curly brackets give the other two kinds. A **dictionary comprehension** builds key-value pairs: `{key_expression: value_expression for item in collection}`. For example `{w: len(w) for w in words}` maps each word to its length; if a key repeats, the later value replaces the earlier one. A **set comprehension** has curly brackets with a single expression and builds a set, so duplicates disappear: `{w.lower() for w in words}`. Remember from Day 9 that empty `{}` is a dictionary, and that sets have no reliable order, so sort before printing.

### Two for clauses

A comprehension can have more than one `for`, which reads like nested loops written in the **same order**:

```text
[(a, b) for a in first for b in second]
```

is the same as an outer loop over `first` and an inner loop over `second`. This is handy for combinations and for flattening a list of lists: `[x for row in table for x in row]`. With a table (list of rows), the row loop comes first and the cell loop second.

### Looking at the loop variable

The loop variable of a comprehension exists only inside it. Unlike a `for` statement, it does not stay behind afterwards, and it does not overwrite a variable with the same name outside the comprehension.

### When not to use a comprehension

A comprehension is for **building a new collection**. If you only want to run an action for each item, such as printing, use a `for` loop; writing `[print(x) for x in items]` builds a useless list of `None`. If the logic needs several steps, several conditions or error handling, a loop with named intermediate variables is easier to read and debug. If your comprehension does not fit comfortably on one line, or has more than one `for` and an `if`, that is a signal to use a loop or a helper function from Day 14. Clear code beats short code.

### A worked trace of a comprehension

Expand `[n * n for n in [1, 2, 3, 4] if n % 2 == 0]` into its loop. Start with an empty result. Take `n = 1`: the condition `1 % 2 == 0` is false, so nothing is added. Take `n = 2`: the condition is true, so `2 * 2 = 4` is added. Take `n = 3`: skipped. Take `n = 4`: `16` is added. The result is `[4, 16]`. The order in the text, expression first and condition last, is not the order of execution: Python runs the `for`, then the `if`, then the expression. If a comprehension puzzles you, rewrite it as the four-line loop and trace that.

A comprehension builds the whole list in memory at once. When you only need a total or a count, a **generator expression**, the same syntax in round brackets passed straight to a function such as `sum()`, produces the items one at a time without storing them. `sum(n * n for n in numbers)` gives the same answer as `sum([n * n for n in numbers])`, but never builds the list, which matters for very large data. You will not need this often at first; the habit that matters now is choosing the simplest tool that is easy to read.

## Syntax and key functions

```text
[expr for x in items]
[expr for x in items if cond]
[a if cond else b for x in items]
{key_expr: value_expr for x in items}
{expr for x in items}
[expr for x in outer for y in inner]
```

- The result of square brackets is a list, curly brackets with a colon a dictionary, curly brackets without a colon a set.
- Trailing `if`: drops items. Leading `a if c else b`: picks a value for every item.
- Multiple `for` clauses run like nested loops, left to right.

| Form | Result |
|---|---|
| `[f(x) for x in items]` | list of `f(x)` for every item |
| `[x for x in items if c(x)]` | the items that pass the test |
| `{k: v for ...}` | dictionary |
| `{x for ...}` | set of the distinct results |
| `sum(x for x in items)` | a total, without building a list (a generator expression, with no brackets) |
| `sorted(...)`, `len(...)` | commonly wrapped around a comprehension |

## Learn by example

### Example 1: From loop to comprehension

```python run
numbers = [1, 2, 3, 4, 5, 6]

squares_loop = []
for n in numbers:
    squares_loop.append(n * n)

squares = [n * n for n in numbers]
print(squares_loop == squares, squares)
print([n * 10 for n in numbers])
print([w.upper() for w in ["ada", "bo"]])
```

```output
True [1, 4, 9, 16, 25, 36]
[10, 20, 30, 40, 50, 60]
['ADA', 'BO']
```

The loop and the comprehension give equal lists.

### Example 2: Filtering and both

```python run
numbers = [1, 2, 3, 4, 5, 6, 7, 8]
evens = [n for n in numbers if n % 2 == 0]
big_squares = [n * n for n in numbers if n > 5]
words = ["data", "sql", "python", "go", "pandas"]
long_upper = [w.upper() for w in words if len(w) > 3]
print(evens)
print(big_squares)
print(long_upper)
print(numbers)
```

```output
[2, 4, 6, 8]
[36, 49, 64]
['DATA', 'PYTHON', 'PANDAS']
[1, 2, 3, 4, 5, 6, 7, 8]
```

The condition filters, then the expression transforms what remains. `numbers` is unchanged.

### Example 3: A conditional expression versus a trailing if

```python run
scores = [45, 82, 67, 30, 91]
labels = ["pass" if s >= 50 else "fail" for s in scores]
print(labels)
passed = [s for s in scores if s >= 50]
print(passed)
print(len(labels), len(passed))
capped = [min(s, 80) for s in scores]
print(capped)
```

```output
['fail', 'pass', 'pass', 'fail', 'pass']
[82, 67, 91]
5 3
[45, 80, 67, 30, 80]
```

`labels` has one result per score (five). `passed` has only the scores that pass (three).

### Example 4: Dictionary and set comprehensions

```python run
words = ["data", "sql", "python", "data", "sql", "pandas"]
lengths = {w: len(w) for w in words}
print(lengths)
unique_upper = {w.upper() for w in words}
print(sorted(unique_upper))
prices = {"pen": 2.5, "desk": 150.0, "ink": 8.0}
expensive = {name: p for name, p in prices.items() if p > 5}
print(expensive)
with_tax = {name: round(p * 1.2, 2) for name, p in prices.items()}
print(with_tax)
swapped = {p: name for name, p in prices.items()}
print(swapped)
```

```output
{'data': 4, 'sql': 3, 'python': 6, 'pandas': 6}
['DATA', 'PANDAS', 'PYTHON', 'SQL']
{'desk': 150.0, 'ink': 8.0}
{'pen': 3.0, 'desk': 180.0, 'ink': 9.6}
{2.5: 'pen', 150.0: 'desk', 8.0: 'ink'}
```

The duplicate words collapse in both the dictionary (same key, same value) and the set. Looping over `prices.items()` gives the pairs, unpacked into `name` and `p`.

### Example 5: Two for clauses

```python run
sizes = ["S", "M"]
colors = ["red", "blue", "green"]
combos = [s + "-" + c for s in sizes for c in colors]
print(combos)
table = [[1, 2, 3], [4, 5, 6], [7, 8, 9]]
flat = [x for row in table for x in row]
print(flat)
diagonal = [table[i][i] for i in range(len(table))]
print(diagonal)
print([x for row in table for x in row if x % 2 == 1])
```

```output
['S-red', 'S-blue', 'S-green', 'M-red', 'M-blue', 'M-green']
[1, 2, 3, 4, 5, 6, 7, 8, 9]
[1, 5, 9]
[1, 3, 5, 7, 9]
```

The order of the `for` clauses matches the nested loops from Day 13: rows first, then the cells in each row.

### Example 6: A realistic cleaning pipeline

Records arrive as text. The comprehensions parse them, drop the invalid ones, and build a lookup table.

```python run
lines = ["Ada,36,London", "Bo,abc,Leeds", "Cy,41,York", "Di,29,", "Ed,52,Hull"]
rows = [line.split(",") for line in lines]
valid = [r for r in rows if r[1].isdigit() and r[2] != ""]
people = [{"name": r[0], "age": int(r[1]), "city": r[2]} for r in valid]
by_name = {p["name"]: p for p in people}
ages = [p["age"] for p in people]
print(len(rows), len(valid))
print(by_name["Cy"])
print(sum(ages) / len(ages))
over_40 = sorted({p["city"] for p in people if p["age"] > 40})
print(over_40)
print(sum(1 for p in people if p["age"] < 50))
```

```output
5 3
{'name': 'Cy', 'age': 41, 'city': 'York'}
43.0
['Hull', 'York']
2
```

The last line uses a **generator expression** (a comprehension without brackets, passed straight to `sum`) to count the people under 50 without building a list.

## Real-world applications

- **Cleaning columns.** `[s.strip().lower() for s in column]` normalises a whole column of text.
- **Selecting records.** `[r for r in records if r["status"] == "paid"]` is the filter step of most small data scripts.
- **Lookup tables.** `{r["id"]: r for r in records}` builds a dictionary for fast search by key instead of searching a list each time.
- **Counting and distinct values.** `{r["city"] for r in records}` gives the distinct cities; `sum(1 for ...)` counts matches.

## Daily review

### Key takeaways

- A list comprehension is the "new list" loop in one expression: `[expr for x in items if cond]`.
- A trailing `if` drops items; a leading `a if c else b` picks a value for every item.
- `{k: v for ...}` builds a dictionary, `{x for ...}` a set.
- Several `for` clauses read like nested loops in the same order.
- Use a plain loop when the logic is long, has side effects, or is hard to read.

### Common mistakes

- **Putting `else` in the trailing condition.** `[x for x in items if x > 0 else 0]` is a `SyntaxError`. Put the conditional expression at the front: `[x if x > 0 else 0 for x in items]`.
- **Using a comprehension just for its side effects.** `[print(x) for x in items]` builds a list of `None`. Use a `for` loop.
- **Expecting `{}` to make a set.** `{x for ...}` is a set, but an empty `{}` is a dictionary.
- **Reversing the order of two `for` clauses.** `[x for x in row for row in table]` raises `NameError: name 'row' is not defined`. Write the outer loop first.
- **Overlong comprehensions.** Three clauses and two conditions on one line cannot be read or debugged. Break the work into steps.
- **Forgetting that duplicates vanish.** A set or dictionary comprehension merges repeats, so the result can be shorter than the input.

### Revision notes

- `[expr for x in items if cond]`; filter at the end, choose-a-value at the front.
- `{k: v for ...}`, `{x for ...}`; sort a set before printing.
- Two `for`s: outer first.
- If it needs a comment to explain, write a loop.
