## Objectives

- Define a function with `def`, give it parameters and call it with arguments.
- Return a value with `return` and explain the difference between returning and printing.
- Predict what a function returns when it has no `return` statement or returns early.
- Return several values as a tuple and unpack them in the caller.
- Write a docstring and use `help()` or `.__doc__` to read it.

## Understand

### Why functions

In the last three days you wrote the same patterns again and again: a total, a filter, a maximum. A **function** is a named block of code that you can run whenever you need it, with different inputs each time. You have already used many built-in functions, such as `len()`, `sum()` and `print()`. Now you write your own. Functions give you three things: no repeated code, a name that says what the code does, and a unit you can test on its own.

A good picture is a small machine with a label. You put things in (the inputs), it does its job, and it hands something back (the output). You do not need to know how it works inside to use it.

### Defining and calling

```text
def function_name(parameter1, parameter2):
    block
    return result
```

The word `def` starts the **definition**. The **parameters** are the names for the inputs, listed in brackets. The block is indented. Defining a function does not run it: it only stores it under its name. You run it with a **call**: `function_name(argument1, argument2)`. The values you pass in the call are the **arguments**, and each one is matched to a parameter by **position**, in order. The words are easy to mix up: parameters are in the definition, arguments are in the call.

Calling a function with the wrong number of arguments raises `TypeError: add() takes 2 positional arguments but 3 were given` (or "missing 1 required positional argument").

A function must be defined **before** the line that calls it runs. Python reads the file from top to bottom, so putting the definition above the first call is the safe habit.

### return and print are different

`return value` ends the function and hands `value` back to the caller. The caller can store it, print it or use it in a calculation: `total = add(2, 3)`. `print()` only shows text on the screen; it gives nothing back. The classic misconception is to write `print(...)` inside a function and then try to use the "result": the call returns `None`, so `add(2, 3) * 2` fails or shows `None`.

If a function reaches the end without a `return`, it returns `None` automatically. A bare `return` also gives `None`. `return` ends the function at once, so lines after it in the same path never run. This allows **early returns**: `if not values: return None` at the top deals with an empty input before the main work, a simple form of the guard clause from Day 7.

### Returning several values

A function returns exactly one object, but that object can be a tuple, so `return low, high` returns the pair `(low, high)`. The caller unpacks it (Day 9): `low, high = min_max(values)`. This is how Python functions give back more than one result.

### Local names

The parameters and any names created inside a function exist only while it runs. They are **local** to the function: the rest of the program cannot see them, and a name inside does not overwrite a name with the same spelling outside. This protects your code from accidental clashes, and you will study the rules fully on Day 16. For now, remember: send data in through parameters and get results out through `return`.

### Docstrings

A **docstring** is a string placed on the first line of the function's block. It documents what the function does, what the parameters mean and what it returns. Tools such as `help(function)` show it, and it is available as `function.__doc__`. Write one short sentence for simple functions and add more when the behaviour is not obvious. A docstring is not a comment: it is stored with the function.

### Designing a good function

Give a function one job and a name that is a verb phrase, such as `total_price` or `is_valid_email`. Prefer functions that **return** a result over functions that print it, because a returned value can be tested and reused. Keep the printing in the part of the program that calls the function. A function that is longer than one screen usually does more than one job and can be split.

### A worked trace of a call

Trace `def double(n): return n * 2` followed by `result = double(5) + 1`. Python evaluates the right-hand side from left to right. To evaluate `double(5)` it creates a new local scope in which the parameter `n` is bound to the argument 5. It runs the block, evaluates `n * 2` as 10, and `return` hands 10 back and discards the local scope, so `n` no longer exists. The call expression is now replaced by 10, so the rest of the line becomes `10 + 1`, and `result` is 11. Thinking of a call as "replaced by its return value" explains why `print(double(5))` prints 10, and why a function with no `return` makes a call evaluate to `None`.

A related point is what a function can change. A parameter is a new name for the object you passed in. If the function assigns a new value to the parameter (`n = n + 1`), only the local name changes and the caller's variable stays as it was. But if you pass a list and the function calls `items.append(4)`, it changes the one list the caller also holds (Day 8), so the caller sees the change. A function that changes its input is hard to reason about, so prefer to build and return a new list, and say clearly in the docstring when a function changes its argument.

## Syntax and key functions

```text
def name(param1, param2):
    """One-line description."""
    ...
    return value

result = name(arg1, arg2)       # call, store the result
a, b = pair_function(x)         # unpack a returned tuple
help(name)                      # show the docstring
name.__doc__                    # the docstring as a string
```

- The colon and the indented block are required, as for `if` and `for`.
- Arguments are matched to parameters by position.
- `return` ends the function; no `return` means `None` is returned.

| Item | Meaning |
|---|---|
| `def` | defines a function |
| parameter | a name in the definition that receives an input |
| argument | a value supplied in the call |
| `return value` | ends the function and gives `value` back |
| docstring | first string in the block; read by `help()` |
| `callable(x)` | `True` if `x` can be called like a function |

## Learn by example

### Example 1: The first function

```python run
def greet(name):
    return "Hello, " + name + "!"

message = greet("Ada")
print(message)
print(greet("Bo"))
print(len(greet("Cy")))
```

```output
Hello, Ada!
Hello, Bo!
10
```

`greet("Ada")` gives back a string. That string is stored, printed, or passed on to `len()`.

### Example 2: Return versus print

```python run
def show_total(a, b):
    print(a + b)

def get_total(a, b):
    return a + b

x = show_total(2, 3)
y = get_total(2, 3)
print(x, y)
print(y * 10)
```

```output
5
None 5
50
```

`show_total` printed 5 but gave nothing back, so `x` is `None`. `get_total` returned 5, which can be used in further calculations.

### Example 3: An early return and a docstring

```python run
def average(values):
    """Return the mean of a list of numbers, or None for an empty list."""
    if not values:
        return None
    return sum(values) / len(values)

print(average([4, 8, 6]))
print(average([]))
print(average.__doc__)
```

```output
6.0
None
Return the mean of a list of numbers, or None for an empty list.
```

`not values` is true for an empty list (truthiness, Day 6), so the function returns early and never divides by zero.

### Example 4: Returning two values

```python run
def min_max(values):
    return min(values), max(values)

pair = min_max([7, 2, 9, 4])
print(pair)
low, high = min_max([7, 2, 9, 4])
print(low, high, high - low)
```

```output
(2, 9)
2 9 7
```

### Example 5: Reusing a function for several calls

The function wraps the filter pattern from Day 13. Different arguments give different results without repeating the loop.

```python run
def above(values, limit):
    """Return the values greater than limit, in order."""
    result = []
    for v in values:
        if v > limit:
            result.append(v)
    return result

temps = [18, 25, 31, 22, 29]
print(above(temps, 24))
print(above(temps, 30))
print(len(above(temps, 0)))
```

```output
[25, 31, 29]
[31]
5
```

### Example 6: A small toolkit that works on records

Several small functions with one job each, combined by a short main part. The total and the label are returned, and only the last lines print.

```python run
def line_total(price, quantity):
    """Return price times quantity."""
    return price * quantity

def order_total(lines):
    """Return the sum of the line totals of (price, quantity) tuples."""
    total = 0
    for price, quantity in lines:
        total += line_total(price, quantity)
    return total

def size_label(total):
    """Return 'small', 'medium' or 'large' for an order total."""
    if total < 20:
        return "small"
    if total < 100:
        return "medium"
    return "large"

basket = [(4.5, 2), (12.0, 3), (1.25, 4)]
amount = order_total(basket)
print(amount, size_label(amount))
print(size_label(order_total([(2.0, 3)])))
```

```output
50.0 medium
small
```

## Real-world applications

- **Reusable cleaning steps.** A function such as `clean_name(text)` applies the same fix to every row of every file.
- **Business rules in one place.** `size_label` holds the thresholds once; a change is made in one place only.
- **Testable calculations.** A function that returns a value can be checked with a single call and a known answer, which is how data code is tested.
- **Building pipelines.** Small functions that each do one step can be chained: extract, clean, calculate, report.

## Daily review

### Key takeaways

- `def name(parameters):` defines; `name(arguments)` calls; arguments match parameters by position.
- `return` gives a value to the caller and ends the function; no `return` gives `None`.
- Return values instead of printing them when you want to reuse the result.
- Return several values as a tuple and unpack them.
- A docstring on the first line documents the function.

### Common mistakes

- **Printing instead of returning.** `print(a + b)` inside the function leaves `result = f(...)` as `None`, so `result * 2` raises `TypeError: unsupported operand type(s) for *: 'NoneType' and 'int'`. Use `return`.
- **Forgetting the call brackets.** `greet` alone is the function object, not its result. Write `greet("Ada")`.
- **Wrong number of arguments.** `TypeError: average() takes 1 positional argument but 2 were given`. Match the parameters.
- **Calling before defining.** `NameError: name 'greet' is not defined` when the call runs above the `def`.
- **Code after `return`.** Lines after a `return` on that path never run. Put the `return` last.
- **Returning inside a loop too early.** A `return` in the first pass of a loop ends the function after one item. Return after the loop if you need all items.

### Revision notes

- `def`, parameters, block, `return`.
- Call with arguments; positional matching.
- `return` versus `print`; no return is `None`.
- `return a, b` is a tuple; unpack with `x, y = f()`.
- Docstring first line; `help(f)`.
