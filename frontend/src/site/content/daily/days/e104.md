## Objectives

- Navigate nested JSON (objects inside objects, arrays of objects) and read a value by path without `KeyError` or `TypeError`.
- Distinguish a missing key, a key with the value `null` and an empty list, and handle each deliberately.
- Flatten nested records into a table with `pandas.json_normalize`, including exploding an array with `record_path` and `meta`.
- Detect schema drift (added, removed, renamed fields and changed types) by comparing each record with an expected schema.
- Turn a response body into a DataFrame with a fixed set of columns even when the API adds or drops fields.

## Understand

### Why parsing is where pipelines break

Day 101 parsed JSON text into Python values. The values are dictionaries, lists and scalars nested inside each other, and the shape belongs to the provider, who can change it without asking you. Most API ingestion failures are not network failures; they are a `KeyError` on a field that disappeared, a `TypeError` from treating `None` as a dictionary, or a column that became text because one record sent `"12.50"` instead of `1250`. Parsing defensively means deciding, for every field, what your pipeline does when the shape is not the one you expected.

The Orders API of this block returns flat records (`order_id`, `customer_id`, `amount_cents`, `currency`, `status`, `created_at`). Real APIs often return richer, nested records, and some provide an option to expand related objects. Today's practice data is a richer, made-up variant of an order with a nested `customer` object, a list of `items` and an optional `discount`.

### Nested structures and paths

An **object** inside an object is read with chained lookups: `order["customer"]["address"]["city"]`. An **array** of objects is read with a loop or an index: `order["items"][0]["sku"]`. A chain like that fails in three different ways. `KeyError` when a key is absent. `TypeError` when an intermediate value is `None` (you cannot look up `"city"` in `None`). `IndexError` when the list is empty. Three different states need three different decisions.

A **missing key** (`discount` not present) usually means "not applicable". A key with the value **`null`** (`"address": null`) means the provider knows the field exists and has no value. An **empty list** (`"items": []`) is a valid answer with zero elements, and iterating over it is safe. A helper that walks a path and returns a default whenever anything is wrong turns the first two states into one `None`. That is convenient for optional fields and wrong for required ones: a missing `order_id` must stop the record, not become `None` in your table.

### Safe access, used on purpose

`dict.get("key", default)` avoids `KeyError` for one level. For several levels, a small function that walks the path is clearer than a chain of `.get` calls: it checks at each step that the current value is a dictionary and that it has the key. Use it for **optional** fields, and use plain indexing for **required** ones, so that a missing required field fails loudly at the record that caused it. Hiding every error behind defaults only moves the failure into the database, where it is harder to find.

### Flattening with `json_normalize`

A table needs one value per cell, so nested records must be **flattened**. `pandas.json_normalize(records, sep="_")` turns each nested object into columns named by path: `customer_id`, `customer_name`, `customer_address_city`. Keys that are missing in some records give `NaN` in those rows. An array cannot become columns without a rule; `record_path="items"` produces **one row per element** of the array, and `meta=["order_id", ["customer", "id"]]` copies parent fields onto each of those rows. The result is the right shape for a child table: one row per order line with the order's key beside it, which is the normalised design from Day 98. If a `meta` field may be absent in some records, pass `errors="ignore"` and the value becomes `NaN` instead of raising a `KeyError`. An empty list contributes no rows, so an order with no items does not appear in the item table at all: count it separately if it matters.

### Schema drift

**Schema drift** is any change in the shape of the data between deliveries: a field **added** (harmless to most code, but it should be noticed), **removed** (breaks code that needs it), **renamed** (looks like one removed and one added), or **retyped** (`amount_cents` changing from `1990` to `"1990"` or to `19.9`). Detect it by comparing each record to an **expected schema**: a table of required fields with types, and optional fields with types. A function returns a list of issues per record, such as `missing required: status` or `amount_cents: expected int, got str`. The pipeline then applies a policy: records with issues go to a quarantine list for inspection while good records continue, and a sudden large share of quarantined records fails the run (a rename affects every record). Unknown extra fields are logged, not silently dropped, because they may signal a new feature or a rename.

### Common misconception

Learners write one lucky parsing script against the first response and consider the API understood. Responses vary by record: the first page may contain no record with a missing `discount`, and the bug shows up on page 40. Test the parser on the records that are difficult, such as an empty list, a `null` object and a missing key, before trusting it.

### Why it matters

A database table has fixed columns and types. The parsing step is the boundary where the provider's unstable shape becomes your stable one. Doing it with explicit rules gives you a list of problems instead of a failed load or, worse, a successful load of wrong data.

## Syntax and key functions

```python
def dig(data, path, default=None):
    """Read 'a.b.c' from nested dictionaries; default if any step is missing or not a dict."""
    for key in path.split("."):
        if isinstance(data, dict) and key in data:
            data = data[key]
        else:
            return default
    return data
```

```python
import pandas as pd

flat = pd.json_normalize(records, sep="_")
lines = pd.json_normalize(records, record_path="items", meta=["order_id", ["customer", "id"]], sep="_", errors="ignore")

```

| Item | What it does or returns |
|---|---|
| `d.get(key, default)` | One-level safe lookup. |
| `pd.json_normalize(records, sep="_")` | DataFrame with nested objects flattened to `a_b` columns. |
| `record_path="items"` | One row per element of that list. |
| `meta=[...]` | Parent fields copied onto each exploded row; a nested key is a list path. |
| `errors="ignore"` | Missing `meta` keys become `NaN`. |
| `df.reindex(columns=cols)` | Fixed column set; missing columns are added as `NaN`, extras dropped. |
| `isinstance(v, dict)` | Guard before a lookup. |
| `set(record) - set(expected)` | Unknown fields; the other direction gives missing ones. |

## Learn by example

### Example 1: Missing key, null and empty list

Three nested orders show the three states: the first has everything, the second has `address: null`, no `discount` key and one item, the third has an empty `items` list. The code reads the city with chained indexing (which fails in two ways) and with the path helper, and reads the discount and the first SKU safely.

```python run
orders = [
    {"order_id": 1, "status": "paid", "customer": {"id": 8, "name": "Ana", "address": {"city": "Lisbon", "country": "PT"}},
     "items": [{"sku": "P1", "qty": 2, "price_cents": 500}, {"sku": "P2", "qty": 1, "price_cents": 1200}],
     "discount": {"code": "SPRING", "percent": 10}},
    {"order_id": 2, "status": "refunded", "customer": {"id": 9, "name": "Ben", "address": None},
     "items": [{"sku": "P1", "qty": 1, "price_cents": 500}]},
    {"order_id": 3, "status": "paid", "customer": {"id": 8, "name": "Ana", "address": {"city": "Lisbon", "country": "PT"}},
     "items": []},
]

def dig(data, path, default=None):
    for key in path.split("."):
        if isinstance(data, dict) and key in data:
            data = data[key]
        else:
            return default
    return data

for order in orders:
    try:
        city = order["customer"]["address"]["city"]
    except (KeyError, TypeError) as err:
        city = f"{type(err).__name__}"
    first_sku = order["items"][0]["sku"] if order["items"] else None
    print(order["order_id"], city, dig(order, "customer.address.city", "unknown"),
          dig(order, "discount.percent", 0), first_sku, len(order["items"]))
```

```output
1 Lisbon Lisbon 10 P1 2
2 TypeError unknown 0 P1 1
3 Lisbon Lisbon 0 None 0
```

Order 2 raised `TypeError` (the address is `None`) with plain indexing, while the helper gave `unknown`. The missing discount key became `0`, which is right for an optional field but would be wrong for `order_id`.

### Example 2: `json_normalize` flattens and explodes

The same orders are flattened into one row per order (nested objects become `customer_name` and so on) and into one row per item with the order id and customer id copied down. Two details appear in the output. The `address: null` of order 2 gives `NaN` in `customer_address_city` and also creates a separate, all-`NaN` column `customer_address` for the null itself, a leftover you would drop. Order 3, with no items, produces no item row.

```python run
import pandas as pd

orders = [
    {"order_id": 1, "status": "paid", "customer": {"id": 8, "name": "Ana", "address": {"city": "Lisbon"}},
     "items": [{"sku": "P1", "qty": 2, "price_cents": 500}, {"sku": "P2", "qty": 1, "price_cents": 1200}]},
    {"order_id": 2, "status": "refunded", "customer": {"id": 9, "name": "Ben", "address": None},
     "items": [{"sku": "P1", "qty": 1, "price_cents": 500}]},
    {"order_id": 3, "status": "paid", "customer": {"id": 8, "name": "Ana", "address": {"city": "Lisbon"}}, "items": []},
]

head = pd.json_normalize(orders, sep="_").drop(columns="items")
print(head.to_string(index=False))
lines = pd.json_normalize(orders, record_path="items", meta=["order_id", ["customer", "id"]], sep="_")
print(lines.to_string(index=False))
print(lines.groupby("order_id")["qty"].sum().to_dict(), sorted(set(head["order_id"]) - set(lines["order_id"])))
```

```output
 order_id   status  customer_id customer_name customer_address_city  customer_address
        1     paid            8           Ana                Lisbon               NaN
        2 refunded            9           Ben                   NaN               NaN
        3     paid            8           Ana                Lisbon               NaN
sku  qty  price_cents order_id customer_id
 P1    2          500        1           8
 P2    1         1200        1           8
 P1    1          500        2           9
{1: 3, 2: 1} [3]
```

The header table has three rows and the item table has three rows too, but for different reasons: order 1 has two items, order 2 has one, order 3 has none. The last line lists order 3 as an order without items.

### Example 3: Detect schema drift record by record

The expected schema lists required and optional fields with their types. `check` returns the issues for one record: missing required fields, wrong types, and unknown fields. Four records show an added field, a removed field and a retyped field. Bad records are quarantined and good ones kept, and the final line shows the policy that stops the run when too many records are bad.

```python run
REQUIRED = {"order_id": int, "customer_id": int, "amount_cents": int, "currency": str, "status": str, "created_at": str}
OPTIONAL = {"coupon": str}

def check(record):
    issues = []
    for name, kind in REQUIRED.items():
        if name not in record:
            issues.append(f"missing required: {name}")
        elif type(record[name]) is not kind:
            issues.append(f"{name}: expected {kind.__name__}, got {type(record[name]).__name__}")
    for name, kind in OPTIONAL.items():
        if name in record and record[name] is not None and type(record[name]) is not kind:
            issues.append(f"{name}: expected {kind.__name__}, got {type(record[name]).__name__}")
    unknown = sorted(set(record) - set(REQUIRED) - set(OPTIONAL))
    if unknown:
        issues.append("unknown fields: " + ", ".join(unknown))
    return issues

base = {"order_id": 1, "customer_id": 8, "amount_cents": 1990, "currency": "EUR", "status": "paid", "created_at": "2026-03-05T10:30:00Z"}
batch = [
    base,
    {**base, "order_id": 2, "coupon": "SPRING"},
    {**base, "order_id": 3, "amount_cents": "1990"},
    {k: v for k, v in base.items() if k != "status"} | {"order_id": 4, "state": "paid"},
]
good, quarantine = [], []
for record in batch:
    issues = check(record)
    (quarantine if issues else good).append((record["order_id"], issues))
print([i for i, _ in good])
for order_id, issues in quarantine:
    print(order_id, issues)
share = len(quarantine) / len(batch)
print("stop the run" if share > 0.2 else "continue", round(share, 2))
```

```output
[1, 2]
3 ['amount_cents: expected int, got str']
4 ['missing required: status', 'unknown fields: state']
stop the run 0.5
```

Order 4 shows why a rename looks like two problems: `status` is missing and `state` is unknown. Order 3 is the silent killer: `"1990"` looks right on screen but sums as text.

### Example 4: A fixed table from a drifting page

A page body arrives with an extra field and one record missing the `currency` field. The code builds the DataFrame with `reindex(columns=EXPECTED)`, so the table always has the same columns in the same order, reports the extra column it dropped, and counts missing values per column so a drift is visible.

```python run
import pandas as pd

EXPECTED = ["order_id", "customer_id", "amount_cents", "currency", "status", "created_at"]
page = {"data": [
    {"order_id": 1, "customer_id": 8, "amount_cents": 1990, "currency": "EUR", "status": "paid", "created_at": "2026-03-05T10:30:00Z", "channel": "web"},
    {"order_id": 2, "customer_id": 9, "amount_cents": 700, "status": "refunded", "created_at": "2026-03-05T11:00:00Z"},
], "page": 1, "total_pages": 1}

raw = pd.DataFrame(page["data"])
extra = sorted(set(raw.columns) - set(EXPECTED))
table = raw.reindex(columns=EXPECTED)
print("extra columns:", extra)
print(list(table.columns))
print(table["currency"].tolist())
print(table.isna().sum().to_dict())
```

```output
extra columns: ['channel']
['order_id', 'customer_id', 'amount_cents', 'currency', 'status', 'created_at']
['EUR', nan]
{'order_id': 0, 'customer_id': 0, 'amount_cents': 0, 'currency': 1, 'status': 0, 'created_at': 0}
```

The table has the six agreed columns whatever the provider sends. The missing currency is `NaN`, and the null count points at it; Day 109 decides what to do with such values.

## Real-world applications

- **Order detail pipelines.** Orders with nested customers and item lists are split into an order table and an order-line table with `record_path` and `meta`, ready for the loading days.
- **Early drift alerts.** A schema check that reports "new field `channel`" or "`amount_cents` is a string in 12 percent of records" lets the team talk to the provider before the dashboards break.
- **Optional fields.** Coupons, notes and addresses are optional; the path helper gives defaults for those without hiding errors in the required ones.
- **Quarantine review.** Records with issues are written to a table for review rather than dropped, so a data owner can see what the provider sent.

## Daily review

### Key takeaways

- Nested JSON has three distinct empty states: missing key, `null` and empty list.
- Use safe access for optional fields and plain indexing for required ones.
- `json_normalize` flattens objects; `record_path` and `meta` turn an array into child rows.
- Schema drift: added, removed, renamed and retyped fields; check every record against an expected schema.
- Fix the column set with `reindex` so that the table does not change shape.

### Common mistakes

- **Chained indexing on optional objects.** `order["customer"]["address"]["city"]` raises `TypeError` when the address is `null`. Guard it.
- **Defaults on required fields.** `record.get("order_id")` puts `None` keys in the database. Require them.
- **Forgetting `errors="ignore"` in `meta`.** A record without the meta key raises `KeyError` in `json_normalize`.
- **Counting rows of the child table as orders.** Orders without items disappear from it.
- **Comparing types with `isinstance(True, int)`.** `bool` is a subclass of `int`; use `type(v) is int` when a boolean must not pass.

### Revision notes
