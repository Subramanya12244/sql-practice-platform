## Objectives

- Assemble an incremental ETL pipeline from the pieces of Days 120 to 130: extract, pure transforms, quarantine, watermark, guarded upsert, run metrics.
- Reconcile every run: rows read equal quarantined plus duplicates plus skipped plus loaded.
- Prove idempotency and late-data handling with reruns and a lookback window.
- Test the transforms and the whole run, and report the run history and freshness.

## Understand

### What the project builds

This project day builds one pipeline from the parts of the ETL phase, the one the pipeline specification described from Day 120: orders arrive as CSV text, small pure functions clean them (`clean_amount`, `parse_ts`, `dedupe_latest`), bad rows are quarantined with a reason, the good rows are loaded into the `sqlite3` table `orders_clean` (the stand-in for PostgreSQL), and a one-row table `etl_state` holds the watermark. Each run writes one row to `etl_runs` with its counts. Nothing here is new; the skill of the day is putting the parts in the right order and proving that they work together.

### The order of one run

A run does these steps in order. Extract the CSV into raw rows. Transform: validate each row, quarantine the bad ones with the raw text, keep the good ones, and remove duplicates by key, keeping the latest. Read the watermark and choose the rows newer than it (minus an optional lookback). Then, in **one transaction**, upsert those rows with the `updated_at` guard, move the watermark to the maximum loaded timestamp, write the quarantined rows and write the `etl_runs` record. Doing all four writes in one transaction means a failed run leaves no trace and the next run starts at the same watermark. After the transaction the run returns its result dictionary.

### Reconciliation

Every row read must be accounted for: `read = quarantined + duplicates + skipped + loaded`. Here `duplicates` are older versions of a key inside the same file, `skipped` are rows at or below the watermark that were already loaded earlier, and `loaded` are the rows written by this run. If the equation fails, a row was lost or counted twice, and the run is not trusted. The equation is computed from the stored `etl_runs` row, not from a counter in the code, so it checks what was actually written.

### Idempotency and late data

Running the same file twice must change nothing: the second run finds every row at or below the watermark, so `loaded` is 0 and the table is unchanged. (With a lookback the rerun rereads the recent rows, so `loaded` is above 0, but the guard leaves their values as they were.) A late row, stamped before the watermark, is invisible to a strict run; a lookback window of 24 hours rereads the recent rows, and the guarded upsert makes the reread harmless. The project proves both with runs, not with arguments.

### Tests

Two kinds of tests protect the pipeline. Table-driven tests on the pure functions (Day 121) cover the edge cases of cleaning. A whole-run test uses a small CSV text, runs it twice, and asserts the counts, the final rows and that the second run loads nothing. Together they run in milliseconds and need no database server.

## Syntax and key functions

```python
result = run(conn, text, lookback_hours=24)
assert result["read"] == result["quarantined"] + result["duplicates"] + result["skipped"] + result["loaded"]
```

| Item | What it does or returns |
|---|---|
| `extract(text)` | CSV text to a list of dicts. |
| `transform(raw)` | `(good, quarantined, duplicates_removed)`; good rows are unique by key. |
| `run(conn, text, lookback_hours)` | One incremental run in one transaction; returns the counts. |
| `etl_state` | One row: the watermark. |
| `etl_runs` | One row per run with the counts and the watermark after it. |
| `quarantine` | Rejected rows with run id, reason and raw value. |
| reconciliation | `read = quarantined + duplicates + skipped + loaded`. |

## Learn by example

### Example 1: The pipeline and the first run

The code is the whole pipeline. The first run reads the seven rows of the first file: one row is quarantined (`abc`), one duplicate version of order 3 is removed and five orders are loaded. The watermark moves to the newest loaded timestamp.

```python run
import csv
import io
import sqlite3
from datetime import datetime, timedelta, timezone

FMT = "%Y-%m-%dT%H:%M:%SZ"
STATUSES = {"paid", "refunded", "failed"}

def extract(text):
    return list(csv.DictReader(io.StringIO(text)))

def clean_amount(text):
    cleaned = text.replace("$", "").replace(",", "").strip()
    try:
        return round(float(cleaned) * 100)
    except ValueError:
        return None

def parse_ts(text):
    parsed = datetime.fromisoformat(text.replace("Z", "+00:00")).astimezone(timezone.utc)
    return parsed.strftime(FMT)

def dedupe_latest(rows):
    latest = {}
    for row in rows:
        key = row["order_id"]
        if key not in latest or row["updated_at"] >= latest[key]["updated_at"]:
            latest[key] = row
    return [latest[key] for key in sorted(latest)]

def transform(raw_rows):
    """Returns (good rows after dedupe, quarantined [(order_id, reason, raw)], duplicates removed)."""
    good, bad = [], []
    for r in raw_rows:
        cents = clean_amount(r["amount"])
        status = r["status"].strip().lower()
        if cents is None:
            bad.append((r["order_id"], "bad amount", r["amount"]))
        elif cents < 0:
            bad.append((r["order_id"], "negative amount", r["amount"]))
        elif status not in STATUSES:
            bad.append((r["order_id"], "bad status", r["status"]))
        else:
            good.append({"order_id": int(r["order_id"]), "customer_id": int(r["customer_id"]), "amount_cents": cents,
                         "currency": r["currency"].upper(), "status": status, "updated_at": parse_ts(r["updated_at"])})
    unique = dedupe_latest(good)
    return unique, bad, len(good) - len(unique)

def open_db():
    conn = sqlite3.connect(":memory:")
    conn.executescript("""
    CREATE TABLE orders_clean (order_id INTEGER PRIMARY KEY, customer_id INTEGER, amount_cents INTEGER NOT NULL,
        currency TEXT, status TEXT, updated_at TEXT);
    CREATE TABLE etl_state (id INTEGER PRIMARY KEY CHECK (id = 1), watermark TEXT NOT NULL);
    INSERT INTO etl_state VALUES (1, '1970-01-01T00:00:00Z');
    CREATE TABLE quarantine (run_id INTEGER, order_id TEXT, reason TEXT, raw TEXT);
    CREATE TABLE etl_runs (run_id INTEGER PRIMARY KEY AUTOINCREMENT, read INTEGER, duplicates INTEGER, quarantined INTEGER,
        skipped INTEGER, loaded INTEGER, watermark TEXT);
    """)
    return conn

UPSERT = """INSERT INTO orders_clean VALUES (:order_id, :customer_id, :amount_cents, :currency, :status, :updated_at)
    ON CONFLICT (order_id) DO UPDATE SET customer_id = excluded.customer_id, amount_cents = excluded.amount_cents,
        currency = excluded.currency, status = excluded.status, updated_at = excluded.updated_at
    WHERE excluded.updated_at > orders_clean.updated_at"""

def run(conn, text, lookback_hours=0):
    raw = extract(text)
    good, bad, dupes = transform(raw)
    watermark = conn.execute("SELECT watermark FROM etl_state").fetchone()[0]
    since = (datetime.strptime(watermark, FMT) - timedelta(hours=lookback_hours)).strftime(FMT)
    new = [r for r in good if r["updated_at"] > since]
    newest = max([watermark] + [r["updated_at"] for r in new])
    with conn:
        conn.executemany(UPSERT, new)
        conn.execute("UPDATE etl_state SET watermark = ?", (newest,))
        cur = conn.execute("INSERT INTO etl_runs (read, duplicates, quarantined, skipped, loaded, watermark) VALUES (?,?,?,?,?,?)",
                           (len(raw), dupes, len(bad), len(good) - len(new), len(new), newest))
        run_id = cur.lastrowid
        conn.executemany("INSERT INTO quarantine VALUES (?, ?, ?, ?)", [(run_id, o, why, raw_value) for o, why, raw_value in bad])
    return {"run_id": run_id, "read": len(raw), "duplicates": dupes, "quarantined": len(bad),
            "skipped": len(good) - len(new), "loaded": len(new), "watermark": newest}

BATCH1 = """order_id,customer_id,amount,currency,status,updated_at
1,10,19.90,EUR,paid,2025-03-01T10:00:00Z
2,11,"1,250.00",EUR,PAID,2025-03-01T11:30:00Z
3,10,40.00,EUR,paid,2025-03-02T09:00:00Z
3,10,45.00,EUR,refunded,2025-03-03T08:00:00Z
4,12,abc,USD,paid,2025-03-02T12:00:00Z
5,13,$7.50,USD,failed,2025-03-03T15:45:00Z
6,11,12.00,EUR,paid,2025-03-04T07:15:00Z
"""

conn = open_db()
print(run(conn, BATCH1))
for row in conn.execute("SELECT order_id, amount_cents, status FROM orders_clean ORDER BY order_id"):
    print(row)
print(conn.execute("SELECT order_id, reason, raw FROM quarantine").fetchall())
```

```output
{'run_id': 1, 'read': 7, 'duplicates': 1, 'quarantined': 1, 'skipped': 0, 'loaded': 5, 'watermark': '2025-03-04T07:15:00Z'}
(1, 1990, 'paid')
(2, 125000, 'paid')
(3, 4500, 'refunded')
(5, 750, 'failed')
```

```python run
    newest = max([watermark] + [r["updated_at"] for r in new])
    with conn:
        conn.executemany(UPSERT, new)
        conn.execute("UPDATE etl_state SET watermark = ?", (newest,))
        cur = conn.execute("INSERT INTO etl_runs (read, duplicates, quarantined, skipped, loaded, watermark) VALUES (?,?,?,?,?,?)",
                           (len(raw), dupes, len(bad), len(good) - len(new), len(new), newest))
        run_id = cur.lastrowid
        conn.executemany("INSERT INTO quarantine VALUES (?, ?, ?, ?)", [(run_id, o, why, raw_value) for o, why, raw_value in bad])
    return {"run_id": run_id, "read": len(raw), "duplicates": dupes, "quarantined": len(bad),
            "skipped": len(good) - len(new), "loaded": len(new), "watermark": newest}
```

## Real-world applications

- **A real nightly pipeline.** With the stand-in source replaced by an API client or file reader and `sqlite3` by PostgreSQL (`%s` placeholders, `numeric` amounts), these functions are the pipeline.
- **Trust before dashboards.** The per-run reconciliation (Example 3) is the check that runs before a dashboard refreshes.
- **Onboarding a colleague.** The `etl_runs` and `quarantine` tables and the report of Example 4 let a new engineer see what ran, what was set aside and how fresh the data is.
- **Safe changes.** The tests of Example 3 run in milliseconds, so a rule change is tried on the cases before it touches data.

## Daily review

### Key takeaways

- One run: extract, transform (validate, quarantine, dedupe), choose rows above the watermark, then one transaction for the upsert, the watermark, the quarantine and the run record.
- Reconcile `read = quarantined + duplicates + skipped + loaded` from stored rows.
- Idempotency: a rerun without lookback loads nothing, and with a lookback it changes no values; late data needs a lookback with a guarded upsert.
- Test the pure functions with cases and the run with a rerun.

### Common mistakes

- Moving the watermark outside the transaction, so a crash skips or replays rows. Commit all writes together.
- Counting a deduplicated row as lost; `duplicates` is part of the equation.
- Forgetting the guard in the upsert, so a replayed old row overwrites a newer one.
- Using the loader's own counters for the reconciliation. Read the stored run record.
- Testing only the first run; the second run is the one that exposes duplicates.

### Revision notes

- Order: extract, transform, filter by watermark, one transaction.
- `read = quarantined + duplicates + skipped + loaded`.
- Late data: lookback plus guard. Rerun: loaded 0.
- Report: runs, quarantine by reason, freshness.
