## Objectives

- Write a `lambda` expression and explain how it relates to a `def` function.
- Apply a function to every item with `map()` and keep items that pass a test with `filter()`, converting the results with `list()`.
- Sort any list by any rule with `sorted(items, key=...)`, including sorting dictionaries by a field and breaking ties.
- Pass functions as arguments to other functions.
- Decide when a named function or a loop is clearer than a lambda.

## Understand

### Functions are values

On Day 14 you defined functions with `def` and called them with brackets. A function is also a **value**, like a number or a string. You can store it in a variable, put it in a list, and, most importantly, pass it as an argument to another function. Writing the name **without brackets** refers to the function itself; writing it with brackets **calls** it. So `len` is the function and `len("ab")` is the result 2.

Passing a function to another function is the basis of "functional style": instead of writing a loop that does something specific, you hand a general tool a small function that says what to do for each item. The tool does the looping.

### lambda: a small unnamed function

A **lambda expression** is a way to write a tiny function in one line without a name:

```text
lambda parameters: expression
```

It is equivalent to a `def` whose body is a single `return expression`. So `lambda x: x * 2` is the same as

```text
def double(x):
    return x * 2
```

except that it has no name. There is no `return` keyword: the value of the expression is returned automatically. A lambda can take several parameters (`lambda a, b: a + b`) and can use conditional expressions from Day 7 (`lambda n: "even" if n % 2 == 0 else "odd"`). It can contain only one expression, no statements such as `if` blocks, loops or assignments. Use a lambda only when the function is short and used once, usually as an argument. If you need a name, several lines or a docstring, use `def`.

### map(): apply a function to every item

`map(function, items)` calls `function` on each item and produces the results in the same order. It does **not** return a list. It returns a **lazy** `map` object, which produces its results only when you go through it. To see the results, convert it: `list(map(len, ["a", "bb"]))` is `[1, 2]`. A common misconception is to print the map object directly and be surprised by output like `<map object at 0x...>`. Wrap it in `list()`.

### filter(): keep the items that pass a test

`filter(function, items)` keeps the items for which `function(item)` is truthy. Like `map`, it returns a lazy object, so wrap it in `list()`. The function must return something that works as a yes or no (a boolean). If `function` is `None`, `filter` keeps the truthy items.

### sorted() with key

You used `sorted(items)` on Day 8. Its optional `key` argument is a function that turns each item into the value to compare. `sorted(words, key=len)` sorts by length. Python calls the key function once per item and sorts by the results, but returns the **original items**. `reverse=True` sorts from largest to smallest. The sort is **stable**: items with equal keys keep their original relative order, which you can use for tie-breaking.

To sort by several rules, return a tuple from the key: `key=lambda p: (p["category"], -p["price"])` sorts by category, then by price from high to low. Negating a number reverses its order within a tuple key. For records stored as dictionaries, the key picks the field: `key=lambda row: row["amount"]`.

The list method `items.sort(key=...)` accepts the same arguments but sorts in place and returns `None`, as you learned on Day 8.

### max and min with key

`max(items, key=...)` and `min(items, key=...)` also take a key, so `max(orders, key=lambda o: o["total"])` returns the whole order with the largest total. This replaces the manual maximum loop of Day 13.

### Functional style, and its limits

`map`, `filter` and `sorted` with `key` let you describe the result rather than loop by hand. Combined, they are compact: "the squares of the even numbers" is `list(map(lambda n: n * n, filter(lambda n: n % 2 == 0, numbers)))`. But long chains of lambdas are hard to read. When a lambda becomes complicated, give the function a name with `def`; the name explains it. Tomorrow's comprehensions are often an even more readable way to express the same idea.

### A worked trace of sorted with a key

Trace `sorted(["pear", "fig", "banana"], key=len)`. Python calls `len` once on each item, producing the keys 4, 3 and 6, and remembers which key belongs to which item. It then orders the items by their keys, 3 then 4 then 6, and returns the original items in that order: `["fig", "pear", "banana"]`. The key values are used only for comparing; they do not appear in the result. This is why a key function can compute anything, such as a negative price to reverse the order, without changing the data you get back.

The key idea of the day is the difference between **referring to** a function and **calling** it. `key=len` hands over the function so that `sorted` can call it. `key=len(words)` would call `len` right now and pass the number it returns, which is an error. The same holds for `map` and `filter`: you pass the function, and they call it. If you ever see "'int' object is not callable" or a similar message in this context, check for brackets that call a function too early.

## Syntax and key functions

```text
lambda x: expression
lambda a, b: expression

list(map(function, items))
list(filter(function, items))
sorted(items, key=function, reverse=False)
max(items, key=function)     min(items, key=function)
```

- A lambda has parameters, a colon and one expression; the expression's value is returned.
- `map`, `filter` and `zip` return lazy objects; use `list()` to see them.
- The key function receives one item and returns the value to sort or compare by.

| Function | What it returns |
|---|---|
| `map(f, items)` | lazy results of `f(item)` for each item |
| `filter(f, items)` | lazy items for which `f(item)` is truthy |
| `sorted(items, key=f, reverse=...)` | a new sorted list of the original items |
| `max(items, key=f)`, `min(items, key=f)` | the item with the biggest or smallest key |
| `list(x)` | a list holding everything `x` produces |
| `callable(x)` | `True` when `x` can be called |

## Learn by example

### Example 1: lambda and its def twin

```python run
def double(x):
    return x * 2

double_lambda = lambda x: x * 2
add = lambda a, b: a + b
parity = lambda n: "even" if n % 2 == 0 else "odd"

print(double(4), double_lambda(4))
print(add(3, 5))
print(parity(7), parity(10))
print(callable(double), callable(double_lambda), callable(5))
```

```output
8 8
8
odd even
True True False
```

Assigning a lambda to a name, as here, is only for showing the equivalence. When you want a name, `def` is the better style.

### Example 2: map

```python run
prices = [10.0, 24.5, 8.0]
with_tax = list(map(lambda p: round(p * 1.2, 2), prices))
print(with_tax)
words = ["data", "sql", "python"]
print(list(map(len, words)))
print(list(map(str.upper, words)))
result = map(len, words)
print(type(result))
```

```output
[12.0, 29.4, 9.6]
[4, 3, 6]
['DATA', 'SQL', 'PYTHON']
<class 'map'>
```

`len` and `str.upper` are existing functions passed by name, with no brackets. The last two lines show that `map` itself is a lazy object, not a list.

### Example 3: filter

```python run
numbers = [3, 8, 15, 22, 7, 40]
big = list(filter(lambda n: n > 10, numbers))
print(big)
names = ["Ada", "", "Bo", "", "Cy"]
print(list(filter(None, names)))
print(list(filter(lambda s: s.startswith("B"), names)))
```

```output
[15, 22, 40]
['Ada', 'Bo', 'Cy']
['Bo']
```

`filter(None, names)` removes the empty strings because they are falsy.

### Example 4: sorted with key

```python run
words = ["banana", "kiwi", "apple", "fig", "cherry"]
print(sorted(words))
print(sorted(words, key=len))
print(sorted(words, key=len, reverse=True))
print(sorted(["b", "A", "c", "D"]))
print(sorted(["b", "A", "c", "D"], key=str.lower))
print(words)
```

```output
['apple', 'banana', 'cherry', 'fig', 'kiwi']
['fig', 'kiwi', 'apple', 'banana', 'cherry']
['banana', 'cherry', 'apple', 'kiwi', 'fig']
['A', 'D', 'b', 'c']
['A', 'b', 'c', 'D']
['banana', 'kiwi', 'apple', 'fig', 'cherry']
```

`banana` and `cherry` both have length 6, so with `key=len` they keep their original order (`banana` first) because the sort is stable. `key=str.lower` ignores capitals. The original list is unchanged.

### Example 5: Sorting records

```python run
products = [
    {"name": "pen", "category": "office", "price": 2.5},
    {"name": "desk", "category": "furniture", "price": 150.0},
    {"name": "lamp", "category": "furniture", "price": 35.0},
    {"name": "ink", "category": "office", "price": 8.0},
]
by_price = sorted(products, key=lambda p: p["price"])
print(list(map(lambda p: p["name"], by_price)))
by_cat_then_price = sorted(products, key=lambda p: (p["category"], -p["price"]))
for p in by_cat_then_price:
    print(p["category"], p["name"], p["price"])
print(max(products, key=lambda p: p["price"])["name"])
print(min(products, key=lambda p: p["price"])["name"])
```

```output
['pen', 'ink', 'lamp', 'desk']
furniture desk 150.0
furniture lamp 35.0
office ink 8.0
office pen 2.5
desk
pen
```

The first line uses `map` to pull out the names in sorted order. The tuple key sorts by category, then by price from high to low.

### Example 6: A small pipeline

A realistic chain: from a list of order dictionaries, take the paid orders, compute totals with tax, and report the three biggest. Each step is named, so no lambda is hard to read.

```python run
orders = [
    {"id": 1, "status": "paid", "net": 100.0},
    {"id": 2, "status": "cancelled", "net": 500.0},
    {"id": 3, "status": "paid", "net": 250.0},
    {"id": 4, "status": "paid", "net": 40.0},
    {"id": 5, "status": "paid", "net": 180.0},
]
paid = list(filter(lambda o: o["status"] == "paid", orders))
priced = list(map(lambda o: {"id": o["id"], "gross": round(o["net"] * 1.2, 2)}, paid))
top = sorted(priced, key=lambda o: o["gross"], reverse=True)[:3]
for o in top:
    print(o["id"], o["gross"])
print(sum(map(lambda o: o["gross"], top)))
```

```output
3 300.0
5 216.0
1 120.0
636.0
```

The order with id 2 is cancelled, so `filter` removed it before the other steps ran.

## Real-world applications

- **Sorting reports.** `sorted(rows, key=lambda r: (r["region"], -r["sales"]))` produces a leaderboard grouped by region.
- **Quick transformations.** `map` applies a cleaning or conversion function to a whole column of values.
- **Selecting rows.** `filter` keeps the records that pass a business rule, such as paid orders over a threshold.
- **Finding the best record.** `max(..., key=...)` returns the entire record with the highest value, not just the number.

## Daily review

### Key takeaways

- A function is a value; its name without brackets refers to it and can be passed around.
- `lambda params: expression` is a one-line anonymous function with an implicit `return`.
- `map` and `filter` return lazy objects; wrap them in `list()`.
- `sorted(items, key=f)` returns a new list sorted by `f(item)`; ties keep their original order.
- Use a tuple key for multi-level sorts and `-value` to reverse a number inside it.

### Common mistakes

- **Printing a `map` or `filter` result directly.** You see `<map object at 0x...>`. Wrap it in `list()`.
- **Calling the function in `key`.** `sorted(words, key=len())` raises `TypeError: len() takes exactly one argument (0 given)`. Pass `key=len`, with no brackets.
- **Statements in a lambda.** `lambda x: return x` or `lambda x: print(x); x` is a `SyntaxError`. A lambda holds one expression.
- **Using a lambda that returns `None` in `filter`.** If the lambda forgets to return a boolean, every item is dropped. Check that it returns True or False.
- **Expecting `sort()` to return a list.** `items.sort(key=...)` returns `None`; use `sorted()` for a result.
- **Reusing a `map` object.** After it has been consumed once, a second `list()` gives `[]`. Convert it once and keep the list.

### Revision notes

- `lambda x: expr`; same as `def` with one `return`.
- `list(map(f, items))`, `list(filter(f, items))`.
- `sorted(items, key=f, reverse=True)`; `max(items, key=f)`.
- Multi-key: `key=lambda r: (r["a"], -r["b"])`.
