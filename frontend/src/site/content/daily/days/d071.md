## Objectives

- Select rows and columns by label with `.loc` and by integer position with `.iloc`.
- Explain how label slices (`loc`) include the end while position slices (`iloc`) exclude it.
- Select a single value, a row, a column, a block, or a list of rows and columns in one expression.
- Predict whether a selection returns a scalar, a Series or a DataFrame.
- Change values in place with `loc` and `iloc`, and use `.copy()` so that you do not change the original by accident.

## Understand

### Two ways to point at data

A DataFrame has labels (the row index and the column names) and positions (0, 1, 2, ... in order). Selecting data means pointing at some rows and some columns, and pandas offers two tools for the two ways of pointing. **`.loc`** selects by **label**: the names in the index and the column names. **`.iloc`** selects by **integer position**, counting from 0 as in lists and arrays (the `i` stands for integer). Both use square brackets, not parentheses, and both take the rows first and then the columns, separated by a comma: `df.loc[rows, columns]` and `df.iloc[rows, columns]`.

A good way to remember it: `loc` is "location by name", like finding a customer by account number, and `iloc` is "location by place in the queue", like asking for the third person in line. When the index is the default 0, 1, 2, ... the label and the position of a row are the same number, which hides the difference. Once the index holds names, dates or numbers that do not start at 0, they diverge, and mixing them up gives wrong answers or a `KeyError`.

### Selecting with loc

For a table with the index `["a", "b", "c", "d"]` and columns `qty` and `price`:

- `df.loc["b", "price"]` gives a single value, a **scalar**.
- `df.loc["b"]` gives the whole row as a Series whose index is the column names.
- `df.loc[:, "price"]` gives the whole column as a Series. The lone colon means "all rows".
- `df.loc[["a", "c"], ["price", "qty"]]` gives a DataFrame with those rows and columns in the order you list them.
- `df.loc["b":"d", "qty":"price"]` gives a block using **label slices**.

The last form has the most surprising rule. A label slice **includes both ends**: `"b":"d"` returns rows b, c and d. The reason is that there is no obvious "next label" after `d` to stop before, so the slice is inclusive. This is different from position slices and from Python lists. Label slices also depend on the order of the rows as they are in the table: `"b":"d"` means "from where b is to where d is", not an alphabetical range.

### Selecting with iloc

`df.iloc[1, 1]` is the value in the second row and second column. `df.iloc[1]` is the second row. `df.iloc[:, 0]` is the first column. `df.iloc[[0, 2], [1, 0]]` picks rows 0 and 2 and columns 1 and 0. `df.iloc[1:3, 0:2]` is a block, and here the slice behaves exactly like a list or NumPy slice: the **stop is excluded**, so `1:3` returns positions 1 and 2. Negative positions work: `df.iloc[-1]` is the last row, and `df.iloc[:2]` the first two.

So the two tools differ in what they accept (labels versus positions) and in how their slices end (loc includes the end label, iloc excludes the end position). A fast check when something looks wrong: ask yourself whether you are pointing by name or by place, and use the matching tool.

### What you get back: scalar, Series or DataFrame

The result type follows the shape of what you ask for. Two single choices give a scalar. One single choice and one range or list gives a Series. Two ranges or lists give a DataFrame. A list with one element still gives a DataFrame or a Series with one entry, because a list keeps the dimension: `df.loc[["b"]]` is a one-row table, while `df.loc["b"]` is a Series. This matters when you pass the result on. A Series has no columns, so calling a column name on it fails, and a one-column DataFrame does not behave like a Series in arithmetic.

### Setting values

The same selections can be placed on the left side of an assignment to change data: `df.loc["b", "price"] = 5.0` changes one cell, `df.loc["a":"c", "qty"] = 0` sets several cells, and `df.iloc[0, 1] = 9.5` does the same by position. Use the selection tools for assignment, and do it in a single step. Writing `df["price"]["b"] = 5.0` is a **chained** assignment. It first selects a column (which may be a copy) and then assigns to that, so it may change nothing or give a warning. The rule is one `loc` or `iloc` with both row and column. Setting values changes the DataFrame in place, which leads to the next point.

### Copies and the original

Selections with `loc` and `iloc` may or may not share memory with the original table, and pandas does not promise which. To change a piece of a table without touching the original, make an explicit copy first: `part = df.loc["a":"c"].copy()` or `work = df.copy()`. The same advice as on Day 64 applies: keep the raw data and edit a copy. When assigning, keep the type in mind. Putting a decimal into a whole-number column, or text into a number column, changes or breaks the column's type, so assign values of the same type in these examples.

### The common misconception

Learners assume that `loc` and `iloc` are interchangeable and that `loc[1:3]` returns two rows like a list slice. With the default index it returns three rows (1, 2, 3), and with a text index `loc[1:3]` raises a `TypeError`. The other classic mistake is calling `df.iloc["b"]`, which raises `ValueError`/`TypeError` because positions must be integers, or `df.loc[0]` on an index that does not contain 0, which raises `KeyError: 0`. The error message names the label or position you asked for, which tells you that you used the wrong tool.

### Why it matters in data work

Cleaning and analysis constantly pick pieces of a table: the row for one customer, the columns needed for a report, the first and last ten rows, a block to export. Fixing a single bad cell, such as replacing a sentinel in a known place, is an assignment with `loc`. Using the right tool prevents silent off-by-one errors, in particular the inclusive end of `loc` slices, which is the most common source of one extra row in a result. Checking the shape of every selection, as you did with arrays, catches the rest.

## Syntax and key functions

Select:

```python
df.loc[row_label, col_label]
df.loc[row_labels, col_labels]
df.loc["start":"stop", "first":"last"]
df.iloc[row_pos, col_pos]
df.iloc[start:stop, start:stop]
```

Set:

```python
df.loc[row_label, col_label] = value
df.iloc[row_pos, col_pos] = value
work = df.copy()
```

| Expression | Returns |
|---|---|
| `df.loc["b", "price"]` | One value (scalar). |
| `df.loc["b"]` | A row as a Series. |
| `df.loc[:, "price"]` | A column as a Series. |
| `df.loc[["a", "c"], ["qty"]]` | A DataFrame of the listed labels, in that order. |
| `df.loc["b":"d"]` | Rows b to d, **both ends included**. |
| `df.iloc[1, 1]` | One value by position. |
| `df.iloc[1:3]` | Rows at positions 1 and 2, **end excluded**. |
| `df.iloc[-1]` | The last row as a Series. |
| `df.loc[...] = v`, `df.iloc[...] = v` | Set the selected cells in place. |
| `df.copy()` | An independent copy. |

## Learn by example

### Example 1: Selecting by label with loc

A table of products uses the product codes as the index. Single labels give a value, a row or a column. Lists of labels give a smaller table, in the order given. The shapes and types show what each form returns.

```python run
import pandas as pd

pd.set_option("display.width", 200)
pd.set_option("display.max_columns", 20)

df = pd.DataFrame({"qty": [10, 4, 7, 12], "price": [2.5, 8.0, 3.2, 1.1], "colour": ["red", "blue", "red", "green"]},
                  index=["p1", "p2", "p3", "p4"])
print(df)
print(df.loc["p2", "price"])
print(df.loc["p3"].to_dict())
print(df.loc[:, "qty"].tolist())
print(df.loc[["p4", "p1"], ["price", "qty"]])
print(type(df.loc["p2"]).__name__, type(df.loc[["p2"]]).__name__, df.loc[["p2"]].shape)
```

```output
    qty  price colour
p1   10    2.5    red
p2    4    8.0   blue
p3    7    3.2    red
p4   12    1.1  green
8.0
{'qty': 7, 'price': 3.2, 'colour': 'red'}
[10, 4, 7, 12]
    price  qty
p4    1.1   12
p1    2.5   10
Series DataFrame (1, 3)
```

### Example 2: Selecting by position with iloc, and the two slice rules

`iloc` counts from 0 and excludes the end of a slice, like a list. `loc` with label slices includes the end. The same two requests, rows 1 to 3, give different numbers of rows with the default index.

```python run
import pandas as pd

pd.set_option("display.width", 200)
pd.set_option("display.max_columns", 20)

df = pd.DataFrame({"qty": [10, 4, 7, 12, 5], "price": [2.5, 8.0, 3.2, 1.1, 6.0]})
print(df.iloc[1, 1], df.iloc[-1].to_dict())
print(df.iloc[:, 0].tolist())
print(df.iloc[1:3])
print(df.loc[1:3])
print(df.iloc[[0, 2], [1, 0]])
print(len(df.iloc[1:3]), len(df.loc[1:3]))
```

```output
8.0 {'qty': 5.0, 'price': 6.0}
[10, 4, 7, 12, 5]
   qty  price
1    4    8.0
2    7    3.2
   qty  price
1    4    8.0
2    7    3.2
3   12    1.1
   price  qty
0    2.5   10
2    3.2    7
2 3
```

### Example 3: Label and position diverge

After the rows are given a different index, the label `2` is no longer the position `2`. `loc[2]` and `iloc[2]` then point at different rows, and a label that is not in the index raises a `KeyError`.

```python run
import pandas as pd

df = pd.DataFrame({"city": ["Oslo", "Rome", "Lima", "Kyiv"], "pop": [700, 2800, 10000, 2900]})
df.index = [3, 2, 1, 0]
print(df.loc[2, "city"], df.iloc[2]["city"])
print(df.loc[3:2, "city"].tolist())
print(df.iloc[0:2]["city"].tolist())
try:
    df.loc[7]
except KeyError as e:
    print("KeyError:", e)
```

```output
Rome Lima
['Oslo', 'Rome']
['Oslo', 'Rome']
KeyError: 7
```

### Example 4: Setting values

Assignment with `loc` and `iloc` changes cells in place. We work on a copy so that the original stays untouched. Several cells can be set at once with a label slice, and the new values keep the column's type.

```python run
import pandas as pd

pd.set_option("display.width", 200)
pd.set_option("display.max_columns", 20)

raw = pd.DataFrame({"qty": [10, -1, 7, 12], "price": [2.5, 8.0, 3.2, 1.1]}, index=["p1", "p2", "p3", "p4"])
work = raw.copy()
work.loc["p2", "qty"] = 0
work.iloc[3, 1] = 1.5
work.loc["p1":"p3", "price"] = 9.0
print(work)
print(raw)
print(raw.loc["p2", "qty"], work.loc["p2", "qty"])
```

```output
    qty  price
p1   10    9.0
p2    0    9.0
p3    7    9.0
p4   12    1.5
    qty  price
p1   10    2.5
p2   -1    8.0
p3    7    3.2
p4   12    1.1
-1 0
```

### Example 5: A realistic case, fixing and extracting a report

A small sales table is indexed by month. A known wrong value is fixed by label, the quarter's block is extracted with a label slice that includes both ends, and the last row and a column are read by position. The extracted block is copied and one value is changed in the copy, so the fixed table stays as it was.

```python run
import pandas as pd

pd.set_option("display.width", 200)
pd.set_option("display.max_columns", 20)

sales = pd.DataFrame({"north": [120, 135, 90, 150, 160, 155], "south": [80, 85, 999, 95, 100, 98]},
                     index=["Jan", "Feb", "Mar", "Apr", "May", "Jun"])
fixed = sales.copy()
fixed.loc["Mar", "south"] = 90
q1 = fixed.loc["Jan":"Mar"].copy()
q1.loc["Feb", "north"] = 140
print(q1)
print((q1["north"] + q1["south"]).tolist())
print(fixed.iloc[-1].to_dict())
print(fixed.iloc[:, 1].sum(), sales.iloc[:, 1].sum())
print(fixed.loc[["Jun", "Jan"], "north"].tolist())
```

```output
     north  south
Jan    120     80
Feb    140     85
Mar     90     90
[200, 225, 180]
{'north': 155, 'south': 98}
548 1457
[155, 120]
```

## Real-world applications

- **Looking up one record.** `loc` with an order number or customer id as the index returns the row, as in Example 1, without any loop.
- **Extracting a period or a block.** A label slice such as `"Jan":"Mar"` pulls a quarter from a table indexed by month, as in Example 5, and `iloc` takes the first or last rows of any table.
- **Fixing known bad cells.** A sentinel or typo found during inspection is corrected with one `loc` assignment, as in Examples 4 and 5, while the raw table is kept as a copy.
- **Choosing and ordering columns for output.** `loc[:, ["id", "price"]]` selects exactly the columns of a report in the order the reader wants.

## Daily review

### Key takeaways

- `loc` selects by label, `iloc` by integer position; both take `[rows, columns]`.
- `loc` slices include the end label; `iloc` slices exclude the end position.
- Two single choices give a scalar, one single choice gives a Series, lists or slices give a DataFrame; a one-element list keeps the DataFrame.
- Set values with one `loc` or `iloc` call; avoid chained assignment like `df["a"]["b"] = x`.
- Work on `.copy()` when you must keep the original.

### Common mistakes

- Using `loc[1:3]` and expecting two rows. It returns three, because the end label is included.
- Using `df.loc[0]` on an index without the label 0 and getting `KeyError: 0`.
- Passing a label to `iloc`, which raises an error because positions must be integers.
- Chained assignment `df["price"]["p2"] = 5`, which may not change the table and may print a warning. Use `df.loc["p2", "price"] = 5`.
- Editing a slice and being surprised that the original also changed. Copy first.
- Forgetting the comma and writing `df.loc["p1"]["price"]` for what should be one step. It works for reading, but use `df.loc["p1", "price"]` for clarity and for assignment.

### Revision notes

- `df.loc[rows, cols]` labels, `df.iloc[rows, cols]` positions.
- `loc["a":"c"]` is a, b, c; `iloc[0:2]` is rows 0 and 1.
- `df.loc[["a"]]` is a DataFrame, `df.loc["a"]` a Series.
- `df.loc["a", "x"] = v`; copy before editing.
