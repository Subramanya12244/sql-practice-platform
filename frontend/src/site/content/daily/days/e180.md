## Objectives

- Run the capstone end to end and state its result as a short list of numbers that reconcile.
- Check the original requirements of Day 173 against the finished pipeline, and show that a check can fail.
- Compare an incremental with a full load, and estimate how ingestion cost grows when the source is a thousand times larger.
- Present the project in five minutes: the problem, the architecture, one result, two trade-offs and the limits.
- Reflect on what to change next, and choose a next step on the engineer path.

## Understand

### What a capstone presentation is for

You built eight stages: scope, ingestion, cleaning, warehouse, analytics, orchestration and tests, documentation. The last day is not new code. It is the skill of **explaining** a data system: what problem it solves, how the data flows, what a decision cost, and where it would break. Interviewers and teammates ask the same questions about any pipeline, and you can answer them from the evidence you already produced: counts that reconcile, checks that pass, a README that states the limits.

### The demo: one story, in numbers

A good five-minute demo has five parts. The **problem** in one sentence: orders arrive from an API and a CSV and must become trustworthy sales numbers. The **flow**: the architecture diagram, from sources through raw, clean and quarantine to the star schema and views. One **result** with its proof: 120 records read, 114 clean and 6 quarantined with reasons, 91 paid orders loaded, revenue by month, and a second run that adds nothing. Two **trade-offs** you made on purpose. And the **limits**: what you would fix next. The most convincing line in the demo is a number that adds up, because it shows the pipeline is accounted for. Practise the demo with a timer, because people run over by half.

### Trade-offs

A **trade-off** is a choice where each option gains one thing and loses another, and a good engineer says which was chosen and why. Examples from this project. Quarantine against stopping: quarantine keeps good data flowing but needs someone to look at the quarantine. Incremental against full load: incremental processes only new rows and is cheap, but needs a watermark and misses late-arriving rows; a full reload is simple and always right, but its cost grows with history. Type 2 history against overwriting: history answers "what was true then" but adds rows and a date-range lookup. Integer cents against decimals: exact sums with display conversion at the end. Python rules against SQL rules: Python parses easily, SQL checks whole tables. Each of these has a case where the other choice is right, and naming that case is what shows judgment.

### Scale: what changes at a thousand times the data

Take the numbers you have and multiply. 120 records at 25 per page is 5 pages and 7 calls when every third call is limited. A source of 120,000 records is 4,800 pages and about 7,200 calls, and 2,400 waits of two seconds is more than an hour of waiting on rate limits alone, so a real pipeline would raise the page size, request in parallel within the limit, or load by date ranges. The in-memory `sqlite3` warehouse would move to PostgreSQL or a cloud warehouse, with indexes on the keys and partitions by date. The cleaning rules still run row by row in Python, which would move to a distributed engine such as Spark. The architecture stays the same; the engines under each stage change.

### Reflection and next steps

A **retrospective** asks what went well, what was hard and what you would change. Write it down; it is the part of the project that turns into interview answers. Typical honest items: late-arriving data is not handled, the PostgreSQL syntax was exercised only on a small sample, the orchestration is a model of Airflow and not Airflow itself, and the monitoring has three rules. Next steps on the engineer path are to run the DAG in real Airflow, load into a real PostgreSQL server, add dbt-style models for the analytics layer, and port the cleaning stage to Spark.

### Common misconception

Learners present the code. The audience wants the decisions: why this design, what it costs, what breaks first. Code is evidence for the decisions, not the story.

### Why it matters

Being able to say what you built, why, and where it fails is what separates a working engineer from someone who followed a tutorial.

## Syntax and key functions

The checkpoint reuses the functions of the earlier days; the new idea is a final report that collects the numbers:

```python
conn, report = pipeline()        # ingest, land, clean, load
report["raw"] == report["clean"] + report["quarantined"]
load_fact(conn, report["good"])  # a second run: returns 0 new rows
```

| Item | What it does or returns |
|---|---|
| `pipeline()` | Runs ingestion, landing, cleaning and the warehouse load; returns the connection and the numbers. |
| `load_fact(conn, good)` | Loads only paid orders newer than the watermark; returns the rows added. |
| `calls_needed(n, size, every)` | Pages and calls for `n` records when every `every`-th call is rate limited. |
| Reconciliation line | `raw = clean + quarantined`, then `fact rows <= clean`. |
| Acceptance check | A requirement of Day 173 as a function that returns True or False. |

## Learn by example

### Example 1: The end-to-end run and the demo headline

One call runs the stages built on Days 174 to 176. The report is the content of the demo: reads and calls from ingestion, rows landed, the reconciliation of the clean stage, the fact rows and the revenue headline from the analytics layer. All numbers come from the run.

```python run
import random
from datetime import date, timedelta

COUNTRIES = ["DE", "FR", "IN", "US", "BR"]
CATEGORIES = ["tools", "books", "games"]

def generate(seed=7):
    """Seeded stand-in data: customers, products and 120 raw order records with planted defects."""
    rng = random.Random(seed)
    customers = [(f"C{n:03d}", f"Customer {n:02d}", COUNTRIES[n % 5]) for n in range(1, 21)]
    products = [(f"P{n:02d}", f"Product {n:02d}", CATEGORIES[n % 3]) for n in range(1, 9)]
    price = {pid: 500 * (i + 1) for i, (pid, _, _) in enumerate(products)}
    orders = []
    for n in range(1, 121):
        pid = products[rng.randrange(8)][0]
        qty = rng.randint(1, 4)
        day = date(2026, 1, 1) + timedelta(days=(n - 1) * 89 // 119)
        orders.append({
            "order_id": f"O{n:04d}", "customer_id": customers[rng.randrange(20)][0], "product_id": pid,
            "quantity": qty, "amount_cents": price[pid] * qty, "currency": "EUR",
            "status": rng.choices(["paid", "refunded", "failed"], weights=[8, 1, 1])[0],
            "created_at": f"{day}T{(n * 7) % 24:02d}:{(n * 13) % 60:02d}:00Z",
        })
    orders[29]["amount_cents"] = -1000
    orders[44]["customer_id"] = "C999"
    orders[59]["created_at"] = ""
    orders[74]["currency"] = "???"
    orders[104]["status"] = "pending"
    orders[119] = dict(orders[9])
    return customers, products, orders

class RateLimited(Exception):
    def __init__(self, retry_after):
        super().__init__("429 too many requests")
        self.retry_after = retry_after

class Unauthorized(Exception):
    pass

def make_api(orders, api_key="secret-key", every=3):
    """Stand-in for GET /orders?page=N&page_size=P: no network, same answers (200, 401, 429)."""
    state = {"calls": 0, "limited": 0}
    def get_orders(page, page_size, headers):
        state["calls"] += 1
        if headers.get("X-Api-Key") != api_key:
            raise Unauthorized("401 invalid API key")
        if every and state["calls"] % every == 0:
            state["limited"] += 1
            raise RateLimited(2)
        total = -(-len(orders) // page_size)
        start = (page - 1) * page_size
        return {"data": orders[start:start + page_size], "page": page, "total_pages": total}
    return get_orders, state

def fetch_page(api, page, size, headers, sleep, max_tries=5):
    for attempt in range(max_tries):
        try:
            return api(page, size, headers)
        except RateLimited as e:
            sleep(e.retry_after * 2 ** attempt)
    raise RuntimeError(f"page {page} still rate limited after {max_tries} tries")

def fetch_all(api, headers, sleep, size=25):
    records, page, total = [], 1, 1
    while page <= total:
        body = fetch_page(api, page, size, headers, sleep)
        records.extend(body["data"])
        total = body["total_pages"]
        page += 1
    return records

from datetime import datetime

def first_problem(rec, seen, known):
    """The first rule a raw order breaks, or None. `seen` holds the order ids already processed."""
    if rec["order_id"] in seen:
        return "duplicate order_id"
    if not rec["created_at"]:
        return "missing created_at"
    try:
        datetime.strptime(rec["created_at"], "%Y-%m-%dT%H:%M:%SZ")
    except ValueError:
        return "bad created_at"
    if not isinstance(rec["amount_cents"], int) or rec["amount_cents"] <= 0:
        return "bad amount"
    if rec["customer_id"].strip().upper() not in known:
        return "unknown customer"
    if rec["currency"].strip().upper() != "EUR":
        return "bad currency"
    if rec["status"].strip().lower() not in ("paid", "refunded", "failed"):
        return "bad status"
    return None

def transform(rec):
    """Typed, normalised copy of a valid raw order."""
    return {"sale_id": int(rec["order_id"][1:]), "order_id": rec["order_id"],
            "customer_id": rec["customer_id"].strip().upper(), "product_id": rec["product_id"],
            "quantity": int(rec["quantity"]), "amount_cents": rec["amount_cents"],
            "status": rec["status"].strip().lower(), "created_at": rec["created_at"],
            "date_key": int(rec["created_at"][:10].replace("-", ""))}

def clean_orders(raw, known):
    good, quarantine, seen = [], [], set()
    for rec in raw:
        reason = first_problem(rec, seen, known)
        seen.add(rec["order_id"])
        if reason:
            quarantine.append({"order_id": rec["order_id"], "reason": reason, "payload": rec})
        else:
            good.append(transform(rec))
    return good, quarantine

import sqlite3
from datetime import date, timedelta

DDL = """
CREATE TABLE dim_date (date_key INTEGER PRIMARY KEY, full_date TEXT, year INTEGER, month INTEGER);
CREATE TABLE dim_product (product_key INTEGER PRIMARY KEY AUTOINCREMENT, product_id TEXT UNIQUE, product_name TEXT, category TEXT);
CREATE TABLE dim_customer (customer_key INTEGER PRIMARY KEY AUTOINCREMENT, customer_id TEXT, customer_name TEXT, country TEXT,
                           valid_from TEXT, valid_to TEXT, is_current INTEGER);
CREATE TABLE fact_sales (sale_id INTEGER PRIMARY KEY, date_key INTEGER, customer_key INTEGER, product_key INTEGER,
                         quantity INTEGER, amount_cents INTEGER);
CREATE TABLE etl_state (name TEXT PRIMARY KEY, watermark TEXT);
"""

def init_warehouse():
    conn = sqlite3.connect(":memory:")
    conn.executescript(DDL)
    return conn

def load_dim_date(conn, start, end):
    days = (end - start).days + 1
    rows = [(int(d.strftime("%Y%m%d")), d.isoformat(), d.year, d.month) for d in (start + timedelta(days=i) for i in range(days))]
    with conn:
        conn.executemany("INSERT OR IGNORE INTO dim_date VALUES (?, ?, ?, ?)", rows)

def load_dim_product(conn, products):
    with conn:
        conn.executemany("""INSERT INTO dim_product (product_id, product_name, category) VALUES (?, ?, ?)
                            ON CONFLICT(product_id) DO UPDATE SET product_name = excluded.product_name, category = excluded.category""", products)

def load_dim_customer(conn, customers, as_of, first_from="2026-01-01"):
    """Type 2 history: a changed customer gets a new row; the old row is closed on `as_of`."""
    with conn:
        for cid, name, country in customers:
            cur = conn.execute("SELECT customer_key, customer_name, country FROM dim_customer WHERE customer_id = ? AND is_current = 1", (cid,)).fetchone()
            if cur is None:
                conn.execute("INSERT INTO dim_customer (customer_id, customer_name, country, valid_from, valid_to, is_current) VALUES (?, ?, ?, ?, '9999-12-31', 1)",
                             (cid, name, country, first_from))
            elif (cur[1], cur[2]) != (name, country):
                conn.execute("UPDATE dim_customer SET valid_to = ?, is_current = 0 WHERE customer_key = ?", (as_of, cur[0]))
                conn.execute("INSERT INTO dim_customer (customer_id, customer_name, country, valid_from, valid_to, is_current) VALUES (?, ?, ?, ?, '9999-12-31', 1)",
                             (cid, name, country, as_of))

def load_fact(conn, good):
    """Incremental: only paid orders newer than the watermark; upsert on sale_id; the watermark moves after the load."""
    row = conn.execute("SELECT watermark FROM etl_state WHERE name = 'fact_sales'").fetchone()
    mark = row[0] if row else ""
    new = [g for g in good if g["created_at"] > mark]
    facts = []
    for g in new:
        if g["status"] != "paid":
            continue
        day = g["created_at"][:10]
        ck = conn.execute("SELECT customer_key FROM dim_customer WHERE customer_id = ? AND valid_from <= ? AND ? < valid_to", (g["customer_id"], day, day)).fetchone()[0]
        pk = conn.execute("SELECT product_key FROM dim_product WHERE product_id = ?", (g["product_id"],)).fetchone()[0]
        facts.append((g["sale_id"], g["date_key"], ck, pk, g["quantity"], g["amount_cents"]))
    with conn:
        conn.executemany("""INSERT INTO fact_sales VALUES (?, ?, ?, ?, ?, ?)
                            ON CONFLICT(sale_id) DO UPDATE SET date_key = excluded.date_key, customer_key = excluded.customer_key,
                            product_key = excluded.product_key, quantity = excluded.quantity, amount_cents = excluded.amount_cents""", facts)
        if new:
            conn.execute("INSERT INTO etl_state VALUES ('fact_sales', ?) ON CONFLICT(name) DO UPDATE SET watermark = excluded.watermark",
                         (max(g["created_at"] for g in new),))
    return len(facts)

import json
import sqlite3

def land(conn, batch_id, records):
    """Land raw records unchanged; a batch is replaced as a whole, so re-running it adds nothing."""
    conn.execute("CREATE TABLE IF NOT EXISTS raw_orders (batch_id TEXT, seq INTEGER, payload TEXT, PRIMARY KEY (batch_id, seq))")
    with conn:
        conn.execute("DELETE FROM raw_orders WHERE batch_id = ?", (batch_id,))
        conn.executemany("INSERT INTO raw_orders VALUES (?, ?, ?)",
                         [(batch_id, i, json.dumps(r, sort_keys=True)) for i, r in enumerate(records)])

def pipeline(orders_in=None):
    """Days 174 to 177 in one call: ingest and land, clean, load the star schema; returns the warehouse and the numbers."""
    customers, products, orders = generate()
    api, state = make_api(orders)
    waits = []
    raw = fetch_all(api, {"X-Api-Key": "secret-key"}, waits.append)
    raw_db = sqlite3.connect(":memory:")
    land(raw_db, "b1", raw)
    good, quarantine = clean_orders(raw, {c[0] for c in customers})
    conn = init_warehouse()
    load_dim_date(conn, date(2026, 1, 1), date(2026, 3, 31))
    load_dim_product(conn, products)
    load_dim_customer(conn, customers, "2026-01-01")
    added = load_fact(conn, good)
    return conn, {"raw": len(raw), "landed": raw_db.execute("SELECT COUNT(*) FROM raw_orders").fetchone()[0], "calls": state["calls"],
                  "waits": waits, "clean": len(good), "quarantined": len(quarantine), "fact_rows": added, "good": good}

conn, r = pipeline()
print(f"ingest: {r['raw']} records in {r['calls']} calls, {len(r['waits'])} rate-limit waits, {r['landed']} landed")
print(f"clean: raw {r['raw']} = clean {r['clean']} + quarantined {r['quarantined']}")
print(f"load: {r['fact_rows']} paid orders in fact_sales")
months = conn.execute("SELECT d.month, SUM(f.amount_cents) FROM fact_sales f JOIN dim_date d ON d.date_key = f.date_key GROUP BY d.month ORDER BY d.month").fetchall()
total = sum(c for _, c in months)
best = max(months, key=lambda m: m[1])
print(f"headline: {total / 100:.2f} EUR revenue, best month {best[0]} with {best[1] / 100:.2f} EUR")
```

```output
load: 91 paid orders in fact_sales
headline: 5235.00 EUR revenue, best month 1 with 2215.00 EUR
```

### Example 2: The Day 173 requirements, checked

The four requirements written on Day 173 are now real checks against the finished pipeline: every raw record is accounted for, the fact table holds paid orders only, revenue is an exact integer, and a second run adds no rows. The last two lines plant a defect (a paid order with the wrong status text removed from the clean set) to show that the checks are able to fail.

### Example 3: Incremental or full

Both strategies load the same three months of clean data in three nightly runs. A full load reprocesses everything each night; an incremental load processes only the rows newer than the last run. The counts of rows processed show why the cost of a full load grows with history while an incremental load's cost follows the daily volume. Both end with the same table.

```python run
import random
from datetime import date, timedelta

COUNTRIES = ["DE", "FR", "IN", "US", "BR"]
CATEGORIES = ["tools", "books", "games"]

def generate(seed=7):

    orders[119] = dict(orders[9])

class RateLimited(Exception):
    def __init__(self, retry_after):
        super().__init__("429 too many requests")
        self.retry_after = retry_after

class Unauthorized(Exception):
    pass

def make_api(orders, api_key="secret-key", every=3):
    """Stand-in for GET /orders?page=N&page_size=P: no network, same answers (200, 401, 429)."""
    state = {"calls": 0, "limited": 0}
    def get_orders(page, page_size, headers):
        state["calls"] += 1
        if headers.get("X-Api-Key") != api_key:
            raise Unauthorized("401 invalid API key")
        if every and state["calls"] % every == 0:
            state["limited"] += 1
            raise RateLimited(2)
        total = -(-len(orders) // page_size)
        start = (page - 1) * page_size
        return {"data": orders[start:start + page_size], "page": page, "total_pages": total}
    return get_orders, state

def fetch_page(api, page, size, headers, sleep, max_tries=5):
    for attempt in range(max_tries):
        try:
            return api(page, size, headers)
        except RateLimited as e:
            sleep(e.retry_after * 2 ** attempt)
    raise RuntimeError(f"page {page} still rate limited after {max_tries} tries")

def fetch_all(api, headers, sleep, size=25):
    records, page, total = [], 1, 1
    while page <= total:
        body = fetch_page(api, page, size, headers, sleep)
        records.extend(body["data"])
        total = body["total_pages"]
        page += 1
    return records

from datetime import datetime

def first_problem(rec, seen, known):
    """The first rule a raw order breaks, or None. `seen` holds the order ids already processed."""
    if rec["order_id"] in seen:
        return "duplicate order_id"
    if not rec["created_at"]:
        return "missing created_at"
    try:
        datetime.strptime(rec["created_at"], "%Y-%m-%dT%H:%M:%SZ")
    except ValueError:
        return "bad created_at"
    if not isinstance(rec["amount_cents"], int) or rec["amount_cents"] <= 0:
        return "bad amount"
    if rec["customer_id"].strip().upper() not in known:
        return "unknown customer"
    if rec["currency"].strip().upper() != "EUR":
        return "bad currency"
    if rec["status"].strip().lower() not in ("paid", "refunded", "failed"):
        return "bad status"
    return None

def transform(rec):
    """Typed, normalised copy of a valid raw order."""
    return {"sale_id": int(rec["order_id"][1:]), "order_id": rec["order_id"],
            "customer_id": rec["customer_id"].strip().upper(), "product_id": rec["product_id"],
            "quantity": int(rec["quantity"]), "amount_cents": rec["amount_cents"],
            "status": rec["status"].strip().lower(), "created_at": rec["created_at"],
            "date_key": int(rec["created_at"][:10].replace("-", ""))}

def clean_orders(raw, known):
    good, quarantine, seen = [], [], set()
    for rec in raw:
        reason = first_problem(rec, seen, known)
        seen.add(rec["order_id"])
        if reason:
            quarantine.append({"order_id": rec["order_id"], "reason": reason, "payload": rec})
        else:
            good.append(transform(rec))
    return good, quarantine

import sqlite3
from datetime import date, timedelta

DDL = """
CREATE TABLE dim_date (date_key INTEGER PRIMARY KEY, full_date TEXT, year INTEGER, month INTEGER);
CREATE TABLE dim_product (product_key INTEGER PRIMARY KEY AUTOINCREMENT, product_id TEXT UNIQUE, product_name TEXT, category TEXT);
CREATE TABLE dim_customer (customer_key INTEGER PRIMARY KEY AUTOINCREMENT, customer_id TEXT, customer_name TEXT, country TEXT,
                           valid_from TEXT, valid_to TEXT, is_current INTEGER);
CREATE TABLE fact_sales (sale_id INTEGER PRIMARY KEY, date_key INTEGER, customer_key INTEGER, product_key INTEGER,
                         quantity INTEGER, amount_cents INTEGER);
CREATE TABLE etl_state (name TEXT PRIMARY KEY, watermark TEXT);
"""

def init_warehouse():
    conn = sqlite3.connect(":memory:")
    conn.executescript(DDL)
    return conn

def load_dim_date(conn, start, end):
    days = (end - start).days + 1
    rows = [(int(d.strftime("%Y%m%d")), d.isoformat(), d.year, d.month) for d in (start + timedelta(days=i) for i in range(days))]
    with conn:
        conn.executemany("INSERT OR IGNORE INTO dim_date VALUES (?, ?, ?, ?)", rows)

def load_dim_product(conn, products):
    with conn:
        conn.executemany("""INSERT INTO dim_product (product_id, product_name, category) VALUES (?, ?, ?)
                            ON CONFLICT(product_id) DO UPDATE SET product_name = excluded.product_name, category = excluded.category""", products)

def load_dim_customer(conn, customers, as_of, first_from="2026-01-01"):
    """Type 2 history: a changed customer gets a new row; the old row is closed on `as_of`."""
    with conn:
        for cid, name, country in customers:
            cur = conn.execute("SELECT customer_key, customer_name, country FROM dim_customer WHERE customer_id = ? AND is_current = 1", (cid,)).fetchone()
            if cur is None:
                conn.execute("INSERT INTO dim_customer (customer_id, customer_name, country, valid_from, valid_to, is_current) VALUES (?, ?, ?, ?, '9999-12-31', 1)",
                             (cid, name, country, first_from))
            elif (cur[1], cur[2]) != (name, country):
                conn.execute("UPDATE dim_customer SET valid_to = ?, is_current = 0 WHERE customer_key = ?", (as_of, cur[0]))
                conn.execute("INSERT INTO dim_customer (customer_id, customer_name, country, valid_from, valid_to, is_current) VALUES (?, ?, ?, ?, '9999-12-31', 1)",
                             (cid, name, country, as_of))

def load_fact(conn, good):
    """Incremental: only paid orders newer than the watermark; upsert on sale_id; the watermark moves after the load."""
    row = conn.execute("SELECT watermark FROM etl_state WHERE name = 'fact_sales'").fetchone()
    mark = row[0] if row else ""
    new = [g for g in good if g["created_at"] > mark]
    facts = []
    for g in new:
        if g["status"] != "paid":
            continue
        day = g["created_at"][:10]
        ck = conn.execute("SELECT customer_key FROM dim_customer WHERE customer_id = ? AND valid_from <= ? AND ? < valid_to", (g["customer_id"], day, day)).fetchone()[0]
        pk = conn.execute("SELECT product_key FROM dim_product WHERE product_id = ?", (g["product_id"],)).fetchone()[0]
        facts.append((g["sale_id"], g["date_key"], ck, pk, g["quantity"], g["amount_cents"]))
    with conn:
        conn.executemany("""INSERT INTO fact_sales VALUES (?, ?, ?, ?, ?, ?)
                            ON CONFLICT(sale_id) DO UPDATE SET date_key = excluded.date_key, customer_key = excluded.customer_key,
                            product_key = excluded.product_key, quantity = excluded.quantity, amount_cents = excluded.amount_cents""", facts)
        if new:
            conn.execute("INSERT INTO etl_state VALUES ('fact_sales', ?) ON CONFLICT(name) DO UPDATE SET watermark = excluded.watermark",
                         (max(g["created_at"] for g in new),))
    return len(facts)
```

### Example 4: What a thousand times the data costs

`calls_needed` simulates the ingestion loop: a call that is rate limited is repeated, and every third call is limited. The same function gives the call counts for 120, 12,000 and 120,000 records. With two seconds of waiting per limited call the waiting time shows where a real pipeline would change its approach.

```python run
def calls_needed(n_records, size, every):
    pages = -(-n_records // size)
    calls = done = 0
    while done < pages:
        calls += 1
        if every and calls % every == 0:
            continue
        done += 1
    return pages, calls

for n in (120, 12000, 120000):
    pages, calls = calls_needed(n, 25, 3)
    limited = calls - pages
    print(f"records={n} pages={pages} calls={calls} limited={limited} wait_minutes={limited * 2 // 60}")
pages, calls = calls_needed(120000, 500, 3)
print("with page size 500:", pages, "pages,", calls, "calls")
```

```output
records=12000 pages=480 calls=719 limited=239 wait_minutes=7
records=120000 pages=4800 calls=7199 limited=2399 wait_minutes=79
with page size 500: 240 pages, 359 calls
```

### Example 5: Check the demo plan

## Daily review

### Key takeaways

- The final report is a list of numbers that reconcile: raw = clean + quarantined, fact rows are the paid clean orders, a rerun adds nothing.
- Requirements written on Day 173 become acceptance checks; a check that cannot fail proves nothing.
- Incremental loads cost per new row; full loads cost per row of history.
- At a thousand times the data the architecture stays and the engines change: page size and parallel ingestion, PostgreSQL or a warehouse, Spark for cleaning.
- A good demo is five minutes: problem, flow, result with proof, two trade-offs, limits.

### Common mistakes

- Presenting code line by line instead of decisions and results.
- Quoting numbers that were not produced by the final run.
- Hiding limitations. Name late-arriving data, the stand-in tools and the small test sample yourself.
- Listing choices without alternatives, so they do not look like decisions.
- Over-running the time: plan for four and a half minutes.
- Treating the project as finished: write down the next steps while the details are fresh.
