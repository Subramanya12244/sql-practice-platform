## Understand

### Expressions: computing a value for every row

So far a select list has held columns and aggregates. It can also hold **expressions**: formulas that compute a new value from columns, literals and functions, one result per row. `unit_price * 1.1` is an expression and so is `UPPER(company_name)`. A **function** is a named operation that takes arguments in parentheses and returns a value. Today covers three families: conditional logic with `CASE`, text functions and number functions. All of them are evaluated row by row in the `SELECT` step (and may also be used in `WHERE`, `GROUP BY`, `HAVING` and `ORDER BY`).

### CASE: if/else inside a query

`CASE` is SQL's if-then-else and it is an expression, so it returns a value. The searched form tests conditions in order:

`CASE WHEN condition_1 THEN result_1 WHEN condition_2 THEN result_2 ELSE other END`

SQL checks the `WHEN` conditions from top to bottom and returns the result of the first one that is true. The rest are not looked at, so the order matters: `WHEN unit_price < 30 ... WHEN unit_price < 10` would never reach the second branch. If no condition is true and there is no `ELSE`, the result is NULL, which is a quiet source of bugs; write an `ELSE` unless NULL is what you want. All results must be compatible types (all text, or all numbers).

The simple form compares one expression with several values: `CASE ship_via WHEN 1 THEN 'first' WHEN 2 THEN 'second' ELSE 'other' END`. It is shorthand for equality tests only. Because a condition that evaluates to NULL is not true, `CASE x WHEN NULL ...` never matches; use `WHEN x IS NULL`.

### Text functions

A text value is a sequence of characters, and the common functions are all about cutting, joining and cleaning it. `LENGTH(s)` counts characters. `UPPER` and `LOWER` change case; `INITCAP` capitalises each word. `LEFT(s, n)` and `RIGHT(s, n)` take the first or last `n` characters. `POSITION('x' IN s)` returns where `x` first occurs, counting from 1, and 0 if absent. `SUBSTRING(s FROM start FOR length)` cuts a piece. `SPLIT_PART(s, delimiter, n)` returns the `n`-th piece of a string split at the delimiter, which is the easy way to split `'Maria Anders'` into first and last name. `TRIM(s)` removes spaces at both ends, and `REPLACE(s, from, to)` swaps every occurrence of one piece of text for another.

To join text, use `||` or `CONCAT(a, b, ...)`. They differ with NULL: `'a' || NULL` is NULL, whereas `CONCAT('a', NULL)` ignores the NULL and returns `'a'`. In Northwind the `phone` column is empty (NULL) everywhere, so `REPLACE(phone, '-', '')` returns NULL for every row: functions on NULL return NULL. Wrap with `COALESCE` (day 35) when you need a fallback.

### Number functions and the integer division trap

`ROUND(x, n)` rounds a numeric to `n` decimals, `CEIL(x)` rounds up to the next whole number, `FLOOR(x)` rounds down, `ABS(x)` removes the sign and `x % y` returns the remainder of division. These work on `numeric` values; as on day 32, a `real` column such as `discount` must be cast with `::numeric` before `ROUND(value, n)`.

The trap is **integer division**: when both sides are integers, PostgreSQL returns an integer and drops the fraction. `7 / 2` is 3, not 3.5. To get a fraction make one side `numeric`: `7 / 2.0` or `7::numeric / 2`. Percentages computed as `count_a / count_b` are the classic victim: the answer is 0 or 1 until you add a cast.

### Conditional aggregation

Putting `CASE` inside an aggregate lets one query count or sum different subsets side by side. `SUM(CASE WHEN freight >= 100 THEN 1 ELSE 0 END)` adds 1 for each high-freight order and 0 otherwise, so it counts them. `COUNT(CASE WHEN freight >= 100 THEN 1 END)` does the same, because `COUNT` skips the NULL that a missing `ELSE` produces. PostgreSQL also offers the shorter `COUNT(*) FILTER (WHERE freight >= 100)`, which is not available in every database. Combined with `GROUP BY`, conditional aggregation builds a small pivot table: one row per group and one column per condition.

### Common misconception

Learners expect `CASE` to change rows like `WHERE`. It does not remove any row; it only computes a value for each row. To count only some rows you either filter with `WHERE` (all aggregates see the same rows) or use conditional aggregation (each aggregate sees its own subset).

### Why it matters

Raw data is rarely in the shape a report needs. Segmenting customers, bucketing prices, cleaning names and building "orders by status" columns are daily analyst tasks, and nearly all of them are `CASE` plus a few functions.

## Syntax and key functions

Searched and simple `CASE`:

```sql-syntax
CASE
  WHEN condition_1 THEN result_1
  WHEN condition_2 THEN result_2
  ELSE default_result
END

CASE expression
  WHEN value_1 THEN result_1
  WHEN value_2 THEN result_2
  ELSE default_result
END
```

Conditional aggregation, two equivalent forms:

```sql-syntax
SUM(CASE WHEN condition THEN 1 ELSE 0 END)
COUNT(*) FILTER (WHERE condition)
```

| Function | Returns | Example result |
|---|---|---|
| `UPPER(s)`, `LOWER(s)`, `INITCAP(s)` | Text in the chosen case | `UPPER('ana')` is `ANA` |
| `LENGTH(s)` | Number of characters | `LENGTH('Ana')` is 3 |
| `LEFT(s, n)`, `RIGHT(s, n)` | First or last `n` characters | `LEFT('Alfreds', 3)` is `Alf` |
| `POSITION(x IN s)` | Start position of `x` (1-based), 0 if absent | `POSITION(' ' IN 'Ana Trujillo')` is 4 |
| `SUBSTRING(s FROM a FOR n)` | `n` characters from position `a` | `SUBSTRING('Alfreds' FROM 2 FOR 3)` is `lfr` |
| `SPLIT_PART(s, d, n)` | The `n`-th piece of `s` split at `d` | `SPLIT_PART('Maria Anders', ' ', 2)` is `Anders` |
| `TRIM(s)`, `REPLACE(s, a, b)` | Text without end spaces; text with `a` swapped for `b` | `REPLACE('a-b', '-', '')` is `ab` |
| `a \|\| b`, `CONCAT(a, b)` | Joined text; `\|\|` gives NULL if either is NULL, `CONCAT` skips NULL | `CONCAT('a', NULL)` is `a` |
| `ROUND(x, n)`, `CEIL(x)`, `FLOOR(x)` | Rounded, rounded up, rounded down | `CEIL(17.5)` is 18 |
| `ABS(x)`, `x % y` | Absolute value; remainder | `10 % 3` is 1 |

## Learn by example

### Example 1: Price bands with CASE

A searched `CASE` labels each product. Conditions are tested top to bottom, so the second branch only sees prices of 10 or more and `unit_price < 30` really means "10 up to 30". The `ELSE` catches everything else. Each row gets its own label; no row is removed.

```sql run
SELECT product_id, product_name, unit_price,
       CASE
         WHEN unit_price < 10 THEN 'budget'
         WHEN unit_price < 30 THEN 'standard'
         ELSE 'premium'
       END AS band
FROM products
WHERE product_id IN (1, 9, 13, 19, 38, 47)
ORDER BY product_id;
```

```output
product_id | product_name | unit_price | band
1 | Chai | 18.00 | standard
9 | Mishi Kobe Niku | 97.00 | premium
13 | Konbu | 6.00 | budget
19 | Teatime Chocolate Biscuits | 9.20 | budget
38 | Côte de Blaye | 263.50 | premium
47 | Zaanse koeken | 9.50 | budget
```

### Example 2: A simple CASE and a status flag

The first column uses the simple form to translate a code into text; the second tests a NULL, which the simple form could not do. Together they turn the raw `ship_via` number and the missing ship date into readable labels.

```sql run
SELECT order_id, ship_via,
       CASE ship_via WHEN 1 THEN 'carrier one' WHEN 2 THEN 'carrier two' ELSE 'carrier three' END AS carrier,
       CASE WHEN shipped_date IS NULL THEN 'open' ELSE 'shipped' END AS status
FROM orders
ORDER BY order_id
LIMIT 5;
```

```output
order_id | ship_via | carrier | status
10248 | 1 | carrier one | open
10249 | 2 | carrier two | shipped
10250 | 3 | carrier three | shipped
10251 | 1 | carrier one | shipped
10252 | 2 | carrier two | shipped
```

### Example 3: CASE with GROUP BY

Repeating the `CASE` in `GROUP BY` summarises the products by band. Grouping by the label (here `GROUP BY 1`, the first select column, as a shorthand) gives one row per band. `ORDER BY MIN(unit_price)` puts the bands in price order, and the result shows how many products and what average price each band has.

```sql run
SELECT CASE
         WHEN unit_price < 10 THEN 'budget'
         WHEN unit_price < 30 THEN 'standard'
         ELSE 'premium'
       END AS band,
       COUNT(*) AS products,
       ROUND(AVG(unit_price), 2) AS avg_price
FROM products
GROUP BY 1
ORDER BY MIN(unit_price);
```

```output
band | products | avg_price
budget | 11 | 7.46
standard | 41 | 17.71
premium | 25 | 56.58
```

### Example 4: Cleaning and splitting text

Several text functions on the same rows. `LEFT` makes a three-letter code, `SPLIT_PART` splits the contact name at the space, `CONCAT` joins city and country, and `LENGTH` counts characters. The `||` operator would give the same result as `CONCAT` here because neither value is NULL.

```sql run
SELECT customer_id,
       UPPER(LEFT(company_name, 3)) AS code,
       SPLIT_PART(contact_name, ' ', 1) AS first_name,
       SPLIT_PART(contact_name, ' ', 2) AS last_name,
       CONCAT(city, ', ', country) AS place,
       LENGTH(company_name) AS name_length
FROM customers
ORDER BY customer_id
LIMIT 4;
```

```output
customer_id | code | first_name | last_name | place | name_length
ALFKI | ALF | Maria | Anders | Berlin, Germany | 19
ANATR | ANA | Ana | Trujillo | México D.F., Mexico | 24
ANTON | ANT | Antonio | Moreno | México D.F., Mexico | 23
AROUT | ARO | Thomas | Hardy | London, UK | 15
```

### Example 5: Numeric functions and integer division

`ROUND`, `CEIL` and `FLOOR` give three versions of a price, and `%` shows the remainder. The last two columns demonstrate the trap: `7 / 2` is integer division and returns 3, while `7 / 2.0` returns 3.5. Always make one side numeric when you want a fraction.

```sql run
SELECT product_id, unit_price,
       ROUND(unit_price * 1.1, 1) AS plus_10_pct,
       CEIL(unit_price) AS rounded_up,
       FLOOR(unit_price) AS rounded_down,
       unit_price % 5 AS remainder_5,
       7 / 2 AS int_division,
       7 / 2.0 AS numeric_division
FROM products
ORDER BY product_id
LIMIT 3;
```

```output
product_id | unit_price | plus_10_pct | rounded_up | rounded_down | remainder_5 | int_division | numeric_division
1 | 18.00 | 19.8 | 18 | 18 | 3.00 | 3 | 3.5000000000000000
2 | 19.00 | 20.9 | 19 | 19 | 4.00 | 3 | 3.5000000000000000
3 | 10.00 | 11.0 | 10 | 10 | 0.00 | 3 | 3.5000000000000000
```

### Example 6: Conditional aggregation by carrier

For each carrier one query produces several counts that would otherwise need several queries. The `SUM(CASE ...)` and `COUNT(CASE ...)` forms both count the high-freight orders, and `FILTER` counts the open ones. The three columns come from the same grouped rows, and each aggregate sees its own subset.

```sql run
SELECT ship_via,
       COUNT(*) AS orders,
       SUM(CASE WHEN freight >= 100 THEN 1 ELSE 0 END) AS high_freight,
       COUNT(CASE WHEN freight >= 100 THEN 1 END) AS high_freight_again,
       COUNT(*) FILTER (WHERE shipped_date IS NULL) AS open_orders
FROM orders
GROUP BY ship_via
ORDER BY ship_via;
```

```output
ship_via | orders | high_freight | high_freight_again | open_orders
1 | 34 | 19 | 19 | 5
2 | 33 | 12 | 12 | 5
3 | 33 | 19 | 19 | 5
```

## Real-world applications

**Customer and product segmentation.** Bands such as budget, standard and premium (examples 1 and 3) are how analysts turn a continuous number into groups a business can act on, and the same `CASE` feeds charts and pricing reviews.

**Cleaning messy text.** Real exports contain odd case, stray spaces and combined fields. Functions like `TRIM`, `INITCAP` and `SPLIT_PART` (example 4) normalise them before joins and deduplication.

**Status and KPI columns.** `open` and `shipped` flags (example 2) and conditional counts per carrier (example 6) are the building blocks of operational dashboards: late orders, unshipped orders, high-value orders per team.

**Ratios and percentages.** Rates such as "share of orders with high freight" divide two counts, and example 5 shows why one side must be numeric or the answer collapses to 0 or 1.

## Daily review

### Key takeaways

- `CASE` is an expression: it returns a value per row, never removes rows. First true `WHEN` wins; no `ELSE` means NULL.
- Use the searched form for ranges and conditions, the simple form for equality against fixed values.
- Text functions return NULL when an input is NULL, except `CONCAT`, which skips NULL.
- Integer divided by integer is an integer in PostgreSQL; cast one side to `numeric`.
- `SUM(CASE ... THEN 1 ELSE 0 END)`, `COUNT(CASE ... THEN 1 END)` and `COUNT(*) FILTER (WHERE ...)` count subsets in one query.

### Common mistakes

- Writing `WHEN` branches in the wrong order so that a broad condition hides a narrow one.
- Leaving out `ELSE` and finding NULL labels in the output. Add `ELSE`.
- Mixing result types in `CASE` (`THEN 'high' ELSE 0`), which fails with "invalid input syntax for type integer". Keep every branch the same type.
- Using `CASE x WHEN NULL`, which never matches. Use `WHEN x IS NULL`.
- Computing `COUNT(a) / COUNT(b)` and getting 0 or 1. Use `COUNT(a)::numeric / COUNT(b)`.
- Joining text with `||` when a value can be NULL and losing the whole string. Use `CONCAT` or `COALESCE`.
- Expecting `POSITION` to start at 0. It starts at 1 and returns 0 for "not found".

### Revision notes

- `CASE WHEN ... THEN ... ELSE ... END`: top to bottom, first match.
- `SPLIT_PART(s, ' ', 1)` first word; `LEFT`, `SUBSTRING`, `POSITION`, `REPLACE`, `TRIM`.
- `7 / 2` is 3, `7 / 2.0` is 3.5.
- Conditional counts: `SUM(CASE ...)`, `COUNT(CASE ...)`, `FILTER`.
