## Objectives

- Order rows with `sort_values` by one or several columns, in ascending or descending order, and control where missing values go.
- Restore a tidy 0, 1, 2 index after sorting with `reset_index(drop=True)`, and sort by the index with `sort_index`.
- Create derived columns by assigning to `df["new"]`, and with the chained, non-modifying `assign` method.
- Change column labels with `rename` and remove columns or rows with `drop`.
- Explain which of these operations return a new DataFrame and which change the original.

## Understand

### Sorting rows

`df.sort_values("price")` returns a new DataFrame with the rows ordered by the values in the `price` column, smallest first. The original table is not changed, and the row labels travel with their rows, so after sorting the index may read `3, 0, 2, 1` instead of `0, 1, 2, 3`. This is correct: the label belongs to the row, not to the position. `ascending=False` reverses the order, giving the largest first.

To sort by several columns, pass a list: `df.sort_values(["city", "price"])` sorts by city first and, among rows with the same city, by price. The `ascending` argument can also be a list with one entry per column, so `ascending=[True, False]` means city A to Z and, inside each city, the highest price first. Text sorts alphabetically by character code, which means that uppercase letters come before lowercase ones (`"Zoe"` before `"adam"`); clean the case first if that matters.

Missing values are placed last by default, whichever direction you sort. The argument `na_position="first"` moves them to the top. When two rows have equal sort values, their order is not guaranteed unless you request a stable sort with `kind="stable"`, which keeps tied rows in their original order. Whenever the order of tied rows matters in a report, add a second sort column or use `kind="stable"`.

`sort_index()` orders the rows by their labels instead of by a column. It is the way back to the original order after sorting by values, if the labels are still the original ones. After a sort, `reset_index(drop=True)` replaces the labels by a fresh `0, 1, 2, ...` and throws away the old labels. Without `drop=True` the old index would be kept as a new column called `index`.

### Derived columns

A **derived column** is a new column calculated from existing ones. You create it by assigning to a name that does not exist yet: `df["total"] = df["qty"] * df["price"]`. The right side is a vectorised calculation on whole columns, the same idea as Day 65, and it needs no loop. If the name exists, the assignment overwrites that column. You can use a constant (`df["currency"] = "EUR"`), or the result of a comparison (`df["big"] = df["qty"] > 5`), which gives a column of booleans. The new column is added at the end of the table.

The assignment form **changes the DataFrame in place**. That is convenient in a script, but it means that running a cell twice or passing the table to a function can modify the original unexpectedly. When you want to keep the original, work on `df.copy()` first.

### assign: new columns without changing the original

`df.assign(total=df["qty"] * df["price"])` returns a **new** DataFrame that has the extra column, and leaves `df` as it was. The names of the new columns are keyword arguments. Several columns can be created in one call, and a later one may use an earlier one if you pass a function, `lambda t: t["total"] * 1.2`, where `t` is the table built so far. The advantage is that `assign` fits into a chain of steps: `df.assign(...).sort_values(...)` reads top to bottom as a recipe, and no step touches the source table. Many analysts prefer `assign` for exactly this reason.

### rename and drop

`df.rename(columns={"qty": "quantity"})` returns a new table with the listed columns renamed; names that are not in the dictionary stay as they are. `df.rename(index={0: "first"})` does the same for row labels. A common cleanup is to lower-case every column label: `df.columns = [c.lower() for c in df.columns]`, an assignment to the `columns` attribute that you met on Day 68.

`df.drop(columns=["colour"])` returns a new table without the listed columns. `df.drop(index=[1, 3])` removes the rows with those **labels**. Remember the label versus position difference from Day 71: `drop(index=[1])` removes the row labelled 1, which may not be the second row. Dropping a name that does not exist raises a `KeyError`, unless you pass `errors="ignore"`.

### Which operations modify in place

A useful rule: methods such as `sort_values`, `rename`, `drop` and `assign` return a new DataFrame. If you write `df.sort_values("price")` on a line by itself and do not store the result, nothing visible happens, exactly like `name.upper()` on Day 4. You must write `df = df.sort_values("price")` or `ordered = df.sort_values("price")`. Plain assignment to a column, `df["total"] = ...`, and assignment to `df.columns` change the table in place. Many methods also accept `inplace=True`, but it saves no memory in practice and breaks chaining, so these lessons always store the returned table.

### The common misconception

Learners think that `sort_values` reorders the table itself and that the index follows. The table you stored is unchanged, and the sorted version keeps the old labels. So `sorted_df.loc[0]` selects the row labelled 0, wherever it has moved, whereas `sorted_df.iloc[0]` selects the first row of the sorted table, which is the smallest or largest value. This is the Day 71 distinction again, and it is the cause of the common bug "I sorted the data and took row 0, but got the wrong row".

### Why it matters in data work

Rankings, top-n lists and reports all start with sorting. Derived columns turn raw measures into the figures people ask for: totals, margins, flags, per-unit costs. Renaming and dropping give a table the clean shape that the next step or reader expects. Using `assign` and returned copies, rather than modifying the original, keeps an analysis repeatable, because you can run it again from the top and get the same result.

### A short trace

Start with prices `[9.5, 4.0, 12.25]` labelled `0, 1, 2`. `sort_values("price")` returns the rows in the order 1, 0, 2: the labels now read `1, 0, 2` and `iloc[0]` is the row with 4.0. Adding `total = qty * price` with `assign` gives a new table with a fourth column. Dropping the `colour` column gives yet another table. After three steps, the original `df` is still exactly as it was, because each step returned a new table.

## Syntax and key functions

Sort, derive, rename, drop:

```python
df.sort_values("price", ascending=False, na_position="last", kind="stable")
df.sort_values(["city", "price"], ascending=[True, False])
df.sort_index()
df.reset_index(drop=True)
df["total"] = df["qty"] * df["price"]
df.assign(total=df["qty"] * df["price"], tax=lambda t: t["total"] * 0.2)
df.rename(columns={"old": "new"})
df.drop(columns=["colour"])
df.drop(index=[1, 3])
```

| Expression | Returns |
|---|---|
| `df.sort_values(by, ascending=True)` | New table ordered by one or more columns. |
| `na_position="first"`, `kind="stable"` | Put missing values first; keep tied rows in original order. |
| `df.sort_index()` | New table ordered by row labels. |
| `df.reset_index(drop=True)` | New table with index 0, 1, 2, ... |
| `df["new"] = expr` | Adds or replaces a column **in place**. |
| `df.assign(new=expr)` | New table with the column; original unchanged. |
| `df.rename(columns={...})` | New table with renamed columns. |
| `df.drop(columns=[...])`, `df.drop(index=[...])` | New table without those columns or row labels. |
| `df.nlargest(n, "col")` | The n rows with the largest values. |

## Learn by example

### Example 1: Sorting by one and several columns

Sorting returns a new table and the labels travel with the rows. The second sort orders by city and then by descending price. The original is unchanged, and `reset_index(drop=True)` renumbers the result.

```python run
import pandas as pd

pd.set_option("display.width", 200)
pd.set_option("display.max_columns", 20)

df = pd.DataFrame({"city": ["Rome", "Oslo", "Rome", "Oslo", "Lima"],
                   "item": ["a", "b", "c", "d", "e"], "price": [4.0, 9.5, 12.25, 7.0, 3.5]})
print(df.sort_values("price"))
print(df.sort_values("price", ascending=False)["item"].tolist())
by_two = df.sort_values(["city", "price"], ascending=[True, False])
print(by_two)
print(by_two.reset_index(drop=True))
print(df["item"].tolist())
```

### Example 2: Missing values, labels and positions after sorting

Missing values go last by default and first with `na_position`. After sorting, `loc[0]` still finds the row labelled 0, while `iloc[0]` is the first row of the new order. `sort_index` restores the original order.

```python run
import pandas as pd

df = pd.DataFrame({"item": ["a", "b", "c", "d"], "price": [7.0, None, 12.25, 4.0]})
s = df.sort_values("price")
print(s["item"].tolist())
print(df.sort_values("price", na_position="first")["item"].tolist())
print(df.sort_values("price", ascending=False)["item"].tolist())
print(s.loc[0, "item"], s.iloc[0]["item"])
print(s.index.tolist(), s.sort_index().index.tolist())
print(df.nlargest(2, "price")["item"].tolist())
```

```output
['d', 'a', 'c', 'b']
['b', 'd', 'a', 'c']
['c', 'a', 'd', 'b']
a d
[3, 0, 2, 1] [0, 1, 2, 3]
['c', 'a']
```

### Example 3: Derived columns and assign

Assigning to a new name adds a column in place. `assign` returns a new table and leaves the original alone, and a later column can use an earlier one with a function.

```python run
import pandas as pd

pd.set_option("display.width", 200)
pd.set_option("display.max_columns", 20)

df = pd.DataFrame({"item": ["pen", "ink", "cap"], "qty": [3, 1, 4], "price": [9.5, 20.0, 3.25]})
new = df.assign(total=df["qty"] * df["price"], big=lambda t: t["total"] > 25)
print(new)
print(df.columns.tolist())
df["currency"] = "EUR"
df["many"] = df["qty"] > 2
print(df)
```

### Example 4: rename and drop

`rename` with a dictionary changes only the listed labels. `drop` removes columns by name or rows by label, and each returns a new table. The original keeps all its columns.

```python run
import pandas as pd

pd.set_option("display.width", 200)
pd.set_option("display.max_columns", 20)

df = pd.DataFrame({"item": ["pen", "ink", "cap"], "qty": [3, 1, 4], "price": [9.5, 20.0, 3.25], "note": ["x", "y", "z"]})
slim = df.drop(columns=["note"]).rename(columns={"qty": "quantity", "price": "unit_price"})
print(slim)
print(df.drop(index=[1]))
print(df.columns.tolist())
try:
    df.drop(columns=["nothing"])
except KeyError as e:
    print("KeyError:", str(e)[:30])
print(df.drop(columns=["nothing"], errors="ignore").shape)
```

### Example 5: A chain, top three by revenue

A table of orders gets a revenue column, is sorted by revenue and the top three are kept with a fresh index. The two equal revenues keep their original order because the sort is stable. Each step returns a new table, so the whole recipe is one expression and the source stays intact.

```python run
import pandas as pd

pd.set_option("display.width", 200)
pd.set_option("display.max_columns", 20)

orders = pd.DataFrame({"city": ["Oslo", "Rome", "Oslo", "Lima", "Rome", "Oslo"],
                       "qty": [3, 8, 6, 2, 9, 4], "price": [9.5, 4.0, 12.25, 7.0, 3.5, 8.0]})
top = (orders.assign(revenue=orders["qty"] * orders["price"])
       .sort_values("revenue", ascending=False, kind="stable")
       .head(3)
       .reset_index(drop=True)
       .rename(columns={"revenue": "rev"}))
print(top)
print(orders.shape, top.shape)
```

```output
   city  qty  price   rev
0  Oslo    6  12.25  73.5
1  Rome    8   4.00  32.0
2  Oslo    4   8.00  32.0
(6, 3) (3, 4)
```

## Real-world applications

- **Rankings and top-n reports.** Sorting by a measure and taking `head(n)`, as in Example 5, gives the best customers, slowest queries or largest orders.
- **Computing business figures.** Derived columns such as revenue, margin or percentage share, as in Example 3, are one vectorised line each.
- **Preparing a clean output table.** `rename` and `drop` give a table the column names and the content that a report or the next system expects, as in Example 4.
- **Repeatable pipelines.** `assign`, `sort_values` and `rename` chained, as in Example 5, form a recipe that can be re-run on new data without changing the source.

## Daily review

### Key takeaways

- `sort_values` returns a new table; labels travel with the rows; missing values go last unless `na_position="first"`.
- Sort by several columns with a list and `ascending=[...]`; use `kind="stable"` or a second column to fix tied rows.
- `reset_index(drop=True)` gives a tidy index; `sort_index` orders by labels.
- `df["new"] = ...` modifies in place; `assign` returns a new table.
- `rename` and `drop` return new tables; store the result.

### Common mistakes

- Calling `df.sort_values("price")` and not storing the result, so `df` is still unsorted.
- Using `loc[0]` after sorting and expecting the smallest value; use `iloc[0]`.
- Forgetting `drop=True` in `reset_index`, which adds an `index` column.
- Writing `df.drop("note")` for a column, which raises a `KeyError` because the default axis is rows. Use `columns=["note"]`.
- Sorting text with mixed case and being surprised that uppercase comes first.
- Using `df.rename({"a": "b"})` without `columns=`, which renames row labels, not columns.

### Revision notes

- `df.sort_values(["a", "b"], ascending=[True, False])`.
- `df.reset_index(drop=True)`, `df.sort_index()`.
- `df["x"] = ...` in place; `df.assign(x=...)` new table.
- `df.rename(columns={...})`, `df.drop(columns=[...])`, `df.drop(index=[...])`.
