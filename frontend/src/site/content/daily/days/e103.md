## Objectives

- Send `GET` requests with the `requests` library using query parameters, headers and a timeout, and explain what each argument does.
- Explain why every request needs an explicit `timeout`, and what the one-number and two-number forms mean.
- Use a `Session` to share headers and connections across calls, and wrap the API in a small client class.
- Name the exceptions a request can raise (`Timeout`, `ConnectionError`, `HTTPError`, JSON decoding errors) and say which step raises each.
- Write client code against a stand-in that has the same call shape as `requests`, so the logic can be tested without a network.

## Understand

### One call, four decisions

`requests.get(url, params=..., headers=..., timeout=...)` looks simple, but each argument is a decision. The **URL** is the address up to the path. **`params`** is a dictionary that `requests` turns into the query string, encoding special characters for you. **`headers`** carries the credential and the format you accept. **`timeout`** is how long you are willing to wait. A fifth decision is what to do with the answer: check the status, then parse the body. This day builds a client that makes those decisions in one place so that the rest of the pipeline never repeats them.

### Query parameters

Pass parameters as a dictionary: `params={"page": 2, "page_size": 50}` produces `?page=2&page_size=50`. A value that is a list produces repeated keys (`{"status": ["paid", "refunded"]}` gives `status=paid&status=refunded`), a value of `None` is dropped, and a value with a space or an ampersand is percent-encoded. Never assemble the query with an f-string: `f"?name={name}"` breaks on `Ann & Bob` and, when the text comes from outside, lets the caller alter the request. The final URL after encoding is `response.url`, which is useful in logs.

### Timeouts

By default `requests` waits **forever**: if the server accepts the connection and never answers, your pipeline hangs, holding a scheduler slot until someone notices. The `timeout` argument fixes that. A single number, `timeout=10`, applies separately to two phases: the time to establish the connection (**connect timeout**) and the time between bytes while waiting for the response (**read timeout**). A pair, `timeout=(3.05, 27)`, sets them separately. Two details matter. First, it is not a cap on the total duration of the call: a server that sends one byte every nine seconds with `timeout=10` never times out. Second, a timeout raises an exception, which your code must handle; Day 107 and Day 108 build the retry and logging around it. A sensible default for a batch pipeline is a few seconds to connect and tens of seconds to read, depending on the endpoint.

### Sessions

`requests.get` opens a new connection for each call. A **`requests.Session`** keeps connections alive and reuses them, which makes repeated calls to the same host faster, and it holds settings shared by every call: `session.headers.update({"X-Api-Key": key})` means that you set the key once. A session can also hold cookies, which this API does not use. The session is the natural place for a pipeline's calls: create it once, pass it to the code that needs it, close it at the end (`with requests.Session() as s:`).

### What can go wrong, and where

An API call fails at different steps, and `requests` raises a different exception for each. The base class of all of them is `requests.exceptions.RequestException`.

- The connection cannot be made (wrong host, server down, refused): `requests.exceptions.ConnectionError`. If the connect phase times out: `ConnectTimeout`.
- The server accepted but did not answer within the read timeout: `requests.exceptions.ReadTimeout`. Both timeout kinds are subclasses of `requests.exceptions.Timeout`.
- The server answered with an error status: nothing is raised until you call `response.raise_for_status()`, which raises `requests.exceptions.HTTPError` for 4xx and 5xx.
- The body is not JSON: `response.json()` raises a decoding error (a subclass of `requests.exceptions.RequestException` and of `ValueError` in current versions), for example when a proxy returns an HTML error page with status 200.

Handling them in the order the steps happen (connect, read, status, body) gives each failure its own message in the log.

### A thin client

A **client class** wraps one API: it knows the base URL, adds the credential, applies the timeout, checks the status and returns parsed data. The rest of the pipeline calls `client.get_page(2, 50)` and never sees `requests`. This isolation has a second benefit that matters for tests: because the client takes a session as an argument, a test can pass a **stand-in** that returns canned responses, with no network and no waiting. All browser examples today do exactly that: `FakeSession` has the same `get(url, params=..., headers=..., timeout=...)` call shape as a real session.

### Common misconception

Learners think `timeout=10` means the call ends after ten seconds at most. It is the wait for connection and then between bytes. Another common belief is that `requests.get` raises an error on a 404. It does not: it returns a response, and you must decide what a status means.

### Why it matters

Hanging jobs and silent partial reads are the two failures that cost the most time in API ingestion. An explicit timeout, a status check and a client that logs the final URL turn both into short, readable errors.

## Syntax and key functions

```python
import requests

with requests.Session() as session:
    session.headers.update({"X-Api-Key": api_key, "Accept": "application/json"})
    response = session.get(
        "https://api.shop.example/orders",
        params={"page": 1, "page_size": 50},
        timeout=(3.05, 27),               # connect, read
    )
    response.raise_for_status()
    body = response.json()
```

```python
class OrdersClient:
    def __init__(self, base_url, session, timeout=(3.05, 27)):
        self.base_url, self.session, self.timeout = base_url, session, timeout

    def get_page(self, page, page_size=50):
        response = self.session.get(f"{self.base_url}/orders", params={"page": page, "page_size": page_size}, timeout=self.timeout)
        response.raise_for_status()
        return response.json()
```

| Item | What it does or returns |
|---|---|
| `requests.get(url, params, headers, timeout)` | One request on a fresh connection. |
| `requests.Session()` | Object that shares headers and connections across calls. |
| `session.headers.update({...})` | Default headers for every call. |
| `timeout=5` / `timeout=(3, 20)` | Same limit for connect and read / separate limits. |
| `response.url` | The final URL including the encoded query. |
| `response.raise_for_status()` | `HTTPError` for 4xx and 5xx. |
| `requests.Request(...).prepare().url` | Shows the encoded URL without sending anything. |
| `requests.exceptions.Timeout`, `ConnectionError`, `HTTPError`, `RequestException` | The exception classes to catch. |

## Learn by example

### Example 1: A client class on a stand-in session (browser-safe)

`FakeSession` has the call shape of a session: shared `headers`, `get(url, params, timeout)`, and a record of the calls it received. The client class never knows that it is not talking to the network. The code fetches two pages, shows what the stand-in saw and what the client does on a `401`.

```python run
import json

STATUSES = ["paid", "paid", "refunded", "failed"]
ORDERS = [
    {"order_id": i, "customer_id": i * 7 % 25 + 1, "amount_cents": 1000 + i * 137 % 9000,
     "currency": "EUR" if i % 4 else "USD", "status": STATUSES[i % 4],
     "created_at": f"2026-03-{(i - 1) // 4 + 1:02d}T{i * 7 % 24:02d}:{i * 13 % 60:02d}:00Z"}
    for i in range(1, 121)
]

class Response:
    """Looks like a `requests` response: status_code, headers, json(), raise_for_status()."""
    def __init__(self, status_code, body=None, headers=None):
        self.status_code = status_code
        self._body = body
        self.headers = headers or {}

    def json(self):
        return json.loads(json.dumps(self._body))

    def raise_for_status(self):
        if self.status_code >= 400:
            raise RuntimeError(f"HTTP {self.status_code}")

class FakeSession:
    def __init__(self):
        self.headers = {}
        self.calls = []

    def get(self, url, params=None, headers=None, timeout=None):
        params = params or {}
        self.calls.append((url, dict(params), timeout))
        if {**self.headers, **(headers or {})}.get("X-Api-Key") != "demo-key-123":
            return Response(401, {"error": "invalid api key"})
        page, size = int(params.get("page", 1)), int(params.get("page_size", 20))
        pages = -(-len(ORDERS) // size)
        return Response(200, {"data": ORDERS[(page - 1) * size:page * size], "page": page, "total_pages": pages})

class OrdersClient:
    def __init__(self, base_url, session, timeout=(3.05, 27)):
        self.base_url, self.session, self.timeout = base_url, session, timeout

    def get_page(self, page, page_size=50):
        response = self.session.get(f"{self.base_url}/orders", params={"page": page, "page_size": page_size}, timeout=self.timeout)
        response.raise_for_status()
        return response.json()

session = FakeSession()
session.headers.update({"X-Api-Key": "demo-key-123"})
client = OrdersClient("https://api.shop.example", session)
for n in (1, 3):
    body = client.get_page(n)
    print(body["page"], body["total_pages"], len(body["data"]), body["data"][0]["order_id"])
print(session.calls[0])

bad = OrdersClient("https://api.shop.example", FakeSession())
try:
    bad.get_page(1)
except RuntimeError as err:
    print("error:", err)
```

```output
1 3 50 1
3 3 20 101
('https://api.shop.example/orders', {'page': 1, 'page_size': 50}, (3.05, 27))
error: HTTP 401
```

The key was set once on the session, the timeout lives in the client, and a `401` becomes an exception through `raise_for_status` (the stand-in raises `RuntimeError`; `requests` raises `HTTPError`).

### Example 2: How `requests` encodes parameters

`requests.Request(...).prepare()` builds the request without sending it, so `.url` shows the encoded address. Lists repeat the key, `None` values disappear, and spaces and ampersands are encoded. This needs `requests`, so it is a local example.

```python local
import requests

def show(params):
    return requests.Request("GET", "https://api.shop.example/orders", params=params).prepare().url

print(show({"page": 2, "page_size": 50}))
print(show({"status": ["paid", "refunded"], "currency": None}))
print(show({"customer": "Ann & Bob", "note": "a b"}))
req = requests.Request("GET", "https://api.shop.example/orders", params={"page": 1}, headers={"X-Api-Key": "k"}).prepare()
print(req.method, req.headers["X-Api-Key"])
```

```output
https://api.shop.example/orders?page=2&page_size=50
https://api.shop.example/orders?status=paid&status=refunded
https://api.shop.example/orders?customer=Ann+%26+Bob&note=a+b
GET k
```

An f-string would have put `Ann & Bob` into the URL unencoded, and the server would have seen a parameter named ` Bob`.

### Example 3: Timeouts on a stand-in

The stand-in server answers after a simulated delay in seconds. When the delay is longer than the timeout the stand-in raises `TimeoutError`, as a real read timeout would. The client catches it and reports the page that failed. Without any timeout, the same call would simply wait for the whole delay.

```python run
class SlowSession:
    def __init__(self, delays):
        self.delays = delays

    def get(self, url, params=None, headers=None, timeout=None):
        delay = self.delays.get(params["page"], 0.1)
        if timeout is not None and delay > timeout:
            raise TimeoutError(f"no answer within {timeout}s")
        return {"page": params["page"], "waited": delay}

def fetch(session, page, timeout):
    try:
        return session.get("/orders", params={"page": page}, timeout=timeout)
    except TimeoutError as err:
        return f"page {page} failed: {err}"

session = SlowSession({2: 30})
print(fetch(session, 1, timeout=5))
print(fetch(session, 2, timeout=5))
print(fetch(session, 2, timeout=None))
```

```output
{'page': 1, 'waited': 0.1}
page 2 failed: no answer within 5s
{'page': 2, 'waited': 30}
```

The last call shows what no timeout means: the client accepts the thirty-second wait, and a stuck server would hold it for ever.

### Example 4: A real session, and the two failures a timeout and a refusal cause

This local example uses a real `requests.Session` against the local server, then provokes two network errors on purpose. A socket that accepts connections but never answers produces `ReadTimeout`; a call to a port where the server has been shut down produces `ConnectionError`. Both are subclasses of the base class `RequestException`, which the code confirms for the timeout.

```python local
import socket

import json
import threading
from http.server import BaseHTTPRequestHandler, HTTPServer
from urllib.parse import parse_qs, urlparse

import requests

STATUSES = ["paid", "paid", "refunded", "failed"]
ORDERS = [
    {"order_id": i, "customer_id": i * 7 % 25 + 1, "amount_cents": 1000 + i * 137 % 9000,
     "currency": "EUR" if i % 4 else "USD", "status": STATUSES[i % 4],
     "created_at": f"2026-03-{(i - 1) // 4 + 1:02d}T{i * 7 % 24:02d}:{i * 13 % 60:02d}:00Z"}
    for i in range(1, 121)
]

API_KEY = "demo-key-123"

def start_server(orders, rate_limit_every=0):
    state = {"requests": 0, "orders": {o["order_id"]: dict(o) for o in orders}}

    def route(method, parts, query, body):
        table = state["orders"]
        if parts == ["orders"] and method == "GET":
            rows = [table[k] for k in sorted(table)]
            if "cursor" in query:
                start = int(query["cursor"] or 0)
                size = int(query.get("limit", 25))
                nxt = start + size
                return 200, {"data": rows[start:nxt], "next_cursor": str(nxt) if nxt < len(rows) else None}
            if "offset" in query:
                start, size = int(query["offset"]), int(query.get("limit", 25))
                return 200, {"data": rows[start:start + size], "offset": start, "total": len(rows)}
            page, size = int(query.get("page", 1)), int(query.get("page_size", 20))
            if page < 1 or not 1 <= size <= 100:
                return 400, {"error": "bad paging parameters"}
            pages = -(-len(rows) // size)
            return 200, {"data": rows[(page - 1) * size:page * size], "page": page, "total_pages": pages}
        if parts == ["orders"] and method == "POST":
            if not body or "customer_id" not in body:
                return 422, {"error": "customer_id is required"}
            new_id = max(table) + 1
            table[new_id] = {"order_id": new_id, **body}
            return 201, table[new_id]
        if len(parts) == 2 and parts[0] == "orders" and parts[1].isdigit():
            key = int(parts[1])
            if key not in table:
                return 404, {"error": "order not found"}
            if method == "GET":
                return 200, table[key]
            if method == "PUT":
                table[key] = {"order_id": key, **body}
                return 200, table[key]
            if method == "DELETE":
                del table[key]
                return 204, None
        return 404, {"error": "no such route"}

    class Handler(BaseHTTPRequestHandler):
        def log_message(self, *args):
            pass

        def handle_request(self, method):
            state["requests"] += 1
            length = int(self.headers.get("Content-Length") or 0)
            body = json.loads(self.rfile.read(length)) if length else None
            if self.headers.get("X-Api-Key") != API_KEY:
                status, payload, extra = 401, {"error": "invalid api key"}, {}
            elif rate_limit_every and state["requests"] % rate_limit_every == 0:
                status, payload, extra = 429, {"error": "slow down"}, {"Retry-After": "2"}
            else:
                url = urlparse(self.path)
                query = {k: v[0] for k, v in parse_qs(url.query, keep_blank_values=True).items()}
                status, payload = route(method, url.path.strip("/").split("/"), query, body)
                extra = {}
            data = b"" if payload is None else json.dumps(payload).encode()
            self.send_response(status)
            self.send_header("Content-Type", "application/json")
            self.send_header("Content-Length", str(len(data)))
            for name, value in extra.items():
                self.send_header(name, value)
            self.end_headers()
            self.wfile.write(data)

        do_GET = lambda self: self.handle_request("GET")
        do_POST = lambda self: self.handle_request("POST")
        do_PUT = lambda self: self.handle_request("PUT")
        do_DELETE = lambda self: self.handle_request("DELETE")

    server = HTTPServer(("127.0.0.1", 0), Handler)
    threading.Thread(target=server.serve_forever, daemon=True).start()
    return server, f"http://127.0.0.1:{server.server_port}", state

server, base, state = start_server(ORDERS)
try:
    with requests.Session() as session:
        session.headers.update({"X-Api-Key": API_KEY})
        for page in (1, 2):
            r = session.get(base + "/orders", params={"page": page, "page_size": 50}, timeout=(2, 5))
            r.raise_for_status()
            print(r.json()["page"], len(r.json()["data"]), r.request.headers["X-Api-Key"] == API_KEY)
    mute = socket.socket()
    mute.bind(("127.0.0.1", 0))
    mute.listen(1)
    try:
        requests.get(f"http://127.0.0.1:{mute.getsockname()[1]}/orders", timeout=0.3)
    except requests.exceptions.Timeout as err:
        print("timeout:", type(err).__name__, isinstance(err, requests.exceptions.RequestException))
    finally:
        mute.close()
finally:
    server.shutdown()
    server.server_close()
try:
    requests.get(base + "/orders", timeout=2)
except requests.exceptions.ConnectionError as err:
    print("refused:", type(err).__name__)
```

```output
1 50 True
2 50 True
timeout: ReadTimeout True
refused: ConnectionError
```

## Real-world applications

- **Daily ingestion client.** One `OrdersClient` is used by the extract step, the retry logic and the tests; changing the key header or the timeout means editing one place.
- **Hung job prevention.** A batch job that reads thousands of pages with a timeout fails one page in seconds, instead of blocking a worker slot until the scheduler's own timeout hours later.
- **Testing without the network.** A `FakeSession` with canned responses lets the team test the paging and error code on every commit, in milliseconds.
- **Log lines for operations.** Logging `response.url` and the status for each call lets an on-call engineer reproduce the exact request.

## Daily review

### Key takeaways

- `params` builds a safe query string; never format it by hand.
- A request without `timeout` can wait for ever; set connect and read limits.
- A timeout limits waiting between bytes, not the total duration.
- A `Session` shares headers and connections; a client class centralises URL, key, timeout and status check.
- Each step has its own exception: connect, read, status, body.

### Common mistakes

- **No timeout.** The job hangs. Pass `timeout=` on every call or set it in the client.
- **`f"{url}?page={page}"`.** Breaks on special characters. Use `params=`.
- **Expecting `get` to raise on 404.** It returns a response. Call `raise_for_status()`.
- **Putting the key in the URL.** It ends up in logs. Use a header.
- **Catching `Exception`.** Hides real bugs. Catch `requests.exceptions.RequestException` or its subclasses.

### Revision notes

- `requests.get(url, params=, headers=, timeout=)`; `Session`, `headers.update`.
- `timeout=(connect, read)`.
- Exceptions: `ConnectionError`, `Timeout` (`ConnectTimeout`, `ReadTimeout`), `HTTPError`, `RequestException`.
- Client class + stand-in session for tests.
