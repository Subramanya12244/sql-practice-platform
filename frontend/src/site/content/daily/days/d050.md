## Objectives

- Number rows inside each group with `ROW_NUMBER() OVER (PARTITION BY ... ORDER BY ...)`.
- Choose between `ROW_NUMBER`, `RANK` and `DENSE_RANK` by predicting what each does with ties.
- Write the top N per group pattern: rank in a subquery or CTE, then filter on the rank.
- Add a tie-breaker column to make a ranking deterministic.

## Understand

### Ordering inside a window

On day 49 every `OVER` had at most a `PARTITION BY`, and the window function ignored row order. Ranking functions need an order, because "first", "second" and "third" only mean something relative to a sort. You supply it with `ORDER BY` inside the `OVER` parentheses:

`ROW_NUMBER() OVER (PARTITION BY category_id ORDER BY unit_price DESC)`

Read it as: split the rows by category, sort each category by price from high to low, and number the rows in that order. The `ORDER BY` inside `OVER` only controls the window's calculation. It does not sort the final result. To control the output order you still write a normal `ORDER BY` at the end of the query.

### Three ranking functions

All three assign a position to each row inside its partition. They differ in how they treat **ties**, which are rows that have equal values in the window's `ORDER BY` column.

`ROW_NUMBER()` gives every row a different number, 1, 2, 3 and so on, even when rows tie. Which of two tied rows gets the lower number is not defined unless you make the order unique. `RANK()` gives tied rows the same number, then skips: after two rows ranked 4 the next row is ranked 6. `DENSE_RANK()` also gives tied rows the same number but does not skip: after two rows ranked 4 the next is ranked 5. With no ties, all three return the same numbers.

A short example with prices 30, 20, 20, 10 sorted descending: `ROW_NUMBER` gives 1, 2, 3, 4; `RANK` gives 1, 2, 2, 4; `DENSE_RANK` gives 1, 2, 2, 3. Example 2 shows this on real data, where four beverages share the price 18.00.

### Making a ranking deterministic

When you use `ROW_NUMBER` and the sort column has ties, PostgreSQL may number the tied rows in any order, and the order can change between runs or after a data change. Always add a tie-breaker that is unique, typically the primary key: `ORDER BY unit_price DESC, product_id`. Then every run gives the same numbering. This matters most when you later filter on `row_number = 1`, because the chosen row would otherwise be arbitrary.

### The top N per group pattern

"Top 3 products in each category" cannot be written with `LIMIT`, because `LIMIT` cuts the whole result, not each group. The standard solution has two steps. First rank the rows inside each group in a subquery or CTE. Then filter in the outer query on the rank column. The second step is needed because window functions cannot be used in `WHERE` (day 49).

Which function to use depends on what "top N" should mean. `ROW_NUMBER() <= N` returns exactly N rows per group and cuts through ties arbitrarily (or by your tie-breaker). `RANK() <= N` returns every row whose rank is within N, so tied rows at the boundary are all included and a group can return more than N rows. `DENSE_RANK() <= N` returns the N highest distinct values with all rows that have them. State which meaning the business asks for before choosing.

### Related uses

`ROW_NUMBER() = 1` per group is the usual way to pick one row per group: the latest order per customer, the highest-paid employee per department. Day 55 uses the same idea to remove duplicates. You can also rank over the whole result with no `PARTITION BY`, for example to rank all products by revenue.

### Common misconception

Learners often put the rank into `WHERE` directly or use `LIMIT 3` and expect three rows per group. Neither works. A second misconception is that `RANK` and `ROW_NUMBER` are interchangeable. With ties they return different row counts after filtering, which can change a report without any error message.

### Why it matters

Leaderboards, best sellers per category, latest status per entity and "top three reasons per region" are all ranking problems. Writing them as one ranked query is shorter and faster than correlated subqueries, and the tie behaviour is explicit.

## Syntax and key functions

```sql-syntax
ranking_function() OVER (
  PARTITION BY group_column [, ...]
  ORDER BY sort_column [ASC | DESC] [, tie_breaker ...]
)
```

`PARTITION BY` is optional; without it the whole result is one group. `ORDER BY` is required for meaningful ranking. The ranking functions take no arguments.

The top N pattern:

```sql-syntax
SELECT *
FROM (
  SELECT t.*,
         ROW_NUMBER() OVER (PARTITION BY group_column ORDER BY sort_column DESC, id) AS rn
  FROM table_name AS t
) AS ranked
WHERE rn <= N;
```

| Function | Returns | Ties |
|---|---|---|
| `ROW_NUMBER()` | Sequence number 1, 2, 3 within the partition | Different numbers; order undefined without a tie-breaker |
| `RANK()` | Position with gaps | Same number, next number skipped |
| `DENSE_RANK()` | Position without gaps | Same number, no skipped numbers |

## Learn by example

### Example 1: number all products by price

`ROW_NUMBER` without `PARTITION BY` numbers the whole result. The `ORDER BY` inside `OVER` sets the numbering order, and the outer `ORDER BY` sets how the rows are shown. The tie-breaker `product_id` makes it repeatable.

```sql run
SELECT product_id, product_name, unit_price,
       ROW_NUMBER() OVER (ORDER BY unit_price DESC, product_id) AS price_position
FROM products
ORDER BY price_position
LIMIT 5;
```

```output
product_id | product_name | unit_price | price_position
38 | Côte de Blaye | 263.50 | 1
29 | Thüringer Rostbratwurst | 123.79 | 2
9 | Mishi Kobe Niku | 97.00 | 3
20 | Sir Rodney's Marmalade | 81.00 | 4
18 | Carnarvon Tigers | 62.50 | 5
```

### Example 2: ROW_NUMBER, RANK and DENSE_RANK with ties

Four products in category 1 cost 18.00 and two cost 14.00. `ROW_NUMBER` still counts 4, 5, 6, 7. `RANK` shows 4 four times and then jumps to 8 for the next row. `DENSE_RANK` shows 4 four times and continues with 5. The window uses only `unit_price` in its `ORDER BY` for RANK so the ties are real; `ROW_NUMBER` gets a tie-breaker.

```sql run
SELECT product_id, unit_price,
       ROW_NUMBER() OVER (ORDER BY unit_price DESC, product_id) AS row_num,
       RANK() OVER (ORDER BY unit_price DESC) AS rnk,
       DENSE_RANK() OVER (ORDER BY unit_price DESC) AS dense_rnk
FROM products
WHERE category_id = 1
ORDER BY row_num
LIMIT 10;
```

```output
product_id | unit_price | row_num | rnk | dense_rnk
38 | 263.50 | 1 | 1 | 1
43 | 46.00 | 2 | 2 | 2
2 | 19.00 | 3 | 3 | 3
1 | 18.00 | 4 | 4 | 4
35 | 18.00 | 5 | 4 | 4
39 | 18.00 | 6 | 4 | 4
76 | 18.00 | 7 | 4 | 4
70 | 15.00 | 8 | 8 | 5
34 | 14.00 | 9 | 9 | 6
67 | 14.00 | 10 | 9 | 6
```

### Example 3: top 2 products per category

Rank inside each category in the subquery, then keep `rn <= 2` outside. Only categories 1 to 3 are shown to keep the output short. Because of the tie-breaker the result is the same on every run.

```sql run
SELECT category_id, product_id, product_name, unit_price, rn
FROM (
  SELECT category_id, product_id, product_name, unit_price,
         ROW_NUMBER() OVER (PARTITION BY category_id ORDER BY unit_price DESC, product_id) AS rn
  FROM products
) AS ranked
WHERE rn <= 2 AND category_id <= 3
ORDER BY category_id, rn;
```

```output
category_id | product_id | product_name | unit_price | rn
1 | 38 | Côte de Blaye | 263.50 | 1
1 | 43 | Ipoh Coffee | 46.00 | 2
2 | 63 | Vegie-spread | 43.90 | 1
2 | 8 | Northwoods Cranberry Sauce | 40.00 | 2
3 | 20 | Sir Rodney's Marmalade | 81.00 | 1
3 | 62 | Tarte au sucre | 49.30 | 2
```

### Example 4: how ties change the top N

The same question with `RANK`: "products in category 1 whose price rank is 4 or better". Four products tie at rank 4, so we get 7 rows with `RANK` but exactly 4 with `ROW_NUMBER`. Decide which behaviour the question needs.

```sql run
SELECT product_id, unit_price, rnk
FROM (
  SELECT product_id, unit_price,
         RANK() OVER (ORDER BY unit_price DESC) AS rnk
  FROM products
  WHERE category_id = 1
) AS ranked
WHERE rnk <= 4
ORDER BY rnk, product_id;
```

```output
product_id | unit_price | rnk
38 | 263.50 | 1
43 | 46.00 | 2
2 | 19.00 | 3
1 | 18.00 | 4
35 | 18.00 | 4
39 | 18.00 | 4
76 | 18.00 | 4
```

### Example 5: the latest order for each customer

`ROW_NUMBER() = 1` picks one row per partition. Order by date descending, then by `order_id` descending, so two orders on the same day do not make the choice arbitrary. Here only five customers are shown.

```sql run
SELECT customer_id, order_id, order_date
FROM (
  SELECT customer_id, order_id, order_date,
         ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY order_date DESC, order_id DESC) AS rn
  FROM orders
) AS ranked
WHERE rn = 1
ORDER BY customer_id
LIMIT 5;
```

```output
customer_id | order_id | order_date
ALFKI | 10339 | 1997-08-08
ANATR | 10340 | 1998-09-09
ANTON | 10250 | 1998-03-03
AROUT | 10342 | 1997-11-11
BERGS | 10343 | 1998-12-12
```

### Example 6: top 2 products by revenue in each category

A realistic case: join `order_details` to `products`, aggregate revenue per product with `GROUP BY` (including the discount), and rank the grouped rows inside each category. This is a window over grouped rows: the `ORDER BY` inside `OVER` uses the aggregate. A CTE keeps the steps readable.

```sql run
WITH product_revenue AS (
  SELECT p.category_id, p.product_id, p.product_name,
         ROUND(SUM(od.unit_price * od.quantity * (1 - od.discount))::numeric, 2) AS revenue
  FROM order_details AS od
  JOIN products AS p ON p.product_id = od.product_id
  GROUP BY p.category_id, p.product_id, p.product_name
), ranked AS (
  SELECT *, DENSE_RANK() OVER (PARTITION BY category_id ORDER BY revenue DESC) AS revenue_rank
  FROM product_revenue
)
SELECT category_id, product_name, revenue, revenue_rank
FROM ranked
WHERE revenue_rank <= 2 AND category_id <= 3
ORDER BY category_id, revenue_rank, product_id;
```

```output
category_id | product_name | revenue | revenue_rank
1 | Côte de Blaye | 17509.57 | 1
1 | Ipoh Coffee | 2371.30 | 2
2 | Northwoods Cranberry Sauce | 3148.00 | 1
2 | Gula Malacca | 2396.24 | 2
3 | Sir Rodney's Marmalade | 5576.85 | 1
3 | Schoggi Schokolade | 3700.77 | 2
```

## Real-world applications

**Best sellers per category.** Example 6 gives the leaders of each product category. Merchandising teams use the same shape for the top products per store, region or month.

**Latest record per entity.** Example 5 returns the most recent order per customer. Pipelines use `ROW_NUMBER() = 1` to keep the newest version of each customer, device or account from a history table.

**Leaderboards with ties.** Sales and support dashboards decide whether two people with the same score share a rank. `RANK` shows both as 1st and skips 2nd; `DENSE_RANK` does not skip. Example 2 shows the difference.

**Sampling the head of every group.** `rn <= 3` lets an analyst inspect a few rows from each category when building a data-quality report, without exporting the whole table.

## Daily review

### Key takeaways

- `ORDER BY` inside `OVER` defines the order of the window calculation; it does not sort the output.
- `ROW_NUMBER` is unique per row, `RANK` repeats numbers for ties and leaves gaps, `DENSE_RANK` repeats numbers and leaves no gaps.
- Top N per group: rank in a subquery or CTE, filter on the rank outside.
- Add a unique tie-breaker (usually the primary key) so `ROW_NUMBER` is deterministic.
- `RANK <= N` and `DENSE_RANK <= N` can return more than N rows per group.

### Common mistakes

- Using `LIMIT 3` and expecting three rows per group. `LIMIT` cuts the whole result. Use the ranking pattern.
- Writing `WHERE ROW_NUMBER() OVER (...) <= 3`. The error is `window functions are not allowed in WHERE`. Put the ranking in a subquery.
- Forgetting the tie-breaker, so a report gives different rows on different runs. Add the primary key to the window's `ORDER BY`.
- Forgetting `DESC`. The default order is ascending, so rank 1 is the cheapest, not the most expensive.
- Using `RANK` for "exactly N rows". Ties at the boundary produce extra rows.
- Naming the subquery nothing. PostgreSQL requires an alias, otherwise `subquery in FROM must have an alias`.

### Revision notes

- Pattern: `ROW_NUMBER() OVER (PARTITION BY g ORDER BY x DESC, id)` in a subquery, then `WHERE rn <= N`.
- 30, 20, 20, 10 gives ROW_NUMBER 1,2,3,4; RANK 1,2,2,4; DENSE_RANK 1,2,2,3.
- Outer `ORDER BY` controls the output order.
