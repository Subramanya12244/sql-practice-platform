## Objectives

- Smooth an ordered series with `rolling(window).mean()` and explain why the first rows are `NaN` unless `min_periods` is set.
- Use a time-based window such as `"3D"` on a datetime index, and describe how it differs from a window of rows.
- Build running totals and running maxima with `expanding`.
- Compare each row with an earlier one using `shift`, `diff` and `pct_change`, also within groups.

## Understand

### Looking at neighbours

Everything so far treated each row on its own or put it into a group. Time series questions are different: "how did sales change since last month?" and "what is the average of the last seven days?" compare a row with the rows around it. The result depends on the order of the rows, so these tools only make sense on data that is sorted by time. Sort first (Day 73's `sort_values`), then apply them. If the order is wrong, the numbers are wrong, and nothing warns you.

### Rolling windows

A **rolling window** slides along the series and computes a summary over the most recent `n` rows. `s.rolling(3).mean()` gives, for each position, the mean of that value and the two before it. Imagine a frame that covers three values and is moved one step at a time; at each stop you record the average of what is inside. Rolling averages smooth out day-to-day noise so a trend becomes visible. The same pattern works with `sum`, `min`, `max`, `std` and others.

The first rows cannot fill the window. With `rolling(3)`, positions 0 and 1 have fewer than three values, so the result is `NaN`. If you prefer a partial answer, `min_periods=1` computes the summary over whatever values are available, which gives a mean of one value in the first row, of two in the second, and of three from then on. Be aware that these early values rest on fewer observations than the rest.

When the index is a datetime, the window can be a span of time instead of a count of rows: `s.rolling("7D").sum()` sums the values in the last seven calendar days up to and including each row. This matters when rows are missing. A window of 7 rows covers a week only when there is one row per day; a window of `"7D"` always covers a week. The datetime index must be sorted in increasing order.

### expanding: from the start to here

`s.expanding().sum()` is a window that starts at the first row and grows with each step. It gives the running total (the same as `cumsum`), and `expanding().max()` gives "the best value so far". `expanding().mean()` is the average of everything up to each row. Where rolling forgets old values, expanding keeps them all.

### shift, diff and pct_change

`s.shift(1)` moves values down by one position, so each row holds the previous row's value, and the first row becomes `NaN`. Called with a negative number, `shift(-1)`, it brings the next value up. A shifted series lined up next to the original lets you compare a row with its predecessor.

`s.diff()` is the current value minus the previous one, which equals `s - s.shift(1)`. It gives the change in absolute units. `s.pct_change()` gives the change as a fraction of the previous value, `(s - s.shift(1)) / s.shift(1)`, so 0.25 means a 25% rise. A zero in the previous row gives `inf`. Pandas has a default in `pct_change` that fills missing values forward before computing; recent versions warn about this default when the data contains `NaN`, so pass `fill_method=None` if you want missing values left alone.

### Windows inside groups

If a table holds many customers or stores, shifting the whole column mixes them: the first order of customer B would be compared with the last order of customer A. The cure is to shift inside groups: `df.groupby("customer")["amount"].shift(1)` restarts at each group, as the group tools of Days 79 and 80 do. The same works for `diff`, `pct_change` and for `rolling`, written `df.groupby("store")["sales"].rolling(3).mean()`, though that form returns a result with an extra index level that needs `reset_index(level=0, drop=True)` to align with the table.

### Common misconception

Learners often think a rolling mean of 3 is the average of the next three or of the whole column. It is the average of the current and previous values only; the result for a row never looks ahead. A related error is using a shifted or rolling column to predict the same row: the value for April must be computed only from data available before April. Using a window that includes the row being predicted is a form of data leakage.

### Why it matters

Trend lines, growth rates, running balances, "days since last order" and moving averages in dashboards are all neighbour calculations. A growth figure computed over unsorted or mixed groups can look reasonable and be completely wrong, so the habits of sorting first and shifting within groups matter more than the syntax.

## Syntax and key functions

```python nocheck
s.rolling(3).mean()                 # mean of current and two previous rows
s.rolling(3, min_periods=1).sum()   # partial windows allowed
s.rolling("7D").sum()               # time window; needs a sorted datetime index
s.expanding().max()                 # best so far
s.shift(1)                          # previous value
s.diff()                            # s - s.shift(1)
s.pct_change(fill_method=None)      # fractional change
df.groupby("key")["col"].shift(1)   # previous value inside each group
```

| Call | Returns |
|---|---|
| `rolling(n).f()` | summary of the last `n` rows; `NaN` until the window is full |
| `rolling(n, min_periods=k)` | allows windows with at least `k` values |
| `rolling("3D")` | summary over the last 3 calendar days |
| `expanding().f()` | summary from the first row to the current one |
| `shift(k)` | values moved down `k` rows (up if negative) |
| `diff()` | current minus previous |
| `pct_change()` | (current minus previous) divided by previous |

## Learn by example

### Example 1: A rolling mean and its first rows

Daily sales are smoothed with a three-row window, first strictly and then allowing partial windows.

```python run
import pandas as pd
sales = pd.Series([10, 20, 30, 40, 20], index=pd.date_range("2024-01-01", periods=5, freq="D"))
out = pd.DataFrame({
    "sales": sales,
    "roll3": sales.rolling(3).mean(),
    "roll3_partial": sales.rolling(3, min_periods=1).mean(),
})
print(out.round(2).to_string())
```

```output
            sales  roll3  roll3_partial
2024-01-01     10    NaN           10.0
2024-01-02     20    NaN           15.0
2024-01-03     30   20.0           20.0
2024-01-04     40   30.0           30.0
2024-01-05     20   30.0           30.0
```

The first two rolling values are missing because fewer than three values exist. The partial column averages what is available.

### Example 2: A time window when days are missing

Rows are missing for 3 and 4 January. A 3-row window and a `"3D"` window give different answers.

```python run
import pandas as pd
s = pd.Series([10, 20, 30, 40], index=pd.to_datetime(["2024-01-01", "2024-01-02", "2024-01-05", "2024-01-06"]))
print(pd.DataFrame({"rows3": s.rolling(3, min_periods=1).sum(), "days3": s.rolling("3D").sum()}).to_string())
```

```output
            rows3  days3
2024-01-01   10.0   10.0
2024-01-02   30.0   30.0
2024-01-05   60.0   30.0
2024-01-06   90.0   70.0
```

On 5 January the 3-day window reaches back only to 3 January, so it holds 30 alone, while the row window still adds the 20 and 10 from earlier.

### Example 3: Running totals and best so far

`expanding` accumulates from the first row. The running total matches `cumsum`.

```python run
import pandas as pd
x = pd.Series([5, 3, 9, 4, 12])
print(pd.DataFrame({"x": x, "total": x.expanding().sum(), "best": x.expanding().max(), "mean": x.expanding().mean()}).to_string())
print(x.expanding().sum().equals(x.cumsum().astype(float)))
```

```output
    x  total  best      mean
0   5    5.0   5.0  5.000000
1   3    8.0   5.0  4.000000
2   9   17.0   9.0  5.666667
3   4   21.0   9.0  5.250000
4  12   33.0  12.0  6.600000
True
```

`expanding().sum()` returns floats, so the comparison converts `cumsum` to floats first.

### Example 4: Change from the previous month

Monthly revenue is compared with the previous month in absolute and relative terms.

```python run
import pandas as pd
rev = pd.Series([100.0, 120.0, 90.0, 135.0], index=["jan", "feb", "mar", "apr"])
t = pd.DataFrame({"rev": rev, "prev": rev.shift(1), "diff": rev.diff(), "pct": rev.pct_change(fill_method=None).round(3)})
print(t.to_string())
```

```output
       rev   prev  diff   pct
jan  100.0    NaN   NaN   NaN
feb  120.0  100.0  20.0  0.20
mar   90.0  120.0 -30.0 -0.25
apr  135.0   90.0  45.0  0.50
```

February rose 20, or 0.2 of January. March fell by 30, a change of minus 0.25.

### Example 5: Shift inside groups

Each customer's previous order amount and the change since it, computed per customer so groups do not mix.

```python run
import pandas as pd
o = pd.DataFrame({
    "customer": ["A", "A", "A", "B", "B"],
    "amount": [10, 14, 9, 50, 55],
})
g = o.groupby("customer")["amount"]
o["prev"] = g.shift(1)
o["change"] = g.diff()
print(o.to_string())
print("wrong:", o["amount"].diff().tolist()[3])
```

```output
  customer  amount  prev  change
0        A      10   NaN     NaN
1        A      14  10.0     4.0
2        A       9  14.0    -5.0
3        B      50   NaN     NaN
4        B      55  50.0     5.0
wrong: 41.0
```

The first order of each customer has no previous value. The ungrouped difference for B's first order, 41, compares it with A's last order and is meaningless.

## Real-world applications

- **Dashboards.** A 7-day moving average of orders removes weekday effects so the trend is visible.
- **Growth reporting.** `pct_change` on monthly revenue gives month-on-month growth for a board report.
- **Customer behaviour.** `groupby("customer")["order_date"].shift(1)` gives the previous order date, so the days between orders can be computed.
- **Sensor monitoring.** `diff()` on a counter reading gives consumption per interval, and a rolling maximum highlights the peak of the last hour.

## Daily review

### Key takeaways

- Sort by time before using rolling, expanding or shift.
- `rolling(n)` looks back over `n` rows, or a time span with `"7D"`; early rows are `NaN` unless `min_periods` is set.
- `expanding` is a window from the start; `shift`, `diff` and `pct_change` compare with earlier rows.
- With several entities, shift and diff inside groups.

### Common mistakes

- Computing `diff` on an unsorted table gives changes between unrelated rows. Sort first.
- Shifting the whole column in a table with many customers mixes them. Use `groupby(...).shift`.
- A row window of 7 when days are missing does not cover a week. Use a datetime index and `"7D"`.
- `pct_change` showing `inf` where the previous value is 0. Handle zeros before dividing, for example by filtering them out.

### Revision notes

- `rolling(3).mean()` has 2 leading `NaN`; `min_periods=1` removes them.
- `diff()` equals `s - s.shift(1)`.
- `pct_change` of 100 to 120 is 0.2.
- Window never looks ahead.
