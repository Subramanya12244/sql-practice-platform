## Objectives

- Design a star schema for the store: dimension tables for customers, products, campaigns and dates, and a fact table at the grain of one row per order.
- Load the cleaned tables into SQLite and prove the load with row counts, a foreign key check and a revenue total.
- Show that primary key, foreign key and check constraints reject bad rows at load time.
- Write PostgreSQL DDL with typed columns and constraints and document the model with a data dictionary.

## Understand

### What this stage produces

After Day 174 the cleaned data lives in pandas DataFrames in memory. Analysis with SQL needs the data in a database with a clear structure. This stage produces three things: a schema (the tables, columns, types and keys), a load that fills it from the cleaned tables, and documentation. You will load SQLite as a stand-in that runs in the browser, and write the same model as PostgreSQL DDL (data definition language: the `CREATE TABLE` statements) that runs on the browser's PostgreSQL. The load is proven by checks: row counts match the clean tables, no foreign key points at a missing row, and the revenue total equals the clean total.

### Star schema and grain

A star schema has one fact table in the middle and dimension tables around it. A fact table records events with numbers you add up: here `fact_orders`, with quantity, discount, revenue and a returned flag. Dimension tables describe the things events refer to: `dim_customer` (country, signup date), `dim_product` (category, price), `dim_campaign` (channel, spend) and `dim_date` (day, month, year). The most important design decision is the grain, the meaning of one fact row. Here the grain is one order. Stating the grain first prevents the classic error of mixing levels, for example adding a per-campaign spend to every order row and then summing it. Campaign spend therefore stays in `dim_campaign`, where it appears once per campaign.

### Keys and constraints

A primary key identifies each row uniquely and cannot be empty: `order_id` in the fact table. A foreign key says that a value must exist in another table's key: `fact_orders.customer_id` must exist in `dim_customer`. A `CHECK` constraint states a rule about a column: `quantity > 0`. Constraints enforce in the database what the cleaning code promised, so a future load with a bug fails instead of storing bad data. This is the same idea as the validation on Day 174, moved to where it cannot be skipped. SQLite does not enforce foreign keys unless you run `PRAGMA foreign_keys = ON` on the connection, which is a frequent source of confusion: without it, orphan rows load silently.

### SQLite stand-in and PostgreSQL

SQLite is a small file or in-memory database with a loose type system, which makes it ideal for practice in Python. PostgreSQL is a server database with strict types (`integer`, `numeric(10,2)`, `date`, `boolean`, `char(2)`). The model is the same, but the syntax differs in places: SQLite's `INTEGER PRIMARY KEY`, text dates and `?` placeholders become PostgreSQL's typed columns, real `date` values and `%s` placeholders in `psycopg`. In production you would bulk load with `COPY` (shown below) rather than inserting row by row. The browser cannot run a PostgreSQL server, so the DDL example runs on the browser database, and `COPY FROM` a file is shown but not run.

### Documentation

A data dictionary lists every table and column with its type and role (key, foreign key, measure). Generating it from the database's own catalogue (`PRAGMA table_info` in SQLite) means the documentation cannot drift from the schema. The README then links to it and states the grain and the keys in a few sentences.

## Syntax and key functions

```sql-syntax
CREATE TABLE fact_orders (
    order_id integer PRIMARY KEY,
    customer_id integer NOT NULL REFERENCES dim_customer (customer_id),
    quantity integer NOT NULL CHECK (quantity > 0)
);
```

```sql-syntax
COPY fact_orders FROM '/path/orders.csv' WITH (FORMAT csv, HEADER true);
```

| Item | Meaning |
|---|---|
| `PRIMARY KEY` | Unique, not null identifier of a row |
| `REFERENCES t (c)` | Foreign key to another table's key |
| `CHECK (condition)` | Rejects rows where the condition is false |
| `PRAGMA foreign_keys = ON` | SQLite only: enforce foreign keys on this connection |
| `PRAGMA foreign_key_check` | SQLite: lists rows that break a foreign key (empty list means none) |
| `PRAGMA table_info(t)` | SQLite: one row per column with name, type and key flag |
| `COPY ... FROM` | PostgreSQL bulk load from a file |

## Learn by example

### Example 1: Load the star schema and prove it

The cleaned tables are loaded into SQLite. Three checks prove the load: counts per table, no foreign key violations, and a revenue total that equals the clean total.

```python run
import numpy as np
import pandas as pd


def generate(seed=7):
    """Seeded online-store data with planted defects: 500 orders, 120 customers, 20 products."""
    rng = np.random.default_rng(seed)
    customers = pd.DataFrame({
        "customer_id": np.arange(1, 121),
        "country": rng.choice(["DE", "FR", "UK", "US"], 120, p=[0.3, 0.2, 0.2, 0.3]),
        "signup_date": pd.Timestamp("2024-07-01") + pd.to_timedelta(rng.integers(0, 180, 120), unit="D"),
    })
    customers.loc[rng.choice(120, 8, replace=False), "country"] = "us "
    products = pd.DataFrame({
        "product_id": np.arange(1, 21),
        "category": np.repeat(["home", "beauty", "sports", "electronics"], 5),
        "unit_price": (10 + rng.random(20) * 90).round(2),
    })
    campaigns = pd.DataFrame({
        "campaign_id": [0, 1, 2, 3],
        "channel": ["organic", "email", "paid_search", "social"],
        "spend": [0.0, 800.0, 2500.0, 1200.0],
    })
    n = 500
    orders = pd.DataFrame({
        "order_id": np.arange(1001, 1001 + n),
        "customer_id": rng.integers(1, 121, n),
        "product_id": rng.integers(1, 21, n),
        "order_date": pd.Timestamp("2025-01-01") + pd.to_timedelta(rng.integers(0, 180, n), unit="D"),
        "quantity": rng.integers(1, 5, n),
        "discount_pct": rng.choice([0, 10, 20], n, p=[0.6, 0.25, 0.15]),
        "campaign_id": rng.choice([0, 1, 2, 3], n, p=[0.4, 0.2, 0.25, 0.15]),
    })
    orders.loc[rng.choice(n, 5, replace=False), "quantity"] = -1
    orders.loc[rng.choice(n, 6, replace=False), "customer_id"] = 999
    orders = pd.concat([orders, orders.sample(10, random_state=1)], ignore_index=True)
    returned = rng.choice(np.arange(1001, 1001 + n), 60, replace=False)
    returns = pd.DataFrame({
        "order_id": np.concatenate([returned, [9001, 9002, 9003]]),
        "reason": rng.choice(["damaged", "wrong_item", "changed_mind"], 63, p=[0.3, 0.2, 0.5]),
    })
    return {"orders": orders, "customers": customers, "products": products, "campaigns": campaigns, "returns": returns}



def clean(t):
    """Apply the quality rules; return cleaned tables and a row-accounting log."""
    log = {}
    o = t["orders"]
    log["raw_orders"] = len(o)
    o = o.drop_duplicates()
    log["after_duplicates"] = len(o)
    o = o[o["quantity"] > 0]
    log["after_quantity"] = len(o)
    c = t["customers"].copy()
    c["country"] = c["country"].str.strip().str.upper()
    o = o[o["customer_id"].isin(c["customer_id"])]
    log["after_customers"] = len(o)
    r = t["returns"]
    log["raw_returns"] = len(r)
    r = r[r["order_id"].isin(o["order_id"])].drop_duplicates("order_id")
    log["clean_returns"] = len(r)
    p = t["products"]
    o = o.merge(p[["product_id", "unit_price"]], on="product_id", how="left")
    o["revenue"] = (o["quantity"] * o["unit_price"] * (1 - o["discount_pct"] / 100)).round(2)
    o["returned"] = o["order_id"].isin(r["order_id"])
    return {"orders": o.reset_index(drop=True), "customers": c, "products": p, "campaigns": t["campaigns"], "returns": r.reset_index(drop=True)}, log

import sqlite3

SCHEMA = """
CREATE TABLE dim_customer (customer_id INTEGER PRIMARY KEY, country TEXT NOT NULL, signup_date TEXT NOT NULL);
CREATE TABLE dim_product (product_id INTEGER PRIMARY KEY, category TEXT NOT NULL, unit_price REAL NOT NULL CHECK (unit_price > 0));
CREATE TABLE dim_campaign (campaign_id INTEGER PRIMARY KEY, channel TEXT NOT NULL, spend REAL NOT NULL);
CREATE TABLE dim_date (date_id INTEGER PRIMARY KEY, full_date TEXT NOT NULL, year INTEGER NOT NULL, month INTEGER NOT NULL);
CREATE TABLE fact_orders (
    order_id INTEGER PRIMARY KEY,
    customer_id INTEGER NOT NULL REFERENCES dim_customer(customer_id),
    product_id INTEGER NOT NULL REFERENCES dim_product(product_id),
    campaign_id INTEGER NOT NULL REFERENCES dim_campaign(campaign_id),
    date_id INTEGER NOT NULL REFERENCES dim_date(date_id),
    quantity INTEGER NOT NULL CHECK (quantity > 0),
    discount_pct INTEGER NOT NULL,
    revenue REAL NOT NULL,
    returned INTEGER NOT NULL CHECK (returned IN (0, 1))
);
CREATE TABLE fact_returns (order_id INTEGER PRIMARY KEY REFERENCES fact_orders(order_id), reason TEXT NOT NULL);
"""


def load(ct):
    """Create the star schema in an in-memory SQLite database and load the cleaned tables."""
    db = sqlite3.connect(":memory:")
    db.execute("PRAGMA foreign_keys = ON")
    db.executescript(SCHEMA)
    c = ct["customers"].assign(signup_date=ct["customers"]["signup_date"].dt.strftime("%Y-%m-%d"))
    db.executemany("INSERT INTO dim_customer VALUES (?, ?, ?)", c.astype(object).values.tolist())
    db.executemany("INSERT INTO dim_product VALUES (?, ?, ?)", ct["products"].astype(object).values.tolist())
    db.executemany("INSERT INTO dim_campaign VALUES (?, ?, ?)", ct["campaigns"].astype(object).values.tolist())
    days = pd.date_range("2025-01-01", "2025-06-30")
    dd = pd.DataFrame({"date_id": days.strftime("%Y%m%d").astype(int), "full_date": days.strftime("%Y-%m-%d"), "year": days.year, "month": days.month})
    db.executemany("INSERT INTO dim_date VALUES (?, ?, ?, ?)", dd.astype(object).values.tolist())
    o = ct["orders"]
    f = pd.DataFrame({"order_id": o["order_id"], "customer_id": o["customer_id"], "product_id": o["product_id"], "campaign_id": o["campaign_id"],
                      "date_id": o["order_date"].dt.strftime("%Y%m%d").astype(int), "quantity": o["quantity"], "discount_pct": o["discount_pct"],
                      "revenue": o["revenue"], "returned": o["returned"].astype(int)})
    db.executemany("INSERT INTO fact_orders VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?)", f.astype(object).values.tolist())
    db.executemany("INSERT INTO fact_returns VALUES (?, ?)", ct["returns"].astype(object).values.tolist())
    db.commit()
    return db


t = generate()
ct, log = clean(t)
db = load(ct)
for name in ["dim_customer", "dim_product", "dim_campaign", "dim_date", "fact_orders", "fact_returns"]:
    print(name, db.execute(f"SELECT COUNT(*) FROM {name}").fetchone()[0])
print("foreign key violations:", len(db.execute("PRAGMA foreign_key_check").fetchall()))
total = db.execute("SELECT ROUND(SUM(revenue), 2) FROM fact_orders").fetchone()[0]
print("revenue matches clean:", total == round(float(ct["orders"]["revenue"].sum()), 2))
db.close()
```

```output
dim_customer 120
dim_product 20
dim_campaign 4
dim_date 181
fact_orders 489
fact_returns 59
foreign key violations: 0
revenue matches clean: True
```

### Example 3: The model in PostgreSQL DDL

The same model, trimmed to three tables, in PostgreSQL syntax: typed columns, `numeric(10,2)` for money, a `date` type, a `boolean`, and the constraints. The block creates its own tables, inserts four orders and runs a star join to total revenue by country.

```sql run
DROP TABLE IF EXISTS fact_orders CASCADE;
DROP TABLE IF EXISTS dim_customer CASCADE;
DROP TABLE IF EXISTS dim_product CASCADE;
CREATE TABLE dim_customer (customer_id integer PRIMARY KEY, country char(2) NOT NULL CHECK (country IN ('DE', 'FR', 'UK', 'US')), signup_date date NOT NULL);
CREATE TABLE dim_product (product_id integer PRIMARY KEY, category text NOT NULL, unit_price numeric(10, 2) NOT NULL CHECK (unit_price > 0));
CREATE TABLE fact_orders (
    order_id integer PRIMARY KEY,
    customer_id integer NOT NULL REFERENCES dim_customer (customer_id),
    product_id integer NOT NULL REFERENCES dim_product (product_id),
    order_date date NOT NULL,
    quantity integer NOT NULL CHECK (quantity > 0),
    discount_pct integer NOT NULL DEFAULT 0,
    returned boolean NOT NULL DEFAULT false
);
INSERT INTO dim_customer VALUES (1, 'DE', '2024-08-01'), (2, 'UK', '2024-09-10'), (3, 'DE', '2024-10-05');
INSERT INTO dim_product VALUES (1, 'home', 20.00), (2, 'electronics', 100.00);
INSERT INTO fact_orders VALUES (1001, 1, 1, '2025-01-05', 2, 0, false), (1002, 1, 2, '2025-01-20', 1, 10, false), (1003, 2, 2, '2025-02-02', 1, 0, true), (1004, 3, 1, '2025-02-14', 3, 20, false);
SELECT c.country, COUNT(*) AS orders, ROUND(SUM(o.quantity * p.unit_price * (1 - o.discount_pct / 100.0)), 2) AS revenue
FROM fact_orders o
JOIN dim_customer c USING (customer_id)
JOIN dim_product p USING (product_id)
GROUP BY c.country
ORDER BY c.country
LIMIT 10;
```

```output
country | orders | revenue
DE | 3 | 178.00
UK | 1 | 100.00
```

    campaign_id INTEGER NOT NULL REFERENCES dim_campaign(campaign_id),

    revenue REAL NOT NULL,
    returned INTEGER NOT NULL CHECK (returned IN (0, 1))

CREATE TABLE fact_returns (order_id INTEGER PRIMARY KEY REFERENCES fact_orders(order_id), reason TEXT NOT NULL);
"""


def load(ct):
    """Create the star schema in an in-memory SQLite database and load the cleaned tables."""
    db = sqlite3.connect(":memory:")
    db.execute("PRAGMA foreign_keys = ON")
    db.executescript(SCHEMA)
    c = ct["customers"].assign(signup_date=ct["customers"]["signup_date"].dt.strftime("%Y-%m-%d"))
    db.executemany("INSERT INTO dim_customer VALUES (?, ?, ?)", c.astype(object).values.tolist())
    db.executemany("INSERT INTO dim_product VALUES (?, ?, ?)", ct["products"].astype(object).values.tolist())
    db.executemany("INSERT INTO dim_campaign VALUES (?, ?, ?)", ct["campaigns"].astype(object).values.tolist())
    days = pd.date_range("2025-01-01", "2025-06-30")
    dd = pd.DataFrame({"date_id": days.strftime("%Y%m%d").astype(int), "full_date": days.strftime("%Y-%m-%d"), "year": days.year, "month": days.month})
    db.executemany("INSERT INTO dim_date VALUES (?, ?, ?, ?)", dd.astype(object).values.tolist())
    o = ct["orders"]
    f = pd.DataFrame({"order_id": o["order_id"], "customer_id": o["customer_id"], "product_id": o["product_id"], "campaign_id": o["campaign_id"],
                      "date_id": o["order_date"].dt.strftime("%Y%m%d").astype(int), "quantity": o["quantity"], "discount_pct": o["discount_pct"],
                      "revenue": o["revenue"], "returned": o["returned"].astype(int)})
    db.executemany("INSERT INTO fact_orders VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?)", f.astype(object).values.tolist())
    db.executemany("INSERT INTO fact_returns VALUES (?, ?)", ct["returns"].astype(object).values.tolist())
    db.commit()
    return db

## Daily review

### Key takeaways

- State the grain first: one order per fact row. Keep attributes in dimensions and numbers in the fact.
- Constraints enforce the cleaning rules in the database: primary keys, foreign keys and checks.
- Prove a load with counts, a foreign key check and a revenue total.
- PostgreSQL needs typed columns; SQLite needs `PRAGMA foreign_keys = ON` for foreign keys to work.

### Common mistakes

- Forgetting `PRAGMA foreign_keys = ON`: orphan rows load without error. Turn it on for every new connection, then run `PRAGMA foreign_key_check`.
- Storing campaign spend on every order row: summing it multiplies the spend by the number of orders. Keep it in the dimension at one row per campaign.
- Passing NumPy types to `executemany` placeholders: values may fail or be stored as blobs. Convert with `astype(object)` or `int`/`float`.
- Loading before creating the date dimension rows the orders need: the foreign key to `dim_date` fails. Load dimensions first, then facts.

- Counts after load: 120 customers, 20 products, 4 campaigns, 181 dates, 489 orders, 59 returns.
- Fact grain: one order. Dimensions: customer, product, campaign, date.
- Constraint types: `PRIMARY KEY`, `REFERENCES`, `CHECK`, `NOT NULL`, `DEFAULT`.
