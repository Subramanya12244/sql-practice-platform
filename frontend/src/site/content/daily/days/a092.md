## Understand

### Formulas, functions and arguments

A **formula** is anything you type into a cell that starts with `=`. It can contain numbers, cell addresses, operators (`+ - * / ^`), comparison operators (`= <> < <= > >=`) and **functions**. A function is a named, ready-made calculation such as `SUM`. You call it by writing its name, an opening bracket, its **arguments** separated by commas, and a closing bracket: `=SUM(B2:B6)`. In some regional settings (for example much of continental Europe) Excel uses semicolons instead of commas between arguments; the structure is the same. Excel follows the usual order of operations: brackets first, then `^`, then `*` and `/`, then `+` and `-`, then comparisons. When in doubt, add brackets.

### The logical test

Many questions in analysis are of the form "if this is true, do one thing, otherwise do another". A **logical test** is an expression that is either `TRUE` or `FALSE`, such as `B2>=100` or `C2="North"`. Excel compares text without regard to upper or lower case, so `"north"="North"` is `TRUE`; Python and pandas are case-sensitive, so this is one of the places where the pandas replica needs `.str.lower()` to behave like Excel.

`IF(test, value_if_true, value_if_false)` evaluates the test and returns one of two values. The two values can be text in quotes, numbers, cell references or other formulas. If you leave out the third argument and the test is false, Excel returns `FALSE`, which is rarely what you want, so always write both branches.

### Combining tests: AND, OR and nested IF

`AND(test1, test2, ...)` is `TRUE` only when every test is true. `OR(test1, test2, ...)` is `TRUE` when at least one test is true. They are used inside `IF`: `=IF(AND(B2>=100, C2="North"), "Bonus", "None")`. A frequent beginner error is to write `B2>=100 AND C2="North"` or a chain such as `100<=B2<=200`; Excel does not read those. Each test must be a separate argument.

For more than two outcomes you can **nest** an `IF` inside the false branch of another: `=IF(B2>=90,"A",IF(B2>=80,"B","C"))`. Excel evaluates the tests from left to right and stops at the first true one, so the order of the tests matters: if you tested `B2>=80` first, a score of 95 would get `B`. Nesting gets hard to read after three levels. `IFS(test1, value1, test2, value2, ...)` is the flatter alternative, available in Excel 2019 and Microsoft 365: it returns the value that belongs to the first true test. If no test is true, `IFS` returns the error `#N/A`. The usual way to supply a default is to end with a test that is always true: `TRUE, "C"`.

### Maths: SUM and rounding

`SUM(range)` adds the numbers in a range and ignores text and empty cells (the effect of text-typed numbers was shown on Day 91). `SUM` accepts many arguments: `=SUM(B2:B6, D2)`. The three rounding functions each take a number and a count of digits. `ROUND(number, digits)` rounds to the nearest value, `ROUNDUP` always moves away from zero and `ROUNDDOWN` always moves toward zero. `digits` of 2 keeps two decimals, 0 gives a whole number and -2 rounds to hundreds, so `ROUND(1234,-2)` is `1200`. Excel's `ROUND` rounds a value exactly halfway (such as 2.5) away from zero, giving 3, which matches school arithmetic. Python's built-in `round(2.5)` returns 2 because it rounds halves to the nearest even number. When you replicate an Excel `ROUND` in pandas you must account for this difference, as the examples below show.

Rounding in a formula changes the value stored in the result. This differs from formatting (Day 91), which changes only what is displayed. Round at the end of a calculation, not in the middle, unless the rounded value really is the amount that is invoiced or paid.

### Relative, absolute and mixed references

When you copy a formula to another cell, Excel adjusts the cell addresses in it by the same distance. A **relative reference** such as `B2` means "the cell in this column, same row" in effect: copy `=B2*2` from C2 down to C3 and it becomes `=B3*2`. An **absolute reference** has a dollar sign before the column letter and the row number, `$F$1`, and never changes when copied. It is what you use for a fixed input such as a rate: `=B2*$F$1` copied down becomes `=B3*$F$1`. A **mixed reference** fixes only one part: `$B2` fixes the column and lets the row move, `B$2` does the opposite. Pressing `F4` while the cursor is in a reference cycles through `B2`, `$B$2`, `B$2` and `$B2`.

The misconception to avoid is that the formula is "the same" after copying. Its text changes; its meaning (relative position) stays the same. If a copied formula gives zeros or the wrong numbers in the lower rows, the first suspect is an input reference that should have been absolute.

### Error values

When Excel cannot calculate a formula it shows an **error value**, which begins with `#`. Each one points to a cause.

- `#DIV/0!`: division by zero or by an empty cell.
- `#VALUE!`: a calculation received the wrong type, such as `="abc"+1`.
- `#REF!`: a cell the formula referred to was deleted.
- `#NAME?`: Excel does not recognise a function or name, usually a typo such as `=SUMM(B2:B6)`.
- `#N/A`: a value is not available, typically a failed lookup or an `IFS` with no true test.
- `#NUM!`: an impossible number, such as the square root of a negative number.

Errors spread: a `SUM` that includes one error cell returns that error. `IFERROR(formula, value_if_error)` returns the first argument unless it is an error, in which case it returns the second. It is useful for a division that may hit zero, but it also hides real mistakes such as a mistyped name, so keep it narrow and prefer to fix the cause. In pandas there is no such error value: dividing by zero gives `inf` or `NaN` quietly, and a column of mixed text and numbers raises an exception only when you try to calculate with it.

### Why this matters

Logical formulas are how an analyst turns a rule in words ("customers who ordered at least 5 times in the North get tier A") into a column that can be counted and summarised. Absolute references and error handling are what separate a formula that works in one cell from a column that works in a thousand rows.

## Syntax and key functions

```excel
=IF(test, value_if_true, value_if_false)
=IFS(test1, value1, test2, value2, TRUE, default)
=AND(test1, test2)
=OR(test1, test2)
=SUM(range1, range2)
=ROUND(number, digits)
=IFERROR(formula, value_if_error)
```

`test` is anything that evaluates to `TRUE` or `FALSE`. `digits` is the number of decimals to keep; it may be negative. Arguments are separated with commas (or semicolons in some regional settings).

| Function | Returns |
|---|---|
| `IF(test, a, b)` | `a` when the test is true, otherwise `b`. |
| `IFS(t1, v1, t2, v2, ...)` | The value of the first true test; `#N/A` if none is true. |
| `AND(...)` / `OR(...)` | `TRUE` when all / at least one of the tests are true. |
| `NOT(test)` | The opposite of the test. |
| `SUM(...)` | Total of the numbers; text and blanks ignored. |
| `ROUND`, `ROUNDUP`, `ROUNDDOWN` | The number rounded nearest, away from zero, toward zero. |
| `IFERROR(f, v)` | `f`, or `v` when `f` is an error. |

| Reference | Copied one row down | Copied one column right |
|---|---|---|
| `B2` | `B3` | `C2` |
| `$B$2` | `$B$2` | `$B$2` |
| `$B2` | `$B3` | `$B2` |
| `B$2` | `B$2` | `C$2` |

## Learn by example

### Example 1: IF with AND and OR

Take the orders below. The rule: an order earns a bonus when its amount is at least 100 and its region is North, and a review flag when it comes from the East or has a quantity of 1.

| OrderID | Region | Qty | Amount |
|---|---|---|---|
| 1 | North | 4 | 120 |
| 2 | North | 2 | 90 |
| 3 | East | 1 | 150 |
| 4 | south | 5 | 200 |

```excel
=IF(AND(D2>=100, C2="North"), "Bonus", "None")
=IF(OR(C2="East", B2=1), "Review", "OK")
```

Excel ignores case in `C2="North"`. The replica uses `np.where` and, to copy that behaviour, lowercases the text.

```python run
import numpy as np
import pandas as pd

o = pd.DataFrame({
    "OrderID": [1, 2, 3, 4],
    "Region": ["North", "North", "East", "south"],
    "Qty": [4, 2, 1, 5],
    "Amount": [120, 90, 150, 200],
})
reg = o["Region"].str.lower()
o["Bonus"] = np.where((o["Amount"] >= 100) & (reg == "north"), "Bonus", "None")
o["Flag"] = np.where((reg == "east") | (o["Qty"] == 1), "Review", "OK")
print(o[["OrderID", "Bonus", "Flag"]].to_string(index=False))
```

```output
 OrderID Bonus   Flag
       1 Bonus     OK
       2  None     OK
       3  None Review
       4  None     OK
```

Order 1 meets both parts of the bonus rule. Order 4 has a large amount but is not North. Order 3 is flagged for review twice over (East and Qty 1), and `OR` is still just `TRUE`. In pandas the operators are `&` and `|`, each test needs its own brackets, and `and`/`or` would raise an error.

### Example 2: IFS against nested IF

Grade a score: 90 or more is A, 80 or more is B, 70 or more is C, otherwise D.

```excel
=IF(B2>=90,"A",IF(B2>=80,"B",IF(B2>=70,"C","D")))
=IFS(B2>=90,"A", B2>=80,"B", B2>=70,"C", TRUE,"D")
```

Both formulas give the same result. `np.select` is the pandas counterpart: a list of conditions, a list of values and a default, with the first true condition winning.

```python run
import numpy as np
import pandas as pd

score = pd.Series([95, 82, 70, 69, 80])
conds = [score >= 90, score >= 80, score >= 70]
print(np.select(conds, ["A", "B", "C"], default="D").tolist())
# Without the final TRUE test, Excel's IFS returns #N/A for a score below 70.
# np.select needs an explicit default; here we choose to mimic the Excel error text.
print(np.select(conds, ["A", "B", "C"], default="#N/A").tolist())
```

```output
['A', 'B', 'C', 'D', 'B']
['A', 'B', 'C', '#N/A', 'B']
```

Scores 80 and 70 land on the boundary values because the tests use `>=`. The second line shows what Excel's `IFS` does without a closing `TRUE` test: scores of 69 get `#N/A`. `np.select` has no error value, so it always needs a default (it is required for text results), and you choose what a no-match row receives. Never let a silent default such as `0` or an empty string hide unmatched rows.

### Example 3: ROUND, ROUNDUP, ROUNDDOWN and the halves

```excel
=ROUND(2.5,0)        gives 3
=ROUND(-2.5,0)       gives -3
=ROUND(2.675,2)      gives 2.68
=ROUNDUP(2.341,2)    gives 2.35
=ROUNDDOWN(2.349,2)  gives 2.34
=ROUND(1234,-2)      gives 1200
```

The first three results are Excel's. Python's `round` behaves differently on halves, so the replica uses the `decimal` module with the rounding mode "half up" (which rounds ties away from zero for positive numbers, and `ROUND_HALF_UP` in `decimal` also rounds negative ties away from zero).

```python run
from decimal import Decimal, ROUND_HALF_UP, ROUND_UP, ROUND_DOWN

def xl_round(x, digits, mode=ROUND_HALF_UP):
    q = Decimal(1).scaleb(-digits)
    return float(Decimal(str(x)).quantize(q, rounding=mode))

print(round(2.5), round(3.5), round(-2.5))
print(xl_round(2.5, 0), xl_round(3.5, 0), xl_round(-2.5, 0))
print(xl_round(2.675, 2), round(2.675, 2))
print(xl_round(2.341, 2, ROUND_UP), xl_round(2.349, 2, ROUND_DOWN))
print(xl_round(1234, -2))
```

```output
2 4 -2
3.0 4.0 -3.0
2.68 2.67
2.35 2.34
1200.0
```

Python's `round` gives 2, 4 and -2 for the halves (nearest even), while Excel's `ROUND` gives 3, 4 and -3. For `2.675` Excel returns 2.68, while Python's `round(2.675, 2)` returns 2.67 because the binary value stored for 2.675 is slightly below the half. Excel rounds the value as it appears to 15 significant digits, so it treats 2.675 as exactly 2.675. The replica uses `Decimal(str(x))`, which sees the text `2.675`, and so matches Excel. Note that `xl_round(1234, -2)` prints `1200.0`; Excel shows `1200`.

### Example 4: Relative and absolute references

A tax rate is in cell `F1` (0.2). Prices are in `B2:B4`. The tax column needs the rate to stay fixed.

| Row | B (Price) | C formula as typed in C2 and filled down | Value |
|---|---|---|---|
| 2 | 10 | `=B2*$F$1` | 2.0 |
| 3 | 25 | `=B3*$F$1` | 5.0 |
| 4 | 40 | `=B4*$F$1` | 8.0 |

If you had typed `=B2*F1`, fill-down would give `=B3*F2` and `=B4*F3`: `F2` and `F3` are empty, so those rows would show 0. The code below builds the filled-down text for both versions and calculates both results.

```python run
import re

prices = {2: 10, 3: 25, 4: 40}
cells = {"F1": 0.2}

def shift(formula, rows):
    """Shift relative row numbers; $ rows stay fixed."""
    return re.sub(r"(?<!\$)\b([A-Z]+)(\d+)\b", lambda m: m.group(1) + str(int(m.group(2)) + rows), formula)

for label, f in [("absolute", "=B2*$F$1"), ("relative", "=B2*F1")]:
    for r in prices:
        text = shift(f, r - 2)
        print(label, r, text)
print([prices[r] * cells["F1"] for r in prices])
print([prices[r] * cells.get("F" + str(r - 1), 0.0) for r in prices])
```

```output
absolute 2 =B2*$F$1
absolute 3 =B3*$F$1
absolute 4 =B4*$F$1
relative 2 =B2*F1
relative 3 =B3*F2
relative 4 =B4*F3
[2.0, 5.0, 8.0]
[2.0, 0.0, 0.0]
```

The first six lines show the formula text Excel produces on fill-down. In the relative version the reference to `F1` drifts to `F2` and `F3`. The numeric lines show the consequence: `[2.0, 5.0, 8.0]` with the absolute reference, and `[2.0, 0.0, 0.0]` when the drifting reference points at empty cells. (The helper is a simple teaching model that moves rows for plain relative addresses; it is not how Excel works internally.)

### Example 5: Errors and IFERROR

A conversion-rate column divides orders by visits, and one row has zero visits.

```excel
=B2/C2
=IFERROR(B2/C2, 0)
=IF(C2=0, 0, B2/C2)
```

The first formula shows `#DIV/0!` in the zero row. The second replaces any error with 0. The third tests for the specific cause, which is safer because it does not hide other errors.

```python run
import numpy as np
import pandas as pd

d = pd.DataFrame({"Orders": [10, 4, 0], "Visits": [200, 0, 50]})
raw = d["Orders"] / d["Visits"]
print(raw.tolist())
iferror = raw.replace([np.inf, -np.inf], np.nan).fillna(0)
specific = np.where(d["Visits"] == 0, 0, d["Orders"] / d["Visits"].replace(0, np.nan))
print(iferror.tolist())
print(specific.tolist())
```

```output
[0.05, inf, 0.0]
[0.05, 0.0, 0.0]
[0.05, 0.0, 0.0]
```

Pandas returns `inf` for 4 orders over 0 visits, with no error, so you have to look for it. The `IFERROR` replica turns that `inf` into 0 and the specific test gives the same numbers here. Note that the third row (0 orders, 50 visits) is a legitimate 0.0, not an error.

## Real-world applications

- **Segmenting customers.** A column such as `=IFS(D2>=1000,"Gold", D2>=500,"Silver", TRUE,"Standard")` turns spend into tiers that can be filtered and counted by tier (Example 2).
- **Flagging exceptions in a report.** `AND`/`OR` rules mark orders that need a review, such as large discounts on small orders, so a manager filters on the flag (Example 1).
- **Models with an assumptions cell.** Prices, rates and targets sit in absolute-referenced input cells, so one change flows through hundreds of rows without editing formulas (Example 4).
- **Presentable money figures.** `ROUND(value, 2)` before summing invoice lines matches what customers are actually billed, and avoids cent differences between a printed total and the sum of its lines (Example 3).

## Daily review

### Key takeaways

- `IF` needs a test that is `TRUE` or `FALSE`; `AND` and `OR` combine tests as separate arguments.
- `IFS` reads left to right and returns the first true test; end it with `TRUE, default` or an unmatched row gives `#N/A`.
- `ROUND` rounds halves away from zero; Python's `round` rounds halves to even.
- Relative addresses move when copied; `$` freezes the column, the row, or both.
- Read the error value: it tells you the cause. Use `IFERROR` sparingly.

### Common mistakes

- Writing `=IF(B2>=100 AND C2="North", ...)` or `=IF(100<=B2<=200, ...)`. Excel reports that there is a problem with the formula. Use `AND(B2>=100, C2="North")`.
- Putting the tests of a nested `IF` in the wrong order, so a score of 95 receives `B` because `>=80` was tested first.
- Forgetting the `$` on an input cell, so rows below the first show 0 or an unexpected number.
- Comparing numbers stored as text, such as `"5"` and `5`: `"5"=5` is `FALSE` in Excel.
- Wrapping everything in `IFERROR(..., 0)` so a `#NAME?` typo is turned into a plausible zero.
- Using Python's `round` to check an Excel `ROUND` on halves and getting 2 where Excel shows 3.

### Revision notes

- `=IF(AND(a,b),x,y)`, `=IF(OR(a,b),x,y)`, `=IFS(t1,v1,t2,v2,TRUE,d)`.
- `ROUND(x,2)`, `ROUND(x,-2)`, `ROUNDUP` away from zero, `ROUNDDOWN` toward zero.
- `$B$2` fixed, `B2` relative, `$B2` column fixed, `B$2` row fixed; `F4` cycles them.
- `#DIV/0!` zero divisor, `#VALUE!` wrong type, `#REF!` deleted cell, `#NAME?` unknown name, `#N/A` not available.
