## Objectives

- Compute several summaries per group at once with `agg`, using a list of functions or named aggregation.
- Use `transform` to put a group-level result back on every original row, for shares, deviations and group-based filling.
- Keep or drop whole groups with `filter`, and with a mask built from `transform`.
- Rank rows inside each group with `rank` and select the top rows per group.

## Understand

### Two different shapes of result

Day 79 gave you the split-apply-combine picture. The combine step can produce two different shapes, and choosing between them is the main idea of today. An **aggregation** reduces each group to one row, so a table of 1,000 order lines grouped by customer becomes a table of one row per customer. A **transformation** keeps every original row and fills in a value computed from the row's group. After transforming, the table still has 1,000 rows, and each line carries, for example, the total of its customer. Aggregation answers "what is the total per customer?". Transformation answers "what share of its customer's total is this line?", because that question needs the line and its group total side by side.

### Several aggregations at once

`agg` accepts more than one function. A list, `g["amount"].agg(["sum", "mean", "max"])`, returns one column per function. A dictionary, `g.agg({"amount": ["sum", "max"], "qty": "sum"})`, picks different functions for different columns, but produces a two-level column header that is awkward to use. Named aggregation from Day 79 solves this: `g.agg(revenue=("amount", "sum"), biggest=("amount", "max"), units=("qty", "sum"))` gives flat, readable names. You can also pass your own function in the pair, for example `("amount", lambda s: s.max() - s.min())` for the range inside each group. Built-in function names given as strings are preferred over lambdas where they exist because they are faster and clearer.

### transform: a group result for every row

`g["amount"].transform("sum")` computes the sum within each group and then repeats it on every row of that group. The result has the same length and the same index as the original column, so it can be assigned straight back as a new column: `df["customer_total"] = df.groupby("customer")["amount"].transform("sum")`. Dividing the line by that column gives each line's share of its group. The function can be a name such as `"mean"`, `"max"`, `"size"` or `"rank"`, or your own function that receives one group's column and returns either a single value or a series of the same length.

A frequent use is to compare a value with its group's norm: `df["amount"] - df.groupby("customer")["amount"].transform("mean")` is each line's difference from its customer's average. Another is filling missing values by group: `s.fillna(s.groupby(key).transform("mean"))` replaces a missing temperature with the average of its own station rather than the average of the whole table. Day 74 listed fill strategies; group-based filling is a stronger one when groups differ.

### filter: keep or drop whole groups

`g.filter(func)` keeps every row of the groups for which `func` returns `True` and drops all rows of the other groups. The function gets the whole group as a small table, so `g.filter(lambda grp: grp["amount"].sum() >= 100)` keeps customers whose total reaches 100. The result is a subset of the original rows, in the original order, with all columns. This is the pandas counterpart of SQL `HAVING` from Day 37, with one difference: `HAVING` returns one row per group, and `filter` returns the original rows of the surviving groups. When you only need a mask, `transform` is often simpler and faster: `df[df.groupby("customer")["amount"].transform("size") >= 3]` keeps customers with at least three lines.

### Group-wise ranking

`g["amount"].rank(ascending=False, method="first")` gives each row its rank inside its group, with 1 for the largest. The ranking restarts for each group. The `method` argument decides what happens with ties: `"first"` gives tied rows different ranks in order of appearance, so every rank from 1 to the group size is used exactly once, while the default `"average"` gives tied rows their average rank, such as 1.5. Once you have the rank, a top-N per group is a filter on it: `df[rank <= 2]`. This is the pandas version of `ROW_NUMBER() OVER (PARTITION BY ...)` from the window function days. A related helper, `cumcount()`, numbers rows within each group in their current order starting from 0.

### Common misconception

Learners often use `agg` when they need `transform`, then try to merge the result back by hand, or they use a loop over groups. If the result must line up with the original rows, ask whether `transform` does it in one line. The opposite mistake is calling `transform` with a function that returns a different length per group, which raises an error, because the output must match the input group size or be a single value to repeat.

### Why it matters

Shares of total, deviations from a group mean, top three products per region and "customers with at least five orders" are everyday analysis questions. Each of them is one of the four tools above. Knowing which shape you need before writing code removes most of the trial and error, and an assertion that the transformed column has the same length as the table catches mistakes early.

## Syntax and key functions

```python nocheck
g = df.groupby("key")
g["col"].agg(["sum", "mean"])                      # one column per function
g.agg(total=("col", "sum"), top=("col", "max"))    # named aggregation
g["col"].transform("sum")                          # same length as df
g.filter(lambda grp: grp["col"].sum() >= 100)      # rows of kept groups
g["col"].rank(ascending=False, method="first")     # rank inside each group
```

`agg` shrinks to one row per group, `transform` keeps the row count, and `filter` returns original rows of the groups that pass.

| Call | Result shape |
|---|---|
| `g["c"].agg([...])` | one row per group, one column per function |
| `g.agg(name=("c", "f"))` | one row per group, named columns |
| `g["c"].transform("sum")` | same length and index as the original |
| `g.filter(func)` | subset of original rows |
| `g["c"].rank(method="first")` | same length, rank within group |
| `g.cumcount()` | position within group, starting at 0 |

## Learn by example

### Example 1: Several summaries in one call

A list of functions and a named aggregation are shown on the same data.

```python run
import pandas as pd
sales = pd.DataFrame({
    "rep": ["Ana", "Ben", "Ana", "Ben", "Ana", "Cal"],
    "amount": [100, 40, 60, 80, 20, 70],
})
g = sales.groupby("rep")
print(g["amount"].agg(["sum", "mean", "max"]).to_string())
named = g.agg(total=("amount", "sum"), deals=("amount", "size"), spread=("amount", lambda s: s.max() - s.min()))
print(named.to_string())
```

```output
     sum  mean  max
rep                
Ana  180  60.0  100
Ben  120  60.0   80
Cal   70  70.0   70
     total  deals  spread
rep                      
Ana    180      3      80
Ben    120      2      40
Cal     70      1       0
```

Ana's spread is 100 minus 20. Each result has one row per rep.

### Example 2: transform for a share of the group total

`transform("sum")` repeats each rep's total on their rows, so the share is plain division.

```python run
import pandas as pd
sales = pd.DataFrame({
    "rep": ["Ana", "Ben", "Ana", "Ben", "Ana", "Cal"],
    "amount": [100, 40, 60, 80, 20, 70],
})
total = sales.groupby("rep")["amount"].transform("sum")
sales["rep_total"] = total
sales["share"] = (sales["amount"] / total).round(3)
print(sales.to_string())
print(len(total) == len(sales))
```

```output
   rep  amount  rep_total  share
0  Ana     100        180  0.556
1  Ben      40        120  0.333
2  Ana      60        180  0.333
3  Ben      80        120  0.667
4  Ana      20        180  0.111
5  Cal      70         70  1.000
True
```

The table keeps six rows. An `agg` would have returned three.

### Example 3: Compare with the group mean, fill by group

First each amount is compared with its rep's mean. Then a missing score is filled with the mean of its own team.

```python run
import numpy as np
import pandas as pd
sales = pd.DataFrame({"rep": ["Ana", "Ben", "Ana", "Ben"], "amount": [100, 40, 60, 80]})
sales["vs_avg"] = sales["amount"] - sales.groupby("rep")["amount"].transform("mean")
print(sales["vs_avg"].tolist())
scores = pd.DataFrame({"team": ["x", "x", "y", "y", "y"], "score": [10.0, np.nan, 30.0, 50.0, np.nan]})
scores["filled"] = scores["score"].fillna(scores.groupby("team")["score"].transform("mean"))
print(scores.to_string())
```

```output
[20.0, -20.0, -20.0, 20.0]
  team  score  filled
0    x   10.0    10.0
1    x    NaN    10.0
2    y   30.0    30.0
3    y   50.0    50.0
4    y    NaN    40.0
```

Team x gets 10, the mean of its only known score. Team y gets 40, not the overall mean of 30.

### Example 4: filter whole groups

Keep reps with at least two deals and a total of at least 100, first with `filter`, then with a `transform` mask.

```python run
import pandas as pd
sales = pd.DataFrame({
    "rep": ["Ana", "Ben", "Ana", "Ben", "Ana", "Cal"],
    "amount": [100, 40, 60, 80, 20, 70],
})
kept = sales.groupby("rep").filter(lambda grp: len(grp) >= 2 and grp["amount"].sum() >= 100)
print(kept.to_string())
mask = sales.groupby("rep")["amount"].transform("size") >= 2
print(sales[mask].index.tolist())
```

```output
   rep  amount
0  Ana     100
1  Ben      40
2  Ana      60
3  Ben      80
4  Ana      20
[0, 1, 2, 3, 4]
```

Cal has one deal and is dropped entirely. The original index labels are preserved, so you can see which rows survived.

### Example 5: Top two per group with rank

Rank inside each rep, with 1 for the largest amount, then keep ranks 1 and 2.

```python run
import pandas as pd
sales = pd.DataFrame({
    "rep": ["Ana", "Ben", "Ana", "Ben", "Ana", "Cal"],
    "amount": [100, 40, 60, 80, 20, 70],
})
sales["rank"] = sales.groupby("rep")["amount"].rank(ascending=False, method="first").astype(int)
top2 = sales[sales["rank"] <= 2].sort_values(["rep", "rank"])
print(top2.to_string(index=False))
```

```output
rep  amount  rank
Ana     100     1
Ana      60     2
Ben      80     1
Ben      40     2
Cal      70     1
```

Ana's 20 has rank 3 and is dropped. Ben and Cal have fewer than three rows, so all theirs stay.

## Real-world applications

- **Share of revenue within a category.** An analyst adds a `share` column with `transform("sum")` so each product line shows its slice of the category total.
- **Outlier checks by segment.** Subtracting the group mean with `transform("mean")` shows which orders are unusually large for their own customer rather than for the whole table.
- **Group-aware imputation.** A data engineer fills missing sensor readings with the mean of the same sensor instead of a table-wide mean.
- **Top-N reports.** A manager asks for the best two products per region; `rank` followed by a filter produces it in two lines.

## Daily review

### Key takeaways

- `agg` gives one row per group; `transform` keeps every row; `filter` keeps whole groups of original rows.
- Named aggregation gives flat names; a lambda inside it supports custom summaries.
- `transform` results can be assigned straight back as a column and used for shares and deviations.
- `rank(method="first")` numbers rows inside a group; filter on the rank for top N.

### Common mistakes

- Using `agg` and then wondering why the result cannot be assigned to the original table: lengths differ and the assignment gives `NaN` or an error. Use `transform` when the result must line up with the rows.
- `g.filter(...)` with a function that returns a series rather than one True or False raises `TypeError: filter function returned a Series, but expected a scalar bool`. Return one boolean for the group.
- Ranking with the default `method="average"` and getting `1.5` for ties; pass `method="first"` when you need distinct integer ranks.
- Dividing by `groupby(...).sum()` instead of `transform("sum")` produces `NaN` because the indexes do not match.

### Revision notes

- `agg` shrinks, `transform` repeats, `filter` keeps groups.
- `rank(ascending=False, method="first")`.
- `fillna(g.transform("mean"))` fills by group.
- A `transform` mask is a quick alternative to `filter`.
