## Understand

### SQL is a second front door to the same engine

You already know SQL from the earlier days, and Spark lets you use it. **Spark SQL** is the part of Spark that parses SQL text and runs it on the same engine as the DataFrame API. Both are turned by the **Catalyst optimiser** into a logical plan and then a physical plan, so a query written in SQL and the same query written with `groupBy` and `agg` normally run identically. Choose by readability: SQL for joins and window functions that you can write quickly and share with analysts, the DataFrame API for building queries step by step in Python code, for testing and for programmatic column lists. Mixing them is normal.

Spark and Java are not available in this course's tests or browser, so each Spark SQL statement shown here is checked by running the same query in PostgreSQL on PGlite, or the same computation in pandas. Spark SQL and PostgreSQL share most syntax, and the differences that matter are pointed out.

### Temporary views

To query a DataFrame with SQL you give it a name. `df.createOrReplaceTempView("orders")` registers a **temporary view**: a name in the current Spark session that refers to the DataFrame's plan. Nothing is copied or computed; the view is just a name for a plan, which stays lazy. `spark.sql("SELECT ... FROM orders ...")` returns a **DataFrame**, so the result can be filtered, joined and written like any other, and the query still runs only when an action asks. A temporary view lives as long as the session that created it and is not visible in other sessions. `createGlobalTempView("orders")` creates a view shared by sessions of the same application, which you refer to as `global_temp.orders`. Neither kind is a table: nothing is stored, and the catalog calls them temporary. Persistent tables need a metastore and are outside this lesson.

```python
orders.createOrReplaceTempView("orders")
top = spark.sql("""
    SELECT category, SUM(amount) AS total
    FROM orders
    GROUP BY category
    ORDER BY total DESC
""")
top.show()
```

### The same query in two languages

`spark.sql("SELECT category, SUM(amount) AS total FROM orders WHERE amount >= 30 GROUP BY category")` and `orders.filter(F.col("amount") >= 30).groupBy("category").agg(F.sum("amount").alias("total"))` describe the same plan. The translation table is regular: `WHERE` is `filter`, `GROUP BY` with aggregates is `groupBy().agg()`, `HAVING` is a `filter` after the aggregation, `ORDER BY` is `orderBy`, `CASE WHEN` is `F.when`, `SELECT a AS b` is `select(F.col("a").alias("b"))`. You can see that they match: `explain()` of both prints the same physical plan. Use whichever you can verify more easily; in this lesson the SQL form is the one that runs here.

### Built-in functions

Spark SQL has hundreds of built-in functions, available in SQL and in `pyspark.sql.functions`. The groups you meet daily are **string** functions (`upper`, `lower`, `trim`, `concat`, `substring`, `length`, `replace`, `regexp_replace`), **numeric** functions (`round`, `floor`, `ceil`, `abs`), **conditional** functions (`CASE WHEN`, `coalesce`, `nullif`, `if`) and **date** functions (`to_date`, `year`, `month`, `date_add`, `datediff`, `date_trunc`, `date_format`). Some details differ from PostgreSQL, so check before moving SQL between systems. `substring(str, pos, len)` is 1-based in both. `datediff(end, start)` in Spark returns the number of days from `start` to `end` (PostgreSQL: subtract the dates, `end - start`). `date_format(d, 'yyyy-MM')` uses Java-style patterns where PostgreSQL's `to_char(d, 'YYYY-MM')` uses its own, and `trunc(d, 'month')` (for a date) or `date_trunc('month', ts)` give the first day of a month in Spark. Integer division with `/` returns a decimal in Spark, so there is no surprise of truncated results, whereas in PostgreSQL `7 / 2` is 3: the examples cast explicitly.

### Window functions

A **window function** computes a value for each row using a set of related rows, without collapsing them as `GROUP BY` does (you used them in the SQL window-functions days). `ROW_NUMBER() OVER (PARTITION BY category ORDER BY amount DESC)` numbers the rows within each category; `SUM(amount) OVER (ORDER BY order_date)` is a running total; `LAG(amount) OVER (ORDER BY order_date)` is the previous row's value. In Spark a window needs all rows of a partition key together, so it is a **wide** operation: Spark shuffles by the `PARTITION BY` columns and sorts within each. A window with no `PARTITION BY` moves every row to a single partition, which does not scale and Spark warns about it. The DataFrame API builds the same thing with `Window.partitionBy("category").orderBy(F.desc("amount"))` and `F.row_number().over(w)`.

### ANSI mode and other differences

Spark SQL follows the SQL standard in many ways but not in all. Behaviour for invalid operations depends on the setting `spark.sql.ansi.enabled`: with it on, an invalid cast or an integer overflow raises an error; with it off, they return null or wrap silently. The default has changed between versions (it is on by default from Spark 4.0), so a query that quietly returned nulls on one version may fail on another. Identifiers that clash with keywords are quoted with backticks, not double quotes, and string literals use single quotes (or double, depending on settings).

### Why it matters

Most data teams already write SQL, so Spark SQL puts the engine within reach of analysts, and temp views let a Python job and a SQL query share intermediate results. The misconception is that SQL on a DataFrame is slower or a different engine; it is the same optimiser and plan. The real risks are version-dependent behaviour and window functions without a partition key.

## Syntax and key functions

```python
df.createOrReplaceTempView("orders")
result = spark.sql("SELECT category, SUM(amount) AS total FROM orders GROUP BY category")
```

```sql-syntax
SELECT <columns or expressions>
FROM <view>
WHERE <condition>
GROUP BY <columns>
HAVING <condition on aggregates>
ORDER BY <columns>
```

| Item | What it does |
|---|---|
| `createOrReplaceTempView(name)` | Names a DataFrame's plan for SQL in this session. |
| `createGlobalTempView(name)` | Shared view; queried as `global_temp.name`. |
| `spark.sql(text)` | Runs SQL, returns a DataFrame (lazy). |
| `row_number()`, `rank()`, `dense_rank()` | Ranking over a window. |
| `SUM(x) OVER (...)`, `LAG(x) OVER (...)` | Running totals and previous values. |
| `date_trunc`, `datediff`, `date_format`, `to_date` | Date helpers; check argument order and patterns. |
| `coalesce`, `nullif`, `CASE WHEN` | Null and conditional handling. |

## Learn by example

### Example 1: A temp view and the same query

The Spark query is `spark.sql("SELECT category, COUNT(*) AS orders, SUM(amount) AS total FROM orders WHERE amount >= 20 GROUP BY category ORDER BY total DESC")`. Run it as SQL and in pandas.

```sql run
WITH orders(order_id, customer_id, category, amount, order_date) AS (
  VALUES (1,'c1','books',20,DATE '2025-01-05'),(2,'c2','books',35,DATE '2025-01-18'),(3,'c1','games',60,DATE '2025-02-02'),
         (4,'c3','games',15,DATE '2025-02-14'),(5,'c2','music',10,DATE '2025-02-20'),(6,'c4','books',45,DATE '2025-03-03'),
         (7,'c3','music',30,DATE '2025-03-09'),(8,'c1','books',25,DATE '2025-03-21'),(9,'c4','games',80,DATE '2025-04-01'),
         (10,'c5','music',12,DATE '2025-04-12'),(11,'c2','games',70,DATE '2025-04-25'),(12,'c5','books',18,DATE '2025-05-02')
)
SELECT category, COUNT(*) AS orders, SUM(amount) AS total
FROM orders
WHERE amount >= 20
GROUP BY category
ORDER BY total DESC
```

```output
category | orders | total
games | 3 | 210
books | 4 | 125
music | 1 | 30
```

```python run
import zlib

COLS = ["order_id", "customer_id", "category", "amount"]
ROWS = [
    (1, "c1", "books", 20), (2, "c2", "books", 35), (3, "c1", "games", 60), (4, "c3", "games", 15),
    (5, "c2", "music", 10), (6, "c4", "books", 45), (7, "c3", "music", 30), (8, "c1", "books", 25),
    (9, "c4", "games", 80), (10, "c5", "music", 12), (11, "c2", "games", 70), (12, "c5", "books", 18),
]

def show(rows, cols, n=20):
    """Format rows the way DataFrame.show() prints them."""
    cells = [[str(v) for v in r] for r in rows[:n]]
    widths = [max(len(c), *(len(r[i]) for r in cells)) if cells else len(c) for i, c in enumerate(cols)]
    line = "+" + "+".join("-" * w for w in widths) + "+"
    out = [line, "|" + "|".join(c.rjust(w) for c, w in zip(cols, widths)) + "|", line]
    out += ["|" + "|".join(v.rjust(w) for v, w in zip(r, widths)) + "|" for r in cells]
    return "\n".join(out + [line])

def slices(rows, n):
    size = -(-len(rows) // n)
    return [rows[i * size:(i + 1) * size] for i in range(n)]

def target(key, n):
    return zlib.crc32(str(key).encode()) % n

import pandas as pd

df = pd.DataFrame(ROWS, columns=COLS)
out = df[df["amount"] >= 20].groupby("category").agg(orders=("order_id", "count"), total=("amount", "sum")).sort_values("total", ascending=False)
print(out.to_string())
```

```output
          orders  total
category               
games          3    210
books          4    125
music          1     30
```

Games lead with 3 orders worth 210, books follow with 4 orders worth 125 and music has 1 order of 30. The two engines agree, which is the check that the Spark SQL statement and the DataFrame form `filter(...).groupBy("category").agg(...)` produce the same rows.

### Example 2: String and date functions

Spark: `SELECT upper(category) AS cat, date_trunc('month', order_date) AS month, SUM(amount) ...` (for a date column, `trunc(order_date, 'month')` gives a date). The PostgreSQL equivalent follows.

```sql run
WITH orders(order_id, category, amount, order_date) AS (
  VALUES (1,'books',20,DATE '2025-01-05'),(2,'books',35,DATE '2025-01-18'),(3,'games',60,DATE '2025-02-02'),
         (4,'games',15,DATE '2025-02-14'),(5,'music',10,DATE '2025-02-20'),(6,'books',45,DATE '2025-03-03'),
         (7,'music',30,DATE '2025-03-09'),(8,'books',25,DATE '2025-03-21'),(9,'games',80,DATE '2025-04-01')
)
SELECT date_trunc('month', order_date)::date AS month,
       upper(substring(category, 1, 3)) AS code,
       SUM(amount) AS total,
       MAX(order_date) - MIN(order_date) AS span_days
FROM orders
GROUP BY 1, 2
ORDER BY 1, 2
```

```output
month | code | total | span_days
2025-01-01 | BOO | 55 | 13
2025-02-01 | GAM | 75 | 12
2025-02-01 | MUS | 10 | 0
2025-03-01 | BOO | 70 | 18
2025-03-01 | MUS | 30 | 0
2025-04-01 | GAM | 80 | 0
```

Each row is a month and a three-letter category code. `substring(category, 1, 3)` takes the first three characters (1-based). The last column subtracts two dates, 13 days for books in January (5 to 18 January); in Spark the same value is `datediff(MAX(order_date), MIN(order_date))` with the later date first.

### Example 3: Top order per category with a window

Spark SQL: `SELECT * FROM (SELECT *, ROW_NUMBER() OVER (PARTITION BY category ORDER BY amount DESC) AS rn FROM orders) WHERE rn = 1`.

```sql run
WITH orders(order_id, category, amount) AS (
  VALUES (1,'books',20),(2,'books',35),(3,'games',60),(4,'games',15),(5,'music',10),(6,'books',45),
         (7,'music',30),(8,'books',25),(9,'games',80),(10,'music',12),(11,'games',70),(12,'books',18)
), ranked AS (
  SELECT *, ROW_NUMBER() OVER (PARTITION BY category ORDER BY amount DESC) AS rn
  FROM orders
)
SELECT category, order_id, amount
FROM ranked
WHERE rn = 1
ORDER BY category
```

```output
category | order_id | amount
books | 6 | 45
games | 9 | 80
music | 7 | 30
```

```python run
import zlib

COLS = ["order_id", "customer_id", "category", "amount"]
ROWS = [
    (1, "c1", "books", 20), (2, "c2", "books", 35), (3, "c1", "games", 60), (4, "c3", "games", 15),
    (5, "c2", "music", 10), (6, "c4", "books", 45), (7, "c3", "music", 30), (8, "c1", "books", 25),
    (9, "c4", "games", 80), (10, "c5", "music", 12), (11, "c2", "games", 70), (12, "c5", "books", 18),
]

def show(rows, cols, n=20):
    """Format rows the way DataFrame.show() prints them."""
    cells = [[str(v) for v in r] for r in rows[:n]]
    widths = [max(len(c), *(len(r[i]) for r in cells)) if cells else len(c) for i, c in enumerate(cols)]
    line = "+" + "+".join("-" * w for w in widths) + "+"
    out = [line, "|" + "|".join(c.rjust(w) for c, w in zip(cols, widths)) + "|", line]
    out += ["|" + "|".join(v.rjust(w) for v, w in zip(r, widths)) + "|" for r in cells]
    return "\n".join(out + [line])

def slices(rows, n):
    size = -(-len(rows) // n)
    return [rows[i * size:(i + 1) * size] for i in range(n)]

def target(key, n):
    return zlib.crc32(str(key).encode()) % n

import pandas as pd

df = pd.DataFrame(ROWS, columns=COLS)
df["rn"] = df.sort_values("amount", ascending=False).groupby("category").cumcount() + 1
print(df[df["rn"] == 1][["category", "order_id", "amount"]].sort_values("category").to_string(index=False))
```

```output
category  order_id  amount
   books         6      45
   games         9      80
   music         7      30
```

The largest order per category is order 6 for books (45), order 9 for games (80) and order 7 for music (30). In PySpark: `w = Window.partitionBy("category").orderBy(F.desc("amount"))`, then `orders.withColumn("rn", F.row_number().over(w)).filter("rn = 1")`. Spark has to shuffle the rows by `category` so that each category sits on one partition before numbering.

### Example 4: Running total and previous value

```sql run
WITH orders(order_id, amount, order_date) AS (
  VALUES (1,20,DATE '2025-01-05'),(2,35,DATE '2025-01-18'),(3,60,DATE '2025-02-02'),(4,15,DATE '2025-02-14'),(5,10,DATE '2025-02-20')
)
SELECT order_id, amount,
       SUM(amount) OVER (ORDER BY order_date) AS running_total,
       LAG(amount) OVER (ORDER BY order_date) AS previous_amount,
       amount - LAG(amount) OVER (ORDER BY order_date) AS change
FROM orders
ORDER BY order_date
```

```output
order_id | amount | running_total | previous_amount | change
1 | 20 | 20 | NULL | NULL
2 | 35 | 55 | 20 | 15
3 | 60 | 115 | 35 | 25
4 | 15 | 130 | 60 | -45
5 | 10 | 140 | 15 | -5
```

```python run
import pandas as pd

amounts = pd.Series([20, 35, 60, 15, 10])
print(amounts.cumsum().tolist(), amounts.shift(1).tolist(), amounts.diff().tolist())
```

```output
[20, 55, 115, 130, 140] [nan, 20.0, 35.0, 60.0, 15.0] [nan, 15.0, 25.0, -45.0, -5.0]
```

The running total after the five orders is 140, the first row has no previous amount (NULL in SQL, NaN in pandas), and the change for order 3 is +25 (60 against 35). This window has no `PARTITION BY`, so on a real cluster Spark would put all rows into one partition to sort them: fine for five rows, a problem for five billion. Partition by customer or day when you can.

### Example 5: A pivot with conditional aggregation

Spark SQL has `PIVOT`; the portable form is `CASE` inside an aggregate, which also runs in PostgreSQL.

```sql run
WITH orders(order_id, category, amount, order_date) AS (
  VALUES (1,'books',20,DATE '2025-01-05'),(2,'books',35,DATE '2025-01-18'),(3,'games',60,DATE '2025-02-02'),
         (4,'games',15,DATE '2025-02-14'),(5,'music',10,DATE '2025-02-20'),(6,'books',45,DATE '2025-03-03'),
         (7,'music',30,DATE '2025-03-09'),(8,'books',25,DATE '2025-03-21'),(9,'games',80,DATE '2025-04-01')
)
SELECT EXTRACT(MONTH FROM order_date)::int AS month,
       SUM(CASE WHEN category = 'books' THEN amount ELSE 0 END) AS books,
       SUM(CASE WHEN category = 'games' THEN amount ELSE 0 END) AS games,
       SUM(CASE WHEN category = 'music' THEN amount ELSE 0 END) AS music
FROM orders
GROUP BY 1
ORDER BY 1
```

```output
month | books | games | music
1 | 55 | 0 | 0
2 | 0 | 75 | 10
3 | 70 | 0 | 30
4 | 0 | 80 | 0
```

January has only books (55), February games 75 and music 10, March books 70 and music 30, April games 80. In PySpark the same table comes from `orders.groupBy(F.month("order_date")).pivot("category").sum("amount")`, which leaves nulls where a category has no orders in a month, while the `CASE` form gives zeros. Pivoting wide tables should list the pivot values explicitly so that Spark does not need an extra job to find them.

## Real-world applications

- **Analyst access.** A team publishes cleaned DataFrames as temp views so analysts can write SQL against them in notebooks (Example 1).
- **Reporting tables.** Monthly summaries with date functions and conditional aggregation feed dashboards (Examples 2 and 5).
- **Top-N and deduplication.** `ROW_NUMBER()` windows pick the latest or largest row per key, the standard way to deduplicate (Example 3).
- **Time series features.** Running totals and `LAG` create features for models and anomaly checks (Example 4).

## Daily review

### Key takeaways

- A temp view names a DataFrame's plan; `spark.sql` returns a lazy DataFrame.
- SQL and the DataFrame API compile to the same plan; choose for readability.
- Built-ins have regular groups, but argument orders and date patterns differ from PostgreSQL.
- Windows are wide operations; give them a `PARTITION BY` on real data.
- ANSI mode changes error behaviour by version; check your Spark version.

### Common mistakes

- Expecting a temp view to be saved or visible in another session.
- Forgetting that `spark.sql` is lazy and nothing has run.
- Using `datediff(start, end)` with the arguments the wrong way round.
- Writing a window with no `PARTITION BY` on a large table.
- Assuming a cast that returned null in one Spark version behaves the same in another.
