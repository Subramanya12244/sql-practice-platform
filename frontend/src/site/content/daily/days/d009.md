- Create tuples, read their items, and explain why a tuple cannot be changed.
- Unpack a tuple (or a list) into several names, including swapping two values and collecting the rest with `*`.

- Choose between a list, a tuple and a set for a given piece of data.

## Understand

### Tuples: a fixed group of values

A **tuple** (type `tuple`) is an ordered collection like a list, but it is **immutable**: once created, its items cannot be replaced, added or removed. You write one with commas, usually inside round brackets: `point = (3, 7)`. Indexing and slicing work exactly as for lists, so `point[0]` is `3` and `point[::-1]` is `(7, 3)`. A tuple with one item needs a trailing comma, `(5,)`, because `(5)` is just the number 5 in brackets. The empty tuple is `()`.

Why have something that cannot change? A tuple signals that the values belong together as one record whose shape is fixed, such as a point `(x, y)`, a date `(2025, 3, 14)` or a database row `("Ada", 36, "London")`. Because it cannot change, it is safe to share, and Python allows tuples in places where lists are not allowed, such as the keys of a dictionary (Day 10). Trying to change one raises `TypeError: 'tuple' object does not support item assignment`.

A common misconception is that the immutability goes "all the way down". It does not: if a tuple holds a list, the list inside can still change. The tuple only guarantees that it keeps pointing at the same items.

### Unpacking

**Unpacking** assigns the items of a tuple (or any sequence) to several names in one statement:

```text
name, age, city = ("Ada", 36, "London")
```

The number of names on the left must equal the number of items, otherwise Python raises `ValueError: too many values to unpack` or `not enough values to unpack`. Unpacking explains a trick you may have seen: `a, b = b, a` swaps two values, because the right side builds a tuple first. A name with a star, as in `first, *rest = items`, collects all the remaining items into a list. A function that returns two values really returns one tuple; you will see this on Day 14.

### Sets: unique values

A **set** (type `set`) is an unordered collection of **unique** values, written with curly brackets: `{3, 1, 2}`. Adding a value that is already present changes nothing. A set has no positions, so `s[0]` is a `TypeError`, and the order in which a set prints is not something you can rely on. An empty set must be written `set()`, because `{}` creates an empty dictionary.

Two properties make sets useful. First, **membership tests** with `in` are very fast, even for very large sets, whereas a list has to be searched item by item. Second, sets remove duplicates: `set([3, 1, 3, 2, 1])` is `{1, 2, 3}`. Set items must be immutable, so a set can hold numbers, strings and tuples but not lists.

### Changing a set

`add(x)` inserts one value, `discard(x)` removes it if present and does nothing if absent, and `remove(x)` removes it but raises `KeyError` when absent. `update(other)` adds all values of another collection. `len()` and `in` work as with lists.

### Set operations

Sets support the operations from school mathematics.

- **Union** `a | b`: everything in either set.
- **Intersection** `a & b`: only what is in both.
- **Difference** `a - b`: what is in `a` but not in `b`.
- **Symmetric difference** `a ^ b`: what is in exactly one of them.

Think of two guest lists: the union is everyone invited to either party, the intersection is the people invited to both, and the difference is the people invited to the first party only. The same results are available as methods: `a.union(b)`, `a.intersection(b)` and `a.difference(b)`.

### Deduplication, and its catch

Converting a list to a set and back, `list(set(items))`, removes duplicates, but the set forgets the original order. When you need a stable order, sort the result with `sorted(set(items))`. Keeping the first-seen order needs a different technique, which comes later in this course.

### Choosing a type

Use a **list** for an ordered sequence you will change. Use a **tuple** for a small fixed record. Use a **set** when you care about uniqueness or fast "is it in there?" checks and not about order.

### A worked trace of unpacking and sets

For the swap `a, b = b, a` with `a = 1` and `b = 2`, Python first builds the tuple `(2, 1)` from the right-hand side, using the old values. Only then does it assign `2` to `a` and `1` to `b`. If it assigned one name at a time, the old value of `a` would be lost; the tuple holds both until the assignment is done.

A set decides membership with a technique called **hashing**: each value is turned into a number that says where to look, much like an index at the back of a book tells you which page to open instead of reading every page. This is why `x in some_set` is fast, and why set items must be immutable: a value that could change would be filed in the wrong place. Two sets are equal when they have the same items, whatever their order, so `{1, 2} == {2, 1}` is `True`.

One surprise to know about: `set("hello")` gives the set of the **characters** `{'h', 'e', 'l', 'o'}`, because a string is a sequence of characters. To make a set holding one string, put it in a list or braces: `{"hello"}`.

## Syntax and key functions

```text
t = (1, 2, 3)        t = 1, 2, 3        single = (5,)
a, b, c = t          first, *rest = t
s = {1, 2, 3}        empty = set()      s = set(items)
s.add(x)   s.discard(x)   s.remove(x)   s.update(items)
a | b      a & b      a - b      a ^ b
x in s     len(s)     sorted(s)
```

- Tuple items are read with indexes and slices; they cannot be assigned.
- Unpacking needs the same number of names as items, unless one name has a star.
- `set()` makes an empty set; `{}` is an empty dictionary.

| Tool | What it returns |
|---|---|
| `tuple(items)` | a tuple with the same items |
| `t.count(x)`, `t.index(x)` | how many times `x` occurs, or its first position |
| `set(items)` | a set of the unique items |
| `a.union(b)`, `a.intersection(b)`, `a.difference(b)` (or the operators) | a new set |
| `s.add(x)`, `s.discard(x)`, `s.update(o)` | `None` (the set is changed) |
| `a.issubset(b)` | `True` if every item of `a` is in `b` |
| `sorted(s)` | a new sorted list of the items |

## Learn by example

### Example 1: Tuples and immutability

```python run
point = (3, 7)
print(point[0], point[-1], len(point))
print(point[::-1])
single = (5,)
print(type(single), type((5)))
longer = point + (9,)
print(longer, point)
```

```output
3 7 2
(7, 3)
<class 'tuple'> <class 'int'>
(3, 7, 9) (3, 7)
```

Writing `point[0] = 9` would raise `TypeError: 'tuple' object does not support item assignment`. To get a different tuple you build a new one: `point + (9,)` joins two tuples into `(3, 7, 9)`, and `point` itself is unchanged.

### Example 2: Unpacking

```python run
record = ("Ada", 36, "London")
name, age, city = record
print(name, age, city)
a, b = 1, 2
a, b = b, a
print(a, b)
first, *rest = [10, 20, 30, 40]
print(first, rest)
*start, last = "abcd"
print(start, last)
```

```output
Ada 36 London
2 1
10 [20, 30, 40]
['a', 'b', 'c'] d
```

The swap works because `b, a` is built as a tuple before any name is changed.

### Example 3: Sets remove duplicates

```python run
emails = ["a@x.com", "b@x.com", "a@x.com", "c@x.com", "b@x.com"]
unique = set(emails)
print(len(emails), len(unique))
print(sorted(unique))
print("b@x.com" in unique, "z@x.com" in unique)
unique.add("d@x.com")
unique.add("a@x.com")
unique.discard("c@x.com")
print(sorted(unique))
```

```output
5 3
['a@x.com', 'b@x.com', 'c@x.com']
True False
['a@x.com', 'b@x.com', 'd@x.com']
```

Adding `"a@x.com"` again changed nothing. We print `sorted(...)` because the order of a set is not reliable.

### Example 4: Set operations

```python run
monday = {"Ann", "Bo", "Cy", "Di"}
tuesday = {"Bo", "Di", "Ed"}
print(sorted(monday | tuesday))
print(sorted(monday & tuesday))
print(sorted(monday - tuesday))
print(sorted(tuesday - monday))
print(sorted(monday ^ tuesday))
print({"Bo"}.issubset(monday))
```

```output
['Ann', 'Bo', 'Cy', 'Di', 'Ed']
['Bo', 'Di']
['Ann', 'Cy']
['Ed']
['Ann', 'Cy', 'Ed']
True
```

### Example 5: Comparing two customer lists

A realistic task: which customers bought in both months, which are new, and which were lost.

```python run
january = ["C01", "C02", "C03", "C02", "C04"]
february = ["C02", "C04", "C05", "C06", "C05"]
jan, feb = set(january), set(february)
print("Both:", sorted(jan & feb))
print("New:", sorted(feb - jan))
print("Lost:", sorted(jan - feb))
print("Active in total:", len(jan | feb))
```

```output
Both: ['C02', 'C04']
New: ['C05', 'C06']
Lost: ['C01', 'C03']
Active in total: 6
```

## Real-world applications

- **Finding distinct values.** `len(set(column))` counts how many different customers, products or countries a column holds.
- **Comparing two data sources.** Intersection and difference show which ids appear in both systems and which are missing from one, a first step in reconciliation.
- **Fast validity checks.** `if code in valid_codes:` with a set of allowed values checks each record quickly.
- **Fixed records.** Tuples hold rows such as `(order_id, amount)` that should not be edited by accident, and unpacking turns them into named values.

## Daily review

### Key takeaways

- A tuple is an immutable ordered group; a list is mutable.
- Unpacking assigns several names at once, and a starred name collects the rest.
- A set stores each value once, has no order and tests membership fast.
- `|`, `&`, `-` and `^` give union, intersection, difference and symmetric difference.
- `sorted(set(items))` removes duplicates and gives a stable order.

### Common mistakes

- **Writing `(5)` for a one-item tuple.** It is the integer 5. Write `(5,)`.
- **Using `{}` for an empty set.** That is an empty dictionary. Write `set()`.
- **Indexing a set.** `s[0]` raises `TypeError: 'set' object is not subscriptable`. Convert with `sorted(s)` first.
- **Relying on set order.** The printed order may differ from what you expect or from another run. Sort before printing.
- **Putting a list inside a set.** `{[1, 2]}` raises `TypeError: unhashable type: 'list'`. Use a tuple `(1, 2)`.
- **Wrong number of names when unpacking.** `a, b = (1, 2, 3)` raises `ValueError: too many values to unpack`. Match the count or use `*`.

### Revision notes

- Tuple: `(a, b)`, fixed, `(x,)` for one item.
- Unpack: `a, b = t`; swap `a, b = b, a`; `first, *rest = items`.
- Set: unique, unordered, `set()` for empty, fast `in`.
- `|` union, `&` both, `-` only left, `^` only one.
