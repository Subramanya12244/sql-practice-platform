## Objectives

- Read the output of `info()` and `describe()`, and explain each line.
- Count how often each value occurs with `value_counts()` and `nunique()`, and read counts of non-missing values with `count()`.

- Write a short inspection routine that you can run on any new DataFrame.

## Understand

### Inspect before you analyse

When a table arrives from a file, a database or a colleague, you do not know what is in it. Computing averages straight away is how wrong reports are produced. **Inspecting** means looking at the data in a systematic way before changing or summarising it. The aim is to answer five questions. How big is it? What are the columns and their types? What do the values look like? How are values distributed? What looks wrong? pandas gives one tool for each question, and together they take a minute to run.

### Size and look: shape, head and tail

`df.shape` gives `(rows, columns)`, which you met on Day 68. A table with a different number of rows than the source claims is the first sign of a bad read. `df.head()` shows the first five rows and `df.tail()` the last five. You can pass a number: `df.head(3)`. Looking at both ends matters because files often have different content at the end, such as a totals line or footer text, and the first rows may be sorted in a way that hides problems further down. Five rows will not show every problem, but they show whether the column names and the cell layout are what you expected.

### Types and completeness: info and dtypes

`df.info()` prints a summary: the number of rows, and for every column its name, the count of **non-null** values (values that are not missing) and its dtype. Two things are worth reading closely. If a column has fewer non-null values than the table has rows, it has missing values. If a column that should be numeric has the dtype `object`, it contains at least one value that pandas could not read as a number, so the whole column is text. A single entry such as `"n/a "` or `"ten"` is enough. The attribute `df.dtypes` lists only the types, and `df.count()` gives the non-null count per column. Note that `info()` prints directly and returns `None`, so you do not wrap it in `print`.

### Numeric summaries: describe

`df.describe()` summarises every numeric column: `count` (non-null values), `mean`, `std` (standard deviation), `min`, the quartiles `25%`, `50%` (the median) and `75%`, and `max`. The **quartiles** are the values below which a quarter, a half and three quarters of the data lie. The summary is a quick plausibility check. An age with a minimum of `-1` or a maximum of `999` is not a real age. A mean far from the median suggests a few extreme values. A standard deviation of 0 means that the column is constant and probably useless. For text columns `describe()` gives different information (the number of unique values, the most common value and its frequency), but only if you ask for text columns explicitly or describe a single column.

### Counting values: value_counts and nunique

`s.value_counts()` counts how many times each distinct value appears in a column, sorted from the most common. It is the best tool for categorical columns: you see the allowed values and, importantly, the spelling variants. If `city` shows `Oslo` 40 times, `oslo` 3 times and `Oslo ` (with a trailing space) 2 times, you have found a labelling problem that would split one city into three groups later. `value_counts(normalize=True)` gives shares instead of counts. `s.nunique()` is the number of distinct values, and `s.unique()` lists them. Comparing `nunique()` with the number of rows tells you whether a column that should be a unique identifier really is one: 100 rows but 97 distinct ids means repeated identifiers.

### Spotting problems: a checklist

From the five tools you can find the usual problems without any fixing:

- **Wrong type.** A numeric column with dtype `object` (info or dtypes).
- **Missing values.** A non-null count below the row count (info or count).
- **Sentinel values.** Codes like `-999` or `9999` that stand for "unknown", visible as odd minima or maxima in `describe`.
- **Impossible ranges.** Negative quantities, ages over 120, dates in the future.
- **Inconsistent labels.** Case and spacing variants in `value_counts`.
- **Repeated identifiers.** `nunique` smaller than the row count for an id column.
- **Unexpected size or columns.** A wrong `shape`, or columns whose names have stray spaces.

Fixing these problems is the work of the next days (missing values, duplicates, types and text). Today you only find and describe them, which is the right order: you cannot fix what you have not seen.

### The common misconception

Learners think that if the file loads without an error, the data is fine. Loading only proves that the text could be split into cells. A table can load with every number stored as text, the wrong separator giving one column, or half of its labels spelled differently, and pandas reports no error in any of these cases. The symptom appears later as an error such as `TypeError: unsupported operand type(s)` or as a wrong total. Inspecting is the cheap way to catch these early.

### Why it matters in data work

Every analysis relies on assumptions: this column is numeric, these ids are unique, these codes are the full list. Inspection checks those assumptions. In a team it also becomes documentation: a short printed summary of shape, types, ranges and top values is what you send with a dataset so that others know what they are working with. Keep the habit of running the same routine on every new table, and update it as you learn what typically goes wrong with your data.

### Printing choices

`head()`, `describe()` and `value_counts()` return objects that print well in a notebook. To keep output compact and stable in a script, use `print(df.head())`, `print(df.describe().round(2))` and `print(s.value_counts().to_dict())`. Rounding the output of `describe()` makes it readable. The examples use `pd.set_option("display.width", 200)` so that wide tables are printed in one piece instead of wrapped.

## Syntax and key functions

Inspection routine:

```python
df.shape
df.head(n)
df.tail(n)
df.info()
df.dtypes
df.describe()
df["col"].value_counts()
df["col"].nunique()
df.count()
```

| Expression | Returns |
|---|---|
| `df.shape` | `(rows, columns)`. |
| `df.head(n)`, `df.tail(n)` | First or last n rows (default 5). |
| `df.info()` | Prints rows, columns, non-null counts and dtypes; returns `None`. |
| `df.describe()` | count, mean, std, min, quartiles, max of numeric columns. |
| `df["c"].describe()` | count, unique, top and freq for a text column. |
| `s.value_counts()` | A Series of counts per distinct value, most common first. |
| `s.value_counts(normalize=True)` | Shares instead of counts. |
| `s.nunique()`, `s.unique()` | Number of distinct values; the distinct values. |
| `df.count()` | Non-null values per column. |
| `df.columns.tolist()` | Column names, to look for stray spaces. |

## Learn by example

### Example 1: First look, shape, head and tail

A small order table is read from CSV text. The shape, the first and last rows and the column names are the first look. Passing a number to `head` and `tail` changes how many rows are shown.

```python run
import io
import pandas as pd

pd.set_option("display.width", 200)
pd.set_option("display.max_columns", 20)

text = """id,city,qty,price,age
1,Oslo,3,9.5,34
2,Rome,1,4.0,29
3,oslo,5,12.25,41
4,Lima,2,7.0,-1
5,Rome,4,3.5,52
6,Oslo ,6,8.0,38
7,Lima,2,5.5,999
"""
df = pd.read_csv(io.StringIO(text))
print(df.shape, df.columns.tolist())
print(df.head(3))
print(df.tail(2))
```

### Example 3: value_counts and nunique find label problems

`value_counts` (sorted by label here, so that ties have a fixed order) shows that one city is spelled three ways. The number of distinct values is larger than the number of real cities, and an id column that is unique has `nunique` equal to the number of rows. `describe` on one text column also reports the number of unique values (it adds the most common value and its frequency, which is ambiguous when two values tie, so we read only `unique`).

```python run
import io
import pandas as pd

text = """id,city,qty
1,Oslo,3
2,Rome,1
3,oslo,5
4,Lima,2
5,Rome,4
6,Oslo ,6
7,Lima,2
"""
df = pd.read_csv(io.StringIO(text))
print(df["city"].value_counts().sort_index().to_dict())
print(df["city"].nunique(), df["id"].nunique(), len(df))
print(sorted(df["city"].unique().tolist()))
print(df["city"].value_counts(normalize=True).sort_index().round(2).to_dict())
print(df["city"].describe()["unique"])
print(df["qty"].max(), df["qty"].min())
```

```output

```

### Example 4: A column that loads as text

One cell, `ten`, makes the whole `qty` column text. `info` shows the dtype `object`, and `value_counts` reveals the culprit. Calling `sum` on a text column does not fail: it joins the strings, so the result `3ten5` is text and not a number, which is a quiet kind of wrong answer.

```python run
import io
import pandas as pd

text = """id,qty,price
1,3,2.5
2,ten,4.0
3,5,1.5
"""
df = pd.read_csv(io.StringIO(text))
df.info(memory_usage=False)
print()
print(df["qty"].value_counts().sort_index().to_dict())
print(df["qty"].sum())
print(df["price"].sum())
```


### Example 5: A reusable inspection routine

The same checks are wrapped in a small function that prints a compact report for any table: the size, the columns that are not numeric, the columns with missing values, and the numeric summary. It is applied to a table with a missing price and a sentinel in `age`.

```python run
import io
import pandas as pd

def inspect(df):
    print("rows", len(df), "columns", df.shape[1])
    counts = df.count()
    for col in df.columns:
        print(col, "non-null", int(counts[col]), "unique", df[col].nunique())
    print(df.describe().round(2).to_string())

text = """id,city,price,age
1,Oslo,9.5,34
2,Rome,,29
3,Oslo,12.25,-1
4,Lima,7.0,999
"""
inspect(pd.read_csv(io.StringIO(text)))
```

## Real-world applications

- **Checking a new data delivery.** Before trusting an export, `shape`, `info` and `describe` confirm the row count, the types and the plausibility of ranges, as in Examples 1 and 2.
- **Finding labelling problems.** `value_counts` on a category column, as in Example 3, finds spelling and spacing variants that would split groups in a report.
- **Detecting type problems early.** Seeing `object` in `info` for a column that should be numeric, as in Example 4, tells you why sums and averages fail.
- **Documenting a dataset.** A short routine like that of Example 5 produces the summary that you attach to a dataset handed to a colleague.

## Daily review

### Key takeaways

- Inspect first: `shape`, `head`, `tail`, `info`, `describe`, `value_counts`.
- `info()` shows non-null counts and dtypes; an `object` column that should be numeric holds at least one bad value.
- `describe()` exposes sentinel values and impossible ranges through `min` and `max`.
- `value_counts()` shows distinct values and spelling variants; `nunique()` checks identifiers.
- Loading without an error does not mean the data is correct.

### Common mistakes

- Writing `print(df.info())`, which prints the summary and then `None`.
- Looking only at `head()` and missing a footer or oddities lower down. Check `tail()` too.
- Trusting `mean` without comparing it to `median` and the minimum and maximum.
- Reading `describe()` of a table and not noticing that text columns are left out.
- Counting a label with spacing or case variants as separate categories without noticing.
- Forgetting that `value_counts()` skips missing values unless `dropna=False` is given.

### Revision notes

- `df.shape`, `df.head(n)`, `df.tail(n)`, `df.info()`, `df.describe()`.
- `s.value_counts()`, `s.nunique()`, `s.unique()`, `df.count()`.
- Look for: object type on numbers, fewer non-nulls, odd min and max, label variants, repeated ids.
