## Understand

### Aggregating only some rows

An **aggregate** is one number that summarises many rows: a total, a count or an average. A **conditional aggregate** summarises only the rows that meet a rule, such as "total amount for the North region" or "number of orders of at least 100". In pandas you build a boolean mask and sum, as you did on the pandas days: `df.loc[mask, "Amount"].sum()`. Excel has a family of functions that do this directly: `SUMIFS`, `COUNTIFS` and `AVERAGEIFS`. In SQL it is the `WHERE` clause or a conditional aggregate.

### SUMIFS

`SUMIFS(sum_range, criteria_range1, criteria1, criteria_range2, criteria2, ...)` adds the cells of `sum_range` in the rows where every criterion is met. The sum range comes first, which differs from the older `SUMIF`, where it comes last. Each criterion is a pair: the range to test and the rule. All ranges must have exactly the same number of rows, or Excel returns `#VALUE!`. With several pairs the conditions are joined by AND: a row must pass all of them. For an OR condition you add two `SUMIFS` together, or use `SUMPRODUCT`, or list the choices in a spill formula. With an Excel Table, the call reads like a sentence: `=SUMIFS(Sales[Amount], Sales[Region], "North", Sales[Qty], ">=2")`.

### COUNTIFS and AVERAGEIFS

`COUNTIFS(criteria_range1, criteria1, criteria_range2, criteria2, ...)` counts the rows that meet all criteria. It has no sum range, because it counts rows. `AVERAGEIFS(average_range, criteria_range1, criteria1, ...)` has the same shape as `SUMIFS`. If no row meets the criteria, `AVERAGEIFS` returns `#DIV/0!`, because an average of nothing is undefined, while `SUMIFS` returns 0 and `COUNTIFS` returns 0. In pandas the mean of an empty selection is `NaN` and no error is raised.

### How criteria are written

A criterion is usually a text string, and the way you write it decides what it means.

- A bare value means equal to: `"North"` or `5`. Text matching ignores case, so `"north"` matches `North`.
- A comparison operator is written inside the string: `">=100"`, `"<>North"` (not equal), `"<50"`.
- To compare with a value in a cell, join the operator and the cell with `&`: `">="&F1`. Writing `">=F1"` would compare with the text "F1".
- The wildcards are `*` (any run of characters) and `?` (one character): `"N*"` matches North and Northeast. To match a real asterisk or question mark, put `~` in front of it.
- `""` matches empty cells, `"<>"` matches non-empty cells and `"<>"&""` is equivalent to `"<>"`.
- For dates, use `">="&DATE(2025,3,1)` or a cell that holds a date: a date is a number, so the comparison works on the serial numbers (Day 93). Typing the date as text in the criterion depends on the regional settings, and is best avoided.

A text number in the data matches a criterion of the same number: `COUNTIFS(A:A, 5)` counts both a number 5 and the text `"5"`, which is unlike a lookup (Day 94). This forgiving behaviour means a count can look right while a sum of the same column still ignores the text.

### Named criteria

Typing `"North"` and `100` inside a formula means that each change needs the formula edited. Instead, put the choices in input cells, give them names (Day 91) such as `RegionPick` and `MinQty`, and write `=SUMIFS(Sales[Amount], Sales[Region], RegionPick, Sales[Qty], ">="&MinQty)`. Changing the input cell changes every result, and anyone reading the formula sees the purpose of each criterion. With a data validation list on `RegionPick` (Day 91), the report becomes a small interactive tool. The operator must still be joined with `&` because a name holds only a value.

### Dynamic arrays

In Microsoft 365 and Excel 2021, a formula can return a whole list or table of results, which **spills** into the cells below and to the right. The formula is typed once in the top-left cell. `UNIQUE(range)` returns the distinct values of a column. `SORT(range, column, order)` returns a sorted copy. `FILTER(range, condition)` returns only the rows that meet a condition, for example `=FILTER(Sales, Sales[Amount]>=100, "none")`. A spilled range is referred to with the spill operator `#`: if `UNIQUE` is in F2, then `F2#` means the entire spilled list. A summary of totals per region is `=UNIQUE(Sales[Region])` in F2 and `=SUMIFS(Sales[Amount], Sales[Region], F2#)` in G2: because the criterion is a whole array, `SUMIFS` returns a whole array of results, one per region. If something is in the way of the spill, Excel shows `#SPILL!` until you clear the cells. Dynamic arrays are not in Excel 2019 or earlier, where older versions fill each cell by hand.

### Common misconception and why it matters

Many learners believe that `SUMIFS` is "a faster SUMIF". The important change is the order of arguments and the ability to use more than one condition. Conditional aggregates are the building blocks of every summary report, KPI table and check total in a workbook, and a PivotTable (the next lessons) is a point-and-click way to produce the same grid.

## Syntax and key functions

```excel
=SUMIFS(sum_range, criteria_range1, criteria1, criteria_range2, criteria2)
=COUNTIFS(criteria_range1, criteria1, criteria_range2, criteria2)
=AVERAGEIFS(average_range, criteria_range1, criteria1)
=UNIQUE(range)
=FILTER(range, condition, "if empty")
=SORT(range, column_number, 1)
```

`criteria` is a value, a cell, or a string such as `">=100"` or `"N*"`. `1` in `SORT` means ascending and `-1` descending. All ranges in one call must be the same size.

| Function | Returns |
|---|---|
| `SUMIFS(s, r1, c1, ...)` | Sum of `s` where all criteria hold; 0 if none. |
| `COUNTIFS(r1, c1, ...)` | Number of rows where all criteria hold. |
| `AVERAGEIFS(a, r1, c1, ...)` | Mean of `a` where all criteria hold; `#DIV/0!` if none. |
| `UNIQUE(r)` | Distinct values, spilled. |
| `FILTER(r, cond, alt)` | Rows where `cond` is true; `alt` if none. |
| `SORT(r, n, order)` | Sorted spilled copy. |
| `F2#` | The whole spill range that starts at F2. |

| Criterion | Meaning |
|---|---|
| `"North"` | Equal to North (any case). |
| `">=100"` or `">="&F1` | At least 100, or at least the value in F1. |
| `"<>North"` | Not equal to North (blank cells count). |
| `"N*"` | Starts with N. |
| `"<>"` | Not empty. |

## Learn by example

### Example 1: SUMIFS with one and two criteria

The sales table is in an Excel Table named `Sales`.

| Date | Region | Product | Qty | Amount |
|---|---|---|---|---|
| 2025-03-01 | North | Pen | 3 | 30 |
| 2025-03-02 | South | Pen | 1 | 10 |
| 2025-03-05 | North | Book | 2 | 40 |
| 2025-03-09 | East | Book | 5 | 100 |
| 2025-03-12 | North | Pen | 4 | 40 |
| 2025-03-15 | South | Book | 1 | 20 |
| 2025-03-20 | East | Pen | 2 | 20 |
| 2025-03-28 | North | Book | 1 | 20 |

```excel
=SUMIFS(Sales[Amount], Sales[Region], "North")
=SUMIFS(Sales[Amount], Sales[Region], "North", Sales[Product], "Pen")
=SUMIFS(Sales[Amount], Sales[Qty], ">=3")
```

```python run
import pandas as pd

sales = pd.DataFrame({
    "Date": pd.to_datetime(["2025-03-01", "2025-03-02", "2025-03-05", "2025-03-09", "2025-03-12", "2025-03-15", "2025-03-20", "2025-03-28"]),
    "Region": ["North", "South", "North", "East", "North", "South", "East", "North"],
    "Product": ["Pen", "Pen", "Book", "Book", "Pen", "Book", "Pen", "Book"],
    "Qty": [3, 1, 2, 5, 4, 1, 2, 1],
    "Amount": [30, 10, 40, 100, 40, 20, 20, 20],
})
print(sales.loc[sales["Region"] == "North", "Amount"].sum())
print(sales.loc[(sales["Region"] == "North") & (sales["Product"] == "Pen"), "Amount"].sum())
print(sales.loc[sales["Qty"] >= 3, "Amount"].sum())
```

```output
130
70
170
```

North has 30 + 40 + 40 + 20 = 130, North pens have 30 + 40 = 70, and rows with quantity at least 3 are 30 + 100 + 40 = 170. Each criterion pair becomes a boolean test joined with `&`, which is AND.

### Example 2: COUNTIFS and AVERAGEIFS, and the empty case

```excel
=COUNTIFS(Sales[Region], "North", Sales[Amount], ">=30")
=AVERAGEIFS(Sales[Amount], Sales[Region], "East")
=AVERAGEIFS(Sales[Amount], Sales[Region], "West")
=IFERROR(AVERAGEIFS(Sales[Amount], Sales[Region], "West"), 0)
```

```python run
import pandas as pd

sales = pd.DataFrame({
    "Region": ["North", "South", "North", "East", "North", "South", "East", "North"],
    "Amount": [30, 10, 40, 100, 40, 20, 20, 20],
})
print(((sales["Region"] == "North") & (sales["Amount"] >= 30)).sum())
print(sales.loc[sales["Region"] == "East", "Amount"].mean())
print(sales.loc[sales["Region"] == "West", "Amount"].mean())
print(sales.loc[sales["Region"] == "West", "Amount"].sum())
```

```output
3
60.0
nan
0
```

Three North orders reach 30 or more (30, 40 and 40). East averages (100 + 20) / 2 = 60. West has no rows: Excel's `AVERAGEIFS` shows `#DIV/0!`, but pandas gives `nan` without a message and `sum` gives 0, like `SUMIFS`. Counting a boolean mask with `.sum()` is the pandas version of `COUNTIFS`.

### Example 3: Operators, wildcards, dates and case

```excel
=SUMIFS(Sales[Amount], Sales[Region], "N*")
=SUMIFS(Sales[Amount], Sales[Region], "<>North")
=SUMIFS(Sales[Amount], Sales[Date], ">="&F1, Sales[Date], "<="&F2)
=COUNTIFS(Sales[Region], "north")
```

With F1 holding 2025-03-05 and F2 holding 2025-03-20 the third formula adds the orders dated from the 5th to the 20th inclusive.

```python run
import pandas as pd

sales = pd.DataFrame({
    "Date": pd.to_datetime(["2025-03-01", "2025-03-02", "2025-03-05", "2025-03-09", "2025-03-12", "2025-03-15", "2025-03-20", "2025-03-28"]),
    "Region": ["North", "South", "North", "East", "North", "South", "East", "North"],
    "Amount": [30, 10, 40, 100, 40, 20, 20, 20],
})
print(sales.loc[sales["Region"].str.startswith("N"), "Amount"].sum())
print(sales.loc[sales["Region"] != "North", "Amount"].sum())
lo, hi = pd.Timestamp("2025-03-05"), pd.Timestamp("2025-03-20")
print(sales.loc[sales["Date"].between(lo, hi), "Amount"].sum())
print((sales["Region"] == "north").sum(), (sales["Region"].str.lower() == "north").sum())
```

```output
130
150
220
0 4
```

`"N*"` becomes `startswith("N")`, but note that the Excel version also ignores case while `startswith` does not. `"<>North"` becomes `!=`; both include blank cells, because a blank is not equal to North. `between` includes both ends by default, like `>=` and `<=`. The last line shows the case difference: `COUNTIFS` with `"north"` counts 4, while the exact pandas comparison counts 0 until you lowercase.

### Example 4: A spilled summary with UNIQUE and SUMIFS

```excel
F2:  =SORT(UNIQUE(Sales[Region]))
G2:  =SUMIFS(Sales[Amount], Sales[Region], F2#)
H2:  =COUNTIFS(Sales[Region], F2#)
```

Type each formula once, in F2, G2 and H2. `F2#` is the full list of regions, so G2 and H2 spill to the same length. A two-way grid takes a second spill: with products across the top as `=TRANSPOSE(UNIQUE(Sales[Product]))` in J1, the formula `=SUMIFS(Sales[Amount], Sales[Region], F2#, Sales[Product], J1#)` fills a region-by-product grid.

```python run
import pandas as pd

sales = pd.DataFrame({
    "Region": ["North", "South", "North", "East", "North", "South", "East", "North"],
    "Product": ["Pen", "Pen", "Book", "Book", "Pen", "Book", "Pen", "Book"],
    "Amount": [30, 10, 40, 100, 40, 20, 20, 20],
})
g = sales.groupby("Region")["Amount"].agg(["sum", "count"])
print(g.to_string())
grid = sales.groupby(["Region", "Product"])["Amount"].sum().unstack(fill_value=0)
print(grid.to_string())
```

```output
        sum  count
Region            
East    120      2
North   130      4
South    30      2
Product  Book  Pen
Region            
East      100   20
North      60   70
South      20   10
```

The first table matches the spilled `SUMIFS` and `COUNTIFS` columns, sorted by region. The second is the two-way grid: East sells 100 in books and 20 in pens, North 60 in books and 70 in pens, and South 20 and 10. `groupby` produces the same grid in one call, where Excel needs one `SUMIFS` per cell, or a spill that expands over two arrays. A `#SPILL!` error in Excel means a non-empty cell blocks the spill range.

### Example 5: FILTER, and named criteria

```excel
=FILTER(Sales[[Region]:[Amount]], Sales[Amount]>=40, "none")
=SUMIFS(Sales[Amount], Sales[Region], RegionPick, Sales[Qty], ">="&MinQty)
```

`RegionPick` and `MinQty` are named input cells holding `North` and `2`. Changing either cell updates the formula result without editing it.

```python run
import pandas as pd

sales = pd.DataFrame({
    "Region": ["North", "South", "North", "East", "North", "South", "East", "North"],
    "Qty": [3, 1, 2, 5, 4, 1, 2, 1],
    "Amount": [30, 10, 40, 100, 40, 20, 20, 20],
})
print(sales[sales["Amount"] >= 40].to_string(index=False))

def report(region_pick, min_qty):
    m = (sales["Region"].str.lower() == region_pick.lower()) & (sales["Qty"] >= min_qty)
    return sales.loc[m, "Amount"].sum()

print(report("North", 2), report("north", 3), report("West", 1))
```

```output
Region  Qty  Amount
 North    2      40
  East    5     100
 North    4      40
110 70 0
```

`FILTER` returns the three rows with an amount of at least 40, like a boolean row filter. The function `report` plays the part of the two input cells: its arguments are the named criteria. North with quantity of at least 2 gives 30 + 40 + 40 = 110, quantity of at least 3 gives 30 + 40 = 70, and an unknown region gives 0, just as `SUMIFS` returns 0 for no match.

## Real-world applications

- **Monthly KPI tables.** One `SUMIFS` per metric, with the month start and end in input cells, produces revenue, order count and average order value for each period (Example 3).
- **Check totals.** Compare `SUM(Sales[Amount])` with the sum of the spilled regional totals, to prove that nothing was lost in a summary (Example 4).
- **Interactive reports.** A validation list for `RegionPick` and a number for `MinQty` turn a sheet into a small tool where a manager changes a cell and sees new totals (Example 5).
- **Exception lists.** `FILTER` lists the orders above a threshold or without a price, which an analyst can send back for correction (Example 5).

## Daily review

### Key takeaways

- `SUMIFS` and `AVERAGEIFS` take the value range first; `COUNTIFS` takes only criteria pairs. All conditions are AND, and all ranges must have the same size.
- Operators go inside a string and join to cell references with `&`: `">="&F1`.
- Excel matching ignores case and supports `*` and `?`; pandas comparisons are exact.
- `AVERAGEIFS` with no matching rows returns `#DIV/0!`; `SUMIFS` and `COUNTIFS` return 0.
- Named input cells and dynamic arrays (`UNIQUE`, `FILTER`, `SORT`, the `#` operator) make reports easier to change.

### Common mistakes

- Putting `sum_range` last, as in `SUMIF`, and getting a wrong total or `#VALUE!`.
- Ranges of different heights, such as `Sales[Amount]` with `D2:D50`, giving `#VALUE!`.
- Writing `">=F1"` instead of `">="&F1`, so the rule compares with the text "F1" and counts nothing.
- Expecting `"<>North"` to exclude blank rows, when blanks are included.
- Forgetting that `AVERAGEIFS` can return `#DIV/0!` when a filter matches no rows, which breaks a report that sums those cells.
- Typing a dynamic array formula in a cell with data below it, giving `#SPILL!`, or using it in Excel 2019 where it is not supported.

### Revision notes

- `=SUMIFS(sum, r1, c1, r2, c2)`, `=COUNTIFS(r1, c1)`, `=AVERAGEIFS(avg, r1, c1)`.
- `">=100"`, `"<>"&""`, `">="&F1`, `"N*"`, `"~*"`.
- `=UNIQUE(range)`, `=FILTER(range, cond)`, `=SORT(range)`, `F2#`.
- pandas: `df.loc[mask, col].sum()`, `mask.sum()`, `groupby(...).agg(...)`.
