## Objectives

- Plan a monthly sales workbook with separate sheets for raw data, lookups, calculations, pivots and the delivered report.
- Clean a raw export with a recorded list of Power Query steps and prove the result with a pandas replica.
- Add price, cost and margin with lookups and calculated columns, and list the rows that cannot be priced.
- Build the summary tables behind a PivotTable and charts, and reconcile every total back to the raw data.
- Deliver the report with KPI cells, charts and a short note on checks and assumptions.

## Understand

### The project

Today you build one small, complete result: a monthly sales workbook that a manager can open, read in a minute and trust. The input is a raw export of one month of orders, which is untidy in the usual ways: inconsistent region names, a product written in two cases, a quantity that is not a number, a repeated line and a product that is not in the price list. The output is a workbook with five sheets and a short list of checks that prove the numbers add up. Every Excel step you take today appears in the lesson as a pandas replica, so each number in the report can be verified in the browser even though Excel itself cannot run here.

### The five sheets

Plan the layout before you click anything, because a good layout is what makes the workbook easy to refresh next month.

- **Raw** holds the export exactly as received. It is never edited. In Excel, Power Query reads it (Day 98) and the original stays untouched.
- **Lookups** holds two small Tables: `Products` with the price and the unit cost, and `Regions` with the region manager. Each key is unique (Day 94) and typed correctly.
- **Orders** is the Power Query output: a clean Table with one row per order, a real date, a numeric quantity and the columns added by the merge: price, cost, amount and margin. This is the single table that everything else uses.
- **Pivots** holds a PivotTable for region by week or month and one for product ranking (Day 96). Pivots read the Orders Table, so a refresh updates them.
- **Report** is the sheet that is delivered: KPI cells, two charts (Day 97), a table of exceptions and a notes block. It contains no raw data.

### The build order

Work from the data towards the report. First clean: import, remove the title rows, set types, trim and standardise text, remove errors and duplicates. Second enrich: merge the product lookup with a Left Outer join (Day 99), expand price and cost, and add `Amount = Qty * Price` and `Margin = Amount - Qty * Cost` as custom columns. Third, keep a record of what could not be enriched: a Left Anti merge, or a filter on a null price, gives the exceptions. Fourth, summarise: build the PivotTables and the KPI formulas. Fifth, reconcile: compare totals at every stage. The cleaned quantity total must equal the raw quantity total minus the removed rows, the pivot grand total must equal the `Amount` total of the Orders Table, and the sum of the regional totals must equal the grand total. A report whose totals do not reconcile is not finished, however good the charts look.

### Decisions to write down

A project has choices that a reader cannot see. Decide and note them on the Report sheet: what happened to the row with a text quantity (here it is removed and counted as an exception, not guessed), which of the duplicate rows is kept, how unpriced items are shown (excluded from revenue and listed separately, not valued at zero), and what the margin definition is. These notes are the difference between a number and an explained number. A manager who asks "why is revenue lower than finance's figure?" can then read the answer.

### Using pandas as the test bench

Excel cannot be run in the browser, but its logic can. The pandas pipeline in the examples is the specification of what the workbook must produce. When you build the workbook, compare its cells with the numbers printed by the pipeline. If a PivotTable total disagrees, the replica tells you which step to look at: a type problem, a missed duplicate or a key that did not match. The same pipeline can also check next month's workbook after a refresh.

## Syntax and key functions

The build checklist, with the tool for each step:

```text
1. Raw sheet: paste the export; do not edit.
2. Data > Get Data > From Table/Range (or From Text/CSV) > Transform Data.
3. Remove Top Rows, Use First Row as Headers, Change Type (Date, whole number, text).
4. Trim and Capitalize Each Word on Region and Product; Remove Errors; Remove Duplicates.
5. Merge Queries: Orders with Products on Product, Left Outer, expand Price and Cost.
6. Add Column > Custom Column: Amount = [Qty] * [Price]; Margin = [Amount] - [Qty] * [Cost].
7. Close & Load to a Table named Orders.
8. Insert > PivotTable from Orders: Region in Rows, Date grouped, Amount in Values.
9. Report sheet: KPI cells, two charts, exceptions list, notes.
10. Data > Refresh All; check the reconciliation cells.
```

KPI and check formulas on the Report sheet:

```excel
=SUM(Orders[Amount])
=COUNTA(Orders[OrderID])
=IFERROR(SUM(Orders[Margin])/SUM(Orders[Amount]), 0)
=COUNTBLANK(Orders[Price])
=SUM(Orders[Amount]) - GETPIVOTDATA("Amount", Pivots!$A$3)
```

The last line is a check: it must show 0. `COUNTBLANK` counts the unpriced rows if the merge left them empty.

| Piece | Excel tool | pandas replica |
|---|---|---|
| Clean and type | Power Query | `read_csv`, `to_numeric`, `str.strip().str.title()`, `drop_duplicates` |
| Lookup | Merge Queries, Left Outer | `merge(..., how="left")` |
| Calculated columns | Custom Column | column arithmetic |
| Exceptions | Left Anti or null filter | boolean mask |
| Summary | PivotTable | `pivot_table`, `groupby` |
| KPIs and checks | `SUM`, `COUNTA`, `IFERROR` | `sum`, `len`, boolean tests |

## Learn by example

### Example 1: Clean the raw export

The raw export (one title line, then a header). The pipeline is the Power Query step list in the comments.

```python run
import io
import pandas as pd

raw_text = """March export
OrderID,Date,Region,Product,Qty
1001,2025-03-02, north ,pen,10
1002,2025-03-05,South,Book,3
1003,2025-03-09,NORTH,Pen,x
1004,2025-03-14,East,Notebook,5
1004,2025-03-14,East,Notebook,5
1005,2025-03-20,South,Pen,8
1006,2025-03-27,North,Book,2
1007,2025-03-30,East,Marker,4
"""
df = pd.read_csv(io.StringIO(raw_text), skiprows=1)                  # Remove Top Rows, Promoted Headers
print(len(df))
df["Date"] = pd.to_datetime(df["Date"])                              # Changed Type: date
df["Qty"] = pd.to_numeric(df["Qty"], errors="coerce")                # Changed Type: number
df["Region"] = df["Region"].str.strip().str.title()                  # Trim, Capitalize Each Word
df["Product"] = df["Product"].str.strip().str.title()
errors = df[df["Qty"].isna()]
print(errors["OrderID"].tolist())
clean = df.dropna(subset=["Qty"]).drop_duplicates().reset_index(drop=True)   # Remove Errors, Remove Duplicates
clean["Qty"] = clean["Qty"].astype(int)
print(len(clean), clean["Qty"].sum())
print(clean.to_string(index=False))
```

```output
8
[1003]
6 32
 OrderID       Date Region  Product  Qty
    1001 2025-03-02  North      Pen   10
    1002 2025-03-05  South     Book    3
    1004 2025-03-14   East Notebook    5
    1005 2025-03-20  South      Pen    8
    1006 2025-03-27  North     Book    2
    1007 2025-03-30   East   Marker    4
```

The raw file has 8 data rows. One row (order 1003) has a text quantity and is removed as an error; one repeated row (1004) is removed as a duplicate. 6 rows remain, with a total quantity of 32. The two removed rows are reported on the Report sheet, not forgotten.

### Example 2: Lookups, calculated columns and exceptions

The Products Table holds price and cost. `Marker` is not in it.

```python run
import pandas as pd

clean = pd.DataFrame({
    "OrderID": [1001, 1002, 1004, 1005, 1006, 1007],
    "Region": ["North", "South", "East", "South", "North", "East"],
    "Product": ["Pen", "Book", "Notebook", "Pen", "Book", "Marker"],
    "Qty": [10, 3, 5, 8, 2, 4],
})
products = pd.DataFrame({"Product": ["Pen", "Book", "Notebook"], "Price": [2.5, 12.0, 4.0], "Cost": [1.5, 8.0, 2.5]})
orders = clean.merge(products, on="Product", how="left")             # Merge Queries, Left Outer
orders["Amount"] = orders["Qty"] * orders["Price"]                   # Custom Column
orders["Margin"] = orders["Amount"] - orders["Qty"] * orders["Cost"]
print(orders.to_string(index=False))
exceptions = orders[orders["Price"].isna()]
print(exceptions["OrderID"].tolist(), int(exceptions["Qty"].sum()))
print(orders["Amount"].sum(), orders["Margin"].sum())
```

```output
 OrderID Region  Product  Qty  Price  Cost  Amount  Margin
    1001  North      Pen   10    2.5   1.5    25.0    10.0
    1002  South     Book    3   12.0   8.0    36.0    12.0
    1004   East Notebook    5    4.0   2.5    20.0     7.5
    1005  South      Pen    8    2.5   1.5    20.0     8.0
    1006  North     Book    2   12.0   8.0    24.0     8.0
    1007   East   Marker    4    NaN   NaN     NaN     NaN
[1007] 4
125.0 45.5
```

Order 1007 (Marker) has no price, so its `Amount` and `Margin` are missing (`NaN` here, null in Excel). It is listed as an exception with quantity 4, and the totals leave it out: revenue is 125.0 and margin 45.5. The sum ignores missing values, as Excel's `SUM` ignores empty cells, so the exception is explicit instead of being counted as zero.

### Example 3: Summaries and reconciliation

The PivotTable has Region in Rows and Product in Columns. The KPI cells and checks follow.

```python run
import pandas as pd

orders = pd.DataFrame({
    "Region": ["North", "South", "East", "South", "North"],
    "Product": ["Pen", "Book", "Notebook", "Pen", "Book"],
    "Qty": [10, 3, 5, 8, 2],
    "Amount": [25.0, 36.0, 20.0, 20.0, 24.0],
    "Margin": [10.0, 12.0, 7.5, 8.0, 8.0],
})
pt = orders.pivot_table(index="Region", columns="Product", values="Amount", aggfunc="sum", margins=True, margins_name="Total", fill_value=0)
print(pt.to_string())
revenue = orders["Amount"].sum()
print(revenue, len(orders), round(orders["Margin"].sum() / revenue, 3))
by_region = orders.groupby("Region")["Amount"].sum()
print(by_region.sum() == revenue, pt.loc["Total", "Total"] == revenue)
rank = orders.groupby("Product")["Amount"].sum().sort_values(ascending=False)
print(rank.to_dict())
```

```output
Product  Book  Notebook   Pen  Total
Region                              
East      0.0      20.0   0.0   20.0
North    24.0       0.0  25.0   49.0
South    36.0       0.0  20.0   56.0
Total    60.0      20.0  45.0  125.0
125.0 5 0.364
True True
{'Book': 60.0, 'Pen': 45.0, 'Notebook': 20.0}
```

The pivot grand total of 125.0 equals the sum of the Amount column, the sum of the regional totals equals revenue (both checks print `True`), and the margin rate is 0.364. The product ranking (Book 60.0, Pen 45.0, Notebook 20.0) is what the sorted bar chart shows. These are the numbers the KPI cells, the PivotTable and the charts must match in Excel.

### Example 4: Write the workbook with formulas and a chart

`openpyxl` can create a workbook with a Table of data, a KPI formula and a bar chart. It cannot calculate formulas or render the chart: the file stores the formula text and the chart definition, and Excel computes and draws them when the file is opened. This example runs on your computer, not in the browser.

```python local
import os, tempfile
from openpyxl import Workbook, load_workbook
from openpyxl.chart import BarChart, Reference

wb = Workbook()
ws = wb.active
ws.title = "Report"
ws.append(["Region", "Amount"])
for row in [("East", 20.0), ("North", 49.0), ("South", 56.0)]:
    ws.append(row)
ws["D1"] = "Revenue"
ws["E1"] = "=SUM(B2:B4)"
chart = BarChart()
chart.title = "Revenue by region"
chart.add_data(Reference(ws, min_col=2, min_row=1, max_row=4), titles_from_data=True)
chart.set_categories(Reference(ws, min_col=1, min_row=2, max_row=4))
ws.add_chart(chart, "G2")
path = os.path.join(tempfile.mkdtemp(), "report.xlsx")
wb.save(path)

back = load_workbook(path)
sheet = back["Report"]
print(sheet["E1"].value)
print(load_workbook(path, data_only=True)["Report"]["E1"].value)
print(len(sheet._charts))
```

```output
=SUM(B2:B4)
None
1
```

The formula is stored as the text `=SUM(B2:B4)`, and its cached value is `None` until Excel opens and saves the file, which would show 125.0. The file contains one chart. In practice you build the real workbook in Excel and use `openpyxl` only to generate repeatable test files or to check what a workbook contains.

## Real-world applications

- **Monthly sales pack.** The same workbook structure is reused every month: paste the new export on Raw, Refresh All, check the reconciliation cells and send the Report sheet (all examples).
- **Exception handling.** The list of unpriced products and removed rows goes back to the data owner, which fixes the problem at the source instead of burying it in the totals (Examples 1 and 2).
- **Testing a workbook.** A pandas replica run on the same raw data confirms the Excel totals before the report goes out, and again after a formula change (Example 3).
- **Handover.** Notes on assumptions and a visible check cell let a colleague take over the report without reverse engineering it.

## Daily review

### Key takeaways

- Separate Raw, Lookups, Orders, Pivots and Report; never edit Raw.
- Clean, enrich, record exceptions, summarise, reconcile, in that order.
- A Left Outer merge with a clear exception list is better than a missing price counted as zero.
- Every total on the Report sheet must reconcile to the cleaned data and back to the raw row counts.
- Write the decisions and assumptions next to the numbers.

### Common mistakes

- Cleaning in the worksheet by hand, so next month's export cannot be processed the same way.
- Treating unpriced rows as zero revenue without a note.
- Building pivots on a plain range, so new rows are missed after a refresh.
- Putting charts and KPIs that read the Raw sheet directly, so the report shows uncleaned numbers.
- Skipping the reconciliation, and noticing a gap only when finance asks.
- Hiding the removed rows: a manager cannot trust a count that differs from the export without a reason.

### Revision notes

- Sheets: Raw, Lookups, Orders, Pivots, Report.
- Steps: Power Query clean, Merge, Custom Columns, load as Table, PivotTable, charts, KPIs, Refresh All.
- Checks: raw rows minus removed rows equals cleaned rows; pivot total equals `SUM(Orders[Amount])`.
- pandas replicas are the test bench for the workbook.
