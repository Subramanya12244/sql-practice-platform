## Objectives

- Build line and bar charts with Matplotlib's object-oriented interface (`fig, ax = plt.subplots()`).
- Draw a monitoring chart with a threshold line, labelled axes and a legend, from pipeline run history.
- Save a figure to a file with a chosen resolution and close it, and verify the file.
- Test a chart through the data behind it and through its properties, not by eye.

## Understand

### Why pipelines need charts

A pipeline that runs every night produces numbers: rows read, rows loaded, rows rejected, run time. A table of last month's runs hides the shape of the story: a slow rise in rejections, one run that read half the usual rows, a sudden step. A small chart shows it at a glance, which is why monitoring pages and weekly reports are mostly charts of run metrics. Day 113 charted order insights; today's charts are about the pipeline itself. The data comes from a **run history**: one record per run with `run`, `read`, `loaded` and `rejected`, where `read = loaded + rejected` as Day 95's reconciliation requires.

### Figure, axes and the object-oriented interface

Matplotlib draws on a **figure** (the whole canvas) that holds one or more **axes** (a single chart with its x and y axis). The reliable way to use it in programs is the object-oriented interface: `fig, ax = plt.subplots()` creates both, and every later call is a method on `ax`: `ax.plot(x, y)` for a line, `ax.bar(x, heights)` for bars, `ax.set_title(...)`, `ax.set_xlabel(...)`, `ax.set_ylabel(...)`. The older `plt.plot(...)` style draws on whichever axes is "current", which is convenient in a notebook and a source of mixed-up charts in a pipeline that draws several figures. Always call `matplotlib.use("Agg")` before importing `pyplot` in a job: the Agg **backend** renders to files and needs no window or display, which is what a server has.

### Monitoring charts

A **monitoring chart** answers one question about pipeline health, so it has one clear mark and a reference. For run history, a bar chart per run showing loaded rows with the rejected rows stacked on top (`bottom=loaded`) shows volume and quality together. A **threshold line** (`ax.axhline(y, linestyle="--")`) marks the limit that matters, for example the maximum acceptable rejected rows, so a breach is visible without reading numbers. Add a legend (`label=` on each artist and `ax.legend()`), axis labels with units, and a title that states what the chart is and its period. Colour carries meaning, so use one colour for loaded and a contrasting one for rejected, and keep the same choices in every chart of the report.

### Saving figures

`fig.savefig("name.png", dpi=100)` writes the figure to a file; the format follows the extension (`.png`, `.svg`, `.pdf`). Pipelines save charts for emails and reports instead of showing them. Two habits matter: call `plt.close(fig)` after saving, because Matplotlib keeps every figure alive until closed and a loop that draws 500 charts without closing them uses a growing amount of memory; and call `fig.tight_layout()` before saving so labels are not clipped. Write to a path from configuration, not a hard-coded one, and keep file names deterministic (`loads_2025-03.png`) so a rerun overwrites the old file, which is an idempotent write.

### Testing a chart without looking at it

A chart is an image, but the objects behind it are ordinary Python values. After drawing, `ax.get_title()`, `ax.get_xlabel()` and `ax.get_ylabel()` return the strings, `len(ax.patches)` counts the bars, `[p.get_height() for p in ax.patches]` returns the bar heights, and `ax.lines[0].get_ydata()` returns the plotted values. Better still, put the calculation in a plain function that returns the data (`rejection_rates(history)`) and test it in the browser or in CI without Matplotlib at all. The drawing function is then a thin layer: it takes the prepared data and draws it. A common misconception is that a chart that "looks fine" is correct: a wrong filter or a mis-sorted axis looks perfectly fine. Test the numbers.

### The x axis and ordering

A run history is ordered by time, and the chart must be too. If the rows come from a query without `ORDER BY`, the line may zigzag between runs in storage order and look like instability that does not exist. Sort by the run number or timestamp before plotting, and plot dates as dates or as equally spaced run numbers, not as text sorted alphabetically (`"10"` would come before `"2"`). The symptom of getting it wrong is a trend that disagrees with the table; the fix is one `ORDER BY` in the query or one `sorted` in the data function.

### Choosing what to chart

Chart what a person acts on: run volume over time, rejection rate against a limit, freshness (hours since last load). Avoid charts of values that never change, and do not chart ten metrics in one panel. Use one figure with a few small panels (`plt.subplots(2, 1, sharex=True)`) when metrics share an x axis but have different units.

## Syntax and key functions

```python
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt

fig, ax = plt.subplots()
ax.bar(runs, loaded, label="loaded")
ax.bar(runs, rejected, bottom=loaded, label="rejected")
ax.axhline(limit, linestyle="--", label="limit")
ax.set_title("Rows per run"); ax.set_xlabel("Run"); ax.set_ylabel("Rows")
ax.legend()
fig.tight_layout()
fig.savefig("runs.png", dpi=100)
plt.close(fig)
```

| Item | What it does or returns |
|---|---|
| `plt.subplots(nrows, ncols, sharex=)` | Returns a figure and one axes (or an array of axes). |
| `ax.plot(x, y)` / `ax.bar(x, h, bottom=)` | Draw a line or bars; return the artists. |
| `ax.axhline(y)` | A horizontal reference line. |
| `ax.legend()` | Draws the legend from the `label=` of each artist. |
| `fig.savefig(path, dpi=)` | Writes the figure to a file; format from the extension. |
| `plt.close(fig)` | Releases the figure's memory. |
| `ax.patches`, `ax.lines` | The bars and lines drawn, for tests. |

## Learn by example

### Example 1: The data behind the chart

A plain function turns the run history into the numbers a chart needs: the rejection rate per run and the runs above a limit. It needs no Matplotlib, so it runs in the browser and is easy to test.

```python run
def run_history():
    rows = []
    for run in range(1, 11):
        read = 100 + (run * 7) % 23
        rejected = (run * 3) % 8 + (6 if run == 7 else 0)
        rows.append({"run": run, "read": read, "rejected": rejected, "loaded": read - rejected})
    return rows

def rejection_rates(history):
    return [round(r["rejected"] / r["read"], 3) for r in history]

history = run_history()
rates = rejection_rates(history)
print(rates)
limit = 0.08
print("runs over the limit:", [r["run"] for r, rate in zip(history, rates) if rate > limit])
print("reconciles:", all(r["read"] == r["loaded"] + r["rejected"] for r in history))
```

```output
[0.028, 0.053, 0.008, 0.038, 0.062, 0.017, 0.107, 0.0, 0.026, 0.059]
runs over the limit: [7]
reconciles: True
```
### Example 2: A line chart of rows read

This example needs Matplotlib, so it is a `python local` example. A line chart of rows read per run with labelled axes; the printed properties are what a test would assert.

```python local
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt
def run_history():
    rows = []
    for run in range(1, 11):
        read = 100 + (run * 7) % 23
        rejected = (run * 3) % 8 + (6 if run == 7 else 0)
        rows.append({"run": run, "read": read, "rejected": rejected, "loaded": read - rejected})
    return rows

history = run_history()
fig, ax = plt.subplots()
ax.plot([r["run"] for r in history], [r["read"] for r in history], marker="o")
ax.set_title("Rows read per run")
ax.set_xlabel("Run")
ax.set_ylabel("Rows")
print(ax.get_title(), "|", ax.get_xlabel(), "|", ax.get_ylabel())
line = ax.lines[0]
print(len(line.get_ydata()), "points, first", int(line.get_ydata()[0]), "last", int(line.get_ydata()[-1]))
plt.close(fig)
```

```output
Rows read per run | Run | Rows
10 points, first 107 last 101
```
### Example 3: A monitoring chart with a threshold

Loaded and rejected rows are stacked per run and a dashed line marks the rejection limit. The legend labels come from the `label=` arguments, and the bar count and heights are printed. Twenty patches are two series of ten bars.

```python local
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt
def run_history():
    rows = []
    for run in range(1, 11):
        read = 100 + (run * 7) % 23
        rejected = (run * 3) % 8 + (6 if run == 7 else 0)
        rows.append({"run": run, "read": read, "rejected": rejected, "loaded": read - rejected})
    return rows

history = run_history()
runs = [r["run"] for r in history]
loaded = [r["loaded"] for r in history]
rejected = [r["rejected"] for r in history]
fig, ax = plt.subplots()
ax.bar(runs, loaded, label="loaded")
ax.bar(runs, rejected, bottom=loaded, label="rejected")
ax.axhline(110, linestyle="--", color="black", label="expected volume")
ax.set_title("Rows per run, loaded and rejected")
ax.set_xlabel("Run")
ax.set_ylabel("Rows")
ax.legend()
handles, labels = ax.get_legend_handles_labels()
print(labels)
print(len(ax.patches), "bars; first loaded bar", ax.patches[0].get_height(), "first rejected bar", ax.patches[10].get_height())
plt.close(fig)
```

```output
['expected volume', 'loaded', 'rejected']
20 bars; first loaded bar 104 first rejected bar 3
```
### Example 4: Two panels with a shared axis

Volume and rejection rate have different units, so each gets its own panel with a shared run axis. `subplots(2, 1, sharex=True)` returns an array of two axes.

```python local
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt
def run_history():
    rows = []
    for run in range(1, 11):
        read = 100 + (run * 7) % 23
        rejected = (run * 3) % 8 + (6 if run == 7 else 0)
        rows.append({"run": run, "read": read, "rejected": rejected, "loaded": read - rejected})
    return rows

history = run_history()
runs = [r["run"] for r in history]
fig, (top, bottom) = plt.subplots(2, 1, sharex=True)
top.plot(runs, [r["loaded"] for r in history], marker="o")
top.set_ylabel("Loaded rows")
bottom.bar(runs, [r["rejected"] / r["read"] for r in history])
bottom.set_ylabel("Rejection rate")
bottom.set_xlabel("Run")
top.set_title("Run health")
fig.tight_layout()
print(len(fig.axes), "panels;", top.get_ylabel(), "/", bottom.get_ylabel())
print(len(bottom.patches), "bars; tallest rate", round(max(p.get_height() for p in bottom.patches), 3))
plt.close(fig)
```

```output
2 panels; Loaded rows / Rejection rate
10 bars; tallest rate 0.107
```
### Example 5: Save the figure and check the file

The figure is saved into a temporary folder that is removed afterwards. The check reads the first eight bytes, which identify a PNG, and tests that the file is not empty, without printing anything that depends on the machine.

```python local
import os
import tempfile
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt
def run_history():
    rows = []
    for run in range(1, 11):
        read = 100 + (run * 7) % 23
        rejected = (run * 3) % 8 + (6 if run == 7 else 0)
        rows.append({"run": run, "read": read, "rejected": rejected, "loaded": read - rejected})
    return rows

history = run_history()
fig, ax = plt.subplots()
ax.plot([r["run"] for r in history], [r["loaded"] for r in history])
ax.set_title("Loaded rows per run")
fig.tight_layout()
with tempfile.TemporaryDirectory() as folder:
    path = os.path.join(folder, "loads_2025-03.png")
    fig.savefig(path, dpi=80)
    with open(path, "rb") as handle:
        header = handle.read(8)
    print("png header:", header == b"\x89PNG\r\n\x1a\n")
    print("not empty:", os.path.getsize(path) > 1000)
plt.close(fig)
print("figures still open:", len(plt.get_fignums()))
```

```output
png header: True
not empty: True
figures still open: 0
```
## Real-world applications

- **Pipeline health page.** The stacked bars and the dashed limit of Example 3 are the standard run-history panel: volume, rejects and the line that decides whether to page someone.
- **Weekly report images.** A scheduled job saves a PNG per chart (Example 5) with a dated, deterministic name, and attaches it to an email or a wiki page.
- **Automated chart tests.** Checking titles, labels, bar counts and the data function (Examples 1 to 3) in CI stops a refactor from silently dropping a series or renaming an axis.
- **Triage.** Two panels with a shared run axis (Example 4) let an engineer see whether a drop in loaded rows coincides with a spike in rejections.

## Daily review

### Key takeaways

- Use `fig, ax = plt.subplots()` and call methods on `ax`; set the `Agg` backend in jobs.
- A monitoring chart has one question, labelled axes, a legend and a threshold line.
- Save with `fig.savefig(path, dpi=)`, then `plt.close(fig)`.
- Compute chart data in plain functions you can test; check the drawn chart through its properties.
- Chart what someone acts on, not everything in the table.

### Common mistakes

- Mixing `plt.plot` calls and `ax` calls, so a line lands on the wrong chart. Use one style, the axes methods.
- Forgetting `plt.close(fig)` in a loop, which gives a warning after about 20 open figures and growing memory. Close each figure.
- Importing `pyplot` before selecting the backend on a server and getting a display error. Call `matplotlib.use("Agg")` first.
- Stacking bars without `bottom=`, so the second series draws over the first and hides it.
- Calling `ax.legend()` when no artist has a `label`, which draws an empty legend.

### Revision notes

- `matplotlib.use("Agg")`; `fig, ax = plt.subplots()`; `ax.bar(..., bottom=...)`; `ax.axhline(y)`.
- `ax.set_title`, `set_xlabel`, `set_ylabel`, `legend`, `tight_layout`, `savefig(dpi=)`, `close`.
- Test: `get_title()`, `len(ax.patches)`, `ax.lines[0].get_ydata()`.
- Data in a plain function, drawing in a thin function.
