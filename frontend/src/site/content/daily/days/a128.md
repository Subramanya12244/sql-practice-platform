## Objectives

- Explain why a model needs a separate, contiguous date table and what goes wrong with only the dates found in the fact table.
- Build a calendar table with year, quarter, month number and month name, in Power Query M or DAX, and validate it the way Power BI's `Mark as date table` does.
- Sort month names by month number and build a Year, Quarter, Month, Date hierarchy.
- Add fiscal year, fiscal quarter and fiscal month columns for a fiscal year that does not start in January, and check them.

## Understand

### Why a separate date table

The `Sales` table has an `order_date` column, so it seems you could group by that column directly. There are three problems. First, the sales table only has dates on which something was sold: in the sample model the 400 orders fall on 237 distinct days of 2025, so 128 days are missing. A chart by date, a running total, or a comparison with the same period last year needs every day to be present, including the days with zero sales; without a full list of dates, those calculations skip days or give wrong answers. Second, a date column alone gives you no year, quarter, month name or weekday to group and slice by. Third, in a model with several fact tables (sales, returns, budget), each with its own dates, you want one shared place to filter all of them by time. A **date table** (also called a calendar table) solves all three: it is a dimension with exactly one row per day, covering the whole period, with the descriptive columns, and each fact table relates to it (Day 127).

### What a date table contains

The minimum is a `date` column with every date from the first to the last, one row each. Around it come the columns analysts group by: `year`, `quarter`, `month_number`, `month_name`, and often `day_of_week`, `week` and a flag for weekends or holidays. The range should cover every date in every related fact table, and it is conventional to run from 1 January of the first year to 31 December of the last year, so that years are complete. If the calendar stops before the data does, the later rows of the fact table have no matching date and are grouped under blank, as on Day 127.

You can create the table three ways. In Power Query you generate a list of dates with `List.Dates(start, count, step)` and add columns. In DAX you create a calculated table with `CALENDAR(start, end)`, which returns a one-column table named `Date`, or `CALENDARAUTO()`, which scans the dates in the model and returns whole years. Or you import a calendar from a database. The pandas equivalent is `pd.date_range`.

### Marking it as the date table

Power BI's time-based calculations (comparing with last year, year to date and so on, which come on later days) need to know which table is the official calendar. You tell it with `Table tools > Mark as date table` and choose the date column. Power BI checks that the column is a date type, has unique values, contains no blanks and is contiguous, with no missing days. If you have a gap, a duplicate or a blank, the check fails, which is why the examples validate exactly those properties. Marking also tells Power BI to stop using its own automatic behaviour for that table. Power BI has an **auto date/time** feature that quietly creates a hidden date table for every date column in the model, which is convenient for a quick report but means that each date column gets its own hierarchy, and the model grows. Most analysts turn it off in the options and use one explicit calendar.

### Sorting month names

A month name column such as `March` sorts alphabetically in a visual: April, August, December, February, and so on, which is useless. The fix is **Sort by column**: select `month_name` and choose `Column tools > Sort by column > month_number`. The names are then ordered by their numbers. The same problem and fix apply to weekday names. This is a good example of why the calendar has both a name and a number: the name is for reading and the number is for ordering.

### Hierarchies

A **hierarchy** is an ordered set of columns that lets a visual drill down: Year, then Quarter, then Month, then Date. You create it in the Fields pane (right-click `year`, `Add to hierarchy`, then add the other columns in order) or in Model view. A chart with the hierarchy on its axis starts at years, and the drill-down buttons expand to quarters and months. The levels must nest correctly: each month belongs to one quarter and each quarter to one year, so totals reconcile at every level. Check that by summing at each level and comparing with the grand total.

### Fiscal calendars

A **fiscal year** is the twelve-month period a company uses for its accounts, and it often does not start in January. Many UK organisations start on 1 April; others use 1 July or 1 October. Conventions differ on naming: some call the year by the calendar year in which it starts, others by the year in which it ends. This lesson uses April start and names a fiscal year by the year in which it ends, so April 2025 to March 2026 is FY2026. The columns you add are the fiscal year, the fiscal month (April is 1, March is 12) and the fiscal quarter (months 1 to 3 are Q1). The fiscal month formula in DAX is `MOD(MONTH([Date]) - 4, 12) + 1`, and the same arithmetic in Python is `(month - 4) % 12 + 1`. The sample data covers only calendar 2025, so it falls in FY2025 (January to March) and FY2026 (April to December).

### Misconceptions and why it matters

One misconception is that a date table is unnecessary because the sales table has dates. It works until a calculation needs the missing days. A second is that any calendar will do: if it has gaps, duplicates or does not cover the data, marking it as a date table fails or numbers silently drop. In analyst work the calendar is the one dimension every model needs, and getting it right once serves every report on the model.

## Syntax and key functions

Power Query M for the calendar with the model's column names:

```
let
    Dates = List.Dates(#date(2025, 1, 1), 365, #duration(1, 0, 0, 0)),
    AsTable = Table.FromList(Dates, Splitter.SplitByNothing(), {"date"}, null, ExtraValues.Error),
    Typed = Table.TransformColumnTypes(AsTable, {{"date", type date}}),
    Year = Table.AddColumn(Typed, "year", each Date.Year([date]), Int64.Type),
    Quarter = Table.AddColumn(Year, "quarter", each Date.QuarterOfYear([date]), Int64.Type),
    MonthNumber = Table.AddColumn(Quarter, "month_number", each Date.Month([date]), Int64.Type),
    MonthName = Table.AddColumn(MonthNumber, "month_name", each Date.MonthName([date]), type text)
in
    MonthName
```

A DAX calculated table gives the same result (`CALENDAR` names its column `Date`; rename it to `date` in the model if you want to match the sample columns):

```
Calendar =
ADDCOLUMNS (
    CALENDAR ( DATE ( 2025, 1, 1 ), DATE ( 2025, 12, 31 ) ),
    "year", YEAR ( [Date] ),
    "quarter", QUARTER ( [Date] ),
    "month_number", MONTH ( [Date] ),
    "month_name", FORMAT ( [Date], "MMMM" )
)
```

Fiscal columns for a fiscal year starting on 1 April, named by the year in which it ends:

```
fiscal_year = YEAR ( [Date] ) + IF ( MONTH ( [Date] ) >= 4, 1, 0 )
fiscal_month = MOD ( MONTH ( [Date] ) - 4, 12 ) + 1
fiscal_quarter = INT ( ( [fiscal_month] - 1 ) / 3 ) + 1
```

Desktop steps:

```text
Table tools > Mark as date table > select the date column
Column tools > Sort by column: month_name sorted by month_number
Fields pane > right-click year > Add to hierarchy > add quarter, month_name, date
Model view: relate Calendar[date] to Sales[order_date], one-to-many, single direction
```

| Item | What it does | pandas equivalent |
|---|---|---|
| `CALENDAR(start, end)` / `List.Dates` | One row per day | `pd.date_range(start, end, freq="D")` |
| `CALENDARAUTO()` | Whole years covering the model's dates | min and max year of the data |
| Mark as date table | Declares the official calendar after validating it | `validate_date_table` below |
| Sort by column | Orders names by a number column | `sort_values("month_number")` |
| Hierarchy | Year, Quarter, Month, Date drill-down | `groupby` at each level |
| Fiscal columns | Fiscal year, quarter and month | `(month - 4) % 12 + 1` |

## Learn by example

### Example 1: Missing days and alphabetical months

The sales table has 237 distinct order days. A calendar from the first to the last day has every day, so zero-sales days are visible. Grouping revenue by month name sorts alphabetically; sorting by the month number restores calendar order, which is what `Sort by column` does in Power BI.

```python run
import numpy as np
import pandas as pd


def make_model():
    rng = np.random.default_rng(7)
    customers = pd.DataFrame({
        "customer_id": np.arange(1, 41),
        "customer_name": [f"Customer {i:02d}" for i in range(1, 41)],
        "country": rng.choice(["UK", "Germany", "France", "Spain"], size=40),
        "segment": rng.choice(["Consumer", "Corporate", "Small Business"], size=40, p=[0.5, 0.3, 0.2]),
    })
    names = ["Desk", "Chair", "Bookcase", "Laptop", "Monitor", "Phone", "Notebook", "Pen Set", "Stapler", "Printer", "Lamp", "Cabinet"]
    categories = ["Furniture", "Furniture", "Furniture", "Technology", "Technology", "Technology",
                  "Office Supplies", "Office Supplies", "Office Supplies", "Technology", "Furniture", "Furniture"]
    products = pd.DataFrame({
        "product_id": np.arange(1, 13),
        "product_name": names,
        "category": categories,
        "unit_cost": rng.integers(5, 120, size=12),
    })
    sales = pd.DataFrame({
        "order_id": np.arange(1001, 1401),
        "order_date": pd.Timestamp("2025-01-01") + pd.to_timedelta(rng.integers(0, 365, 400), unit="D"),
        "customer_id": rng.integers(1, 41, 400),
        "product_id": rng.integers(1, 13, 400),
        "quantity": rng.integers(1, 8, 400),
    })
    cost = products.set_index("product_id")["unit_cost"]
    sales["unit_price"] = (cost[sales["product_id"]].to_numpy() * (1.3 + 0.5 * rng.random(400))).round(2)
    sales = sales.sort_values(["order_date", "order_id"]).reset_index(drop=True)
    dates = pd.date_range("2025-01-01", "2025-12-31", freq="D")
    calendar = pd.DataFrame({
        "date": dates,
        "year": dates.year,
        "quarter": dates.quarter,
        "month_number": dates.month,
        "month_name": dates.strftime("%B"),
    })
    return sales, customers, products, calendar


def validate_date_table(cal, sales_dates):
    dates = cal["date"]
    return {
        "unique": bool(dates.is_unique),
        "no blanks": bool(dates.notna().all()),
        "contiguous": bool((dates.sort_values().diff().dropna() == pd.to_timedelta(1, unit="D")).all()),
        "covers sales": bool(sales_dates.min() >= dates.min() and sales_dates.max() <= dates.max()),
    }


sales, customers, products, calendar = make_model()
sales = sales.assign(revenue=sales["quantity"] * sales["unit_price"])
span = pd.date_range(sales["order_date"].min(), sales["order_date"].max(), freq="D")
print("distinct order days:", sales["order_date"].nunique(), "| days in the span:", len(span))
print("days with no sales:", len(span) - sales["order_date"].nunique())

by_name = sales.merge(calendar, left_on="order_date", right_on="date").groupby(["month_number", "month_name"])["revenue"].sum().round(0)
print("alphabetical:", sorted(by_name.index.get_level_values("month_name"))[:4])
print("by month number:", [name for number, name in by_name.index][:4])
```

```output
distinct order days: 237 | days in the span: 364
days with no sales: 127
alphabetical: ['April', 'August', 'December', 'February']
by month number: ['January', 'February', 'March', 'April']
```

### Example 2: Validate a date table

The function checks the four properties that Power BI needs: unique dates, no blanks, no gaps and coverage of the sales dates. The sample calendar passes. A copy with one day removed fails the contiguity check, and a copy that ends early fails the coverage check, the two ways that marking a date table goes wrong in practice.

### Example 3: Hierarchy levels and zero-sales days

Revenue is rolled up at each level of the hierarchy (year, quarter, month), starting from a left join of the calendar to the sales so that days without sales are kept as zero. The totals must agree at every level, and the number of zero-sales days per quarter is a number that only a complete calendar can give.

```python run

import pandas as pd


def make_model():

        "quarter": dates.quarter,
```

### Example 4: A fiscal calendar starting in April

The fiscal columns are added to the calendar with the arithmetic from the DAX formulas. January to March 2025 belong to FY2025 (fiscal quarter 4) and April to December belong to FY2026. Revenue by fiscal quarter must add up to the same total as by calendar month.

```python run
import numpy as np
import pandas as pd


def make_model():
    rng = np.random.default_rng(7)
    customers = pd.DataFrame({
        "customer_id": np.arange(1, 41),
        "customer_name": [f"Customer {i:02d}" for i in range(1, 41)],
        "country": rng.choice(["UK", "Germany", "France", "Spain"], size=40),

    categories = ["Furniture", "Furniture", "Furniture", "Technology", "Technology", "Technology",
                  "Office Supplies", "Office Supplies", "Office Supplies", "Technology", "Furniture", "Furniture"]
    products = pd.DataFrame({
        "product_id": np.arange(1, 13),
        "product_name": names,
        "category": categories,
        "unit_cost": rng.integers(5, 120, size=12),
    })
    sales = pd.DataFrame({

        "order_date": pd.Timestamp("2025-01-01") + pd.to_timedelta(rng.integers(0, 365, 400), unit="D"),
        "customer_id": rng.integers(1, 41, 400),
        "product_id": rng.integers(1, 13, 400),

        "date": dates,
        "year": dates.year,
        "quarter": dates.quarter,
        "month_number": dates.month,

    })
    return sales, customers, products, calendar

    return {
        "unique": bool(dates.is_unique),

cal = calendar.assign(

print(cal.drop_duplicates("month_number")[["month_name", "fiscal_year", "fiscal_month", "fiscal_quarter"]].head(5).to_string(index=False))

joined = sales.merge(cal, left_on="order_date", right_on="date")
by_fq = joined.groupby(["fiscal_year", "fiscal_quarter"])["revenue"].sum().round(0)
print({f"FY{y} Q{q}": float(v) for (y, q), v in by_fq.items()})
```

## Real-world applications

- **Year-over-year reporting.** Comparisons with the same period last year need a complete, marked date table; without it the report skips days (Example 1) or fails validation (Example 2).
- **Fiscal reporting.** A finance team reports by fiscal quarter, and the fiscal columns (Example 4) are written once in the calendar, so every report on the model uses the same definition.
- **Sparse data diagnostics.** A complete calendar shows how many days had no sales (Example 3), which matters for forecasting and staffing.
- **One shared time filter.** A single year slicer on the calendar filters sales, returns and budget together.

## Daily review

### Key takeaways

- A date table has one row per day, no gaps, no duplicates and no blanks, and covers every fact table's dates.
- Build it in Power Query (`List.Dates`) or DAX (`CALENDAR`), then mark it as the date table.
- Sort month names by month number, and drill down with a Year, Quarter, Month, Date hierarchy.
- Fiscal columns are arithmetic on the month: fiscal month is `(month - 4) % 12 + 1` for an April start.
- Turn off auto date/time when you have your own calendar.

### Common mistakes

- Using only the dates in the fact table. Symptom: charts skip days and running totals jump. Fix: a calendar with every day.
- A calendar that stops before the data does. Symptom: the latest rows have a blank date and totals are short or grouped as blank. Fix: extend the range to the full years.
- Month names sorted alphabetically. Symptom: April before January. Fix: Sort by column with `month_number`.
- Fiscal year naming that is not documented. Symptom: two reports disagree on what FY2026 means. Fix: write the convention in the model.

### Revision notes

- `pd.date_range`, `List.Dates`, `CALENDAR`, `CALENDARAUTO`.
- Validate: unique, no blanks, contiguous, covers the facts.
- Sort by column: name by number. Hierarchy: Year, Quarter, Month, Date.
- Fiscal: `fiscal_month = (month - 4) % 12 + 1`; `fiscal_year = year + (month >= 4)`.
