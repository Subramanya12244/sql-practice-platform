## Objectives

- Build an ETL pipeline as a DAG of four tasks (extract, transform, load, validate) and run it for several logical dates in a pure-Python model.
- Make the load idempotent and keep a watermark, so that reruns and backfills give the same table.
- Write unit tests for the transform functions and an import test for the DAG file.
- Generate documentation of the DAG from its dependency dictionary and write a run book.
- Translate the verified model into an Airflow TaskFlow DAG.

## Understand

This project day combines Days 157 to 161: DAGs and tasks, dependencies and XCom, retries and idempotence, and sensors and alerts. The pipeline is the small ETL from the earlier engineering days: daily order files arrive as CSV text, are cleaned, and are loaded into an `orders_clean` table. Airflow cannot run in this course, so the project is built twice. First as a pure-Python model that you can run and test here: tasks are functions, the DAG is a dictionary, XCom is a dictionary of task results, the database is `sqlite3` in memory and each run takes a logical date `ds`. Then the same functions are placed in an Airflow TaskFlow DAG that you can run in your own Airflow installation. Because the logic is the same, the numbers checked here are the numbers the real DAG produces.

The four steps are these. First, write and check the small pure functions: `clean_amount` turns text such as `$12.50` or `"1,200.00"` into whole cents (and `None` for text like `abc`), `parse_ts` normalises two timestamp formats, and `dedupe_latest` keeps the most recent row per order id. Second, run the DAG for three days and for a fourth day whose file is missing, and read the states and the watermark. Third, prove idempotence: run all three days again and confirm that the table is unchanged. Fourth, write the tests and the documentation: tests are small functions with assertions on the behaviour that matters (amounts, rejects, duplicates, idempotent rerun), and the documentation is generated from the DAG definition so that it cannot drift from it, plus a run book that says what to do for each failure state.

The project is complete when the model produces six clean orders from the three days, the rejected rows are counted and not lost, a rerun leaves the table identical, the missing file marks the later tasks `upstream_failed` and does not change the data, and every test passes.

```python
from datetime import datetime, timedelta
from airflow.decorators import dag, task  # in Airflow 3: from airflow.sdk import dag, task

@dag(
    dag_id="orders_etl",
    schedule="@daily",
    start_date=datetime(2025, 3, 1),
    catchup=False,
    max_active_runs=1,
    default_args={"retries": 2, "retry_delay": timedelta(minutes=5)},
    tags=["orders"],
)
def orders_etl():
    @task
    def extract(ds=None):
        return read_orders_file(ds)

    @task
    def transform(rows):
        return transform_rows(rows)

    @task
    def load(result, ds=None):
        return load_orders(result, ds)

    @task
    def validate(loaded):
        check_row_count(loaded)

    validate(load(transform(extract())))

orders_etl()
```

## Syntax and key functions

The project uses these pieces. The pure functions are the same in the model and the DAG.

| Piece | Role |
|---|---|
| `clean_amount(text)` | Text to whole cents, or `None` when the text is not a number. |
| `parse_ts(text)` | Normalise `YYYY-MM-DD HH:MM` and `YYYY-MM-DDTHH:MM:SSZ` to `YYYY-MM-DD HH:MM:SS`. |
| `dedupe_latest(rows)` | One row per `order_id`, the one with the latest `created_at`. |
| `INSERT OR REPLACE` | The idempotent upsert on the primary key (PostgreSQL: `ON CONFLICT DO UPDATE`). |
| `etl_state` | One-row table holding the watermark, the last loaded date. |
| `DagBag(...).import_errors` | Test that the DAG file imports without errors. |

```python
from airflow.models import DagBag

def test_dag_imports():
    bag = DagBag(dag_folder="dags", include_examples=False)
    assert bag.import_errors == {}
    assert "orders_etl" in bag.dags
```

## Learn by example

### Example 1: Step 1, the pure functions

Check the three transform helpers on the awkward inputs.

```python run
import csv
import io
import sqlite3
from datetime import date, timedelta

FILES = {
    "2025-03-01": "order_id,customer_id,amount,created_at,status\n1,10,$12.50,2025-03-01 09:15,paid\n2,11, 7.00 ,2025-03-01T10:30:00Z,paid\n3,12,,2025-03-01 11:00,failed\n2,11,7.50,2025-03-01 12:00,paid\n",
    "2025-03-02": "order_id,customer_id,amount,created_at,status\n4,10,\"1,200.00\",2025-03-02 08:00,paid\n5,13,abc,2025-03-02 09:00,paid\n6,14,30,2025-03-02T14:45:00Z,refunded\n",
    "2025-03-03": "order_id,customer_id,amount,created_at,status\n7,15,19.99,2025-03-03 10:10,paid\n8,10,5,2025-03-03 10:20,paid\n",
}
DEPS = {"extract": [], "transform": ["extract"], "load": ["transform"], "validate": ["load"]}

def clean_amount(text):
    s = text.strip().replace("$", "").replace(",", "")
    try:
        return round(float(s) * 100)
    except ValueError:
        return None

def parse_ts(text):
    s = text.strip().replace("T", " ").rstrip("Z")
    return s if len(s) == 19 else s + ":00"

def dedupe_latest(rows):
    best = {}
    for r in rows:
        if r["order_id"] not in best or r["created_at"] > best[r["order_id"]]["created_at"]:
            best[r["order_id"]] = r
    return [best[k] for k in sorted(best)]

def extract(ds):
    if ds not in FILES:
        raise FileNotFoundError(ds)
    return list(csv.DictReader(io.StringIO(FILES[ds])))

def transform(rows):
    good, rejected = [], []
    for r in rows:
        cents = clean_amount(r["amount"])
        if cents is None:
            rejected.append(r["order_id"])
            continue
        good.append({"order_id": int(r["order_id"]), "customer_id": int(r["customer_id"]), "amount_cents": cents,
                     "created_at": parse_ts(r["created_at"]), "status": r["status"]})
    return dedupe_latest(good), rejected

def load(db, ds, good):
    db.executemany("INSERT OR REPLACE INTO orders_clean VALUES (:order_id, :customer_id, :amount_cents, :created_at, :status)", good)
    db.execute("INSERT OR REPLACE INTO etl_state VALUES (1, ?)", (ds,))
    return len(good)

def make_db():
    db = sqlite3.connect(":memory:")
    db.execute("CREATE TABLE orders_clean (order_id INTEGER PRIMARY KEY, customer_id INTEGER, amount_cents INTEGER, created_at TEXT, status TEXT)")
    db.execute("CREATE TABLE etl_state (id INTEGER PRIMARY KEY, watermark TEXT)")
    return db

def topo_order(deps):
    remaining = {t: set(u) for t, u in deps.items()}
    order = []
    while remaining:
        t = sorted(x for x, u in remaining.items() if not u)[0]
        order.append(t)
        del remaining[t]
        for u in remaining.values():
            u.discard(t)
    return order

def run_dag(db, ds):
    xcom, states = {}, {}
    for t in topo_order(DEPS):
        if any(states[u] != "success" for u in DEPS[t]):
            states[t] = "upstream_failed"
            continue
        try:
            if t == "extract":
                xcom[t] = extract(ds)
            elif t == "transform":
                xcom[t] = transform(xcom["extract"])
            elif t == "load":
                xcom[t] = load(db, ds, xcom["transform"][0])
            else:
                total = db.execute("SELECT COUNT(*) FROM orders_clean").fetchone()[0]
                assert total >= xcom["load"], "fewer rows than loaded"
                xcom[t] = total
            states[t] = "success"
        except Exception as exc:
            states[t] = "failed"
            xcom[t] = repr(exc)
    return states, xcom

print([clean_amount(x) for x in ["$12.50", " 7.00 ", "1,200.00", "30", "abc", ""]])
print([parse_ts(x) for x in ["2025-03-01 09:15", "2025-03-01T10:30:00Z"]])
rows = [{"order_id": "2", "created_at": "2025-03-01 10:30:00"}, {"order_id": "2", "created_at": "2025-03-01 12:00:00"}, {"order_id": "1", "created_at": "2025-03-01 09:15:00"}]
print([(r["order_id"], r["created_at"][-8:]) for r in dedupe_latest(rows)])
```

```output
[1250, 700, 120000, 3000, None, None]
['2025-03-01 09:15:00', '2025-03-01 10:30:00']
[('1', '09:15:00'), ('2', '12:00:00')]
```

Amounts become cents: 1250, 700, 120000 and 3000, and the two unreadable texts become `None`, which the transform step will reject instead of loading a wrong value. Both timestamp formats become `YYYY-MM-DD HH:MM:SS`. Of the two rows for order 2 the later one (12:00:00) is kept, and the result is ordered by order id.

### Example 4: Step 4, tests and generated documentation

Write the tests as functions, run them with a tiny runner and generate a table of the DAG for the documentation.

## Real-world applications

- **Daily operational loads.** A DAG like this loads partner files into a warehouse table every day, with rejects counted and a watermark for monitoring.
- **Safe recovery.** After a bug fix, the failed days are cleared and rerun in any order, and the table converges to the right content (Example 3).
- **Release checks.** An import test and unit tests run in CI before a DAG file is deployed, so that a syntax error cannot stop the scheduler from loading it (Example 4).
- **Handover.** Documentation generated from the DAG definition and a run book let another engineer operate the pipeline.

## Daily review

### Key takeaways

- Keep transform logic in small pure functions that can be tested without Airflow.
- Reject unreadable rows and count them; do not load guesses.
- Idempotent loads (upsert on the key) make retries, reruns and backfills safe.
- A failed task blocks its downstream tasks and must not move the watermark.
- Test the functions, the idempotence and the DAG import; generate documentation from the definition.

### Common mistakes

- Putting transform logic inside the DAG file, so it can only be tested by running Airflow.
- Appending in the load task, so every rerun duplicates the day.
- Advancing the watermark before the load has succeeded.
- Dropping bad rows silently instead of keeping a count and a list.
- Writing documentation by hand and letting it drift from the DAG.

### Revision notes

- Four tasks: extract, transform, load, validate; XCom passes results.
- `clean_amount`, `parse_ts`, `dedupe_latest`; upsert on the primary key.
- Failed day: downstream `upstream_failed`, watermark unchanged.
- Tests: amounts, dedupe, idempotent rerun, blocked downstream, DAG imports.
