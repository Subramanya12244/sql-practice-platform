## Understand

### Why programs need files

Variables live only while a program runs. When it ends, everything in memory is gone. A **file** is a named block of data stored on disk that survives after the program ends, so files are how programs receive input (a downloaded export) and leave output (a report, a cleaned data set). A **text file** holds characters, such as `.txt`, `.csv`, `.json` or `.log`. This lesson covers text files; the next day adds the formats CSV and JSON on top of them.

Your program does not touch the disk directly. It asks the operating system to **open** the file, which returns a **file object** (also called a handle): a Python value that remembers the file and your current position in it. You read or write through that object, and then you must **close** it so that the operating system finishes writing and releases the file.

The browser version of Python used in DataForge has a small in-memory file system. Every example below first creates the file it needs in the working directory, so the examples behave the same in the browser and on your computer.

### open() and modes

`open(path, mode, encoding=...)` returns the file object. The **mode** says what you intend to do:

- `"r"` reads. This is the default. The file must exist, otherwise Python raises `FileNotFoundError`.
- `"w"` writes. It creates the file, and if the file already exists it is emptied immediately. This is the most common way to lose data by accident.
- `"a"` appends. It creates the file if needed and adds to the end without touching what is there.
- `"x"` creates a new file and raises `FileExistsError` if it already exists, which is a safe way to avoid overwriting.

Adding `"b"` (as in `"rb"`) opens the file as raw bytes rather than text. Binary mode is for images and archives and is not needed for text.

### The with statement

If you call `f = open(...)` you must remember `f.close()`, including when an error happens half way. Forgetting leaves data stuck in a buffer (a temporary memory area Python fills before writing to disk), so a file can look empty or short. The `with` statement solves this. A **context manager** is an object that does set-up when a `with` block starts and clean-up when it ends, even if the block fails. A file object is a context manager whose clean-up is `close()`:

```python
with open("notes.txt", "w", encoding="utf-8") as f:
    f.write("hello\n")
# the file is closed here
```

Use `with` every time. Day 27 returns to context managers and shows how to write your own.

### Reading: three ways

- `f.read()` returns the whole file as one string. Simple, but a 5 GB file becomes 5 GB of memory.
- `f.readlines()` returns a list of lines, each still ending in `"\n"`. It also loads everything.
- Looping `for line in f:` gives one line at a time and keeps only that line in memory. This is the right default for anything that could be large.

Every line except possibly the last ends with the newline character `"\n"`, so you usually call `line.rstrip("\n")` or `line.strip()` (Day 4). File objects also remember a position: once `read()` has reached the end, a second `read()` returns the empty string `""`, not the content again. Opening the file again starts at the beginning.

### Writing

`f.write(text)` writes a string and returns the number of characters written. It does not add a newline, so you must add `"\n"` yourself. Writing a number needs `str()` or an f-string. `f.writelines(list_of_strings)` writes each string as given, again without adding newlines. Printing is another way to write: `print(text, file=f)` adds the newline for you.

### Paths and pathlib

A **path** is the text that locates a file, such as `data/sales.csv`. A **relative** path starts from the **working directory** (the folder the program runs in), and an **absolute** path starts from the root of the disk. Different operating systems separate folders differently, so building paths with `+` and slashes breaks. The `pathlib` module models a path as an object: `Path("data") / "sales.csv"` joins parts with the `/` operator and uses the right separator. A `Path` has useful properties and methods: `.name`, `.stem` (name without extension), `.suffix` (the extension), `.parent`, `.exists()`, `.is_file()`, `.mkdir(parents=True, exist_ok=True)`, `.iterdir()`, `.glob("*.txt")`, `.unlink()` (delete) and the shortcuts `.read_text()` and `.write_text()`, which open, read or write, and close in one call.

### Encodings

Disks store bytes, not characters. An **encoding** is the rule that converts characters to bytes and back. **UTF-8** is the standard that can represent every character, and it is the sensible default for files you create. If you read a file with a different encoding from the one it was written in, you get either an error (`UnicodeDecodeError`) or garbled text such as `cafÃ©` instead of `café`. Python's default depends on the operating system, so always pass `encoding="utf-8"` explicitly. When a file comes from an old Windows export, try `encoding="cp1252"` or `"latin-1"`. The `newline` setting is a related detail: leave it at the default for text files, and pass `newline=""` only when the `csv` module asks for it (Day 20).

### Common misconception

Learners think `"w"` adds to a file. It replaces the file, even if you write nothing. Use `"a"` to add, and think twice before opening an existing file with `"w"`.

### Why it matters

Pipelines read raw exports and write cleaned output. Streaming large files line by line, closing files reliably and getting the encoding right are the difference between a job that works on a sample and one that survives real data.

## Syntax and key functions

Open with a context manager:

```python
with open(path, mode, encoding="utf-8") as f:
    ...
```

`path` is a string or `Path`, `mode` is `"r"`, `"w"`, `"a"` or `"x"`, and `f` is the file object that exists only inside the block.

Iterate lines and path operations:

```python
for line in f:
    line = line.rstrip("\n")

p = Path("out") / "report.txt"
p.parent.mkdir(parents=True, exist_ok=True)
p.write_text("text", encoding="utf-8")
```

| Call | Returns |
|---|---|
| `open(path, "r")` | A file object for reading. |
| `f.read()` | The remaining content as one string. |
| `f.readline()` | The next line, or `""` at the end. |
| `f.readlines()` | A list of all remaining lines. |
| `f.write(s)` | The number of characters written. |
| `f.writelines(seq)` | `None`; writes each string unchanged. |
| `Path(p) / "x"` | A new `Path`. |
| `p.exists()`, `p.is_file()` | `True` or `False`. |
| `p.name`, `p.stem`, `p.suffix` | Parts of the final path component, as strings. |
| `p.read_text()`, `p.write_text(s)` | The text; the number of characters written. |
| `p.glob("*.txt")` | An iterator of matching paths (sort it before printing). |
| `p.unlink()` | `None`; deletes the file. |

## Learn by example

### Example 1: Write, then read back

The first block writes three lines. The `"w"` mode creates the file, and each line needs its own `"\n"`. The second block reads the whole file as one string, and the `repr` call makes the newline characters visible.

```python run
with open("fruit.txt", "w", encoding="utf-8") as f:
    n = f.write("apple\n")
    f.write("banana\n")
    f.write("cherry\n")
print(n)

with open("fruit.txt", encoding="utf-8") as f:
    text = f.read()
print(repr(text))
print(len(text))
```

```output
6
'apple\nbanana\ncherry\n'
20
```

### Example 2: Three ways to read lines

The same file is read as a list of lines, then line by line in a loop, then with `readline()`. The loop strips the newline from each line. After a full `read()` the position is at the end, so a second `read()` returns an empty string.

```python run
with open("fruit.txt", "w", encoding="utf-8") as f:
    f.write("apple\nbanana\ncherry\n")

with open("fruit.txt", encoding="utf-8") as f:
    print(f.readlines())

with open("fruit.txt", encoding="utf-8") as f:
    for number, line in enumerate(f, start=1):
        print(number, line.rstrip("\n"))

with open("fruit.txt", encoding="utf-8") as f:
    print(repr(f.readline()))
    print(repr(f.read()))
    print(repr(f.read()))
```

```output
['apple\n', 'banana\n', 'cherry\n']
1 apple
2 banana
3 cherry
'apple\n'
'banana\ncherry\n'
''
```

### Example 3: "w" erases, "a" appends

Opening an existing file with `"w"` throws away its content. Opening it with `"a"` adds to the end. The mode `"x"` refuses to touch an existing file, which Python reports with `FileExistsError`.

```python run
with open("log.txt", "w", encoding="utf-8") as f:
    f.write("first run\n")
with open("log.txt", "a", encoding="utf-8") as f:
    f.write("second run\n")
with open("log.txt", encoding="utf-8") as f:
    print(f.read().splitlines())

with open("log.txt", "w", encoding="utf-8") as f:
    f.write("fresh start\n")
with open("log.txt", encoding="utf-8") as f:
    print(f.read().splitlines())

try:
    open("log.txt", "x")
except FileExistsError:
    print("x mode refuses to overwrite")
```

```output
['first run', 'second run']
['fresh start']
x mode refuses to overwrite
```

### Example 4: Processing a file line by line

A small log is created and then scanned in a streaming loop, so only one line is in memory at a time. Blank lines are skipped, and a dictionary counts each level. The counts are printed in sorted order so the output is stable.

```python run
lines = ["INFO start", "WARN slow query", "", "INFO loaded 40 rows", "ERROR disk full", "INFO done"]
with open("app.log", "w", encoding="utf-8") as f:
    f.write("\n".join(lines) + "\n")

counts = {}
with open("app.log", encoding="utf-8") as f:
    for line in f:
        line = line.strip()
        if not line:
            continue
        level = line.split()[0]
        counts[level] = counts.get(level, 0) + 1

for level in sorted(counts):
    print(level, counts[level])
```

```output
ERROR 1
INFO 3
WARN 1
```

### Example 5: pathlib

`Path` objects join with `/`, report their parts and work on files without an explicit `open`. The folder is created first with `mkdir`, and the glob result is sorted because the order in which a disk lists files is not guaranteed.

```python run
from pathlib import Path

folder = Path("reports") / "2026"
folder.mkdir(parents=True, exist_ok=True)
(folder / "jan.txt").write_text("100\n", encoding="utf-8")
(folder / "feb.txt").write_text("120\n", encoding="utf-8")

p = folder / "jan.txt"
print(p)
print(p.name, p.stem, p.suffix, p.parent)
print(p.exists(), (folder / "mar.txt").exists())
print(p.read_text(encoding="utf-8").strip())
print([x.name for x in sorted(folder.glob("*.txt"))])
p.unlink()
print([x.name for x in sorted(folder.iterdir())])
```

```output
reports/2026/jan.txt
jan.txt jan .txt reports/2026
True False
100
['feb.txt', 'jan.txt']
['feb.txt']
```

### Example 6: Encodings and a safe report writer

The text `café` becomes different bytes in different encodings. Reading UTF-8 bytes as Latin-1 produces garbled text, which is the typical sign of a wrong encoding. The last part builds a small report from a dictionary and writes it with an explicit encoding.

```python run
from pathlib import Path

word = "café"
print(len(word), len(word.encode("utf-8")), len(word.encode("latin-1")))
Path("w.txt").write_bytes(word.encode("utf-8"))
print(Path("w.txt").read_text(encoding="utf-8"))
print(Path("w.txt").read_text(encoding="latin-1"))

sales = {"Berlin": 1200, "Lisbon": 950, "Oslo": 780}
with open("report.txt", "w", encoding="utf-8") as f:
    f.write("City | Sales\n")
    for city, amount in sorted(sales.items()):
        f.write(f"{city} | {amount}\n")
    print("Total |", sum(sales.values()), file=f)
print(Path("report.txt").read_text(encoding="utf-8"), end="")
```

```output
4 5 4
café
cafÃ©
City | Sales
Berlin | 1200
Lisbon | 950
Oslo | 780
Total | 2930
```

## Real-world applications

- **Reading raw exports.** A nightly job receives a log or export of millions of lines. Looping over the file (Examples 2 and 4) keeps memory small, where `read()` would load the whole file.
- **Writing reports and cleaned data.** A pipeline writes its result to a file that another system picks up. Using `"w"` for a fresh output file and `"a"` for a running journal (Example 3) decides whether history is kept.
- **Organising folders of files.** Data teams keep one file per day or per region. `pathlib` with `glob` (Example 5) finds them all and builds output paths that work on any operating system.
- **Handling foreign text.** Customer names with accents or symbols break jobs that rely on the default encoding. Passing `encoding="utf-8"` explicitly, and recognising garbled text as in Example 6, saves hours of debugging.

## Daily review

### Key takeaways

- A file object is opened with `open()`, and a `with` block closes it for you, even after an error.
- `"r"` reads, `"w"` replaces, `"a"` appends and `"x"` refuses to overwrite.
- Loop over the file object to process one line at a time; `read()` and `readlines()` load everything.
- `write()` never adds a newline; lines end with `"\n"` which you strip when reading.
- `pathlib.Path` builds portable paths and offers `exists`, `glob`, `read_text`, `write_text` and `unlink`.
- Pass `encoding="utf-8"` explicitly.

### Common mistakes

- Opening an existing file with `"w"` and wiping it. The file becomes empty, with no error. Use `"a"`, or `"x"` to be safe.
- Forgetting the `"\n"` in `write()`, so the output is one long line such as `applebananacherry`.
- Not closing a file opened without `with`, so the data is missing when you read it back. Use `with`.
- Calling `read()` twice and getting `""` the second time, because the position is at the end. Open the file again or store the first result.
- Printing lines read from a file and getting blank lines between them, because each line still ends in `"\n"` and `print` adds another. Strip the line.
- Reading with the wrong encoding, which raises `UnicodeDecodeError` or shows text such as `cafÃ©`. Pass the right `encoding`.
- Building paths with `"data" + "\\" + name`, which fails on other systems. Use `Path("data") / name`.

### Revision notes

- `with open(path, "r", encoding="utf-8") as f:` is the standard form.
- Modes: `r` read, `w` replace, `a` append, `x` exclusive create, `b` bytes.
- `for line in f` is memory-friendly; `f.read()` is one string; `f.readlines()` is a list.
- `Path(a) / b`, `.name`, `.stem`, `.suffix`, `.exists()`, `.glob()`, `.read_text()`, `.write_text()`.
- Bytes in, bytes out: the encoding is the translation rule.
