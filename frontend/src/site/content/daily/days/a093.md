## Understand

### Text in a cell is a string

A cell that holds text is a **string**: an ordered row of characters, as on Day 4. Excel's text functions mirror the Python string tools you already know, with one important change: **positions start at 1, not 0**. The first character of `"DF-2024-0137"` is character 1. This single difference is behind most of the mistakes learners make when they move between Python slicing and Excel text formulas.

### Taking text apart: LEFT, RIGHT, MID, LEN, FIND

`LEFT(text, n)` returns the first `n` characters and `RIGHT(text, n)` the last `n`. `MID(text, start, n)` returns `n` characters beginning at position `start`, so `MID("DF-2024-0137", 4, 4)` is `2024`. `LEN(text)` is the number of characters, spaces included. `FIND(find_text, within_text)` returns the position where `find_text` first starts, or the error `#VALUE!` if it is absent. `FIND` is case-sensitive. Its sibling `SEARCH` ignores case and accepts the wildcards `?` and `*`. When parts have varying length, `FIND` supplies the cut position: the text before the first dash is `=LEFT(A2, FIND("-",A2)-1)`. The `-1` is needed because `FIND` gives the position of the dash itself, and you want the characters before it.

A text function always returns text. `=MID("DF-2024-0137",4,4)` returns the text `2024`, not the number 2024. It left-aligns in the cell, and adding it to another number only works because Excel quietly converts it in arithmetic (`=MID(...)+1` gives 2025). `VALUE(text)` converts explicitly, and `--MID(...)` (a double negative) is a common shortcut for the same.

### Cleaning text: TRIM, CLEAN, SUBSTITUTE and case

Real data carries invisible clutter. `TRIM(text)` removes spaces at the start and end and reduces runs of internal spaces to a single space. This is stronger than Python's `strip()`, which touches only the ends; the Python equivalent of `TRIM` is `" ".join(text.split())`. `CLEAN(text)` removes non-printing characters such as line feeds. A web page or a database export often contains a **non-breaking space**, character code 160, that looks like a space but that `TRIM` does not remove. Replace it first with `SUBSTITUTE(text, CHAR(160), " ")`. `SUBSTITUTE(text, old, new)` replaces every occurrence of `old` and is case-sensitive; add an instance number as a fourth argument to replace only that occurrence. `UPPER`, `LOWER` and `PROPER` change case, and `PROPER` capitalises the first letter of each word. A typical cleaning formula chains them: `=PROPER(TRIM(SUBSTITUTE(A2,CHAR(160)," ")))`. Read it from the inside out.

### Joining text: &, TEXTJOIN and TEXT

The `&` operator joins text: `=A2&" "&B2`. `TEXTJOIN(delimiter, ignore_empty, range1, range2, ...)` joins many cells with a separator between them, and with `ignore_empty` set to `TRUE` it skips blank cells, so you do not get `Ada,,Lovelace`. `TEXTJOIN` is available in Excel 2019 and Microsoft 365. `TEXT(value, format_text)` converts a number or date into text shaped by a format code, for example `TEXT(1234.5,"#,##0.00")` gives `1,234.50` and `TEXT(date,"yyyy-mm")` gives `2025-03`. The result is text, so it cannot be summed, and a month label made with `TEXT(date,"mmm")` sorts alphabetically, not by month, unless you keep the real date nearby. Format codes depend on the language of your Excel installation (some languages use different letters for year and day), which is one reason to prefer numeric `YEAR` and `MONTH` for calculations and use `TEXT` only for labels.

### Dates are numbers

Excel stores a date as a **serial number**: the count of days since a start point. In the default Windows system, serial 1 is 1 January 1900, and the date 2025-01-31 is 45688. A time of day is the fraction of a day, so noon is 0.5. A date format only decides how that number is shown. This is why subtracting two dates gives the number of days between them, and why a cell that shows `45688` simply has a General format instead of a date format. Excel has a historic quirk: it treats 1900 as a leap year, so serial 60 is a date (29 Feb 1900) that never existed. For dates from March 1900 onward you can convert with the Python start date 1899-12-30, as the examples do.

### Building and taking apart dates

`DATE(year, month, day)` builds a real date. `YEAR(date)`, `MONTH(date)` and `DAY(date)` take one apart. `DATE` rolls over out-of-range arguments: `DATE(2025,14,1)` is 1 February 2026 and `DATE(2025,3,0)` is the last day of February. `EDATE(date, months)` shifts by whole months, clamping to the end of a shorter month, so `EDATE("2025-01-31",1)` is 28 February 2025. `EOMONTH(date, months)` gives the last day of the month `months` away. `WEEKDAY(date)` returns 1 for Sunday to 7 for Saturday by default; `WEEKDAY(date,2)` returns 1 for Monday to 7 for Sunday. `TODAY()` returns today's date and recalculates each time the workbook opens, which makes results change from day to day. These are called **volatile** functions, and a report that must not move should hold a fixed date in a cell instead. Date text such as `"2025-03-07"` is often not a date at all: build the date with `=DATE(LEFT(A2,4), MID(A2,6,2), RIGHT(A2,2))`. `DATEVALUE` also works but depends on regional settings.

### Why it matters, and the misconception

Almost every messy spreadsheet is messy in its text and its dates. The misconception is that something that looks like a date or a number is one. Check by right-aligning: genuine dates and numbers align right and respond to a format change, and text values align left and do not.

## Syntax and key functions

```excel
=LEFT(text, n)
=RIGHT(text, n)
=MID(text, start, n)
=FIND(find_text, within_text)
=SUBSTITUTE(text, old, new)
=TEXTJOIN(delimiter, ignore_empty, range)
=TEXT(value, "format")
=DATE(year, month, day)
=EOMONTH(date, months)
```

`start` and `n` are counted from 1. `ignore_empty` is `TRUE` or `FALSE`. `format` is a format code in quotes.

| Function | Returns |
|---|---|
| `LEN(t)` | Number of characters. |
| `TRIM(t)` | Text without leading, trailing and repeated spaces. |
| `CLEAN(t)` | Text without non-printing characters. |
| `UPPER/LOWER/PROPER(t)` | Text in capitals, lower case or capitalised words. |
| `FIND(a, t)` / `SEARCH(a, t)` | Position of `a` in `t` (case-sensitive / not); `#VALUE!` if absent. |
| `VALUE(t)` | The number a text represents. |
| `YEAR/MONTH/DAY(d)` | Part of a date. |
| `EDATE(d, m)` / `EOMONTH(d, m)` | Same day / last day of the month, `m` months later. |
| `WEEKDAY(d, type)` | Day number; type 1 Sunday=1, type 2 Monday=1. |
| `TODAY()` | Today's date; recalculates (volatile). |

Common `TEXT` codes: `0.00` two decimals, `#,##0` thousands separator, `0%` percent, `yyyy-mm-dd` ISO date, `mmm yyyy` month and year, `dddd` weekday name.

## Learn by example

### Example 1: Taking a product code apart

A product code has the form `DF-2024-0137`.

```excel
=LEFT(A2, 2)                      gives DF
=MID(A2, 4, 4)                    gives 2024
=RIGHT(A2, 4)                     gives 0137
=LEN(A2)                          gives 12
=FIND("-", A2)                    gives 3
=LEFT(A2, FIND("-", A2)-1)        gives DF
=VALUE(MID(A2, 4, 4))             gives 2024 as a number
```

The Python replica needs the shift from position 4 to index 3.

```python run
code = "DF-2024-0137"
print(code[:2])
print(code[3:3 + 4])
print(code[-4:])
print(len(code))
print(code.find("-") + 1)
print(code[:code.find("-")])
print(int(code[3:7]) + 1)
```

```output
DF
2024
0137
12
3
DF
2025
```

`MID(A2,4,4)` is `code[3:7]`: start minus 1, then start minus 1 plus length. `FIND` returns 3 but Python's `find` returns 2, so add 1 to compare. Python's `find` returns -1 for a missing text, while Excel's `FIND` returns `#VALUE!`, which is a loud error you can catch with `IFERROR`.

### Example 2: Cleaning names

Cell A2 contains `"  aDA   LOVELACE"`, with extra spaces.

```excel
=TRIM(A2)                     gives aDA LOVELACE
=PROPER(TRIM(A2))             gives Ada Lovelace
=SUBSTITUTE(A2, " ", "")      gives aDALOVELACE
```

If the spaces were non-breaking (character 160, common when text is copied from a web page), `TRIM` leaves them, and you write `=TRIM(SUBSTITUTE(A2,CHAR(160)," "))`.

```python run
raw = "  aDA   LOVELACE"
print(repr(raw.strip()))
print(repr(" ".join(raw.split())))
print(" ".join(raw.split()).title())
print(raw.replace(" ", ""))

nbsp = "Ada  Lovelace"
print(repr(" ".join(nbsp.split())))
print(repr(nbsp.strip()))
print(repr(" ".join(nbsp.replace(" ", " ").split())))
```

```output
'aDA   LOVELACE'
'aDA LOVELACE'
Ada Lovelace
aDALOVELACE
'Ada Lovelace'
'Ada\xa0 Lovelace'
'Ada Lovelace'
```

Python's `strip()` leaves the doubled internal spaces, while `" ".join(text.split())` matches Excel's `TRIM`. A caution about the second block: Python's `split()` treats the non-breaking space as whitespace and removes it, whereas Excel's `TRIM` does not, so Python is more forgiving than Excel here. In Excel you must substitute `CHAR(160)` first.

### Example 3: TEXT and TEXTJOIN

```excel
=TEXT(1234.5, "#,##0.00")         gives 1,234.50
=TEXT(0.256, "0.0%")              gives 25.6%
=TEXT(DATE(2025,3,7), "yyyy-mm")  gives 2025-03
=TEXTJOIN(", ", TRUE, A2:A5)      joins the non-blank cells
```

If `A2:A5` holds `North`, an empty cell, `East` and `West`, the result with `TRUE` is `North, East, West`; with `FALSE` it is `North, , East, West`.

```python run
import datetime as dt

print(f"{1234.5:,.2f}")
print(f"{0.256:.1%}")
print(dt.date(2025, 3, 7).strftime("%Y-%m"))
cells = ["North", "", "East", "West"]
print(", ".join(c for c in cells if c))
print(", ".join(cells))
```

```output
1,234.50
25.6%
2025-03
North, East, West
North, , East, West
```

The format codes differ (`#,##0.00` in Excel, `,.2f` in Python), but the results match. The pandas or Python habit of `join` corresponds to `TEXTJOIN` with `FALSE`, so skip empties yourself (as in the fourth line) to match `TRUE`.

### Example 4: Dates as serial numbers

```excel
=DATE(2025,1,31)                  stored as 45688
=YEAR(A2)  =MONTH(A2)  =DAY(A2)   gives 2025, 1, 31
=A2+30                            gives 2025-03-02
=EDATE(A2,1)                      gives 2025-02-28
=EOMONTH(A2,0)                    gives 2025-01-31
=DATE(2025,3,0)                   gives 2025-02-28
=WEEKDAY(A2,2)                    gives 5 (Friday)
```

```python run
import pandas as pd

d = pd.Timestamp("2025-01-31")
print((d - pd.Timestamp("1899-12-30")).days)
print(d.year, d.month, d.day)
print((d + pd.DateOffset(days=30)).date())
print((d + pd.DateOffset(months=1)).date())
print((d + pd.offsets.MonthEnd(0)).date())
print(pd.Timestamp(2025, 3, 1) - pd.DateOffset(days=1))
print(d.isoweekday())
```

```output
45688
2025 1 31
2025-03-02
2025-02-28
2025-01-31
2025-02-28 00:00:00
5
```

The serial number 45688 comes from counting days from 1899-12-30. `DateOffset(months=1)` clamps to 28 February, like `EDATE`. `MonthEnd(0)` rolls forward to the end of the current month, like `EOMONTH(d,0)`. `isoweekday()` returns 1 for Monday to 7 for Sunday, the same as `WEEKDAY(d,2)`; Excel's default `WEEKDAY(d)` counts Sunday as 1 instead.

### Example 5: Cleaning a column and building real dates

A column holds order codes and date text: `" df-2024-0137 "` with `"2025-03-07"`, and `"DF-2025-0021"` with `"2025-12-30"`.

```excel
Code:   =UPPER(TRIM(A2))
Year:   =VALUE(MID(B2,4,4))
Date:   =DATE(LEFT(C2,4), MID(C2,6,2), RIGHT(C2,2))
Month start:   =DATE(YEAR(D2), MONTH(D2), 1)
Quarter label:  ="Q"&ROUNDUP(MONTH(D2)/3,0)&" "&YEAR(D2)
```

```python run
import pandas as pd

raw = pd.DataFrame({"Code": [" df-2024-0137 ", "DF-2025-0021"], "When": ["2025-03-07", "2025-12-30"]})
raw["Code"] = raw["Code"].str.split().str.join(" ").str.upper()
raw["Year"] = raw["Code"].str[3:7].astype(int)
raw["Date"] = pd.to_datetime(raw["When"].str[:4] + "-" + raw["When"].str[5:7] + "-" + raw["When"].str[8:])
raw["MonthStart"] = raw["Date"].dt.to_period("M").dt.to_timestamp()
raw["Quarter"] = "Q" + raw["Date"].dt.quarter.astype(str) + " " + raw["Date"].dt.year.astype(str)
print(raw[["Code", "Year", "MonthStart", "Quarter"]].to_string(index=False))
```

```output
        Code  Year MonthStart Quarter
DF-2024-0137  2024 2025-03-01 Q1 2025
DF-2025-0021  2025 2025-12-01 Q4 2025
```

The cleaned code, the year taken from characters 4 to 7, the first day of the month and the quarter label all match what the Excel formulas return. `ROUNDUP(MONTH/3,0)` is the Excel way to get a quarter from a month number, the same as `dt.quarter`.

## Real-world applications

- **Splitting identifiers.** Order, SKU and customer codes carry a prefix, a year or a region; `LEFT`, `MID` and `FIND` split them into columns that can be filtered and counted (Example 1).
- **Cleaning an import before a lookup.** A lookup on names fails because of trailing spaces and different case. `TRIM`, `SUBSTITUTE` and `PROPER` normalise both sides first (Example 2).
- **Reporting periods.** `DATE(YEAR(d),MONTH(d),1)`, `EOMONTH` and a `TEXT(d,"mmm yyyy")` label turn daily records into month and quarter columns for summaries (Examples 4 and 5).
- **Mail merge style labels.** `TEXTJOIN` builds an address line or a list of products per customer, skipping blank cells (Example 3).

## Daily review

### Key takeaways

- Excel positions start at 1: `MID(t,4,4)` equals Python `t[3:7]`.
- `TRIM` also collapses internal repeated spaces; it does not remove character 160.
- Text functions return text; use `VALUE` or `--` to get a number.
- A date is a serial number; formats only change the display. `DATE` builds, `YEAR`/`MONTH`/`DAY` take apart, `EDATE`/`EOMONTH` shift.
- `TEXT` gives text for labels, not for calculation. `TODAY()` is volatile.

### Common mistakes

- Using index 0 logic in Excel (`MID(A2,0,4)` returns `#VALUE!`).
- Forgetting the `-1` in `LEFT(A2, FIND("-",A2)-1)`, which leaves the dash in the result.
- Expecting `TRIM` to fix a non-breaking space and then finding that lookups still fail.
- Summing or sorting the output of `TEXT` (months sorted as Apr, Aug, Dec) when the original date should be kept.
- Treating `"2025-03-07"` as a date: it is text until you convert it, so date arithmetic and month grouping give errors or wrong results.
- Using `TODAY()` in a report that should be reproducible, so last month's numbers change.

### Revision notes

- `=MID(t,start,n)` is `t[start-1:start-1+n]`; `FIND` is 1-based and case-sensitive, `SEARCH` is not.
- Cleaning chain: `=PROPER(TRIM(SUBSTITUTE(A2,CHAR(160)," ")))`.
- `=DATE(y,m,d)`, `=EOMONTH(d,0)`, `=EDATE(d,1)`, `=WEEKDAY(d,2)`.
- Serial date: days since 1899-12-30 (for dates after February 1900).
