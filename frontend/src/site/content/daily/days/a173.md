## Objectives

- Write the generated tables to CSV text and read them back with explicit types, proving the round trip loses nothing.
- Write an ingestion function that validates columns and row counts against a manifest and fails loudly.
- Show that the project is reproducible: the same seed gives the same data and a different seed does not.
- Set up the Git repository with a `.gitignore` that keeps generated data out of version control.

## Understand

### What ingestion means here

Ingestion is the step that moves data from where it comes from into the place where your code works on it, in a controlled and repeatable way. In a real project the source might be an export from the shop's database, a CSV from the marketing team or an API. In this capstone the source is the seeded generator from Day 172, and the "files" are CSV text. Treating the generated tables as files is deliberate: it practises the exact steps you would take with real exports, and everything stays in code, so you can run it in the browser.

### Why CSV needs explicit types

A CSV file stores only text. When it is read back, the reader guesses: `2025-03-04` is just a string unless you say it is a date, and a column of ids with one blank cell becomes floats. These guesses are the most common cause of silent errors later, such as dates sorting alphabetically or ids no longer matching a lookup table. The fix is to be explicit: pass `parse_dates` for date columns, and check the column names and dtypes after reading. The round-trip test (write, read, compare with `equals`) proves that your writing and reading settings agree.

### Manifest and validation at the door

A manifest says what you expect: for each table, the column names in order, which columns are dates, and the row count. After reading, the ingestion function compares what arrived with the manifest and raises an error when they differ. This is cheap and catches the failures that cost hours later: a truncated file (fewer rows than expected), a renamed column, a missing table. The rule is to fail early and loudly with a message naming the table and the difference, instead of continuing with partial data. Note that ingestion does not clean: the duplicates and bad quantities still arrive, because cleaning is Day 174 and needs the raw data to measure against.

### Reproducibility

A result is reproducible when someone else, or you in three months, can run the same code and get the same numbers. Two things make that true here. The generator takes a seed, and `np.random.default_rng(7)` always produces the same stream, so the same seed yields identical tables. And the project records its steps in a repository. A misconception is that setting a seed once at the top of a notebook is enough: if the cells run in a different order, the random stream is consumed differently. A function that creates its own generator from a seed, like `generate(seed)`, avoids that.

### Git for the project

Git records snapshots of the project. A repository for this capstone has `README.md`, `requirements.txt`, `src/`, `sql/`, `tests/`, `reports/` and a `.gitignore`. Generated data lives in `data/` and is ignored, because the generator can recreate it and large generated files make the history heavy. Commit messages describe what changed: `Add ingestion with manifest checks` is useful, `update` is not. You will use a single `main` branch for the first commits and a feature branch on Day 179.

## Learn by example

### Example 1: Write and read back

Each table is written to CSV text and read back. The round trip must give an identical table, including date types. `equals` also compares dtypes, and integer widths depend on the platform: the browser's Python builds 32-bit integers by default while the CSV reader returns 64-bit ones. The values are what must match, so the comparison first converts the original to the dtypes that came back.

```python run
import io
import numpy as np
import pandas as pd


def generate(seed=7):
    """Seeded online-store data with planted defects: 500 orders, 120 customers, 20 products."""
    rng = np.random.default_rng(seed)
    customers = pd.DataFrame({
        "customer_id": np.arange(1, 121),
        "country": rng.choice(["DE", "FR", "UK", "US"], 120, p=[0.3, 0.2, 0.2, 0.3]),
        "signup_date": pd.Timestamp("2024-07-01") + pd.to_timedelta(rng.integers(0, 180, 120), unit="D"),
    })
    customers.loc[rng.choice(120, 8, replace=False), "country"] = "us "
    products = pd.DataFrame({
        "product_id": np.arange(1, 21),
        "category": np.repeat(["home", "beauty", "sports", "electronics"], 5),
        "unit_price": (10 + rng.random(20) * 90).round(2),
    })
    campaigns = pd.DataFrame({
        "campaign_id": [0, 1, 2, 3],
        "channel": ["organic", "email", "paid_search", "social"],
        "spend": [0.0, 800.0, 2500.0, 1200.0],
    })
    n = 500
    orders = pd.DataFrame({
        "order_id": np.arange(1001, 1001 + n),
        "customer_id": rng.integers(1, 121, n),
        "product_id": rng.integers(1, 21, n),
        "order_date": pd.Timestamp("2025-01-01") + pd.to_timedelta(rng.integers(0, 180, n), unit="D"),
        "quantity": rng.integers(1, 5, n),
        "discount_pct": rng.choice([0, 10, 20], n, p=[0.6, 0.25, 0.15]),
        "campaign_id": rng.choice([0, 1, 2, 3], n, p=[0.4, 0.2, 0.25, 0.15]),
    })
    orders.loc[rng.choice(n, 5, replace=False), "quantity"] = -1
    orders.loc[rng.choice(n, 6, replace=False), "customer_id"] = 999
    orders = pd.concat([orders, orders.sample(10, random_state=1)], ignore_index=True)
    returned = rng.choice(np.arange(1001, 1001 + n), 60, replace=False)
    returns = pd.DataFrame({
        "order_id": np.concatenate([returned, [9001, 9002, 9003]]),
        "reason": rng.choice(["damaged", "wrong_item", "changed_mind"], 63, p=[0.3, 0.2, 0.5]),
    })
    return {"orders": orders, "customers": customers, "products": products, "campaigns": campaigns, "returns": returns}


t = generate()
texts = {name: df.to_csv(index=False) for name, df in t.items()}
for name in sorted(texts):
    print(name, "lines:", texts[name].count("\n"))
back = pd.read_csv(io.StringIO(texts["orders"]), parse_dates=["order_date"])
print("orders round trip equal:", back.equals(t["orders"].astype(back.dtypes.to_dict())))
naive = pd.read_csv(io.StringIO(texts["orders"]))
print("without parse_dates, order_date is a date:", pd.api.types.is_datetime64_any_dtype(naive["order_date"]))
```

```output
campaigns lines: 5
customers lines: 121
orders lines: 511
products lines: 21
returns lines: 64
orders round trip equal: True
without parse_dates, order_date is a date: False
```

### Example 2: Ingest against a manifest

The manifest holds the expected columns, date columns and row counts. The ingestion function raises an error that names the table when a file does not match, which is shown with a truncated file.

t = generate()
texts = {name: df.to_csv(index=False) for name, df in t.items()}
MANIFEST = {
    "orders": {"dates": ["order_date"], "rows": 510, "cols": ["order_id", "customer_id", "product_id", "order_date", "quantity", "discount_pct", "campaign_id"]},
    "customers": {"dates": ["signup_date"], "rows": 120, "cols": ["customer_id", "country", "signup_date"]},
    "products": {"dates": [], "rows": 20, "cols": ["product_id", "category", "unit_price"]},
    "campaigns": {"dates": [], "rows": 4, "cols": ["campaign_id", "channel", "spend"]},
    "returns": {"dates": [], "rows": 63, "cols": ["order_id", "reason"]},
}


def ingest(texts, manifest=MANIFEST):
    tables, log = {}, []
    for name, spec in manifest.items():
        df = pd.read_csv(io.StringIO(texts[name]), parse_dates=spec["dates"])
        if list(df.columns) != spec["cols"]:
            raise ValueError(f"{name}: unexpected columns {list(df.columns)}")
        if len(df) != spec["rows"]:
            raise ValueError(f"{name}: expected {spec['rows']} rows, got {len(df)}")
        tables[name] = df
        log.append(f"{name}: {len(df)} rows ok")
    return tables, log


tables, log = ingest(texts)
print("\n".join(log))
broken = dict(texts)
broken["orders"] = "\n".join(texts["orders"].splitlines()[:-1]) + "\n"
try:
    ingest(broken)
except ValueError as e:
    print("rejected:", e)
```

customers: 120 rows ok
products: 20 rows ok
campaigns: 4 rows ok
returns: 63 rows ok
rejected: orders: expected 510 rows, got 509
```

### Example 3: Reproducibility check

Same seed, same data. A different seed gives different data. A small fingerprint (row count and totals) makes the comparison readable in a log.

## Real-world applications

- A data engineer validates every file against a manifest before it enters a warehouse, rejecting a truncated nightly export exactly as Example 2 rejects the broken orders file.
- An analyst ships a project with a seeded generator or a data download script, so a reviewer can recreate the data and reproduce every figure.
- A team keeps a `.gitignore` for raw data and secrets so that repositories stay small and credentials never reach version control.
- A BI developer reads a vendor CSV with explicit date parsing so that month groupings do not break on text dates.

## Daily review

### Key takeaways

- CSV stores text only, so read with explicit dates and compare the result with the original.
- A manifest of columns and row counts makes ingestion fail early and loudly.
- A function that builds its own seeded generator is reproducible regardless of run order.
- Generated data is ignored by Git; code, tests and documents are tracked.

### Common mistakes

- Reading dates without `parse_dates`: the column has dtype object and month grouping or sorting gives wrong results. Pass `parse_dates` and check the dtype.
- Writing the index with `to_csv()`: an extra unnamed column appears when the file is read back. Use `index=False`.
- Cleaning during ingestion and losing the raw baseline, so the quality report cannot show what was wrong. Ingest raw, clean in the next stage.
- Committing generated data and then adding it to `.gitignore`: files already tracked stay tracked. Ignore before the first `git add`.

### Revision notes

- Round trip: `to_csv(index=False)`, `read_csv(StringIO, parse_dates=...)`, `equals`.
- Manifest check: columns in order, row count, dates; raise `ValueError` with the table name.
- Raw counts: orders 510, customers 120, products 20, campaigns 4, returns 63.
- Repository: layout folders, ignore `data/`, commit with a clear message.
