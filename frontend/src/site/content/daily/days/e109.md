## Objectives

- Combine paged API responses into one DataFrame with `pd.json_normalize`, keeping the page number of each record.
- Repair types: text numbers to integers, ISO timestamps to UTC datetimes, padded or mixed-case text to a controlled vocabulary.
- Find and resolve duplicates by key, and tell exact duplicates from conflicting ones.
- Express validation rules as boolean masks, split the table into clean rows and rejected rows with a reason, and reconcile the counts.
- Produce a DataFrame whose columns and types match the target `orders` table, ready to load on Day 110.

## Understand

### What "clean" means here

The extract steps of Days 103 to 108 deliver a list of JSON records that were fetched safely. They are not yet table rows. The target table (`orders` with `order_id` as primary key, `customer_id`, `amount_cents`, `currency`, `status`, `created_at`) has a type for every column and a rule for every constraint. **Cleaning** is the work between the two: flatten the records into columns, give each column its type, remove duplicates, and check each row against the rules, setting aside the rows that fail. The result should be a DataFrame that the database will accept without complaint, plus a record of what was set aside and why.

Cleaning is done in pandas before the load for two reasons. It is easier to look at a column of 50,000 values, count the odd ones and fix them in a DataFrame than in a failed `INSERT`. And a database constraint error stops a batch at the first bad row, while a validation mask classifies all of them in one pass (Day 99).

### Flattening pages into one table

A paged API gives a list of page bodies, each with a `data` list. `pd.json_normalize(pages, record_path="data", meta=["page"])` produces one row per record, and `meta` copies the page number onto each of its records, which is valuable for debugging ("which page did this bad record come from?"). Nested fields flatten into columns such as `customer_name` (Day 104). After this step the DataFrame has the columns the API sent, with whatever types the JSON values gave pandas: a column that mixes integers and strings becomes `object`.

### Types

Every column gets its target type deliberately.

- **Integers from text.** `pd.to_numeric(col, errors="coerce")` turns `"1990"` into 1990 and an unreadable value into `NaN`; count how many became `NaN` and keep the originals, because a coerced value is a rejected value, not a lost one. Because `NaN` forces floats, convert to the nullable `Int64` type after validation (`col.astype("Int64")`) if missing values remain, or to `int64` when none are left.
- **Timestamps.** `pd.to_datetime(col, utc=True, errors="coerce")` parses ISO strings such as `2026-03-05T10:30:00Z` into timezone-aware UTC timestamps and turns impossible dates into `NaT` ("not a time"). Store timestamps in UTC and convert for display only; this avoids daylight saving mistakes.
- **Controlled vocabularies.** `status` should be one of `paid`, `refunded`, `failed`; `currency` one of an agreed list. Normalise first (`.str.strip().str.lower()` for status, `.str.strip().str.upper()` for currency), then validate against the list. Normalising before validating prevents `" PAID "` from being rejected for a cosmetic reason, and validating after normalising still catches `"paidd"`.

### Duplicates

Paging can return the same record twice, especially with offset paging (Day 106), and a re-run can fetch records again. Two kinds exist. An **exact duplicate** has the same key and the same values in every column: drop all but one. A **conflicting duplicate** has the same key but different values, for example `order_id 5` once with status `paid` and once with `refunded`. The rows disagree, and keeping an arbitrary one is a decision that must be stated. With no `updated_at` field in the Orders API, a defensible rule is **last seen wins** (a later page or a later request holds the fresher state), implemented by `drop_duplicates(subset="order_id", keep="last")` on data in fetch order. Report the conflicting keys, so that the rule can be questioned. `duplicated(subset="order_id", keep=False)` marks every row involved in a duplicate, which is what you need to inspect them.

### Validation as masks

A **rule** is a boolean expression over a column: `amount_cents >= 0`, `status.isin(STATUSES)`, `created_at.notna()`. A DataFrame mask per rule lets you compute, for each row, the first rule it breaks, and so split the table: `clean = df[all_ok]` and `rejects = df[~all_ok].assign(reason=...)`. Order matters for the reason column; test the "cannot even be read" rules (missing, unparseable) before the business rules. Count each rule's failures, and check that **rows in = clean rows + rejected rows + duplicates removed**, so nothing disappears.

### Common misconception

Learners clean until the DataFrame "looks right" and then load it. Looking at `df.head()` shows the first five rows; the defects are in row 4,031. Cleaning is finished only when explicit checks pass: every column has its target dtype, the key is unique, every rule holds for the clean table, and the counts reconcile.

### Why it matters

Whatever you let through is in the warehouse for good, and every report builds on it. Strict, explicit rules at this boundary keep the table trustworthy, and the reject table keeps the problem visible instead of buried.

## Syntax and key functions

```python
import pandas as pd

df = pd.json_normalize(pages, record_path="data", meta=["page"])
df["amount_cents"] = pd.to_numeric(df["amount_cents"], errors="coerce")
df["created_at"] = pd.to_datetime(df["created_at"], utc=True, errors="coerce")
df["status"] = df["status"].str.strip().str.lower()
df["currency"] = df["currency"].str.strip().str.upper()

dupes = df[df.duplicated(subset="order_id", keep=False)]
df = df.drop_duplicates(subset="order_id", keep="last")

ok = df["amount_cents"].ge(0) & df["status"].isin(STATUSES) & df["created_at"].notna()
clean, rejects = df[ok], df[~ok]
```

| Item | What it does or returns |
|---|---|
| `pd.json_normalize(pages, record_path="data", meta=["page"])` | One row per record with the page number. |
| `pd.to_numeric(s, errors="coerce")` | Numbers; unreadable values become `NaN`. |
| `pd.to_datetime(s, utc=True, errors="coerce")` | UTC timestamps; unreadable become `NaT`. |
| `s.str.strip()`, `.str.lower()`, `.str.upper()` | Text normalisation. |
| `df.duplicated(subset, keep=False)` | Mask of every row in a duplicate group. |
| `df.drop_duplicates(subset, keep="last")` | One row per key (the last seen). |
| `s.isin(values)` | Membership rule. |
| `s.astype("Int64")` | Nullable integer type. |

## Learn by example

### Example 1: Pages to one DataFrame

The raw pages are built from the Orders stand-in and then given the defects that real data has: a text amount, a negative amount, a padded status, an overlap between the pages with a changed status, an impossible date and a lower-case currency. `json_normalize` combines them, adding the page number, and the dtypes show what the defects did.

```python run
import pandas as pd

STATUSES = ["paid", "paid", "refunded", "failed"]
ORDERS = [
    {"order_id": i, "customer_id": i * 7 % 25 + 1, "amount_cents": 1000 + i * 137 % 9000,
     "currency": "EUR" if i % 4 else "USD", "status": STATUSES[i % 4],
     "created_at": f"2026-03-{(i - 1) // 4 + 1:02d}T{i * 7 % 24:02d}:{i * 13 % 60:02d}:00Z"}
    for i in range(1, 121)
]

pages = [
    {"page": 1, "data": [dict(o) for o in ORDERS[0:5]]},
    {"page": 2, "data": [dict(o) for o in ORDERS[4:10]]},
]
pages[0]["data"][1]["amount_cents"] = "1990"                  # text instead of a number
pages[0]["data"][2]["amount_cents"] = -500                     # negative amount
pages[0]["data"][3]["status"] = " PAID "                       # spacing and case
pages[1]["data"][0]["status"] = "refunded"                     # order 5 again, with a changed status
pages[1]["data"][2]["created_at"] = "2026-13-45T00:00:00Z"     # impossible date
pages[1]["data"][4]["currency"] = "eur"                        # lower-case currency

df = pd.json_normalize(pages, record_path="data", meta=["page"])
print(df.shape)
print(df["page"].tolist())
print({c: str(t) for c, t in df.dtypes.items()})
print(df[["order_id", "amount_cents", "status", "currency"]].to_string(index=False))
```

### Example 3: Duplicates: exact, conflicting, and the rule

After type repair, order 5 appears twice with different statuses. The code lists every row involved in a duplicate, separates exact from conflicting duplicates by counting distinct values per key, applies "last seen wins" and reports which keys had conflicts.

]

pages[0]["data"][1]["amount_cents"] = "1990"                  # text instead of a number
pages[0]["data"][2]["amount_cents"] = -500                     # negative amount

pages[1]["data"][4]["currency"] = "eur"                        # lower-case currency

df = pd.json_normalize(pages, record_path="data", meta=["page"])

Order 5 is a conflicting duplicate: the same key with two different statuses. The `keep="last"` rule picks the page-2 version, and the report names the key so that the rule can be questioned.

### Example 4: Validate, split and reconcile

The full cleaning function applies types, the duplicate rule and five validation rules. It builds the reason for each rejected row from the first rule it breaks and returns the clean table and the rejects. The final lines reconcile: rows in = clean + rejected + duplicates removed.

```python run
import pandas as pd

STATUSES = ["paid", "paid", "refunded", "failed"]
ORDERS = [
    {"order_id": i, "customer_id": i * 7 % 25 + 1, "amount_cents": 1000 + i * 137 % 9000,
     "currency": "EUR" if i % 4 else "USD", "status": STATUSES[i % 4],
     "created_at": f"2026-03-{(i - 1) // 4 + 1:02d}T{i * 7 % 24:02d}:{i * 13 % 60:02d}:00Z"}
    for i in range(1, 121)
]

pages = [
    {"page": 1, "data": [dict(o) for o in ORDERS[0:5]]},
    {"page": 2, "data": [dict(o) for o in ORDERS[4:10]]},
]
pages[0]["data"][1]["amount_cents"] = "1990"                  # text instead of a number
pages[0]["data"][2]["amount_cents"] = -500                     # negative amount
pages[0]["data"][3]["status"] = " PAID "                       # spacing and case
pages[1]["data"][0]["status"] = "refunded"                     # order 5 again, with a changed status
pages[1]["data"][2]["created_at"] = "2026-13-45T00:00:00Z"     # impossible date
pages[1]["data"][4]["currency"] = "eur"                        # lower-case currency

STATUSES = {"paid", "refunded", "failed"}
CURRENCIES = {"EUR", "USD"}

def clean_orders(pages):
    df = pd.json_normalize(pages, record_path="data", meta=["page"])
    rows_in = len(df)
    df["amount_cents"] = pd.to_numeric(df["amount_cents"], errors="coerce")
    df["created_at"] = pd.to_datetime(df["created_at"], utc=True, errors="coerce")
    df["status"] = df["status"].str.strip().str.lower()
    df["currency"] = df["currency"].str.strip().str.upper()
    df = df.drop_duplicates(subset="order_id", keep="last")
    removed = rows_in - len(df)
    rules = [
        ("unreadable amount", df["amount_cents"].notna()),
        ("unreadable created_at", df["created_at"].notna()),
        ("negative amount", df["amount_cents"].fillna(0) >= 0),
        ("unknown status", df["status"].isin(STATUSES)),
        ("unknown currency", df["currency"].isin(CURRENCIES)),
    ]
    reason = pd.Series("", index=df.index)
    for name, ok in rules:
        reason = reason.mask((reason == "") & ~ok, name)
    clean = df[reason == ""].copy()
    clean["amount_cents"] = clean["amount_cents"].astype("int64")
    rejects = df[reason != ""].assign(reason=reason[reason != ""])
    return clean, rejects, rows_in, removed

clean, rejects, rows_in, removed = clean_orders(pages)
print(rejects[["order_id", "reason"]].to_string(index=False))
print({c: str(t) for c, t in clean.dtypes.items() if c in ("order_id", "amount_cents", "status")})
print(rows_in, len(clean), len(rejects), removed, rows_in == len(clean) + len(rejects) + removed)
print(clean["order_id"].is_unique, sorted(clean["currency"].unique()))
```

```output
 order_id                reason
        3       negative amount
        7 unreadable created_at
{'order_id': 'int64', 'amount_cents': 'int64', 'status': 'object'}
11 8 2 1 True
True ['EUR', 'USD']
```

Eleven rows came in. One duplicate was removed, two rows are rejected (the negative amount and the impossible date) and eight are clean. The padded status and the lower-case currency were repaired and not rejected, because normalisation comes before validation.

## Real-world applications

- **Before every load.** The clean DataFrame has the exact columns and dtypes of the target table, and the reject DataFrame becomes the dead-letter data for review.
- **Provider quality report.** Counting rejects per rule per run shows whether a provider's data is getting worse.
- **Safe re-runs.** Deduplicating by key makes a re-fetched overlap harmless before it reaches the database.
- **Auditable rules.** The rules are code in one function; a data owner can read them and change them in one place.

## Daily review

### Key takeaways

- Flatten pages with `json_normalize(record_path="data", meta=["page"])`.
- Convert each column to its target type with `errors="coerce"`, and count what failed.
- Normalise vocabularies before validating them.
- Exact duplicates are dropped; conflicting duplicates need a stated rule (here: last seen wins) and a report.
- Rules are masks; split into clean and rejected with a reason; reconcile the counts.

### Common mistakes

- **Validating before normalising.** `" PAID "` is rejected for a cosmetic reason. Normalise first.
- **`drop_duplicates()` without `subset`.** Rows with the same key and different values both survive. Deduplicate on the key.
- **Dropping rows without recording them.** Counts no longer reconcile. Keep a rejects table.
- **Naive timestamps.** Mixing zones produces wrong day boundaries. Parse with `utc=True`.
- **Checking only `head()`.** Defects hide in later rows. Check dtypes, uniqueness, rule counts.

### Revision notes

- `json_normalize`, `to_numeric`, `to_datetime(utc=True)`, `str.strip/lower/upper`.
- `duplicated(keep=False)` to inspect; `drop_duplicates(subset, keep="last")` to resolve.
- Rules as masks; first failing rule gives the reason.
- rows in = clean + rejected + duplicates removed.
