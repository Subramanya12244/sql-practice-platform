## Objectives

- Run a complete small analytics job: query with SQL, transform with pandas, chart and report.
- Combine a join, a window function and a pandas summary in one workflow built from small functions.
- Verify the report numbers by reconciling the SQL result with an independent calculation.
- Write the findings as sentences generated from the data, with their definitions.

## Understand

### What the project builds

This mini-project joins the skills of Days 114 to 118 into one job on the Orders data. The data is the 120 orders of the stand-in API in an in-memory `sqlite3` database (the stand-in for PostgreSQL) plus a small `customers` table with a `segment` column. The question is: **how is paid revenue developing day by day, and does it differ between business and retail customers?** The deliverable has four parts: a query function that returns daily paid revenue per segment with a moving average, a transform that adds week labels and a week-over-week comparison, a chart of daily revenue with its seven-day average, and a short report of three findings.

### The plan

Work in the order the data flows, and keep each stage a function with a clear input and output, as on Day 116. Stage one is the **query**: join `orders` to `customers`, keep `status = 'paid'`, group by day and segment, and compute a moving average with a window. Doing the join, filter and aggregation in SQL is pushdown (Day 115): the result has one row per day and segment, not 120 rows. Stage two is the **transform** in pandas: parse the dates, add the week number, pivot segments into columns and compute the share of each segment. Stage three is the **chart**, a thin function over the prepared frame (Day 118): a line of daily revenue and a dashed line of its moving average, plus the printed properties that a test can check. Stage four is the **report**: sentences built from numbers with f-strings, each with its definition, as on Day 113.

### Checks before you trust it

A report is only as good as its checks. Before writing a sentence, reconcile: the total of the daily query must equal a separate `SELECT SUM(amount_cents)` over paid orders, and the segment counts must add up to the number of paid orders. These checks catch the classic join errors: a join that multiplies rows (several customer rows per id) or drops them (orders whose customer is missing). With a primary key on `customer_id` the join cannot multiply, but an inner join drops orders without a customer, so the check compares counts and says how many were lost.

### What a good result looks like

The finished job is a few small functions and a `main` that calls them, tests built on five-row tables, a chart saved under a deterministic name, and a report whose numbers all trace back to a query. A misconception to avoid is that the mini-project is about the chart: the value is in the verified numbers and the structure that lets someone rerun it next month with a different date range.

## Syntax and key functions

```sql-syntax
SELECT o.created_at, c.segment, SUM(o.amount_cents) AS cents
FROM orders o JOIN customers c ON c.customer_id = o.customer_id
WHERE o.status = 'paid' GROUP BY o.created_at, c.segment;
```

```python

```

| Item | What it does or returns |
|---|---|
| `JOIN ... ON` | Combines orders with customers on `customer_id`; an inner join drops orders without a customer. |
| `AVG(x) OVER (ORDER BY d ROWS BETWEEN 6 PRECEDING AND CURRENT ROW)` | Seven-day moving average. |
| `df.pivot_table(index, columns, values, aggfunc, fill_value)` | Segments as columns, one row per day. |
| `dt.isocalendar().week` | ISO week number of a datetime column. |
| `df.pipe(f)` | Chains the stage functions. |

## Learn by example

### Example 1: The query stage

The query joins orders to customers, keeps paid orders, and aggregates per day and segment. The orders have a unique `customer_id` match, so the join cannot multiply rows. The printed checks reconcile against an independent total.

```python run
import sqlite3
import pandas as pd
import math

def make_orders():
    statuses = ["paid", "paid", "paid", "refunded", "paid", "failed"]
    rows = []
    for i in range(1, 121):
        rows.append({
            "order_id": i,
            "customer_id": 1 + (i * 5) % 17,
            "amount_cents": 500 + (i * 37) % 89 * 50,
            "currency": "EUR" if i % 5 else "USD",
            "status": statuses[i % 6],
            "created_at": f"2025-03-{1 + (i * 13) % 28:02d}T{(i * 3) % 24:02d}:{(i * 11) % 60:02d}:00Z",
        })
    return rows

ORDERS = make_orders()

def get_orders(page, page_size, api_key):
    """Stand-in for GET /orders?page=N&page_size=P, header X-Api-Key."""
    if api_key != "demo-key":
        return {"error": "unauthorized"}
    total_pages = math.ceil(len(ORDERS) / page_size)
    start = (page - 1) * page_size
    return {"data": ORDERS[start:start + page_size], "page": page, "total_pages": total_pages}


def make_conn():
    conn = sqlite3.connect(":memory:")
    conn.execute("""CREATE TABLE orders (order_id INTEGER PRIMARY KEY, customer_id INTEGER,
        amount_cents INTEGER, currency TEXT, status TEXT, created_at TEXT)""")
    conn.execute("CREATE TABLE customers (customer_id INTEGER PRIMARY KEY, segment TEXT)")
    conn.executemany("INSERT INTO orders VALUES (:order_id,:customer_id,:amount_cents,:currency,:status,:created_at)", ORDERS)
    conn.executemany("INSERT INTO customers VALUES (?, ?)", [(c, "business" if c % 3 == 0 else "retail") for c in range(1, 18)])
    return conn

def query_daily(conn):
    sql = """SELECT substr(o.created_at, 1, 10) AS day, c.segment, COUNT(*) AS orders, SUM(o.amount_cents) AS cents
             FROM orders o JOIN customers c ON c.customer_id = o.customer_id
             WHERE o.status = 'paid' GROUP BY 1, 2 ORDER BY 1, 2"""
    return pd.read_sql(sql, conn, parse_dates=["day"])

conn = make_conn()
daily = query_daily(conn)
print(daily.shape)
print(daily.head(4).to_string(index=False))
paid_total = conn.execute("SELECT SUM(amount_cents), COUNT(*) FROM orders WHERE status = 'paid'").fetchone()
print("reconciles:", int(daily["cents"].sum()) == paid_total[0], int(daily["orders"].sum()) == paid_total[1])
```

```output
(43, 4)
       day  segment  orders  cents
2025-03-01 business       1   1750
2025-03-01   retail       3  10950
2025-03-02 business       1   2300
2025-03-02   retail       1   1950
reconciles: True True
```

### Example 3: The transform stage

The transform pivots the segments into columns, fills missing days with 0 and adds the business share. The function takes the query result and returns a new frame, as on Day 116.

```python run

import math

    start = (page - 1) * page_size

def make_conn():

    conn.execute("""CREATE TABLE orders (order_id INTEGER PRIMARY KEY, customer_id INTEGER,
        amount_cents INTEGER, currency TEXT, status TEXT, created_at TEXT)""")

    conn.executemany("INSERT INTO orders VALUES (:order_id,:customer_id,:amount_cents,:currency,:status,:created_at)", ORDERS)
    conn.executemany("INSERT INTO customers VALUES (?, ?)", [(c, "business" if c % 3 == 0 else "retail") for c in range(1, 18)])
    return conn

def query_daily(conn):
    sql = """SELECT substr(o.created_at, 1, 10) AS day, c.segment, SUM(o.amount_cents) AS cents
             FROM orders o JOIN customers c ON c.customer_id = o.customer_id
             WHERE o.status = 'paid' GROUP BY 1, 2"""
    return pd.read_sql(sql, conn, parse_dates=["day"])

def to_wide(daily):
    wide = daily.pivot_table(index="day", columns="segment", values="cents", aggfunc="sum", fill_value=0)
    wide = wide.assign(total=wide["business"] + wide["retail"])
    return wide.assign(business_share=(wide["business"] / wide["total"]).round(3)).reset_index()

wide = query_daily(make_conn()).pipe(to_wide)
print(list(wide.columns))
print(wide.head(3).to_string(index=False))
print("days with no business sales:", int((wide["business"] == 0).sum()))
```

## Real-world applications

- **Recurring management report.** The same four stages produce a weekly revenue note; only the date range changes, and the reconciliation step proves the numbers before they are sent.
- **Join-error detection.** Reconciling the joined result with a plain total (Example 1) is the first test of any report built on a join, because fan-out and dropped rows change totals silently.
- **Reusable stages.** The query stage can feed a dashboard, the transform a data-quality check and the report a Slack message, because each stage has a clear input and output.
- **Review and handover.** A reviewer can read the report sentences next to the queries that support them, which is what makes the work reviewable.

## Daily review

### Key takeaways

- One job, four stages: query, transform, chart, report; each a function with an explicit input and output.
- Push the join, filter and aggregate into SQL; finish in pandas.
- Reconcile the result against an independent total before writing sentences.
- Generate the report text from the numbers and state each definition and caveat.

### Common mistakes

- Skipping reconciliation, so a join that drops orders without a customer goes unnoticed. Compare counts and totals with a join-free query.
- Averaging daily averages instead of recomputing, which weights days equally and misstates the figure. Use the window or totals, not an average of averages.
- Treating a missing day as zero without saying so, or leaving the day out of a rolling window; decide and state the rule.
- Hard-coding the date range inside the query. Pass it as a parameter.
- Putting drawing code and calculations in one function, which cannot be tested without Matplotlib.

### Revision notes

- Reconcile: `SUM(amount_cents)` and `COUNT(*)` with a join-free query.
- `AVG(x) OVER (ORDER BY d ROWS BETWEEN 6 PRECEDING AND CURRENT ROW)`; `pivot_table(..., fill_value=0)`.
- Report numbers come from variables, not typing.
- Stages are functions; the chart only draws.
