## Objectives

- Validate the sample model (keys, relationships, duplicates) before building anything on it.
- Define a library of explicit measures and test each one against an independent pandas calculation.
- Specify a one-page sales dashboard as a list of visuals on a grid and check it against the layout rules of Day 134.
- Add a row-level security rule and reconcile the restricted views with the total.
- Run a publishing checklist as code and record what must still be done in Power BI Desktop and the Service.

## Understand

This project day builds one small, complete result: a specification and a verified set of numbers for a sales dashboard on the sample model. Power BI Desktop (Windows-only) and the Power BI Service (browser) are not available in this course, so the project is built in the way a careful analyst plans it. Every measure is written in DAX and its expected value is computed independently in pandas; every visual is a rectangle in a specification that a function checks; and every publishing step is an item in a checklist. When you later open Power BI Desktop, you rebuild the dashboard from the specification and compare each number in each visual with the value printed here. That comparison is how real teams test a report.

The work follows five steps, which are the order of the phase. First, **validate the model**: the fact table must have a unique `order_id`, every `customer_id` and `product_id` in `Sales` must exist in its dimension, and every order date must be in the calendar. A missing key does not raise an error in Power BI; it shows up as a blank row in a visual, or as revenue that silently vanishes from a total. Second, **write the measures**: a small, named library (revenue, orders, units, average order value, price per unit, share of total, year to date, top-customer share). Third, **specify the visuals**: three cards, a monthly trend, a category bar and a customer table on the 40 pixel grid, with the key card top left. Fourth, **add security and reconcile**: a country role, with the restricted views adding up to the total. Fifth, **publish**: a checklist of the Service steps.

The most useful habit of the day is to keep the expected numbers next to the DAX. The dashboard is complete when the specification passes the layout check, every measure matches its pandas value, the restricted views reconcile and the checklist has no open item that you could have done now.

The measure library, as DAX text that you would paste into the model:

```dax
Total Revenue = SUM(Sales[Revenue])
Orders = DISTINCTCOUNT(Sales[order_id])
Units = SUM(Sales[quantity])
Average Order Value = DIVIDE([Total Revenue], [Orders])
Price per Unit = DIVIDE([Total Revenue], [Units])
Revenue Share =
    DIVIDE([Total Revenue], CALCULATE([Total Revenue], ALL(Products[category])))
Revenue YTD = TOTALYTD([Total Revenue], Calendar[date])
Top 5 Customer Share =
VAR TopRevenue = CALCULATE([Total Revenue], TOPN(5, ALL(Customers[customer_name]), [Total Revenue]))
VAR AllRevenue = CALCULATE([Total Revenue], ALL(Customers[customer_name]))
RETURN DIVIDE(TopRevenue, AllRevenue)
```

## Learn by example

### Example 1: Step 1, validate the model

Check the keys and relationships of the sample model the way Power BI would silently fail on them.

```python run
import numpy as np
import pandas as pd

rng = np.random.default_rng(7)
countries = ["UK", "Germany", "France", "Spain"]
cats = ["Hardware", "Software", "Services"]
customers = pd.DataFrame({
    "customer_id": range(1, 41),
    "customer_name": [f"Customer {i:02d}" for i in range(1, 41)],
    "country": [countries[i % 4] for i in range(40)],
    "segment": [["Retail", "Corporate"][(i // 4) % 2] for i in range(40)],
})
products = pd.DataFrame({
    "product_id": range(1, 13),
    "product_name": [f"Product {i:02d}" for i in range(1, 13)],
    "category": [cats[i % 3] for i in range(12)],
    "unit_cost": [float(10 + 5 * i) for i in range(12)],
})
n = 400
sales = pd.DataFrame({
    "order_id": range(1, n + 1),
    "order_date": pd.to_datetime("2025-01-01") + pd.to_timedelta(rng.integers(0, 365, n), unit="D"),
    "customer_id": rng.integers(1, 41, n),
    "product_id": rng.integers(1, 13, n),
    "quantity": rng.integers(1, 6, n),
})
sales["unit_price"] = (sales["product_id"].map(products.set_index("product_id")["unit_cost"]) * 1.5).round(2)
calendar = pd.DataFrame({"date": pd.date_range("2025-01-01", "2025-12-31")})
calendar["year"] = calendar["date"].dt.year
calendar["quarter"] = calendar["date"].dt.quarter
calendar["month_number"] = calendar["date"].dt.month
calendar["month_name"] = calendar["date"].dt.strftime("%B")
sales["revenue"] = sales["quantity"] * sales["unit_price"]
fact = (sales.merge(customers, on="customer_id").merge(products, on="product_id")
        .merge(calendar, left_on="order_date", right_on="date"))
checks = {
    "order_id unique": bool(sales["order_id"].is_unique),
    "customers resolve": bool(sales["customer_id"].isin(customers["customer_id"]).all()),
    "products resolve": bool(sales["product_id"].isin(products["product_id"]).all()),
    "dates in calendar": bool(sales["order_date"].isin(calendar["date"]).all()),
    "calendar continuous": bool(calendar["date"].diff().dropna().eq(pd.to_timedelta(1, unit="D")).all()),
    "no rows lost in merge": len(fact) == len(sales),
}
for name, ok in checks.items():
    print(f"{name}: {'pass' if ok else 'FAIL'}")
print(len(sales), len(customers), len(products), len(calendar))
```

```output
order_id unique: pass
customers resolve: pass
products resolve: pass
dates in calendar: pass
calendar continuous: pass
no rows lost in merge: pass
400 40 12 365
```

All six checks pass: 400 sales rows resolve against 40 customers, 12 products and a continuous 365-day calendar, and the merge that builds the report table keeps every row. If one failed, for example a customer id missing from `Customers`, the DAX measures would still run and the total would be right, but a visual by customer would show a blank row, which is the symptom to look for.

### Example 2: Step 2, the measure test sheet

Compute the expected value of each measure from the project library with pandas, for the whole model and for the UK filter context.

```python run
import numpy as np
import pandas as pd

rng = np.random.default_rng(7)
countries = ["UK", "Germany", "France", "Spain"]
cats = ["Hardware", "Software", "Services"]
customers = pd.DataFrame({

    "country": [countries[i % 4] for i in range(40)],
    "segment": [["Retail", "Corporate"][(i // 4) % 2] for i in range(40)],
})
products = pd.DataFrame({
    "product_id": range(1, 13),
    "product_name": [f"Product {i:02d}" for i in range(1, 13)],
    "category": [cats[i % 3] for i in range(12)],
    "unit_cost": [float(10 + 5 * i) for i in range(12)],
})
n = 400
sales = pd.DataFrame({
    "order_id": range(1, n + 1),
    "order_date": pd.to_datetime("2025-01-01") + pd.to_timedelta(rng.integers(0, 365, n), unit="D"),
    "customer_id": rng.integers(1, 41, n),
    "product_id": rng.integers(1, 13, n),
    "quantity": rng.integers(1, 6, n),
})
sales["unit_price"] = (sales["product_id"].map(products.set_index("product_id")["unit_cost"]) * 1.5).round(2)
calendar = pd.DataFrame({"date": pd.date_range("2025-01-01", "2025-12-31")})
calendar["year"] = calendar["date"].dt.year
calendar["quarter"] = calendar["date"].dt.quarter
calendar["month_number"] = calendar["date"].dt.month
calendar["month_name"] = calendar["date"].dt.strftime("%B")
sales["revenue"] = sales["quantity"] * sales["unit_price"]
fact = (sales.merge(customers, on="customer_id").merge(products, on="product_id")
        .merge(calendar, left_on="order_date", right_on="date"))
def measures(df):
    by_customer = df.groupby("customer_id")["revenue"].sum()
    revenue = float(df["revenue"].sum())
    return {
        "Total Revenue": round(revenue, 2),
        "Orders": int(df["order_id"].nunique()),
        "Units": int(df["quantity"].sum()),
        "Average Order Value": round(revenue / df["order_id"].nunique(), 2),
        "Price per Unit": round(revenue / df["quantity"].sum(), 2),
        "Top 5 Customer Share": round(float(by_customer.nlargest(5).sum() / by_customer.sum()), 4),
    }

all_rows = measures(fact)
uk_rows = measures(fact[fact["country"] == "UK"])
print(pd.DataFrame({"all": all_rows, "UK": uk_rows}).to_string())
```

```output

Total Revenue         67132.5000  14047.5000
Orders                  400.0000     83.0000
Units                  1202.0000    247.0000
Average Order Value     167.8300    169.2500
Price per Unit           55.8500     56.8700
Top 5 Customer Share      0.2148      0.8003
```

The whole-model column is the test sheet for the report: Total Revenue 67,132.50, Orders 400 and so on. The UK column is the value each measure should show when a UK slicer is selected, and it is also what a UK-restricted user sees. The year-to-date and share measures depend on the filter context and are tested in the exercises of the day.

```python run
sales = pd.DataFrame({

page = [
    {"name": "Revenue card", "type": "card", "x": 40, "y": 40, "w": 360, "h": 120},
    {"name": "Orders card", "type": "card", "x": 440, "y": 40, "w": 360, "h": 120},

def overlaps(a, b):
    return (a["x"] < b["x"] + b["w"] and b["x"] < a["x"] + a["w"]
            and a["y"] < b["y"] + b["h"] and b["y"] < a["y"] + a["h"])

problems += [f"{a['name']} overlaps {b['name']}" for i, a in enumerate(page) for b in page[i + 1:] if overlaps(a, b)]
first = min(page, key=lambda v: (v["y"], v["x"]))
```

### Example 4: Steps 4 and 5, security reconciliation and publishing checklist

A country role restricts the rows. The sum of the four country views must equal the total, and the checklist records what is done in code and what is left for Desktop and the Service.

```python run
import numpy as np
import pandas as pd

rng = np.random.default_rng(7)
countries = ["UK", "Germany", "France", "Spain"]
cats = ["Hardware", "Software", "Services"]

    "category": [cats[i % 3] for i in range(12)],
    "unit_cost": [float(10 + 5 * i) for i in range(12)],
})
n = 400
sales = pd.DataFrame({
    "order_id": range(1, n + 1),
    "order_date": pd.to_datetime("2025-01-01") + pd.to_timedelta(rng.integers(0, 365, n), unit="D"),
    "customer_id": rng.integers(1, 41, n),
    "product_id": rng.integers(1, 13, n),

fact = (sales.merge(customers, on="customer_id").merge(products, on="product_id")
        .merge(calendar, left_on="order_date", right_on="date"))
total = round(float(sales["revenue"].sum()), 2)
parts = {}
for country in sorted(customers["country"].unique()):
    ids = customers.loc[customers["country"] == country, "customer_id"]
    parts[country] = round(float(sales.loc[sales["customer_id"].isin(ids), "revenue"].sum()), 2)
print(parts)
print(round(sum(parts.values()), 2) == total)

checklist = [
    ("model validated", True),
    ("measures tested against pandas", True),
    ("layout check passed", True),
    ("RLS views reconcile to total", round(sum(parts.values()), 2) == total),
    ("RLS roles assigned in the Service", False),
    ("refresh scheduled and tested", False),
    ("report shared as an app", False),
]
for item, done in checklist:
    print(("[x] " if done else "[ ] ") + item)
print(sum(done for _, done in checklist), "of", len(checklist))
```

## Real-world applications

- **Report acceptance tests.** A measure test sheet like Example 2 is attached to a dashboard release so the business owner can compare their own figures.
- **Design review.** A page specification that passes a layout check is reviewed before any chart is built (Example 3).
- **Security sign-off.** A reconciliation of restricted views to the total is evidence that row-level security does not drop rows (Example 4).
- **Handover.** The checklist and the specification let another analyst rebuild or maintain the report.

## Daily review

### Key takeaways

- Validate keys and the calendar first; missing keys show up as blanks, not errors.
- Keep an expected value for every measure, computed independently of the model.
- A page specification can be checked by code before it is built.
- Restricted views must reconcile to the total.
- A checklist makes the publishing steps explicit and verifiable.

### Common mistakes

- Building visuals before checking the model, then debugging blank rows in a visual.
- Writing measures without an independent check, so a wrong filter is never found.
- Designing the page in the tool by eye and discovering overlap or an off-canvas table at the end.
- Testing RLS as a workspace editor (who is not restricted) and concluding it works.
- Treating "published" as the end, with no scheduled refresh or owner for failures.

### Revision notes

- Order: validate, measures, visuals, security, publish.
- Test sheet: measure, DAX, expected value, all rows and one filter context.
- Layout: grid, bounds, overlap, key card first.
- RLS: sum of views equals the total.
- Checklist: done in code versus still to do in Desktop and the Service.
