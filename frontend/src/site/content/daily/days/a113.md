## Objectives

- Plan an exploration from written questions and run it in an order that protects the conclusions.
- Clean a messy table with a function that reports how many rows each step changed.
- Produce univariate, bivariate, time and cohort results that answer the planned questions.
- Write three to five findings that state a claim, a number, a base and a caveat.
- Deliver a short written report from a rerunnable script.

## Understand

### What the project is

This project day brings Days 106 to 112 together on one dataset. You will explore the online-store orders table from its raw, messy form to a written set of findings, and every step is a short script that can be rerun. The dataset is the one from the earlier days: 600 orders over six months, with duplicates, inconsistent channel labels and impossible quantities deliberately planted in the raw version. The product is not a pile of tables, but a report that a manager could act on, backed by code that reproduces every number.

### The sequence

The project follows the checklist from Day 106 in six steps. First write the questions and the metric definitions. Second profile the raw table and run quality checks. Third clean it with a function that returns the cleaned table and a count of rows at every step, and write the decisions into the log. Fourth explore: single variables (Day 107), pairs of variables (Day 108), outliers and missing values (Day 109), time (Day 110) and segments and cohorts (Day 111). Fifth pick the findings that answer the questions and check each one: base, comparison, uncertainty. Sixth write the report (Day 112) with the findings first, then the caveats and the next steps.

### Working rules

Keep the raw table untouched and build the cleaned table in a function, so any reader can rerun it. Every row you remove or value you change must be counted in the log. Decide the questions before looking at results, and when you add a question later, mark it as a follow-up so readers can tell planned from found. Limit the report to the findings that matter for the decisions, and put all other tables in an appendix. Before finalising, ask of each finding: what is the base, what is it compared with, how uncertain is it, and what could explain it besides the story I am telling?

### What good looks like

A strong submission has a cleaned table with a row-accounting line, a profile with missing shares, one or two checks of outliers and missingness, a trend with its noise, at least one segment comparison with sizes, and a report whose every number is produced by the code. The report states what is not known as clearly as what is.

## Learn by example

### Example 1: Plan, profile and decide

The plan lists three questions with the columns needed. The raw table is profiled: row counts, planted problems found with counts and the missing shares. The numbers go straight into a log that will later feed the report's data section.

```python run
import numpy as np
import pandas as pd
from scipy import stats

pd.set_option("display.width", 200)
pd.set_option("display.max_columns", 20)


def make_orders(messy=False):
    rng = np.random.default_rng(7)
    n = 600
    category = rng.choice(["home", "beauty", "sports", "electronics", "toys"], size=n, p=[0.30, 0.25, 0.20, 0.15, 0.10])
    base = pd.Series({"home": 40, "beauty": 25, "sports": 55, "electronics": 180, "toys": 20})
    discount = rng.choice([0, 5, 10, 20], size=n, p=[0.6, 0.15, 0.15, 0.1])
    ship = np.clip(rng.poisson(3.5, n) + 1, 1, 12).astype(float)
    df = pd.DataFrame({
        "order_id": np.arange(1001, 1001 + n),
        "order_date": pd.Timestamp("2025-01-01") + pd.to_timedelta(rng.integers(0, 180, n), unit="D"),
        "customer_id": rng.integers(1, 260, n),
        "channel": rng.choice(["organic", "paid", "email", "referral"], size=n, p=[0.4, 0.3, 0.2, 0.1]),
        "device": rng.choice(["mobile", "desktop", "tablet"], size=n, p=[0.55, 0.35, 0.10]),
        "category": category,
        "quantity": np.clip(rng.poisson(0.8 + discount / 20, n) + 1, 1, 6),
        "unit_price": (base[category].to_numpy() * rng.lognormal(0, 0.25, n)).round(2),
        "discount_pct": discount,
        "shipping_days": ship,
    })
    df.loc[rng.choice(n, 4, replace=False), "unit_price"] *= 8
    df["order_total"] = (df["quantity"] * df["unit_price"] * (1 - df["discount_pct"] / 100)).round(2)
    df["rating"] = np.clip(np.round(4.3 - 0.2 * ship + rng.normal(0, 0.8, n)), 1, 5)
    df["returned"] = rng.random(n) < 0.06 + 0.06 * (category == "electronics") + 0.03 * (ship > 6)
    df.loc[rng.random(n) < 0.05, "shipping_days"] = np.nan
    df.loc[rng.random(n) < 0.25, "rating"] = np.nan
    if messy:
        df.loc[rng.choice(n, 25, replace=False), "channel"] = "Paid "
        df.loc[rng.choice(n, 3, replace=False), "quantity"] = -1
        df = pd.concat([df, df.sample(6, random_state=1)], ignore_index=True)
    return df
questions = {
    "Q1 How concentrated is revenue across customers?": ["customer_id", "order_total"],
    "Q2 What goes with low ratings?": ["shipping_days", "rating"],
    "Q3 Which categories are returned most?": ["category", "returned"],
}
raw = make_orders(messy=True)
missing_cols = [c for cols in questions.values() for c in cols if c not in raw.columns]
print("questions ready:", not missing_cols)
print("rows:", len(raw), "| duplicates:", int(raw.duplicated().sum()))
print("channel labels raw:", raw["channel"].nunique(),
      "| clean:", raw["channel"].str.strip().str.lower().nunique())
print("quantity <= 0:", int((raw["quantity"] <= 0).sum()))
print("missing %:", (raw[["shipping_days", "rating"]].isna().mean() * 100).round(1).to_dict())
```

rows: 606 | duplicates: 6
channel labels raw: 5 | clean: 4
quantity <= 0: 3
missing %: {'shipping_days': 4.1, 'rating': 27.4}

### Example 4: Time and cohorts

Weekly revenue for complete weeks is summarised with its slope and the week-to-week standard deviation, as on Day 110. The cohort table from Day 111 gives month-1 retention. def weekly_table(orders):
    first, last = orders["order_date"].min(), orders["order_date"].max()
    weekly = orders.set_index("order_date").resample("W-SUN").agg(
        orders=("order_id", "size"), revenue=("order_total", "sum"),
        returns=("returned", "sum"))
    ends = weekly.index
    starts = ends - pd.to_timedelta(6, unit="D")
    lo = starts.where(starts > first, first)
    hi = ends.where(ends < last, last)
    weekly["days"] = (hi - lo).days + 1
    weekly["aov"] = weekly["revenue"] / weekly["orders"]
    weekly["return_rate"] = weekly["returns"] / weekly["orders"]
    return weekly

orders["first_month"] = orders.groupby("customer_id")["month"].transform("min")

## Real-world applications

- **Onboarding to a new dataset.** The same six-step sequence (questions, profile, clean, explore, check, report) is how an analyst takes over a table at a new employer, and the cleaning function with its row counts is the evidence that the data was handled responsibly.
- **Recurring analytical reports.** A script like Example 5, which regenerates the report from the data, is the basis of a weekly business review and removes manual copy errors.
- **Stakeholder requests.** A short report with three findings, each with its base and caveat, answers "what is going on with returns?" in a form a manager can use.
- **Portfolio work.** A project that shows a cleaning log, checks and a report with honest caveats is the artefact that interviewers ask to see.

## Daily review

### Key takeaways

- Start from written questions and keep the raw data untouched.
- Clean in a function that returns row counts for every step.
- Every number in a report should come from code and carry its base.
- Prefer a few findings with evidence and caveats over many unchecked observations.
- Associations are not causes; say so and suggest the experiment that would settle it.

### Common mistakes

- Starting with charts and tables and writing questions afterwards. Fix: write the questions first and tag later ones as follow-ups.
- Cleaning in place, which destroys the raw table. Fix: return a new table from a function.
- Removing rows without counting them. Fix: return and print the counts at each step.
- Including every table in the summary. Fix: choose three to five findings and move the rest to an appendix.
- Reporting a borderline p-value as a discovery or as "no effect". Fix: label it suggestive and show the interval.
- Forgetting the denominator of ratings and return rates. Fix: print n beside every rate.

### Revision notes

- Order: questions, profile, clean, explore, check, report.
- `clean_orders(raw)` returns `(df, steps)`.
- Quality counts: duplicates 6, bad quantities 3, channel labels 5 down to 4.
- Findings need claim, number, base and caveat.
- Rerunnable script plus appendix of tables.
