## Objectives

- Move around the file system and manage files and folders with `cd`, `ls`, `mkdir`, `touch`, `cp`, `mv`, `rm` and `cat`, using relative and absolute paths.
- Read and set file permissions with `ls -l` and `chmod`, in symbolic and octal form.
- Combine commands with pipes (`|`) and redirection (`>`, `>>`, `<`) to build small data-processing pipelines.
- Search, sort and slice text files with `grep`, `sort`, `cut`, `uniq`, `head`, `tail` and `wc`.
- Use shell basics: variables, exit status, `&&` and `||`, and a `for` loop.

## Understand

### What the shell is

The **command line** is a text interface to the computer. A program called the **shell** (usually `bash` or `zsh`) reads what you type, runs the program you name and shows its output. **Linux** is an operating system whose command-line tools are also found on macOS and in cloud servers, containers and data pipeline machines. Learning a small set of commands lets you inspect files without opening an editor, run jobs on remote servers and automate repetitive tasks.

A command has the form `command options arguments`. Options (also called flags) start with a hyphen, such as `-l`. Arguments are what the command works on, such as a file name. For example, `ls -l data` runs `ls` with the option `-l` on the folder `data`. Commands print results to **standard output** and error messages to **standard error**, and every command finishes with an **exit status**: 0 means success and any other number means failure.

### Navigating and managing files

The file system is a tree of folders (directories). The **current directory** is where you are. A **path** locates something: an **absolute** path starts at the root `/`, like `/home/ana/data`; a **relative** path starts from the current directory, like `data/raw`. Special names: `.` is the current directory, `..` is the parent, and `~` is your home directory. Core commands:

- `pwd` prints the current directory, `cd folder` moves into it, `cd ..` goes up and `cd` alone goes home.
- `ls` lists a folder; `ls -l` shows details; `ls -a` includes hidden files whose names start with a dot.
- `mkdir name` creates a folder (`-p` creates the parents too), `touch name` creates an empty file.
- `cp source target` copies, `mv source target` moves or renames, and `rm file` deletes. **`rm` has no recycle bin**: deleted files are gone. `rm -r folder` deletes a folder and everything inside, so check the path first.
- `cat file` prints a file, `head -n 3 file` and `tail -n 3 file` print its first and last lines, `wc -l file` counts lines.

A **wildcard** (glob) is expanded by the shell before the command runs: `*.csv` stands for every name that ends in `.csv`, and `?` for one character. Names containing spaces must be quoted, `"my file.txt"`, or the shell treats them as two arguments.

### Permissions

Every file has an owner, a group and permission bits. `ls -l` shows them as ten characters, for example `-rwxr-xr--`. The first character is the type (`-` file, `d` directory). The next nine are three groups of three for the **owner**, the **group** and **others**, each `r` (read), `w` (write) and `x` (execute), with `-` for "not allowed". So `rwxr-xr--` means the owner can read, write and run; the group can read and run; others can only read. `chmod` changes them. Symbolic form: `chmod u+x script.sh` adds execute for the owner, `chmod go-w file` removes write from group and others. Octal form uses digits where read is 4, write is 2 and execute is 1, added together per group: `chmod 754 file` means owner 7 (rwx), group 5 (r-x), others 4 (r--). A script cannot be run as `./script.sh` unless it has execute permission.

### Redirection and pipes

Output normally goes to the screen. **Redirection** sends it elsewhere: `command > file` writes output to a file and **replaces** its content, `command >> file` appends, and `command < file` feeds a file to the command's input. `2> file` redirects standard error. A **pipe** `a | b` connects the output of `a` to the input of `b`, so small tools combine into pipelines, just like the generator pipelines of Day 26: each stage does one job and passes lines on.

### The text tools

- `grep pattern file` prints lines that contain the pattern (a regular expression, as in Day 28). Useful options: `-i` ignore case, `-v` invert (lines that do not match), `-c` count, `-n` show line numbers. `grep` exits with status 1 when nothing matches.
- `sort` orders lines alphabetically; `-n` sorts numerically, `-r` reverses, and `-t, -k2` chooses a field.
- `cut -d, -f1,3` splits each line on the delimiter `,` and prints the chosen fields.
- `uniq` removes **adjacent** duplicate lines, so sort first; `uniq -c` prefixes counts.
- `wc -l` counts lines.

A classic pipeline for "how many of each value" is `cut -d, -f2 file | sort | uniq -c | sort -rn`.

### Shell basics

A variable is set without spaces around `=` and read with a dollar sign: `name=ana; echo "$name"`. `$?` holds the exit status of the last command. `a && b` runs `b` only if `a` succeeded and `a || b` runs `b` only if `a` failed. A `for` loop runs commands for each item: `for f in *.csv; do echo "$f"; done`. Put a script's commands in a file, make it executable, and the shell becomes an automation tool.

### Common misconception

Learners think the shell is only for system administrators. For data work it is a fast way to peek into a file (`head`), count rows (`wc -l`), find bad lines (`grep`) and chain steps together before writing any Python. Another one: `>` looks harmless but overwrites the target without asking.

## Syntax and key functions

```text
command [options] [arguments]
command > file       # replace file with output
command >> file      # append output
command < file       # read input from file
a | b                # pipe a's output into b
```

Typical data pipeline:

```text
grep -v '^#' data.csv | cut -d, -f2 | sort | uniq -c | sort -rn | head -3
```

It drops comment lines, takes column 2, groups equal values, counts them and shows the three most common.

| Command | What it does |
|---|---|
| `pwd`, `cd`, `ls -l`, `ls -a` | Where am I; move; list with details; include hidden files. |
| `mkdir -p`, `touch`, `cp`, `mv`, `rm`, `rm -r` | Create folder; create file; copy; move or rename; delete; delete folder tree. |
| `cat`, `head -n`, `tail -n`, `wc -l` | Print file; first lines; last lines; count lines. |
| `grep -i -v -c -n` | Filter lines by pattern (ignore case, invert, count, line numbers). |
| `sort -n -r -t, -k2` | Sort lines (numeric, reverse, by field). |
| `cut -d, -f1,3` | Select delimited fields. |
| `uniq`, `uniq -c` | Collapse adjacent duplicates; count them. |
| `chmod u+x`, `chmod 754` | Change permissions (symbolic, octal). |
| `echo`, `$?`, `&&`, `||` | Print text; last exit status; run if success; run if failure. |

## Learn by example

### Example 1: Folders and files

A project folder is created and entered, files are made, copied, renamed and listed. `ls` output is sorted by the shell's locale, and the `C` locale used here sorts plainly. The `rm` at the end deletes a file permanently; `-r` would remove a whole folder.

```bash run
mkdir -p project/raw project/clean
cd project
touch raw/sales.csv raw/stock.csv notes.txt
cp raw/sales.csv clean/sales_backup.csv
mv notes.txt README.txt
ls
ls raw clean
cd raw
ls ../clean
cd ..
rm clean/sales_backup.csv
ls clean | wc -l | tr -d ' '
```

```output
README.txt
clean
raw
clean:
sales_backup.csv

raw:
sales.csv
stock.csv
sales_backup.csv
0
```

### Example 2: Writing, appending and reading files

`>` creates a file and replaces anything in it, `>>` adds to the end, and `cat`, `head`, `tail` and `wc` read it back. The glob `*.txt` is expanded by the shell before `ls` runs.

```bash run
echo "id,city,amount" > orders.csv
echo "1,Oslo,120" >> orders.csv
echo "2,Rome,80" >> orders.csv
echo "3,Oslo,45" >> orders.csv
cat orders.csv
head -n 2 orders.csv
tail -n 1 orders.csv
wc -l < orders.csv | tr -d ' '
echo "reset" > orders.csv
cat orders.csv
touch a.txt b.txt c.csv
ls *.txt
```

```output
id,city,amount
1,Oslo,120
2,Rome,80
3,Oslo,45
id,city,amount
1,Oslo,120
3,Oslo,45
4
reset
a.txt
b.txt
```

### Example 3: grep, cut and sort

The file is filtered, split into fields and sorted. `grep -v` inverts a match, `cut` takes comma-separated fields, and `sort -t, -k3 -n` sorts numerically by the third field. `grep -c` counts the lines that match.

```bash run
cat > sales.csv <<'EOF'
# daily sales
id,city,amount
1,Oslo,120
2,Rome,80
3,Oslo,45
4,Paris,200
5,rome,60
EOF
grep -v '^#' sales.csv | cut -d, -f2,3 | head -n 3
grep -c Oslo sales.csv
grep -i rome sales.csv
grep -v -e '^#' -e '^id' sales.csv | sort -t, -k3 -n | cut -d, -f1,3
grep -n Paris sales.csv
```

```output
city,amount
Oslo,120
Rome,80
2
2,Rome,80
5,rome,60
3,45
5,60
2,80
1,120
4,200
6:4,Paris,200
```

### Example 4: A pipeline that counts

The classic "count by value" pipeline: take the city column, sort so equal values are adjacent, count with `uniq -c`, and sort by count. The `awk` step rewrites each line as `value count` so the spacing is the same on every system (the width of `uniq -c` numbers differs between Linux and macOS).

```bash run
cat > visits.csv <<'EOF'
user,page
ana,home
bo,pricing
ana,pricing
cy,home
bo,home
dee,docs
ana,home
EOF
tail -n +2 visits.csv | cut -d, -f2 | sort | uniq -c | sort -rn | awk '{print $2, $1}'
echo "---"
tail -n +2 visits.csv | cut -d, -f1 | sort -u | wc -l | tr -d ' '
```

```output
home 4
pricing 2
docs 1
---
4
```

### Example 5: Permissions, exit status and a loop

`ls -l` shows permission bits; the first ten characters are cut out so no owner, size or date appears. A script becomes runnable after `chmod u+x`. `$?` shows exit status, `&&` and `||` choose what runs next, and a `for` loop repeats a command. The `umask` line fixes the default permissions so the output is the same everywhere.

```bash run
umask 022
echo 'echo "hello from script"' > run.sh
ls -l run.sh | cut -c1-10
chmod u+x run.sh
ls -l run.sh | cut -c1-10
./run.sh
chmod 640 run.sh
ls -l run.sh | cut -c1-10
test -x run.sh && echo "runnable" || echo "not runnable"
grep -q missing run.sh || echo "grep found nothing, status $?"
for name in ana bo; do echo "user: $name"; done
```

```output
-rw-r--r--
-rwxr--r--
hello from script
-rw-r-----
not runnable
grep found nothing, status 1
user: ana
user: bo
```

### Example 6: The same pipeline in Python

The shell pipeline of Example 4 is reproduced with Python lists, one function per command. This is the graded, browser-safe version of the skill: every stage takes lines in and returns lines, exactly like a pipe.

```python run
from collections import Counter

visits = """user,page
ana,home
bo,pricing
ana,pricing
cy,home
bo,home
dee,docs
ana,home""".splitlines()

def tail_from(lines, n):
    return lines[n - 1:]

def cut(lines, delimiter, field):
    return [line.split(delimiter)[field - 1] for line in lines]

def sort_lines(lines):
    return sorted(lines)

def uniq_c(lines):
    counts = []
    for line in lines:
        if counts and counts[-1][0] == line:
            counts[-1][1] += 1
        else:
            counts.append([line, 1])
    return counts

pipeline = uniq_c(sort_lines(cut(tail_from(visits, 2), ",", 2)))
for value, count in sorted(pipeline, key=lambda p: -p[1]):
    print(value, count)
print(Counter(cut(tail_from(visits, 2), ",", 2)).most_common(1))
```

```output
home 4
pricing 2
docs 1
[('home', 4)]
```

## Real-world applications

- **Inspecting data files.** `head`, `tail`, `wc -l` and `grep` (Examples 2 and 3) answer "how big is this file, what does it look like, which lines are bad" in seconds, before any Python code is written.
- **Quick aggregations on a server.** A pipeline such as Example 4 counts events by type from a log on a machine that has no database.
- **Automating jobs.** A script with `chmod u+x`, variables, `&&` and a loop (Example 5) is how many scheduled data jobs start; the scheduler runs a shell command.
- **Debugging deployments.** Reading permissions with `ls -l` explains "permission denied" errors when a job cannot read an input file or run a script.

## Daily review

### Key takeaways

- A command is `name options arguments`; paths are absolute (from `/`) or relative; `.`, `..` and `~` are shortcuts.
- `>` replaces a file, `>>` appends, `|` connects commands; each stage handles lines of text.
- `grep` filters, `cut` selects fields, `sort` orders, `uniq -c` counts adjacent duplicates (sort first).
- Permissions are `rwx` for owner, group and others; octal 4, 2, 1 add up; `chmod u+x` makes a script runnable.
- Exit status 0 means success; `&&` and `||` branch on it.

### Common mistakes

- Using `>` instead of `>>` and wiping a file. Check which operator you typed.
- Running `rm -r` with a wrong path or wildcard, which deletes data without recovery. Run `ls` with the same arguments first.
- Using `uniq` on unsorted input and getting duplicates. Sort first: `sort | uniq -c`.
- Spaces in file names without quotes, so `rm my file.txt` tries to delete two files. Quote the name.
- Putting spaces around `=` in a variable assignment, `name = ana`, which runs a command called `name`. Write `name=ana`.
- Forgetting `chmod +x` and then seeing `Permission denied` when running `./script.sh`.
- Sorting numbers as text: `sort` puts `100` before `20`. Use `sort -n`.

### Revision notes

- `pwd`, `cd`, `ls -l`, `mkdir -p`, `touch`, `cp`, `mv`, `rm`, `cat`, `head`, `tail`, `wc -l`.
