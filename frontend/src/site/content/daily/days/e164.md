## Understand

### Column expressions

Day 163 showed that a Spark DataFrame operation is a description of work. The unit of description is the **column expression**, a value that stands for a column or a computation on columns. `F.col("amount")` (or `df["amount"]`) is a column; `F.col("amount") * 2` is another column expression; `F.lit(10)` is a constant column. Expressions are not evaluated when you write them. They are handed to a transformation, and Spark evaluates them for every row when an action runs the plan. This is why you never write a Python loop over rows: you describe one expression and Spark applies it everywhere, in parallel and in its own optimised engine.

The expressions you will use most are arithmetic (`+ - * /`), comparison (`== != > >= < <=`), the conditional `F.when(condition, value).otherwise(other)`, which is SQL's `CASE WHEN`, `.cast("double")` to change a type, `.alias("name")` to name a result, `F.round(col, 2)`, `F.coalesce(col, F.lit(0))` to replace nulls, and string and date functions (Day 165). Python's `==` on a column builds an expression and does not return a boolean, so `if df["a"] == 1:` is an error: use `F.when` or `filter`.

### select, withColumn and drop

`select` chooses and computes columns and returns a new DataFrame containing only what you list: `df.select("order_id", (F.col("amount") * 1.2).alias("gross"))`. `withColumn(name, expr)` returns a DataFrame with one extra column (or a replaced one, if the name exists) and keeps all the others; chaining many `withColumn` calls works but `select` with several expressions is neater for many columns. `withColumnRenamed` renames a column and `drop` removes one. All of them are narrow transformations: they act on each partition on its own and need no shuffle. `selectExpr` and `F.expr` accept SQL text, such as `df.selectExpr("amount * 2 AS double_amount")`, which is useful when you know the SQL and Day 165 returns to this.

### filter

`filter` (alias `where`) keeps rows for which a boolean column expression is true: `df.filter(F.col("amount") >= 30)`. Several conditions are joined with `&` (and), `|` (or) and `~` (not). These are Python's bitwise operators, which bind more tightly than comparisons, so every comparison must be wrapped in parentheses: `(F.col("category") == "books") & (F.col("amount") > 20)`. Without the parentheses Python reads `F.col("category") == ("books" & F.col("amount")) > 20` and fails with a confusing error. Useful column methods are `isin("a", "b")`, `between(10, 50)` (inclusive on both ends), `isNull()` and `isNotNull()`, and string tests such as `startswith` and `contains`. The `and`, `or` and `not` keywords do not work on columns.

### Aggregations

`groupBy("category")` groups rows and returns a grouped object; `.agg(...)` computes aggregate expressions per group: `F.sum`, `F.avg`, `F.min`, `F.max`, `F.count`, `F.countDistinct`. Give each result a name with `alias`, or Spark invents names such as `sum(amount)`. `df.agg(...)` without `groupBy` aggregates the whole DataFrame into one row. `groupBy` is a wide transformation, so it triggers a shuffle (Day 166), but Spark first aggregates inside each partition, so only partial results move. The result has no guaranteed order: add `orderBy` when order matters, for example `orderBy(F.desc("total"))`.

### Nulls

Missing values are `null` in Spark and `NULL` in SQL. A comparison with a null is neither true nor false but null, and `filter` keeps only rows where the condition is true. So `F.col("discount") == None` and `F.col("discount") != 5` both drop the null rows; use `isNull()` to find them, or `eqNullSafe` for a comparison that treats two nulls as equal. Aggregations skip nulls: `F.sum` and `F.avg` ignore them (the average divides by the number of non-null values), `F.count("discount")` counts only non-null values, while `F.count("*")` counts rows. `F.coalesce(col, F.lit(0))` replaces nulls, and `df.na.fill(0)` and `df.dropna()` do it for whole DataFrames. Whether a null should count as zero or be ignored is a business decision, and a silent difference between the two is a common source of wrong averages.

### Order of work and naming

A chain of transformations is read from top to bottom, and each step sees only the columns that the step before it produced. A `select` that lists three columns removes all the others for every later step, and a filter written after an aggregation sees the aggregated column names, not the original ones. Filtering early, before a `groupBy` or a join, is usually a good habit, because fewer rows reach the expensive step; Spark's optimiser often reorders simple filters for you, but it cannot repair a plan that computes something large that is thrown away later. Name results with `alias` as you create them, keep names lower snake case so they work in SQL on Day 165, and avoid dots and spaces in column names, which need backticks in expressions.

### Why it matters

Almost every Spark job is a chain of these operations. Writing them as column expressions, not Python loops, is what lets Spark optimise and distribute the work, and null handling decides whether a total or an average is correct. The misconception to remove from pandas habits is that you can index and modify cells: a Spark DataFrame is immutable and expressions describe whole columns.

## Syntax and key functions

```python
from pyspark.sql import functions as F

df.select("order_id", (F.col("amount") * 1.2).alias("gross"))
df.withColumn("size", F.when(F.col("amount") >= 30, "big").otherwise("small"))
df.filter((F.col("category") == "books") & F.col("amount").between(20, 50))
df.groupBy("category").agg(F.sum("amount").alias("total"), F.count("*").alias("orders"))
```

| Function or method | Returns |
|---|---|
| `F.col(name)`, `F.lit(v)` | A column, a constant column. |
| `select(...)`, `withColumn(n, e)`, `drop(...)` | New DataFrame with chosen, added or removed columns. |
| `F.when(c, v).otherwise(w)` | Conditional column (SQL `CASE WHEN`). |
| `filter(cond)` / `where(cond)` | Rows where the condition is true. |
| `isin`, `between`, `isNull`, `isNotNull` | Boolean column expressions. |
| `groupBy(...).agg(...)` | One row per group with the aggregates. |
| `F.sum`, `F.avg`, `F.count`, `F.countDistinct`, `F.max`, `F.min` | Aggregate expressions; nulls are skipped. |
| `F.coalesce(c, F.lit(0))` | The first non-null value. |
| `alias(name)`, `cast(type)` | Rename or retype a column expression. |

## Learn by example

### Example 1: select and a conditional column

The PySpark job is `orders.select("order_id", "amount", F.when(F.col("amount") >= 30, "big").otherwise("small").alias("size"))`. In pandas it is `np.where`, in SQL a `CASE`.

```python run
import zlib

COLS = ["order_id", "customer_id", "category", "amount"]
ROWS = [
    (1, "c1", "books", 20), (2, "c2", "books", 35), (3, "c1", "games", 60), (4, "c3", "games", 15),
    (5, "c2", "music", 10), (6, "c4", "books", 45), (7, "c3", "music", 30), (8, "c1", "books", 25),
    (9, "c4", "games", 80), (10, "c5", "music", 12), (11, "c2", "games", 70), (12, "c5", "books", 18),
]

def show(rows, cols, n=20):
    """Format rows the way DataFrame.show() prints them."""
    cells = [[str(v) for v in r] for r in rows[:n]]
    widths = [max(len(c), *(len(r[i]) for r in cells)) if cells else len(c) for i, c in enumerate(cols)]
    line = "+" + "+".join("-" * w for w in widths) + "+"
    out = [line, "|" + "|".join(c.rjust(w) for c, w in zip(cols, widths)) + "|", line]
    out += ["|" + "|".join(v.rjust(w) for v, w in zip(r, widths)) + "|" for r in cells]
    return "\n".join(out + [line])

def slices(rows, n):
    size = -(-len(rows) // n)
    return [rows[i * size:(i + 1) * size] for i in range(n)]

def target(key, n):
    return zlib.crc32(str(key).encode()) % n

import numpy as np
import pandas as pd

df = pd.DataFrame(ROWS, columns=COLS)
out = df[["order_id", "amount"]].copy()
out["size"] = np.where(df["amount"] >= 30, "big", "small")
print(show(out.head(6).values.tolist(), ["order_id", "amount", "size"]))
print(out["size"].value_counts().sort_index().to_dict())
```

```output
+--------+------+-----+
|order_id|amount| size|
+--------+------+-----+
|       1|    20|small|
|       2|    35|  big|
|       3|    60|  big|
|       4|    15|small|
|       5|    10|small|
|       6|    45|  big|
+--------+------+-----+
{'big': 6, 'small': 6}
```

```sql run
WITH orders(order_id, customer_id, category, amount) AS (
  VALUES (1,'c1','books',20),(2,'c2','books',35),(3,'c1','games',60),(4,'c3','games',15),
         (5,'c2','music',10),(6,'c4','books',45),(7,'c3','music',30),(8,'c1','books',25),
         (9,'c4','games',80),(10,'c5','music',12),(11,'c2','games',70),(12,'c5','books',18)
)
SELECT CASE WHEN amount >= 30 THEN 'big' ELSE 'small' END AS size, COUNT(*) AS orders
FROM orders
GROUP BY 1
ORDER BY 1
```

```output
size | orders
big | 6
small | 6
```

Six orders are big and six are small, and the first rows show the column added by `when/otherwise`. The boundary is the point to check: an amount of exactly 30 (order 7) is big because the condition is `>=`.

### Example 4: Nulls in comparisons and aggregates

Some orders have no discount recorded. Compare `== None`, `isNull()` and the aggregates.

```output
2 4
20.0 5.0 6

```

```sql run
WITH o(order_id, category, amount, discount) AS (
  VALUES (1,'books',20,NULL),(2,'books',35,5),(3,'games',60,10),(4,'games',15,NULL),(5,'music',10,0),(6,'books',45,5)
)
SELECT COUNT(*) AS rows_total, COUNT(discount) AS non_null, SUM(discount) AS total,
       ROUND(AVG(discount)::numeric, 2) AS avg_ignoring_nulls,
       ROUND(AVG(COALESCE(discount, 0))::numeric, 2) AS avg_nulls_as_zero,
       COUNT(*) FILTER (WHERE discount = NULL) AS equals_null,
       COUNT(*) FILTER (WHERE discount IS NULL) AS is_null
FROM o
```

```output
rows_total | non_null | total | avg_ignoring_nulls | avg_nulls_as_zero | equals_null | is_null
6 | 4 | 20 | 5.00 | 3.33 | 0 | 2
```

Two of the six discounts are missing. Sums and averages skip them: the total is 20, the average of the four known values is 5.0, but if the missing discounts mean zero the average is 3.3333. `COUNT(discount)` counts 4 non-null values while `COUNT(*)` counts 6 rows. The comparison with null matches nothing (`equals_null` is 0) and only the null test finds the 2 missing rows; PySpark's `F.col("discount") == None` behaves the same way as the SQL, so use `isNull()`.

### Example 5: A chain of expressions

Compute the net amount after discount, treating a missing discount as zero, and total it by category: `withColumn("net", F.col("amount") * (1 - F.coalesce(F.col("discount"), F.lit(0)) / 100))` followed by `groupBy("category").agg(F.sum("net"))`.

```python run
import zlib

COLS = ["order_id", "customer_id", "category", "amount"]
ROWS = [
    (1, "c1", "books", 20), (2, "c2", "books", 35), (3, "c1", "games", 60), (4, "c3", "games", 15),
    (5, "c2", "music", 10), (6, "c4", "books", 45), (7, "c3", "music", 30), (8, "c1", "books", 25),
    (9, "c4", "games", 80), (10, "c5", "music", 12), (11, "c2", "games", 70), (12, "c5", "books", 18),
]

def show(rows, cols, n=20):
    """Format rows the way DataFrame.show() prints them."""
    cells = [[str(v) for v in r] for r in rows[:n]]
    widths = [max(len(c), *(len(r[i]) for r in cells)) if cells else len(c) for i, c in enumerate(cols)]
    line = "+" + "+".join("-" * w for w in widths) + "+"
    out = [line, "|" + "|".join(c.rjust(w) for c, w in zip(cols, widths)) + "|", line]
    out += ["|" + "|".join(v.rjust(w) for v, w in zip(r, widths)) + "|" for r in cells]
    return "\n".join(out + [line])

def slices(rows, n):
    size = -(-len(rows) // n)
    return [rows[i * size:(i + 1) * size] for i in range(n)]

def target(key, n):
    return zlib.crc32(str(key).encode()) % n

import pandas as pd

rows = [(1, "books", 20, None), (2, "books", 35, 5), (3, "games", 60, 10), (4, "games", 15, None), (5, "music", 10, 0), (6, "books", 45, 5)]
df = pd.DataFrame(rows, columns=["order_id", "category", "amount", "discount"])
df["net"] = df["amount"] * (1 - df["discount"].fillna(0) / 100)
out = df.groupby("category", as_index=False).agg(net_total=("net", "sum"), orders=("order_id", "count"))
print(out.round(2).to_string(index=False))
```

```output
category  net_total  orders
   books       96.0       3
   games       69.0       2
   music       10.0       1
```

```sql run
WITH o(order_id, category, amount, discount) AS (
  VALUES (1,'books',20,NULL),(2,'books',35,5),(3,'games',60,10),(4,'games',15,NULL),(5,'music',10,0),(6,'books',45,5)
)
SELECT category, ROUND(SUM(amount * (1 - COALESCE(discount, 0) / 100.0))::numeric, 2) AS net_total, COUNT(*) AS orders
FROM o
GROUP BY category
ORDER BY category
```

```output
category | net_total | orders
books | 96.00 | 3
games | 69.00 | 2
music | 10.00 | 1
```

Books net 96.00 over three orders (20, 33.25 and 42.75), games 69.00 and music 10.00. The computation is identical in pandas and SQL, which is the check that the PySpark chain `withColumn` then `groupBy().agg()` gives the same three rows. Without `coalesce` the missing discounts would make `net` null for orders 1 and 4 and silently remove them from the sums.

## Real-world applications

- **Feature and flag columns.** `when/otherwise` creates size bands, risk flags or clean category labels on billions of rows (Example 1).
- **Segment filters.** Combined filters select the customers or events for a report or a model (Example 2).
- **Daily and monthly aggregates.** `groupBy().agg()` builds the summary tables that dashboards read (Example 3).
- **Data quality.** Counting nulls with `isNull` and comparing `count("*")` with `count(col)` is the first check on a new dataset (Example 4).

## Daily review

### Key takeaways

- Column expressions describe a computation per row; Spark evaluates them when an action runs.
- `select`, `withColumn`, `filter` are narrow; `groupBy().agg()` is wide.
- Combine conditions with `&`, `|` and `~` and parenthesise every comparison.
- Aggregations skip nulls; `count("*")` counts rows and `count(col)` counts non-nulls.
- Use `isNull`, `coalesce` and `na.fill`, not `== None`.

### Common mistakes

- Writing `F.col("a") > 1 & F.col("b") == 2` without parentheses and getting an error about ambiguous truth values.
- Using `and`/`or` between columns instead of `&`/`|`.
- Filtering with `== None` and finding no rows.
- Averaging a column with nulls without deciding whether a null means zero or unknown.
- Forgetting `alias`, so the result column is called `sum(amount)`.

### Revision notes

- `F.col`, `F.lit`, `alias`, `cast`, `F.when(...).otherwise(...)`, `F.coalesce`.
- `filter` with `&`, `|`, `~`, `isin`, `between` (inclusive), `isNull`.
- `groupBy(...).agg(F.sum, F.avg, F.count, F.countDistinct, F.max)`.
- Nulls: comparisons give null; aggregates skip nulls.
