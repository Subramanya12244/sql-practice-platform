## Objectives

- Create a dictionary, read, add, change and delete entries by key.
- Use `get()` to read a key that might be missing without an error, and `in` to test for a key.
- Read all keys, values and key-value pairs with `keys()`, `values()` and `items()`.
- Merge dictionaries with `update()` and read and change nested dictionaries.
- Count occurrences with `get(key, 0) + 1`.

## Understand

### What a dictionary is

A **dictionary** (type `dict`) stores values under **keys**. Instead of asking for the item at position 2, you ask for the value labelled `"age"`. A dictionary is written in curly brackets with `key: value` pairs:

```text
customer = {"name": "Ada", "age": 36, "city": "London"}
```

Think of a paper address book: you look someone up by name, not by page number. Each key appears at most once, and each key has exactly one value. Keys must be immutable, so strings, numbers and tuples work and lists do not. Values can be anything, including lists and other dictionaries. Dictionaries keep the order in which keys were first added (this is guaranteed in current Python), but you never use a position to read them.

Dictionaries are the natural shape for one record of data: a row of a table with named columns, a JSON object, a configuration. A list of dictionaries is how a small table looks in Python.

### Reading, adding, changing, deleting

You read with square brackets and the key: `customer["city"]` is `"London"`. Asking for a key that does not exist raises `KeyError: 'phone'`. Assigning to a key either changes the existing value or, if the key is new, adds an entry: `customer["age"] = 37` changes, `customer["phone"] = "555"` adds. `del customer["phone"]` removes an entry, and `customer.pop("phone")` removes it and returns its value. `len(customer)` is the number of entries.

### Safe reading with get() and in

The `get(key)` method returns the value, or `None` if the key is missing, instead of raising an error. A second argument gives a default: `customer.get("phone", "unknown")`. The test `"phone" in customer` checks keys, not values, and gives `True` or `False`. A common misconception: `in` on a dictionary does not search the values. To search values, use `x in customer.values()`.

### keys(), values() and items()

`keys()` gives the keys, `values()` the values and `items()` the pairs, each pair a tuple `(key, value)`. These return special **view** objects that track the dictionary, so wrap them in `list()` to see them or to index them. Pairs can be unpacked into two names, using what you learned about tuples on Day 9. Tomorrow you will go through these one by one with a loop; today you use `list()`, `sorted()`, `len()` and `sum()` on them.

### update(): merging

`a.update(b)` copies every entry of `b` into `a`. Keys that exist in both take the value from `b`, so the later data wins. New keys are added. `update` changes `a` in place and returns `None`.

### Nested dictionaries

A value can itself be a dictionary, which models structured data:

```text
order = {"id": 7, "customer": {"name": "Ada", "city": "London"}}
```

Read through the levels one key at a time: `order["customer"]["city"]`. If a middle key is missing you get `KeyError`, so use `get` with an empty dictionary default when a level may be absent: `order.get("shipping", {}).get("city")`.

### Counting

Counting how often something occurs is the classic dictionary job: the key is the thing counted and the value is the count. The idiom is

```text
counts[item] = counts.get(item, 0) + 1
```

If `item` has not been seen, `get` returns the default 0, so the new count is 1; otherwise it adds one to the stored count. Writing `counts[item] += 1` on a key that does not exist yet raises `KeyError`, which is why the `get` form is used. Without loops you would repeat that line once per item; Day 11 shows how a loop does it for any number of items.

### Why it matters

Almost all real data, whether JSON from a web service or a row from a database, arrives as keys and values. Mastering dictionaries is mastering the shape of data.

### A worked trace of the counting idiom

Suppose `counts` starts as `{}` and Python meets `"red"`. It evaluates the right-hand side first: `counts.get("red", 0)` finds no key and gives 0, so `0 + 1` is 1, and the assignment stores `counts["red"] = 1`. The dictionary is now `{"red": 1}`. Meeting `"blue"` gives `{"red": 1, "blue": 1}`. Meeting `"red"` again, `get` now finds 1, so the new value is 2, and the assignment replaces the old value because the key already exists. Each key therefore holds one running total, and the order of the keys is the order in which they first appeared.

Two further points matter in data work. First, keys must be immutable for the same reason as set items: Python files each key using a hash, so a key that could change would be lost. That is why a tuple such as `("2025", "Q1")` can be a key but a list cannot. Second, like lists, dictionaries are shared on assignment: `b = a` gives one dictionary two names, and `a.copy()` makes a separate (shallow) copy. Changing a configuration dictionary through a second name is a common source of confusing bugs.

## Syntax and key functions

```text
d = {"a": 1, "b": 2}        empty = {}
d["a"]                       # read, KeyError if missing
d["c"] = 3                   # add or change
del d["a"]                   # delete
d.get("z")  d.get("z", 0)    # safe read
"a" in d                     # key test
d.update(other)              # merge, other wins
d["x"]["y"]                  # nested read
```

| Tool | What it returns |
|---|---|
| `d[key]` | the value, or `KeyError` |
| `d.get(key, default)` | the value, or `default` (`None` if omitted) |
| `d.keys()`, `d.values()`, `d.items()` | views of keys, values, and `(key, value)` tuples |
| `d.pop(key)` | the removed value |
| `d.update(other)` | `None` (changes `d`) |
| `len(d)` | the number of entries |
| `key in d` | `True` if the key exists |
| `sorted(d)` | a sorted list of the keys |

## Learn by example

### Example 1: Create, read, change

```python run
customer = {"name": "Ada", "age": 36, "city": "London"}
print(customer["name"], len(customer))
customer["age"] = 37
customer["phone"] = "555-0101"
print(customer)
del customer["phone"]
print("phone" in customer, "name" in customer, "London" in customer)
```

```output
Ada 3
{'name': 'Ada', 'age': 37, 'city': 'London', 'phone': '555-0101'}
False True False
```

`"London" in customer` is `False`: `in` checks keys only.

### Example 2: Missing keys

```python run
prices = {"apple": 0.5, "pear": 0.75}
print(prices.get("apple"))
print(prices.get("kiwi"))
print(prices.get("kiwi", 0))
print("kiwi" in prices)
if "kiwi" in prices:
    print(prices["kiwi"])
else:
    print("no kiwi price")
```

```output
0.5
None
0
False
no kiwi price
```

`get` never raises an error. Reading `prices["kiwi"]` directly would raise `KeyError: 'kiwi'`, so the program checks `in` first and only reads the key when it exists.

### Example 3: keys, values and items

```python run
stock = {"pens": 120, "ink": 15, "paper": 60}
print(list(stock.keys()))
print(list(stock.values()))
print(list(stock.items()))
print(sum(stock.values()), max(stock.values()))
print(sorted(stock))
name, qty = list(stock.items())[1]
print(name, qty)
```

```output
['pens', 'ink', 'paper']
[120, 15, 60]
[('pens', 120), ('ink', 15), ('paper', 60)]
195 120
['ink', 'paper', 'pens']
ink 15
```

Each item is a tuple, so `list(stock.items())[1]` can be unpacked into two names.

### Example 4: update and nested dictionaries

```python run
settings = {"theme": "light", "language": "en"}
overrides = {"theme": "dark", "font": 14}
settings.update(overrides)
print(settings)
order = {"id": 7, "customer": {"name": "Ada", "city": "London"}, "lines": [3, 5]}
print(order["customer"]["city"])
order["customer"]["city"] = "Paris"
print(order["customer"])
print(order.get("shipping", {}).get("city", "no shipping"))
```

```output
{'theme': 'dark', 'language': 'en', 'font': 14}
London
{'name': 'Ada', 'city': 'Paris'}
no shipping
```

`theme` took the value from `overrides`, because the later data wins.

### Example 5: Counting

```python run
counts = {}
counts["red"] = counts.get("red", 0) + 1
counts["blue"] = counts.get("blue", 0) + 1
counts["red"] = counts.get("red", 0) + 1
counts["red"] = counts.get("red", 0) + 1
print(counts)
print(counts["red"], counts.get("green", 0))
```

```output
{'red': 3, 'blue': 1}
3 0
```

The first time a colour appears, `get` gives 0; afterwards it gives the stored count.

### Example 6: A table as a list of dictionaries

```python run
orders = [
    {"id": 1, "customer": "Ada", "total": 120.0},
    {"id": 2, "customer": "Bo", "total": 80.5},
    {"id": 3, "customer": "Ada", "total": 45.0},
]
totals = {}
totals[orders[0]["customer"]] = totals.get(orders[0]["customer"], 0) + orders[0]["total"]
totals[orders[1]["customer"]] = totals.get(orders[1]["customer"], 0) + orders[1]["total"]
totals[orders[2]["customer"]] = totals.get(orders[2]["customer"], 0) + orders[2]["total"]
print(totals)
print(orders[1]["total"] > orders[2]["total"])
print(orders[0]["id"], orders[2]["id"])
```

```output
{'Ada': 165.0, 'Bo': 80.5}
True
1 3
```

The three repeated lines show the pattern that a loop will replace on Day 11. The last line reads the ids of the first and third orders, which are Ada's.

## Real-world applications

- **One record.** A customer, product or log entry is a dictionary whose keys are the column names.
- **JSON data.** Data from web services and configuration files is nested dictionaries and lists, read with chained keys.
- **Lookups.** A dictionary from product code to price answers "what is the price of X?" instantly, with `get` supplying a default.
- **Frequency tables.** Counting events, words or categories with `get(key, 0) + 1` is the plain-Python version of `GROUP BY ... COUNT(*)`.

## Daily review

### Key takeaways

- A dictionary maps unique, immutable keys to values; you read by key, not by position.
- `d[key]` raises `KeyError` for a missing key; `get()` does not.
- `in` tests keys; use `.values()` to search values.
- `items()` gives `(key, value)` tuples; wrap views in `list()` to see them.
- `update()` merges with the later value winning; counting uses `counts[k] = counts.get(k, 0) + 1`.

### Common mistakes

- **Reading a missing key with brackets.** `d["phone"]` raises `KeyError: 'phone'`. Use `d.get("phone")` or check `in` first.
- **Expecting `in` to search values.** `"London" in customer` is `False`. Use `"London" in customer.values()`.
- **Using `+= 1` before the key exists.** `counts["red"] += 1` raises `KeyError`. Use `counts.get("red", 0) + 1`.
- **Using `{}` expecting a set.** `{}` is an empty dictionary.
- **Using a list as a key.** `{[1, 2]: "x"}` raises `TypeError: unhashable type: 'list'`. Use a tuple.
- **Assigning the result of `update`.** `d = d.update(x)` makes `d` equal to `None`. Call `d.update(x)` on its own.

### Revision notes

- `{key: value}`; read `d[k]`; add or change `d[k] = v`; `del d[k]`.
- `d.get(k, default)`; `k in d` tests keys.
- `keys()`, `values()`, `items()`; `list()` to display.
- `a.update(b)`: `b` wins. Nested: `d["a"]["b"]`.
- Count: `d[k] = d.get(k, 0) + 1`.
