## Understand

### Why Spark exists

pandas works on one machine and needs the data to fit in its memory. When a table has billions of rows, or the computation must finish in minutes, one machine is not enough. **Apache Spark** is an engine that splits data into pieces, runs the same computation on many pieces at once on a cluster of machines, and combines the results. PySpark is its Python interface. The ideas you know from pandas and SQL carry over: select, filter, group, join, window. What changes is where and when the work happens. Spark and Java are not available in this course's tests or browser, so the examples show PySpark code as text and check every result with equivalents that run: pandas, SQL on PGlite, and small pure-Python models of Spark's behaviour.

### Architecture

A Spark application has one **driver** and many **executors**. The driver is the process that runs your program: it creates the `SparkSession`, turns your DataFrame operations into a plan and schedules the work. The executors are worker processes, on cluster machines, that hold pieces of the data and run **tasks** on them. A **cluster manager** (Spark's standalone manager, YARN or Kubernetes) provides the machines. In **local mode** (`master("local[*]")`) everything runs on your own computer, with threads acting as executors, which is how you learn and test. A Spark DataFrame is split into **partitions**, pieces of rows; one task processes one partition, so the number of partitions is the amount of parallelism.

```python
from pyspark.sql import SparkSession, functions as F

spark = SparkSession.builder.master("local[*]").appName("orders").getOrCreate()

orders = spark.createDataFrame(
    [(1, "c1", "books", 20), (2, "c2", "books", 35), (3, "c1", "games", 60)],
    ["order_id", "customer_id", "category", "amount"],
)
orders.printSchema()
```

### DataFrames

A Spark **DataFrame** is a table with named, typed columns, like a pandas DataFrame or a SQL table, but distributed across partitions and **immutable**: an operation never changes a DataFrame, it returns a new one. Its **schema** (column names and types) is known to Spark, which is what lets the engine optimise a query before running it. The entry point is the `SparkSession`; `spark.createDataFrame` builds a small DataFrame from Python data and `spark.read` loads files (Day 167). Columns are referred to with `F.col("amount")` or `df["amount"]`, and expressions on them are built with operators, such as `F.col("amount") * 2`. These expressions are not values; they are descriptions of a computation that Spark will run later.

### Transformations and actions

Operations come in two kinds. A **transformation** takes a DataFrame and returns a new DataFrame: `select`, `filter`, `withColumn`, `groupBy(...).agg(...)`, `join`, `orderBy`. A transformation does no work; it only adds a step to the plan. An **action** asks for a result and makes Spark run the plan: `show()`, `count()`, `collect()`, `take(n)`, `first()`, and writing to storage with `write`. This is **lazy evaluation**. It matters for three reasons. Spark can look at the whole chain of steps and optimise it before running, for example by pushing a filter before a join or reading only the columns that are used. It does not compute intermediate results that nobody asks for. And it can recompute a lost partition from the plan if an executor fails. The practical consequence is that code which looks slow or broken may not have run at all yet, and that every action runs the whole plan again unless you cache the result.

### Narrow and wide transformations, stages

Transformations are **narrow** when each output partition depends on one input partition: `select`, `filter`, `withColumn`. They need no data movement and run independently on each partition. They are **wide** when an output partition needs rows from many input partitions: `groupBy`, `join` (in general), `orderBy`, `distinct`. A wide transformation requires a **shuffle**, which redistributes rows across the network so that rows with the same key meet on one partition. Spark places a **stage** boundary at each shuffle: a stage is a run of narrow steps executed as tasks, one per partition, and the number of stages is one more than the number of shuffles in a job. Shuffles are the expensive part of Spark (Day 166), so reading a plan means counting them. `df.explain()` prints the plan, and shuffles appear as `Exchange` operators.

### Why it matters

The common mistakes in Spark come from forgetting that it is lazy and distributed. A `collect()` on a large DataFrame pulls everything into the driver's memory and can crash it. A loop that calls `count()` after each step runs the plan again each time. A wide operation in the middle of a chain can dominate the run time. The misconception to unlearn from pandas is that a line of code does its work when it executes: in Spark the work happens at the action.

## Syntax and key functions

```python
spark = SparkSession.builder.master("local[*]").appName("name").getOrCreate()
df = spark.createDataFrame(rows, ["col1", "col2"])
result = df.filter(F.col("amount") > 30).withColumn("amount_k", F.col("amount") / 1000)
result.show()
```

| Item | Kind | What it does |
|---|---|---|
| `select`, `filter`, `withColumn`, `drop` | narrow transformation | New DataFrame, per-partition work, nothing runs. |
| `groupBy().agg()`, `join`, `orderBy`, `distinct` | wide transformation | New DataFrame, needs a shuffle. |
| `show(n)`, `count()`, `collect()`, `take(n)`, `first()` | action | Runs the plan and returns or prints a result. |
| `write` | action | Runs the plan and saves the result. |
| `printSchema()`, `explain()` | inspection | Print the schema or the plan; no data is processed. |
| `df.rdd.getNumPartitions()` | inspection | Number of partitions. |

## Learn by example

### Example 1: A lazy plan in pure Python

This small class mimics a DataFrame: transformations add a step to a plan, and only an action runs it. The counters show when work happens.

```python run
import zlib

COLS = ["order_id", "customer_id", "category", "amount"]
ROWS = [
    (1, "c1", "books", 20), (2, "c2", "books", 35), (3, "c1", "games", 60), (4, "c3", "games", 15),
    (5, "c2", "music", 10), (6, "c4", "books", 45), (7, "c3", "music", 30), (8, "c1", "books", 25),
    (9, "c4", "games", 80), (10, "c5", "music", 12), (11, "c2", "games", 70), (12, "c5", "books", 18),
]

def show(rows, cols, n=20):
    """Format rows the way DataFrame.show() prints them."""
    cells = [[str(v) for v in r] for r in rows[:n]]
    widths = [max(len(c), *(len(r[i]) for r in cells)) if cells else len(c) for i, c in enumerate(cols)]
    line = "+" + "+".join("-" * w for w in widths) + "+"
    out = [line, "|" + "|".join(c.rjust(w) for c, w in zip(cols, widths)) + "|", line]
    out += ["|" + "|".join(v.rjust(w) for v, w in zip(r, widths)) + "|" for r in cells]
    return "\n".join(out + [line])

def slices(rows, n):
    size = -(-len(rows) // n)
    return [rows[i * size:(i + 1) * size] for i in range(n)]

def target(key, n):
    return zlib.crc32(str(key).encode()) % n

class LazyFrame:
    jobs = 0

    def __init__(self, rows, cols, plan=()):
        self.rows, self.cols, self.plan = rows, cols, tuple(plan)

    def filter(self, name, fn):
        return LazyFrame(self.rows, self.cols, self.plan + (("filter", name, fn),))

    def with_column(self, name, fn):
        return LazyFrame(self.rows, self.cols, self.plan + (("withColumn", name, fn),))

    def explain(self):
        return " -> ".join(f"{kind}({name})" for kind, name, _ in self.plan) or "scan"

    def collect(self):
        LazyFrame.jobs += 1
        rows = [dict(zip(self.cols, r)) for r in self.rows]
        for kind, name, fn in self.plan:
            rows = [r for r in rows if fn(r)] if kind == "filter" else [{**r, name: fn(r)} for r in rows]
        return rows

    def count(self):
        return len(self.collect())

df = LazyFrame(ROWS, COLS)
big = df.filter("amount >= 30", lambda r: r["amount"] >= 30)
tagged = big.with_column("amount_k", lambda r: r["amount"] / 1000)
print(LazyFrame.jobs, tagged.explain())
print(tagged.count(), LazyFrame.jobs)
print(tagged.count(), LazyFrame.jobs)
print(df.count(), len(df.plan))
```

```output
0 filter(amount >= 30) -> withColumn(amount_k)
6 1
6 2
12 0
```

After two transformations no job has run (0), and the plan reads `filter(amount >= 30) -> withColumn(amount_k)`. The first `count()` runs the plan and finds 6 rows; the second `count()` runs the whole plan again (2 jobs so far); `df` itself is unchanged and has an empty plan, which shows that transformations return new objects. The real Spark behaves the same way: each action is a new job unless the data is cached.

### Example 2: What `show()` prints

The `show` helper in this example formats rows the way Spark's `DataFrame.show()` does: a border, a header and right-aligned values. It makes the Spark output reproducible here.

```python run
import zlib

COLS = ["order_id", "customer_id", "category", "amount"]

    """Format rows the way DataFrame.show() prints them."""

    widths = [max(len(c), *(len(r[i]) for r in cells)) if cells else len(c) for i, c in enumerate(cols)]
    line = "+" + "+".join("-" * w for w in widths) + "+"

    out += ["|" + "|".join(v.rjust(w) for v, w in zip(r, widths)) + "|" for r in cells]

```

```output
+--------+-----------+--------+------+
|order_id|customer_id|category|amount|
+--------+-----------+--------+------+
|       2|         c2|   books|    35|
|       3|         c1|   games|    60|
|       6|         c4|   books|    45|
|       7|         c3|   music|    30|
+--------+-----------+--------+------+
only showing top 4 rows
6
```

`show()` prints at most 20 rows by default and notes `only showing top N rows` when it truncates. Six orders have an amount of at least 30. In PySpark, `orders.filter(F.col("amount") >= 30).show(4)` prints exactly this table, because `filter` is a transformation and `show` is the action that runs it.

### Example 3: Partitions and narrow transformations

Split the 12 rows into 3 partitions and apply a filter to each partition independently.

```python run
import zlib

COLS = ["order_id", "customer_id", "category", "amount"]
ROWS = [
    (1, "c1", "books", 20), (2, "c2", "books", 35), (3, "c1", "games", 60), (4, "c3", "games", 15),
    (5, "c2", "music", 10), (6, "c4", "books", 45), (7, "c3", "music", 30), (8, "c1", "books", 25),
    (9, "c4", "games", 80), (10, "c5", "music", 12), (11, "c2", "games", 70), (12, "c5", "books", 18),
]

def show(rows, cols, n=20):
    """Format rows the way DataFrame.show() prints them."""
    cells = [[str(v) for v in r] for r in rows[:n]]
    widths = [max(len(c), *(len(r[i]) for r in cells)) if cells else len(c) for i, c in enumerate(cols)]
    line = "+" + "+".join("-" * w for w in widths) + "+"
    out = [line, "|" + "|".join(c.rjust(w) for c, w in zip(cols, widths)) + "|", line]
    out += ["|" + "|".join(v.rjust(w) for v, w in zip(r, widths)) + "|" for r in cells]
    return "\n".join(out + [line])

def slices(rows, n):
    size = -(-len(rows) // n)
    return [rows[i * size:(i + 1) * size] for i in range(n)]

def target(key, n):
    return zlib.crc32(str(key).encode()) % n

parts = slices(ROWS, 3)
print([len(p) for p in parts])
filtered = [[r for r in p if r[3] >= 30] for p in parts]
print([len(p) for p in filtered])
print(sum(len(p) for p in filtered))
skewed = slices(sorted(ROWS, key=lambda r: -r[3]), 3)
print([len([r for r in p if r[3] >= 30]) for p in skewed])
```

```output
[4, 4, 4]
[2, 2, 2]
6
[4, 2, 0]
```

Each partition has 4 rows, and the filter keeps 2 in each, 6 in total; no partition needed to see another one, which is what makes a narrow transformation cheap. The last line sorts the rows by amount before slicing: now the big orders are concentrated in the first partitions (4, 2 and 0), and the last partition has nothing to do. Uneven partitions leave some executors idle, a problem that returns on Day 166.

### Example 4: A wide transformation needs a shuffle

`groupBy("category")` must bring all rows of one category to one partition. Count how many rows have to move to a different partition.

```python run
import zlib

COLS = ["order_id", "customer_id", "category", "amount"]
ROWS = [
    (1, "c1", "books", 20), (2, "c2", "books", 35), (3, "c1", "games", 60), (4, "c3", "games", 15),
    (5, "c2", "music", 10), (6, "c4", "books", 45), (7, "c3", "music", 30), (8, "c1", "books", 25),
    (9, "c4", "games", 80), (10, "c5", "music", 12), (11, "c2", "games", 70), (12, "c5", "books", 18),
]

def show(rows, cols, n=20):
    """Format rows the way DataFrame.show() prints them."""
    cells = [[str(v) for v in r] for r in rows[:n]]
    widths = [max(len(c), *(len(r[i]) for r in cells)) if cells else len(c) for i, c in enumerate(cols)]
    line = "+" + "+".join("-" * w for w in widths) + "+"
    out = [line, "|" + "|".join(c.rjust(w) for c, w in zip(cols, widths)) + "|", line]
    out += ["|" + "|".join(v.rjust(w) for v, w in zip(r, widths)) + "|" for r in cells]
    return "\n".join(out + [line])

def slices(rows, n):
    size = -(-len(rows) // n)
    return [rows[i * size:(i + 1) * size] for i in range(n)]

def target(key, n):
    return zlib.crc32(str(key).encode()) % n

n = 3
parts = slices(ROWS, n)
moved = sum(1 for i, p in enumerate(parts) for r in p if target(r[2], n) != i)
print(moved, "of", len(ROWS), "rows move")
print({k: target(k, n) for k in ["books", "games", "music"]})
stages = 1 + 1
print("stages:", stages)
```

```output
9 of 12 rows move
{'books': 1, 'games': 1, 'music': 2}
stages: 2
```

Each category is assigned to a partition by hashing its name (the model uses a CRC32 hash; Spark uses its own Murmur3 hash, so real assignments differ): books go to partition 1, games to 1 and music to 2. 9 of the 12 rows start on a different partition and must travel. One shuffle gives two stages: the first scans and pre-aggregates, the second combines the groups.

### Example 5: The same result in pandas and SQL

Check a Spark-style aggregation, `df.groupBy("category").agg(F.sum("amount"), F.count("*"))`, with pandas and with SQL.

```python run
import zlib

COLS = ["order_id", "customer_id", "category", "amount"]
ROWS = [
    (1, "c1", "books", 20), (2, "c2", "books", 35), (3, "c1", "games", 60), (4, "c3", "games", 15),
    (5, "c2", "music", 10), (6, "c4", "books", 45), (7, "c3", "music", 30), (8, "c1", "books", 25),
    (9, "c4", "games", 80), (10, "c5", "music", 12), (11, "c2", "games", 70), (12, "c5", "books", 18),
]

def show(rows, cols, n=20):
    """Format rows the way DataFrame.show() prints them."""
    cells = [[str(v) for v in r] for r in rows[:n]]
    widths = [max(len(c), *(len(r[i]) for r in cells)) if cells else len(c) for i, c in enumerate(cols)]
    line = "+" + "+".join("-" * w for w in widths) + "+"
    out = [line, "|" + "|".join(c.rjust(w) for c, w in zip(cols, widths)) + "|", line]
    out += ["|" + "|".join(v.rjust(w) for v, w in zip(r, widths)) + "|" for r in cells]
    return "\n".join(out + [line])

def slices(rows, n):
    size = -(-len(rows) // n)
    return [rows[i * size:(i + 1) * size] for i in range(n)]

def target(key, n):
    return zlib.crc32(str(key).encode()) % n

import pandas as pd

df = pd.DataFrame(ROWS, columns=COLS)
out = df.groupby("category", as_index=False).agg(total=("amount", "sum"), orders=("order_id", "count"))
print(show(out.sort_values("category").values.tolist(), ["category", "total", "orders"]))
```

```output
+--------+-----+------+
|category|total|orders|
+--------+-----+------+
|   books|  143|     5|
|   games|  225|     4|
|   music|   52|     3|
+--------+-----+------+
```

```sql run
WITH orders(order_id, customer_id, category, amount) AS (
  VALUES (1,'c1','books',20),(2,'c2','books',35),(3,'c1','games',60),(4,'c3','games',15),
         (5,'c2','music',10),(6,'c4','books',45),(7,'c3','music',30),(8,'c1','books',25),
         (9,'c4','games',80),(10,'c5','music',12),(11,'c2','games',70),(12,'c5','books',18)
)
SELECT category, SUM(amount) AS total, COUNT(*) AS orders
FROM orders
GROUP BY category
ORDER BY category
```

```output
category | total | orders
books | 143 | 5
games | 225 | 4
music | 52 | 3
```

Books total 143 over 5 orders, games 225 over 4 and music 52 over 3, in pandas and in SQL alike. The PySpark version produces the same three rows (Spark does not promise an order unless you add `orderBy`).

## Real-world applications

- **Large batch jobs.** Nightly aggregation of billions of events that do not fit on one machine is a classic Spark job (Examples 3 and 4).
- **Cost control.** Knowing that only actions run the plan, and that shuffles dominate cost, guides what to cache and how to structure a pipeline.
- **Local development.** Developing with `local[*]` and small data, then running the same code on a cluster, relies on the same plan being executed on more partitions.
- **Debugging.** Reading `explain()` and counting `Exchange` operators tells you where the time goes (Example 4).

## Daily review

### Key takeaways

- A Spark application has a driver, executors, a cluster manager, partitions and tasks.
- DataFrames are distributed, immutable and have a schema.
- Transformations are lazy and build a plan; actions run it, and each action runs it again.
- Narrow transformations work per partition; wide ones shuffle data and start a new stage.
- Check Spark logic with small equivalents in pandas and SQL.

### Common mistakes

- Expecting a transformation to do work and being surprised that nothing happens until an action.
- Calling `collect()` on a large DataFrame and exhausting the driver's memory.
- Calling `count()` repeatedly in a loop, running the whole plan each time.
- Assuming the order of rows in a DataFrame is stable without an `orderBy`.
- Treating Spark like pandas: iterating over rows in Python instead of using column expressions.

### Revision notes

- Driver, executors, cluster manager; local mode; partitions and tasks.
- Transformations (lazy): select, filter, withColumn, groupBy, join. Actions: show, count, collect, write.
- Narrow = no shuffle; wide = shuffle and a new stage.
- `explain()` shows the plan and `Exchange` operators.
