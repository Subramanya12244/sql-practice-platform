- Add and subtract time with `timedelta`, and measure the gap between two dates in days and in seconds.

## Understand

### Dates are values, not text

A date such as `03/04/2026` is ambiguous as text: it is the 4th of March in much of the world and the 3rd of April in the United States. Python's `datetime` module represents moments as proper values that can be compared, sorted and subtracted. Three classes matter. A `date` holds year, month and day. A `datetime` holds a date plus hour, minute, second and microsecond. A `timedelta` holds a duration, a length of time such as 3 days or 90 minutes. The names are in the `datetime` module, so you write `from datetime import date, datetime, timedelta`.

All examples in this lesson use fixed dates. Calling `datetime.now()` or `date.today()` gives a different answer every day, which is fine in a program but makes results impossible to check, so pipelines that must be reproducible pass the date in as an argument.

### Creating and reading

`date(2026, 3, 15)` and `datetime(2026, 3, 15, 14, 30)` create values; the order is always year, month, day, then hour, minute, second. Their parts are attributes: `.year`, `.month`, `.day`, `.hour`, `.minute`. The method `.weekday()` returns the day of the week as a number where Monday is 0 and Sunday is 6 (`.isoweekday()` uses 1 to 7). A date prints in the ISO form `2026-03-15`, which is the standard year-month-day order and sorts correctly as text.

### Arithmetic with timedelta

Subtracting two dates gives a `timedelta`: `date(2026, 3, 15) - date(2026, 3, 1)` is 14 days. Adding a `timedelta` to a date gives a new date: `d + timedelta(days=30)`. A `timedelta` is built from `days`, `seconds`, `minutes`, `hours` or `weeks`. It is stored as days, seconds and microseconds, so `.days` is only the whole-days part. Use `.total_seconds()` for the full length and divide to get hours. A `timedelta` can also be compared (`delta > timedelta(days=7)`) and multiplied by a number. There is no `months` argument, because months have different lengths.

### Parsing and formatting

**Parsing** converts text into a datetime and **formatting** converts a datetime into text. `datetime.strptime(text, format)` parses using a format string made of codes: `%Y` four-digit year, `%m` month number, `%d` day, `%H` hour (24-hour clock), `%M` minute, `%S` second, `%b` short month name (`Mar`), `%B` full month name, `%A` weekday name. The format must match the text exactly, including separators, or Python raises `ValueError`. `datetime.strftime(format)` goes the other way. For ISO text, `date.fromisoformat("2026-03-15")` and `datetime.fromisoformat(...)` are simpler, and `.isoformat()` writes it back. Store and exchange dates in ISO form whenever you can.

### Time zones: naive and aware

A **naive** datetime has no time zone, so it does not say which moment it names: 09:00 is a different instant in Oslo and in Tokyo. An **aware** datetime carries a `tzinfo`, its offset from UTC. UTC (Coordinated Universal Time) is the world reference with no daylight saving. A fixed offset is written `timezone(timedelta(hours=2))`, and `timezone.utc` is UTC. For real regions, with their daylight saving rules, the standard library has `zoneinfo.ZoneInfo("Europe/Berlin")`, which reads the system's time zone database. Convert an aware value to another zone with `.astimezone(zone)`; the moment stays the same and only the displayed clock changes. Add a zone to a naive value with `.replace(tzinfo=zone)`, which relabels without converting, so use it only when you know which zone the naive value was in.

Comparing or subtracting a naive and an aware datetime raises `TypeError`. The safe habit for stored data is to keep timestamps in UTC and convert to local time only for display.

### Common pitfalls

- **Month arithmetic.** There is no month in `timedelta`. Adding 30 days to 31 January lands on 2 March. If you need "the same day next month", compute it from `year` and `month`, and decide what to do when the day does not exist.
- **Daylight saving.** On the day clocks change, a local day is 23 or 25 hours long. Adding `timedelta(days=1)` to an aware local datetime keeps the clock time, not 24 real hours.
- **Naive and aware mixing.** Raises `TypeError`, as above.
- **Ambiguous text.** `03/04/2026` can be read two ways. Always agree on a format.
- **`.days` alone.** `timedelta(hours=36).days` is 1, not 1.5.

### Common misconception

Learners think `astimezone` changes the moment. It never does: 12:00 UTC and 14:00 in a zone two hours ahead are the same instant, and subtracting them gives zero.

### Why it matters

Time drives data work: daily and monthly reports, retention windows, event ordering and incremental loads. A single time zone or month-end mistake silently shifts revenue to the wrong day.

## Syntax and key functions

```python
from datetime import date, datetime, timedelta, timezone

d = date(2026, 3, 15)
dt = datetime.strptime("2026-03-15 14:30", "%Y-%m-%d %H:%M")
later = dt + timedelta(hours=36)
text = later.strftime("%d %b %Y, %H:%M")
aware = dt.replace(tzinfo=timezone.utc)
```

The first line imports the classes. `strptime` parses, `+ timedelta` shifts, `strftime` formats, and `replace(tzinfo=...)` marks a naive value as UTC.

| Call | Returns |
|---|---|
| `date(y, m, d)`, `datetime(y, m, d, h, mi)` | A date or datetime. |
| `d.weekday()` | 0 (Monday) to 6 (Sunday). |
| `d2 - d1` | A `timedelta`. |
| `timedelta(days=, hours=, minutes=, weeks=)` | A duration. |
| `delta.days`, `delta.total_seconds()` | Whole days; the full length in seconds. |
| `datetime.strptime(text, fmt)` | A parsed datetime; `ValueError` on mismatch. |
| `dt.strftime(fmt)` | Formatted text. |
| `date.fromisoformat(s)`, `dt.isoformat()` | Parse and write ISO text. |
| `dt.replace(tzinfo=tz)` | A copy relabelled with the zone. |
| `dt.astimezone(tz)` | The same moment shown in another zone. |
| `timezone.utc`, `timezone(timedelta(hours=n))` | UTC; a fixed offset. |

## Learn by example

### Example 1: Creating dates and reading their parts

Dates are built from numbers and printed in ISO form. Attributes give the parts, `weekday()` gives a number (Monday is 0), and `strftime("%A")` gives the name. A `datetime` adds the time of day.

```python run
from datetime import date, datetime

d = date(2026, 3, 15)
print(d)
print(d.year, d.month, d.day)
print(d.weekday(), d.strftime("%A"))
dt = datetime(2026, 3, 15, 14, 30)
print(dt)
print(dt.hour, dt.minute)
print(d < date(2026, 12, 1))
```

```output
2026-03-15
2026 3 15
6 Sunday
2026-03-15 14:30:00
14 30
True
```

### Example 2: Arithmetic with timedelta

Subtracting dates gives a `timedelta`. Adding one moves a date. Note that `.days` ignores the leftover seconds, while `total_seconds()` divided by 3600 gives hours as a decimal.

```python run
from datetime import date, datetime, timedelta

start = date(2026, 3, 1)
end = date(2026, 3, 15)
gap = end - start
print(gap, gap.days)
print(start + timedelta(days=30))
print(end - timedelta(weeks=2))

delta = datetime(2026, 3, 16, 6, 0) - datetime(2026, 3, 15, 0, 0)
print(delta, delta.days, delta.total_seconds() / 3600)
print(timedelta(hours=36).days, timedelta(hours=36).total_seconds())
```

```output
14 days, 0:00:00 14
2026-03-31
2026-03-01
1 day, 6:00:00 1 30.0
1 129600.0
```

### Example 3: Parsing and formatting

The same moment appears in two different text forms. `strptime` needs a format that matches exactly; a wrong format raises `ValueError`, which is caught and reported. `strftime` writes the value in a new layout, and `isoformat` writes the standard one.

```python run
from datetime import date, datetime

a = datetime.strptime("15/03/2026 14:30", "%d/%m/%Y %H:%M")
b = datetime.strptime("March 15, 2026", "%B %d, %Y")
print(a, b)
print(a.strftime("%d %b %Y, %H:%M"))
print(a.isoformat(), date.fromisoformat("2026-03-15"))
try:
    datetime.strptime("2026-03-15", "%d/%m/%Y")
except ValueError as error:
    print("ValueError:", error)
```

```output
2026-03-15 14:30:00 2026-03-15 00:00:00
15 Mar 2026, 14:30
2026-03-15T14:30:00 2026-03-15
ValueError: time data '2026-03-15' does not match format '%d/%m/%Y'
```

### Example 4: Fixed-offset time zones

A naive value is labelled as UTC and then shown in a zone two hours ahead and one five hours behind. The clock times differ but the moment is the same, so subtracting gives zero. Mixing naive and aware raises `TypeError`.

```python run
from datetime import datetime, timedelta, timezone

utc = datetime(2026, 3, 15, 12, 0, tzinfo=timezone.utc)
plus2 = timezone(timedelta(hours=2))
minus5 = timezone(timedelta(hours=-5))
print(utc)
print(utc.astimezone(plus2))
print(utc.astimezone(minus5))
print(utc - utc.astimezone(plus2))
try:
    utc - datetime(2026, 3, 15, 12, 0)
except TypeError as error:
    print("TypeError:", error)
```

```output
2026-03-15 12:00:00+00:00
2026-03-15 14:00:00+02:00
2026-03-15 07:00:00-05:00
0:00:00
TypeError: can't subtract offset-naive and offset-aware datetimes
```

### Example 5: Named zones and daylight saving

`ZoneInfo` knows the real rules of a region, so the offset of Berlin changes from +01:00 to +02:00 on 29 March 2026. Adding one day keeps the clock time, but only 23 real hours pass, which comparing the UTC values shows. This needs the system time-zone database, so the example is tagged `python local`.

```python local
from datetime import datetime, timedelta
from zoneinfo import ZoneInfo

berlin = ZoneInfo("Europe/Berlin")
utc = ZoneInfo("UTC")
before = datetime(2026, 3, 28, 12, 0, tzinfo=berlin)
after = before + timedelta(days=1)
print(before, before.utcoffset())
print(after, after.utcoffset())
print(after.astimezone(utc) - before.astimezone(utc))
```

```output
2026-03-28 12:00:00+01:00 1:00:00
2026-03-29 12:00:00+02:00 2:00:00
23:00:00
```

### Example 6: A realistic report window

Timestamps arrive as text in two time zones. They are parsed, converted to UTC for comparison, filtered to a seven-day window ending on a fixed date, and grouped by their UTC day. This is the standard shape of a date-range filter in a pipeline.

```python run
from datetime import datetime, timedelta, timezone

raw = [
    ("a", "2026-03-10T23:30:00+02:00"),
    ("b", "2026-03-12T09:00:00+00:00"),
    ("c", "2026-03-14T20:00:00-05:00"),
    ("d", "2026-03-01T10:00:00+00:00"),
]
end = datetime(2026, 3, 15, tzinfo=timezone.utc)
start = end - timedelta(days=7)
by_day = {}
for name, text in raw:
    moment = datetime.fromisoformat(text).astimezone(timezone.utc)
    if start <= moment < end:
        by_day.setdefault(moment.date().isoformat(), []).append(name)
print(start.date(), "to", end.date())
for day in sorted(by_day):
    print(day, by_day[day])
```

```output
2026-03-08 to 2026-03-15
2026-03-10 ['a']
2026-03-12 ['b']
```

## Real-world applications

- **Reporting periods.** Daily, weekly and monthly reports filter rows by date ranges built with `timedelta` (Examples 2 and 6).
- **Cleaning date columns.** Source files write dates in many layouts. `strptime` with the correct format and `isoformat` for output (Example 3) turns them into one reliable form before loading.
- **Combining sources across regions.** Events from servers in different zones are converted to UTC before comparing or ordering them (Examples 4 and 6).
- **Retention and expiry checks.** Rules such as "customers inactive for more than 90 days" subtract dates and compare the result with a `timedelta`.

## Daily review

### Key takeaways

- `date`, `datetime` and `timedelta` are values: you can compare, sort, add and subtract them.
- Subtracting two dates gives a `timedelta`; use `total_seconds()` for the full length, not `.days` alone.
- `strptime` parses text and needs an exactly matching format; `strftime` and `isoformat` write text; prefer ISO form.
- A naive datetime has no zone; an aware one does. Never mix them. Store UTC and convert for display.
- `astimezone` shows the same moment in another zone; `replace(tzinfo=...)` only relabels.

### Common mistakes

- Using the wrong format code, such as `%m` for minutes (it is `%M`) or `%Y` for a two-digit year (`%y`). The result is a `ValueError` or a wrong date.
- Assuming `timedelta(days=30)` is "one month", so 31 January plus 30 days is 2 March, not 28 February.
- Mixing a naive and an aware datetime, which raises `TypeError: can't subtract offset-naive and offset-aware datetimes`.
- Calling `replace(tzinfo=...)` to convert zones. It relabels the clock time without changing it, so the moment is wrong by the offset.
- Reading `delta.days` for a duration of 36 hours and getting 1.
- Using `datetime.now()` inside a function that must be repeatable, so results change every run.
- Reading `03/04/2026` without agreeing on day-first or month-first.

### Revision notes

- `date(y, m, d)`, `datetime(y, m, d, h, mi)`, `timedelta(days=, hours=)`.
- `end - start` gives a `timedelta`; `.total_seconds()` for the exact length.
- `%Y %m %d %H %M %S %b %B %A`; `strptime` parses, `strftime` formats.
- `timezone.utc`, `dt.astimezone(zone)`, `dt.replace(tzinfo=zone)` (label only).
- Weekday: Monday is 0.
