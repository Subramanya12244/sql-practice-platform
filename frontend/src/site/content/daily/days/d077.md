## Objectives

- Convert text columns to real datetimes with `pd.to_datetime`, naming the format and handling bad values with `errors="coerce"`.
- Extract parts of a date (year, month, weekday name, quarter) with the `.dt` accessor and use them to filter and label rows.
- Calculate with time: subtract two datetimes to get a `Timedelta`, and convert it to days or seconds.
- Summarise a series by calendar period with `resample`, including periods that have no rows.

## Understand

### Why dates need their own type

A date in a file is just text: `"2024-03-05"` is ten characters, and pandas treats it like any other string. You cannot ask a string for its month, you cannot subtract two strings, and sorting strings only happens to work when the format is year-month-day. The text `"05/03/2024"` sorts before `"12/01/2023"` even though it is a year later. A **datetime** is a value that pandas understands as a point in time. Once a column has the datetime type, called `datetime64[ns]` by pandas, sorting is chronological, subtraction gives a duration, and a whole family of calendar tools becomes available. Day 75 showed that `astype` and `to_numeric` convert types; `to_datetime` is the same idea for dates, with extra options because dates are written in so many ways.

Think of a datetime column as a ruler laid along the timeline. Each value is a position on it, and pandas can measure the distance between two positions or group positions into calendar buckets such as months. A string column is a list of labels with no ruler underneath.

### Parsing with to_datetime

`pd.to_datetime(series)` reads each text value and returns a datetime series. Without help, pandas guesses the format from the first values, and a guess is dangerous for dates such as `03/04/2024`, which is 3 April in much of the world and 4 March in the United States. The safe habit is to state the format with `format="%d/%m/%Y"`. The codes follow the C convention: `%Y` is a four-digit year, `%m` a month number, `%d` a day of the month, `%H`, `%M` and `%S` hours, minutes and seconds. When the format is stated, every value must match it, and a value that does not match is an error rather than a silent misreading.

Real columns contain junk: `"unknown"`, `"n/a"`, an impossible date such as `31/02/2024`. By default `to_datetime` raises an error on the first such value. With `errors="coerce"` it turns each unparseable value into `NaT`, short for "not a time", which is the datetime version of `NaN` from Day 74. You can then count the bad rows with `isna()` and decide what to do with them. Coercing hides problems if you never look at what became `NaT`, so always count them straight after the conversion.

### The .dt accessor

Day 76 introduced `.str`, which exposes string methods on a whole column. The `.dt` accessor does the same for datetimes. `s.dt.year`, `s.dt.month` and `s.dt.day` return integers. `s.dt.dayofweek` returns 0 for Monday up to 6 for Sunday, `s.dt.day_name()` returns the weekday as text, and `s.dt.quarter` returns 1 to 4. `s.dt.to_period("M")` turns each date into the month it falls in, and `s.dt.normalize()` sets the time of day to midnight. Each of these works on the whole column at once, so no loop is needed. The accessor only works on a datetime column, and a column of text gives the error `Can only use .dt accessor with datetimelike values`. That error always means the conversion step was skipped.

### Time deltas

Subtracting one datetime from another gives a **Timedelta**, a length of time. `pd.Timestamp("2024-03-10") - pd.Timestamp("2024-03-05")` is five days. Subtracting two datetime columns gives a column of timedeltas with the dtype `timedelta64[ns]`. Through `.dt` you read it as numbers: `.dt.days` is the whole number of days, and `.dt.total_seconds()` is the length in seconds including the part of a day. The difference matters: a gap of 1 day and 12 hours has `.dt.days` equal to 1 but `total_seconds() / 86400` equal to 1.5. You can also create a duration yourself, with `pd.to_timedelta(7, unit="D")`, and add it to a date column to compute a due date, or compare a timedelta column with it to find slow rows.

### Resampling

**Resampling** groups time-indexed data into regular calendar periods and aggregates each one. The series must have a datetime index; then `s.resample("MS").sum()` adds up the values in each month. The code `"MS"` means month start and `"D"` means calendar day. Each result row is labelled with the first day of its period. The important property is that resampling creates every period between the first and last date, even periods with no data. A month with no orders appears as 0 for `sum()` and `count()`, which a plain grouping on the month would silently leave out. That makes resample the right tool for trends, because a missing month is information.

### Common misconception

Learners often believe a column that prints like dates is a date column. A column read from a CSV prints as `2024-03-05` and still has dtype `object`, so `.dt` fails and sorting treats it as text. Always check `df.dtypes` after loading. The second misconception is that `to_datetime` without a format is harmless; on ambiguous day and month values it can silently swap them, and the data looks plausible, so nothing warns you.

### Why it matters

Almost every business table has dates: orders, tickets, sensor readings, signups. Questions such as "how many orders per month", "how long did delivery take" and "which weekday is busiest" all start with a correct datetime column. Mistakes here are quiet: a month number swapped with a day number produces a believable chart that is wrong.

## Syntax and key functions

```python nocheck
pd.to_datetime(series, format="%Y-%m-%d", errors="coerce")
series.dt.year            # also month, day, dayofweek, quarter
series.dt.day_name()
end - start               # Timedelta (or a timedelta column)
(end - start).dt.days
df.set_index("date")["amount"].resample("MS").sum()
```

`format` names how the text is laid out. `errors="coerce"` replaces unparseable values with `NaT`; the default `"raise"` stops with an error. The `.dt` accessor needs a datetime column. `resample` needs a datetime index and an aggregation such as `sum`, `count`, `mean` after it.

| Function or option | Returns |
|---|---|
| `pd.to_datetime(s, format=..., errors=...)` | datetime series, `NaT` where coerced |
| `s.dt.year`, `.month`, `.day`, `.quarter` | integer series |
| `s.dt.dayofweek` | 0 (Monday) to 6 (Sunday) |
| `s.dt.day_name()` | weekday names as text |
| `s.dt.to_period("M")` | month-level period per row |
| `a - b` for datetimes | Timedelta or timedelta series |
| `td.dt.days`, `td.dt.total_seconds()` | whole days; seconds as float |
| `pd.to_timedelta(7, unit="D")` | one duration |
| `s.resample("MS").sum()` | one row per month, gaps included |

## Learn by example

### Example 1: Parse text into datetimes

The strings use day, month and year order. Naming the format removes any guessing. The bad value `"n/a"` becomes `NaT`, and `isna().sum()` counts it.

```python run
import pandas as pd
raw = pd.Series(["03/04/2024", "15/04/2024", "n/a", "01/05/2024"])
dates = pd.to_datetime(raw, format="%d/%m/%Y", errors="coerce")
print(dates.to_string())
print(dates.dtype)
print("bad values:", dates.isna().sum())
```

```output
0   2024-04-03
1   2024-04-15
2          NaT
3   2024-05-01
datetime64[ns]
bad values: 1
```

Row 0 is 3 April, not 4 March, because the format said day first.

### Example 2: Parts of a date with .dt

A small orders table gets a weekday name and a month number, then is filtered to weekends. Boolean masks are from Day 72.

```python run
import pandas as pd
pd.set_option("display.width", 100)
orders = pd.DataFrame({
    "order_id": [1, 2, 3, 4, 5],
    "order_date": pd.to_datetime(["2024-03-01", "2024-03-02", "2024-03-03", "2024-04-05", "2024-04-06"]),
    "amount": [120.0, 80.0, 45.5, 200.0, 60.0],
})
orders["weekday"] = orders["order_date"].dt.day_name()
orders["month"] = orders["order_date"].dt.month
print(orders.to_string())
weekend = orders[orders["order_date"].dt.dayofweek >= 5]
print(weekend["order_id"].tolist())
```

```output
   order_id order_date  amount   weekday  month
0         1 2024-03-01   120.0    Friday      3
1         2 2024-03-02    80.0  Saturday      3
2         3 2024-03-03    45.5    Sunday      3
3         4 2024-04-05   200.0    Friday      4
4         5 2024-04-06    60.0  Saturday      4
[2, 3, 5]
```

Saturday is 5 and Sunday is 6, so `>= 5` selects orders 2, 3 and 5.

### Example 3: Time deltas

Delivery time is the difference of two datetime columns. `.dt.days` drops the partial day; `total_seconds()` keeps it.

```python run
import pandas as pd
d = pd.DataFrame({
    "ordered": pd.to_datetime(["2024-03-01 09:00", "2024-03-02 18:30", "2024-03-05 12:00"]),
    "delivered": pd.to_datetime(["2024-03-04 21:00", "2024-03-03 06:30", "2024-03-12 12:00"]),
})
gap = d["delivered"] - d["ordered"]
d["days"] = gap.dt.days
d["hours"] = gap.dt.total_seconds() / 3600
d["late"] = gap > pd.to_timedelta(5, unit="D")
print(d[["days", "hours", "late"]].to_string())
```

```output
   days  hours   late
0     3   84.0  False
1     0   12.0  False
2     7  168.0   True
```

The first order took 3 days and 12 hours: `days` shows 3 and `hours` shows 84. Only the third exceeds five days.

### Example 4: Resample to months, with a gap

Daily sales are placed on a datetime index and totalled per month. January has no rows between the first and third months, yet February still appears.

```python run
import pandas as pd
sales = pd.DataFrame({
    "date": pd.to_datetime(["2024-01-05", "2024-01-20", "2024-03-02", "2024-03-15", "2024-04-01"]),
    "amount": [100.0, 50.0, 70.0, 30.0, 90.0],
})
s = sales.set_index("date")["amount"]
monthly = s.resample("MS").agg(["sum", "count"])
print(monthly.to_string())
```

```output
              sum  count
date                    
2024-01-01  150.0      2
2024-02-01    0.0      0
2024-03-01  100.0      2
2024-04-01   90.0      1
```

February is present with sum 0 and count 0. Grouping by `dt.month` would have dropped it.

## Real-world applications

- **Monthly reporting.** A finance analyst totals revenue per month with `resample("MS")`. Months with no sales stay in the table as zero, so a chart does not skip them.
- **Service-level checks.** A support team subtracts `opened` from `closed` to get resolution time, then flags tickets slower than `pd.to_timedelta(2, unit="D")`.
- **Parsing files from different regions.** A data engineer receives CSV files from two countries, states `format="%d/%m/%Y"` for one and `"%m/%d/%Y"` for the other, and counts `NaT` values to reject a file that does not match.
- **Seasonality.** Extracting `day_name()` from timestamps shows which weekday carries most traffic, which drives staffing.

## Daily review

### Key takeaways

- Convert date text with `pd.to_datetime` and check `dtypes`; text that looks like a date is still text.
- State `format` so day and month cannot be swapped silently.
- `errors="coerce"` makes bad values `NaT`; count them straight away.
- `.dt` gives parts of dates; subtraction gives timedeltas; `resample` fills calendar gaps.

### Common mistakes

- Calling `.dt` on an `object` column raises `AttributeError: Can only use .dt accessor with datetimelike values`. Convert with `to_datetime` first.
- Leaving out `format` on `03/04/2024` data gives a plausible but wrong month. Always name the format for non-ISO text.
- Using `.dt.days` as a precise length drops the hours; use `total_seconds()` when the part of a day matters.
- Calling `resample` on a column instead of a datetime index raises `TypeError: Only valid with DatetimeIndex...`. Use `set_index` first.

### Revision notes

- `%Y-%m-%d`, `%d/%m/%Y`, `%H:%M`; coerce gives `NaT`.
- `dayofweek`: Monday is 0.
- `"MS"` is month start, `"D"` is day.
- Resample keeps empty periods.
