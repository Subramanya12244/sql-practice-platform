## Objectives

- Write a loop inside another loop and predict how many times the inner block runs.
- Build grids, tables and combinations of two sequences with nested loops.
- Apply the standard loop patterns: accumulate, count, filter, find the maximum, and search with an early exit.
- Build a new list or dictionary from existing data without changing the original.
- Stop an inner loop with `break` and understand that it does not stop the outer loop.

## Understand

### A loop inside a loop

The block of a loop can contain any statements, including another loop. A **nested loop** is a loop inside the block of another loop. The outer loop runs its block once per item; each time, the inner loop starts fresh and runs completely.

```text
for outer_item in outer_collection:
    for inner_item in inner_collection:
        block
```

The counting rule is simple: if the outer loop makes 3 passes and the inner loop makes 4 passes each time, the inner block runs 3 × 4 = 12 times. A good picture is a clock: the minute hand goes all the way round (the inner loop) for every single step of the hour hand (the outer loop). The inner variable changes fastest.

Indentation shows which loop a line belongs to. A line indented once belongs to the outer loop only and runs once per outer pass; a line indented twice runs on every inner pass. A frequent beginner error is putting a `print()` at the wrong level and getting a table that is not shaped as expected.

### Grids and combinations

Nested loops are the natural way to walk a **grid**: rows are the outer loop and columns the inner loop. They also produce all **combinations** of two sequences, such as every size with every colour of a product. Another common structure is a **list of lists** (a table where each row is a list): the outer loop goes through rows, the inner loop through the cells of the current row.

### The standard loop patterns

Almost every loop falls into one of these patterns. They all use an accumulator created before the loop (Day 11).

- **Accumulate**: add up or combine values. `total += x`.
- **Count**: add 1 when a condition holds. `if x > 10: count += 1`.
- **Filter**: collect only the items that pass a test into a new list. `if x > 10: result.append(x)`.
- **Transform** (also called map): collect a changed version of every item. `result.append(x * 2)`.
- **Maximum or minimum**: remember the best so far and replace it when a better item appears. Start with the first item (or `None`), not with 0, because 0 could be larger than every negative value.
- **Search**: look for an item and stop at the first match with `break`, or return a flag saying whether it was found.

Combining these inside nested loops covers a large part of everyday data processing: for each order, for each line of the order, add up the amounts that pass a test.

### break only leaves one level

`break` ends the **nearest** loop around it. In a nested loop, a `break` in the inner loop stops the inner loop only; the outer loop carries on with its next item. To stop everything, set a flag variable such as `found = True` before the `break` and test it in the outer loop, or restructure the search into a function (Day 14) that returns as soon as it finds the answer.

### Building results without changing the source

A reliable habit is to create a new, empty result (a list, dictionary or number) before the loop, fill it during the loop, and leave the input data untouched. This avoids the problem from Day 11 of changing a list while looping over it, and it keeps the original available for another pass. When the input is a list of dictionaries, the new result is often a smaller list of dictionaries or a dictionary of totals.

### Cost

Nested loops multiply work: two loops over 1,000 items each give a million inner passes. That is fine for small data, but for large data you reach for other tools later in the course (sets, dictionaries, pandas). When you only need to know whether a value is present, a set lookup (Day 9) replaces an inner search loop.

### A worked trace of two loops

Trace `for i in range(2): for j in range(3): print(i, j)`. The outer loop sets `i` to 0. The inner loop then runs completely, with `j` taking the values 0, 1 and 2, printing `0 0`, `0 1` and `0 2`. Only when the inner loop has finished does the outer loop move on, set `i` to 1, and start the inner loop again from the beginning, printing `1 0`, `1 1` and `1 2`. The inner loop restarts fresh every time, which is why a variable that must restart for each row, such as a row total, has to be set to 0 between the two `for` lines.

Why does this matter in data work? Many questions involve two collections: every order against every customer, every row against every column. A nested loop is the most direct way to express them. It is also the first place where the size of the data matters. Comparing 5 items with 5 items is 25 checks, but 10,000 with 10,000 is 100 million, which can take a noticeable time. When a nested loop only searches for a match, replacing the inner loop with a set or dictionary lookup (Days 9 and 10) keeps the cost low.

## Syntax and key functions

```text
for row in table:
    for cell in row:
        ...

result = []
for item in items:
    if condition(item):
        result.append(item)       # filter

best = None
for item in items:
    if best is None or item > best:
        best = item               # maximum

found = False
for item in items:
    if item == target:
        found = True
        break                     # search with early exit
```

- Each nesting level adds four more spaces of indentation.
- The names of the loop variables must differ between the loops, otherwise the inner one overwrites the outer one.

| Tool | Use in this lesson |
|---|---|
| `range(n)` | the number of rows or columns |
| `len(items)` | the size of a row or table |
| `list.append(x)` | build a result list |
| `max(items)`, `min(items)`, `sum(items)` | built-in versions of the maximum, minimum and accumulate patterns |
| `print(..., end="")` | stay on the same line while printing a row |

## Learn by example

### Example 1: A multiplication table

The outer loop makes a row, the inner loop makes the cells. The empty `print()` ends the row.

```python run
for row in range(1, 4):
    for col in range(1, 5):
        print(row * col, end=" ")
    print()
```

```output
1 2 3 4 
2 4 6 8 
3 6 9 12 
```

The inner block ran 3 × 4 = 12 times, and the `print()` that ends the line is indented once, so it ran 3 times.

### Example 2: Combinations

```python run
sizes = ["S", "M", "L"]
colors = ["red", "blue"]
combos = []
for size in sizes:
    for color in colors:
        combos.append(size + "-" + color)
print(combos)
print(len(combos))
```

```output
['S-red', 'S-blue', 'M-red', 'M-blue', 'L-red', 'L-blue']
6
```

### Example 3: Walking a table (list of lists)

```python run
scores = [
    [70, 85, 90],
    [60, 75, 80],
    [95, 88, 92],
]
row_totals = []
best = None
for row in scores:
    total = 0
    for value in row:
        total += value
        if best is None or value > best:
            best = value
    row_totals.append(total)
print(row_totals)
print("best:", best)
```

```output
[245, 215, 275]
best: 95
```

`total = 0` is inside the outer loop but before the inner loop, so each row starts fresh.

### Example 4: Filtering and transforming

```python run
prices = [12.5, 3.0, 45.0, 8.25, 60.0]
expensive = []
discounted = []
for price in prices:
    if price >= 10:
        expensive.append(price)
    discounted.append(round(price * 0.9, 2))
print(expensive)
print(discounted)
print(prices)
```

```output
[12.5, 45.0, 60.0]
[11.25, 2.7, 40.5, 7.42, 54.0]
[12.5, 3.0, 45.0, 8.25, 60.0]
```

Two new lists were built, and `prices` is unchanged.

### Example 5: Search, and break at one level

The program looks for the first row that contains a target value. The inner `break` stops only the inner loop; the flag stops the outer one.

```python run
grid = [[1, 2, 3], [4, 5, 6], [7, 8, 9]]
target = 5
found_at = None
for r in range(len(grid)):
    for c in range(len(grid[r])):
        if grid[r][c] == target:
            found_at = (r, c)
            break
    if found_at is not None:
        break
print(found_at)
```

```output
(1, 1)
```

Without the second `break`, the outer loop would carry on to the remaining rows, which is wasted work (and could overwrite `found_at` if the value appeared again).

### Example 6: Matching records between two lists

For each order, find the customer's city by searching the customer list. The result is a new list of dictionaries.

```python run
customers = [
    {"id": 1, "city": "Leeds"},
    {"id": 2, "city": "York"},
    {"id": 3, "city": "Hull"},
]
orders = [
    {"order": 101, "customer": 2, "total": 30.0},
    {"order": 102, "customer": 9, "total": 12.5},
    {"order": 103, "customer": 1, "total": 55.0},
]
report = []
for order in orders:
    city = "unknown"
    for customer in customers:
        if customer["id"] == order["customer"]:
            city = customer["city"]
            break
    report.append({"order": order["order"], "city": city})
print(report)
```

```output
[{'order': 101, 'city': 'York'}, {'order': 102, 'city': 'unknown'}, {'order': 103, 'city': 'Leeds'}]
```

Order 102 has no matching customer, so it keeps the default `"unknown"`. Setting the default before the inner loop is the key to this pattern.

## Real-world applications

- **Joining two sources by hand.** The matching loop in Example 6 is the plain-Python idea behind a SQL join, and shows what a join does.
- **Report tables.** Walking rows and cells builds totals per row and per column, as in a spreadsheet.
- **Filtering to a clean dataset.** The filter and transform patterns select valid rows and convert values before analysis.
- **Finding the first match.** Searching for the first record that satisfies a rule and stopping saves time on large files.

## Daily review

### Key takeaways

- The inner loop runs completely for every pass of the outer loop; passes multiply.
- Indentation decides which loop a statement belongs to.
- Standard patterns: accumulate, count, filter, transform, maximum or minimum, search.
- Create results before the loop; do not change the list you are looping over.
- `break` leaves only the nearest loop; use a flag to leave both.

### Common mistakes

- **Wrong indentation of the row-ending `print()`.** If it is inside the inner loop, every cell ends up on its own line. Indent it one level, aligned with the inner `for`.
- **Initialising an accumulator at the wrong level.** `total = 0` before the outer loop mixes up the rows; put it inside the outer loop when each row needs its own total.
- **Starting a maximum at 0.** If all values are negative, the result stays 0, which is wrong. Start with `None` or the first item.
- **Reusing a loop variable name.** `for x in a: for x in b:` overwrites the outer `x`. Use different names.
- **Expecting an inner `break` to stop everything.** The outer loop continues. Use a flag, as in Example 5.
- **Forgetting the default before a search.** If nothing matches, the variable keeps the value from the previous outer pass. Reset it before each inner loop.

### Revision notes

- `for ...:` then an indented `for ...:`; passes multiply.
- Patterns: accumulate, count, filter, transform, max, search.
- New result before the loop; source untouched.
- Inner `break` stops the inner loop only.
