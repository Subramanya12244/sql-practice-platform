- Write rows and dictionaries to CSV text with `csv.writer` and `csv.DictWriter`, including a header line.

## Understand

### Tables as text

Data exchanged between systems is very often plain text with a simple structure. **CSV** (comma-separated values) stores a table: one record per line, fields separated by commas, and usually a first line of column names called the **header**. **JSON** (JavaScript Object Notation) stores structured data made of objects, lists, strings, numbers, booleans and null, and is the usual format for web APIs and configuration. Both are ordinary text files, so everything from Day 19 applies. What is new is the parsing: turning the text into Python values and back.

The key point is that text carries no types. In a CSV file the field `42` is just the characters `4` and `2`, so a reader always returns strings, and you convert them yourself with `int()` or `float()`. An empty field is the empty string `""`, not `None` and not `0`.

### Why not split on commas

`line.split(",")` works for the simplest data and fails on real data. A field may contain a comma when it is wrapped in quotes: `"Lopez, Ana"` is one field. A quoted field can also contain a doubled quote or even a line break. The `csv` module understands these rules, called quoting. When you write, it adds quotes only where they are needed. Always use it for CSV.

### csv.reader and DictReader

`csv.reader(f)` yields each line as a list of strings. The header is just the first list, so you skip it yourself with `next(reader)`. `csv.DictReader(f)` reads the header for you and yields each record as a dictionary keyed by column name, for example `{"name": "Ana", "qty": "3"}`. Dictionaries are clearer than positions such as `row[2]`, and they keep working when columns are reordered. The values are still strings.

When the file object comes from `open()`, pass `newline=""` so the module handles line endings itself. For text held in a string, `io.StringIO(text)` makes a file-like object that works with the same code, which is also how this lesson avoids needing real files.

Trace one row to see what happens. For the text `name,qty` followed by `Ana,3`, `DictReader` reads the first line once and keeps `['name', 'qty']` as its `fieldnames`. Each later line is split into fields and paired with those names by position, so the loop receives `{"name": "Ana", "qty": "3"}`. The header itself is never yielded as a row. If a line has fewer fields than the header, the missing keys get the value `None`, and extra fields are collected in a list under the key `None`, so a row with the wrong number of commas shows up as an odd dictionary and not as an error.

### csv.writer and DictWriter

`csv.writer(f)` has `writerow(list)` and `writerows(list_of_lists)`. `csv.DictWriter(f, fieldnames=[...])` takes the column order explicitly; call `writeheader()` once and then `writerow(dict)` or `writerows(list_of_dicts)`. A dictionary with a key that is not in `fieldnames` raises `ValueError`. By default the line ending written is `"\r\n"`; the examples pass `lineterminator="\n"` to keep output tidy. Another delimiter, such as a semicolon or tab, is chosen with `delimiter=";"`.

### JSON and Python values

JSON maps closely to Python: an object becomes a `dict`, an array a `list`, a string a `str`, a number an `int` or `float`, `true` and `false` become `True` and `False`, and `null` becomes `None`. Two functions work on text and two on files. The `s` stands for "string":

- `json.loads(text)` parses JSON text into Python values, and `json.dumps(value)` produces JSON text.
- `json.load(f)` and `json.dump(value, f)` do the same with a file object.

`dumps` accepts `indent=2` for readable output and `sort_keys=True` for a stable key order. JSON has only string keys, so a dictionary key `1` becomes `"1"` after a round trip. JSON also has no date, set or tuple type: tuples come back as lists, and a `datetime` raises `TypeError` unless you convert it to text first. Invalid text raises `json.JSONDecodeError`, a subclass of `ValueError`.

### Nested data

Real JSON is **nested**: objects contain lists that contain objects. You reach into it with chained indexing, `order["customer"]["city"]`, and loop over inner lists. Because a table has one level, a common job is **flattening**: producing one flat row per innermost item and copying the outer values onto each row. Use `dict.get(key, default)` where a key may be missing, since a missing key in `[]` raises `KeyError`.

### Common misconception

Learners expect `csv` to return numbers because the values look like numbers. Everything is a string until you convert it, and sorting or summing the unconverted strings gives wrong answers: the strings `"10"` and `"9"` sort with `"10"` first.

### Why it matters

CSV and JSON are the two most common raw formats in data engineering. A pipeline that reads them reliably, converts types explicitly and writes clean output is the first stage of nearly every project, and the nested-to-flat step is how API data reaches a table.

## Syntax and key functions

Read and write CSV:

```python
import csv

reader = csv.DictReader(f)
writer = csv.DictWriter(f, fieldnames=["a", "b"], lineterminator="\n")
writer.writeheader()
writer.writerow({"a": 1, "b": 2})
```

`f` is a file object opened with `newline=""`, or `io.StringIO`. `fieldnames` fixes the column order.

Convert JSON:

```python
import json

value = json.loads(text)
text = json.dumps(value, indent=2, sort_keys=True)
```

| Call | Returns |
|---|---|
| `csv.reader(f)` | An iterator of lists of strings. |
| `csv.DictReader(f)` | An iterator of dictionaries; `.fieldnames` holds the header. |
| `csv.writer(f).writerow(seq)` | Writes one line. |
| `csv.DictWriter(f, fieldnames)` | A writer for dictionaries; `writeheader()`, `writerow()`, `writerows()`. |
| `json.loads(s)` / `json.dumps(v)` | Python value / JSON text. |
| `json.load(f)` / `json.dump(v, f)` | Python value read from a file / writes JSON text into a file. |
| `d.get(key, default)` | The value, or the default when the key is missing. |
| `io.StringIO(text)` | A file-like object over a string; `.getvalue()` returns what was written. |

## Learn by example

### Example 1: Why split(",") is not enough

The second line of the data has a quoted field that contains a comma. Splitting on commas cuts it into three pieces, while the `csv` module returns two fields, with the quotes removed. Everything it returns is a string.

```python run
import csv
import io

text = 'id,name\n1,"Lopez, Ana"\n2,Bo\n'
print(text.splitlines()[1].split(","))
for row in csv.reader(io.StringIO(text)):
    print(row)
```

```output
['1', '"Lopez', ' Ana"']
['id', 'name']
['1', 'Lopez, Ana']
['2', 'Bo']
```

### Example 2: DictReader and type conversion

`DictReader` uses the header as keys. Each value is converted explicitly with `int()` and `float()`, so the totals are numbers. An empty field would need a decision, which is shown with a default of zero.

```python run
import csv
import io

text = """product,qty,price
pen,10,1.5
book,3,12.0
bag,,40.0
"""
total = 0
for row in csv.DictReader(io.StringIO(text)):
    qty = int(row["qty"]) if row["qty"] else 0
    line = qty * float(row["price"])
    total += line
    print(row["product"], qty, line)
print("total", total)
```

```output
pen 10 15.0
book 3 36.0
bag 0 0.0
total 51.0
```

### Example 3: Writing CSV with DictWriter

The writer fixes the column order with `fieldnames`. A value that contains a comma is quoted automatically. `StringIO` collects the text so we can print it, and a real file would be opened with `open("out.csv", "w", newline="", encoding="utf-8")`.

```python run
import csv
import io

rows = [
    {"city": "Berlin", "sales": 1200, "note": "ok"},
    {"city": "Lisbon", "sales": 950, "note": "late, partial"},
]
buffer = io.StringIO()
writer = csv.DictWriter(buffer, fieldnames=["city", "sales", "note"], lineterminator="\n")
writer.writeheader()
writer.writerows(rows)
print(buffer.getvalue(), end="")
```

```output
city,sales,note
Berlin,1200,ok
Lisbon,950,"late, partial"
```

### Example 4: JSON round trip

`dumps` turns Python data into text and `loads` turns it back. Notice what changes: the tuple returns as a list, the integer key returns as a string, `True` and `None` are written as `true` and `null`. `sort_keys` and `indent` give readable, stable text.

```python run
import json

data = {"id": 7, "tags": ("a", "b"), "active": True, "manager": None}
text = json.dumps(data, sort_keys=True)
print(text)
back = json.loads(text)
print(back)
print(back["tags"] == ("a", "b"), back["tags"] == ["a", "b"])
print(json.loads(json.dumps({1: "one"})))
print(json.dumps({"b": [1, 2], "a": {"x": 1}}, indent=2, sort_keys=True))
```

```output
{"active": true, "id": 7, "manager": null, "tags": ["a", "b"]}
{'active': True, 'id': 7, 'manager': None, 'tags': ['a', 'b']}
False True
{'1': 'one'}
{
  "a": {
    "x": 1
  },
  "b": [
    1,
    2
  ]
}
```

### Example 5: Files, errors and nested access

`json.dump` and `json.load` use a file. Bad text raises `JSONDecodeError`, which is caught here as `ValueError`. The nested order is read by chaining keys, and `get` supplies a default for a key that may be absent.

```python run
import json

order = {"id": 1, "customer": {"name": "Ana", "city": "Oslo"}, "items": [{"sku": "A", "qty": 2}, {"sku": "B", "qty": 1}]}
with open("order.json", "w", encoding="utf-8") as f:
    json.dump(order, f)
with open("order.json", encoding="utf-8") as f:
    loaded = json.load(f)
print(loaded["customer"]["city"])
print(sum(item["qty"] for item in loaded["items"]))
print(loaded["customer"].get("phone", "unknown"))
try:
    json.loads("{'a': 1}")
except ValueError as error:
    print(type(error).__name__)
```

```output
Oslo
3
unknown
JSONDecodeError
```

### Example 6: JSON to CSV, a flattening pipeline

Orders arrive as nested JSON. Each order has several items, so the flat table has one row per item with the order's id and city copied onto it. The rows are then written as CSV. This is the shape of most API-to-table jobs.

```python run
import csv
import io
import json

text = """[
  {"id": 1, "city": "Oslo", "items": [{"sku": "A", "qty": 2}, {"sku": "B", "qty": 1}]},
  {"id": 2, "city": "Rome", "items": [{"sku": "A", "qty": 5}]},
  {"id": 3, "city": "Oslo", "items": []}
]"""
rows = []
for order in json.loads(text):
    for item in order["items"]:
        rows.append({"order_id": order["id"], "city": order["city"], "sku": item["sku"], "qty": item["qty"]})

out = io.StringIO()
writer = csv.DictWriter(out, fieldnames=["order_id", "city", "sku", "qty"], lineterminator="\n")
writer.writeheader()
writer.writerows(rows)
print(out.getvalue(), end="")
print(len(rows), "rows from 3 orders")
```

```output
order_id,city,sku,qty
1,Oslo,A,2
1,Oslo,B,1
2,Rome,A,5
3 rows from 3 orders
```

## Real-world applications

- **Loading exports.** A supplier sends a daily CSV. `DictReader` plus explicit conversion (Example 2) reads it safely, including quoted names that contain commas (Example 1).
- **Producing files for other teams.** A report is written with `DictWriter` (Example 3), with a fixed column order so downstream tools never see columns move.
- **Consuming API responses.** REST APIs return JSON. `json.loads` and nested access (Example 5) pull the needed fields, and flattening (Example 6) turns them into rows ready for a database or a data frame.
- **Configuration and checkpoints.** Pipelines store settings and the last processed position as small JSON files, written with `json.dump` and read back with `json.load`.

## Daily review

### Key takeaways

- The `csv` module handles quoting; `split(",")` does not.
- `DictReader` and `DictWriter` use column names; every CSV value read is a string until you convert it.
- Open CSV files with `newline=""`; use `io.StringIO` for text held in memory.
- `loads` and `dumps` work with text, `load` and `dump` with files.
- JSON turns tuples into lists and integer keys into strings, and cannot hold dates or sets directly.
- Flatten nested data with loops, copying outer values onto each inner row.

### Common mistakes

- Summing or comparing CSV values without converting them, which gives `TypeError` or wrong sorting such as `"10" < "9"`. Convert with `int()` or `float()`.
- Using `split(",")` on quoted data, giving too many fields. Use the `csv` module.
- Forgetting `newline=""` when writing, which can produce blank lines between rows on Windows.
- Confusing `json.load` with `json.loads` and getting `AttributeError: 'str' object has no attribute 'read'`. The version with `s` takes a string.
- Writing single-quoted text such as `{'a': 1}` and expecting `json.loads` to read it. JSON requires double quotes.
- Passing a dictionary with an extra key to `DictWriter`, which raises `ValueError: dict contains fields not in fieldnames`.
- Indexing a missing key and getting `KeyError`. Use `.get()` with a default when the key is optional.

### Revision notes

- `for row in csv.DictReader(f)`: row is a dict of strings.
- `w = csv.DictWriter(f, fieldnames=[...])`, `w.writeheader()`, `w.writerows(rows)`.
- `json.loads(s)`, `json.dumps(v, indent=2)`, `json.load(f)`, `json.dump(v, f)`.
- JSON object is dict, array is list, `null` is `None`.
- `d.get("k", default)` for optional keys; flatten by looping outer then inner.
