## Understand

### Processes and PIDs

A **program** is a file on disk; a **process** is a running instance of it. Every process has a numeric **PID** (process id) that the system assigns, an owner, an environment, a working directory and an exit status once it ends. Each process also has a **parent**, the process that started it: your terminal's shell is the parent of every command you type. In a script `$$` is the PID of the shell itself and `$!` is the PID of the last job started in the background. PIDs are different on every run, so scripts never print them and tests never compare them; they are used only to refer to a process in the next command.

### Foreground, background and wait

A command normally runs in the **foreground**: the shell waits for it to end. Adding `&` starts it in the **background**; the shell carries on at once. Background jobs let a script do several slow things in parallel, for example three extracts from three systems. `wait` pauses the script until all background jobs of the shell have ended, and `wait $pid` waits for one job and returns that job's exit status, so you can detect which one failed. A frequent mistake is to start jobs with `&` and then read their output files immediately: the files are empty or half written because the jobs have not finished. Always call `wait` before using results.

### Signals

A **signal** is a small message the system delivers to a process. `SIGTERM` (15) asks the process to stop politely; it is what `kill pid` sends by default, and a program may catch it to clean up. `SIGINT` (2) is what Ctrl+C sends. `SIGHUP` (1) originally meant the terminal hung up and is often used to ask a service to reload its configuration. `SIGKILL` (9) cannot be caught or ignored: the system removes the process at once with no chance to clean up, so use it only after `SIGTERM` has failed. When a process dies from a signal its exit status is 128 plus the signal number, so a process stopped by `SIGTERM` reports 143. In a script, `trap 'commands' TERM` runs the commands when the signal arrives. `kill -0 pid` sends no signal; its exit code only says whether the process exists and may be signalled.

### Files, owners and permissions

Every file has an **owner**, a **group** and a **mode**: nine permission bits in three triples for the owner (u), the group (g) and everyone else (o). In each triple `r` means read (value 4), `w` write (2) and `x` execute (1). `ls -l` shows the mode after a type character: `-rwxr-xr--` is a regular file (`-`) where the owner has `rwx`, the group `r-x` and others `r--`. Adding the values per triple gives the **octal** form: 7, 5, 4, so 754. For a directory, `r` means you can list names, `w` means you can create and delete entries, and `x` means you can enter the directory and reach files inside it; a directory without `x` is unusable even if it can be listed.

`chmod` changes the mode. Octal form sets everything: `chmod 640 f` gives `rw-r-----`. Symbolic form changes parts: `chmod u+x f` adds execute for the owner, `chmod go-w f` removes write for group and others, `chmod a=r f` sets read-only for all. The **umask** is a mask of bits that new files do not receive. New files start from 666 and new directories from 777, then the umask is removed. With umask 022 a new file is 644 and a directory 755; with umask 077 a file is 600, readable only by its owner. A misconception is that `chmod 777` fixes any permission error: it opens the file to everyone and hides the real problem, which is usually the wrong owner or a missing `x` on a parent directory. Credentials files, for example, should be 600.

### Disk usage and finding files

`wc -c file` counts the bytes in a file exactly. `du -s dir` reports the disk space used by a directory in blocks, which is not the same as the sum of byte counts because disks allocate whole blocks. `df` reports the space left on a filesystem. These numbers differ between systems, so compare them rather than print them, for example "directory A is larger than directory B". `find dir -name '*.csv'` lists matching files, `find dir -size +1k` selects files larger than one kilobyte, and piping into `sort` makes the order stable. A full disk is one of the most common reasons a nightly job fails halfway, and logs and temporary files are the usual cause.

### Why it matters

Pipelines are processes started by schedulers, killed by timeouts, and restricted by file permissions. Knowing what exit status 143 means, why a job cannot read a file, or how to run three loads in parallel saves hours of guessing. Airflow's workers later in this phase run each task as a process and report its exit status in the same way.

## Syntax and key functions

```text
command &                 # start in the background
pid=$!                    # PID of that job
wait $pid                 # wait; the status is the job's exit status
kill -TERM $pid           # same as kill $pid
kill -0 $pid              # does the process exist?
trap 'cleanup' TERM       # run cleanup on SIGTERM
chmod 640 file            # octal mode
chmod u+x,go-w file       # symbolic mode
umask 022                 # new files 644, directories 755
find dir -name '*.csv' -size +1k
```

| Command | What it gives you |
|---|---|
| `$$`, `$!` | PID of this shell, PID of the last background job. |
| `wait [pid]` | Blocks until jobs end; returns the status of the named job. |
| `kill -SIGNAL pid` | Sends a signal; default `TERM`. |
| `ls -l` | Mode, links, owner, group, size, date and name. |
| `chmod` | Changes the mode. |
| `umask` | Shows or sets the default permission mask. |
| `wc -c` | Byte count. |
| `du -s`, `df` | Space used by a tree; space free on a filesystem. |
| `find` | Selects files by name, size and type. |

## Learn by example

### Example 1: Reading and changing modes

A new file gets `rw-r--r--`. Without the execute bit the shell will not run it directly. The example prints only the first ten characters of each `ls -l` line (the type and the mode), which are the same on every machine, and never the owner or the date.

```bash run
mkdir work && cd work
printf 'echo hello from the script\n' > run.sh
ls -l run.sh | cut -c1-10
[ -x run.sh ] || echo "not executable"
chmod u+x run.sh
ls -l run.sh | cut -c1-10
./run.sh
chmod 640 run.sh
ls -l run.sh | cut -c1-10
chmod go= run.sh
ls -l run.sh | cut -c1-10
```

```output
-rw-r--r--
not executable
-rwxr--r--
hello from the script
-rw-r-----
-rw-------
```

The first listing shows `-rw-r--r--`, so the test prints "not executable". `u+x` turns the owner's triple into `rwx`. `640` sets `rw-r-----`, and `go=` clears every bit for group and others, leaving `-rw-------`. The owner has read and write only, because `640` had already replaced the owner's execute bit.

### Example 2: umask

The umask is removed from the default mode of new files, so the same `touch` gives different modes.

```bash run
mkdir work && cd work
umask 077
touch private
umask 022
touch shared
mkdir folder
ls -ld folder private shared | cut -c1-10
```

```output
drwxr-xr-x
-rw-------
-rw-r--r--
```

`ls` lists names alphabetically: the folder `drwxr-xr-x` (777 minus 022 is 755), then `-rw-------` (666 minus 077 is 600) and `-rw-r--r--` (644).

### Example 3: Background job, signal and exit status

The script starts a long `sleep` in the background, checks that it exists, terminates it and reads its status. 143 is 128 plus 15, the number of `SIGTERM`. The job notice that Bash prints goes to stderr and is not part of the output.

```bash run
sleep 30 &
pid=$!
kill -0 $pid && echo "running"
kill -TERM $pid
wait $pid || echo "status=$?"
kill -0 $pid 2>/dev/null || echo "gone"
bash -c 'trap "echo got TERM; exit 0" TERM; kill -TERM $$; echo not reached'
echo "handler exit=$?"
```

```output
running
status=143
gone
got TERM
handler exit=0
```

The last two lines run a child Bash that catches `SIGTERM` with `trap`: the handler prints and exits 0, so "not reached" never prints. A process that traps `TERM` can clean up; one killed with `SIGKILL` cannot.

### Example 4: Parallel jobs and wait

Three jobs sleep for different times and write a file each. Without `wait` the final `cat` would run too early. One job fails on purpose, and `wait $pid` reports its exit status.

```bash run
mkdir work && cd work
for n in 1 2 3; do
  ( sleep 0.$((4 - n)); echo "job $n done" > out$n.txt ) &
done
wait
cat out1.txt out2.txt out3.txt
( exit 2 ) &
pid=$!
wait $pid || echo "failed job status=$?"
```

```output
job 1 done
job 2 done
job 3 done
failed job status=2
```

Job 3 sleeps shortest and finishes first, but `wait` holds the script until all of them end, and the files are read in a fixed order, so the output is stable. The failing job's status 2 is returned by `wait $pid`.

### Example 5: Finding files and comparing sizes

`find` selects by name and size; `wc -c` is exact; for `du` the example compares two directories instead of printing block counts.

```bash run
mkdir -p work/small work/big && cd work
printf 'a,b\n1,2\n' > small/a.csv
head -c 2000000 /dev/zero > big/blob.bin
printf 'x,y\n3,4\n' > big/b.csv
find . -name '*.csv' | sort
find . -size +1000k | sort
wc -c < small/a.csv | tr -d ' '
a=$(du -sk small | cut -f1)
b=$(du -sk big | cut -f1)
[ "$b" -gt "$a" ] && echo "big uses more disk than small"
```

```output
./big/b.csv
./small/a.csv
./big/blob.bin
8
big uses more disk than small
```

`find` found the two CSV files and, with `-size +1000k`, only the 2 MB blob. `a.csv` holds exactly 8 bytes (four characters per line). The final test prints a comparison rather than the numbers because block counts differ between systems.

### Example 6: Modes in Python

The shell cannot run in the browser, so these functions model the permission arithmetic: converting `rwxr-xr--` to 754 and back, and applying a symbolic `chmod` clause to an octal mode. They are graded in the exercises.

```python run
BITS = {"r": 4, "w": 2, "x": 1}


def mode_to_octal(text):
    if len(text) != 9:
        raise ValueError("mode must have 9 characters")
    digits = ""
    for start in range(0, 9, 3):
        total = 0
        for offset, letter in enumerate("rwx"):
            ch = text[start + offset]
            if ch == letter:
                total += BITS[letter]
            elif ch != "-":
                raise ValueError(f"unexpected {ch!r} at position {start + offset}")
        digits += str(total)
    return int(digits)


def octal_to_mode(number):
    digits = f"{number:03d}"
    if len(digits) != 3 or any(d not in "01234567" for d in digits):
        raise ValueError("expected three octal digits")
    return "".join(
        "".join(letter if int(d) & BITS[letter] else "-" for letter in "rwx") for d in digits
    )


def apply_chmod(number, spec):
    parts = [int(d) for d in f"{number:03d}"]
    index = {"u": 0, "g": 1, "o": 2}
    for clause in spec.split(","):
        sign = "+" if "+" in clause else "-" if "-" in clause else "="
        who, bits = clause.split(sign)
        who = "ugo" if who in ("", "a") else who
        value = sum(BITS[b] for b in bits)
        for w in who:
            i = index[w]
            if sign == "+":
                parts[i] |= value
            elif sign == "-":
                parts[i] &= ~value & 7
            else:
                parts[i] = value
    return int("".join(str(p) for p in parts))


print(mode_to_octal("rwxr-xr--"), mode_to_octal("rw-------"))
print(octal_to_mode(640), octal_to_mode(755))
print(apply_chmod(644, "u+x"), apply_chmod(755, "go-w"), apply_chmod(600, "a+r"), apply_chmod(755, "g=r"))
```

```output
754 600
rw-r----- rwxr-xr-x
744 755 644 745
```

754 is 4+2+1, 4+0+1, 4. `chmod u+x` on 644 gives 744, `go-w` on 755 gives 755 because group and others had no write bit, and `g=r` replaces the group's triple with read only.

## Real-world applications

- A loader starts three source extracts with `&`, calls `wait` and checks each status before the load begins (Example 4).
- A deployment sets credential files to 600 and shared directories to 755 so that a pipeline user can read secrets and colleagues cannot (Examples 1 and 2).
- An operator investigating a failed night reads exit status 143 as "killed by SIGTERM", for example a timeout, instead of a bug in the code (Example 3).
- A disk-space check compares the size of the staging and archive directories and cleans up the one that grows without bound (Example 5).

## Daily review

### Key takeaways

- A process has a PID and an exit status; `$!` and `wait $pid` tie a background job to its result.
- A process stopped by a signal exits with 128 plus the signal number; 143 is SIGTERM.
- Mode bits are r=4, w=2, x=1 in three triples (u, g, o); umask removes bits from new files.
- Compare disk sizes instead of printing system-dependent block counts.

### Common mistakes

- Reading the output of a background job before `wait`. Symptom: empty or partial files. Fix: `wait` first.
- Using `chmod 777` to solve "Permission denied". Symptom: files open to everyone and the real cause (owner, parent directory `x`) unfixed. Fix: set the narrowest mode, and check the directory's `x` bit.
- Using `kill -9` first. Symptom: temporary files and locks left behind. Fix: send `TERM`, wait, then `KILL` if needed.
- Forgetting that `wait` without a PID returns 0. Symptom: a failed job is missed. Fix: `wait $pid` for each job whose status matters.

### Revision notes

- `&`, `$!`, `wait $pid`, `kill -TERM`, `trap ... TERM`.
- Status 128+n means signal n.
- 754 = rwxr-xr--; umask 022 gives 644 and 755.
