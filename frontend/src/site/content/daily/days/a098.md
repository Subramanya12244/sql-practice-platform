## Understand

### What Power Query is

**Power Query** is the data import and transformation tool built into Excel. It reads data from a file, a folder, a database or a web page, lets you clean and reshape it through a graphical editor, and loads the result into a worksheet Table or into the Data Model. Its most important property is that it records everything you do as a list of **steps**. The original data is never changed. When the source file is replaced by next month's version, you choose Refresh and every step runs again on the new data. In pandas terms, Power Query is a pipeline of operations that you build by clicking and that Excel stores as a script.

Cleaning by hand in the worksheet (deleting rows, retyping, copying formulas) has no record and cannot be repeated. A Power Query is repeatable, can be reviewed, and does not touch the source. Those three properties are the reason analysts prefer it for any file that arrives more than once.

### Where to find it

In Excel for Windows (2016 and later, and Microsoft 365) the commands are in the **Data** tab, in the Get & Transform Data group: Get Data, From Text/CSV, From Table/Range and Refresh All. In Microsoft 365 for Mac the Power Query Editor is available too, with fewer connectors than Windows; check that your version offers Get Data before the exercises. Excel 2010 and 2013 need a separate add-in, and Excel for the web has limited support. The editor opens in a new window with a ribbon (Home, Transform, Add Column, View), a preview grid in the middle, a **Queries** list on the left and a **Query Settings** pane on the right that contains the **Applied Steps**.

### Get Data

For a CSV or text file choose Data, Get Data, From File, From Text/CSV. Excel shows a preview with the detected delimiter, encoding and data types. Choose **Transform Data** (not Load) to open the editor. For data that already sits in the workbook, click inside a Table or a range and choose From Table/Range; Excel turns a range into a Table for you. Loading the result is done with Home, Close & Load, which writes a Table to a new sheet, or Close & Load To, which also allows "Only Create Connection". The loaded output is an ordinary Table that you can pivot or chart, and it carries a refresh icon.

### Applied steps

Every action appears as a named step in the Applied Steps list: `Source`, `Promoted Headers`, `Changed Type`, `Trimmed Text`, `Filtered Rows`, and so on. Clicking a step shows the data as it was after that step, so you can see exactly where something went wrong. Steps run from top to bottom and each one works on the result of the one above. You can rename a step, delete it, or drag it. Inserting a step in the middle can break the steps below it, for example when a later step refers to a column that an earlier step now removes, and Excel warns you. Two steps appear automatically: Excel promotes the first row to headers and guesses data types, and you should check both.

### Data types

Each column has a **data type**, shown by an icon in the column header: whole number (`123`), decimal number (`1.2`), text (`ABC`), date, date/time, true/false, or "any" (no type). A wrong type is the usual cause of wrong results: a numeric column left as text cannot be summed, and a date left as text cannot be grouped. Set a type with Transform, Data Type, or by clicking the icon. If a value cannot be converted, for example the text `n/a` in a number column, the cell shows `Error` instead of stopping the query. Use Home, Remove Rows, Remove Errors, or Replace Errors to deal with them, and never ignore them. Dates written as `03/04/2025` are ambiguous, so use Change Type, Using Locale, and choose the language in which the file was written.

### Cleaning text and removing duplicates

Under Transform, Format you find **Trim** (removes whitespace at the start and end of each value, but leaves spaces inside), **Clean** (removes non-printing characters), and the case changes **lowercase**, **UPPERCASE** and **Capitalize Each Word**. Replace Values changes one value into another across a column. Home, Remove Rows, Remove Duplicates keeps the first row of each distinct combination of the selected columns, and is case-sensitive, so `North` and `north` are different until you change the case first. Removing duplicates after trimming and changing case is therefore the order to use, and the order of the steps in the pane shows it.

### Filtering rows

The drop-down arrow on a header opens a filter list, as in a worksheet, but the effect is recorded as a step. Filters compare values exactly: unlike Excel worksheet formulas and `SUMIFS` from Day 95, Power Query's text filters are **case-sensitive**, so filtering to `north` would keep no rows if the data says `North`. The list shows each spelling as a separate item, which is a quick way to spot untidy labels. Remove Rows has options such as Remove Top Rows (to skip a title), Remove Blank Rows and Keep Top Rows. **null** is Power Query's value for a missing cell, shown in italics. It is not the same as an empty text `""`, and a filter "does not equal North" keeps null rows because null is not North.

### Unpivoting

Reports often arrive with one column per period: `Region, Jan, Feb, Mar`. This is a wide layout. A PivotTable, a chart or a `SUMIFS` needs the long layout: one row per Region and Month with one Amount column. **Unpivot** turns the columns into rows. Select the identifier column (`Region`) and choose Transform, Unpivot Columns, Unpivot Other Columns. Excel creates two columns, `Attribute` (the old column names) and `Value` (the numbers), which you then rename. Choosing "Unpivot Other Columns" rather than selecting the month columns is safer: when next month adds an `Apr` column, a refresh still unpivots it. The opposite operation, Pivot Column, turns rows back into columns.

### Misconception and why it matters

A common belief is that loading changes the original file. It never does; Power Query reads a copy of the source each time. Another is that the preview is the full data: the editor shows a sample, and the result you load is the full result of the steps. The reward of the tool is that the cleaning logic is written once and re-run each month.

## Syntax and key functions

Power Query is operated from the ribbon, and each command adds a step. The commands used today:

| Command | Where | Effect |
|---|---|---|
| From Text/CSV | Data, Get Data | Import a delimited file with a preview. |
| From Table/Range | Data | Use workbook data as the source. |
| Transform Data / Close & Load | Preview dialog / Home | Open the editor / write the result to a sheet. |
| Use First Row as Headers | Home or Transform | Turns the first data row into column names. |
| Data Type | Transform | Sets whole number, decimal, text, date and so on. |
| Trim, Clean, Capitalize Each Word | Transform, Format | Text clean-up. |
| Replace Values / Replace Errors | Transform | Change a value or an error into another. |
| Remove Duplicates / Remove Errors | Home, Remove Rows | Keep first of each duplicate / drop error rows. |
| Remove Top Rows / Remove Blank Rows | Home, Remove Rows | Skip titles and empty lines. |
| Filter arrow | Column header | Keep rows that match, recorded as a step. |
| Unpivot Other Columns | Transform | Wide layout to long layout. |
| Refresh / Refresh All | Data | Run all steps again on the source. |

The pandas counterparts:

```python
pd.read_csv(src, skiprows=2)                      # Source, Remove Top Rows, Promoted Headers
df["Qty"] = pd.to_numeric(df["Qty"], errors="coerce")   # Changed Type (errors become NaN)
df["Region"] = df["Region"].str.strip().str.title()      # Trim, Capitalize Each Word
df.drop_duplicates()                                     # Remove Duplicates
df.melt(id_vars="Region", var_name="Month", value_name="Amount")   # Unpivot Other Columns
```

## Learn by example

### Example 1: Import, skip a title and promote headers

A CSV export starts with a title line and a blank line before the header. Power Query steps: `Source`, Remove Top Rows (2), Use First Row as Headers, Changed Type.

```python run
import io
import pandas as pd

text = "Sales export 2025\n\nOrderID,Region,Qty\n1,North,3\n2,South,5\n3,North,x\n"
df = pd.read_csv(io.StringIO(text), skiprows=2)
print(df.columns.tolist())
print(len(df))
df["Qty"] = pd.to_numeric(df["Qty"], errors="coerce")
print(df["Qty"].tolist())
print(int(df["Qty"].isna().sum()))
```

```output
['OrderID', 'Region', 'Qty']
3
[3.0, 5.0, nan]
1
```

After skipping the two top rows, `read_csv` takes the next row as the header, which is `Promoted Headers`. The value `x` cannot become a number. In Power Query that cell becomes `Error` and the query keeps running; the pandas replica uses `errors="coerce"`, which turns it into `NaN`. Both leave you one problem to handle, here counted as 1. Use Remove Errors, or replace the error with a default, once you have looked at it.

### Example 2: Cleaning text and removing duplicates

The raw regions are `"north "`, `"North"`, `" NORTH"` and `"South"`.

```python run
import pandas as pd

raw = pd.DataFrame({"Region": ["north ", "North", " NORTH", "South"], "Qty": [3, 3, 3, 5]})
step1 = raw.drop_duplicates()
print(len(step1))
step2 = raw.assign(Region=raw["Region"].str.strip().str.title())
print(step2["Region"].tolist())
step3 = step2.drop_duplicates()
print(len(step3))
print(step3.to_string(index=False))
```

```output
4
['North', 'North', 'North', 'South']
2
Region  Qty
 North    3
 South    5
```

Removing duplicates before cleaning leaves all four rows, because the spellings differ. After Trim and Capitalize Each Word the first three rows are identical, and removing duplicates then leaves 2 rows. The order of the steps matters, and the Applied Steps pane records it. Pandas `str.strip()` matches Power Query's Trim: both remove whitespace at the ends and leave inner spaces, which differs from the worksheet `TRIM` of Day 93.

### Example 3: Case-sensitive filters and null

The filter must keep North rows. Power Query's comparison is case-sensitive, and a missing region is null.

```python run
import numpy as np
import pandas as pd

d = pd.DataFrame({"Region": ["North", "north", "South", None], "Amount": [10, 20, 30, 40]})
print(d[d["Region"] == "north"]["Amount"].tolist())
print(d[d["Region"].str.lower() == "north"]["Amount"].tolist())
print(d[d["Region"] != "North"]["Amount"].tolist())
print(d[d["Region"].notna() & (d["Region"] != "North")]["Amount"].tolist())
```

```output
[20]
[10, 20]
[20, 30, 40]
[20, 30]
```

An exact filter on `north` keeps only the lowercase row (20), as Power Query would. Lowercasing the column first keeps both spellings (10 and 20). The filter "does not equal North" keeps 20, 30 and 40, which includes the null row, just as Power Query's does. Add a "not null" condition (the last line) to leave it out. Excel formulas such as `SUMIFS` ignore case and would match `north` as well.

### Example 4: Unpivot Other Columns

A report has one column per month.

| Region | Jan | Feb | Mar |
|---|---|---|---|
| North | 100 | 120 | 150 |
| South | 60 | 50 | 90 |

Select `Region`, then Transform, Unpivot Other Columns, and rename `Attribute` to `Month` and `Value` to `Amount`.

```python run
import pandas as pd

wide = pd.DataFrame({"Region": ["North", "South"], "Jan": [100, 60], "Feb": [120, 50], "Mar": [150, 90]})
long = wide.melt(id_vars="Region", var_name="Month", value_name="Amount")
print(long.to_string(index=False))
print(long.groupby("Month", sort=False)["Amount"].sum().to_dict())
print(long.pivot(index="Region", columns="Month", values="Amount")[["Jan", "Feb", "Mar"]].to_string())
```

```output
Region Month  Amount
 North   Jan     100
 South   Jan      60
 North   Feb     120
 South   Feb      50
 North   Mar     150
 South   Mar      90
{'Jan': 160, 'Feb': 170, 'Mar': 240}
Month   Jan  Feb  Mar
Region               
North   100  120  150
South    60   50   90
```

Two rows and three month columns give six long rows. Now a PivotTable can use `Month` in Rows and a chart has a single series. `pivot` is the reverse (Pivot Column in Power Query). A difference: `melt` and Unpivot do not care how many month columns exist, as long as the identifier columns are named, so a new column such as `Apr` is picked up by the next refresh.

### Example 5: A whole query as a function, and refresh

The steps are collected into one function. Running it on new data is what Refresh does.

```python run
import io
import pandas as pd

def query(csv_text):
    df = pd.read_csv(io.StringIO(csv_text), skiprows=1)                       # Source, Promoted Headers
    df["Qty"] = pd.to_numeric(df["Qty"], errors="coerce")                      # Changed Type
    df["Region"] = df["Region"].str.strip().str.title()                        # Trim, Capitalize
    df = df.dropna(subset=["Qty"]).drop_duplicates()                           # Remove Errors, Remove Duplicates
    return df[df["Region"] != "Test"].reset_index(drop=True)                   # Filtered Rows

jan = "Export\nRegion,Qty\n north ,3\nNorth,3\nTest,9\nSouth,x\nSouth,5\n"
feb = jan + "East,7\nEAST,7\n"
print(query(jan).to_string(index=False))
print(len(query(feb)), query(feb)["Qty"].sum())
```

```output
Region  Qty
 North  3.0
 South  5.0
3 15.0
```

The January file gives North 3 (the duplicate is gone) and South 5; the Test row and the error row are removed. When the source file grows (February adds East twice), running the same steps gives 3 rows and a total quantity of 15 without any manual work. This is the benefit of Power Query: the steps are kept, only the source changes.

## Real-world applications

- **Monthly file intake.** A finance export arrives with a title, inconsistent labels and a footer. Power Query skips, cleans and types it identically each month, and one Refresh updates the report (Examples 1, 2 and 5).
- **Reshaping for analysis.** A budget with one column per month becomes a long table that a PivotTable (Day 96) or a chart (Day 97) can use (Example 4).
- **Finding hidden quality problems.** The filter list shows every spelling of a label, and the Error cells point to bad values, so problems are seen before they reach a total (Examples 1 and 3).
- **Auditable cleaning.** The Applied Steps list documents each change, which is useful when a colleague asks why a number differs from the source.

## Daily review

### Key takeaways

- Power Query records steps and re-runs them on refresh; the source file is never changed.
- Data tab, Get Data, From Text/CSV or From Table/Range; Transform Data opens the editor; Close & Load writes the result.
- Check the promoted headers and the data types; bad values become `Error`, not a crash.
- Power Query text comparison and Remove Duplicates are case-sensitive; Trim leaves inner spaces; null differs from empty text.
- Unpivot Other Columns turns a wide layout into a long one and survives new columns.

### Common mistakes

- Letting Excel guess the types and not checking them: IDs with leading zeros become numbers, dates are read in the wrong locale.
- Removing duplicates before trimming and fixing case, so near-duplicates survive.
- Ignoring `Error` cells; a SUM of the loaded column then shows an error or silently misses rows.
- Filtering text with the wrong case and getting zero rows.
- Selecting the month columns to unpivot, so that a new month column is not unpivoted after a refresh.
- Forgetting to refresh after the source changes, or editing the loaded Table by hand: the next refresh overwrites manual changes.

### Revision notes

- Data, Get Data, From Text/CSV, Transform Data; Home, Close & Load.
- Remove Top Rows, Use First Row as Headers, Data Type, Trim, Capitalize Each Word, Remove Duplicates, Remove Errors, Unpivot Other Columns.

- Refresh = the same steps on the current source.
