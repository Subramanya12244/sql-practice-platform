## Objectives

- Distinguish the `date`, `timestamp` and `interval` types and say which one a column or an expression has.
- Pull parts out of a date with `EXTRACT` and `to_char`, and group by year, quarter or month.
- Round a date down to the start of its month, quarter or year with `date_trunc`.
- Do date arithmetic: add days and intervals, and subtract dates to get a number of days.
- Write date range filters that include the right days and avoid wrapping the column in a function.

## Understand

### Dates are values, not text

A date such as `1997-02-02` looks like text but PostgreSQL stores it as a real **date**: a point on the calendar with no time of day. That is why `order_date >= '1997-01-01'` compares correctly (the text literal is converted to a date) and why you can subtract two dates. Three types matter today.

- `date`: year, month and day. The Northwind columns `order_date`, `required_date`, `shipped_date`, `hire_date` and `birth_date` are all dates.
- `timestamp` (and `timestamp with time zone`, `timestamptz`): a date plus a time of day, such as `1998-03-31 10:00:00`. `timestamptz` also depends on the session time zone.
- `interval`: a length of time, such as `1 month` or `3 days`. It is not a point on the calendar but a distance between two points.

Always write date literals in the unambiguous order year-month-day (`'1998-03-31'`, or `DATE '1998-03-31'` to state the type). Formats such as `03/04/1998` mean different dates in different countries.

### Parts of a date: EXTRACT and to_char

`EXTRACT(field FROM value)` returns one numeric part: `year`, `quarter`, `month`, `day`, `dow` (day of week, where 0 is Sunday and 6 is Saturday) or `isodow` (Monday is 1, Sunday is 7), among others. The result is numeric, so cast it with `::int` for tidy output. Use `EXTRACT` to group by a part, for example orders per year. `to_char(value, 'YYYY-MM')` goes the other way and formats a date as text, which is convenient for labels (`'DD Mon YYYY'` gives `17 May 1997`), but the result is text, so it sorts alphabetically, not by date.

### date_trunc: round down to a period

`EXTRACT(month ...)` returns 2 for both February 1996 and February 1997, so grouping by it merges years. `date_trunc('month', value)` instead rounds a date down to the first moment of its month: every date in February 1997 becomes the same value, 1997-02-01, and February 1996 becomes 1996-02-01. Valid units include `year`, `quarter`, `month`, `week` (weeks start on Monday in PostgreSQL) and `day`. Group by the truncated value to get a proper timeline. When you pass a `date`, PostgreSQL returns a `timestamp with time zone`, so cast the result back with `::date` to display a plain date and keep results independent of the time zone.

### Date arithmetic and intervals

Adding an integer to a date adds days: `order_date + 30` is thirty days later. Subtracting two dates gives an integer number of days: `shipped_date - order_date` is how long shipping took. Both rules only apply to `date` values; subtracting two timestamps returns an interval instead (`89 days 10:00:00`). To move by months or years use an interval: `order_date + INTERVAL '1 month'`. That expression returns a timestamp, so cast it with `::date`. Months have different lengths, so interval arithmetic clamps to the end of the month: `DATE '1998-01-31' + INTERVAL '1 month'` is 1998-02-28. `age(later, earlier)` returns the interval between two dates as years, months and days, and `EXTRACT(year FROM age(...))` gives whole years, for example an employee's age at hire.

If either date is NULL the result is NULL (day 35). `shipped_date - order_date` is NULL for unshipped orders and aggregates skip those rows.

### Filtering dates: half-open ranges

`BETWEEN` includes both ends and is risky once a column has a time of day. The safe pattern for any period is a half-open range: `>= start AND < next_start`. The first quarter of 1997 is `order_date >= '1997-01-01' AND order_date < '1997-04-01'`. It works for dates and timestamps alike and never needs you to know the last day of the month. It is also better than `EXTRACT(year FROM order_date) = 1997`: wrapping the column in a function usually stops the database from using an index on that column, while a plain comparison on the column can use it. On a table of 100 rows the difference is invisible; on 100 million it is not.

### Common misconception

Learners store or compare dates as text and then wonder why `'9/1/1997'` sorts after `'12/1/1997'`. Text compares character by character; real dates compare by calendar. Keep dates in date columns, and convert with `to_char` only for display.

### Why it matters

Almost every business question has a time axis: revenue per month, orders per quarter, days from order to delivery, customers inactive for six months. Date handling is also where silent errors hide: an off-by-one range or a time zone shift moves rows into the wrong period.

## Syntax and key functions

Extracting parts and truncating:

```sql-syntax
EXTRACT(field FROM date_or_timestamp)
date_trunc('unit', date_or_timestamp)
to_char(date_or_timestamp, 'format')
```

Arithmetic and ranges:

```sql-syntax
date + integer              -- a date, that many days later
date - date                 -- integer number of days
date + INTERVAL '1 month'   -- a timestamp; cast with ::date
WHERE col >= 'start' AND col < 'next_start'
```

| Function or operator | Returns | Example |
|---|---|---|
| `EXTRACT(year FROM d)` | Year as a number | 1997 |
| `EXTRACT(dow FROM d)` | Weekday, 0 is Sunday | 6 for Saturday |
| `EXTRACT(quarter FROM d)` | 1 to 4 | 2 for May |
| `date_trunc('month', d)` | Start of the month (timestamptz for a date) | `1997-05-01` after `::date` |
| `to_char(d, 'YYYY-MM')` | Formatted text | `1997-05` |
| `d + 30`, `d - 7` | A date | `1998-03-31 - 7` is 1998-03-24 |
| `d1 - d2` | Integer days | `shipped_date - order_date` |
| `d + INTERVAL '1 month'` | A timestamp | clamps to month end |
| `age(d1, d2)` | Interval in years, months, days | `EXTRACT(year FROM age(hire_date, birth_date))` |
| `make_date(y, m, d)` | A date | `make_date(1997, 5, 17)` |

## Learn by example

### Example 1: Parts of a date

Four ways to look at one date. `EXTRACT` returns numbers (cast to `int` for tidy output), `to_char` returns text with a weekday name. Order 10249 is dated 1997-02-02, a Sunday, which is why its `dow` is 0.

```sql run
SELECT order_id, order_date,
       EXTRACT(year FROM order_date)::int AS yr,
       EXTRACT(month FROM order_date)::int AS mon,
       EXTRACT(dow FROM order_date)::int AS dow,
       to_char(order_date, 'Dy DD Mon YYYY') AS label
FROM orders
ORDER BY order_id
LIMIT 3;
```

```output
order_id | order_date | yr | mon | dow | label
10248 | 1996-01-01 | 1996 | 1 | 1 | Mon 01 Jan 1996
10249 | 1997-02-02 | 1997 | 2 | 0 | Sun 02 Feb 1997
10250 | 1998-03-03 | 1998 | 3 | 2 | Tue 03 Mar 1998
```

### Example 2: Orders per year and quarter

Grouping by two `EXTRACT` values gives a year-by-quarter report. Orders are spread almost evenly across the 12 quarters, about eight or nine each, and the first four rows show 1996.

```sql run
SELECT EXTRACT(year FROM order_date)::int AS yr,
       EXTRACT(quarter FROM order_date)::int AS qtr,
       COUNT(*) AS orders,
       SUM(freight) AS total_freight
FROM orders
GROUP BY 1, 2
ORDER BY 1, 2
LIMIT 4;
```

```output
yr | qtr | orders | total_freight
1996 | 1 | 9 | 1283.18
1996 | 2 | 9 | 844.94
1996 | 3 | 8 | 817.71
1996 | 4 | 8 | 745.04
```

### Example 3: A timeline with date_trunc

`date_trunc('month', order_date)` maps every date to the first day of its month, so grouping by it gives one row per calendar month in order. The cast `::date` removes the time-zone part. Northwind has orders only in some months, and months without orders do not appear because a group exists only where rows exist.

```sql run
SELECT date_trunc('month', order_date)::date AS month,
       COUNT(*) AS orders,
       SUM(freight) AS total_freight
FROM orders
GROUP BY 1
ORDER BY 1
LIMIT 6;
```

```output
month | orders | total_freight
1996-01-01 | 9 | 1283.18
1996-04-01 | 9 | 844.94
1996-07-01 | 8 | 817.71
1996-10-01 | 8 | 745.04
1997-02-01 | 9 | 678.15
1997-05-01 | 8 | 941.74
```

### Example 4: Date arithmetic

Subtracting dates gives days, adding an integer moves a date, and adding an interval moves by calendar months. The `required_date - shipped_date` column is the slack before the deadline. The last two columns show interval arithmetic on the order date and on a literal at the end of a month, which clamps to 28 February.

```sql run
SELECT order_id, order_date,
       shipped_date - order_date AS days_to_ship,
       required_date - shipped_date AS days_to_spare,
       order_date + 30 AS plus_30_days,
       (order_date + INTERVAL '1 month')::date AS plus_1_month,
       (DATE '1998-01-31' + INTERVAL '1 month')::date AS month_end_case
FROM orders
WHERE shipped_date IS NOT NULL
ORDER BY order_id
LIMIT 3;
```

```output
order_id | order_date | days_to_ship | days_to_spare | plus_30_days | plus_1_month | month_end_case
10249 | 1997-02-02 | 3 | 25 | 1997-03-04 | 1997-03-02 | 1998-02-28
10250 | 1998-03-03 | 3 | 25 | 1998-04-02 | 1998-04-03 | 1998-02-28
10251 | 1996-04-04 | 3 | 25 | 1996-05-04 | 1996-05-04 | 1998-02-28
```

### Example 5: A half-open range

First quarter of 1997 with `>= start AND < next_start`. The second column counts the same rows with `EXTRACT` conditions to show the results are identical; the first form is preferred because it compares the plain column. Note that no `BETWEEN` and no knowledge of the last day of March is needed.

```sql run
SELECT COUNT(*) FILTER (WHERE order_date >= '1997-01-01' AND order_date < '1997-04-01') AS half_open_range,
       COUNT(*) FILTER (WHERE EXTRACT(year FROM order_date) = 1997 AND EXTRACT(quarter FROM order_date) = 1) AS extract_version,
       COUNT(*) AS all_orders
FROM orders;
```

```output
half_open_range | extract_version | all_orders
9 | 9 | 100
```

### Example 6: Shipping performance per year

A realistic report. The orders are grouped by year; the average of `shipped_date - order_date` skips unshipped orders (NULL), the `FILTER` counts late and open orders, and everything is rounded. Each year has exactly five open orders.

```sql run
SELECT EXTRACT(year FROM order_date)::int AS yr,
       COUNT(*) AS orders,
       ROUND(AVG(shipped_date - order_date), 2) AS avg_days_to_ship,
       COUNT(*) FILTER (WHERE shipped_date > required_date) AS late,
       COUNT(*) FILTER (WHERE shipped_date IS NULL) AS open_orders
FROM orders
GROUP BY 1
ORDER BY 1;
```

```output
yr | orders | avg_days_to_ship | late | open_orders
1996 | 34 | 5.83 | 3 | 5
1997 | 33 | 4.93 | 2 | 5
1998 | 33 | 6.18 | 3 | 5
```

## Real-world applications

**Time-series reporting.** Monthly, quarterly and yearly totals (examples 2, 3 and 6) are the foundation of every revenue report. `date_trunc` is the usual way to build the time axis because it keeps years apart.

**Service-level and delivery metrics.** Days to ship, days late and days to spare (examples 4 and 6) are how operations teams measure fulfilment against promises, and date subtraction does the calculation without any conversion.

**Safe period filters in pipelines.** Incremental loads and report parameters use half-open ranges (example 5) so that each row belongs to exactly one period, with no gap and no double counting at the boundary.

**Tenure and age calculations.** `age()` and `EXTRACT(year FROM age(...))` give employee tenure, customer age and account age, for example the age of each employee at hiring.

## Daily review

### Key takeaways

- `date` has no time of day, `timestamp` does, and `interval` is a length of time.
- `EXTRACT(part FROM d)` gives a number; `to_char` gives text for display; `date_trunc` rounds down to a period start.
- `date - date` is an integer number of days; `date + integer` adds days; `date + INTERVAL` gives a timestamp.
- Month arithmetic clamps to the last valid day of the month.
- Filter periods with `>= start AND < next_start` instead of `BETWEEN` or wrapping the column in a function.
- NULL dates give NULL results, and aggregates skip them.

### Common mistakes

- Grouping by `EXTRACT(month ...)` alone and merging every January together. Group by year too, or use `date_trunc`.
- Using `BETWEEN '1997-01-01' AND '1997-03-31'` on a timestamp column and losing the last day's afternoon rows. Use a half-open range.
- Sorting `to_char` output and expecting date order. `'Apr'` sorts before `'Jan'`. Sort by the date or the number.
- Displaying `date_trunc` output without `::date` and getting a timestamp with a time zone offset.
- Expecting `date - date` to be an interval. For dates it is an integer; for timestamps it is an interval.
- Forgetting the weekday numbering: in `EXTRACT(dow ...)` Sunday is 0, in `isodow` Sunday is 7.
- Hard-coding `CURRENT_DATE` in a report you want to be reproducible: the result changes every day.

### Revision notes

- `EXTRACT(year FROM d)::int`, `date_trunc('month', d)::date`, `to_char(d, 'YYYY-MM')`.
- `d1 - d2` is days; `d + INTERVAL '1 month'` needs `::date`.
- Period filter: `>= start AND < next_start`.
- `dow`: Sunday 0.
