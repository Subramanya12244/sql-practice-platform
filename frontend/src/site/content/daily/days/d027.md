## Objectives

- Treat functions as values: store them in variables and lists, pass them to other functions, and return them.
- Write a decorator that wraps a function, and apply it with the `@` syntax.
- Use `functools.wraps` so a decorated function keeps its name and documentation.
- Write a decorator that takes arguments, and use a decorator for timing, counting or caching calls.
- Write a context manager with a class (`__enter__`, `__exit__`) and with `contextlib.contextmanager`, and explain what `with` guarantees.

## Understand

### Functions are values

In Python a function is an object like a number or a string. `def greet(): ...` creates a function and attaches the name `greet` to it, and you can attach another name with `say = greet`. You can put functions in a list, pass them as arguments (you did this with `key=` in `sorted` on Day 17) and return them from other functions. Passing a function means writing its name without brackets: `apply(greet)` hands over the function, while `apply(greet())` calls `greet` first and hands over its result.

A function defined inside another function is a **nested function**, and it can use the variables of the enclosing function even after the outer function has returned. Such a function plus the variables it remembers is called a **closure**. Closures are the mechanism behind decorators.

### Decorators

A **decorator** is a function that takes a function and returns a new function, usually one that does something extra before or after calling the original. The extra code is written once and applied to many functions. A typical decorator has three layers: the outer function receives the original function, the inner **wrapper** function accepts any arguments, runs extra code and calls the original, and the outer function returns the wrapper.

```python
def shout(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs).upper()
    return wrapper

@shout
def greet(name):
    return "hello " + name
```

The line `@shout` above the definition means exactly `greet = shout(greet)`: the name `greet` now refers to the wrapper. `*args` collects any positional arguments into a tuple and `**kwargs` collects any keyword arguments into a dictionary, so the wrapper can accept whatever the original accepts and pass it on with `func(*args, **kwargs)`. Remember to return the original's result, otherwise the decorated function returns `None`.

### functools.wraps

After decoration, `greet.__name__` is `"wrapper"` and the original docstring is gone, which confuses debugging and documentation tools. The decorator `functools.wraps(func)`, placed above the wrapper, copies the name, docstring and other details from the original to the wrapper. Use it in every decorator you write.

### Decorators with arguments

To write `@repeat(3)`, you need one more layer: `repeat(3)` is a call that returns the real decorator. So the structure is: a function that takes the arguments, returns a decorator, which returns a wrapper. Read it from the outside in: `repeat(3)` runs first and gives a decorator, then Python applies that decorator to the function. Decorators can also keep state, such as a call counter or a cache dictionary, in the outer function's variables or as attributes of the wrapper.

Common uses are timing, logging, counting calls, retrying, checking arguments and **caching** (memoisation): storing results for arguments already seen. The standard library provides `functools.lru_cache` for caching, which you can use as `@lru_cache(maxsize=None)`.

### Context managers

Day 19 introduced `with open(...) as f:`. A **context manager** is any object that defines what happens when a `with` block is entered and, crucially, when it is left, whether normally or because of an error. The statement `with A as x: body` does: call `A.__enter__()` and bind its return value to `x`, run the body, and finally call `A.__exit__(exc_type, exc_value, traceback)`. The three arguments describe the exception raised in the body, or are all `None` if it ended normally. If `__exit__` returns a true value the exception is suppressed; the default (returning `None`) lets the exception continue. This guarantee is what makes `with` the right tool for pairs of actions that must not be separated: open and close, lock and release, begin and commit, set a state and restore it.

### Writing context managers

You can write a class with `__enter__` and `__exit__`. A shorter way is `contextlib.contextmanager`, which turns a generator function (Day 26) into a context manager. Everything before the single `yield` is the set-up, the yielded value becomes the `as` variable, and everything after it is the clean-up. Wrap the `yield` in `try ... finally` so the clean-up runs even when the body raises. `contextlib` also has ready-made helpers, such as `suppress(ValueError)`, which ignores the named exceptions in its block, and `redirect_stdout`, which captures printed output.

### Common misconception

Learners think a decorator changes the original function's code. It replaces the name with a new function that calls the original. The original still exists inside the wrapper, and `greet.__wrapped__` reaches it when `functools.wraps` is used. Also, a decorator runs at definition time: the line `@shout` runs once, when Python reads the function, not on every call. Only the wrapper runs on every call.

### Why it matters

Cross-cutting concerns in pipelines, such as timing each step, retrying a flaky call, logging inputs and outputs, or releasing a connection, belong in one place. Decorators and context managers keep that code out of the business logic and make sure clean-up always happens.

## Syntax and key functions

```python
import functools

def timed(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        # code before
        result = func(*args, **kwargs)
        # code after
        return result
    return wrapper

@timed
def work(x):
    return x * 2
```

`@timed` is the same as `work = timed(work)`. `functools.wraps(func)` keeps the original's name.

```python
from contextlib import contextmanager

@contextmanager
def opened(name):
    print("enter", name)
    try:
        yield name
    finally:
        print("exit", name)
```

The code before `yield` is set-up, after it is clean-up, and `finally` makes the clean-up unconditional.

| Name | Meaning |
|---|---|
| `*args`, `**kwargs` | Collect any positional / keyword arguments. |
| `@decorator` | Applies `decorator` to the function below it. |
| `functools.wraps(func)` | Copies name and docstring to the wrapper. |
| `functools.lru_cache(maxsize=None)` | Caches results by arguments. |
| `__enter__(self)`, `__exit__(self, t, v, tb)` | Methods that make an object a context manager. |
| `contextlib.contextmanager` | Builds a context manager from a generator. |
| `contextlib.suppress(Exc)` | Ignores the named exceptions in the block. |
| `func.__wrapped__` | The original function behind a `wraps` wrapper. |

## Learn by example

### Example 1: Functions as values

A function is stored in a variable and a dictionary, passed to another function and returned from one. The name without brackets is the function; with brackets it is a call.

```python run
def double(x):
    return x * 2

def square(x):
    return x * x

def apply_twice(func, value):
    return func(func(value))

operations = {"double": double, "square": square}
say = double
print(say(5), apply_twice(square, 3))
for name, func in operations.items():
    print(name, func(4))

def make_multiplier(n):
    def multiply(x):
        return x * n
    return multiply

triple = make_multiplier(3)
print(triple(7), make_multiplier(10)(7))
```

```output
10 81
double 8
square 16
21 70
```

### Example 2: A first decorator

`shout` wraps a function so its text result is upper case. The `@shout` line is shorthand for `greet = shout(greet)`, shown on the last two lines with a plain function. Without `functools.wraps` the name is `wrapper`.

```python run
def shout(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs).upper()
    return wrapper

@shout
def greet(name, punctuation="!"):
    return "hello " + name + punctuation

print(greet("ana"))
print(greet("bo", punctuation="?"))
print(greet.__name__)

def plain(name):
    return "hi " + name

plain = shout(plain)
print(plain("cy"))
```

```output
HELLO ANA!
HELLO BO?
wrapper
HI CY
```

### Example 3: wraps, counting and timing structure

This decorator counts calls and keeps the original name and docstring with `functools.wraps`. The count is stored as an attribute of the wrapper. Timing real durations would vary between runs, so a counter stands in for a stable demonstration.

```python run
import functools

def counted(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        wrapper.calls += 1
        return func(*args, **kwargs)
    wrapper.calls = 0
    return wrapper

@counted
def add(a, b):
    """Add two numbers."""
    return a + b

add(1, 2)
add(3, 4)
print(add.calls, add.__name__, add.__doc__)
print(add.__wrapped__(10, 5), add.calls)
```

```output
2 add Add two numbers.
15 2
```

### Example 4: A decorator with arguments

`repeat(3)` is called first and returns the real decorator. The wrapper runs the function that many times and collects the results. The structure has three levels: parameter, decorator and wrapper.

```python run
import functools

def repeat(times):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            return [func(*args, **kwargs) for _ in range(times)]
        return wrapper
    return decorator

@repeat(3)
def beep(tone):
    return tone + "!"

print(beep("hi"))
print(beep.__name__)
```

```output
['hi!', 'hi!', 'hi!']
beep
```

### Example 5: A caching decorator

The decorator keeps a dictionary of results by argument, so repeated calls reuse earlier answers. A counter of real calls shows the saving: computing 10 Fibonacci numbers recursively would call the function hundreds of times without the cache. This is what `functools.lru_cache` does for you.

```python run
import functools

def memoize(func):
    cache = {}
    @functools.wraps(func)
    def wrapper(n):
        if n not in cache:
            cache[n] = func(n)
        return cache[n]
    return wrapper

real_calls = 0

@memoize
def fib(n):
    global real_calls
    real_calls += 1
    return n if n < 2 else fib(n - 1) + fib(n - 2)

print(fib(30))
print(real_calls)
print(fib(30), real_calls)

@functools.lru_cache(maxsize=None)
def square(n):
    return n * n

square(4); square(4); square(5)
print(square.cache_info().hits, square.cache_info().misses)
```

```output
832040
31
832040 31
1 2
```

### Example 6: Context managers, two ways

The class version prints on entering and leaving and suppresses `ValueError` by returning `True` from `__exit__`. The generator version uses `contextmanager` with `try/finally` so clean-up runs even when the body fails. `suppress` from `contextlib` does the same ignoring in one line.

```python run
from contextlib import contextmanager, suppress

class Section:
    def __init__(self, name):
        self.name = name

    def __enter__(self):
        print("enter", self.name)
        return self

    def __exit__(self, exc_type, exc, tb):
        print("exit", self.name, exc_type.__name__ if exc_type else "ok")
        return exc_type is ValueError

with Section("load") as s:
    print("working in", s.name)
with Section("parse"):
    raise ValueError("bad row")
print("continued")

@contextmanager
def tag(name):
    print(f"<{name}>")
    try:
        yield name
    finally:
        print(f"</{name}>")

try:
    with tag("b") as t:
        print("inside", t)
        raise KeyError("x")
except KeyError:
    print("KeyError escaped")

with suppress(ZeroDivisionError):
    1 / 0
print("done")
```

```output
enter load
working in load
exit load ok
enter parse
exit parse ValueError
continued
<b>
inside b
</b>
KeyError escaped
done
```

## Real-world applications

- **Timing and logging pipeline steps.** One `@timed` or `@logged` decorator applied to every step reports duration and arguments uniformly, without touching the steps' code.
- **Retrying flaky calls.** A `@retry(times=3)` decorator (Example 4's shape) re-calls an API function that sometimes fails, so every client function gains retries by adding one line.
- **Caching expensive lookups.** A cache decorator (Example 5) avoids repeating a slow lookup or computation for the same input.
- **Guaranteed clean-up.** Context managers close files, release database connections, restore settings and roll back a failed transaction even when an error occurs (Example 6).

## Daily review

### Key takeaways

- Functions are values: pass them by name, store them and return them; brackets mean "call".
- A decorator takes a function and returns a wrapper; `@d` above a function means `f = d(f)`.
- Use `*args, **kwargs` in wrappers, return the result, and add `functools.wraps`.
- A decorator with arguments needs an extra outer layer.
- `with` calls `__enter__` first and `__exit__` always; `@contextmanager` builds one from a generator with `try/finally`.

### Common mistakes

- Forgetting to `return` the result inside the wrapper, so the decorated function returns `None`.
- Writing `@repeat` instead of `@repeat(3)` for a decorator that takes arguments, which makes the function itself the argument and fails with a confusing `TypeError`.
- Passing `func()` instead of `func`, which calls the function and passes its result.
- Leaving out `functools.wraps`, so error messages and help show `wrapper` as the name.
- Putting the clean-up after `yield` in a `@contextmanager` function without `try/finally`, so it is skipped when the body raises.
- Expecting the decorator body to run on every call. The outer function runs once at definition; only the wrapper runs on each call.
- Returning `True` from `__exit__` by accident (for example by ending with a comparison), which silently swallows every error.

### Revision notes

- `@d` over `def f` is `f = d(f)`; the wrapper is `def wrapper(*args, **kwargs): return func(*args, **kwargs)`.
- `@functools.wraps(func)` on the wrapper; `@lru_cache(maxsize=None)` for caching.
- Decorator with arguments: outer(args) returns decorator(func) returns wrapper.
- `with obj as x:` calls `__enter__` then `__exit__(type, value, traceback)`.
- `@contextmanager`: set-up, `try: yield value finally: clean-up`.
