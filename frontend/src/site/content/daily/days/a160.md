## Objectives

- Read an Excel sheet into a DataFrame with `read_excel`, choosing the sheet and the header row, and read the same messy structure from CSV text in the browser.
- Normalise messy headers (spaces, capitals, symbols) into stable snake_case column names with one small function.
- Convert text columns to proper types (numbers, dates, categories), and count what could not be converted instead of hiding it.
- Remove non-data rows (titles, blank separators, totals) and fill values that Excel merged cells left empty.
- Design a PostgreSQL target table (types, keys, constraints) for the cleaned data and check a DataFrame against it before loading.

## Understand

### Excel is made for people, databases are made for programs

A spreadsheet is designed to be read by a person. It can have a title in the first row, a blank line, headers that wrap onto two words, a region name written once and merged over five rows, amounts formatted with a currency sign and thousands separators, and a "Total" line at the bottom. Every one of these helps a human reader and every one breaks a program. A database table is the opposite: one header row, one record per row, one type per column, no decoration. The work of this day and the next is the bridge: **Excel, then a DataFrame, then a PostgreSQL table**. Day 160 covers reading and cleaning and designing the target; Day 161 covers loading it safely.

The bridge has a rule that saves most of the pain: **read first, clean second, and clean in code**. Never fix the workbook by hand before loading. A hand-edited file cannot be repeated next month when the new export arrives, and nobody can say what was changed. Code that cleans a file can be rerun on the next export, reviewed by a colleague and tested.

### Reading Excel with pandas

`pd.read_excel(path, sheet_name=..., header=...)` returns a DataFrame. The important arguments are `sheet_name` (a name, a position or a list), `header` (the zero-based row that holds the column names: for a sheet with a title row and a blank row the headers are on row index 2), `usecols` (which columns to keep), `nrows`, `na_values` (extra texts that mean missing, such as `n/a`) and `dtype`. Reading `.xlsx` needs the `openpyxl` package, which the browser Python does not have. That is why this lesson shows `read_excel` in a local example and does all browser-run work on **CSV text with the same messy structure**. Once the data is in a DataFrame, the cleaning code is identical, because CSV text and a worksheet both end up as a table of cells. In a real sheet, Excel stores dates as numbers (days since a start date) with a date format; `openpyxl` converts a cell with a date format into a Python date, so a properly formatted column arrives as dates, while a column of dates typed as text arrives as text.

A habit that avoids silent damage is to read every column as text first (`dtype=str`) and convert each column explicitly. If pandas guesses, a column that is mostly numbers but has `n/a` in one row becomes text, and a column of identifiers such as `00123` loses its leading zeros.

### Cleaning headers

Headers like `Customer Name ` (with a trailing space), `Amount (EUR)` and `Order ID` are awkward: they need quotes in SQL, they differ between exports by a space or a capital, and they do not match the target table. A **header cleaner** applies the same rule to each name: lower-case, replace every run of characters that are not letters or digits by one underscore, and strip underscores at the ends. The three headers above become `customer_name`, `amount_eur` and `order_id`. Because the same function runs on every export, a changed capital letter in next month's file does not break the load. If two headers become the same name after cleaning, the function must raise an error rather than overwrite one column silently.

### Cleaning types and counting what failed

Each column gets an explicit conversion. Amounts: remove everything except digits, the decimal point and a minus sign, then `pd.to_numeric(..., errors="coerce")`. The option `errors="coerce"` turns anything that cannot be converted into missing (`NaN`), which is useful only if you then **count the missing values and report them**. A conversion that silently turns 5% of the amounts into missing values is a data-quality incident hiding in a clean-looking table. Dates: `pd.to_datetime(s, format="%Y-%m-%d", errors="coerce")` accepts only the format you state, so a row written `15/01/2025` becomes `NaT` (not a time) and is reported rather than guessed (a date such as `05/02/2025` is ambiguous between 5 February and 2 May, and guessing is how wrong dates reach reports). Categories such as a status are stripped and lower-cased so that `Paid`, `paid` and `PAID ` become one value.

Non-data rows need removing: titles and blank separators are skipped when reading, and the **totals row** is dropped after checking it. Keep the reported total, though: it is a free check. After cleaning, the sum of the amounts should equal the total from the sheet, and a difference means a row was lost or a value misread.

Merged cells are a special case. When a region is merged over several rows, only the first row holds the value and the rest are empty. A forward fill (`ffill()`) copies the last seen value downwards, which restores the region for every row. Use it only on columns where a blank genuinely means "same as above".

### The target table

A **target table** is the PostgreSQL table the cleaned data will be loaded into. Design it on purpose; do not let a loading function invent it. Choose a type for each column that matches the meaning (`integer` or `bigint` for identifiers, `text` for names, `date` for dates, `numeric(12,2)` for money, never `float`, because binary floating point cannot represent 0.10 exactly), mark the key columns, decide which columns may be empty (`NOT NULL` for the ones that must not), and add `CHECK` constraints for rules such as `amount >= 0` or an allowed list of statuses. PostgreSQL enforces all of this: a row that violates a constraint is rejected, which is exactly what you want. The browser example creates a table on a PostgreSQL-compatible database and reads its column types from `information_schema.columns`; the Python code that sends it would use `psycopg` with the same SQL.

### Why it matters, and the misconception

Most analytics projects begin with someone's spreadsheet. If the conversion to a database table is repeatable, the analysis is repeatable. The common misconception is that `read_excel` returns clean data because the result looks like a table. It looks like a table, but the types, the headers and the extra rows are whatever the file contained. A second misconception is that a loader such as `to_sql` will choose good column types. It chooses generic ones; for a real target table you create the table yourself, which is the topic of Day 161.

## Syntax and key functions

```python
import pandas as pd

df = pd.read_excel("sales.xlsx", sheet_name="Orders", header=2, dtype=str)   # needs openpyxl
df = pd.read_csv(io.StringIO(text), skiprows=2, dtype=str)                   # same structure, from text
```

```sql-syntax
CREATE TABLE <name> (
    <column> <type> [NOT NULL] [PRIMARY KEY] [CHECK (<condition>)],
    ...
);
```

| Function | Returns or does |
|---|---|
| `pd.read_excel(path, sheet_name, header, usecols, dtype, na_values)` | DataFrame from a worksheet (needs `openpyxl`). |
| `pd.read_csv(io.StringIO(text), skiprows, dtype=str)` | DataFrame from CSV text. |
| `df.columns.str.strip().str.lower().str.replace(r"[^0-9a-z]+", "_", regex=True)` | Cleaned header names. |
| `pd.to_numeric(s, errors="coerce")` | Numbers; unconvertible values become `NaN`. |
| `pd.to_datetime(s, format=..., errors="coerce")` | Dates; unparsable values become `NaT`. |
| `s.str.strip()`, `s.str.lower()`, `s.str.replace(pat, repl, regex=True)` | Text cleaning. |
| `s.ffill()` | Copies the last non-missing value downwards. |
| `df.isna().sum()` | Count of missing values per column. |

## Learn by example

The messy sheet used here is an export called "Sales export - Q1 2025": a title row, a separator row of commas, headers with spaces, amounts such as `1,200.50` and `€89.90`, one `n/a`, one date written in another format, a region written only on the first row of each group, and a `Total` line at the end. The examples read it from CSV text, which has the same layout as the worksheet.

### Example 1: Reading past the title rows

Reading the text as it is makes pandas treat the title as the header. Skipping the first two lines (`skiprows=2`, the equivalent of `header=2` in `read_excel`) puts the real header in place. Reading with `dtype=str` keeps every cell as the text it was.

```python run
import io
import pandas as pd

RAW = """Sales export - Q1 2025
,,,,,
Order ID,Customer Name ,Order Date,Amount (EUR),Status,Region
1001,Ana Silva,2025-01-05,"1,200.50",Paid,North
1002,ben OKAFOR,2025-01-07,310,paid,
1003,Cy Tran,2025-01-09,€89.90,PAID ,South
1004,Dee Park,15/01/2025,n/a,Refunded,
1005,Eli Roth,2025-01-21,"2,050.00",Paid,
1006,Fay Lund,2025-01-30,45.5,failed,West
Total,,,"3,695.90",,
"""
wrong = pd.read_csv(io.StringIO(RAW), dtype=str)
print("as is:", list(wrong.columns)[:3])
df = pd.read_csv(io.StringIO(RAW), skiprows=2, dtype=str)
print("headers:", list(df.columns))
print("shape:", df.shape)
print(df.tail(2).to_string(index=False))
```

```output

    1006       Fay Lund 2025-01-30         45.5 failed   West

```

The shape includes the totals line, which is not a record. The header names still carry a trailing space and a bracket, which the next example fixes.

### Example 2: A header cleaner that refuses collisions

One function applies the same rule to every header. If two cleaned names collide, it raises an error, so a column is never dropped silently.

```python run
import re

def clean_header(name):
    return re.sub(r"[^0-9a-z]+", "_", name.strip().lower()).strip("_")

def clean_headers(names):
    cleaned = [clean_header(n) for n in names]
    dupes = sorted({c for c in cleaned if cleaned.count(c) > 1})
    if dupes:
        raise ValueError("duplicate headers after cleaning: " + ", ".join(dupes))
    return cleaned

headers = ["Order ID", "Customer Name ", "Order Date", "Amount (EUR)", "Status", "Region"]
print(clean_headers(headers))
try:
    clean_headers(["Amount (EUR)", "amount eur", "Status"])
except ValueError as e:
    print(e)
```

```output
['order_id', 'customer_name', 'order_date', 'amount_eur', 'status', 'region']
duplicate headers after cleaning: amount_eur
```

The cleaned names are stable: `Amount (EUR)` and `amount eur` collapse to `amount_eur`, so the second call correctly fails instead of losing a column.

### Example 3: Clean the types and report what failed

Each column is converted explicitly. Counting the missing values after the conversion turns silent failures into a visible report, and the cleaned amounts are compared with the total printed in the sheet.

```python run
import io
import re
import pandas as pd

RAW = """Sales export - Q1 2025
,,,,,
Order ID,Customer Name ,Order Date,Amount (EUR),Status,Region
1001,Ana Silva,2025-01-05,"1,200.50",Paid,North
1002,ben OKAFOR,2025-01-07,310,paid,
1003,Cy Tran,2025-01-09,€89.90,PAID ,South
1004,Dee Park,15/01/2025,n/a,Refunded,
1005,Eli Roth,2025-01-21,"2,050.00",Paid,
1006,Fay Lund,2025-01-30,45.5,failed,West
Total,,,"3,695.90",,
"""
def clean_header(name):
    return re.sub(r"[^0-9a-z]+", "_", name.strip().lower()).strip("_")

df = pd.read_csv(io.StringIO(RAW), skiprows=2, dtype=str)
df.columns = [clean_header(c) for c in df.columns]

total_row = df[df["order_id"] == "Total"].iloc[0]
reported_total = float(total_row["amount_eur"].replace(",", ""))
df = df[df["order_id"] != "Total"].copy()

df["order_id"] = pd.to_numeric(df["order_id"]).astype("int64")
df["customer_name"] = df["customer_name"].str.strip().str.title()
df["order_date"] = pd.to_datetime(df["order_date"], format="%Y-%m-%d", errors="coerce")
df["amount_eur"] = pd.to_numeric(df["amount_eur"].str.replace(r"[^0-9.\-]", "", regex=True), errors="coerce")
df["status"] = df["status"].str.strip().str.lower()
df["region"] = df["region"].ffill()

print(df.to_string(index=False))
print("missing:", {k: int(v) for k, v in df.isna().sum().items() if v})
print("sum matches sheet total:", round(float(df["amount_eur"].sum()), 2) == reported_total)
```

```output
 order_id customer_name order_date  amount_eur   status region
     1001     Ana Silva 2025-01-05      1200.5     paid  North
     1002    Ben Okafor 2025-01-07       310.0     paid  North
     1003       Cy Tran 2025-01-09        89.9     paid  South
     1004      Dee Park        NaT         NaN refunded  South
     1005      Eli Roth 2025-01-21      2050.0     paid  South
     1006      Fay Lund 2025-01-30        45.5   failed   West
missing: {'order_date': 1, 'amount_eur': 1}
sum matches sheet total: True
```

Two problems are now visible instead of hidden: the date `15/01/2025` became `NaT` and the amount `n/a` became `NaN`. The sum of the cleaned amounts equals the total in the sheet because the `n/a` row contributed nothing to either. The forward fill gave orders 1002, 1004 and 1005 a region; whether that is right depends on how the sheet was merged, so confirm it with the owner of the file.

### Example 4: The same read from a real workbook (local)

This example builds an `.xlsx` file in a temporary folder with `openpyxl`, including a title row, a blank row, real date cells and a merged region cell, and reads it with `read_excel`. It needs `pip install openpyxl pandas` and runs on your own computer; the browser shows it read-only with the verified output.

```python local
import datetime
import os
import tempfile
import pandas as pd
from openpyxl import Workbook

wb = Workbook()
ws = wb.active
ws.title = "Orders"
ws.append(["Sales export - Q1 2025"])
ws.append([])
ws.append(["Order ID", "Customer Name ", "Order Date", "Amount (EUR)", "Region"])
ws.append([1001, "Ana Silva", datetime.date(2025, 1, 5), 1200.5, "North"])
ws.append([1002, "Ben Okafor", datetime.date(2025, 1, 7), 310, None])
ws.append([1003, "Cy Tran", datetime.date(2025, 1, 9), "n/a", "South"])
ws.append([1004, "Dee Park", datetime.date(2025, 1, 12), 99, None])
ws.merge_cells("E4:E5")
ws.merge_cells("E6:E7")

with tempfile.TemporaryDirectory() as folder:
    path = os.path.join(folder, "sales.xlsx")
    wb.save(path)
    df = pd.read_excel(path, sheet_name="Orders", header=2, na_values=["n/a"])

print(list(df.columns))
print(df.dtypes.astype(str).to_dict())
df["Region"] = df["Region"].ffill()
print(df.to_string(index=False))
```

```output
['Order ID', 'Customer Name ', 'Order Date', 'Amount (EUR)', 'Region']
{'Order ID': 'int64', 'Customer Name ': 'object', 'Order Date': 'datetime64[ns]', 'Amount (EUR)': 'float64', 'Region': 'object'}
 Order ID Customer Name  Order Date  Amount (EUR) Region
     1001      Ana Silva 2025-01-05        1200.5  North
     1002     Ben Okafor 2025-01-07         310.0  North
     1003        Cy Tran 2025-01-09           NaN  South
     1004       Dee Park 2025-01-12          99.0  South
```

The dates arrive as real dates because the cells have a date format, `na_values=["n/a"]` turned the text into a missing value so the amount column is numeric, and the merged cells show up as missing values below the first row of each group until the forward fill.

### Example 5: The target table in PostgreSQL

The target table states the types and rules. The block creates it on the PostgreSQL-compatible browser database, inserts two cleaned rows, and then reads the column types back from `information_schema.columns`, which is where PostgreSQL describes its tables. `numeric(12,2)` stores money exactly; the `CHECK` list and `NOT NULL` reject bad rows. The Python script would send the same `CREATE TABLE` with `psycopg` before loading.

```sql run
DROP TABLE IF EXISTS xl_sales_orders;
CREATE TABLE xl_sales_orders (
    order_id      integer PRIMARY KEY,
    customer_name text NOT NULL,
    order_date    date,
    amount_eur    numeric(12,2) CHECK (amount_eur >= 0),
    status        text NOT NULL CHECK (status IN ('paid', 'refunded', 'failed')),
    region        text
);
INSERT INTO xl_sales_orders VALUES
    (1001, 'Ana Silva', DATE '2025-01-05', 1200.50, 'paid', 'North'),
    (1002, 'Ben Okafor', DATE '2025-01-07', 310, 'paid', 'North');
SELECT column_name, data_type, is_nullable
FROM information_schema.columns
WHERE table_name = 'xl_sales_orders'
ORDER BY ordinal_position;
```

```output
column_name | data_type | is_nullable
order_id | integer | NO
customer_name | text | NO
order_date | date | YES
amount_eur | numeric | YES
status | text | NO
region | text | YES
```

The key column is `NOT NULL` automatically (a primary key cannot be empty), which the output shows. These types and constraints are PostgreSQL features. SQLite (the stand-in used in Python examples) would accept text in a numeric column and ignore column lengths, so type problems have to be caught by checks in the cleaning code, as in the next example.

### Example 6: Check the DataFrame against the target before loading

A function lists every way the cleaned data would violate the target table's rules. Running it before the load turns a failed database insert into a readable report.

```python run
import pandas as pd

df = pd.DataFrame({
    "order_id": [1001, 1002, 1003, 1003],
    "customer_name": ["Ana Silva", "Ben Okafor", None, "Cy Tran"],
    "order_date": pd.to_datetime(["2025-01-05", "2025-01-07", None, "2025-01-09"]),
    "amount_eur": [1200.5, -310.0, 89.9, 89.9],
    "status": ["paid", "paid", "pending", "failed"],
})
ALLOWED_STATUS = {"paid", "refunded", "failed"}

def problems(frame):
    found = []
    if frame["order_id"].duplicated().any():
        found.append("duplicate order_id: " + str(sorted(frame.loc[frame["order_id"].duplicated(), "order_id"].tolist())))
    if frame["customer_name"].isna().any():
        found.append("customer_name is NOT NULL: " + str(int(frame["customer_name"].isna().sum())) + " missing")
    if (frame["amount_eur"] < 0).any():
        found.append("amount_eur must be >= 0: " + str(int((frame["amount_eur"] < 0).sum())) + " negative")
    bad = sorted(set(frame["status"]) - ALLOWED_STATUS)
    if bad:
        found.append("status not allowed: " + ", ".join(bad))
    return found

for p in problems(df):
    print(p)
print("problems found:", len(problems(df)))
```

```output
duplicate order_id: [1003]
customer_name is NOT NULL: 1 missing
amount_eur must be >= 0: 1 negative
status not allowed: pending
problems found: 4
```

The function reports four problems. Checking does not repair anything: the load must wait until the rows are fixed or moved aside. Day 161 uses this check inside a safe load.

## Real-world applications

- **Monthly finance exports**: the finance team sends the same workbook layout each month; a function that skips the title rows, cleans the headers and drops the total line (Examples 1 to 3) loads each new file without manual editing.
- **Data-quality reports**: counting the values that could not be converted and comparing the cleaned sum with the sheet's total (Example 3) tells the file's owner exactly which rows to correct.
- **Designing the warehouse table**: choosing `numeric(12,2)`, `date` and `CHECK` constraints before loading (Example 5) means that later bad data is rejected at the door instead of being found in a dashboard.
- **Pre-load validation**: the check function of Example 6 is run on every file and its output attached to the load log.

## Daily review

### Key takeaways

- Read first, clean second, and clean in code so the work is repeatable.
- `read_excel` needs `openpyxl`; the browser examples use CSV text with the same layout, and the cleaning code is the same.
- One header-cleaning function (lower case, non-alphanumerics to underscores) keeps names stable and must reject collisions.
- Convert with `errors="coerce"` only if you then count and report the failures; state date formats explicitly.
- Drop totals after using them as a check; forward-fill merged cells only where a blank means "same as above".
- The target table has deliberate types, keys and constraints; use `numeric` for money.

### Common mistakes

- Letting pandas guess types. An `n/a` in one row turns a numeric column into text and identifiers lose leading zeros; read with `dtype=str` and convert explicitly.
- Converting with `errors="coerce"` and never looking at the result. Rows disappear from totals; print `df.isna().sum()`.
- Parsing dates without a format. `05/02/2025` is read as 5 May in one place and 2 May in another; give `format=`.
- Leaving the totals row in. The total is added to the sum, so the report counts everything twice; drop it and compare.
- Using `float` for money in the target table. Sums show tiny errors such as 0.30000000000000004; use `numeric(12,2)`.

### Revision notes

- `pd.read_excel(path, sheet_name=..., header=2, dtype=str)`; CSV equivalent `skiprows=2`.
- Header rule: `strip`, `lower`, `re.sub(r"[^0-9a-z]+", "_", ...)`, `strip("_")`.
- `pd.to_numeric(errors="coerce")`, `pd.to_datetime(format=..., errors="coerce")`, then count the missing values.
- `ffill()` for merged cells.
- Target table: types, `NOT NULL`, `PRIMARY KEY`, `CHECK`, `numeric(12,2)`.
