## Objectives

- Write a `while` loop whose condition decides when to stop, and trace its variables step by step.
- Read a series of inputs until a sentinel value ends the loop.
- Leave a loop early with `break` and skip to the next pass with `continue`.
- Use the `else` clause of a loop to detect that the loop finished without a `break`.
- Spot and fix an infinite loop, and choose between `for` and `while`.

## Understand

### Repeat while something is true

A `for` loop (Day 11) repeats once per item. Often you do not know how many repetitions you need: ask for a password until it is correct, keep reading lines until the user types `quit`, halve a number until it is small. A **`while` loop** repeats its block **as long as a condition is true**.

```text
while condition:
    block
```

Python checks the condition before every pass. If it is true, the block runs and the condition is checked again. If it is false, the loop ends and the program carries on after the block. The picture is a door guard who looks at a rule each time you approach: if the rule still holds you go round again.

If the condition is false at the very start, the block never runs. That is not an error; it just means zero passes.

### The three parts of a safe while loop

A correct `while` loop has three parts, and forgetting any one causes bugs.

1. **Set up** a variable before the loop so the condition can be evaluated: `count = 0`.
2. **Test** it in the condition: `while count < 3:`.
3. **Change** it inside the block so the condition can eventually become false: `count += 1`.

If the block never changes anything the condition depends on, the condition stays true forever. That is an **infinite loop**: the program hangs and prints forever. In a terminal you stop it with Ctrl+C. In the browser a runaway program has to be stopped with the Stop button or by reloading the page, so trace your loop before you run it. When you write a loop, always ask: "what changes each pass, and does it move towards the condition becoming false?"

### Sentinel loops

A **sentinel** is a special value that means "stop", such as the text `"done"` or an empty line. A sentinel loop reads a value, checks for the sentinel, handles real values, and reads the next. The standard shape reads once before the loop and again at the end of each pass:

```text
line = input()
while line != "done":
    handle(line)
    line = input()
```

The first read happens before the loop, so the check has something to test. The second read is the "change" step. A common alternative is a loop that runs forever on purpose with `while True:` and ends with `break` when the sentinel arrives.

### break and continue

`break` ends the **nearest enclosing loop** immediately. Python jumps to the first line after the loop. `continue` ends only the **current pass** and goes back to the loop's condition (or to the next item in a `for` loop). Use `break` when you have found what you were looking for or when a stop signal arrives. Use `continue` to skip an item that does not need processing, which avoids deeply indented `if` blocks.

Be careful with `continue` in a `while` loop: it jumps straight to the condition check, so any update of the loop variable placed after the `continue` is skipped. That is a classic way to create an infinite loop.

### The else clause of a loop

A loop can have an `else:` block. It runs **only if the loop ended normally**, that is, without a `break`. This matches a search: "look through the items; if you found it, stop; else (nothing found) report that". The word `else` here is not "otherwise" in the sense of `if`; read it as "no break happened". The clause works on `for` loops too.

### for or while?

Use `for` when you have a collection or a known count. Use `while` when the number of passes depends on something that changes during the loop, such as input or a value that converges. Any `for` loop can be written as a `while`, but the reverse is not true, and the `for` version has no risk of an infinite loop, so prefer it when it fits.

### Why it matters

Pipelines retry operations until they succeed, readers process lines until the end of a stream, and algorithms repeat until a measure is small enough. All of these are `while` loops with a clear stop rule.

### A worked trace, and a trap with decimals

Trace `value = 100`, `while value >= 1: value = value / 2`. Before each pass the condition is tested: 100, 50, 25, 12.5, 6.25, 3.125 and 1.5625 are all at least 1, so the block runs seven times. After the seventh halving the value is 0.78125, the test is false and the loop ends. Writing the value after each pass shows that the variable moves steadily towards making the condition false, which is exactly what a safe loop needs.

The most common infinite loop for data work involves decimals. A loop such as `while x != 1.0:` that adds 0.1 each time never reaches exactly 1.0, because 0.1 cannot be stored exactly (Day 6). The comparison is never true and the program hangs. Use an inequality such as `while x < 1.0:`, or count whole steps with an integer. In general, test with `<`, `<=`, `>` or `>=` rather than `!=` or `==` when the variable changes by steps, because a step can jump over the exact value. As a safety net for loops that wait for something, keep a counter and `break` after a maximum number of tries, as Example 6 does.

## Syntax and key functions

```text
while condition:
    block                  # must change something the condition uses

while True:
    ...
    if stop_signal:
        break              # leave the loop now

for/while ...:
    if skip_this:
        continue           # go to the next pass
else:
    block                  # runs only when no break happened
```

| Keyword | Effect |
|---|---|
| `while cond:` | repeat while `cond` is truthy; test before each pass |
| `break` | leave the nearest loop immediately |
| `continue` | skip the rest of this pass |
| loop `else:` | run when the loop ends without `break` |
| `input()` | read one line of text (the sentinel pattern uses it) |

## Learn by example

### Example 1: A counting loop

```python run
count = 1
while count <= 4:
    print("pass", count)
    count += 1
print("finished with count =", count)
```

```output
pass 1
pass 2
pass 3
pass 4
finished with count = 5
```

After the loop `count` is 5, because the condition `count <= 4` was false at that point.

### Example 2: A loop whose length is not known in advance

How many times can you halve 100 before the value drops below 1? A `for` loop cannot answer that without knowing the count.

```python run
value = 100
steps = 0
while value >= 1:
    value = value / 2
    steps += 1
print(steps, value)
```

```output
7 0.78125
```

### Example 3: A sentinel loop with input

The program reads numbers until the line `done`, adding them up. The input lines are given in `stdin`.

```python run
total = 0
count = 0
line = input()
while line != "done":
    total += int(line)
    count += 1
    line = input()
print("count:", count)
print("total:", total)
```

```stdin
10
25
7
done
```

```output
count: 3
total: 42
```

### Example 4: break and continue

```python run
readings = [12, -1, 15, 0, 18, 999, 20]
good = []
for r in readings:
    if r == 999:
        print("stop signal")
        break
    if r < 0:
        continue
    good.append(r)
print(good)
```

```output
stop signal
[12, 15, 0, 18]
```

`-1` was skipped by `continue`. At `999` the loop ended, so `20` was never read.

### Example 5: A search with the loop else

```python run
names = ["Ada", "Bo", "Cy"]
target = "Di"
for name in names:
    if name == target:
        print("found", name)
        break
else:
    print(target, "not in list")
target = "Bo"
for name in names:
    if name == target:
        print("found", name)
        break
else:
    print(target, "not in list")
```

```output
Di not in list
found Bo
```

The `else` printed only in the first search, where no `break` happened.

### Example 6: Validate input with a limited number of tries

The program reads guesses until one is correct or three tries are used up. It uses `while True`, `break` and a counter, and the safeguard prevents an infinite loop. The guesses come from `stdin`.

```python run
secret = "python"
tries = 0
while True:
    guess = input().strip().lower()
    tries += 1
    if guess == secret:
        print("Correct after", tries, "tries")
        break
    if tries == 3:
        print("No more tries")
        break
    print("Wrong, try again")
```

```stdin
java
Sql
  PYTHON
```

```output
Wrong, try again
Wrong, try again
Correct after 3 tries
```

## Real-world applications

- **Reading until the end.** Reading a stream or file line by line until it is empty, or until an end marker, is a sentinel loop.
- **Retrying.** A data pipeline tries a flaky step until it succeeds or reaches a maximum number of attempts, which needs a counter and `break`.
- **Searching.** Looking for the first record that matches a rule, then stopping, uses `break`; the loop `else` reports that nothing matched.
- **Skipping bad rows.** `continue` skips blank or malformed rows without wrapping the rest of the code in an `if`.

## Daily review

### Key takeaways

- `while` repeats as long as its condition is true; the condition is tested before each pass.
- Set up, test and change the loop variable, or the loop never ends.
- A sentinel loop reads before the loop and again at the end of each pass, or uses `while True` with `break`.
- `break` leaves the loop; `continue` skips to the next pass; loop `else` runs only when there was no `break`.
- Prefer `for` when you have a collection or fixed count.

### Common mistakes

- **Forgetting to update the variable.** `while count < 3:` without `count += 1` hangs forever. Add the update.
- **Putting the update after `continue`.** The update is skipped and the loop sticks. Update before `continue`.
- **Reading the sentinel only once.** The loop checks the same line forever. Read the next line at the end of the block.
- **Using `int(line)` on the sentinel.** `int("done")` raises `ValueError: invalid literal for int() with base 10: 'done'`. Test for the sentinel first.
- **Off-by-one in the condition.** `while count < 3` runs 3 times starting from 0; `<= 3` runs 4. Trace by hand.
- **Reading `else` as "otherwise".** The loop `else` runs when no `break` happened, even if the loop body ran many times.

### Revision notes

- `while cond:` with setup, test, change.
- Sentinel: read, test, handle, read again.
- `break` leaves; `continue` skips; loop `else` means no break.
- Infinite loop: stop with Ctrl+C, then fix the update.
