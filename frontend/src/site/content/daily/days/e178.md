## Objectives

- Run a DAG with retries, and show that a failed task marks its downstream tasks as not run instead of running them on bad input.
- Read an Airflow DAG definition for the pipeline and map each part (schedule, retries, dependencies) to the Python model.
- Write pytest tests for the cleaning rules and the stage counts, and run them from the shell.
- Define run metrics and alert rules that notice an empty load, a rising quarantine rate or a shrinking fact table.

## Understand

### From a script to a scheduled pipeline

Days 174 to 177 built four stages. Run by hand in the right order they give the right answer, but a production pipeline needs more: something that runs the stages in order every day, retries a flaky call, stops cleanly when a stage fails, and tells a person. That is **orchestration**. An orchestrator such as Apache Airflow does not process data itself. It runs your tasks, in order, on a schedule, and records what happened.

### The DAG

The stages and their dependencies form a **DAG**, a directed acyclic graph: tasks are the nodes, an arrow from A to B means B needs A's output, and no chain of arrows leads back to its start (there are no cycles, so there is always a valid order). For the capstone: `ingest` first; then `clean` and `load_dims`, which do not need each other; `load_fact` needs both; and after it `quality_checks` and `analytics`, again independent. The **run order** comes from a topological sort: repeatedly take every task whose dependencies are done. The tasks taken together in one round could run in parallel. A cycle makes the sort stop, which is how an orchestrator rejects a bad DAG.

### Retries and failure

A task can fail for a temporary reason, such as a rate limit or a network error, and succeed on the next try, so each task has a number of **retries** with a delay. A task that still fails after its retries is `failed`, and every task that depends on it is marked `upstream_failed` and not run, because running `load_fact` after a failed `clean` would load nothing or load stale data. Independent branches still run, which keeps as much of the pipeline working as possible. Retries are safe only because each task is idempotent, the property built on Days 174 and 176: running it twice gives the same result.

### Airflow in this lesson

Airflow is not available here, so the lesson models its core ideas in plain Python, which you can run and grade, and shows the Airflow code for the same DAG in a read-only block. In Airflow a DAG is a Python file: you create a `DAG` object with a schedule and default arguments, create one operator per task, and declare dependencies with `>>`. The scheduler reads the file, creates a run per schedule interval and tracks each task's state. Setting up an Airflow server is outside this course; the environment note says how to try it on your computer.

### Tests

A **test** is a small program that checks one behaviour and fails loudly. `pytest` finds functions named `test_*`, runs them and reports passes and failures. For a pipeline, tests protect the rules: a record with a negative amount must be quarantined, a valid record must be transformed to the expected keys, and the generated data must clean to 114 good and 6 quarantined records. A test is cheap insurance: when someone changes a rule, the test that encodes the old behaviour fails the same day, not at the next quarterly report.

### Monitoring

**Monitoring** means recording numbers about every run and alerting on the unusual: rows read, rows loaded, rows quarantined, the fact table size. Simple rules catch most problems: no rows loaded, quarantine above 5 percent of the rows read, the fact table smaller than yesterday. The numbers cost nothing to produce, because the stages already count them. Alerts should name the rule and the numbers, so that the person receiving them can act.

### Common misconception

Learners think the orchestrator makes the pipeline correct. It only runs what you give it, in order. A scheduled pipeline with no checks fails silently every day at the scheduled time, and nobody notices until a report is wrong.

### Why it matters

An unattended pipeline is only as good as its failure handling. Order, retries, tests and alerts are what let you go home.

|---|---|
| `topo(tasks)` | The run order as a list of task names. |
| `levels(tasks)` | Groups of tasks that could run in parallel. |

## Learn by example

### Example 1: The DAG, its order and its parallel groups

The pipeline is a dictionary of tasks with their dependencies. `topo` returns a valid run order and `levels` groups the tasks that could run at the same time. `clean` and `load_dims` share a group because neither needs the other. The last lines show that a cycle is rejected.

```python run
def topo(tasks):
    """Run order: repeatedly take every task whose dependencies are done (sorted for a stable order)."""
    done, order = set(), []
    while len(order) < len(tasks):
        ready = sorted(n for n, t in tasks.items() if n not in done and all(d in done for d in t["deps"]))
        if not ready:
            raise ValueError("cycle in the DAG")
        order += ready
        done.update(ready)
    return order

def levels(tasks):
    """Groups of tasks that could run in parallel: all dependencies are in earlier groups."""
    done, groups = set(), []
    while len(done) < len(tasks):
        ready = sorted(n for n, t in tasks.items() if n not in done and all(d in done for d in t["deps"]))
        if not ready:
            raise ValueError("cycle in the DAG")
        groups.append(ready)
        done.update(ready)
    return groups

noop = lambda ctx: None
tasks = {
    "ingest": {"deps": [], "fn": noop},
    "clean": {"deps": ["ingest"], "fn": noop},
    "load_dims": {"deps": ["ingest"], "fn": noop},
    "load_fact": {"deps": ["clean", "load_dims"], "fn": noop},
    "quality_checks": {"deps": ["load_fact"], "fn": noop},
    "analytics": {"deps": ["load_fact"], "fn": noop},
}
print("order:", topo(tasks))
print("parallel groups:", levels(tasks))
tasks["ingest"]["deps"] = ["analytics"]
try:
    topo(tasks)
except ValueError as e:
    print("error:", e)
```

error: cycle in the DAG

### Example 2: Run the real pipeline as a DAG, with metrics

Each task is a function of a shared `ctx` dictionary (named `run_...` so that they do not hide the loader functions), using the code of Days 174 to 176: `ingest` calls the rate-limited stand-in API, `clean` splits clean and quarantined records, `load_dims` and `load_fact` fill the star schema, `quality_checks` raises an error when a check fails, and `analytics` computes revenue per month. After the run, a metrics dictionary and an alert function summarise it. The alert rule fires when more than 5 percent of the rows read were quarantined; here 6 of 120 is exactly 5 percent, so no alert fires.

    orders[29]["amount_cents"] = -1000
    orders[44]["customer_id"] = "C999"
    orders[59]["created_at"] = ""
    orders[74]["currency"] = "???"
    orders[104]["status"] = "pending"
    orders[119] = dict(orders[9])
    return customers, products, orders

class RateLimited(Exception):
    def __init__(self, retry_after):
        super().__init__("429 too many requests")
        self.retry_after = retry_after

class Unauthorized(Exception):
    pass

def make_api(orders, api_key="secret-key", every=3):
    """Stand-in for GET /orders?page=N&page_size=P: no network, same answers (200, 401, 429)."""
    state = {"calls": 0, "limited": 0}
    def get_orders(page, page_size, headers):
        state["calls"] += 1
        if headers.get("X-Api-Key") != api_key:
            raise Unauthorized("401 invalid API key")
        if every and state["calls"] % every == 0:
            state["limited"] += 1
            raise RateLimited(2)
        total = -(-len(orders) // page_size)
        start = (page - 1) * page_size
        return {"data": orders[start:start + page_size], "page": page, "total_pages": total}
    return get_orders, state

def fetch_page(api, page, size, headers, sleep, max_tries=5):
    for attempt in range(max_tries):
        try:
            return api(page, size, headers)
        except RateLimited as e:
            sleep(e.retry_after * 2 ** attempt)
    raise RuntimeError(f"page {page} still rate limited after {max_tries} tries")

def fetch_all(api, headers, sleep, size=25):
    records, page, total = [], 1, 1
    while page <= total:
        body = fetch_page(api, page, size, headers, sleep)
        records.extend(body["data"])
        total = body["total_pages"]
        page += 1
    return records

from datetime import datetime

def first_problem(rec, seen, known):
    """The first rule a raw order breaks, or None. `seen` holds the order ids already processed."""
    if rec["order_id"] in seen:
        return "duplicate order_id"
    if not rec["created_at"]:
        return "missing created_at"
    try:
        datetime.strptime(rec["created_at"], "%Y-%m-%dT%H:%M:%SZ")
    except ValueError:
        return "bad created_at"
    if not isinstance(rec["amount_cents"], int) or rec["amount_cents"] <= 0:
        return "bad amount"
    if rec["customer_id"].strip().upper() not in known:
        return "unknown customer"
    if rec["currency"].strip().upper() != "EUR":
        return "bad currency"
    if rec["status"].strip().lower() not in ("paid", "refunded", "failed"):
        return "bad status"
    return None

def transform(rec):
    """Typed, normalised copy of a valid raw order."""
    return {"sale_id": int(rec["order_id"][1:]), "order_id": rec["order_id"],
            "customer_id": rec["customer_id"].strip().upper(), "product_id": rec["product_id"],
            "quantity": int(rec["quantity"]), "amount_cents": rec["amount_cents"],
            "status": rec["status"].strip().lower(), "created_at": rec["created_at"],
            "date_key": int(rec["created_at"][:10].replace("-", ""))}

def clean_orders(raw, known):
    good, quarantine, seen = [], [], set()
    for rec in raw:
        reason = first_problem(rec, seen, known)
        seen.add(rec["order_id"])
        if reason:
            quarantine.append({"order_id": rec["order_id"], "reason": reason, "payload": rec})
        else:
            good.append(transform(rec))
    return good, quarantine

import sqlite3
from datetime import date, timedelta

DDL = """
CREATE TABLE dim_date (date_key INTEGER PRIMARY KEY, full_date TEXT, year INTEGER, month INTEGER);
CREATE TABLE dim_product (product_key INTEGER PRIMARY KEY AUTOINCREMENT, product_id TEXT UNIQUE, product_name TEXT, category TEXT);
CREATE TABLE dim_customer (customer_key INTEGER PRIMARY KEY AUTOINCREMENT, customer_id TEXT, customer_name TEXT, country TEXT,
                           valid_from TEXT, valid_to TEXT, is_current INTEGER);
CREATE TABLE fact_sales (sale_id INTEGER PRIMARY KEY, date_key INTEGER, customer_key INTEGER, product_key INTEGER,
                         quantity INTEGER, amount_cents INTEGER);
CREATE TABLE etl_state (name TEXT PRIMARY KEY, watermark TEXT);
"""

def init_warehouse():
    conn = sqlite3.connect(":memory:")
    conn.executescript(DDL)
    return conn

def load_dim_date(conn, start, end):
    days = (end - start).days + 1
    rows = [(int(d.strftime("%Y%m%d")), d.isoformat(), d.year, d.month) for d in (start + timedelta(days=i) for i in range(days))]
    with conn:
        conn.executemany("INSERT OR IGNORE INTO dim_date VALUES (?, ?, ?, ?)", rows)

def load_dim_product(conn, products):
    with conn:
        conn.executemany("""INSERT INTO dim_product (product_id, product_name, category) VALUES (?, ?, ?)
                            ON CONFLICT(product_id) DO UPDATE SET product_name = excluded.product_name, category = excluded.category""", products)

def load_dim_customer(conn, customers, as_of, first_from="2026-01-01"):
    """Type 2 history: a changed customer gets a new row; the old row is closed on `as_of`."""
    with conn:
        for cid, name, country in customers:
            cur = conn.execute("SELECT customer_key, customer_name, country FROM dim_customer WHERE customer_id = ? AND is_current = 1", (cid,)).fetchone()
            if cur is None:
                conn.execute("INSERT INTO dim_customer (customer_id, customer_name, country, valid_from, valid_to, is_current) VALUES (?, ?, ?, ?, '9999-12-31', 1)",
                             (cid, name, country, first_from))
            elif (cur[1], cur[2]) != (name, country):
                conn.execute("UPDATE dim_customer SET valid_to = ?, is_current = 0 WHERE customer_key = ?", (as_of, cur[0]))
                conn.execute("INSERT INTO dim_customer (customer_id, customer_name, country, valid_from, valid_to, is_current) VALUES (?, ?, ?, ?, '9999-12-31', 1)",
                             (cid, name, country, as_of))

def load_fact(conn, good):
    """Incremental: only paid orders newer than the watermark; upsert on sale_id; the watermark moves after the load."""
    row = conn.execute("SELECT watermark FROM etl_state WHERE name = 'fact_sales'").fetchone()
    mark = row[0] if row else ""
    new = [g for g in good if g["created_at"] > mark]
    facts = []
    for g in new:
        if g["status"] != "paid":
            continue
        day = g["created_at"][:10]
        ck = conn.execute("SELECT customer_key FROM dim_customer WHERE customer_id = ? AND valid_from <= ? AND ? < valid_to", (g["customer_id"], day, day)).fetchone()[0]
        pk = conn.execute("SELECT product_key FROM dim_product WHERE product_id = ?", (g["product_id"],)).fetchone()[0]
        facts.append((g["sale_id"], g["date_key"], ck, pk, g["quantity"], g["amount_cents"]))
    with conn:
        conn.executemany("""INSERT INTO fact_sales VALUES (?, ?, ?, ?, ?, ?)
                            ON CONFLICT(sale_id) DO UPDATE SET date_key = excluded.date_key, customer_key = excluded.customer_key,
                            product_key = excluded.product_key, quantity = excluded.quantity, amount_cents = excluded.amount_cents""", facts)
        if new:
            conn.execute("INSERT INTO etl_state VALUES ('fact_sales', ?) ON CONFLICT(name) DO UPDATE SET watermark = excluded.watermark",
                         (max(g["created_at"] for g in new),))
    return len(facts)

        if not ready:

    """Groups of tasks that could run in parallel: all dependencies are in earlier groups."""
    done, groups = set(), []
    while len(done) < len(tasks):
        ready = sorted(n for n, t in tasks.items() if n not in done and all(d in done for d in t["deps"]))

        done.update(ready)

def run_dag(tasks, ctx, retries=2):
    """Run tasks in dependency order. A failed task is retried; its downstream tasks are marked upstream_failed."""
    state, attempts = {}, {}
    for name in topo(tasks):
        if any(state[d] != "success" for d in tasks[name]["deps"]):
            state[name], attempts[name] = "upstream_failed", 0
            continue
        for attempt in range(1, retries + 2):
            attempts[name] = attempt
            try:
                tasks[name]["fn"](ctx)
                state[name] = "success"
                break
            except Exception as e:
                state[name] = "failed"
                ctx.setdefault("errors", []).append(f"{name} attempt {attempt}: {e}")
    return state, attempts

def run_ingest(ctx):
    customers, products, orders = generate()
    api, state = make_api(orders)
    ctx["customers"], ctx["products"] = customers, products
    ctx["raw"] = fetch_all(api, {"X-Api-Key": "secret-key"}, lambda s: None)
    ctx["calls"] = state["calls"]

def run_clean(ctx):
    ctx["good"], ctx["quarantine"] = clean_orders(ctx["raw"], {c[0] for c in ctx["customers"]})

def run_load_dims(ctx):
    ctx["conn"] = conn = init_warehouse()
    load_dim_date(conn, date(2026, 1, 1), date(2026, 3, 31))
    load_dim_product(conn, ctx["products"])
    load_dim_customer(conn, ctx["customers"], "2026-01-01")

def run_load_fact(ctx):
    ctx["loaded"] = load_fact(ctx["conn"], ctx["good"])

def run_checks(ctx):
    n = ctx["conn"].execute("SELECT COUNT(*) FROM fact_sales").fetchone()[0]
    assert len(ctx["raw"]) == len(ctx["good"]) + len(ctx["quarantine"]), "raw != clean + quarantined"
    assert n == sum(1 for g in ctx["good"] if g["status"] == "paid"), "fact rows != paid clean"

def run_analytics(ctx):
    ctx["by_month"] = ctx["conn"].execute("SELECT d.month, SUM(f.amount_cents) FROM fact_sales f JOIN dim_date d ON d.date_key = f.date_key GROUP BY d.month ORDER BY d.month").fetchall()

tasks = {
    "ingest": {"deps": [], "fn": run_ingest}, "clean": {"deps": ["ingest"], "fn": run_clean}, "load_dims": {"deps": ["ingest"], "fn": run_load_dims},
    "load_fact": {"deps": ["clean", "load_dims"], "fn": run_load_fact}, "quality_checks": {"deps": ["load_fact"], "fn": run_checks},
    "analytics": {"deps": ["load_fact"], "fn": run_analytics},
}
ctx = {}
state, attempts = run_dag(tasks, ctx)
print({k: state[k] for k in sorted(state)})
metrics = {"rows_read": len(ctx["raw"]), "rows_loaded": ctx["loaded"], "quarantined": len(ctx["quarantine"]), "api_calls": ctx["calls"]}
print(metrics)

def alerts(m):
    out = []
    if m["rows_loaded"] == 0:
        out.append("no rows loaded")
    if m["quarantined"] > 0.05 * m["rows_read"]:
        out.append(f"quarantine rate {m['quarantined']}/{m['rows_read']} above 5%")
    return out

print("alerts:", alerts(metrics), "| with 12 quarantined:", alerts({**metrics, "quarantined": 12}))
print("revenue by month:", ctx["by_month"])

### Example 3: Retries and upstream failures

Four tiny tasks show the two outcomes. `b` is flaky: it fails on its first two calls. With two retries it succeeds on the third attempt, so the whole DAG succeeds. With one retry it fails; `c`, which needs `b`, is marked `upstream_failed` and never runs, while `d`, which only needs `a`, still runs. The error log records each failed attempt.

def make_tasks():
    calls = {"b": 0}
    def flaky(ctx):
        calls["b"] += 1
        if calls["b"] <= 2:
            raise RuntimeError("temporary error")
    ok = lambda ctx: None
    return {"a": {"deps": [], "fn": ok}, "b": {"deps": ["a"], "fn": flaky}, "c": {"deps": ["b"], "fn": ok}, "d": {"deps": ["a"], "fn": ok}}

for retries in (2, 1):

    print("  errors:", ctx.get("errors", []))

This is the Airflow definition of the pipeline. It is shown, not run, because Airflow is not available in the browser or in these tests. To confirm that its dependencies match the model, the Python block that follows prints the `>>` statements generated from the dictionary of Example 1; they are the same dependencies as those written by hand in the Airflow file.

```python
from datetime import datetime, timedelta

from airflow import DAG
from airflow.operators.python import PythonOperator

default_args = {"retries": 2, "retry_delay": timedelta(minutes=5)}

with DAG(
    dag_id="orders_pipeline",
    start_date=datetime(2026, 1, 1),
    schedule="@daily",
    catchup=False,
    default_args=default_args,
) as dag:
    ingest = PythonOperator(task_id="ingest", python_callable=run_ingest)
    clean = PythonOperator(task_id="clean", python_callable=run_clean)
    load_dims = PythonOperator(task_id="load_dims", python_callable=run_load_dims)
    load_fact = PythonOperator(task_id="load_fact", python_callable=run_load_fact)
    quality_checks = PythonOperator(task_id="quality_checks", python_callable=run_checks)
    analytics = PythonOperator(task_id="analytics", python_callable=run_analytics)

    ingest >> [clean, load_dims] >> load_fact >> [quality_checks, analytics]
```

from datetime import datetime

def first_problem(rec, seen, known):
    """The first rule a raw order breaks, or None. `seen` holds the order ids already processed."""
    if rec["order_id"] in seen:
        return "duplicate order_id"
    if not rec["created_at"]:
        return "missing created_at"
    try:
        datetime.strptime(rec["created_at"], "%Y-%m-%dT%H:%M:%SZ")
    except ValueError:
        return "bad created_at"
    if not isinstance(rec["amount_cents"], int) or rec["amount_cents"] <= 0:
        return "bad amount"
    if rec["customer_id"].strip().upper() not in known:
        return "unknown customer"
    if rec["currency"].strip().upper() != "EUR":
        return "bad currency"
    if rec["status"].strip().lower() not in ("paid", "refunded", "failed"):
        return "bad status"
    return None

def transform(rec):
    """Typed, normalised copy of a valid raw order."""
    return {"sale_id": int(rec["order_id"][1:]), "order_id": rec["order_id"],
            "customer_id": rec["customer_id"].strip().upper(), "product_id": rec["product_id"],
            "quantity": int(rec["quantity"]), "amount_cents": rec["amount_cents"],
            "status": rec["status"].strip().lower(), "created_at": rec["created_at"],
            "date_key": int(rec["created_at"][:10].replace("-", ""))}

def clean_orders(raw, known):
    good, quarantine, seen = [], [], set()
    for rec in raw:
        reason = first_problem(rec, seen, known)
        seen.add(rec["order_id"])
        if reason:
            quarantine.append({"order_id": rec["order_id"], "reason": reason, "payload": rec})
        else:
            good.append(transform(rec))
    return good, quarantine

## Daily review

### Key takeaways

- The pipeline is a DAG: tasks, dependencies, no cycles; a topological sort gives the run order and the parallel groups.
- A failed task is retried and then marked `failed`; its downstream tasks become `upstream_failed` and do not run.
- Retries are safe only when tasks are idempotent.
- Airflow declares the same DAG with a schedule, default arguments and `>>`; here the model is verified in Python.
- Tests encode the rules and the expected counts; monitoring turns run counts into alerts.

### Common mistakes

- Creating a cycle (A needs B and B needs A), which no scheduler can order.
- Running a downstream task after an upstream failure, so it loads stale or empty data.
- Retrying a non-idempotent task, which duplicates rows after a half-finished first attempt.
- Writing tests that only call the function and never assert the result.
- Alerting on a rate with no denominator, such as "10 quarantined", when the meaning depends on how many rows were read.
- Setting `catchup` or the start date without thinking: a past `start_date` with catch-up on creates a run for every missed interval.

### Revision notes

- Order: ingest, then clean and load_dims, then load_fact, then quality_checks and analytics.
- States: success, failed, upstream_failed.
- Tests: `test_*` functions, `assert`, `parametrize`; run `python -m pytest -q`.
- Alert rules: no rows loaded; quarantine over 5 percent; fact table shrinks.
