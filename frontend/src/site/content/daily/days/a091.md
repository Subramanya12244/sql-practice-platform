## Understand

### What a workbook is made of

A **workbook** is one Excel file (`.xlsx`). It holds one or more **worksheets**, the tabs along the bottom. A worksheet is a grid of **cells**; each cell has an address made of a column letter and a row number, so `C4` is column C, row 4. A **range** is a rectangle of cells written with a colon, so `B2:B6` is five cells in column B. A cell holds one of three things: a **constant** (a number, a piece of text or a date that you typed), a **formula** (anything that starts with `=`), or nothing. A formula stores the instruction, and Excel shows the result of the instruction. This is the first idea to hold on to: what you see in a cell is often not what is stored in it.

If you have worked with pandas, the closest comparison is that a worksheet is like a DataFrame that you can edit by hand, except that nothing forces the cells to follow a structure. A DataFrame guarantees that every value in a column has one type and every row has the same columns. A worksheet guarantees nothing. Most spreadsheet trouble comes from that freedom, and most good spreadsheet practice is a set of habits that put the structure back.

### Separate inputs, calculations and reports

A tidy workbook keeps three jobs on different sheets. A **data sheet** holds the raw records, one row per event, and is never decorated. A **calculation sheet** or area holds lookups and helper columns. A **report sheet** holds the summary tables and charts that someone else reads. When all three are mixed on one sheet, a single inserted row can break a summary, and nobody can tell which numbers are inputs. This is the same separation as raw, cleaned and reporting layers in a data pipeline, scaled down to one file.

### Excel Tables

Select any cell inside a block of data and press `Ctrl+T` (Windows) or `Cmd+T` (Mac), or choose Insert, then Table. Confirm that "My table has headers" is ticked. Excel converts the block into an **Excel Table** (a ListObject): a named, structured block with filter buttons, banded rows and a name shown on the Table Design tab, by default `Table1`. Rename it to something meaningful such as `Sales`.

A Table gives you four things a plain range does not.

- **It grows by itself.** Type in the row directly under the Table, or paste more rows, and the Table expands. Formulas, formatting, charts and PivotTables that point at the Table name pick the new rows up.
- **Formulas use column names.** Instead of `=C2*D2`, you click the cells and Excel writes `=[@Qty]*[@UnitPrice]`. The `@` means "this row". The formula fills down the whole column automatically and every row has the same formula, which removes the classic mistake of one row with a different formula.
- **Whole-column references are stable.** `Sales[Amount]` means the entire Amount column of the Table, whatever its length. `=SUM(Sales[Amount])` keeps working when the Table gets longer or shorter.
- **Totals and filters are built in.** Table Design, then Total Row adds a last row where each cell can show a Sum, Average, Count and so on. These use `SUBTOTAL`, which ignores rows hidden by a filter.

The most common misconception is that a Table is "just formatting". Formatting is a small part of it. The important part is that the Table is a named object that formulas can refer to.

### Values versus formats

Formatting changes how a value is shown, never what is stored. If a cell holds `1234.5678` and you apply the format `0.00`, it shows `1234.57`, but the stored value, and every formula that uses it, still sees `1234.5678`. Dates make this vivid: Excel stores a date as a serial number counting days (the date 2025-01-31 is stored as 45688 in the default 1900 system) and the date format only decides whether you see `31/01/2025`, `Jan 31` or `45688`. A percent format multiplies the display by 100 but not the stored value: `0.25` shows as `25%`. Use `Ctrl+1` (Format Cells) to choose a category: Number, Currency, Accounting, Date, Percentage, Text. Round with the `ROUND` function when the value itself must change, and format when only the display should change.

Format with purpose: right-align numbers, left-align text, use a thousands separator, show the same decimals in a column, freeze the header row (View, Freeze Panes), and use one fill colour for inputs and none for formulas. Avoid merged cells in a data area; a merged cell breaks sorting, filtering and Tables.

### Named ranges and table names

A **named range** gives a cell or range a readable name. Select the cells, type a name in the Name Box (left of the formula bar) and press Enter, or use Formulas, then Name Manager. Names cannot contain spaces, cannot look like a cell address (`Q1` is invalid) and by convention use letters and underscores, such as `TaxRate`. A formula `=Sales[Amount]*TaxRate` is easier to read than `=$D$2:$D$6*$H$1`. Names are workbook-wide by default and they do not move when you sort, which is the reason to prefer them for constants such as a tax rate or a target.

### Data entry hygiene

Hygiene is the set of rules that keep a sheet analysable. They are the same rules you applied in pandas on tidy data.

- **One header row**, in the first row of the block, with a unique, non-empty name for each column.
- **One record per row, one value per cell.** Do not store "Berlin, DE" in one cell if you will need the city and the country separately.
- **One type per column.** A column of numbers must hold only numbers. A number typed as text (`'120`, or `120 ` with a trailing space) looks the same but does not add up. Excel marks it with a small green triangle and left-aligns it.
- **Consistent spelling.** `North`, `north` and `North ` are three different labels in a PivotTable. Data Validation (Data, Data Validation, List) restricts a column to an agreed list.
- **No blank rows, no subtotal rows and no merged cells inside the data**, and no notes in the same rows as the data.
- **Dates as real dates**, never as text such as `3rd of May`.

The reason to follow these rules is that every later feature (sort, filter, lookup, PivotTable, Power Query) assumes the block is a clean table. A hygiene problem you leave in the data is a wrong number you will find late.

## Syntax and key functions

Reference a cell, a range and a name:

```excel
=B2
=SUM(B2:B6)
=SUM(SalesAmounts)
```

`B2:B6` is a range address. `SalesAmounts` is a named range. Both give the same sum if the name refers to `B2:B6`.

Structured references inside an Excel Table named `Sales`:

```excel
=[@Qty]*[@UnitPrice]
=SUM(Sales[Amount])
=SUBTOTAL(109,Sales[Amount])
=Sales[@Amount]
```

`[@Qty]` is the Qty value of the current row. `Sales[Amount]` is the whole Amount column without its header. `SUBTOTAL(109, ...)` sums only the rows that a filter has left visible (code 9 also sums, but includes rows hidden by hand; 109 ignores them).

| Item | What it does |
|---|---|
| `Ctrl+T` / `Cmd+T` | Converts a range to a Table. |
| `Ctrl+1` | Opens Format Cells. |
| Name Box | Shows the active cell and lets you type a name for the selection. |
| Name Manager (Formulas tab) | Lists, edits and deletes names. |
| `Table[Column]` | All data cells of one column of a Table. |
| `[@Column]` | The value of that column in the current row. |
| `SUBTOTAL(109, range)` | Sum of the visible rows only. |
| Data Validation | Restricts what can be typed in a cell. |

## Learn by example

### Example 1: A Table as a DataFrame

Excel has no runtime here, so each number below is checked by pandas. Take this block, turned into a Table named `Sales`.

| OrderID | Region | Qty | UnitPrice |
|---|---|---|---|
| 1001 | North | 3 | 12.50 |
| 1002 | South | 5 | 8.00 |
| 1003 | North | 2 | 20.00 |
| 1004 | East | 4 | 15.25 |

Add a column named `Amount` with the formula `=[@Qty]*[@UnitPrice]` and, below the Table, `=SUM(Sales[Amount])`. Excel fills the formula down all four rows. The pandas replica computes a column and sums it.

```python run
import pandas as pd

sales = pd.DataFrame({
    "OrderID": [1001, 1002, 1003, 1004],
    "Region": ["North", "South", "North", "East"],
    "Qty": [3, 5, 2, 4],
    "UnitPrice": [12.50, 8.00, 20.00, 15.25],
})
sales["Amount"] = sales["Qty"] * sales["UnitPrice"]
print(sales["Amount"].tolist())
print(sales["Amount"].sum())
```

```output
[37.5, 40.0, 40.0, 61.0]
178.5
```

The Amount column is `37.5, 40.0, 40.0, 61.0` and `=SUM(Sales[Amount])` gives `178.5`. Adding a fifth row to the Table makes Excel extend the formula and the sum; in pandas you would have to rerun the code on the new frame.

### Example 2: SUBTOTAL and filtered rows

If you filter the Region column of the Table to `North`, a Total Row set to Sum uses `SUBTOTAL(109,Sales[Amount])` and shows only the North rows. A plain `=SUM(Sales[Amount])` placed outside the Table would still show every row. The replica is a boolean filter.

```python run
import pandas as pd

sales = pd.DataFrame({
    "Region": ["North", "South", "North", "East"],
    "Amount": [37.5, 40.0, 40.0, 61.0],
})
print(sales["Amount"].sum())
print(sales.loc[sales["Region"] == "North", "Amount"].sum())
```

```output
178.5
77.5
```

`SUM` gives 178.5 and `SUBTOTAL(109, ...)` under a North filter gives 77.5. The difference from pandas is that Excel changes the answer when the user changes the filter, whereas pandas computes exactly what the code says.

### Example 3: Value versus format

A cell holding `1234.5678` formatted as `0.00` shows `1234.57`, and `=A1*2` still gives `2469.1356`. Rounding with `ROUND(A1,2)` changes the stored value. The comparison in Python shows the same distinction between a display string and the number.

```python run
value = 1234.5678
shown = f"{value:.2f}"
print(shown)
print(value * 2)
print(round(value, 2) * 2)
```

```output
1234.57
2469.1356
2469.14
```

The first line is what the cell displays. The second is what a formula using the unrounded cell gets, and the third is what a formula using `ROUND(A1,2)` gets. Excel's `ROUND` rounds halves away from zero, whereas Python's `round` rounds halves to the nearest even digit; no half case appears here, but the difference matters for values such as 2.5.

### Example 4: Hygiene check with pandas

A block as it often arrives: a quantity typed as text, a trailing space in a region name and a blank row.

| OrderID | Region | Qty |
|---|---|---|
| 1 | North | 3 |
| 2 | north | "5" (text) |
| 3 | North + trailing space | 2 |
| (blank) | (blank) | (blank) |

Excel shows the text `5` left-aligned with a green triangle, and `=SUM(C2:C5)` ignores it and returns 5 instead of 10. The pandas replica finds the same three problems.

```python run
import pandas as pd

raw = pd.DataFrame({
    "OrderID": [1, 2, 3, None],
    "Region": ["North", "north", "North ", None],
    "Qty": [3, "5", 2, None],
})
numeric_only = raw["Qty"].map(lambda v: isinstance(v, (int, float)) and v == v)
print(raw["Qty"][numeric_only].sum())
print(pd.to_numeric(raw["Qty"]).sum())
print(raw["Region"].dropna().str.strip().str.title().unique().tolist())
print(raw.dropna(how="all").shape[0])
```

```output
5
10.0
['North']
3
```

The first number mimics Excel's `SUM`, which skips text numbers. After conversion the total is 10.0 (pandas shows a float). Cleaning the region labels leaves one label, `North`, instead of three. Dropping the all-blank row leaves 3 records. Excel's own fix is Data, then Text to Columns on the text number column, or multiplying by 1. Stray spaces and case in labels are fixed with text formulas.

### Example 5: Writing a workbook with a Table and a name

`openpyxl` is a Python library that writes `.xlsx` files. It writes formulas as text but cannot calculate them: a file written by `openpyxl` has no cached results, so a program that reads it back with `data_only=True` sees `None` for each formula until Excel or LibreOffice opens and saves it. This example runs locally, not in the browser.

```python local
import os, tempfile
from openpyxl import Workbook, load_workbook
from openpyxl.worksheet.table import Table
from openpyxl.workbook.defined_name import DefinedName

wb = Workbook()
ws = wb.active
ws.title = "Sales"
ws.append(["OrderID", "Region", "Qty", "UnitPrice", "Amount"])
for i, (reg, q, p) in enumerate([("North", 3, 12.5), ("South", 5, 8.0), ("North", 2, 20.0)], start=2):
    ws.append([1000 + i, reg, q, p, f"=C{i}*D{i}"])
ws.add_table(Table(displayName="SalesTbl", ref="A1:E4"))
wb.defined_names["Amounts"] = DefinedName("Amounts", attr_text="Sales!$E$2:$E$4")
ws["G1"] = "=SUM(Amounts)"

path = os.path.join(tempfile.mkdtemp(), "sales.xlsx")
wb.save(path)

back = load_workbook(path)
print(back["Sales"]["E2"].value)
print(back["Sales"]["G1"].value)
print(list(back.defined_names.keys()))
print(list(back["Sales"].tables.keys()))
print(load_workbook(path, data_only=True)["Sales"]["G1"].value)
```

```output
=C2*D2
=SUM(Amounts)
['Amounts']
['SalesTbl']
None
```

The formulas are stored as text, the name and the Table exist, and the cached value is `None`. The result of `=SUM(Amounts)` would be 37.5 + 40 + 40 = 117.5 in Excel. Note that here `Amount` holds ordinary cell formulas; openpyxl does not translate `[@Qty]` structured references for you, so write plain addresses or enter the structured formula in Excel itself.

## Real-world applications

- **A shared sales log.** A Table named `Sales` on a data sheet, with a validation list for Region, lets many people add rows without damaging the totals, because `Sales[Amount]` in the report sheet always covers every row (Examples 1 and 2).
- **Parameters in one place.** A tax rate, a currency rate or a target stored as a named cell (`TaxRate`) and used as `=[@Amount]*TaxRate` means one change updates every formula, and a reviewer can read what each formula does.
- **Preparing a file for analysis.** Before loading a workbook received from another team into pandas or Power Query, run the checks of Example 4 (text numbers, spelling variants, blank rows). The same problems are cheaper to fix at the source.
- **Reporting formats.** Showing revenue as currency with no decimals and margins as percentages makes a report readable while the underlying values keep full precision (Example 3).

## Daily review

### Key takeaways

- A cell stores a constant or a formula; formatting changes the display only.
- An Excel Table is a named block that grows, fills formulas down and exposes `Table[Column]` and `[@Column]` references.
- `SUBTOTAL(109, ...)` follows filters, `SUM` does not.
- A named range or table name makes formulas readable and stable.
- Clean data means one header row, one value per cell, one type per column, consistent labels and no merged cells.

### Common mistakes

- Typing numbers that Excel stores as text (a leading apostrophe, a trailing space). The sum silently leaves them out. Convert them and look for the green triangle.
- Leaving blank rows or a Total row inside the data block, so the Table or a sort stops early or double counts.
- Merging cells in a data area, which makes sort and filter fail with "this operation requires the merged cells to be identically sized".
- Believing a rounded display is a rounded value, then finding that a total differs by a cent from the sum of the displayed numbers.
- Naming a range `Q1` or `TaxRate 2025`: a name that looks like a cell address, or contains a space, is rejected.
- Putting inputs, calculations and the report on the same sheet and inserting a row through all three.

### Revision notes

- Table: `Ctrl+T`, rename on Table Design, formulas `[@Col]`, `Table[Col]`.
- Display is not value; `ROUND` changes the value.
- Name Box creates names; Name Manager edits them.
- `SUBTOTAL(109, ...)` respects filters.
- `openpyxl` writes formulas but does not compute them.
