## Objectives

- Create a subclass that inherits attributes and methods from a parent class, and override a method.
- Call the parent's version of a method with `super()`, especially in `__init__`.
- Implement common dunder methods (`__eq__`, `__lt__`, `__len__`, `__str__`, `__add__`) so objects behave like built-in values.
- Write a `@dataclass` with defaults, `field(default_factory=...)`, ordering and `frozen=True`.
- Choose between inheritance and composition for a design.

## Understand

### Inheritance: reusing and specialising a class

**Inheritance** lets a new class start from an existing one and add or change behaviour. The existing class is the **parent** (or base class) and the new class is the **child** (or subclass). You write the parent in brackets: `class Manager(Employee):`. A `Manager` object then has every attribute and method of `Employee` for free, and can add its own. The relationship should read as "is a": a manager is an employee. The test `isinstance(m, Employee)` is `True` for a `Manager`, and `issubclass(Manager, Employee)` is `True` too.

When you call `obj.method()`, Python looks for the method on the object's class first, then on its parent, then on the parent's parent, and uses the first match. Python calls that search order the **method resolution order**; you can see it as `Manager.__mro__`. Defining a method in the child with the same name as one in the parent **overrides** it: the child's version wins for child objects, and parent objects are unaffected.

### super()

When a child overrides `__init__`, the parent's `__init__` does not run automatically, so the parent's attributes would never be set. `super()` returns a proxy to the parent so you can call its version: `super().__init__(name, salary)`. Notice that `self` is not passed; `super()` supplies it. The same trick extends a method rather than replacing it: `super().describe() + " (manager)"`. Call `super().__init__` before using attributes the parent sets.

### Dunder methods: making objects behave like values

Dunder methods are the hooks Python calls for operators and built-in functions, so your objects can behave like built-in types. You met `__init__` and `__repr__` on Day 24. Others you will use:

- `__str__` returns friendly text for `print(obj)` and `str(obj)`; `__repr__` is the precise form shown for debugging.
- `__eq__(self, other)` defines `==`. Without it, two objects are equal only if they are the same object.
- `__lt__(self, other)` defines `<`, which is all `sorted()` needs to sort a list of your objects.
- `__len__` makes `len(obj)` work, and `__add__` defines `+`.

Return `NotImplemented` (not an exception) from a comparison when `other` is a type you do not handle, so Python can try the other side. Python calls these methods for you; you rarely call them by name.

### Dataclasses

Many classes only carry data, and writing `__init__`, `__repr__` and `__eq__` by hand is repetitive. The **dataclass** decorator from the `dataclasses` module writes them for you from annotated attributes:

```python
from dataclasses import dataclass

@dataclass
class Point:
    x: int
    y: int = 0
```

Each line `name: type` declares a field; the type is a hint for readers and tools and Python does not enforce it. A field with `= value` is optional with that default. Fields without defaults must come before fields with defaults. For a mutable default such as a list you must use `field(default_factory=list)`, because a plain `[]` would be shared by every object (the class attribute trap from Day 24); the dataclass refuses it with a `ValueError`. Useful options: `@dataclass(order=True)` adds comparison methods that compare fields in order, and `@dataclass(frozen=True)` makes objects immutable, so assigning to a field raises `FrozenInstanceError` and the object can be used as a dictionary key. `dataclasses.asdict(obj)` converts an object to a dictionary, and `dataclasses.replace(obj, x=5)` makes a modified copy. A dataclass is still an ordinary class, so it can have methods. The `@` line is a decorator, explained on Day 27.

### Composition: has-a instead of is-a

**Composition** builds an object out of other objects: an `Order` has a list of `OrderLine` objects and a `Customer`. Choose it when the relationship reads "has a" rather than "is a". It is usually more flexible than inheritance, because parts can be swapped without a family tree of classes. A good rule: use inheritance for a true specialisation with the same interface, and composition for everything else. Deep inheritance chains are hard to follow, so keep them shallow.

### Common misconception

Learners think a subclass copies the parent's code. It does not: the child object finds the parent's methods by lookup, so changing the parent changes every child that has not overridden the method. A second one: forgetting `super().__init__(...)` and expecting the parent's attributes to exist.

### Why it matters

Pipelines often have families of similar things (several sources, several validators) that differ in one step. Inheritance shares the common part, dataclasses make record types cheap to write, and composition keeps larger designs simple.

## Syntax and key functions

```python
class Child(Parent):
    def __init__(self, a, b):
        super().__init__(a)
        self.b = b

    def method(self):
        return super().method() + "!"
```

`Child(Parent)` inherits. `super().__init__(a)` runs the parent's initialiser. `super().method()` calls the parent's version.

```python
from dataclasses import dataclass, field

@dataclass(order=True, frozen=False)
class Row:
    key: str
    values: list = field(default_factory=list)
```

| Name | Meaning |
|---|---|
| `class Child(Parent)` | Inheritance. |
| `super()` | Proxy for calling the parent's methods. |
| `isinstance(o, C)`, `issubclass(A, B)` | Instance of a class or its subclasses; subclass test. |
| `Class.__mro__` | Order in which classes are searched for methods. |
| `__str__`, `__repr__` | Friendly text; debugging text. |
| `__eq__`, `__lt__`, `__len__`, `__add__` | `==`, `<`, `len()`, `+`. |
| `@dataclass` | Generates `__init__`, `__repr__`, `__eq__`. |
| `field(default_factory=list)` | A fresh mutable default per object. |
| `dataclasses.asdict(obj)`, `replace(obj, f=v)` | To dict; modified copy. |

## Learn by example

### Example 1: A subclass and an override

`Manager` inherits `Employee`'s attributes and methods. It overrides `describe` and adds its own attribute. `isinstance` is `True` for the parent class as well, and the method resolution order shows where Python searches.

```python run
class Employee:
    def __init__(self, name, salary):
        self.name = name
        self.salary = salary

    def describe(self):
        return f"{self.name} earns {self.salary}"

class Manager(Employee):
    def __init__(self, name, salary, team):
        super().__init__(name, salary)
        self.team = team

    def describe(self):
        return super().describe() + f" and leads {len(self.team)} people"

e = Employee("Ana", 3000)
m = Manager("Bo", 5000, ["Ana", "Cy"])
print(e.describe())
print(m.describe())
print(isinstance(m, Employee), isinstance(e, Manager))
print([c.__name__ for c in Manager.__mro__])
```

```output
Ana earns 3000
Bo earns 5000 and leads 2 people
True False
['Manager', 'Employee', 'object']
```

### Example 2: Forgetting super().__init__

If a child defines `__init__` and does not call the parent's, the parent's attributes are never set. The broken class fails with an `AttributeError` when the method that needs them runs, and the fixed class works.

```python run
class Base:
    def __init__(self, name):
        self.name = name

    def hello(self):
        return "hello " + self.name

class Broken(Base):
    def __init__(self, name, extra):
        self.extra = extra

class Fixed(Base):
    def __init__(self, name, extra):
        super().__init__(name)
        self.extra = extra

try:
    Broken("a", 1).hello()
except AttributeError as error:
    print("AttributeError:", error)
print(Fixed("a", 1).hello())
```

```output
AttributeError: 'Broken' object has no attribute 'name'
hello a
```

### Example 3: Dunder methods

`Money` compares by amount with `__eq__` and `__lt__`, so `sorted` and `max` work. `__add__` makes `+` work and `__str__` gives friendly text. Comparing with an unrelated type returns `NotImplemented`, which makes Python report `False` for `==`.

```python run
class Money:
    def __init__(self, amount):
        self.amount = amount

    def __eq__(self, other):
        if not isinstance(other, Money):
            return NotImplemented
        return self.amount == other.amount

    def __lt__(self, other):
        return self.amount < other.amount

    def __add__(self, other):
        return Money(self.amount + other.amount)

    def __str__(self):
        return f"${self.amount:.2f}"

    def __repr__(self):
        return f"Money({self.amount})"

a, b = Money(5), Money(12.5)
print(a + b)
print(a == Money(5), a == 5, a < b)
print(sorted([b, a, Money(1)]))
print(max(a, b))
```

```output
$17.50
True False True
[Money(1), Money(5), Money(12.5)]
$12.50
```

### Example 4: A dataclass

The decorator writes `__init__`, `__repr__` and `__eq__`. `field(default_factory=list)` gives each object its own list. `asdict` converts to a dictionary and `replace` makes a modified copy.

```python run
from dataclasses import dataclass, field, asdict, replace

@dataclass
class Order:
    order_id: int
    customer: str
    status: str = "new"
    tags: list = field(default_factory=list)

o1 = Order(1, "Ana")
o2 = Order(2, "Bo", "paid", ["vip"])
o1.tags.append("gift")
print(o1)
print(o2.tags, Order(2, "Bo").tags)
print(o1 == Order(1, "Ana", "new", ["gift"]))
print(asdict(o2))
print(replace(o2, status="shipped"))
```

```output
Order(order_id=1, customer='Ana', status='new', tags=['gift'])
['vip'] []
True
{'order_id': 2, 'customer': 'Bo', 'status': 'paid', 'tags': ['vip']}
Order(order_id=2, customer='Bo', status='shipped', tags=['vip'])
```

### Example 5: Ordering and frozen dataclasses

With `order=True` objects compare field by field, so a list of them sorts. With `frozen=True` assignment is refused and the object can serve as a dictionary key or set member. A mutable default list without `default_factory` is rejected when the class is defined.

```python run
from dataclasses import dataclass, field, FrozenInstanceError

@dataclass(order=True, frozen=True)
class Version:
    major: int
    minor: int = 0

versions = [Version(2, 1), Version(1, 9), Version(2, 0)]
print(sorted(versions))
print(Version(1, 9) < Version(2))
seen = {Version(1, 0): "first"}
print(seen[Version(1, 0)])
try:
    versions[0].major = 5
except FrozenInstanceError:
    print("frozen")
try:
    @dataclass
    class Bad:
        items: list = []
except ValueError as error:
    print("ValueError")
```

```output
[Version(major=1, minor=9), Version(major=2, minor=0), Version(major=2, minor=1)]
True
first
frozen
ValueError
```

### Example 6: Composition in a small domain model

An `Order` is made of `Line` objects and holds a customer, which is "has a" and not "is a". The order computes its total from its lines and reports its size with `__len__`. Each class stays small and has a single responsibility.

```python run
from dataclasses import dataclass, field

@dataclass
class Line:
    sku: str
    price: float
    qty: int = 1

    @property
    def amount(self):
        return self.price * self.qty

@dataclass
class Customer:
    name: str
    country: str

@dataclass
class Order:
    customer: Customer
    lines: list = field(default_factory=list)

    def add(self, sku, price, qty=1):
        self.lines.append(Line(sku, price, qty))

    @property
    def total(self):
        return sum(line.amount for line in self.lines)

    def __len__(self):
        return len(self.lines)

order = Order(Customer("Ana", "NO"))
order.add("pen", 1.5, 4)
order.add("book", 12.0)
print(len(order), order.total)
print(order.customer.name, order.lines[0])
```

```output
2 18.0
Ana Line(sku='pen', price=1.5, qty=4)
```

## Real-world applications

- **Families of sources or validators.** A `Source` base class with `read()` and subclasses `CsvSource` and `JsonSource` share the surrounding pipeline code (Examples 1 and 2).
- **Record types.** Dataclasses model rows and API payloads (Example 4), with defaults, readable output, equality for tests and `asdict` for writing JSON.
- **Sortable, comparable domain values.** Money, versions and keys with ordering (Examples 3 and 5) sort and compare correctly, instead of relying on raw strings.
- **Modelling an order or a run.** Objects that contain other objects (Example 6) keep a pipeline's configuration and results organised.

## Daily review

### Key takeaways

- A subclass inherits from its parent, can override methods and calls the parent with `super()`.
- Override `__init__` only together with `super().__init__(...)`.
- Dunder methods make objects work with `==`, `<`, `+`, `len()` and `print`.
- `@dataclass` generates `__init__`, `__repr__` and `__eq__`; use `default_factory` for mutable defaults, `order=True` for sorting and `frozen=True` for immutability.
- Prefer composition ("has a") unless the relationship is truly "is a".

### Common mistakes

- Overriding `__init__` without calling `super().__init__()`, then getting `AttributeError` for the parent's attributes.
- Passing `self` to `super().__init__(self, ...)`, which shifts the arguments and raises `TypeError`.
- Using a list as a dataclass default (`items: list = []`), which raises `ValueError: mutable default ... use default_factory`.
- Putting a field with a default before a field without one, giving `TypeError: non-default argument follows default argument`.
- Defining `__eq__` and then using the object as a dictionary key: a class that defines `__eq__` without `__hash__` becomes unhashable (`TypeError: unhashable type`). Use a frozen dataclass.
- Using inheritance to share code between unrelated things (a `Stack` that inherits `list`), which exposes methods that break its rules. Use composition.
- Believing type hints are checked: `Order("x", 5)` runs fine even though `order_id` is annotated `int`.

### Revision notes

- `class Child(Parent):`, `super().__init__(...)`, `super().method()`.
- `isinstance(obj, Parent)` is `True` for children; `Child.__mro__` lists the search order.
- Dunders: `__eq__`, `__lt__`, `__add__`, `__len__`, `__str__`, `__repr__`.
- `@dataclass`, `field(default_factory=list)`, `@dataclass(order=True, frozen=True)`, `asdict`, `replace`.
- "is a" is inheritance; "has a" is composition.
