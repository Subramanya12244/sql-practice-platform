## Objectives

- Write regular expressions using literal characters, character classes, quantifiers, anchors and groups.
- Use `re.search`, `re.fullmatch`, `re.findall` and `re.finditer` to test and extract text, and read the match object.
- Capture parts of a match with groups and named groups, and rewrite text with `re.sub`, including references to groups.
- Compile and reuse patterns, and use flags such as `re.IGNORECASE`.
- Clean messy text (spacing, punctuation, phone numbers, codes) with a sequence of `re.sub` calls, and recognise when a regular expression is the wrong tool.

## Understand

### What a regular expression is

A **regular expression** (regex) is a compact pattern that describes a set of strings, such as "three digits, a hyphen, then four digits". You use it to test whether text has a certain shape, to pull pieces out of text, and to replace patterns. String methods from Day 4 (`find`, `replace`, `startswith`) work for fixed text. A regex handles text that varies: phone numbers in different layouts, order codes with changing digits, dates in log lines. Python's regex support is in the `re` module.

Write patterns as **raw strings**, with an `r` before the quote: `r"\d+"`. In a normal string `"\d"` is an unrecognised escape, and `"\b"` would be a backspace character. A raw string leaves backslashes alone so the regex engine sees them.

### Building blocks

- A **literal** matches itself: `cat` matches the text `cat`.
- A **character class** in square brackets matches one character from a set: `[aeiou]`, or a range `[a-z]`, `[0-9]`. A caret first negates it: `[^0-9]` is any character that is not a digit. The dot `.` matches any character except a newline.
- **Shorthand classes**: `\d` a digit, `\w` a letter, digit or underscore, `\s` whitespace; the capital versions `\D`, `\W`, `\S` mean the opposite.
- **Quantifiers** say how many times the item before them repeats: `?` zero or one, `*` zero or more, `+` one or more, `{3}` exactly three, `{2,4}` two to four. Quantifiers are **greedy**: they match as much as possible. Adding `?` after one, as in `.*?`, makes it **lazy** (as little as possible).
- **Anchors** match a position, not a character: `^` the start of the text, `$` the end, `\b` a word boundary.
- **Alternation** `a|b` means "a or b", and **parentheses** group: `(ab)+`.
- Special characters such as `. * + ? ( ) [ ] { } | \ ^ $` must be escaped with a backslash to be matched literally: `\.` is a dot.

### Functions of the re module

- `re.search(pattern, text)` finds the first match anywhere and returns a **match object**, or `None` when there is none. A match object is true, `None` is false, so you can write `if re.search(...)`.
- `re.match` matches only at the start of the text, and `re.fullmatch` requires the whole text to match. Validation (is this a valid code?) needs `fullmatch`, or the anchors `^...$`.
- `re.findall(pattern, text)` returns a list of all non-overlapping matches (as strings, or tuples when the pattern has groups). `re.finditer` returns match objects one at a time.
- `re.sub(pattern, replacement, text)` replaces every match, and `re.split(pattern, text)` splits at matches.
- On a match object, `m.group()` is the matched text, `m.start()` and `m.end()` give positions, and `m.group(1)` is the first captured group.

### Groups

Parentheses also **capture**: the text matched inside is remembered. In `(\d{4})-(\d{2})-(\d{2})` applied to `2026-03-15`, group 1 is `2026`, group 2 is `03` and group 3 is `15`. A **named group** is easier to read: `(?P<year>\d{4})`, retrieved with `m.group("year")` or `m.groupdict()`. In `re.sub` the replacement can refer to groups with `\1`, `\2` or `\g<year>`, so you can reorder pieces: turning `2026-03-15` into `15/03/2026`. A group that should not capture, only group, is written `(?:...)`.

### Flags and compiling

A **flag** changes how matching works: `re.IGNORECASE` ignores case, and `re.MULTILINE` makes `^` and `$` match at each line. Pass them as the last argument: `re.search("error", text, re.IGNORECASE)`. If you use the same pattern many times, `p = re.compile(r"...")` builds it once and you call `p.search(text)` and `p.sub(...)`.

### Cleaning text step by step

Text cleaning is usually a sequence of small substitutions: collapse runs of whitespace with `re.sub(r"\s+", " ", text)`, strip the result, remove characters that are not wanted with `re.sub(r"[^\w\s]", "", text)`, and normalise formats such as phone numbers by removing everything that is not a digit. Each step is easy to check, and the order matters.

### Common misconception

Learners think regex is the right tool for any text problem. It is not suited to nested structures such as HTML or JSON, where a real parser (like `json`) is correct, and a complicated pattern that nobody can read is a maintenance burden. Prefer simple string methods when they are enough, and add a short comment when a pattern is not obvious. Also, `re.match` is not "search anywhere"; it only tests the start.

### Why it matters

Real data hides structure in free text: IDs in log lines, amounts in descriptions, dates in file names, phone numbers typed ten different ways. A handful of patterns turns that text into clean columns, which is the first job of many cleaning pipelines.

## Syntax and key functions

```python
import re

m = re.search(r"(?P<year>\d{4})-(?P<month>\d{2})", text)
if m:
    m.group("year"), m.groupdict()

re.findall(r"\d+", text)
re.sub(r"\s+", " ", text)
re.fullmatch(r"[A-Z]{2}-\d{4}", code)
```

`search` returns a match object or `None`. `findall` returns all matches as a list. `sub` returns a new string. `fullmatch` validates the whole text.

| Pattern | Matches |
|---|---|
| `\d`, `\w`, `\s` | One digit; one word character; one whitespace character. |
| `.`, `[abc]`, `[^abc]` | Any character; one of a, b, c; any character except those. |
| `*`, `+`, `?`, `{n}`, `{n,m}` | Repeat 0+, 1+, 0 or 1, exactly n, n to m times. |
| `^`, `$`, `\b` | Start, end, word boundary. |
| `(...)`, `(?P<name>...)`, `(?:...)` | Capturing group, named group, non-capturing group. |
| `a|b` | a or b. |

| Function | Returns |
|---|---|
| `re.search(p, s)` | First match object or `None`. |
| `re.fullmatch(p, s)` | Match object if the whole string matches, else `None`. |
| `re.findall(p, s)` | List of matches (tuples if several groups). |
| `re.finditer(p, s)` | Iterator of match objects. |
| `re.sub(p, repl, s)` | New string with matches replaced. |
| `re.split(p, s)` | List of pieces. |
| `re.compile(p, flags)` | A reusable pattern object. |

## Learn by example

### Example 1: search and the match object

`search` returns a match object when the pattern is found and `None` when it is not. The object reports the text, its position and the groups. `match` looks only at the start, which is why it fails on the same text.

```python run
import re

text = "Order 4821 shipped on 2026-03-15 to Oslo"
m = re.search(r"\d+", text)
print(m.group(), m.start(), m.end())
print(re.search(r"Paris", text))
print(re.match(r"\d+", text))
print(bool(re.search(r"order", text)), bool(re.search(r"order", text, re.IGNORECASE)))
d = re.search(r"(\d{4})-(\d{2})-(\d{2})", text)
print(d.group(1), d.group(2), d.group(3), d.groups())
```

```output
4821 6 10
None
None
False True
2026 03 15 ('2026', '03', '15')
```

### Example 2: findall and quantifiers

`findall` lists every match. Greedy quantifiers take as much as they can, lazy ones as little as possible, which matters when text sits between delimiters. Anchors and `fullmatch` check the whole string.

```python run
import re

text = "Prices: 12.50, 7, 130.25 and 0.99"
print(re.findall(r"\d+\.\d+", text))
print(re.findall(r"\d+(?:\.\d+)?", text))
html = "<b>one</b> and <b>two</b>"
print(re.findall(r"<b>.*</b>", html))
print(re.findall(r"<b>.*?</b>", html))
print(re.findall(r"\b[A-Z][a-z]+\b", "Ana met bo and Cy in Oslo"))
for code in ["AB-1234", "AB-12345", "ab-1234", "XAB-1234"]:
    print(code, bool(re.fullmatch(r"[A-Z]{2}-\d{4}", code)))
```

```output
['12.50', '130.25', '0.99']
['12.50', '7', '130.25', '0.99']
['<b>one</b> and <b>two</b>']
['<b>one</b>', '<b>two</b>']
['Ana', 'Cy', 'Oslo']
AB-1234 True
AB-12345 False
ab-1234 False
XAB-1234 False
```

### Example 3: Groups, named groups and finditer

Groups capture parts of a match. With several groups `findall` returns tuples. Named groups read better and turn into a dictionary with `groupdict()`. `finditer` gives match objects, so positions are available too.

```python run
import re

log = "2026-03-01 ERROR disk full\n2026-03-02 INFO started\n2026-03-04 ERROR timeout"
print(re.findall(r"(\d{4}-\d{2}-\d{2}) (ERROR|INFO)", log))
pattern = re.compile(r"(?P<date>\d{4}-\d{2}-\d{2}) ERROR (?P<msg>.+)")
for m in pattern.finditer(log):
    print(m.groupdict(), m.start())
print(re.split(r"[,;]\s*", "a, b;c,   d"))
```

```output
[('2026-03-01', 'ERROR'), ('2026-03-02', 'INFO'), ('2026-03-04', 'ERROR')]
{'date': '2026-03-01', 'msg': 'disk full'} 0
{'date': '2026-03-04', 'msg': 'timeout'} 51
['a', 'b', 'c', 'd']
```

### Example 4: sub and group references

`sub` replaces every match. Group references in the replacement reorder pieces: the date is rewritten from year-month-day to day/month/year. A function can also be passed as the replacement to compute each new value.

```python run
import re

print(re.sub(r"\d", "#", "Card 4111-2222"))
print(re.sub(r"(\d{4})-(\d{2})-(\d{2})", r"\3/\2/\1", "From 2026-03-15 to 2026-04-01"))
print(re.sub(r"(?P<h>\w+)@(?P<d>\w+\.com)", r"\g<h> at \g<d>", "ana@shop.com"))
print(re.sub(r"\d+", lambda m: str(int(m.group()) * 2), "3 apples and 10 pears"))
print(re.sub(r"a", "A", "banana", count=2))
```

```output
Card ####-####
From 15/03/2026 to 01/04/2026
ana at shop.com
6 apples and 20 pears
bAnAna
```

### Example 5: Cleaning messy text

A short chain of substitutions cleans a product title: it collapses whitespace, removes punctuation that is not wanted and normalises case. Phone numbers are normalised by keeping only digits and validating the length. The order of the steps matters and each step can be tested alone.

```python run
import re

raw = "  Red   T-Shirt!!  (SIZE:  M) \n"
step1 = re.sub(r"\s+", " ", raw).strip()
step2 = re.sub(r"[^\w\s-]", "", step1)
print(repr(step1))
print(repr(step2))
print(step2.lower().replace(" ", "-"))

phones = ["(555) 123-4567", "555.123.4567", "+1 555 123 4567", "12345"]
for p in phones:
    digits = re.sub(r"\D", "", p)
    digits = digits[-10:] if len(digits) >= 10 else None
    print(p, "->", digits)
```

```output
'Red T-Shirt!! (SIZE: M)'
'Red T-Shirt SIZE M'
red-t-shirt-size-m
(555) 123-4567 -> 5551234567
555.123.4567 -> 5551234567
+1 555 123 4567 -> 5551234567
12345 -> None
```

### Example 6: Extracting a table from log text

Each log line is matched with one compiled pattern that has named groups; lines that do not match are counted separately. The extracted fields are converted to numbers and summarised, which is a typical text-to-table step.

```python run
import re

lines = [
    "2026-03-01 12:00:01 GET /orders/12 200 35ms",
    "2026-03-01 12:00:02 POST /orders 201 120ms",
    "malformed line",
    "2026-03-01 12:00:05 GET /orders/13 404 8ms",
    "2026-03-01 12:00:09 GET /items 200 60ms",
]
pattern = re.compile(r"(?P<time>\d{2}:\d{2}:\d{2}) (?P<method>[A-Z]+) (?P<path>\S+) (?P<status>\d{3}) (?P<ms>\d+)ms")
rows, bad = [], 0
for line in lines:
    m = pattern.search(line)
    if m:
        row = m.groupdict()
        row["status"], row["ms"] = int(row["status"]), int(row["ms"])
        rows.append(row)
    else:
        bad += 1
print(len(rows), "parsed,", bad, "unparsed")
print([r["path"] for r in rows if r["status"] >= 400])
print(sum(r["ms"] for r in rows) / len(rows))
print(sorted({r["method"] for r in rows}))
```

```output
4 parsed, 1 unparsed
['/orders/13']
55.75
['GET', 'POST']
```

## Real-world applications

- **Extracting fields from free text.** Order numbers, amounts and dates are pulled out of log lines and descriptions with groups (Examples 3 and 6) and then stored as columns.
- **Normalising phone numbers, codes and names.** Substituting unwanted characters (Example 5) makes the same value look identical everywhere, so joins and duplicate checks work.
- **Validating formats.** `fullmatch` checks that postcodes, SKUs and IDs follow the expected shape (Example 2) before they enter a table.
- **Reformatting.** `sub` with group references (Example 4) converts date layouts or masks sensitive numbers before export.

## Daily review

### Key takeaways

- A regex describes a text pattern; write it as a raw string `r"..."`.
- Classes (`\d`, `\w`, `[a-z]`), quantifiers (`+`, `*`, `?`, `{n}`), anchors (`^`, `$`, `\b`) and groups are the core building blocks.
- `search` finds the first match, `fullmatch` validates the whole text, `findall` lists all matches, `sub` replaces.
- Parentheses capture; named groups and `groupdict()` make results readable.
- Quantifiers are greedy; add `?` to make them lazy.

### Common mistakes

- Forgetting the `r` prefix, so `\b` becomes a backspace and `\d` raises a warning. Use raw strings.
- Using `re.match` and expecting a search anywhere. It only tests the start; use `re.search`.
- Validating with `search` and accepting `"XAB-1234"` because it contains a valid code. Use `fullmatch` or anchors.
- Not escaping a literal dot, so `\d+.\d+` also matches `12x50`. Write `\.`.
- Using a greedy `.*` between delimiters and matching from the first opening to the last closing one. Use `.*?`.
- Calling `m.group()` on `None` when nothing matched, which raises `AttributeError: 'NoneType' object has no attribute 'group'`. Test `if m:` first.
- Parsing HTML or JSON with regex. Use a parser.

### Revision notes

- `import re`, raw strings, `re.search`, `re.fullmatch`, `re.findall`, `re.sub`, `re.split`, `re.compile`.
- `\d \w \s`, `[a-z]`, `[^x]`, `. * + ? {n,m}`, `^ $ \b`, `(a|b)`.
- Groups `( )`, `(?P<name>...)`, `m.group(1)`, `m.groupdict()`, replacement `\1` or `\g<name>`.
- `re.IGNORECASE`; `.*` greedy, `.*?` lazy.
- Always check a match for `None`.
