## Objectives

- Compute the facts and the KPI scorecard for an executive page from the sample sales data and its 2024 comparison.
- Specify a dashboard of a few visuals, each tied to a question, and check its layout and purpose with code.
- Write a short narrative with the recommendation first, a sized scenario and a caveat.
- Check that every number in the narrative is traceable to the computed facts.
- Assemble the dashboard specification and narrative as one deliverable.

## Understand

This project day brings together the storytelling phase: Day 138 (story structure), Day 139 (dashboard design), Day 140 (KPIs and scorecards) and Day 141 (insights, scenarios and caveats). The deliverable is what an analyst would send to an executive before a meeting: a one-page dashboard specification and a narrative of about a hundred words. The data is the sample sales model with a 2024 year added, as in Day 131, so that growth can be computed. Nothing here needs Power BI: the dashboard is a specification (a list of visuals on a grid, each tied to a question) that you could build in any tool, and the narrative is text that is produced from computed facts.

The project has four steps. First, **compute the facts and the scorecard**: total revenue and growth, revenue per market and its growth, the weakest month, orders, average order value and the concentration of the top five customers, each with a target, a variance and a RAG status. Second, **specify the dashboard**: three KPI cards, a monthly trend and a market bar on the 40 pixel grid, with each visual mapped to a question that the executive asks. Check the layout (no overlap, on the canvas, key card first) and that no visual is an orphan. Third, **write the narrative** from the facts: recommendation first, a situation and a complication with numbers, a sized scenario and the one caveat that matters. Fourth, **check traceability**: extract the numbers from the narrative and confirm that each of them comes from the facts dictionary. A narrative with a number that is not in the facts is a number someone typed, and it is the first thing that goes wrong after a data refresh.

The common failure in project work like this is a narrative that is written first and supported afterwards. Work in the opposite direction: facts, then dashboard, then words. The project is complete when the layout check returns nothing, every visual answers a question, the narrative fits its word budget, starts with a recommendation and contains no untraceable numbers.

## Syntax and key functions

The project uses only the ideas of the earlier days. The table lists each step with the check that closes it.

| Step | Output | Check |
|---|---|---|
| Facts and scorecard | A facts dictionary and KPI table with status | RAG boundaries tested; direction handled |
| Dashboard specification | Visuals as rectangles with a question each | Layout problems empty; no orphan visuals |
| Narrative | Recommendation, situation, complication, scenario, caveat | At most 100 words; recommendation first |
| Traceability | Numbers in the text found in the facts | Untraced list empty |

The pattern used for the traceability check:

```python
import re
numbers = re.findall(r"\d[\d,]*\.?\d*", text)
untraced = [n for n in numbers if n not in allowed]
```

## Learn by example

### Example 1: Step 1, the facts and the scorecard

Compute the facts for 2025 against 2024, then a scorecard with targets and status.

```python run
import numpy as np
import pandas as pd

rng = np.random.default_rng(7)
countries = ["UK", "Germany", "France", "Spain"]
cats = ["Hardware", "Software", "Services"]
customers = pd.DataFrame({
    "customer_id": range(1, 41),
    "customer_name": [f"Customer {i:02d}" for i in range(1, 41)],
    "country": [countries[i % 4] for i in range(40)],
    "segment": [["Retail", "Corporate"][(i // 4) % 2] for i in range(40)],
})
products = pd.DataFrame({
    "product_id": range(1, 13),
    "product_name": [f"Product {i:02d}" for i in range(1, 13)],
    "category": [cats[i % 3] for i in range(12)],
    "unit_cost": [float(10 + 5 * i) for i in range(12)],
})
n = 400
sales = pd.DataFrame({
    "order_id": range(1, n + 1),
    "order_date": pd.to_datetime("2025-01-01") + pd.to_timedelta(rng.integers(0, 365, n), unit="D"),
    "customer_id": rng.integers(1, 41, n),
    "product_id": rng.integers(1, 13, n),
    "quantity": rng.integers(1, 6, n),
})
sales["unit_price"] = (sales["product_id"].map(products.set_index("product_id")["unit_cost"]) * 1.5).round(2)
calendar = pd.DataFrame({"date": pd.date_range("2025-01-01", "2025-12-31")})
calendar["year"] = calendar["date"].dt.year
calendar["quarter"] = calendar["date"].dt.quarter
calendar["month_number"] = calendar["date"].dt.month
calendar["month_name"] = calendar["date"].dt.strftime("%B")
sales["revenue"] = sales["quantity"] * sales["unit_price"]
fact = (sales.merge(customers, on="customer_id").merge(products, on="product_id")
        .merge(calendar, left_on="order_date", right_on="date"))
s24 = sales.copy()
s24["order_date"] = s24["order_date"] - pd.DateOffset(years=1)
s24["quantity"] = (s24["quantity"] + 1) // 2
s24["revenue"] = s24["quantity"] * s24["unit_price"]
both = pd.concat([s24, sales], ignore_index=True)
monthly = both.groupby(both["order_date"].dt.to_period("M"))["revenue"].sum()
t24 = s24.merge(customers, on="customer_id")
c24 = t24.groupby("country")["revenue"].sum()
c25 = fact.groupby("country")["revenue"].sum()
mom = monthly["2025"].pct_change() * 100
by_customer = fact.groupby("customer_id")["revenue"].sum()
revenue = float(c25.sum())
orders = int(fact["order_id"].nunique())
facts = {
    "revenue": revenue,
    "growth": (revenue / float(c24.sum()) - 1) * 100,
    "slow_market": (c25 / c24).idxmin(),
    "slow_growth": float((c25 / c24).min() - 1) * 100,
    "uk_growth": float(c25["UK"] / c24["UK"] - 1) * 100,
    "worst_month": mom.idxmin().strftime("%B"),
    "worst_drop": -float(mom.min()),
    "orders": orders,
    "aov": revenue / orders,
    "top5": float(by_customer.nlargest(5).sum() / by_customer.sum() * 100),
}
for k, v in facts.items():
    print(k, round(v, 2) if isinstance(v, float) else v)

def rag(actual, target, higher=True):
    r = actual / target if higher else target / actual
    return "green" if r >= 1.0 else ("amber" if r >= 0.9 else "red")

card = [
    ("Revenue", facts["revenue"], 66000, True),
    ("Orders", facts["orders"], 380, True),
    ("Average order value", facts["aov"], 170, True),
    ("Top-5 customer share %", facts["top5"], 25, False),
]
for name, actual, target, higher in card:
    print(f"{name}: {actual:,.2f} vs {target} -> {rag(actual, target, higher)}")
```

```output
revenue 67132.5
growth 65.7
slow_market Spain
slow_growth 62.56
uk_growth 68.13
worst_month August
worst_drop 15.9
orders 400
aov 167.83
top5 21.48
Revenue: 67,132.50 vs 66000 -> green
Orders: 400.00 vs 380 -> green
Average order value: 167.83 vs 170 -> amber
Top-5 customer share %: 21.48 vs 25 -> green
```

Revenue is 67,132.50 and grew 65.7%, Spain grew slowest at 62.6% against 68.1% for the UK, August fell 15.9% against July, and the top five customers hold 21.5% of revenue. In the scorecard revenue and orders are green, the average order value of 167.83 is amber at 98.7% of its 170 target, and the concentration KPI, where lower is better, is green at 21.5% against a limit of 25. The targets here are invented for the exercise.

### Example 2: Step 2, the dashboard specification

Each visual is a rectangle and answers one executive question. Check the layout and that no visual is an orphan.

```python run
questions = {"q1": "Are we on target this year?", "q2": "Which market needs attention?", "q3": "When did we lose momentum?"}
page = [
    {"name": "Revenue card", "type": "card", "x": 40, "y": 40, "w": 360, "h": 120, "answers": "q1"},
    {"name": "Orders card", "type": "card", "x": 440, "y": 40, "w": 360, "h": 120, "answers": "q1"},
    {"name": "AOV card", "type": "card", "x": 840, "y": 40, "w": 360, "h": 120, "answers": "q1"},
    {"name": "Monthly trend", "type": "line", "x": 40, "y": 200, "w": 760, "h": 480, "answers": "q3"},
    {"name": "Revenue growth by market", "type": "bar", "x": 840, "y": 200, "w": 360, "h": 480, "answers": "q2"},
]

def overlaps(a, b):
    return (a["x"] < b["x"] + b["w"] and b["x"] < a["x"] + a["w"]
            and a["y"] < b["y"] + b["h"] and b["y"] < a["y"] + a["h"])

problems = []
for v in page:
    if v["x"] + v["w"] > 1280 or v["y"] + v["h"] > 720:
        problems.append(v["name"] + ": off canvas")
    if any(v[k] % 40 for k in ("x", "y", "w", "h")):
        problems.append(v["name"] + ": not on grid")
problems += [f"{a['name']} overlaps {b['name']}" for i, a in enumerate(page) for b in page[i + 1:] if overlaps(a, b)]
if min(page, key=lambda v: (v["y"], v["x"]))["type"] != "card":
    problems.append("top-left is not a card")
problems += [v["name"] + ": orphan" for v in page if v["answers"] not in questions]
uncovered = sorted(set(questions) - {v["answers"] for v in page})
print(problems, uncovered, len(page))
```

```output
[] [] 5
```

The page has five visuals, no layout problem, no orphan, and every question has a visual. The trend is the largest rectangle, so it carries the main message of timing, and the market bar answers the market question. In the build, the Spain bar would use the accent colour and the others grey (Day 139).

### Example 3: Step 3, the narrative from facts

Write the narrative as a template filled from the facts, and check its length and first words.

```python run
import numpy as np
import pandas as pd

rng = np.random.default_rng(7)
countries = ["UK", "Germany", "France", "Spain"]
cats = ["Hardware", "Software", "Services"]
customers = pd.DataFrame({

        .merge(calendar, left_on="order_date", right_on="date"))
s24 = sales.copy()
s24["order_date"] = s24["order_date"] - pd.DateOffset(years=1)
s24["quantity"] = (s24["quantity"] + 1) // 2
s24["revenue"] = s24["quantity"] * s24["unit_price"]
both = pd.concat([s24, sales], ignore_index=True)

mom = monthly["2025"].pct_change() * 100
slow = (c25 / c24).idxmin()
rate = c25["UK"] / c24["UK"]
gain = float(c24[slow] * rate - c25[slow])
text = (
    f"Recommendation: review the {slow} plan and the cause of the {mom.idxmin().strftime('%B')} dip before the next planning round. "
    f"Revenue grew {(c25.sum() / c24.sum() - 1) * 100:.1f}% to {c25.sum():,.2f}, ahead of target, "
    f"but {slow} grew {(c25[slow] / c24[slow] - 1) * 100:.1f}% and {mom.idxmin().strftime('%B')} fell {-mom.min():.1f}% from July. "
    f"If {slow} had matched the UK rate, revenue would be {gain:,.0f} higher ({gain / c25.sum() * 100:.1f}%). "
    f"Caveat: the UK has 83 orders, so market comparisons are indicative."
)
print(text)
words = len(text.split())
print(words, words <= 100, text.startswith("Recommendation:"))
```

```output

Revenue grew 65.7% to 67,132.50, ahead of target, but Spain grew 62.6% and August fell 15.9% from July. If Spain had matched the UK rate, revenue would be 570 higher (0.8%). Caveat: the UK has 83 orders, so market comparisons are indicative.
59 True True
```

The narrative starts with the recommendation, states the growth and its complication with numbers, sizes the scenario at about 570 (0.8% of revenue) and ends with the caveat. It is 59 words, within the budget of 100. It says "ahead of target", which is supported by the scorecard of step 1 (revenue 67,132.50 against 66,000).

### Example 4: Step 4, traceability

Extract the numbers from the narrative and check each one against the formatted facts. A deliberately wrong number is found.

```python run
import re

allowed = {"65.7", "67,132.50", "62.6", "15.9", "570", "0.8", "83", "100"}
good = "Revenue grew 65.7% to 67,132.50, Spain grew 62.6%, August fell 15.9%, the gap is 570 (0.8%) and the UK has 83 orders."
bad = "Revenue grew 66.0% to 67,132.50 and August fell 15.9%."

def untraced(text, allowed):
    numbers = [n.rstrip(".,") for n in re.findall(r"\d[\d,]*\.?\d*", text)]
    return [n for n in numbers if n not in allowed]

print(untraced(good, allowed))
print(untraced(bad, allowed))
```

```output
[]
['66.0']
```

The first narrative has no untraced numbers. The second contains 66.0, which is not among the facts (the real growth is 65.7), so the check returns it. In a real deliverable the allowed set is built from the facts dictionary with the same format strings that make the text, so the check can run after every data refresh.

## Real-world applications

- **Executive pre-read.** A one-page specification and a 100-word narrative sent before a meeting, with the numbers produced from code.
- **Report QA.** The untraced-number check catches typed numbers before a pack is circulated (Example 4).
- **Dashboard briefs.** Handing a visual specification with questions to a dashboard developer or to another analyst (Example 2).
- **Scorecard governance.** A scorecard with targets, directions and a tested RAG rule is the same artefact every month (Example 1).

## Daily review

### Key takeaways

- Work in order: facts, dashboard specification, narrative, traceability.
- Each visual answers an executive question; the layout check and the orphan check are cheap.
- The narrative has the recommendation first, numbers from the facts, a sized scenario and one caveat.
- Every number in a narrative must be traceable; check by code.
- A project is finished when its checks pass, not when it looks finished.

### Common mistakes

- Writing the narrative first and then looking for numbers to support it.
- Typing numbers in the text so that they differ from the dashboard after a refresh.
- Keeping visuals that answer no question because they were easy to build.
- Using a scenario without stating its assumption, or presenting it as a forecast.
- Exceeding the word budget so the recommendation is not read.

### Revision notes

- Facts dictionary and scorecard with direction-aware RAG.
- Page spec: grid, key card first, one question per visual, no orphans.
- Narrative: recommendation, situation, complication, scenario, caveat; word budget.
- Traceability: numbers in text found in the allowed set.
