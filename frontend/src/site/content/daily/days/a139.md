## Objectives

- State a dashboard's purpose as a question and decision, and test every visual against it.
- Explain visual hierarchy and use contrast, ordering and one accent colour to direct attention.
- Identify and remove noise: redundant legends, heavy gridlines, decoration, excess precision and colours.
- Format numbers for the reader and order categories so comparisons are easy.
- Audit a chart specification with a scoring function and compare a cluttered chart with a clean one.

## Understand

### Purpose first

Day 134 laid out a page on a grid in Power BI. This lesson steps back from the tool and asks what a dashboard is for. A **dashboard** is a single screen that lets one audience monitor something and notice when it needs attention. It is not a place to show everything the data contains. Before choosing any chart, write the **purpose** as one sentence: who looks at it, which question it answers and which decision follows. "The regional sales manager checks each morning whether revenue is on track and which market needs a call" is a purpose. "Sales dashboard" is a title. A purpose gives a test for every element: a visual earns its place only if it helps answer the question; otherwise it is a candidate for removal or for a second page. Dashboards without a purpose grow by accretion, one requested chart at a time, until nobody can say what they are for.

A useful distinction is between **monitoring** (what is the state now, is anything off?), **analysis** (why did it change, what is behind this number?) and **explanation** (the story of Days 138 and 141). A monitoring dashboard is glanceable and has few visuals; an analysis page invites interaction; trying to be both makes both worse. State which one you are building.

### Visual hierarchy

**Visual hierarchy** means the page tells the reader where to look first, second and third. The eye is drawn by differences: size, position, colour, contrast and isolation. Use them deliberately. The most important number gets the largest and top-left position. One **accent colour** marks what matters (the market that needs attention, the bar that is off target), and everything else is quiet grey. A page where six things are bright has no hierarchy, because when everything stands out, nothing does. The check is the squint test: blur the page by squinting and see what remains visible. It should be the headline measure and the one mark that needs action.

Order is part of hierarchy. A bar chart sorted by value is read in one pass from the largest to the smallest; sorted alphabetically it forces the reader to compare bars across the chart. Alphabetical order is right when the reader looks things up by name, and wrong when the point is a ranking. Time always runs left to right in its natural order.

### Reducing noise

**Noise** is anything on the page that does not carry information. The concept goes back to the idea of the data-ink ratio: as much as possible of what is drawn should represent data. Typical noise is easy to list. A legend for a chart with one series. Heavy gridlines and boxes around every chart. Three-dimensional bars, whose depth makes values harder to read. A different colour for each bar when the colour encodes nothing. Axis labels repeated on every chart. Numbers with more precision than the decision needs: showing 67,132.50 when 67K is enough. Decorative backgrounds and logos on every page. Each item may be small, but together they take attention from the data. The remedy is subtraction: remove an element, see if anything is lost, and if not leave it out. Remove first and add back only what is missed.

Numbers deserve their own care. Round to the precision the decision requires, abbreviate large values (K for thousands, M for millions) and keep units in the title or label and not repeated on each value. Align numbers to the right in tables so the digits line up. Use the same format for the same measure everywhere on the page.

### Context for the reader

A number alone is hard to judge: is 67K good? Day 140 develops this for KPIs; for the principle here, remember that a dashboard value should come with a point of comparison (target, previous period) wherever the reader must judge it. Titles should say what the chart shows and the period, so the page can be understood without opening a manual. Colour should never be the only carrier of meaning: add a label or a symbol for readers who cannot tell the colours apart.

### Why it matters

A dashboard is used under time pressure by people who are not analysts. A design that makes the main signal obvious saves time at every viewing and a design that hides it costs time at every viewing. Noise also reduces trust: a cluttered page looks careless, and readers assume the numbers are as well. The misconception is that more information is more helpful. For a dashboard the opposite is usually true: the work of the designer is choosing what to leave out.

## Syntax and key functions

This is a design lesson. The table lists the principles and the check that goes with each.

| Principle | Check |
|---|---|
| Purpose | One sentence: audience, question, decision. Every visual answers part of it. |
| Hierarchy | Squint test: the main number and the one thing needing action stand out. |
| One accent colour | At most one or two colours that carry meaning, the rest grey. |
| Order | Sort by value for rankings; natural order for time. |
| Noise | Remove legends on one series, 3-D, heavy grid, colour without meaning. |
| Number format | Precision for the decision, K and M, units once. |

A small noise score, used in the exercises:

```python
def noise_score(spec):
    return (3 * spec["three_d"] + spec["gridlines"] + spec["single_series_legend"]
            + max(0, spec["colours"] - 3) + (spec["decimals"] > 1) + spec["border"])
```

## Learn by example

### Example 1: Every visual answers a question

Write the purpose as questions, map each visual to one, and find the orphans.

```python run
purpose = "Each morning the regional manager checks whether revenue is on track and which market needs a call."
questions = {"q1": "Is revenue on track this month?", "q2": "Which market is behind?"}
visuals = [
    {"name": "Revenue card", "answers": "q1"},
    {"name": "Monthly trend", "answers": "q1"},
    {"name": "Revenue by country", "answers": "q2"},
    {"name": "Company logo carousel", "answers": None},
    {"name": "Product mix donut", "answers": None},
]
orphans = [v["name"] for v in visuals if v["answers"] not in questions]
print(len(visuals), len(orphans))
print(orphans)
covered = {v["answers"] for v in visuals if v["answers"]}
print(sorted(set(questions) - covered))
```

```output
5 2
['Company logo carousel', 'Product mix donut']
[]
```

Five visuals, two of which answer no question: the logo carousel and the product-mix donut. The second print shows that every question has at least one visual, so nothing is missing. Orphans are candidates for deletion or for an analysis page. The purpose line is what lets you make that call without an argument.

### Example 2: A noise score

Score a cluttered chart specification and a cleaned one.

```python run
def noise_score(spec):
    return (3 * spec["three_d"] + spec["gridlines"] + spec["single_series_legend"]
            + max(0, spec["colours"] - 3) + (spec["decimals"] > 1) + spec["border"])

before = {"three_d": True, "gridlines": True, "single_series_legend": True, "colours": 8, "decimals": 2, "border": True}
after = {"three_d": False, "gridlines": False, "single_series_legend": False, "colours": 2, "decimals": 0, "border": False}
print(noise_score(before), noise_score(after))
steps = ["three_d", "single_series_legend", "gridlines", "border"]
spec = dict(before)
for s in steps:
    spec[s] = False
    print("remove", s, noise_score(spec))
```

```output
12 0
remove three_d 9
remove single_series_legend 8
remove gridlines 7
remove border 6
```

The cluttered chart scores 12: three for 3-D, one each for gridlines, a legend and a border, five for colours beyond three and one for two decimals. The clean one scores 0. The loop removes one element at a time, which shows that removing 3-D saves the most (three points). The score is a crude teaching device, not a standard: its value is that it lists what to look for.

### Example 3: Numbers for the reader

Format the same values as the raw numbers and for a dashboard card.

```python run
import numpy as np
import pandas as pd

rng = np.random.default_rng(7)
countries = ["UK", "Germany", "France", "Spain"]
cats = ["Hardware", "Software", "Services"]
customers = pd.DataFrame({
    "customer_id": range(1, 41),
    "customer_name": [f"Customer {i:02d}" for i in range(1, 41)],
    "country": [countries[i % 4] for i in range(40)],
    "segment": [["Retail", "Corporate"][(i // 4) % 2] for i in range(40)],
})
products = pd.DataFrame({
    "product_id": range(1, 13),
    "product_name": [f"Product {i:02d}" for i in range(1, 13)],
    "category": [cats[i % 3] for i in range(12)],
    "unit_cost": [float(10 + 5 * i) for i in range(12)],
})
n = 400
sales = pd.DataFrame({
    "order_id": range(1, n + 1),
    "order_date": pd.to_datetime("2025-01-01") + pd.to_timedelta(rng.integers(0, 365, n), unit="D"),
    "customer_id": rng.integers(1, 41, n),
    "product_id": rng.integers(1, 13, n),
    "quantity": rng.integers(1, 6, n),
})
sales["unit_price"] = (sales["product_id"].map(products.set_index("product_id")["unit_cost"]) * 1.5).round(2)
calendar = pd.DataFrame({"date": pd.date_range("2025-01-01", "2025-12-31")})
calendar["year"] = calendar["date"].dt.year
calendar["quarter"] = calendar["date"].dt.quarter
calendar["month_number"] = calendar["date"].dt.month
calendar["month_name"] = calendar["date"].dt.strftime("%B")
sales["revenue"] = sales["quantity"] * sales["unit_price"]
fact = (sales.merge(customers, on="customer_id").merge(products, on="product_id")
        .merge(calendar, left_on="order_date", right_on="date"))
def short(x):
    if abs(x) >= 1_000_000:
        return f"{x / 1_000_000:.1f}M"
    if abs(x) >= 1_000:
        return f"{x / 1_000:.1f}K"
    return f"{x:.0f}"

rev = fact.groupby("country")["revenue"].sum()
for country, value in rev.items():
    print(f"{country:<8}{value:>12,.2f}{short(value):>8}")
print(short(float(rev.sum())), short(250), short(2_400_000))
```

```output
France     16,995.00   17.0K
Germany    19,447.50   19.4K
Spain      16,642.50   16.6K
UK         14,047.50   14.0K
67.1K 250 2.4M
```

The raw column carries six significant figures that nobody needs to compare four markets. The short form is 17.0K, 19.4K, 16.6K and 14.0K, and the right-aligned digits make the order obvious. The total is 67.1K. A table that people use for exact reconciliation keeps full precision, so the choice follows the purpose.

```python run
rng = np.random.default_rng(7)

        .merge(calendar, left_on="order_date", right_on="date"))
rev = fact.groupby("country")["revenue"].sum()

def inversions(values):
    return sum(1 for a, b in zip(values, values[1:]) if b > a)

alphabetical = list(rev.sort_index().round(1).values)
by_value = list(rev.sort_values(ascending=False, kind="stable").round(1).values)
print([float(v) for v in alphabetical], inversions(alphabetical))
print([float(v) for v in by_value], inversions(by_value))
```

```output
[16995.0, 19447.5, 16642.5, 14047.5] 1
[19447.5, 16995.0, 16642.5, 14047.5] 0
```

Alphabetically the countries have one place where a bar is taller than its left neighbour (Germany after France), so the eye has to jump around. Sorted by value, the count is 0 and the ranking reads straight down. The data is the same; only the order changed.

Draw the cluttered and the clean version of the same bar chart and print what each contains. Matplotlib draws the charts and the program prints their properties, not the image.

```python local
import pandas as pd

rng = np.random.default_rng(7)

        .merge(calendar, left_on="order_date", right_on="date"))
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt
from matplotlib.colors import to_hex

rev = fact.groupby("country")["revenue"].sum().sort_values(ascending=False, kind="stable")

def describe(ax):
    colours = sorted({to_hex(p.get_facecolor()) for p in ax.patches})
    grid = any(line.get_visible() for line in ax.get_ygridlines())
    return {"title": ax.get_title(), "bars": len(ax.patches), "colours": len(colours),
            "grid": grid, "legend": ax.get_legend() is not None, "top_spine": ax.spines["top"].get_visible()}

fig, ax = plt.subplots()
ax.bar(rev.index, rev.values, color=["red", "green", "blue", "orange"], label="Revenue")
ax.grid(True)
ax.legend()
ax.set_title("Revenue by country")
print(describe(ax))
plt.close(fig)

fig, ax = plt.subplots()
accent = {"Germany": "#0B3D91"}
ax.bar(rev.index, rev.values, color=[accent.get(c, "#BBBBBB") for c in rev.index])
ax.spines["top"].set_visible(False)
ax.spines["right"].set_visible(False)
ax.set_title("Germany is the largest market at 29.0% of revenue")
print(describe(ax))
plt.close(fig)
```

```output
{'title': 'Revenue by country', 'bars': 4, 'colours': 4, 'grid': True, 'legend': True, 'top_spine': True}
{'title': 'Germany is the largest market at 29.0% of revenue', 'bars': 4, 'colours': 2, 'grid': False, 'legend': False, 'top_spine': False}
```

The cluttered version has four colours that encode nothing, gridlines, a legend for a single series, a top border and a topic title. The clean version has two colours (an accent for Germany, grey for the rest), no grid, no legend, no top border and an action title (Day 138) that states the finding. Both charts hold the same four bars.

## Real-world applications

- **Dashboard requirements.** Starting every dashboard request with the purpose sentence turns "add a chart" requests into "which question does this answer?" conversations (Example 1).
- **Design reviews.** A checklist or score of noise elements gives reviewers specific things to remove (Example 2).
- **Executive packs.** Abbreviated numbers and sorted bars let a page be read in seconds (Examples 3 and 4).
- **Template standards.** A team's chart template sets grey for context and one accent colour so that every dashboard uses colour the same way (Example 5).

## Daily review

### Key takeaways

- Write the purpose as one sentence with audience, question and decision; every visual must serve it.
- Hierarchy comes from size, position and one accent colour; test by squinting.
- Remove noise: redundant legends, 3-D, heavy grid, meaningless colours, excess precision.
- Sort rankings by value; abbreviate numbers to the precision the decision needs.
- Colour is never the only carrier of meaning.

### Common mistakes

- Starting with chart types instead of the question, and ending with a page of unrelated visuals.
- Giving every bar a different colour although colour encodes nothing.
- Leaving default gridlines, borders and legends because the tool added them.
- Showing five decimal places on a card, which hides the signal.
- Sorting alphabetically when the point is a ranking.

### Revision notes

- Purpose: audience, question, decision. Monitoring, analysis or explanation.
- Hierarchy: size, position, accent colour; squint test.
- Noise list: legend on one series, 3-D, grid, borders, colour without meaning, decimals.
- Sorted bars; K and M; units once.
