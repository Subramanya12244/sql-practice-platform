## Objectives

- Break a small problem into data, steps and functions before writing code.
- Build a complete program from lists, dictionaries, loops and functions on data defined in the code.
- Write small functions that return values, and combine them in a short main section that prints a report.
- Test each function by hand with inputs whose answers you can work out yourself.
- Extend a working program with a new feature without breaking the old ones.

## Understand

### The project

Today you build an **expense summariser**. The input is a list of expenses, each one a dictionary with a date, a category, a description and an amount. The program reports the total spent, the total per category, the largest expense, the expenses above a limit, and the share of the total each category represents. All the data is written in the code, so the output is the same every time you run it.

This project uses everything from Days 1 to 14: strings and f-strings for the report, comparisons and `if` for validation, lists and dictionaries for the data, `for` loops for the patterns of Day 13, and functions to keep the pieces separate. Nothing new is taught; the skill is putting the pieces together.

### Design before code

Start by writing down three things before any code.

1. **The data shape.** One expense is `{"date": "2025-03-01", "category": "food", "note": "lunch", "amount": 12.5}`. The whole data set is a list of these dictionaries.
2. **The questions** the report must answer, in order: how many valid expenses? What is the total? What is the total per category? Which expense is the largest? Which are above the limit? What share does each category take?
3. **One function per question.** Each takes the list of expenses (and maybe a limit) and **returns** an answer. None of them prints. Only the last part of the program prints.

This split has a name: separating **calculation** from **presentation**. It lets you test a calculation by calling it with a tiny list and comparing with an answer you worked out by hand.

### Build in steps and test each step

Do not write the whole program and then run it. Write the data, check it prints. Write the first function and call it with a tiny list such as two expenses of 10 and 5, where you know the answer is 15. Only then write the next function. When something is wrong, you know it is in the code you wrote last. This is **testing by hand**: you choose inputs with known answers and compare.

### Dealing with bad data

Real data is untidy. Our data includes one expense with a negative amount and one with an empty category. A function `is_valid(expense)` decides whether a record is usable; the other functions then work on the list of valid expenses only. The guard clause idea from Day 7 and Day 14 fits here: check the bad cases first and return `False` early.

### Where the project can go wrong

The mistakes to watch for are the ones from earlier days: an accumulator initialised inside the loop (Day 11), a dictionary counted with `[]` before the key exists (Day 10), a maximum started at 0 (Day 13), and a function that prints when it should return (Day 14). Check each when a number looks wrong.

## Learn by example

### Example 1: Step 1, the data and the validity check

The list holds eight records, two of which are bad. `is_valid` returns `True` only for a positive amount and a non-empty category.

```python run
expenses = [
    {"date": "2025-03-01", "category": "food", "note": "lunch", "amount": 12.5},
    {"date": "2025-03-01", "category": "transport", "note": "bus pass", "amount": 40.0},
    {"date": "2025-03-02", "category": "food", "note": "groceries", "amount": 63.2},
    {"date": "2025-03-03", "category": "fun", "note": "cinema", "amount": 18.0},
    {"date": "2025-03-04", "category": "food", "note": "refund?", "amount": -5.0},
    {"date": "2025-03-05", "category": "", "note": "unknown", "amount": 9.99},
    {"date": "2025-03-06", "category": "transport", "note": "taxi", "amount": 22.4},
    {"date": "2025-03-07", "category": "fun", "note": "concert", "amount": 55.0},
]

def is_valid(expense):
    """Return True when the amount is positive and the category is not empty."""
    if expense["amount"] <= 0:
        return False
    if not expense["category"]:
        return False
    return True

valid = []
for e in expenses:
    if is_valid(e):
        valid.append(e)
print(len(expenses), len(valid))
print(is_valid({"category": "x", "amount": 1}), is_valid({"category": "", "amount": 1}))
```

```output
8 6
True False
```

Two quick hand tests at the end confirm the function before we build on it.

### Example 2: Step 2, the total

`total_spent` uses the accumulator pattern. We test it with two tiny lists whose answers are obvious.

```python run
def total_spent(expenses):
    """Return the sum of the amounts."""
    total = 0
    for e in expenses:
        total += e["amount"]
    return total

print(total_spent([{"amount": 10}, {"amount": 5}]))
print(total_spent([]))
sample = [{"amount": 12.5}, {"amount": 40.0}, {"amount": 63.2}]
print(round(total_spent(sample), 2))
```

```output
15
0
115.7
```

An empty list gives 0, which is the correct total of nothing.

### Example 3: Step 3, totals per category

The dictionary counting idiom from Day 10, adding the amount instead of 1.

```python run
def totals_by_category(expenses):
    """Return a dict mapping each category to the sum of its amounts."""
    totals = {}
    for e in expenses:
        name = e["category"]
        totals[name] = totals.get(name, 0) + e["amount"]
    return totals

sample = [
    {"category": "food", "amount": 10},
    {"category": "fun", "amount": 4},
    {"category": "food", "amount": 6},
]
print(totals_by_category(sample))
print(totals_by_category([]))
```

```output
{'food': 16, 'fun': 4}
{}
```

Work out by hand that food is 16 and fun is 4; the function agrees.

### Example 4: Step 4, the largest expense and the expenses above a limit

The maximum pattern starts at `None` (Day 13), and the filter pattern builds a new list.

```python run
def largest(expenses):
    """Return the expense with the biggest amount, or None for an empty list."""
    best = None
    for e in expenses:
        if best is None or e["amount"] > best["amount"]:
            best = e
    return best

def above_limit(expenses, limit):
    """Return the expenses whose amount is greater than limit, in order."""
    result = []
    for e in expenses:
        if e["amount"] > limit:
            result.append(e)
    return result

sample = [
    {"note": "a", "amount": 30},
    {"note": "b", "amount": 75},
    {"note": "c", "amount": 50},
]
print(largest(sample))
print(largest([]))
for e in above_limit(sample, 40):
    print(e["note"])
print(above_limit(sample, 100))
```

```output
{'note': 'b', 'amount': 75}
None
b
c
[]
```

The last two checks show a filter that matches some expenses (the loop prints their notes) and one that matches none (an empty list).

### Example 5: Step 5, shares and a formatted line

Percentages come from the totals; the report line uses f-string format specs (Day 5).

```python run
def shares(totals):
    """Return each category's percentage of the grand total, rounded to 1 place."""
    grand = 0
    for amount in totals.values():
        grand += amount
    result = {}
    for name, amount in totals.items():
        result[name] = round(amount / grand * 100, 1)
    return result

totals = {"food": 75.7, "transport": 62.4, "fun": 73.0}
pct = shares(totals)
print(pct)
for name in sorted(totals):
    print(f"{name:<10}{totals[name]:>8.2f}{pct[name]:>7.1f}%")
```

```output
{'food': 35.9, 'transport': 29.6, 'fun': 34.6}
food         75.70   35.9%
fun          73.00   34.6%
transport    62.40   29.6%
```

`sorted(totals)` gives the keys in alphabetical order, so the report has a stable order.

### Example 6: The complete program

All the functions are defined above one short main section. The main section filters the data, calls the functions and prints the report. It prints nothing else.

```python run
expenses = [
    {"date": "2025-03-01", "category": "food", "note": "lunch", "amount": 12.5},
    {"date": "2025-03-01", "category": "transport", "note": "bus pass", "amount": 40.0},
    {"date": "2025-03-02", "category": "food", "note": "groceries", "amount": 63.2},
    {"date": "2025-03-03", "category": "fun", "note": "cinema", "amount": 18.0},
    {"date": "2025-03-04", "category": "food", "note": "refund?", "amount": -5.0},
    {"date": "2025-03-05", "category": "", "note": "unknown", "amount": 9.99},
    {"date": "2025-03-06", "category": "transport", "note": "taxi", "amount": 22.4},
    {"date": "2025-03-07", "category": "fun", "note": "concert", "amount": 55.0},
]
LIMIT = 50

def is_valid(expense):
    """Return True when the amount is positive and the category is not empty."""
    return expense["amount"] > 0 and bool(expense["category"])

def clean(expenses):
    """Return only the valid expenses."""
    result = []
    for e in expenses:
        if is_valid(e):
            result.append(e)
    return result

def total_spent(expenses):
    """Return the sum of the amounts."""
    total = 0
    for e in expenses:
        total += e["amount"]
    return total

def totals_by_category(expenses):
    """Return a dict of category totals."""
    totals = {}
    for e in expenses:
        totals[e["category"]] = totals.get(e["category"], 0) + e["amount"]
    return totals

def largest(expenses):
    """Return the biggest expense or None."""
    best = None
    for e in expenses:
        if best is None or e["amount"] > best["amount"]:
            best = e
    return best

def above_limit(expenses, limit):
    """Return the expenses above the limit."""
    result = []
    for e in expenses:
        if e["amount"] > limit:
            result.append(e)
    return result

valid = clean(expenses)
total = total_spent(valid)
by_cat = totals_by_category(valid)
top = largest(valid)
big = above_limit(valid, LIMIT)

print(f"Valid expenses: {len(valid)} of {len(expenses)}")
print(f"Total spent: {total:.2f}")
for name in sorted(by_cat):
    print(f"  {name:<10}{by_cat[name]:>8.2f}{by_cat[name] / total * 100:>7.1f}%")
print(f"Largest: {top['note']} ({top['amount']:.2f}) on {top['date']}")
notes = []
for e in big:
    notes.append(e["note"])
print(f"Above {LIMIT}: {', '.join(notes)}")
```

```output
Valid expenses: 6 of 8
Total spent: 211.10
  food         75.70   35.9%
  fun          73.00   34.6%
  transport    62.40   29.6%
Largest: groceries (63.20) on 2025-03-02
Above 50: groceries, concert
```

`', '.join(notes)` is a string method that glues a list of strings together with `, ` between them. The structure is what matters: data, one function per question, then one block that prints.

## Real-world applications

- **Finance and operations reporting.** Totals by category and the largest items are the first lines of almost every cost report.
- **Data cleaning before analysis.** A validity function and a `clean` step remove bad rows before any statistic is calculated.
- **Reusable functions.** The same `totals_by_category` works for sales by region or tickets by team; only the key name changes.
- **Hand tests.** Checking a function with a small list whose answer you know is the habit behind automated testing.

## Daily review

### Key takeaways

- Design first: data shape, questions, then one returning function per question.
- Separate calculation (functions return values) from presentation (the main section prints).
- Build and test one step at a time with inputs whose answers you can compute by hand.
- Clean the data once, then run every calculation on the clean list.
- A new feature should be a new function plus a new line in the report.

### Common mistakes

- **Writing everything at once.** A wrong number is then hard to trace. Test each function with a tiny list as soon as it exists.
- **Printing inside the calculation functions.** They cannot be reused or tested. Return the result.
- **Dividing by a zero total.** `shares({})` fails with `ZeroDivisionError: division by zero`. Check for an empty list first.
- **Counting invalid rows.** If you forget to call `clean`, the negative amount reduces the total and the empty category appears as a blank name.
- **Floating-point noise in output.** Sums such as `63.2 + 12.5` may print with extra digits. Format with `:.2f` or `round()` before showing.

### Revision notes

- Data: list of dictionaries. Questions: total, per category, largest, above limit, shares.
- One function per question; returns, never prints.
- Clean first. Test with small lists. Print in one block at the end.
