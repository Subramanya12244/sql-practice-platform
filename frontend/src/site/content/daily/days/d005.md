## Understand

### The problem with building text by hand

Programs spend much of their time turning values into readable text: "Total: 1,234.50", "Loaded 120 rows in 3.2 seconds". With what you know already you can do this by joining strings with `+`, but each number must be converted with `str()` first and every space is typed by hand. Long messages become hard to read and easy to get wrong. Python has a better tool for this called the f-string.

### f-strings

An **f-string** (formatted string literal) is an ordinary string with the letter `f` directly before the opening quote. Inside it, anything in curly braces `{ }` is a **placeholder**: Python evaluates the code between the braces and puts the result into the text. Because the result is converted to text for you, no `str()` is needed. The braces can hold a variable, `{name}`, or a whole expression, `{price * quantity}`, or a method call, `{name.upper()}`. Use a different kind of quote inside the braces from the one around the string, so `f"{data['key']}"` is safe.

If you forget the `f`, Python does not complain. It treats the braces as ordinary characters and prints them as they are, so `"Hello, {name}"` prints exactly `Hello, {name}`. To print a real brace in an f-string, double it: `f"{{done}}"` shows `{done}`.

### Format specifications

A placeholder can carry a **format specification**, written after a colon: `{value:spec}`. The specification controls how the value is displayed, not what it is. The pieces are optional and appear in this order: alignment, width, grouping, precision and type.

- Precision and type: `.2f` means "a float with 2 digits after the decimal point". `f"{3.14159:.2f}"` is `3.14`, and `f"{2:.2f}"` is `2.00`, which is why `f` is the usual tool for money.
- Grouping: `,` inserts thousands separators, so `f"{1234567.5:,.2f}"` is `1,234,567.50`.
- Percentages: `.1%` multiplies by 100, appends a percent sign and keeps one decimal, so `f"{0.256:.1%}"` is `25.6%`. You do not multiply by 100 yourself.
- Width: a number sets the minimum width of the field and pads with spaces. `{x:8}` makes an 8-character field.
- Alignment: `<` aligns left, `>` aligns right and `^` centres, and it comes before the width. Text aligns left by default and numbers right by default, so `{name:<10}` and `{amount:>8.2f}` make columns line up.
- Zero padding: `{n:05d}` pads the whole number `n` with zeros to width 5, so 42 becomes `00042`. The letter `d` means "whole number".

A format specification returns text. The value in the variable is unchanged, and it is a string you should show, not calculate with. Round with `round()` when you need the rounded number and format when you need the display.

### Reading input with input()

So far every value was typed into the program. The function `input()` pauses the program, reads one line of text that the user types, and returns it as a string, without the final line break. For example, `name = input()` waits for a line and stores it. In DataForge's exercises the lines to read are supplied in a box called `stdin`, short for **standard input**, the stream a program reads from. Each call to `input()` consumes the next line.

You can write a prompt inside the parentheses, `input("Name: ")`, and the prompt is printed before waiting. That prompt is part of the program's output, so the exercises on this day avoid prompts and use plain `input()`, which keeps the output exactly what the task states. If a program calls `input()` more times than there are lines, it raises an `EOFError`.

### The input() type trap

`input()` always returns a `str`, even when the user types digits. If the user types `5`, you receive the text `"5"`. Calculating with it directly either joins strings, as in `"5" + "5"` giving `"55"`, or raises a `TypeError`. Convert the text first: `int(input())` for whole numbers or `float(input())` for decimals. Text with extra spaces can be cleaned with `strip()` first. If the text is not a valid number, the conversion raises a `ValueError`; handling that comes later.

### print() options: sep and end

`print()` has two options that you give by name. `sep` is the text placed between values, with a default of one space. `end` is the text added after the last value, with a default of a newline, which is why each `print()` starts a new line. Setting `sep=""` removes the spaces, `sep="-"` joins with hyphens, and `sep="\n"` puts each value on its own line. Setting `end=""` keeps the output on the same line so the next `print()` continues it. The names must be written out, as in `print(a, b, sep=", ")`.

### Common misconception

Many people think `input()` returns a number when the user types a number. It returns text, always. A second frequent belief is that `f"{x:.2f}"` changes `x`. It only produces a formatted string; `x` still holds all its digits.

### Why it matters

Reports, logs, dashboards and exports all need values in a readable and consistent layout: the same decimals, aligned columns, percentages shown as percentages. Reading input is how a script receives its parameters, such as a file name, a date or a threshold. Together they make a program that can be used by someone other than its author.

## Syntax and key functions

An f-string with placeholders:

```python
f"text {expression} more text {expression:spec}"
```

The `f` prefix switches placeholders on. Each `{ }` holds an expression and an optional `:spec` that controls the display.

The shape of a format specification:

```text
{value:[align][width][,][.precision][type]}
```

Every part is optional. `align` is `<`, `>` or `^`; `width` is a number; `,` adds thousands separators; `.precision` is a dot and a number of decimals; `type` is `f` for floats, `d` for whole numbers or `%` for percentages. A `0` before the width pads with zeros.

Read a line of input and convert it:

```python
text = input()
count = int(input())
price = float(input())
```

`input()` returns a string. `int()` and `float()` convert it.

Control print:

```python
print(value1, value2, sep="-", end="")
```

`sep` goes between the values and `end` after the last one.

| Spec | Example | Result |
|---|---|---|
| `.2f` | `f"{3.14159:.2f}"` | `3.14` |
| `,.2f` | `f"{1234567.5:,.2f}"` | `1,234,567.50` |
| `.1%` | `f"{0.256:.1%}"` | `25.6%` |
| `>6` | `f"{42:>6}"` | 42 right-aligned in 6 characters: four spaces, then `42` |
| `<6` | `f"{'ab':<6}"` | `ab` left-aligned in 6 characters: `ab`, then four spaces |
| `^7` | `f"{'ab':^7}"` | `ab` centred in 7 characters: two spaces, `ab`, three spaces |
| `05d` | `f"{42:05d}"` | `00042` |
| `02d` | `f"{7:02d}"` | `07` |

| Function or option | What it does |
|---|---|
| `input()` | Reads one line, returns a string without the line break. |
| `int(text)`, `float(text)` | Convert input text to a number. |
| `print(..., sep=x)` | Puts `x` between values (default a space). |
| `print(..., end=x)` | Puts `x` after the last value (default a newline). |

## Learn by example

### Example 1: f-string placeholders

The placeholders hold variables and a calculation. No `str()` is needed, because the f-string converts values to text. The last line has no `f`, so the braces are printed literally.

```python run
name = "Ada"
orders = 12
price = 4.5
print(f"{name} placed {orders} orders")
print(f"Revenue: {orders * price}")
print(f"Shout: {name.upper()}")
print("Missing the f: {name}")
```

```output
Ada placed 12 orders
Revenue: 54.0
Shout: ADA
Missing the f: {name}
```

### Example 2: Format specifications

One value, several displays. `.2f` fixes two decimals, `,` adds thousands separators, `%` turns a ratio into a percentage, and `05d` pads a whole number with zeros. The unchanged variable on the last line shows that formatting only affects the text.

```python run
amount = 1234567.891
print(f"{amount:.2f}")
print(f"{amount:,.2f}")
print(f"{0.256:.1%}")
print(f"{42:05d}")
print(f"{2:.2f}")
print(amount)
```

```output
1234567.89
1,234,567.89
25.6%
00042
2.00
1234567.891
```

### Example 3: Width and alignment

A width reserves space for a field and `<`, `>` and `^` choose where the content sits. The vertical bars mark the field edges so that you can see the padding. This is how columns are made to line up.

```python run
word = "data"
print(f"|{word:<10}|")
print(f"|{word:>10}|")
print(f"|{word:^10}|")
print(f"|{3.14159:>10.2f}|")
print(f"|{7:>4}|{8:>4}|{1000:>6}|")
```

```output
|data      |
|      data|
|   data   |
|      3.14|
|   7|   8|  1000|
```

### Example 4: Reading text and numbers with input()

Each `input()` call reads the next line of the `stdin` block. The name stays text. The age is converted with `int()` so that arithmetic works. Without the conversion, `age + 1` would raise a `TypeError`.

```python run
name = input()
age = int(input())
print(f"Hello, {name}!")
print(f"Next year you will be {age + 1}.")
print(type(name), type(age))
```
```stdin
Grace
36
```

```output
Hello, Grace!
Next year you will be 37.
<class 'str'> <class 'int'>
```

### Example 5: A calculation from input

The unit price and the quantity arrive as text and are converted with `float()` and `int()`. The total is calculated from the converted numbers, then shown with thousands separators and two decimals. The first `input()` is wrapped in `strip()` to remove spaces that could be typed around it.

```python run
product = input().strip()
price = float(input())
quantity = int(input())
total = price * quantity
print(f"{product}: {quantity} x {price:.2f} = {total:,.2f}")
```
```stdin
  Laptop stand
1249.5
3
```

```output
Laptop stand: 3 x 1249.50 = 3,748.50
```

### Example 6: sep and end

`sep` changes what goes between the values, and `end` changes what goes after the last one. With `end=""` the next `print()` carries on in the same line. Using `sep="\n"` puts each value on a separate line.

```python run
print(2024, 6, 15, sep="-")
print("a", "b", "c", sep="")
print("Loading", end="...")
print("done")
print("x", "y", "z", sep="\n")
print("Name", "City", sep=", ", end=" <- header\n")
```

```output
2024-6-15
abc
Loading...done
x
y
z
Name, City <- header
```

## Real-world applications

- **Readable reports and logs.** A pipeline's run summary such as `Loaded 1,250 rows in 3.20 s (98.5% valid)` is built with an f-string, with `,` for the count, `.2f` for seconds and `.1%` for the share. The same message in every run makes logs easy to scan.
- **Consistent codes and identifiers.** Order numbers, file names and partition names often need fixed widths: `f"order_{42:06d}.csv"` gives `order_000042.csv`, which also sorts correctly as text.
- **Plain-text tables.** Aligned columns, as in Example 3, turn a few values into a table that is readable in a terminal, an email or a log, without any spreadsheet.
- **Scripts that take parameters.** A job that reads a threshold or a name with `input()` can be rerun with different values without editing its code, provided the text is converted to the right type first. The same idea carries over to command-line arguments and configuration later in the programme.

## Daily review

### Key takeaways

- An f-string is a string with an `f` prefix; each `{expression}` is replaced by its value as text.
- A format specification after a colon controls the display: `.2f`, `,`, `%`, width, `<`, `>`, `^`, and `05d` for zero padding.
- Formatting changes the text shown, not the number stored.
- `input()` always returns a string; convert with `int()` or `float()` before calculating.
- `print(..., sep=..., end=...)` changes the separator between values and the ending of the line.

### Common mistakes

- Forgetting the `f` prefix, so the braces are printed literally.
- Calculating with the result of `input()` without converting it, so numbers are joined as text or a `TypeError` appears.
- Writing the format specification before the colon instead of after it, or forgetting the colon.
- Putting the alignment after the width (`{x:8>}`) instead of before it (`{x:>8}`).
- Using the same kind of quote inside a placeholder as around the string.
- Passing a prompt to `input()` when the expected output does not contain it, which makes the output differ.
- Writing `sep` or `end` without the name, so they are printed as values.

### Revision notes

- `f"{name} is {age}"`, `f"{price:.2f}"`, `f"{n:,}"`, `f"{share:.1%}"`, `f"{n:05d}"`, `f"{text:<10}"`, `f"{num:>8.2f}"`.
- `x = int(input())` and `y = float(input())`; plain `input()` is text.
- `print("a", "b", sep="-")` shows `a-b`; `print("a", end="")` stays on the line.
- No `f` means no placeholders: braces print as typed.
