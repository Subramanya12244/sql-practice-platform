## Objectives

- Read a CSV in chunks with `pandas.read_csv(chunksize=...)` and carry a running result across chunks.
- Read raw text without losing information, using `dtype=str` and `keep_default_na=False`.
- Check a file's header against an expected schema before any row is processed.
- Validate each chunk with vectorised rules, recording the file line number and a reason for every bad row.
- Handle structurally broken lines and decide when a file has too many bad rows to continue.

## Understand

### Why read in chunks

A CSV file read with a plain `pd.read_csv(path)` is turned into one DataFrame in memory. For a 200 MB export that may be 1 GB of RAM, and for a file larger than memory the program simply crashes. **Chunked reading** processes the file a fixed number of rows at a time. `pd.read_csv(path, chunksize=50_000)` does not return a DataFrame; it returns an **iterator**, an object that hands you the next DataFrame each time a `for` loop asks. Only one chunk is held in memory, and anything you want to keep across chunks, such as a total, a count or the set of ids seen so far, you carry yourself in ordinary variables. You met `chunksize` on Day 84; today the chunks are used for checking, not only for saving memory.

A chunk does not know about the others. Anything that depends on the whole file, such as duplicate keys, must be tracked across the loop. Anything that depends on one row, such as "the amount is a number", can be checked inside each chunk.

### Read raw, decide later

By default `read_csv` guesses a type for each column, and the guesses destroy information. The text `007` becomes the number `7`. A column that is mostly numbers but has one `n/a` becomes text for that chunk and numeric for the next, so the types change from chunk to chunk. The country code `NA` (Namibia) and the strings `null`, `NULL`, `NaN` and `n/a` are silently turned into missing values. For ingestion the safe habit is `dtype=str, keep_default_na=False`. Every field then arrives as the exact text in the file, and an empty cell is an empty string. You convert and test the values yourself, with rules you chose, and you can report exactly what the file contained. This matches the all-text staging table of Day 92.

### Schema checks come first

A **schema check** compares the file's structure with what the target expects: the column names, their order, and whether any are missing or extra. It runs once, on the header, before any data. If the columns are wrong, nothing downstream can be right, and the correct response is to stop and say which columns are missing or unexpected. Checking the header costs nothing; discovering after an hour of loading that `amount` was renamed `total` costs a great deal. `pandas` reads the header into the `columns` attribute of the first chunk. A chunk's `columns` are identical for every chunk, so one check is enough.

### Validating a chunk

A **validation rule** is a test that a row either passes or fails, written so that it applies to the whole chunk at once. Convert a text column with an error-tolerant function: `pd.to_numeric(col, errors="coerce")` returns a number or `NaN` for text that is not a number, and `pd.to_datetime(col, format="%Y-%m-%d", errors="coerce")` returns a timestamp or `NaT`, and, unlike a pattern test, it rejects `2026-02-30`. The resulting missing values mark the failing rows. Then check ranges (`>= 0`), allowed values (`isin([...])`), required fields (`!= ""`) and format (`str.fullmatch`).

Each row should leave validation with either a pass or **one reason**, the first rule it broke, so that a count by reason reads cleanly. Keep the **line number** too. A chunk's index runs on across chunks, so the line in the file is the index plus 2: one for the header and one because the index starts at zero. A data owner can fix "line 7: bad amount"; they cannot fix "some rows are bad".

### What to do with bad rows

There are three policies. **Fail fast** stops at the first error: safe, but one bad row blocks the whole file. **Skip silently** drops bad rows and is the worst choice, because data disappears with no record. **Quarantine** is the standard answer: good rows continue, bad rows are collected with their line numbers and reasons into a reject file or table, and the run reports `read = good + rejected`. Add a **threshold**: if more than, say, 5% of rows are rejected, the file is probably not the file you expected (wrong delimiter, wrong encoding, shifted columns), so abort instead of loading a mostly empty result.

### Structurally broken lines

Some lines are broken before any value is examined: a row has more fields than the header, or an unbalanced quote swallows several lines. With the default C engine `read_csv` raises `ParserError` on a line with too many fields. `on_bad_lines="skip"` drops such lines and `on_bad_lines="warn"` also reports them. With `engine="python"` you can pass a function that receives the fields of each bad line, which lets you record it. A row with too few fields is not treated as bad: pandas pads it with missing values, so the shortage must be caught by your own required-field rule.

### Common misconception

Learners assume that `chunksize` makes the whole job safe and fast. It only limits memory. A rule that needs the whole file (uniqueness, totals) still needs state carried between chunks, and a chunk size that is far too small (say 10 rows) makes the job slow because each chunk has overhead.

### Why it matters

Files from other teams and vendors are never perfectly clean. A loader that reads in chunks, checks the header, quarantines bad rows with reasons and stops on a threshold turns a surprise at 3 a.m. into a clear report: how many rows came in, how many were loaded, and exactly which lines to fix.

## Syntax and key functions

Read in chunks as raw text:

```python
import pandas as pd

reader = pd.read_csv(source, chunksize=1000, dtype=str, keep_default_na=False)
for chunk in reader:
    ...   # chunk is a DataFrame; chunk.index continues across chunks
```

`source` is a path or, in examples here, an `io.StringIO` object holding CSV text. Setting `dtype=str` keeps all fields as text and `keep_default_na=False` stops `NA` and `null` becoming missing.

Convert with tolerance:

```python
amount = pd.to_numeric(chunk["amount"], errors="coerce")
day = pd.to_datetime(chunk["order_date"], format="%Y-%m-%d", errors="coerce")
bad = amount.isna() | (amount < 0)
```

Handle broken lines:

```python
pd.read_csv(source, on_bad_lines="skip")
pd.read_csv(source, engine="python", on_bad_lines=lambda fields: None)
```

| Item | Returns or does |
|---|---|
| `read_csv(..., chunksize=n)` | An iterator of DataFrames of up to `n` rows. |
| `dtype=str`, `keep_default_na=False` | Keep every field as exact text; empty cells become `""`. |
| `chunk.columns` | The header names of the file. |
| `pd.to_numeric(s, errors="coerce")` | Numbers, with `NaN` where the text is not numeric. |
| `pd.to_datetime(s, format=f, errors="coerce")` | Timestamps, with `NaT` where the text does not match. |
| `s.isin(values)` | Boolean mask of allowed values. |
| `s.str.fullmatch(regex)` | True where the whole text matches. |
| `s.mask(cond, value)` | A copy where `cond` is true replaced by `value`. |
| `on_bad_lines` | `"error"` (default), `"warn"`, `"skip"` or a function (python engine). |
| `chunk.index + 2` | The line number in the file for each row. |

## Learn by example

### Example 1: Chunks and a running total

A CSV is held as text in a `StringIO` object, so the example needs no file. With `chunksize=4` the 10 rows arrive as chunks of 4, 4 and 2. The index runs on from one chunk to the next, and the total is carried in an ordinary variable.

```python run
import io
import pandas as pd

text = "id,amount\n" + "\n".join(f"{i},{i * 10}" for i in range(1, 11)) + "\n"
total = 0
for number, chunk in enumerate(pd.read_csv(io.StringIO(text), chunksize=4), start=1):
    total += int(chunk["amount"].sum())
    print(number, chunk.shape, chunk.index[0], chunk.index[-1], total)
```

```output
1 (4, 2) 0 3 100
2 (4, 2) 4 7 360
3 (2, 2) 8 9 550
```

### Example 2: Read raw text

The first read lets pandas guess; the second keeps the exact text. Guessing turns `007` into `7` and the country code `NA` into a missing value. The raw read keeps both, and an empty cell is an empty string that a rule can test.

```python run
import io
import pandas as pd

text = "code,country,note\n007,NA,ok\n042,US,\n"
guessed = pd.read_csv(io.StringIO(text))
raw = pd.read_csv(io.StringIO(text), dtype=str, keep_default_na=False)
print(guessed.values.tolist())
print(raw.values.tolist())
print((raw["note"] == "").tolist())
```

```output
[[7, nan, 'ok'], [42, 'US', nan]]
[['007', 'NA', 'ok'], ['042', 'US', '']]
[False, True]
```

### Example 3: Check the header

`check_header` compares the file's columns with the expected ones and reports problems in plain words. Only the header is read here (`nrows=0` reads no data rows), which is how you can fail before touching any data.

```python run
import io
import pandas as pd

EXPECTED = ["order_id", "customer_email", "order_date", "amount", "status"]

def check_header(columns, expected):
    problems = []
    missing = [c for c in expected if c not in columns]
    extra = [c for c in columns if c not in expected]
    if missing:
        problems.append("missing: " + ", ".join(missing))
    if extra:
        problems.append("unexpected: " + ", ".join(extra))
    if not missing and not extra and list(columns) != expected:
        problems.append("columns are in a different order")
    return problems

good = "order_id,customer_email,order_date,amount,status\n"
renamed = "order_id,customer_email,order_date,total,status,note\n"
shuffled = "order_id,order_date,customer_email,amount,status\n"
for header in (good, renamed, shuffled):
    cols = pd.read_csv(io.StringIO(header), nrows=0).columns
    print(check_header(cols, EXPECTED) or "header ok")
```

```output
header ok
['missing: amount', 'unexpected: total, note']
['columns are in a different order']
```

### Example 4: Validate a chunk and keep the reasons

Each rule marks failing rows, and the first rule that fails gives the reason (`mask` fills only rows that have none yet). The file line is the index plus 2. The loop collects rejects across chunks and remembers the good order ids to catch duplicates that fall in a later chunk. The date `2026-02-30` is rejected here, because `to_datetime` knows the calendar.

```python run
import io
import pandas as pd

text = """order_id,customer_email,order_date,amount,status
1001,ana@example.com,2026-01-05,19.90,paid
1002,ben@example.com,2026-01-06,25,paid
abc,cy@example.com,2026-01-07,12.50,new
1004,,2026-01-08,4,shipped
1005,dee@example.com,2026-02-30,8.00,paid
1006,eli@example.com,2026-01-09,,paid
1007,fay@example.com,2026-01-10,30.00,pending
1008,gus@example.com,2026-01-10,7.5,paid
1002,ben@example.com,2026-01-06,25,paid
1010,hal@example.com,2026-01-11,-3,paid
1011,ivy@example.com,2026-01-12,11.25,cancelled
1012,jo@example.com,2026-01-12,6,paid
"""

def validate_chunk(chunk, seen):
    amount = pd.to_numeric(chunk["amount"], errors="coerce")
    day = pd.to_datetime(chunk["order_date"], format="%Y-%m-%d", errors="coerce")
    rules = [
        ("bad order_id", ~chunk["order_id"].str.fullmatch(r"[0-9]+")),
        ("missing email", chunk["customer_email"] == ""),
        ("bad date", day.isna()),
        ("bad amount", amount.isna() | (amount < 0)),
        ("bad status", ~chunk["status"].isin(["new", "paid", "shipped", "cancelled"])),
        ("duplicate order_id", chunk["order_id"].isin(seen) | chunk["order_id"].duplicated()),
    ]
    reason = pd.Series("", index=chunk.index)
    for label, failed in rules:
        reason = reason.mask((reason == "") & failed, label)
    return chunk[reason == ""], reason[reason != ""]

seen, good_rows, rejects = set(), 0, []
for chunk in pd.read_csv(io.StringIO(text), chunksize=5, dtype=str, keep_default_na=False):
    good, bad = validate_chunk(chunk, seen)
    seen.update(good["order_id"])
    good_rows += len(good)
    rejects += [(int(i) + 2, why) for i, why in bad.items()]

print("good:", good_rows)
for line, why in rejects:
    print(f"line {line}: {why}")
```

```output
good: 5
line 4: bad order_id
line 5: missing email
line 6: bad date
line 7: bad amount
line 8: bad status
line 10: duplicate order_id
line 11: bad amount
```

### Example 5: Structurally broken lines

Line 3 has an extra field and line 5 is missing one. With the default engine the extra field raises an error. `on_bad_lines="skip"` drops it. A callable on the Python engine receives the fields of the bad line so it can be recorded. Line 5, which has too few fields, is not bad as far as pandas is concerned: it is padded with an empty value, and only your own required-field rule can catch it.

```python run
import io
import pandas as pd

text = "id,name,city\n1,Ana,Oslo\n2,Ben,Lyon,extra\n3,Cy,Turin\n4,Dee\n"
try:
    pd.read_csv(io.StringIO(text))
except pd.errors.ParserError as err:
    print("error:", str(err).splitlines()[0])

skipped = pd.read_csv(io.StringIO(text), on_bad_lines="skip", dtype=str, keep_default_na=False)
print(skipped.values.tolist())

caught = []
def record(fields):
    caught.append(fields)
    return None

kept = pd.read_csv(io.StringIO(text), engine="python", on_bad_lines=record, dtype=str, keep_default_na=False)
print(len(kept), caught)
```

```output
error: Error tokenizing data. C error: Expected 3 fields in line 3, saw 4
[['1', 'Ana', 'Oslo'], ['3', 'Cy', 'Turin'], ['4', 'Dee', '']]
3 [['2', 'Ben', 'Lyon', 'extra']]
```

### Example 6: A loader report with a threshold

The function reads a file in chunks, validates each chunk, counts rejects by reason and aborts when the rejected share exceeds a limit. It returns a small report so that `read = good + rejected` can be checked. The two runs use the same data, with limits of 50% and 20%.

```python run
import io
import pandas as pd

text = "id,qty,status\n" + "\n".join([
    "1,3,open", "2,x,open", "3,5,closed", "4,2,paused", "5,7,open",
    "6,,closed", "7,1,open", "8,4,closed", "9,9,open", "10,2,open",
]) + "\n"

def load(text, chunksize, max_bad_share):
    counts, good, read = {}, 0, 0
    for chunk in pd.read_csv(io.StringIO(text), chunksize=chunksize, dtype=str, keep_default_na=False):
        qty = pd.to_numeric(chunk["qty"], errors="coerce")
        reason = pd.Series("", index=chunk.index)
        reason = reason.mask(qty.isna(), "bad qty")
        reason = reason.mask((reason == "") & ~chunk["status"].isin(["open", "closed"]), "bad status")
        read += len(chunk)
        good += int((reason == "").sum())
        for why, n in reason[reason != ""].value_counts().items():
            counts[why] = counts.get(why, 0) + int(n)
        if sum(counts.values()) / read > max_bad_share:
            return {"aborted_after": read, "rejected": dict(sorted(counts.items()))}
    return {"read": read, "good": good, "rejected": dict(sorted(counts.items()))}

print(load(text, 4, 0.5))
print(load(text, 4, 0.2))
```

```output
{'read': 10, 'good': 7, 'rejected': {'bad qty': 2, 'bad status': 1}}
{'aborted_after': 4, 'rejected': {'bad qty': 1, 'bad status': 1}}
```

## Real-world applications

- **Large vendor exports.** A daily sales file of several million rows is read with `chunksize` (Example 1), so the loading server needs memory for one chunk and not for the whole file.
- **Rejecting a wrong file early.** A header check (Example 3) catches a renamed column or a file for the wrong system in milliseconds, and a rejected-share threshold (Example 6) catches a wrong delimiter or encoding before a mostly empty table is loaded.
- **Returning a fix list to the source.** Rejects with line numbers and reasons (Example 4) can be written back as a small CSV that the data owner corrects and re-sends, which is far faster than describing the problems by email.
- **Preserving codes and identifiers.** Reading raw text (Example 2) keeps postal codes, product codes with leading zeros and country codes such as `NA` intact all the way to the staging table.

## Daily review

### Key takeaways

- `read_csv(chunksize=n)` returns an iterator of DataFrames; carry any whole-file state yourself.
- Read raw with `dtype=str, keep_default_na=False`, and convert and test the values with your own rules.
- Check the header once, before any data, and say which columns are missing or unexpected.
- Give every rejected row a line number (`index + 2`) and one reason; keep `read = good + rejected`.
- Choose quarantine over silent skipping, and abort when the rejected share passes a threshold.

### Common mistakes

- Letting pandas guess types: `007` becomes `7`, and `NA` becomes a missing value. Use `dtype=str, keep_default_na=False`.
- Treating `chunksize` as a list: `len(reader)` raises `TypeError: object of type 'TextFileReader' has no len()` and `reader[0]` fails. Loop over it.
- Checking duplicates only inside a chunk, so a repeat in a later chunk is accepted. Keep a set of ids seen so far.
- Reporting `index` as the file line. The first data row has index 0 and is line 2.
- Expecting `on_bad_lines` to catch rows with too few fields; they are padded with empty values. Add a required-field rule.
- Using `errors="ignore"` or dropping rows with `dropna()` and losing the rejects without a record. Use `errors="coerce"` and quarantine.

### Revision notes

- `for chunk in pd.read_csv(src, chunksize=n, dtype=str, keep_default_na=False):`
- `pd.to_numeric(s, errors="coerce")`, `pd.to_datetime(s, format="%Y-%m-%d", errors="coerce")`.
- `reason = reason.mask((reason == "") & failed, "label")` keeps the first reason.
- Line number is `index + 2`; the header check uses `read_csv(src, nrows=0).columns`.
- `on_bad_lines="skip"`; too-few-field rows are padded, not skipped.
