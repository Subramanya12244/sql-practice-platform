- Compute expected counts by hand and explain what they represent under the null hypothesis of independence.
- Run a chi-square test of independence with `scipy.stats.chi2_contingency` and report the statistic, degrees of freedom and p-value.
- Check the expected-count assumption, measure the strength of an association with Cramér's V, and find which cells drive a result.

## Understand

### Why categorical data needs its own test

On Day 103 you compared means with t-tests. A mean only exists for numbers such as order value or delivery time. Many analyst questions concern categories instead: did the customer buy or not, which device did they use, which plan did they pick, which region are they in. The data for such a question is a count of how many rows fall in each category, not an average. The question "does buying depend on the device?" asks whether two categorical columns are related, and the chi-square test (written χ², pronounced "kai-square") is the standard tool for it.

### Contingency tables

A **contingency table** (also called a cross-tab) counts how many rows fall into each combination of two categorical columns. You met `pd.crosstab` on Day 82. Rows of the table are the categories of one column, columns are the categories of the other, and each cell holds a count. The **row totals** and **column totals** are called the margins, and the **grand total** is the number of rows. Picture a grid: each visitor to a shop is dropped into exactly one cell, according to their device and whether they bought.

Counts alone mislead when groups have different sizes. If 120 desktop visitors and 200 mobile visitors each produced 30 buyers, the counts match but the rates (25% and 15%) do not. Read a contingency table as proportions within a group, using `pd.crosstab(..., normalize="index")`, before any test.

### The idea of the chi-square test of independence

Two variables are **independent** when knowing one tells you nothing about the other. The test begins from the null hypothesis, H0: the two columns are independent. Under H0 the overall buying rate is the same for every device, so you can work out how many buyers you would expect in each cell if only chance and the table margins mattered. These are the **expected counts**:

expected count for a cell = (row total x column total) / grand total

Trace one cell. If 36% of all 1,000 visitors are on mobile and 12% of all visitors bought, then independence predicts that 12% of mobile visitors bought as well, so the expected number of mobile buyers is 360 x 0.12 = 43.2. The formula above is that multiplication written with counts. Expected counts are usually not whole numbers and that is fine: they describe an average over many imaginary repeats.

The test statistic then measures the total distance between what you observed (O) and what you expected (E):

χ² = sum over all cells of (O - E)² / E

Each cell contributes a non-negative amount. Squaring stops positive and negative gaps from cancelling, and dividing by E means a gap of 10 matters more in a cell expecting 20 than in a cell expecting 2,000. When observed counts match expected counts exactly the statistic is 0, and it grows as the data departs from independence.

### Degrees of freedom and the p-value

If H0 is true, χ² follows a known curve called the **chi-square distribution**, whose shape depends on the **degrees of freedom** (df). For a table with r rows and c columns, df = (r - 1) x (c - 1). The reason is that once the margins are fixed, only (r - 1) x (c - 1) cells can be filled freely; the rest are forced. A 3 x 2 table has df = 2. The **p-value** is the probability, if H0 were true, of a χ² at least as large as the one you computed. As on Day 90, a small p-value (below your chosen significance level, commonly 0.05) is evidence against independence. It never proves a relationship and it says nothing about size.

### Assumptions to check

The chi-square curve is only an approximation, and it is poor when expected counts are tiny. A common rule of thumb is that every expected count should be at least 5 (some texts allow a few cells between 1 and 5). Rows must also be independent observations: if one customer appears ten times in the table, the test overstates its confidence. Finally, the table must hold counts of rows, not percentages or averages. For 2 x 2 tables, `chi2_contingency` applies Yates' continuity correction by default, a small adjustment that makes the p-value more cautious when counts are small.

### Effect size and finding the cells that matter

A tiny p-value can come from a huge sample with a trivial difference, just as with t-tests. **Cramér's V** is an effect size for categorical association. It equals the square root of χ² / (n x min(r - 1, c - 1)), where n is the grand total, and it lies between 0 (no association) and 1 (perfect association). Reading values of about 0.1 as small, 0.3 as medium and 0.5 as large is a rough convention, not a law.

The overall test tells you only that something differs. To see where, compare observed with expected cell by cell. The **standardised residual** (O - E) / sqrt(E) is positive where a cell holds more rows than independence predicts and negative where it holds fewer; values beyond about plus or minus 2 stand out.

### Goodness of fit

A second chi-square test compares one categorical column with a set of proportions you state in advance, for example "orders should be spread evenly across the five weekdays". This is the **goodness-of-fit** test. The expected counts come from the stated proportions times the number of rows, the statistic is the same sum, and df = (number of categories - 1).

### Common misconception

"A significant chi-square test means one variable causes the other." It does not. It says the counts are unlikely under independence. A second misconception is feeding the test percentages: the same data as percentages produces a different, wrong χ², because the formula needs real counts to know how much evidence there is.

### Why it matters

Analysts use these tests to check whether a conversion rate differs by channel, whether a survey answer depends on customer segment, and whether categories in a sample match the population. Tomorrow's lesson on A/B testing applies the same logic to a two-group experiment.

## Syntax and key functions

Contingency table from raw rows:

```python
table = pd.crosstab(df["row_col"], df["col_col"])
rates = pd.crosstab(df["row_col"], df["col_col"], normalize="index")
```

`normalize="index"` divides each row by its row total so each row sums to 1.

Test of independence:

```python
chi2, p, dof, expected = stats.chi2_contingency(table)
chi2, p, dof, expected = stats.chi2_contingency(table, correction=False)
```

The function returns four items: the statistic, the p-value, the degrees of freedom and an array of expected counts with the same shape as the table. `correction=False` turns off Yates' correction for 2 x 2 tables.

Goodness of fit:

```python
chi2, p = stats.chisquare(observed, f_exp=expected)
```

`observed` and `f_exp` are lists of counts in the same category order, and both must have the same total.

| Function or quantity | Returns |
|---|---|
| `pd.crosstab(a, b)` | Table of counts for each pair of categories. |
| `pd.crosstab(a, b, normalize="index")` | Proportions within each row. |
| `stats.chi2_contingency(table)` | Statistic, p-value, df, expected counts. |
| `stats.chisquare(obs, f_exp=exp)` | Goodness-of-fit statistic and p-value. |
| `(O - E) / np.sqrt(E)` | Standardised residual per cell. |
| `np.sqrt(chi2 / (n * min(r - 1, c - 1)))` | Cramér's V. |

## Learn by example

### Example 1: From raw rows to a contingency table

The raw data has one row per visitor. The table is built from counts here so the numbers are the same on every run. `pd.crosstab` counts each combination, and `margins=True` adds the totals. The second table shows the buying rate within each device, which is the comparison that matters.

```python run
import numpy as np
import pandas as pd

counts = {("desktop", "yes"): 36, ("desktop", "no"): 84,
          ("mobile", "yes"): 30, ("mobile", "no"): 170,
          ("tablet", "yes"): 14, ("tablet", "no"): 66}
rows = [(device, bought) for (device, bought), n in counts.items() for _ in range(n)]
df = pd.DataFrame(rows, columns=["device", "bought"])

table = pd.crosstab(df["device"], df["bought"])
print(pd.crosstab(df["device"], df["bought"], margins=True).to_string())
print()
print(pd.crosstab(df["device"], df["bought"], normalize="index").round(3).to_string())
```

```output
bought    no  yes  All
device                
desktop   84   36  120
mobile   170   30  200
tablet    66   14   80
All      320   80  400

bought      no    yes
device               
desktop  0.700  0.300
mobile   0.850  0.150
tablet   0.825  0.175
```

### Example 2: Expected counts by hand

Under independence each expected count is row total x column total / grand total. `np.outer` multiplies every row total by every column total at once, so one line fills the whole grid. Compare it with the observed table to see where the data departs from independence.

```python run
import numpy as np
import pandas as pd

table = pd.DataFrame({"no": [84, 170, 66], "yes": [36, 30, 14]},
                     index=["desktop", "mobile", "tablet"])
row_totals = table.sum(axis=1).to_numpy()
col_totals = table.sum(axis=0).to_numpy()
grand = table.to_numpy().sum()

expected = pd.DataFrame(np.outer(row_totals, col_totals) / grand,
                        index=table.index, columns=table.columns)
print(expected.round(2).to_string())
print()
print((table - expected).round(2).to_string())
chi2 = ((table - expected) ** 2 / expected).to_numpy().sum()
print()
print("chi-square by hand:", round(chi2, 3))
```

```output
            no   yes
desktop   96.0  24.0
mobile   160.0  40.0
tablet    64.0  16.0

           no   yes
desktop -12.0  12.0
mobile   10.0 -10.0
tablet    2.0  -2.0

chi-square by hand: 10.938
```

### Example 3: The test with scipy

`chi2_contingency` repeats Example 2 internally and adds the p-value. The degrees of freedom are (3 - 1) x (2 - 1) = 2. The decision rule compares the p-value with the significance level chosen before looking at the data. The statistic matches the hand calculation, which is a useful check.

```python run
import pandas as pd
from scipy import stats

table = pd.DataFrame({"no": [84, 170, 66], "yes": [36, 30, 14]},
                     index=["desktop", "mobile", "tablet"])
chi2, p, dof, expected = stats.chi2_contingency(table)
print("chi2 =", round(chi2, 3))
print("df =", dof)
print("p =", round(p, 4))
print("smallest expected count:", round(expected.min(), 2))
alpha = 0.05
print("reject independence" if p < alpha else "no evidence against independence")
```

```output
chi2 = 10.938
df = 2
p = 0.0042
smallest expected count: 16.0
reject independence
```

### Example 4: Effect size and the cells that drive the result

A small p-value says the device and buying are related, not how strongly. Cramér's V gives the strength, and standardised residuals show which cells are above or below what independence predicts. Positive residuals mean more rows than expected.

```python run
import numpy as np
import pandas as pd
from scipy import stats

table = pd.DataFrame({"no": [84, 170, 66], "yes": [36, 30, 14]},
                     index=["desktop", "mobile", "tablet"])
chi2, p, dof, expected = stats.chi2_contingency(table, correction=False)
n = table.to_numpy().sum()
r, c = table.shape
v = np.sqrt(chi2 / (n * min(r - 1, c - 1)))
print("Cramer's V =", round(v, 3))

resid = (table.to_numpy() - expected) / np.sqrt(expected)
print(pd.DataFrame(resid, index=table.index, columns=table.columns).round(2).to_string())
```

```output
Cramer's V = 0.165
           no   yes
desktop -1.22  2.45
mobile   0.79 -1.58
tablet   0.25 -0.50
```

### Example 5: Goodness of fit

The business expects orders to be spread evenly over the five weekdays. `chisquare` compares the observed counts with the expected counts, here 100 per day. The df is 5 - 1 = 4.

```python run
from scipy import stats

observed = [112, 98, 83, 96, 111]
expected = [sum(observed) / 5] * 5
chi2, p = stats.chisquare(observed, f_exp=expected)
print("expected per day:", expected)
print("chi2 =", round(chi2, 3), "p =", round(p, 4))
print("uneven" if p < 0.05 else "consistent with an even spread")
```

```output
expected per day: [100.0, 100.0, 100.0, 100.0, 100.0]
chi2 = 5.74 p = 0.2194
consistent with an even spread
```

### Example 6: A small 2 x 2 table and Yates' correction

For a 2 x 2 table the default correction shrinks the statistic, and the expected-count check matters more because the counts are small. Here one expected count is below 5, so the result should be treated with caution and a different method (Fisher's exact test, not covered here) is usually preferred.

```python run
import numpy as np
from scipy import stats

table = np.array([[8, 2],
                  [4, 6]])
for correction in (True, False):
    chi2, p, dof, expected = stats.chi2_contingency(table, correction=correction)
    print("correction", correction, "chi2", round(chi2, 3), "p", round(p, 4))
print(expected.round(2))
print("any expected count below 5:", bool((expected < 5).any()))
```

```output
correction True chi2 1.875 p 0.1709
correction False chi2 3.333 p 0.0679
[[6. 4.]
 [6. 4.]]
any expected count below 5: True
```

## Real-world applications

- **Channel and conversion.** A marketing analyst crosses acquisition channel with purchase (yes or no) and uses the test of independence plus Cramér's V, as in Examples 3 and 4, to say whether the channel mix matters and how much.
- **Survey analysis.** Satisfaction level (low, medium, high) against customer segment is a contingency table. Standardised residuals show which segment is unusually unhappy.
- **Data quality and sampling checks.** A goodness-of-fit test, as in Example 5, checks that a sample's region mix matches the known customer base, or that orders are not bunched on one weekday because of a logging fault.
- **Experiment readouts.** A 2 x 2 table of group by outcome is the core of an A/B test on conversion, which Day 105 builds on.

## Daily review

### Key takeaways

- A contingency table counts rows in each pair of categories; read it as rates within a group before testing.
- Expected count = row total x column total / grand total, and χ² sums (O - E)² / E over all cells.
- df = (rows - 1) x (columns - 1); a small p-value is evidence against independence, not proof of cause.
- Check expected counts are at least about 5, use raw counts, and report an effect size such as Cramér's V.
- Standardised residuals locate the cells behind a significant result; goodness of fit tests one column against stated proportions.

### Common mistakes

- Passing percentages or rates to `chi2_contingency`. The p-value changes and is meaningless; pass counts.
- Passing the raw DataFrame instead of the crosstab. The function expects a table of counts and raises an error or gives nonsense for a column of labels.
- Ignoring small expected counts. With several expected values below 5 the p-value is unreliable; merge sparse categories or use an exact test.
- Reading `p < 0.05` as a strong effect. With 100,000 rows a trivial gap is "significant"; report Cramér's V.
- Forgetting that `chi2_contingency` returns four values in the order statistic, p, dof, expected, and mixing up `p` and `dof`.
- Using the test on repeated measures, such as the same customer in many rows, which breaks independence.

### Revision notes

- `table = pd.crosstab(a, b)`; `chi2, p, dof, exp = stats.chi2_contingency(table)`.
- Expected = `np.outer(row_totals, col_totals) / grand`.
- df = (r - 1)(c - 1); goodness of fit df = categories - 1.
- Cramér's V = sqrt(chi2 / (n x min(r - 1, c - 1))), from the uncorrected statistic.
- Rule: all expected counts at least 5.
