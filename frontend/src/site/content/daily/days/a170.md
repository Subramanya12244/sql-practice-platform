## Understand

### What a Python and pandas interview looks like

For analyst roles the Python interview is usually a notebook or a shared editor with a small DataFrame and three or four tasks. They cover four things you have practised: **cleaning** (duplicates, text case and whitespace, numbers stored as text, missing values), **groupby** (totals, ranks, top N, shares), **merge** (joining two tables and noticing what went wrong) and **reading code** (what does this print, and where is the bug). A fifth part may be a short plain Python question, such as counting words or finding the first value that does not repeat, to see that you can use dictionaries and loops without a library. The routine from the SQL day applies unchanged: restate the task, say the grain of the output, write in small pieces, print the shape and the first rows after each piece, test an edge case, and explain.

### Cleaning in a sensible order

Cleaning has an order that avoids surprises. Remove exact duplicates first, because they inflate counts. Then fix text (`str.strip()`, `str.lower()`), because `" ana "` and `"Ana"` are one customer, and a duplicate check on text that has not been normalised misses them. Convert types next: `pd.to_numeric(col, errors="coerce")` turns text numbers into floats and anything unparseable (`"n/a"`, an empty string) into `NaN`, which you count rather than hide. Parse dates with an explicit format (`pd.to_datetime(col, format="%Y-%m-%d")`) so that day and month are never guessed. Decide about missing values deliberately (drop, fill with a stated value, or keep and report) and write the decision into the answer. After each step print `len(df)` so you can say how many rows the step changed. Note that duplicates become visible only after normalisation in some data: removing duplicates before and after cleaning text can give different counts, and you should say which you did.

### Groupby, ranks and top N

`df.groupby("customer")["amount"].sum()` gives one total per group; `.agg(orders=("order_id", "count"), total=("amount", "sum"))` gives several named columns at once. Two different row-count behaviours matter. An aggregation reduces the rows to one per group. A transform keeps all rows: `df.groupby("customer")["amount"].transform("sum")` attaches the group total to every row, which is how you compute a share of the group (`amount / group_total`). **Top N per group** is solved by sorting and taking the head of each group: `df.sort_values("amount", ascending=False).groupby("customer").head(2)`. Explain ties and decide what to do with them. The pandas counterpart of SQL's `ROW_NUMBER` is `groupby(...).cumcount()` after sorting, and of `RANK` is `groupby(...)["col"].rank(method="dense", ascending=False)`.

### Merges and how to check them

`left.merge(right, on="key", how="left")` keeps all left rows and adds the right columns where a key matches; unmatched rows get `NaN`. The checks are the same as in SQL: compare the row counts before and after (a many-to-many match multiplies rows), count the unmatched rows, and look for duplicate keys on the side that should be unique. Pandas can enforce this with `validate="m:1"` (many left rows to one right row): if the right table has duplicate keys it raises a `MergeError` instead of silently multiplying rows. An **anti-join** (rows in the left table with no match in the right) is written with `indicator=True` and a filter on `_merge == "left_only"`, or with `~left["key"].isin(right["key"])`. Say which join type you chose and why.

### Reading code and common traps

The "what does this print?" part often uses a known trap. A **mutable default argument** (`def add(x, items=[])`) creates the list once, when the function is defined, so calls share it. A **shallow copy** (`list(a)` or `a.copy()` of a list of lists) copies the outer list but shares the inner ones, so changing an inner list changes both. In pandas, `df.sort_values(...)` and `df.drop_duplicates()` **return new objects**; calling them without assigning the result changes nothing. Assigning into a slice (`df[df.x > 0]["y"] = 1`, called chained assignment) may not modify the original and is a warned-about pattern; use `df.loc[mask, "y"] = 1`. Comparing with `is` tests identity, not equality. Integer division with `//` and floating-point rounding (`0.1 + 0.2 == 0.3` is `False`) also appear. When reading code, trace one small example by hand, line by line, writing the value of each variable.

### Why it matters, and the misconception

The misconception is that interviewers want the shortest code. They want correct, readable code and evidence that you check it. Printing row counts and an example row after each step is cheap and is exactly what protects real analyses from silent errors.

```python
df = df.drop_duplicates()
df["name"] = df["name"].str.strip().str.lower()
df["amount"] = pd.to_numeric(df["amount"], errors="coerce")
df["date"] = pd.to_datetime(df["date"], format="%Y-%m-%d")

```

| Task | Tool |
|---|---|
| Text fix | `str.strip()`, `str.lower()` |
| Text to number | `pd.to_numeric(errors="coerce")` |
| Count missing | `df["col"].isna().sum()` |
| Group total, keep rows | `groupby().transform("sum")` |
| Top N per group | `sort_values` then `groupby().head(n)` |
| Anti-join | `merge(indicator=True)` and `_merge == "left_only"` |
| Guard a merge | `validate="m:1"` |
| Count items | `collections.Counter` |

## Learn by example

### Example 1: Clean in order and count rows

The orders have a duplicated row, messy customer text, amounts stored as text (with `n/a` and an empty string) and date strings. Each step prints how many rows or missing values remain, so every change can be explained.

```python run
import pandas as pd

orders = pd.DataFrame({
    "order_id": [1, 2, 3, 3, 4, 5, 6, 7, 8],
    "customer": [" ana ", "BEN", "cho", "cho", "Ana", "ben ", "Dev", "cho", "Ana"],
    "amount": ["120.5", "80", "n/a", "n/a", "45.25", "60", "", "300", "90.75"],
    "order_date": ["2025-01-05", "2025-01-09", "2025-02-11", "2025-02-11", "2025-02-14", "2025-03-01", "2025-03-03", "2025-03-09", "2025-03-20"],
})
customers = pd.DataFrame({"customer": ["ana", "ben", "cho", "eli"], "city": ["Leeds", "York", "Hull", "Bath"]})

print("raw rows:", len(orders))
df = orders.drop_duplicates().copy()
print("after drop_duplicates:", len(df))
df["customer"] = df["customer"].str.strip().str.lower()
df["amount"] = pd.to_numeric(df["amount"], errors="coerce")
print("amounts missing after conversion:", int(df["amount"].isna().sum()))
df["order_date"] = pd.to_datetime(df["order_date"], format="%Y-%m-%d")
print("customers:", sorted(df["customer"].unique()))
print("date range:", df["order_date"].min().date(), "to", df["order_date"].max().date())
```

```output
raw rows: 9
after drop_duplicates: 8
amounts missing after conversion: 2
customers: ['ana', 'ben', 'cho', 'dev']
date range: 2025-01-05 to 2025-03-20
```

### Example 2: Groupby, share and top two per group

With the cleaned table: totals and counts per customer in one `agg`, each order's share of its customer's total with `transform` (all rows are kept), and the two biggest orders per customer by sorting and `head(2)`. Missing amounts are ignored by `sum`, which the report should say.

```python run
import pandas as pd

orders = pd.DataFrame({
    "order_id": [1, 2, 3, 3, 4, 5, 6, 7, 8],
    "customer": [" ana ", "BEN", "cho", "cho", "Ana", "ben ", "Dev", "cho", "Ana"],
    "amount": ["120.5", "80", "n/a", "n/a", "45.25", "60", "", "300", "90.75"],
    "order_date": ["2025-01-05", "2025-01-09", "2025-02-11", "2025-02-11", "2025-02-14", "2025-03-01", "2025-03-03", "2025-03-09", "2025-03-20"],
})
customers = pd.DataFrame({"customer": ["ana", "ben", "cho", "eli"], "city": ["Leeds", "York", "Hull", "Bath"]})

def clean(df):
    out = df.drop_duplicates().copy()
    out["customer"] = out["customer"].str.strip().str.lower()
    out["amount"] = pd.to_numeric(out["amount"], errors="coerce")
    out["order_date"] = pd.to_datetime(out["order_date"], format="%Y-%m-%d")
    return out.reset_index(drop=True)

df = clean(orders)
summary = df.groupby("customer").agg(orders=("order_id", "count"), total=("amount", "sum"))
print(summary.to_string())
df["share"] = (df["amount"] / df.groupby("customer")["amount"].transform("sum") * 100).round(1)
print("rows kept by transform:", len(df))
top2 = df.sort_values(["customer", "amount"], ascending=[True, False]).groupby("customer").head(2)
print(top2[["customer", "order_id", "amount", "share"]].to_string(index=False))
```

```output

ana            3  256.5
ben            2  140.0
cho            2  300.0
dev            1    0.0
rows kept by transform: 8
customer  order_id  amount  share
     ana         1  120.50   47.0
     ana         8   90.75   35.4
     ben         2   80.00   57.1
     ben         5   60.00   42.9
     cho         7  300.00  100.0
     cho         3     NaN    NaN
     dev         6     NaN    NaN
```

### Example 3: Merge, anti-join and a guard

Orders are merged with the customer table. A left merge keeps all orders and shows which customers have no city (`dev` is not in the customer table). The anti-join lists customers with no orders (`eli`). The `validate` option shows a duplicated key in the right table being caught instead of multiplying rows.

```python run
import pandas as pd

orders = pd.DataFrame({
    "order_id": [1, 2, 3, 3, 4, 5, 6, 7, 8],
    "customer": [" ana ", "BEN", "cho", "cho", "Ana", "ben ", "Dev", "cho", "Ana"],
    "amount": ["120.5", "80", "n/a", "n/a", "45.25", "60", "", "300", "90.75"],
    "order_date": ["2025-01-05", "2025-01-09", "2025-02-11", "2025-02-11", "2025-02-14", "2025-03-01", "2025-03-03", "2025-03-09", "2025-03-20"],
})
customers = pd.DataFrame({"customer": ["ana", "ben", "cho", "eli"], "city": ["Leeds", "York", "Hull", "Bath"]})

def clean(df):
    out = df.drop_duplicates().copy()
    out["customer"] = out["customer"].str.strip().str.lower()
    out["amount"] = pd.to_numeric(out["amount"], errors="coerce")
    out["order_date"] = pd.to_datetime(out["order_date"], format="%Y-%m-%d")
    return out.reset_index(drop=True)

df = clean(orders)
merged = df.merge(customers, on="customer", how="left")
print("rows before/after:", len(df), len(merged), "| orders with no city:", int(merged["city"].isna().sum()))
print("no match:", sorted(merged.loc[merged["city"].isna(), "customer"].unique()))
anti = customers.merge(df[["customer"]].drop_duplicates(), on="customer", how="left", indicator=True)
print("customers with no orders:", anti.loc[anti["_merge"] == "left_only", "customer"].tolist())

dup = pd.concat([customers, customers.iloc[[0]]], ignore_index=True)
print("without validate:", len(df.merge(dup, on="customer", how="left")), "rows")
try:
    df.merge(dup, on="customer", how="left", validate="m:1")
except pd.errors.MergeError:
    print("validate m:1 caught the duplicate key")
```

```output
rows before/after: 8 8 | orders with no city: 1
no match: ['dev']
customers with no orders: ['eli']
without validate: 11 rows
validate m:1 caught the duplicate key
```

### Example 4: Plain Python warm-ups

Two classic questions without pandas: count the most common word with a dictionary (using `collections.Counter`, and with a plain dictionary to show what it does), and find the first character that does not repeat. Both are linear in the length of the input, which is the complexity to state aloud.

```python run
from collections import Counter

text = "the cat saw the dog and the cat ran"
counts = {}
for word in text.split():
    counts[word] = counts.get(word, 0) + 1
print("plain dict:", sorted(counts.items(), key=lambda kv: (-kv[1], kv[0]))[:3])
print("Counter:", sorted(Counter(text.split()).items(), key=lambda kv: (-kv[1], kv[0]))[:3])


def first_unique(s):
    seen = Counter(s)
    for ch in s:
        if seen[ch] == 1:
            return ch
    return None


print(first_unique("swiss"), first_unique("aabb"))
```

```output
plain dict: [('the', 3), ('cat', 2), ('and', 1)]
Counter: [('the', 3), ('cat', 2), ('and', 1)]
w None
```

### Example 5: Reading code, three traps

Predict each result before reading the output. The mutable default list is shared between calls. A shallow copy shares inner lists. And `sort_values` without assignment leaves the DataFrame unchanged. Writing the prediction first is the exercise.

```python run
import pandas as pd


def add(x, items=[]):
    items.append(x)
    return items


print(add(1), add(2))


def add_safe(x, items=None):
    items = [] if items is None else items
    items.append(x)
    return items


print(add_safe(1), add_safe(2))

a = [[1], [2]]
b = list(a)
b[0].append(99)
print("shallow copy shares inner lists:", a)

df = pd.DataFrame({"x": [3, 1, 2]})
df.sort_values("x")
print("unassigned sort:", df["x"].tolist())
df = df.sort_values("x")
print("assigned sort:", df["x"].tolist())
```

```output
[1, 2] [1, 2]
[1] [2]
shallow copy shares inner lists: [[1, 99], [2]]
unassigned sort: [3, 1, 2]
assigned sort: [1, 2, 3]
```

## Real-world applications

- **Take-home cleaning tasks.** The ordered cleaning routine and row counts (Example 1) are what a reviewer reads first in a take-home notebook.
- **Reports with rankings.** Top-N per group and shares (Example 2) are used in "best product per region" and "customer concentration" reports.
- **Data integration checks.** Merge checks and anti-joins (Example 3) are the daily tool for finding records missing from a reference table.
- **Code review.** Reading code for shared mutable state and unassigned results (Example 5) catches bugs in colleagues' notebooks before they reach a report.

## Daily review

### Key takeaways

- Clean in order: duplicates, text, types, dates, missing; print row counts at each step.
- Aggregation reduces rows; `transform` keeps them; top N is sort then `groupby().head(n)`.
- Check every merge: rows before and after, unmatched keys, duplicate keys, `validate`.
- Anti-join with `indicator=True` or `isin`.
- Read code by tracing a small example; know the mutable default, shallow copy and unassigned-result traps.

### Common mistakes

- Removing duplicates before normalising text. Symptom: `Ana` and `ana ` counted as two customers. Fix: normalise first, then deduplicate.
- Letting `to_datetime` guess the format. Symptom: day and month swapped without an error. Fix: pass `format=`.
- Merging without checking keys. Symptom: more rows after the merge and inflated totals. Fix: `validate="m:1"` and a row count.
- Calling `sort_values` or `drop_duplicates` and not assigning the result. Symptom: nothing changes. Fix: assign it back.

### Revision notes

- `drop_duplicates`, `str.strip().str.lower()`, `to_numeric(errors="coerce")`, `to_datetime(format=...)`.
- `agg(name=(col, func))`, `transform("sum")`, `sort_values().groupby().head(n)`.
- `merge(how, indicator, validate)`; `_merge == "left_only"`.
- Traps: mutable default, shallow copy, unassigned result, chained assignment.
